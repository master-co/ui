An app shell is the frame of an application: a sidebar that stays in place while the main region moves. It is built on the `shell` layout classes, which hold the parts utilities cannot write: heights in `dvh`, the sticky sidebar with its own scroll, the inset for the home indicator, and the width at which the sidebar steps aside.

The shell draws nothing. In the example the hairline is a border utility, the bar is a [navbar](/components/navbar), the links are a [nav](/components/nav) and the tiles are [cards](/components/card) in an [auto grid](/components/auto-grid).

## How it is built \{#how-it-is-built\}

| Part | Class | What it does |
| --- | --- | --- |
| The frame | `shell` | A grid at least as tall as the viewport, and a size container named `shell` |
| The sidebar | `shell-sidebar` | Sticks under the header, as tall as the room left in the viewport, with its own scroll |
| The main region | `shell-main` | Takes the column that is left and never grows past it |
| The toggle | `shell-toggle` | Any control that should exist only while the sidebar is away |

By default **the document scrolls**. A sticky [navbar](/components/navbar) keeps working, links to headings land where they should, and the browser restores the scroll position on the way back.

Below 48rem of shell the sidebar is removed from the layout. Nothing replaces it by itself: put the same navigation in a [drawer](/components/dialog#drawer) on the start edge and open it from a button with `shell-toggle`. The drawer is a native `<dialog>`, opened by `commandfor`, so the whole arrangement needs no script.

The threshold measures the shell, not the screen: a shell inside a narrow panel collapses there, on any display.

## On a tray \{#on-a-tray\}

Set the shell on the tray tone and stand the main region on a [sheet](/components/surface#sheet), 8px in. The sidebar then reads as part of the frame and the content as the thing on it. The same classes; only the surfaces changed.

## Fixed \{#fixed\}

`shell-fixed` makes the shell exactly the viewport. Nothing scrolls but the regions, each by itself: the list keeps its place while the reader moves through what they opened. Use it for an inbox, an editor or a chat, where two things are read side by side. Use the default for everything else: a document that scrolls as a whole behaves better on a phone, where the browser's toolbars collapse as the page moves.

`--shell-sidebar` sets the sidebar's width; here it is 20rem, for a list of messages.

## Accessibility \{#accessibility\}

- Use landmarks: `<aside>` or `<nav>` for the sidebar, `<main>` for the main region, `<header>` for a header. Label each `<nav>`; with the drawer there are two, so their labels must differ.
- The drawer holds the same links as the sidebar, in the same order. While the sidebar is shown, the toggle is `display: none` and out of the tab order.
- A region that scrolls by itself and holds nothing focusable needs `tabindex="0"` and a label, so the keyboard can scroll it.
- Heights use `dvh`, so a phone's toolbars never cover the foot of the sidebar; the sidebar also pads its foot by the home indicator's inset.
