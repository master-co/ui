## 구성 방법 \{#how-it-is-built\}

- **프레임에 `container-inline` 적용**. 프레임이 크기 컨테이너가 됩니다. 내부의 모든 `@container(…)` 유틸리티는 프레임 너비를 기준으로 동작합니다.
- **높이가 고정된 행.** `flex h(440)`로 두 영역의 높이를 같게 맞추고, 목록과 상세 영역에 각각 `overflow-y-auto`를 적용해 독립적으로 스크롤되게 합니다. `min-h(0)` 덕분에 목록은 헤더 아래에서 줄어들 수 있고 헤더는 제자리에 남습니다. 화면 높이를 모두 쓰는 앱에서는 높이를 숫자로 지정하는 대신 [고정형 셸](/pages/app-shell#fixed)에서 가져옵니다.
- **목록은 고정 너비, 상세 영역은 가변 너비.** 프레임 너비가 48rem 미만이면 목록에 `w-full`을 적용하고, 48rem 이상이면 `shrink(0)`와 함께 `w(300)@container(--3xl)`을 적용합니다. 상세 영역에는 `grow(1) basis(0) min-w(0)`를 적용해 남은 너비를 채우고 목록을 밀어내지 않도록 합니다.
- **48rem 미만에서는 영역 하나만 표시.** 상세 영역은 `hidden`으로 숨기고 `flex@container(--3xl)`을 적용해 다시 표시합니다. 좁은 화면에서는 목록이 표시되며, 행을 선택하면 해당 항목의 상세 페이지로 이동합니다. 이는 페이지 이동이므로 레이아웃이 아니라 라우터가 담당합니다.
- **행은 영역 안쪽에 놓입니다.** 목록에 `p-sm`을 지정하므로 현재 행의 시트가 영역의 가장자리와 헤더 아래 선에 닿지 않습니다. 헤더 제목에는 행 자체의 안쪽 여백(`--list-inset`)과 같은 `pxs(10)`을 지정해 행의 텍스트와 같은 위치에서 시작합니다.
- **두 영역 사이의 구분선**에는 `bxe(1)@container(--3xl) bxe-solid@container(--3xl)`을 적용해 두 영역이 모두 표시될 때만 보이게 합니다.

[`list-interactive`](/components/list) 안의 `list-row`에 `aria-current="true"`를 적용해 현재 행을 표시합니다.

</div>`} />

- **돌아가는 길이 페이지의 첫 요소입니다.** 제목 위의 [링크](/components/link) 하나이며, 이동할 곳인 API keys로 이름을 붙입니다. 상세 영역은 페이지가 되면서 목록을 잃었고, 이 링크가 목록을 되돌려 줍니다. 그래서 사용자가 가장 먼저 보는 곳이자 키보드가 헤더 다음에 가장 먼저 도달하는 곳에 둡니다.
- **헤더는 [페이지 헤더](/blocks/page-header)입니다.** 이름은 페이지의 `<h1>`이고 그 옆에 상태가 놓이며, 두 작업 버튼은 줄바꿈되는 양쪽 배치인 `flex flex-wrap items-end justify-between`입니다. 이름의 열은 `grow(1) basis(320) min-w(0)`입니다. 긴 이름은 320px을 확보할 수 있는 동안 버튼 옆에서 줄바꿈되고, 그보다 좁아지면 버튼이 순서를 유지한 채 이름 아래로 내려갑니다.
- **컨테이너 안의 3등분 그리드.** 메인 영역은 `container-inline`입니다. 그리드는 메인 영역이 48rem을 내주기 전까지 `grid-cols(1)`이고, 그 뒤로는 `grid-cols(3)@container(--3xl)`입니다. 키와 활동 내역은 `grid-col-span(2)@container(--3xl)`로 그중 두 칸을 차지하고 세부 정보는 세 번째 칸을 차지하며, 이 칸은 최대 너비에서 약 19rem입니다. 그만큼 좁은 열에서는 [데이터 목록](/components/data-list)이 각 용어를 값 위에 알아서 배치합니다.
- **읽는 순서대로 놓인 세 섹션.** 소스 순서는 키, 세부 정보, 활동 내역입니다. 두 열일 때 세부 정보는 `grid-row-span(2)@container(--3xl)`로 나머지 둘의 옆에 놓이고, `items-start`가 각 섹션을 자기 높이로 유지합니다. 한 열일 때는 작성된 순서 그대로 놓입니다. 키가 무엇이고 무엇을 할 수 있는지, 키에 관한 사실, 그리고 가장 길고 가장 덜 급한 기록 순입니다.
- **하나의 너비 제한과 하나의 가장자리 여백.** 메인 영역은 `max-w(1040) mx-auto px-lg`입니다. 내비게이션 바는 전체 너비를 차지하므로 패딩이 너비 제한을 따릅니다. `--navbar-padding-x: max(1.5rem, calc(50% - 31rem))`은 좁은 화면에서는 1.5rem이고 넓은 화면에서는 너비 제한의 가장자리입니다. 브랜드, 돌아가는 링크, 제목, 각 섹션의 첫 단어가 모든 너비에서 같은 선에서 시작합니다.

링크가 어디로 이동하는지, Rotate key와 Revoke가 무엇을 하는지는 애플리케이션이 정합니다. 여기서는 동작이 아니라 자리만 나타냅니다.

## 세 가지 구성 방법 \{#three-ways\}

| 사용 상황 | 구성 방법 | 사용자가 얻는 것 |
| --- | --- | --- |
| 두 영역이 페이지의 일부인 경우 | [위 예제](#how-it-is-built)처럼 유틸리티와 컨테이너 사용 | 공간이 48rem 이상이면 목록과 항목 하나를 동시에 봅니다 |
| 사용자가 두 영역의 너비를 조절하는 경우 | [분할 조절기](/components/splitter) | 같은 구성을 사용자가 정한 비율로 봅니다 |
| 두 영역이 앱 전체를 구성하는 경우 | 목록을 사이드바로 둔 [고정형 셸](/pages/app-shell#fixed) | 같은 구성을 뷰포트 높이로 봅니다 |
| 두 영역을 둘 공간이 없거나 다른 곳에서 항목으로 링크하는 경우 | 별도의 경로에 둔 [단독](#standalone) 상세 페이지 | 어떤 너비에서든 고유한 주소로 항목 하나를 봅니다 |

두 영역을 동시에 읽으면 목록의 위치가 유지됩니다. 사용자는 페이지를 떠나지 않고 행을 따라 내려가며 한 항목을 다음 항목과 비교합니다. 다만 두 영역 모두를 위한 너비가 필요하고, 선택은 페이지가 보관하는 선택 상태이거나 하나의 주소의 일부입니다. 상세 경로에는 고유한 주소, 방문 기록에서의 자리, 고유한 제목이 있으며 어떤 너비에서도 동작합니다. 대신 목록을 잃으므로 돌아가는 길을 제공하고, 목록은 사용자가 떠났던 행으로 돌아가야 합니다. 대부분의 애플리케이션에는 둘 다 필요합니다. 공간이 있으면 두 영역을, 없으면 같은 상세 내용을 페이지로 제공하되, 하나의 주소를 사용해 링크가 상황에 맞는 쪽을 열게 합니다.

## 접근성 \{#accessibility\}

- 목록은 각 항목의 상세 내용으로 연결되는 링크로 구성됩니다. 현재 표시 중인 항목의 링크에 `aria-current="true"`를 지정합니다.
- 프레임에 레이블을 지정하고, 상세 영역에는 선택한 항목의 이름을 제목으로 넣습니다. 그러면 상세 영역에 바로 도달한 사용자도 어떤 항목을 보고 있는지 알 수 있습니다.
- 스크롤할 수 있지만 내부에 포커스를 받을 요소가 없는 영역에는 키보드로 스크롤할 수 있도록 `tabindex="0"`을 지정합니다.
- 좁은 화면에서 상세 영역을 숨기면 `display: none`이 적용되어 접근성 트리에서 제외됩니다. 상세 영역을 가리키는 컨트롤도 남지 않도록 합니다.
- 단독 상세 페이지에는 [페이지](/pages/page)의 랜드마크가 있습니다. 건너뛰기 링크, 내비게이션이 있는 `<header>` 하나, `<main>` 하나입니다. 세 섹션은 각각 제목으로 이름을 지정하므로 영역으로 이동할 수 있습니다.
- 돌아가는 길은 목록의 이름인 "API keys"를 이름으로 가진 링크이며, 그 앞의 화살표는 `aria-hidden`입니다. 여기에 `history.back()`을 사용하지 않습니다. 링크로 도착한 사용자의 방문 기록에는 돌아갈 목록이 없습니다.
- 항목의 이름은 페이지의 유일한 `<h1>`이고, 섹션은 `<h2>`, 스코프는 `<h3>`입니다. 두 영역 구성에서는 같은 이름이 목록의 `<h2>` 아래에 있는 `<h3>`입니다. 제목 수준은 상세 내용이 놓인 자리를 따르므로, 상세 내용을 옮길 때 수준을 다시 지정합니다.
- `aria-current="true"`는 목록의 행에 지정하는 것인데, 이 페이지에는 목록이 없습니다. 헤더에서 현재 섹션으로 연결되는 링크만 `aria-current="page"`를 가집니다. 타임라인에서는 `aria-current="true"`가 가장 최근 이벤트를 표시합니다.
- 경로가 바뀐 뒤에는 포커스를 메인 영역이나 `<h1>`로 옮기고 문서의 제목을 갱신해 새 페이지가 안내되도록 합니다.
