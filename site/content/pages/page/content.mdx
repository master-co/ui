A page is the frame of a document that scrolls as a whole: a header, the main region and a footer. One layout class, `page`, makes the frame at least as tall as the viewport; utilities do the rest.

## How it is built \{#how-it-is-built\}

- **`page` on the frame.** It is a column with a minimum height of `100dvh`. The dynamic viewport unit follows a phone's toolbars as they show and hide, so the frame is never taller than what can be seen and never leaves a gap. This is the one thing here a utility cannot write.
- **`grow(1)` on the main region.** It takes the room that is left, which is what keeps the footer at the foot of a short page.
- **A measure on the content, not on the regions.** The header and the footer run the full width. The main region and what is inside the footer share one measure, `max-w(720) mx-auto px-lg`, so their edges line up; the navbar keeps its own padding. Use a wider measure for an index page and this one for reading.
- **Surfaces come from components.** The bar is a [navbar](/components/navbar), sticky by itself; the hairline over the footer is a border utility.

## Accessibility \{#accessibility\}

- Use the landmarks: `<header>`, `<main>` and `<footer>`, one of each, and a label on every `<nav>`.
- The first element of the page is a [skip link](/components/skip) to the main region, which has `tabindex="-1"` so focus moves there with the jump. A reader who uses the keyboard passes the header in one press.
- A sticky header covers the top of the page: set `scroll-padding-top` on the root to the header's height, so a link to a heading does not land under it, or put [flash](/components/flash) on the headings links point at, which keeps each of them clear by itself.
