コンボボックスは、入力に一致する候補の[リストボックス](/components/listbox)を開くテキストフィールドです。文字を入力して選択肢を探せます。既存の[入力グループ](/components/input#input-group)とフローティングリストボックスを、`combobox`ラッパーでひとまとめにします。スタイルシートが配置と見た目を担い、`combobox`の[ビヘイビア](/guide/behaviors)が候補の絞り込み、候補間の移動、選択した値のフィールドへの反映を行います。

## スタイルシートの役割 \{#what-the-stylesheet-does\}

- **配置**　`combobox` ラッパーは自身にアンカー名を付け、その名前のスコープを自身に限定します。リストボックスはフィールド全体の下端から 6px 下に開き、`anchor-size()` によって少なくともフィールドと同じ幅を確保します。基準となるのはキャレットやボタンではなくフィールド全体です。寸法の計測は不要で、同じページに複数のコンボボックスがあっても互いに干渉しません。
- **開閉ボタン**　`combobox-toggle` はフィールドの端にある小さなボタンで、山形アイコンを入れます。フィールドが `aria-expanded="true"` の間は、山形アイコンの向きが反転します。
- **空の状態**　すべての選択肢が `hidden` になると、`listbox-empty` が自動で表示されます。
- **フィールドの状態**　ホバー、フォーカス、無効な入力、操作不可の各状態は、入力グループが管理します。

アンカー位置指定に対応していないブラウザーでも、リストボックスは開きます。その場合はマークアップ上の位置どおりフィールドの直下に、リストボックス自身の幅で表示されます。

## ビヘイビア \{#behavior\}

`combobox` は、`combobox` クラスを持つルート要素とオプションのオブジェクトを受け取り、ビヘイビアを解除する関数を返します。フィールドは `role="combobox"`、リストは `role="listbox"` で探します。`filter` オプションの既定は true です。`filter: false` を指定すると、[オートコンプリート](#autocomplete)の例のように選択肢をページ側に任せます。`name`、`removeLabel`、`draw` は[複数の値](#several-values)に関するオプションです。

```js name=app.js
import { combobox } from '@master/ui/behaviors/combobox.js'

const box = combobox(document.querySelector('.combobox'))
box.value // what the chosen option stands for, or null
box.query // the text in the field
```

返される関数には 2 つのプロパティがあり、外部から読み取りと設定ができます。どちらを設定してもイベントは発行されません。

- **`value`**　選択した選択肢が表す値で、その `data-value` またはテキストです。フィールドにテキストがあり、選択が確定していない間は null です。設定すると、その選択肢にチェックを付け、そのテキストをフィールドに書き込みます。
- **`query`**　フィールドのテキストで、読者が探しているものです。値とは異なり、キーを押すたびに変わり、選択肢を選ぶとその選択肢のテキストになります。設定するとフィールドに書き込まれ、文字入力時と同じように選択肢が絞り込まれます。

- **文字入力**　大文字と小文字を区別せず、テキストに入力文字列を含まない選択肢に `hidden` を設定します。リストを開き、最初に一致した選択肢をアクティブにします。
- **アクティブな選択肢**　アクティブな選択肢には `aria-selected="true"` が付き、フィールドの `aria-activedescendant` がその選択肢を参照します。フォーカスはフィールドに留まります。
- **選択の確定**　<kbd>Enter</kbd> またはポインターで確定すると、選択肢のテキストから `listbox-description` と `listbox-end` を除いた内容がフィールドに入ります。確定した選択肢を `aria-checked="true"`、残りを `false` にして、リストを閉じます。確定した値を上書き入力すると、その選択肢のチェック状態が解除されます。
- **開閉**　リストボックスは `popover="manual"` なので、フィールドへの入力やフィールド内のクリックで開いているリストが閉じることはありません。フィールドや開閉ボタンをクリックするか、矢印キーを押すと開きます。<kbd>Esc</kbd> を押すか、フォーカスがコンボボックスの外に移ると閉じます。`aria-expanded` は開閉状態に合わせて更新されます。
- **イベント**　選択肢を確定すると、文字入力時と同様に、フィールドが `input`、`change` の順にイベントを発行します。値はフィールドの `value` で取得できます。

無効または非表示の選択肢はスキップされます。入力メソッドで文字が未確定の間は、<kbd>Enter</kbd> と矢印キーを入力メソッドが処理します。

ビヘイビアを適用しない場合、フィールドは通常のテキスト入力として機能します。値は入力できますが、リストは開きません。

## 複数の値 \{#several-values\}

`aria-multiselectable="true"` を指定したリストボックスでは、複数の値を選べます。その場合、フィールドは[タグ入力](/components/tags)と同様に `input-group-wrap` を指定した入力グループになり、選択した各選択肢がフィールドの前に[チップ](/components/chip)として並びます。選択肢を選ぶとチェックが切り替わり、フィールドは空になり、リストは開いたままになります。そのため、少ないキー操作で次の値を選べます。選択肢のチェックは維持されるため、チップと同様にリストでも何が選ばれているかがわかります。

- **フィールドは検索専用**　文字を入力するとリストが絞り込まれますが、チェックが外れることはありません。選択した値はチップが保持します。

- **値**　選択した値を、選択した順に並べたものです。

値をリストから選ぶのではなく自由に入力する場合は、[タグ入力](/components/tags)を使います。

## オートコンプリート \{#autocomplete\}

一致する候補をサーバーやページ独自の検索から取得する場合は、`filter: false` を指定してビヘイビアを適用します。ビヘイビアは何も非表示にしません。フィールドの `input` のたびに `query` を読み取って検索し、一致した候補をリストの選択肢として書き込みます。入力から遅れて届いた選択肢にもアクティブな選択肢が設定されるため、<kbd>Enter</kbd> と矢印キーで操作できます。

  var cities = ['Amsterdam', 'Athens', 'Auckland', 'Bangkok', 'Barcelona', 'Berlin', 'Bogotá', 'Boston', 'Brussels', 'Buenos Aires', 'Cairo', 'Cape Town', 'Chicago', 'Copenhagen', 'Dublin', 'Frankfurt', 'Helsinki', 'Hong Kong', 'Istanbul', 'Lisbon', 'London', 'Los Angeles', 'Madrid', 'Melbourne', 'Mexico City', 'Montreal', 'Mumbai', 'Nairobi', 'New York', 'Oslo', 'Paris', 'Prague', 'Rome', 'San Francisco', 'Santiago', 'São Paulo', 'Seoul', 'Singapore', 'Stockholm', 'Sydney', 'Taipei', 'Tokyo', 'Toronto', 'Vienna', 'Warsaw', 'Zurich']
  var box = MasterUI.combobox(root, { filter: false })

  // Stands for a request to a server: the cities that start with the query, a moment later.
  function search(query) {
    return new Promise(function (resolve) {
      setTimeout(function () {
        var text = query.trim().toLowerCase()
        resolve(cities.filter(function (city) { return city.toLowerCase().startsWith(text) }).slice(0, 6))
      }, 120)

      option.setAttribute('role', 'option')
      option.setAttribute('aria-checked', 'false')
      option.textContent = city
      list.insertBefore(option, list.querySelector('.listbox-empty'))

    // A choice says input too; its text is the option's, with nothing more to look for.

    search(box.query).then(function (matches) {
      // An answer to an older query that arrives late is dropped.
      if (ticket === asked) write(matches)
    })
  })
  search('').then(write)

- **イベントではなく `query` を読み取る**　クエリはフィールドのテキストです。`query` は、読者が入力した場合もフレームワークが書き込んだ場合も同じように読み取れます。
- **選択でも `input` が発行される**　そのときのテキストは選択した選択肢のもので、`value` は null ではなくなります。検索する必要はなく、この時点で新しい選択肢を書き込むと、選択した選択肢が消えてしまいます。
- **応答の順序は前後する**　最新のクエリに対する応答だけを使います。
- **空の状態はスタイルシートが担う**　リストに選択肢がない間は、`listbox-empty` が自動で表示されます。

React、Svelte、Vue では、コンポーネントの `query` と `onQueryChange`（Svelte ではバインド可能な `query`、Vue では `v-model:query`）が同じテキストを受け渡します。そのテキストで検索し、一致した候補を `options` として渡し、`filter` を false にします。

マークアップで非表示にした選択肢は、ラベルが検索語に一致したときも検索欄を空にしたときも非表示のままです。アプリ側で検索結果を用意する場合は `filter: false` を指定します。

## コントロールの選び方 \{#choosing-a-control\}

単純な選択肢が 12 個程度までなら、[セレクト](/components/select)を使うと、スクリプトなしでプラットフォーム標準の文字入力による候補選択が使えます。検索が必要な長いリスト、入力に応じて候補を読み込むリスト、複数の要素を含む行には、コンボボックスを使います。

## キーボード操作 \{#keyboard\}

キー操作はビヘイビアが処理します。リストが閉じているときや、<kbd>Shift</kbd> を押しているときは、通常の入力欄と同様に <kbd>Home</kbd> と <kbd>End</kbd> でキャレットを移動できます。アクティブな選択肢がないときは <kbd>Enter</kbd> の既定の動作が維持され、フォームを送信できます。

## アクセシビリティ \{#accessibility\}

- 入力欄には `role="combobox"`、リストボックスを参照する `aria-controls`、`aria-autocomplete="list"`、`aria-expanded` を指定します。
- フォーカスは入力欄に留まり、アクティブな選択肢は `aria-activedescendant` を通じて読み上げられます。
- フィールドから矢印キーでリストを開けるため、開閉ボタンは `tabindex="-1"` で Tab キーの移動順序から外します。
- ブラウザーの入力候補がリストに重ならないように、`autocomplete="off"` を設定します。

## React、Svelte、Vue \{#frameworks\}

`combobox` コンポーネントは、選択肢のリストからこのマークアップを生成し、ビヘイビアを適用します。選択値の受け渡しにも対応します。`multiple` を指定すると値はリストになり、その値からチップを描画します。`group` を持つ選択肢は、その見出しの下に、`role="group"` を持ち `listbox-label` でラベル付けされた `listbox-group` 内に書き出されます。選択肢がすべて絞り込みで除外されたグループは、選択肢と一緒に非表示になります。値のほかにクエリも受け渡します。React では `query` と `onQueryChange`、Svelte ではバインド可能な `query` と `onQueryChange`、Vue では `v-model:query` を使います。クエリは読者の入力に合わせて、また選択時には値の後に外部へ通知されます。所有側が渡したクエリはフィールドに書き込まれ、選択肢を絞り込みます。`npx master-ui add combobox` でプロジェクトにコピーできます。コンポーネントの構成と使い方は [React、Svelte、Vue](/guide/frameworks) を参照してください。
