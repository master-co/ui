스와이프는 행을 옆으로 밀면 해당 행에서 수행할 수 있는 작업이 나타나는 컴포넌트입니다. 행은 두 위치에 멈추는 스크롤 영역입니다. 한쪽에는 행 전체 너비를 차지하는 콘텐츠가 있고, 다른 쪽에는 행의 끝 가장자리 뒤에 숨은 작업이 있습니다. 브라우저의 기본 스크롤을 사용하므로 손가락이나 트랙패드로 밀거나 <kbd>Tab</kbd> 키를 눌러 작업을 표시할 수 있으며, 스크립트가 필요하지 않습니다.

## 동작 방식 \{#how-it-works\}

`swipe`는 스크롤바가 없는 가로 스크롤 영역이며, 스크롤 스냅이 반드시 적용됩니다. `swipe-content`는 행 전체 너비를 차지하며 시작 가장자리에 스냅됩니다. 그 뒤에 오는 `swipe-actions`는 끝 가장자리에 스냅됩니다. 두 위치 사이에서 놓으면 더 가까운 위치에 멈추고, 반대 방향으로 스크롤하면 행이 닫힙니다.

콘텐츠는 불투명합니다. [볼록한 표면](/components/surface)과 카드가 제공하는 `--surface-color`에서 바탕 표면의 색을 가져오고, 드러난 오목한 영역에 짧은 그림자를 드리웁니다. 스크롤 기반 애니메이션을 지원하는 환경에서는 작업이 드러날 때 서서히 나타납니다. 그 외 환경에서는 애니메이션 없이 표시됩니다.

다른 행을 열어도 기존 행이 자동으로 닫히지 않으며, 작업을 눌러도 해당 행이 자동으로 제거되지 않습니다. 두 동작은 페이지에서 처리합니다. 스크립트로 행을 닫으려면 해당 행의 `scrollLeft` 값을 0으로 설정하세요.

## 작업 \{#actions\}

작업은 버튼이나 링크로 표시하며, 단어 하나를 쓰거나 단어 위에 [아이콘](/components/icon)을 배치합니다. 각 셀은 너비가 최소 72px이고 높이는 행과 같으므로, 행 높이에 관계없이 셀 전체가 터치 대상입니다. `swipe-action-danger`는 되돌릴 수 없는 작업으로, 전용 배경색 위에 위험을 나타내는 전경색으로 표시됩니다. 작업은 한두 개로 제한하고, 파괴적 작업은 맨 마지막에 배치하세요.

## 접근성 \{#accessibility\}

- **스와이프는 빠른 접근 수단이며, 같은 작업을 수행할 다른 방법도 반드시 제공해야 합니다.** 트랙패드 없이 마우스를 사용하는 사용자는 행을 가로로 스크롤할 수 없습니다. 포인터로도 같은 작업을 찾을 수 있게 하세요. 예를 들어 행에 [메뉴](/components/menu)를 두거나, 항목을 열었을 때 같은 작업을 제공할 수 있습니다.
- 작업에는 기본 버튼 요소를 사용하며, 각 버튼은 Tab 키 탐색 순서에 포함됩니다. 버튼이 포커스를 받으면 브라우저가 버튼이 보이도록 스크롤하므로 별도의 키보드 처리가 필요하지 않습니다. 포커스 윤곽선은 스크롤 영역에 잘리지 않도록 셀 안쪽에 그려집니다.
- 아이콘만 표시하는 작업에는 접근 가능한 이름이 필요합니다. 사용자가 텍스트를 읽고 작업을 찾으므로 아이콘 아래에 단어를 표시하는 편이 좋습니다.
- 파괴적 작업을 실행하기 전에 확인을 받거나, 실행한 뒤 [토스트](/components/toast)에서 실행을 취소할 수 있게 하세요.
