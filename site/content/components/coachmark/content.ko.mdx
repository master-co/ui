코치마크는 안내 투어의 한 단계입니다. 잉크색의 작은 카드가 컨트롤을 가리키며 그 기능을 설명합니다. 코치마크는 팝오버이므로 브라우저가 최상위 레이어에 표시하고 포커스를 카드 안으로 옮깁니다. CSS 앵커 위치 지정은 코치마크를 연 요소에 맞춰 카드를 배치하고 화살표가 해당 요소를 가리키게 합니다. 비컨은 간헐적으로 고리 효과를 내는 잉크색 점으로, 페이지에서 안내할 위치를 표시하며 코치마크를 여는 버튼 역할을 합니다. 투어는 `tour` 동작으로 여러 코치마크를 차례로 엽니다.

카드에는 [sheet-inverse](/components/surface)의 평평한 반전 표면을 적용합니다. moonstone 배경에는 잉크색을, obsidian 배경에는 진주색을 전경색으로 사용합니다. 이 표면은 일반 팝오버의 표면과 뒤쪽 페이지에서 뚜렷하게 구분되며, 화살표는 카드에 이음새 없이 이어집니다. 카드의 기본 [button](/components/button)은 실행할 동작을 강조합니다. 강조를 낮춘 버튼에는 카드의 잉크색을 쓰고, 호버 시에는 같은 색을 배경에 옅게 적용합니다.

## 구성 \{#anatomy\}

제목만 필수입니다.

| 클래스 | 내용 |
| --- | --- |
| `coachmark-count` | ‘4단계 중 2단계’와 같은 투어 진행 위치나 ‘새 기능’과 같은 짧은 문구를 한층 은은한 잉크색으로 표시 |
| `coachmark-title` | 단계 제목. 제목에 id를 지정하고 이를 참조해 코치마크에 접근성 이름을 부여하세요. |
| `coachmark-text` | 컨트롤의 기능을 설명하는 한두 문장 |
| `coachmark-actions` | 카드 하단에 배치하는 작은 버튼. 버튼이 여러 개면 ‘건너뛰기’와 같은 첫 버튼은 시작 쪽에 두고, ‘이전’, ‘다음’과 같은 나머지 버튼은 끝 쪽에 정렬합니다. |

동작 버튼은 카드 가장자리에서 12px 안쪽에 배치합니다. 작은 버튼의 둥근 모서리가 카드 모서리 안에 맞물리도록 카드의 모서리 반경은 버튼의 모서리 반경에 이 여백을 더한 값으로 설정합니다.

## 배치 \{#placement\}

코치마크는 기본적으로 자신을 연 요소의 아래쪽 중앙에 열리며, 화살표 끝은 그 요소에서 6px 떨어집니다. 아래쪽 공간이 부족하면 위쪽으로 전환됩니다. `coachmark-top`은 위쪽 공간을 우선 사용합니다. 화면 하단에 가까운 컨트롤이나 컨트롤의 위쪽 모서리에 놓인 비컨에 사용합니다. 첫 번째 예시에서는 비컨을 위쪽 모서리에 배치합니다.

화살표는 마크업에서 코치마크 바로 앞의 요소를 가리킵니다. 따라서 코치마크는 비컨이나 설명할 컨트롤 바로 뒤에 배치하세요. 투어에서는 단계의 대상 위에 놓이는 투어의 스포트라이트를 가리킵니다. 코치마크가 열려 있는 동안 화살표가 가리키는 요소가 앵커로 지정되고 화살표는 그 요소의 중앙을 따라갑니다. 뷰포트 가장자리 때문에 카드가 옆으로 밀려도 화살표는 앵커 중앙을 계속 가리키면서 카드의 둥근 모서리를 피합니다. 카드가 위아래로 전환되면 화살표도 카드의 반대쪽 가장자리로 이동합니다. 투어에서처럼 코치마크는 한 번에 하나만 열립니다.

## 비컨 \{#beacon\}

`coachmark-beacon`은 버튼에 표시되는 10px 점입니다. 점 둘레에는 배경 표면과 같은 색의 테두리가 있으며, 조작 영역은 24px이고 터치 화면에서는 44px입니다. 비컨은 `popovertarget` 속성으로 코치마크를 열며, 무엇을 여는지 알려 주는 `aria-label` 속성이 필요합니다. 비컨의 위치는 페이지에서 정합니다. `relative` 래퍼 안에서 `absolute` 유틸리티를 사용해 비컨을 컨트롤의 위쪽 모서리에 놓거나 컨트롤 옆에 같은 행으로 배치하세요.

비컨의 고리는 사용자의 시선을 끕니다. 비컨에 호버하거나 포커스가 있을 때, 코치마크가 열려 있을 때, 또는 동작 줄이기 설정이 켜져 있을 때는 고리가 움직이지 않고 점 둘레에 머뭅니다. 사용자가 해당 단계를 본 뒤에는 비컨을 제거하세요.

## 안내 투어 \{#tour\}

투어는 여러 코치마크를 차례로 열며, 각 코치마크는 자신이 설명하는 컨트롤을 기준으로 열립니다. 투어의 단계는 진행 순서대로 `coachmark-tour` 안에 두고, 각 단계에 `popover="manual"`을 지정하세요. 그러면 사용자가 안내 중인 컨트롤을 시험해 보는 등 페이지를 클릭해도 투어가 종료되지 않습니다. 단계는 `data-target`에 선택자를 지정해 대상을 정합니다. 지정하지 않으면 마크업에서 단계 바로 앞의 요소를 가리킵니다. 단계의 버튼은 `value`로 기능을 나타냅니다. `next`, `back`, `skip`을 사용하고, 마지막 단계에는 `done`을 사용합니다.

나머지는 `tour` [동작](/guide/behaviors)이 처리합니다. `command="--start"`가 있고 `commandfor`로 투어를 가리키는 버튼을 누르면 투어가 시작됩니다. 동작은 `showPopover({ source })`로 각 단계를 대상 기준으로 엽니다. 따라서 브라우저가 카드를 대상에 앵커로 연결하고 CSS가 배치하며, 포커스는 카드 안의 ‘다음’ 또는 ‘완료’ 버튼으로 이동합니다. 투어 안에 `coachmark-spotlight`가 있으면 먼저 대상 위에 엽니다. 단계가 마크업 어디에 있든 단계의 화살표는 스포트라이트를 가리킵니다.

투어는 이 예시처럼 설명하는 영역을 포함할 수도 있고, 단계와 스포트라이트만 담을 수도 있습니다. 단계는 문서 어디에 있든 대상을 찾습니다. 닫혀 있는 단계와 스포트라이트는 공간을 차지하지 않으므로, 투어 요소를 그대로 해당 행으로 사용할 수 있습니다.

## 기다리는 단계 \{#waiting\}

단계는 사용자의 조작이나 대상이 나타나기를 기다릴 수 있습니다.

- **사용자 조작.** `data-advance`가 있는 단계는 대상에서 발생하면 투어를 진행시키는 `click` 같은 이벤트를 지정합니다. 이런 단계에는 ‘다음’ 버튼을 두지 마세요. 사용자에게 직접 해 보도록 요청하고, 페이지가 반응하면 투어가 계속됩니다. ‘건너뛰기’와 <kbd>Esc</kbd>로는 여전히 나갈 수 있습니다.
- **나중에 나타나는 대상.** 단계의 대상이 페이지에 없거나 렌더링되지 않았다면 단계는 대상을 기다리다가 나타나는 즉시 열립니다. 버튼을 눌러야 나타나는 필드나 아직 로딩 중인 행이 그 예입니다. 3초 또는 동작에 지정한 `wait` 시간이 지나도 대상이 나타나지 않으면 해당 단계를 건너뛰며, 마지막 단계를 지나면 투어가 완료됩니다. 투어는 아무것도 가리키지 않는 카드에서 멈추지 않습니다. 표시되지 못할 수도 있는 단계에는 그 단계 없이도 찾을 수 있는 내용만 담으세요.

## 스포트라이트 \{#spotlight\}

`coachmark-spotlight-dim`은 [대화 상자](/components/dialog)의 배경막으로 단계의 대상 주변 페이지를 어둡게 하고, 대상과 그 둘레의 4px 여백은 밝게 남깁니다. 밝은 영역의 모서리는 컨트롤의 모서리 반경에 이 여백을 더한 값입니다. 배경막은 화면만큼 넓은 그림자 고리이며, 앵커 위치 지정으로 대상 위에 놓인 스포트라이트가 그립니다. 따라서 페이지를 스크롤해도 대상을 따라갑니다. 투어가 시작되면 서서히 나타나고 끝나면 서서히 사라지며, 단계를 넘길 때는 밝은 영역이 바로 이동합니다.

배경막은 벽이 아니라 칠일 뿐입니다. 그 아래의 페이지는 여전히 포인터와 키보드에 반응하므로, 사용자는 단계가 가리키는 기능을 시험해 볼 수 있고 투어는 사용자의 다른 작업을 방해하지 않습니다. 시선을 이끌어야 하는 화면의 첫 투어에 사용하고, 새 컨트롤 하나에 대한 팁에는 사용하지 마세요.

## 동작 \{#behavior\}

`tour`는 `coachmark-tour` 클래스가 있는 루트 요소를 받아, 연결한 동작을 해제하는 함수를 반환합니다. `@master/ui/behaviors`의 `attach()`는 페이지의 모든 투어를 찾아 연결합니다.

```js name=app.js
import { tour } from '@master/ui/behaviors/tour.js'

const root = document.querySelector('#deploys-tour')
const deploys = tour(root)

deploys.value = 0 // starts the tour, as the button does
root.addEventListener('end', (event) => {
  if (event.detail.completed) localStorage.setItem('deploys-tour', 'seen')
})
```

- **값**은 투어가 표시 중인 단계의 인덱스(0부터 시작)이며, 투어가 실행 중이 아니면 `null`입니다. 단계를 열려면 인덱스를 설정하고, 투어를 끝내려면 `null`로 설정하세요. 이때 이벤트는 발행하지 않습니다.
- **이벤트.** 투어가 다른 단계로 이동할 때마다 루트는 `detail.value`에 인덱스를 담아 버블링되는 `change`를 발생시킵니다. 사용자가 투어를 끝내면 `null`을 담은 `change`를 발생시킨 뒤 `end`를 발생시킵니다. `end`의 `detail.completed`는 사용자가 마지막 단계까지 진행했으면 true이고, ‘건너뛰기’, <kbd>Esc</kbd> 등 단계를 닫는 다른 방법으로 그 전에 나갔으면 false입니다.
- **포커스**는 각 단계가 열릴 때 단계 안으로 이동합니다. `autofocus`가 있는 동작 버튼으로, 없으면 ‘다음’ 또는 ‘완료’ 버튼으로, 그것도 없으면 단계 자체로 이동합니다. 투어가 끝나면 포커스는 투어를 시작할 때 있던 위치로 돌아갑니다. 단, 그사이 사용자가 포커스를 페이지 안의 다른 곳으로 옮겼다면 돌아가지 않습니다.
- **옵션.** `target(step, index)`는 단계의 대상을 찾는 함수로, 대상을 페이지가 직접 관리할 때 사용합니다. `wait`는 단계가 대상을 기다리는 시간(밀리초)이며 기본값은 3000입니다.
- **호출 명령.** 브라우저가 `command`와 `commandfor`를 지원하지 않으면 동작이 시작 버튼의 클릭을 직접 감지합니다.

동작이 없으면 투어를 시작할 수 없습니다. 단계는 닫힌 상태로 남고, 페이지는 단계 없이도 온전합니다. `end` 이벤트로 사용자가 투어를 마쳤는지 기억해 두고, 투어를 다시 자동으로 시작하지 마세요. 나중에 찾을 수 있는 버튼에서 투어를 제공하세요.

## 접근성 \{#accessibility\}

- 코치마크에 `role="dialog"`를 지정하고 `aria-labelledby`로 제목을 참조해 접근성 이름을 부여하세요. 코치마크는 비모달이므로 열린 상태에서도 주변 페이지를 사용할 수 있으며, 투어에서는 스포트라이트 아래의 페이지도 사용할 수 있습니다.
- 비컨으로 여는 코치마크에서는 주 동작 버튼에 `autofocus` 속성을 지정하세요. 카드가 열리면 포커스가 카드 안으로 이동하고, 키보드에서 <kbd>Enter</kbd>를 눌러 계속 진행할 수 있습니다. 투어의 단계에서는 동작이 포커스를 옮깁니다.
- 모든 단계에서 ‘건너뛰기’ 또는 ‘완료’ 버튼이나 <kbd>Esc</kbd>로 나갈 수 있습니다. 단일 코치마크는 바깥을 클릭해서 닫을 수도 있습니다.
- 투어는 버튼을 누르는 등 사용자가 직접 조작할 때 시작하고, 페이지가 로드될 때 시작하지 마세요. 투어는 도움말이므로 사용자가 하려던 작업에서 포커스를 빼앗아서는 안 됩니다.
- 투어에서 안내하는 정보는 투어 밖에서도 찾을 수 있게 하세요. 사용자가 투어 전체를 건너뛰거나 일부 단계가 건너뛰어져도 놓치는 정보가 없어야 합니다.
- 코치마크를 마크업에서 비컨 바로 뒤에 배치하면, 카드가 화면 어디에 표시되든 탭 순서에서 비컨 바로 다음에 옵니다.

## React, Svelte, Vue \{#frameworks\}

`tour` 컴포넌트는 데이터의 항목마다 제목, 텍스트, 진행 위치, 필요한 동작 버튼을 갖춘 단계를 하나씩 작성하고, 열린 단계의 인덱스를 주고받으며, 투어가 끝나면 `onEnd`로 알립니다. 단계의 대상은 선택자, 요소, ref 또는 대상을 찾는 함수로 지정합니다. `npx master-ui add tour`로 프로젝트에 복사하세요. 컴포넌트의 구성과 사용법은 [React, Svelte, Vue](/guide/frameworks)에서 확인할 수 있습니다.

## 브라우저 지원 \{#browser-support\}

코치마크는 CSS 앵커 위치 지정으로 배치합니다. 카드에는 `position-area`와 `position-try-fallbacks`를 사용하고, 화살표와 투어의 스포트라이트를 배치할 때는 카드와 화살표가 가리키는 요소 사이에 `anchor()`를 사용합니다. 앵커 위치 지정을 지원하지 않는 브라우저에서도 카드는 열리고 닫힙니다. 이때 카드는 브라우저의 기본 팝오버 위치인 뷰포트 중앙에 표시되고 화살표는 표시되지 않습니다. 스포트라이트는 대상을 밝게 남길 수 없으므로 아무것도 어둡게 하지 않습니다. `showPopover()`의 `source` 옵션으로 투어 단계에 앵커를 지정할 수 있습니다. 이 옵션이 없으면 단계가 앵커 없이 열립니다. 시작 버튼은 호출 명령을 사용하며, 이를 지원하지 않는 브라우저에서는 동작이 대신 처리합니다. 페이드와 짧은 슬라이드에는 `@starting-style` 규칙을 사용합니다. 이를 지원하지 않으면 카드와 배경막이 즉시 나타나고 사라집니다.

카드가 열릴 때는 서서히 나타나며 앵커 쪽으로 4px 이동하고, 닫힐 때는 더 짧은 페이드로 사라집니다. 다른 팝오버에서 사용하는 크기 전환을 카드에 적용하면 화살표가 카드 안쪽에 머물러 대상 요소 쪽으로 충분히 뻗지 못하므로, 코치마크의 크기는 전환 중에도 일정하게 유지합니다.
