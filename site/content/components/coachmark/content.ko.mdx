코치마크는 안내 투어의 한 단계입니다. 잉크색의 작은 카드가 컨트롤을 가리키며 그 기능을 설명합니다. 코치마크는 팝오버이므로 브라우저가 최상위 레이어에 표시하고 포커스를 카드 안으로 옮깁니다. CSS 앵커 위치 지정은 코치마크를 연 요소에 맞춰 카드를 배치하고 화살표가 해당 요소를 가리키게 합니다. 비컨은 간헐적으로 고리 효과를 내는 잉크색 점으로, 페이지에서 안내할 위치를 표시하며 코치마크를 여는 버튼 역할을 합니다.

카드에는 [sheet-inverse](/components/surface)의 평평한 반전 표면을 적용합니다. moonstone에서는 잉크색을, obsidian에서는 진주색을 전경색으로 사용합니다. 이 표면은 일반 팝오버의 표면과 뒤쪽 페이지에서 뚜렷하게 구분되며, 화살표는 카드에 이음새 없이 이어집니다. 카드의 기본 [button](/components/button)은 실행할 동작을 강조합니다. 강조를 낮춘 버튼에는 카드의 잉크색을 쓰고, 호버 시에는 같은 색을 배경에 옅게 적용합니다.

## 구성 \{#anatomy\}

제목만 필수입니다.

| 클래스 | 내용 |
| --- | --- |
| `coachmark-count` | ‘4단계 중 2단계’와 같은 투어 진행 위치나 ‘새 기능’과 같은 짧은 문구를 한층 은은한 잉크색으로 표시 |
| `coachmark-title` | 단계 제목. 제목에 id를 지정하고 이를 참조해 코치마크에 접근성 이름을 부여하세요. |
| `coachmark-text` | 컨트롤의 기능을 설명하는 한두 문장 |
| `coachmark-actions` | 카드 하단에 배치하는 작은 버튼. 버튼이 여러 개면 ‘건너뛰기’와 같은 첫 버튼은 시작 쪽에 두고, ‘이전’, ‘다음’과 같은 나머지 버튼은 끝 쪽에 정렬합니다. |

동작 버튼은 카드 가장자리에서 12px 안쪽에 배치합니다. 작은 버튼의 둥근 모서리가 카드 모서리 안에 맞물리도록 카드의 모서리 반경은 버튼의 모서리 반경에 이 여백을 더한 값으로 설정합니다.

## 배치 \{#placement\}

코치마크는 기본적으로 자신을 연 요소의 아래쪽 중앙에 열리며, 화살표 끝은 그 요소에서 6px 떨어집니다. 아래쪽 공간이 부족하면 위쪽으로 전환됩니다. `coachmark-top`은 위쪽 공간을 우선 사용합니다. 화면 하단에 가까운 컨트롤이나 컨트롤의 위쪽 모서리에 놓인 비컨에 사용합니다. 첫 번째 예시에서는 비컨을 위쪽 모서리에 배치합니다.

화살표는 마크업에서 코치마크 바로 앞의 요소를 가리킵니다. 따라서 코치마크는 비컨이나 설명할 컨트롤 바로 뒤에 배치하세요. 코치마크가 열려 있는 동안 앞의 요소가 앵커로 지정되고 화살표는 그 요소의 중앙을 따라갑니다. 뷰포트 가장자리 때문에 카드가 옆으로 밀려도 화살표는 앵커 중앙을 계속 가리키면서 카드의 둥근 모서리를 피합니다. 카드가 위아래로 전환되면 화살표도 카드의 반대쪽 가장자리로 이동합니다. 투어에서처럼 코치마크는 한 번에 하나만 열립니다.

## 비컨 \{#beacon\}

`coachmark-beacon`은 버튼에 표시되는 10px 점입니다. 점 둘레에는 배경 표면과 같은 색의 테두리가 있으며, 조작 영역은 24px이고 터치 화면에서는 44px입니다. 비컨은 `popovertarget` 속성으로 코치마크를 열며, 무엇을 여는지 알려 주는 `aria-label` 속성이 필요합니다. 비컨의 위치는 페이지에서 정합니다. `relative` 래퍼 안에서 `absolute` 유틸리티를 사용해 비컨을 컨트롤의 위쪽 모서리에 놓거나 컨트롤 옆에 같은 행으로 배치하세요.

비컨의 고리는 사용자의 시선을 끕니다. 비컨에 호버하거나 포커스가 있을 때, 코치마크가 열려 있을 때, 또는 동작 줄이기 설정이 켜져 있을 때는 고리가 움직이지 않고 점 둘레에 머뭅니다. 사용자가 해당 단계를 본 뒤에는 비컨을 제거하세요.

## 안내 투어 \{#tour\}

투어는 여러 코치마크를 차례로 여는 방식으로 구성합니다. 각 단계에 `popover="manual"`을 지정하면 사용자가 안내 중인 컨트롤을 시험해 보는 등 페이지를 클릭해도 투어가 종료되지 않습니다. 짧은 스크립트로 단계 이동을 처리하세요. `showPopover({ source })`를 호출하면 마크업에서 해당 단계 바로 앞의 요소에 맞춰 코치마크가 열리고, 단계의 동작 버튼은 이를 호출해 다음 단계나 이전 단계를 엽니다. 수동 팝오버는 <kbd>Esc</kbd>를 눌러도 자동으로 닫히지 않으므로, 스크립트에서 팝오버를 닫고 투어를 시작한 위치로 포커스를 돌려보내세요.

## 접근성 \{#accessibility\}

- 코치마크에 `role="dialog"`를 지정하고 `aria-labelledby`로 제목을 참조해 접근성 이름을 부여하세요. 코치마크는 비모달이므로 열린 상태에서도 주변 페이지를 사용할 수 있습니다.
- 주 동작 버튼에 `autofocus` 속성을 지정하세요. 카드가 열리면 포커스가 카드 안으로 이동하고, 키보드에서 <kbd>Enter</kbd>를 눌러 계속 진행할 수 있습니다.
- 모든 단계에서 ‘건너뛰기’ 또는 ‘완료’ 버튼이나 <kbd>Esc</kbd>로 나갈 수 있습니다. 단일 코치마크는 바깥을 클릭해서 닫을 수도 있습니다.
- 투어에서 안내하는 정보는 투어 밖에서도 찾을 수 있게 하세요. 투어를 건너뛴 사용자도 놓치는 정보가 없어야 합니다.
- 코치마크를 마크업에서 비컨 바로 뒤에 배치하면, 카드가 화면 어디에 표시되든 탭 순서에서 비컨 바로 다음에 옵니다.

## 브라우저 지원 \{#browser-support\}

코치마크는 CSS 앵커 위치 지정으로 배치합니다. 카드에는 `position-area`와 `position-try-fallbacks`를 사용하고, 화살표를 배치할 때는 카드와 화살표가 가리키는 요소 사이에 `anchor()`를 사용합니다. 앵커 위치 지정을 지원하지 않는 브라우저에서도 카드는 열리고 닫힙니다. 이때 카드는 브라우저의 기본 팝오버 위치인 뷰포트 중앙에 표시되고 화살표는 표시되지 않습니다. `showPopover()`의 `source` 옵션으로 투어 단계에 앵커를 지정할 수 있습니다. 이 옵션이 없으면 단계가 앵커 없이 열립니다. 페이드와 짧은 슬라이드에는 `@starting-style` 규칙을 사용합니다. 이를 지원하지 않으면 카드가 즉시 나타나고 사라집니다.

카드가 열릴 때는 서서히 나타나며 앵커 쪽으로 4px 이동하고, 닫힐 때는 더 짧은 페이드로 사라집니다. 다른 팝오버에서 사용하는 크기 전환을 카드에 적용하면 화살표가 카드 안쪽에 머물러 대상 요소 쪽으로 충분히 뻗지 못하므로, 코치마크의 크기는 전환 중에도 일정하게 유지합니다.
