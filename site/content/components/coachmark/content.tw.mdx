導覽提示是操作導覽中的一個步驟，用一張小卡片指向控制項並說明其用途。它是彈出面板，因此瀏覽器會將它放在頂層，並把焦點移入其中。CSS 錨點定位會將卡片放在開啟它的元素旁，並以箭頭指向該元素。提示點是個不時向外擴散圓環的小圓點，用來標示頁面上的位置，也是開啟卡片的按鈕。操作導覽則透過 `tour` 行為依序開啟多則導覽提示。

卡片以平面樣式呈現 [sheet-inverse](/components/surface) 的反相配色，在月長石色底上用墨色，在黑曜石色底上用珍珠色，因此能與一般彈出面板及下方頁面區隔，箭頭也與卡片無縫相接。卡片上的預設[按鈕](/components/button)清楚標示可執行的動作。低調樣式的按鈕沿用卡片的前景色，指標停留時則以該色的淡色調作為底色。

## 結構 \{#anatomy\}

只有標題是必填項目。

| 類別 | 內容 |
| --- | --- |
| `coachmark-count` | 以較低調的前景色顯示導覽進度，例如「第 2 步，共 4 步」，也可顯示「新功能」之類的字樣 |
| `coachmark-title` | 步驟標題。為它設定 id，並用它標示導覽提示 |
| `coachmark-text` | 用一兩句話說明控制項的用途 |
| `coachmark-actions` | 卡片底部的小按鈕。有多個按鈕時，第一個（例如「略過」）靠起始端，其餘（例如「上一步」和「下一步」）靠結束端排列 |

操作按鈕與卡片邊緣相距 12px，讓小按鈕的圓角與卡片圓角相襯。卡片的圓角半徑等於按鈕的圓角半徑加上這段內距。

## 位置 \{#placement\}

導覽提示預設在觸發元素正下方置中開啟，箭頭尖端距離該元素 6px。下方空間不足時，卡片會翻到上方。`coachmark-top` 優先使用上方空間，適合靠近畫面底部的控制項，或像第一個範例那樣把提示點放在控制項的上角。

箭頭會指向標記中緊接在導覽提示前面的元素，因此請把導覽提示放在提示點或所要說明的控制項之後；在操作導覽中，箭頭則指向導覽的聚光燈，聚光燈會覆蓋在該步驟的目標上。導覽提示開啟時，該元素會成為具名錨點，箭頭會對準其中央。即使檢視區邊緣把卡片推向一旁，箭頭也會維持對準，同時避開卡片的圓角。卡片翻轉時，箭頭會移到另一側。和操作導覽一樣，一次只會開啟一則導覽提示。

## 提示點 \{#beacon\}

`coachmark-beacon` 是按鈕上直徑 10px 的圓點，外框沿用所在表面的顏色，可點按範圍為 24px，在觸控螢幕上為 44px。它透過 `popovertarget` 開啟對應的導覽提示，並需要用 `aria-label` 說明會開啟什麼。提示點的位置由頁面決定。可在 `relative` 包裝元素內使用 `absolute` utility，將提示點放在控制項的上角，也可將兩者並排。

提示點以向外擴散的圓環吸引注意。指標停在提示點上、提示點取得焦點、對應的導覽提示開啟，或使用者偏好減少動態效果時，圓環會維持為靜止的光暈。使用者看過該步驟後，請移除提示點。

## 操作導覽 \{#tour\}

操作導覽會依序開啟數則導覽提示，每則都以它所說明的控制項為錨點。將各步驟依進行順序放在 `coachmark-tour` 中，並為每個步驟設定 `popover="manual"`，讓使用者點擊頁面（例如試用步驟所指的控制項）時不會結束導覽。步驟以 `data-target` 中的選擇器指定目標；沒有指定時，會指向標記中緊接在它前面的元素。步驟的按鈕以 `value` 表示其作用：`next`、`back`、`skip`，最後一個步驟則用 `done`。

其餘工作由 `tour` [行為](/guide/behaviors)處理。帶有 `command="--start"` 且以 `commandfor` 指向導覽的按鈕會開始導覽；行為會用 `showPopover({ source })` 以目標為錨點開啟每個步驟，讓瀏覽器把卡片錨定在那裡並由 CSS 定位，再把焦點移入卡片中的「下一步」或「完成」。導覽中的 `coachmark-spotlight` 會先在目標上方開啟：無論步驟位在標記中的哪個位置，步驟的箭頭都會指向它。

## 等待中的步驟 \{#waiting\}

步驟可以等待讀者，也可以等待它的目標。

- **操作。** 帶有 `data-advance` 的步驟會指定目標上的某個事件（例如 `click`），觸發時導覽便繼續。不要給它「下一步」：它要求讀者親自操作，等頁面回應後導覽才會繼續。「略過」和 <kbd>Esc</kbd> 仍可離開。
- **稍後才出現的目標。** 當步驟的目標不在頁面中或尚未算繪時，步驟會等待它，並在它出現後立即開啟，例如由按鈕顯示的欄位，或仍在載入的列。目標在三秒後（或依行為的 `wait` 設定的時間）仍未出現時，該步驟會被跳過；越過最後一個步驟時，導覽即算完成。導覽不會停在一張什麼都沒指到的卡片上，而無法顯示的步驟所包含的內容，應該讓讀者不靠它也能找到。

## 聚光燈 \{#spotlight\}

`coachmark-spotlight-dim` 會用[對話框](/components/dialog)的遮罩讓步驟目標周圍的頁面變暗，並讓目標及其周圍 4px 保持明亮，圓角為控制項的圓角加上這段內距。遮罩是一圈與畫面同寬的陰影，由聚光燈繪製，錨點定位讓聚光燈維持在目標上方，因此頁面捲動時遮罩會跟著目標移動。導覽開始時遮罩淡入，結束時淡出；從一個步驟換到下一個步驟時，明亮的位置會直接移動。

遮罩只是視覺效果，並不會阻擋操作：底下的頁面仍會回應指標和按鍵，讀者可以試用步驟所指的控制項，導覽也不會妨礙他們做其他事。第一次導覽某個畫面、需要引導視線時使用它；只是介紹一個新控制項的提示則不要使用。

## 行為 \{#behavior\}

`tour` 接收根元素（帶有 `coachmark-tour` 類別的元素），並回傳可卸載行為的函式。從 `@master/ui/behaviors` 匯入的 `attach()` 會找出頁面上的每個導覽。

```js name=app.js
import { tour } from '@master/ui/behaviors/tour.js'

const root = document.querySelector('#deploys-tour')
const deploys = tour(root)

deploys.value = 0 // starts the tour, as the button does
root.addEventListener('end', (event) => {
  if (event.detail.completed) localStorage.setItem('deploys-tour', 'seen')
})
```

- **值**是導覽目前所在步驟的索引，從 0 開始；導覽未執行時為 `null`。設定它可開啟某個步驟，設為 `null` 則結束導覽；這兩種做法都不會派送事件。
- **事件。** 每當導覽移到另一個步驟，根元素都會派送可向上冒泡的 `change` 事件，索引放在 `detail.value`。讀者結束導覽時，會先派送值為 `null` 的 `change`，再派送 `end`；讀者走完最後一個步驟時，其 `detail.completed` 為 true，在那之前透過「略過」、<kbd>Esc</kbd> 或其他關閉步驟的方式離開時則為 false。
- **焦點**會在每個步驟開啟時移入其中：移到帶有 `autofocus` 的操作，否則移到「下一步」或「完成」，再否則移到步驟本身。導覽結束時，焦點會回到導覽開始時的位置，除非讀者之後已把焦點移到頁面中的其他地方。
- **選項。** `target(step, index)` 會找出步驟的目標，適用於自行持有目標的頁面；`wait` 是步驟等待目標的時間，單位為毫秒，預設為 3000。
- **觸發指令。** 瀏覽器不支援 `command` 和 `commandfor` 時，行為會自行監聽開始按鈕的點擊。

沒有行為時，導覽不會開始；步驟保持關閉，頁面少了它們依然完整。請從 `end` 事件記住讀者已看完導覽，之後不要再自動開始：改由讀者日後找得到的按鈕提供。

## 無障礙 \{#accessibility\}

- 為導覽提示設定 `role="dialog"`，並透過 `aria-labelledby` 以其標題作為名稱。這是非模態對話框，使用者仍可操作周圍的頁面；在操作導覽中，聚光燈下的頁面也一樣。
- 在由提示點開啟的導覽提示的主要操作按鈕上加上 `autofocus`，讓卡片開啟時焦點移入其中，使用者便可按 <kbd>Enter</kbd> 繼續。操作導覽的步驟則由行為移入焦點。
- 每個步驟都應能退出，可透過「略過」或「完成」按鈕，也可按 <kbd>Esc</kbd>。單則導覽提示還可透過點擊外部關閉。
- 從讀者的操作開始導覽，例如按下按鈕，絕不要在頁面載入時開始：導覽是輔助說明，不應搶走讀者原本要處理的工作的焦點。
- 導覽中的所有資訊都應能從其他地方取得，讓略過導覽的使用者，或遇到步驟被跳過時，也不會錯過任何內容。
- 在標記中將導覽提示緊接在提示點之後，這樣無論卡片顯示在哪裡，Tab 鍵都會在提示點之後進入導覽提示。

## React、Svelte 和 Vue \{#frameworks\}

`tour` 元件會依資料中的每個項目寫出一個步驟，各含標題、文字、計數和所需的操作按鈕，並接收和傳出開啟中步驟的索引，以 `onEnd` 回報導覽結束。步驟的目標可以是選擇器、元素、ref，或找出目標的函式。使用 `npx master-ui add tour` 將元件複製到專案中；元件的實作方式與用法請見 [React、Svelte 和 Vue](/guide/frameworks)。

## 瀏覽器支援 \{#browser-support\}

導覽提示使用 CSS 錨點定位。卡片的位置由 `position-area` 和 `position-try-fallbacks` 決定，箭頭和操作導覽的聚光燈則使用 `anchor()` 相對於卡片與所指向的元素定位。瀏覽器若不支援錨點定位，導覽提示仍可開關，會依瀏覽器的彈出面板預設位置在檢視區置中顯示，並省略箭頭；聚光燈不會讓任何區域變暗，因為它無法讓目標保持明亮。`showPopover()` 的 `source` 選項為導覽步驟指定錨點。未提供此選項時，步驟會在沒有錨點的情況下開啟。開始按鈕使用觸發指令，瀏覽器不支援時由行為代為處理。淡入與短距離滑動使用 `@starting-style`，缺少支援時卡片和遮罩會立即出現或消失。

卡片進場時會淡入並朝錨點滑動 4px，退場時則以較短的時間淡出。卡片維持原尺寸，因為套用其他彈出面板的縮放效果會把箭頭縮進卡片範圍內，使箭頭無法伸向所指的元素。
