コーチマークは操作ガイドの1ステップです。インク色の小さなカードがコントロールを指し、その機能を説明します。ポップオーバーなので、ブラウザーがトップレイヤーに表示し、フォーカスを内部に移します。CSSアンカー配置で、開くきっかけとなった要素のそばに配置し、矢印でその要素を指します。ビーコンは、時折リングが広がるインク色の点で、ページ上の対象を示すとともに、コーチマークを開くボタンとして機能します。ツアーでは、`tour`ビヘイビアを使って複数のコーチマークを順に開きます。

カードは[反転シート](/components/surface)と同じ反転色の面を平らに表示します。moonstoneの背景にはインク色、obsidianの背景にはパール色を前景に使うため、通常のポップオーバーや背後のページと見分けやすくなります。矢印は継ぎ目なくカードにつながります。既定の[ボタン](/components/button)はアクションとして目立ち、控えめなボタンはカード上の文字色を使い、ホバー時はその色を淡く背景に重ねます。

## 構成 \{#anatomy\}

タイトル以外の各部は省略できます。

| クラス | 内容 |
| --- | --- |
| `coachmark-count` | 「全4ステップ中の2」のような進行状況や「新機能」などの短い語を、控えめな文字色で表示 |
| `coachmark-title` | ステップの見出し。IDを付け、コーチマークのラベルとして参照 |
| `coachmark-text` | コントロールの機能を説明する1〜2文 |
| `coachmark-actions` | 下部に並ぶ小さなボタン。複数ある場合は「スキップ」など最初のボタンを列の始端に、「戻る」「次へ」など残りを終端に寄せて配置 |

アクションはカードの端から12px内側に配置します。小さなボタンとカードの角が同心円状になるように、カードの角丸半径はボタンの角丸半径にこの余白を足した値になります。

## 配置 \{#placement\}

コーチマークは、開くきっかけとなった要素の真下に中央揃えで表示され、矢印の先端はその要素から6px離れます。下に十分な空間がなければ、上に切り替わります。`coachmark-top`は上側を優先します。画面下部のコントロールや、最初の例のようにコントロールの上隅にビーコンがある場合に使います。

矢印はマークアップ上でコーチマークの直前にある要素を指すため、コーチマークはビーコンか説明対象のコントロールの直後に置きます。ツアーでは、ステップの対象の上に重なるツアーのスポットライトを指します。表示中はその要素がアンカーとして指定され、矢印はその中央を追従します。カードがビューポートの端を避けてずれても対象を指し続け、カードの角丸を避け、カードの配置が反転すると反対側の辺に移ります。ツアーと同様、一度に開くコーチマークは1つです。

## ビーコン \{#beacon\}

`coachmark-beacon`はボタン上に表示する10pxの点で、配置先の面と同じ色の縁取りが付きます。操作領域は24px、タッチ画面では44pxです。`popovertarget`でコーチマークを開き、何が開くかを示す`aria-label`が必要です。配置はページ側で指定します。`relative`ラッパー内で`absolute`ユーティリティを使って対象のコントロールの上隅に置くか、同じ行で隣に並べます。

リングの動きでビーコンに注意を促します。ビーコンのホバー時やフォーカス時、コーチマークの表示中、動きを抑える設定が有効なときは、リングが静止した状態になります。読者がステップを確認したら、ビーコンを取り除きます。

## ツアー \{#tour\}

ツアーでは、複数のコーチマークを、それぞれが説明するコントロールに合わせて順に開きます。ステップは進む順に`coachmark-tour`内に置き、それぞれに`popover="manual"`を指定します。これにより、説明対象のコントロールを試すなど、ページ内をクリックしてもツアーが終了しません。ステップの対象は`data-target`にセレクターで指定します。指定がなければ、マークアップ上でステップの直前にある要素を指します。ステップのボタンは、`value`で役割を示します。`next`、`back`、`skip`、そして最後のステップでは`done`を使います。

残りは`tour` [ビヘイビア](/guide/behaviors)が担います。`command="--start"`を持ち、`commandfor`でツアーを指定したボタンでツアーを開始します。ビヘイビアは`showPopover({ source })`で各ステップを対象に合わせて開くため、ブラウザーがカードをそこにアンカーし、CSSが配置を決めます。さらに、フォーカスをステップ内の「次へ」または「完了」に移します。ツアー内に`coachmark-spotlight`がある場合は、まずそれを対象の上に開きます。ステップがマークアップ上のどこにあっても、ステップの矢印はこのスポットライトを指します。

ツアーには、この例のように説明対象の領域を含めることも、ステップとスポットライトだけを含めることもできます。ステップは文書内のどこにある対象でも見つけられます。閉じている間、ステップとスポットライトは場所を取らないため、ツアーの要素自体をそれが置かれた行として使えます。

ビーコンから開く単独のコーチマークには、これらはどれも必要ありません。`popover="auto"`なので、スクリプトなしで、外側のクリックや<kbd>Esc</kbd>でブラウザーが閉じ、フォーカスをビーコンに戻します。

## 待機するステップ \{#waiting\}

ステップは、読者の操作や対象の出現を待つことができます。

- **操作。** `data-advance`を持つステップは、ツアーを先に進める対象のイベント（`click`など）を指定します。このステップには「次へ」を置きません。読者自身に操作を促し、ページが応答した時点でツアーが進みます。「スキップ」や<kbd>Esc</kbd>では引き続き終了できます。
- **後から現れる対象**。ステップの対象がページ内にない場合や描画されていない場合、ステップは対象を待ち、現れるとすぐに開きます。ボタンで表示されるフィールドや、読み込み中の行などが該当します。3秒後（またはビヘイビアに渡した`wait`の時間が経過した後）も現れない対象のステップは飛ばされ、最後のステップを過ぎるとツアーは完了します。何も指していないカードでツアーが止まることはありません。表示できない可能性のあるステップには、それがなくても読者が見つけられる内容だけを含めてください。

## スポットライト \{#spotlight\}

`coachmark-spotlight-dim`は、[ダイアログ](/components/dialog)と同じ背景幕でステップの対象の周囲を暗くし、対象とその周囲4pxを明るいまま残します。明るい部分の角は、コントロールの角丸にこの余白を足した値です。背景幕は画面全体に広がる影のリングで、アンカー配置で対象の上に重なるスポットライトが描画します。そのため、ページをスクロールしても対象に追従します。ツアーの開始時にフェードインし、終了時にフェードアウトします。ステップ間では、明るい部分が即座に移動します。

背景幕は見た目を塗るだけで、操作を遮る壁ではありません。下にあるページは引き続きポインターやキー操作に反応するため、読者はステップが指すものを試せますし、ツアーがほかの操作の妨げになることもありません。画面の最初のツアーなど、視線を導く必要がある場合に使い、新しいコントロール1つについてのヒントには使わないでください。

## ビヘイビア \{#behavior\}

`tour`は、`coachmark-tour`クラスを持つルート要素を受け取り、ビヘイビアを解除する関数を返します。`@master/ui/behaviors`の`attach()`は、ページ内のすべてのツアーを見つけます。

```js name=app.js
import { tour } from '@master/ui/behaviors/tour.js'

const root = document.querySelector('#deploys-tour')
const deploys = tour(root)

deploys.value = 0 // starts the tour, as the button does
root.addEventListener('end', (event) => {
  if (event.detail.completed) localStorage.setItem('deploys-tour', 'seen')
})
```

- **値**は、ツアーが表示しているステップの0から始まるインデックスで、ツアーが実行されていない間は`null`です。値を設定するとそのステップが開き、`null`を設定するとツアーが終了します。このときイベントは発行されません。
- **イベント**。ツアーが別のステップに移るたびに、ルートはバブリングする`change`を発行し、`detail.value`にインデックスを入れます。読者がツアーを終えると、`null`を値とする`change`を発行した後に`end`を発行します。`end`の`detail.completed`は、読者が最後のステップまで進んだ場合はtrue、「スキップ」、<kbd>Esc</kbd>、その他ステップを閉じる操作でそれより前に離れた場合はfalseです。
- **フォーカス**は、各ステップが開くとその内部に移ります。移動先は`autofocus`を持つアクション、なければ「次へ」または「完了」、それもなければステップ自体です。ツアーが終わると、読者がその後フォーカスをページ内に移していない限り、ツアー開始時の位置にフォーカスが戻ります。
- **オプション。** `target(step, index)`はステップの対象を見つける関数で、ページ側で対象を管理する場合に使います。`wait`はステップが対象を待つ時間で、単位はミリ秒、既定は3000です。
- **呼び出しコマンド**。ブラウザーが`command`と`commandfor`に対応していない場合は、ビヘイビアが開始ボタンのクリックを直接受け取ります。

ビヘイビアがなければツアーは開始されません。ステップは閉じたままで、ページはそれらがなくても完全に機能します。`end`イベントで読者がツアーを終えたことを記録し、同じツアーを自動で再び開始しないでください。後から見つけられるボタンから開始できるようにします。

## アクセシビリティ \{#accessibility\}

- コーチマークに`role="dialog"`を指定し、`aria-labelledby`でタイトルをラベルとして参照します。コーチマークは非モーダルなので、表示中も周囲のページを操作できます。ツアーでは、スポットライトの下にあるページも操作できます。
- ビーコンから開くコーチマークでは、主アクションに`autofocus`を指定すると、カードを開いたときにフォーカスが内部に移り、キーボードの<kbd>Enter</kbd>で先に進めます。ツアーのステップには、ビヘイビアがフォーカスを移します。
- どのステップからでも、「スキップ」や「完了」などのアクション、または<kbd>Esc</kbd>で終了できます。単独のコーチマークは、外側をクリックしても閉じられます。
- ツアーは、ボタンなど読者の操作をきっかけに開始し、ページの読み込み時には開始しないでください。ツアーは補助であり、読者が本来の目的としている作業からフォーカスを奪うべきではありません。
- 読者がツアーをスキップしたり、途中のステップが飛ばされたりしても、説明内容をすべてツアー以外の場所で確認できるようにします。
- コーチマークをマークアップ上でビーコンの直後に置くと、カードの表示位置にかかわらず、Tabキーの移動順でもビーコンの次になります。

## React、Svelte、Vue \{#frameworks\}

`tour`コンポーネントは、データの各項目からステップを1つずつ生成し、それぞれにタイトル、テキスト、進行状況、必要なアクションを書き出します。開いているステップのインデックスを外部から受け取り、変更を外部に通知します。ツアーの終了は`onEnd`で受け取ります。ステップの対象には、セレクター、要素、ref、または対象を見つける関数を指定できます。`npx master-ui add tour`でプロジェクトにコピーできます。コンポーネントの構成と使い方は[React、Svelte、Vue](/guide/frameworks)を参照してください。

## ブラウザーの対応状況 \{#browser-support\}

コーチマークの配置にはCSSアンカー配置を使います。カードには`position-area`と`position-try-fallbacks`を使い、矢印とツアーのスポットライトにはカードと参照先の要素の間に`anchor()`を使います。アンカー配置に対応していないブラウザーでも開閉でき、通常のポップオーバーと同じくビューポート中央に表示されます。この場合、矢印は表示されません。スポットライトは対象を明るく残せないため、何も暗くしません。ツアーのステップには、`showPopover()`の`source`オプションでアンカーを指定します。このオプションがなければ、ステップはアンカーなしで開きます。開始ボタンは呼び出しコマンドを使い、未対応のブラウザーではビヘイビアが代わりを務めます。フェードと短いスライドには`@starting-style`を使います。対応していない場合、カードと背景幕はアニメーションなしで表示・非表示が切り替わります。

カードはフェードインしながらアンカーに向かって4px移動し、閉じるときはより短いフェードアウトで消えます。ほかのポップオーバーと違い、拡大・縮小は行いません。拡大・縮小すると矢印がカードの内側に収まり、指し示す要素に届かなくなるためです。
