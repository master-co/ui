引导提示是功能导览中的一个步骤，用一张采用墨色色调的小卡片指向控件并说明其用途。它采用弹出层，浏览器将其置于顶层并把焦点移入其中。CSS 锚点定位将卡片放在打开它的元素旁，并让箭头指向该元素。信标是一个不时向外扩散圆环的墨色圆点，既标出页面上的位置，也是打开引导提示的按钮。功能导览通过 `tour` 行为依次打开多个引导提示。

卡片在 moonstone 中使用墨色前景，在 obsidian 中使用珍珠色前景。它采用 [sheet-inverse](/components/surface) 的平坦反色表面，与普通弹出层的面板及下方页面区分开来，箭头与卡片无缝衔接。卡片上的默认 [按钮](/components/button) 突出操作，低强调按钮沿用卡片的前景色，指针悬停时以同一颜色淡淡着色。

## 组成 \{#anatomy\}

标题必填，其余部分可选。

| 类名 | 内容 |
| --- | --- |
| `coachmark-count` | 用较低对比度的前景色显示当前导览进度，例如“2 of 4”，也可显示一个词，例如“New” |
| `coachmark-title` | 步骤标题。为标题设置 id，并用它为引导提示提供无障碍名称 |
| `coachmark-text` | 用一两句话说明控件的用途 |
| `coachmark-actions` | 沿卡片底部排列的小按钮。有多个按钮时，第一个放在起始侧，例如“Skip”，其余按钮排列在末尾侧，例如“Back”和“Next” |

操作按钮距卡片边缘 12px。卡片的圆角半径等于小按钮的圆角半径加上这段内距，让两者的圆角相互贴合。

## 位置 \{#placement\}

引导提示默认在触发元素下方居中打开，箭头尖端距该元素 6px。下方空间不足时，卡片翻到上方。`coachmark-top` 优先放在上方，适用于靠近屏幕底部的控件，或信标位于控件上方一角的情况，如第一个示例所示。

箭头指向标记中紧挨在引导提示之前的元素，因此应把引导提示紧接在信标或它所说明的控件之后；在功能导览中，箭头指向导览的聚光区域，它位于该步骤的目标之上。引导提示打开时，该元素会被设为具名锚点，箭头对准它的中心。视口边缘把卡片推向一侧时，箭头仍指向锚点中心，同时避开卡片圆角。卡片翻转时，箭头移到另一侧边缘。和导览中一样，每次只打开一个引导提示。

## 信标 \{#beacon\}

`coachmark-beacon` 是按钮上的一个 10px 圆点，外圈与所在表面同色。其点击目标为 24px，在触摸屏上为 44px。它通过 `popovertarget` 打开对应的引导提示，并需要用 `aria-label` 说明会打开什么。信标由页面定位。可在 `relative` 包裹元素内使用 `absolute` 工具类，把信标放在所标记控件的上方一角，也可将它与控件并排放在同一行。

扩散的圆环用来吸引注意。指针悬停在信标上、信标获得焦点、对应引导提示打开，或启用减少动态效果时，圆环会停留为静态光环。读者看过该步骤后，移除信标。

## 功能导览 \{#tour\}

功能导览依次打开几个引导提示，每个都显示在它所说明的控件旁。将各步骤按顺序放进 `coachmark-tour`，并为每一步设置 `popover="manual"`，这样，点击页面（例如试用当前步骤指向的控件）也不会结束导览。步骤通过 `data-target` 中的选择器指定目标；未指定时，它指向标记中紧挨在它之前的元素。步骤中的按钮用 `value` 说明其作用：`next`、`back`、`skip`，最后一步则用 `done`。

其余工作由 `tour` [行为](/guide/behaviors)完成。带有 `command="--start"` 且 `commandfor` 指向该导览的按钮会启动导览；该行为通过 `showPopover({ source })` 将每一步打开在其目标旁，由浏览器将卡片锚定在那里、由 CSS 定位，并将焦点移入卡片中的“Next”或“Done”。导览中的 `coachmark-spotlight` 会先打开并覆盖目标：无论步骤在标记中的哪个位置，其箭头都指向它。

导览可以像此处一样包含它所说明的区域，也可以只包含其步骤和聚光区域：步骤可以在文档中的任何位置找到其目标。关闭时，步骤和聚光区域不占空间，因此导览本身可以就是它所在的那一行。

由信标打开的单个引导提示不需要这些。它采用 `popover="auto"`：点击外部或按下 <kbd>Esc</kbd> 时，浏览器会自动关闭引导提示并将焦点还给信标，全程无需脚本。

## 等待的步骤 \{#waiting\}

步骤可以等待读者，也可以等待其目标。

- **等待操作。** 带有 `data-advance` 的步骤指定目标上的一个事件（例如 `click`），该事件发生后导览继续。不要为这一步提供“Next”：它请读者亲自完成这项操作，页面作出响应后导览才继续。“Skip”和 <kbd>Esc</kbd> 仍可退出。
- **稍后出现的目标。** 步骤的目标不在页面中或未被渲染时，步骤会等待它，并在它出现后立即打开，例如由按钮显示出来的输入框，或仍在加载的行。三秒后（或等待传给该行为的 `wait` 所指定的时长）仍未出现的目标会被跳过；越过最后一步后，导览即告完成。导览不会停在一张没有指向任何东西的卡片上；可能无法显示的步骤不应包含读者在别处找不到的内容。

## 聚光 \{#spotlight\}

`coachmark-spotlight-dim` 用[对话框](/components/dialog)的遮罩调暗步骤目标周围的页面，并让目标及其周围 4px 保持明亮，聚光区域的圆角半径等于控件的圆角半径加上这 4px。遮罩是一圈与屏幕同宽的阴影，由聚光区域绘制，锚点定位让聚光区域覆盖目标，因此页面滚动时它会跟随目标。导览开始时遮罩淡入，结束时淡出；从一步切换到下一步时，明亮区域会立即移动。

遮罩只是绘制效果，而不是一堵墙：其下方的页面仍响应指针和按键，因此读者可以试用步骤所指的控件，导览也不会妨碍读者做其他事。用于某个界面的首次导览，在需要引导视线时使用；只介绍一个新控件的提示则不要使用。

## 行为 \{#behavior\}

`tour` 接收带有 `coachmark-tour` 类的根元素，并返回一个用于解除绑定的函数。`@master/ui/behaviors` 中的 `attach()` 会找到页面上的所有导览。

```js name=app.js
import { tour } from '@master/ui/behaviors/tour.js'

const root = document.querySelector('#deploys-tour')
const deploys = tour(root)

deploys.value = 0 // starts the tour, as the button does
root.addEventListener('end', (event) => {
  if (event.detail.completed) localStorage.setItem('deploys-tour', 'seen')
})
```

- **值**是导览当前所在步骤的索引，从 0 开始；导览未运行时为 `null`。设置它可打开某一步，设为 `null` 则结束导览；设置时不会派发事件。
- **事件。** 每当导览移到另一步，根元素都会派发可冒泡的 `change` 事件，索引位于 `detail.value` 中。读者结束导览时，先派发值为 `null` 的 `change`，再派发 `end`；读者走完最后一步时，其 `detail.completed` 为 true，在此之前通过“Skip”、<kbd>Esc</kbd> 或其他关闭步骤的方式离开时为 false。
- **焦点**会在每一步打开时移入其中：优先移到带有 `autofocus` 的操作，其次是“Next”或“Done”，否则移到步骤本身。导览结束时，焦点回到导览开始时所在的位置，除非读者此后已将焦点移到页面中的其他地方。
- **选项。** `target(step, index)` 用于查找步骤的目标，适用于由页面自行管理目标的情况；`wait` 是步骤等待其目标的时长，以毫秒为单位，默认为 3000。
- **触发器命令。** 浏览器不支持 `command` 和 `commandfor` 时，该行为会直接监听启动按钮的点击。

未启用该行为时，导览不会启动；各步骤保持关闭，页面在没有它们的情况下也完整可用。根据 `end` 事件记住读者已完成导览，不要再自动启动它：改为通过读者以后能找到的按钮提供导览。

## 无障碍 \{#accessibility\}

- 为引导提示设置 `role="dialog"`，并通过 `aria-labelledby` 用标题为它提供无障碍名称。引导提示以非模态方式打开，周围的页面仍可操作；在功能导览中，聚光遮罩下方的页面同样可以操作。
- 在由信标打开的引导提示的主要操作上设置 `autofocus`，使卡片打开时焦点移入卡片，键盘用户可按 <kbd>Enter</kbd> 继续。功能导览的行为脚本会将焦点移入各步骤。
- 每一步都可通过“Skip”或“Done”操作，或按下 <kbd>Esc</kbd> 退出。单个引导提示还可通过点击其他位置关闭。
- 从读者的操作（例如点击按钮）启动导览，绝不要在页面加载时启动：导览是帮助，不应从读者前来完成的任务中夺走焦点。
- 确保导览中的所有信息都能从其他地方找到，让跳过导览的读者，或遇到被跳过的步骤时，都不会错过任何信息。
- 在标记中将引导提示紧接在信标之后。无论卡片显示在哪里，引导提示在 Tab 导航顺序中都紧跟在信标之后。

## React、Svelte 和 Vue \{#frameworks\}

`tour` 组件为数据中的每一项写出一个步骤，各带其标题、文字、计数和所需的操作，并接收和传出当前打开步骤的索引，导览结束时调用 `onEnd`。步骤的目标可以是选择器、元素、ref 或用于查找它的函数。使用 `npx master-ui add tour` 将组件复制到项目中。[React、Svelte 和 Vue](/guide/frameworks) 介绍这些组件的实现和用法。

## 浏览器支持 \{#browser-support\}

引导提示使用 CSS 锚点定位。卡片通过 `position-area` 和 `position-try-fallbacks` 定位，箭头和功能导览的聚光区域都通过卡片与所指元素之间的 `anchor()` 定位。在不支持锚点定位的浏览器中，卡片仍可打开和关闭，会按浏览器的默认弹出层位置居中显示在视口中，且不显示箭头；聚光区域不会调暗任何内容，因为它无法让目标保持明亮。`showPopover()` 的 `source` 选项为导览步骤指定锚点。省略该选项时，步骤会在没有锚点的情况下打开。启动按钮使用触发器命令，浏览器不支持时由该行为代为处理。淡入淡出和短距离滑动使用 `@starting-style`。不支持该特性时，卡片和遮罩会立即出现或消失。

卡片淡入时朝锚点滑动 4px，退出时以更短的时间淡出。其他弹出层带有缩放动画，引导提示卡片保持原尺寸，因为缩放会让箭头缩进卡片内，够不到它所指的元素。
