A meter shows a measurement within a known range: storage used, a score, a password's strength. Use `.meter` on a native `<meter>`. It has the shape of a [progress bar](/components/progress), a thin well with an ink fill, but it means something else: progress is how far a task has come, a meter is where a quantity stands.

## The element decides the tone \{#tone\}

A `<meter>` knows what a good value is. Its `low`, `high` and `optimum` attributes divide the range, and the browser reports which part the value is in. The stylesheet maps that to ink:

- **Where it should be**: ink. A meter with no thresholds is always here.
- **Off**: the warning ink.
- **Far off**: the danger ink.

No class or script picks the color. Below, `optimum="0"` says low usage is good, and `low="6" high="9"` set the two thresholds.

## Sizes \{#sizes\}

The track is 6px thick. `meter-sm` is 4px and `meter-lg` is 8px.

## Browsers \{#browsers\}

Chromium and Firefox draw the meter as above. Safari keeps the platform's own meter, which reports the same value and the same three tones in its own style. The text inside `<meter>` is shown by a browser that does not draw the element at all.

## Accessibility \{#accessibility\}

- Label the meter with a `field` label, `aria-label` or `aria-labelledby`.
- A meter does not print its number. Write the reading beside it.
- For a task that completes, use [progress](/components/progress); a meter has no indeterminate state.
