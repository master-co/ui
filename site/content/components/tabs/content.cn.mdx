横向排列时，标签页的文字沿同一条细线排列，当前标签带有墨色下划线。标签页用于在同级页面或面板间切换。若要紧凑地呈现一组选项供用户选择，可使用[分段控件](/components/segmented)。

横向排列时，如果浏览器支持 CSS 锚点定位，`aria-selected` 变化会让同一条下划线滑到当前标签下方。下划线的上缘经过圆滑处理，避免墨色形成生硬的尖角。其他情况下，每个标签各自绘制下划线。

## 标签页面板 \{#tab-panels\}

在同一页面内切换面板时，遵循 WAI-ARIA 标签页模式：使用 `role="tablist"` 容器、带有 `aria-selected` 和 `aria-controls` 的 `role="tab"` 按钮，以及 `role="tabpanel"` 区域。样式表绘制所有状态，`tabs` [行为脚本](/guide/behaviors)负责切换面板，并为标签列表提供键盘操作。

`tabs` 接收标签列表，并返回卸载行为的函数。

```js name=app.js
import { tabs } from '@master/ui/behaviors/tabs.js'

const detach = tabs(document.querySelector('.tabs[role="tablist"]'))
```

- **Tab 键只停一处。** 只有选中的标签位于 Tab 键的焦点顺序中。方向键将焦点移到上一个或下一个标签并选中它，跳过禁用的标签，到达首尾时循环切换。<kbd>Home</kbd> 和 <kbd>End</kbd> 分别跳到第一个和最后一个标签。带有 `aria-orientation="vertical"` 的标签列表改用上、下方向键。
- **面板。** 标签通过 `aria-controls` 指定对应的面板。选中标签的面板会显示，其余面板会加上 `hidden`。
- **值。** 选中另一个标签时，标签列表会依次派发 `input` 和 `change`。两个事件都会冒泡，两者的 `detail.value` 都取该标签的 `data-value`，若无则取其文本。行为脚本返回的函数也有同样的 `value`，从外部设置它即可选中对应标签，此时不会派发任何事件。
- **没有脚本时**，只有选中标签的面板不带 `hidden`，面板也无法切换。如果每个标签都可以对应一个独立页面，可在 `nav` 中使用链接。

要在面板旁纵向排列标签页，请给标签列表设置 `aria-orientation="vertical"`。上下方向键沿列移动，选中标记贴着该列的起始边。标签和 `aria-controls` 指向的面板应位于同一文档或同一个 shadow root 中。移除选中的标签后，会选中下一个可用标签；如果已在末尾，则选中前一个。只有焦点原先位于被移除的标签上时，焦点才随之移动。

## 可搜索的面板 \{#searchable-panels\}

将 `{ searchable: true }` 作为 `tabs()` 的第二个参数，或设置框架组件的 `searchable` 属性，即可让文字较多的未选中面板也纳入页内查找和片段导航。原生 `beforematch` 会选中显示出来的面板对应的标签，并派发与点击相同的事件。请把面板的装饰和间距放在内层元素上，让隐藏的面板不占空间。不支持 `beforematch` 的浏览器沿用普通的隐藏面板。

## React、Svelte 和 Vue \{#frameworks\}

`tabs` 组件根据数据渲染标签列表及其面板，通过 ID 将各标签与对应面板关联起来，挂载行为脚本，并支持从外部传入和读取当前选中的标签。若标签是 `nav` 中的链接，直接使用 HTML 标记即可。使用 `npx master-ui add tabs` 将组件复制到项目中。[React、Svelte 和 Vue](/guide/frameworks) 介绍了这些组件的实现和用法。
