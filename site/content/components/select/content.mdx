Use `.select` directly on a native `<select>`. The browser keeps the keys, type-ahead and the form value; the class draws the well and a quiet chevron that reads in both themes. Where the browser supports the customizable select, the option list is drawn in the same material as the rest of the interface.

## The option list \{#the-option-list\}

With `appearance: base-select` the list is no longer drawn by the operating system. It becomes `::picker(select)`, a popover that the browser anchors to the control and flips at the viewport edge, and the stylesheet gives it the floating sheet, whose corner is a row's corner plus the 4px between them. Put `select-option` on each `<option>`:

- The row under the pointer or the arrow keys takes a chip tone.
- The current option carries a check at its end, drawn on `::checkmark`.
- The control's chevron is `::picker-icon`; it turns over while the list is open.

A browser without the customizable select ignores all of this and shows the platform's own list, as it always has. Nothing in the markup changes, and `select-option` does no harm there.

## Options with icons \{#options-with-icons\}

Give each option a text label and a value. A decorative icon can sit beside the text. In a customizable select, `<selectedcontent>` mirrors the chosen option in the closed control; make it a row, `flex items-center gap(8)`, as the option is, or the icon stands above the words. The native picker in other browsers still shows the labels and submits the same values.

## Invalid \{#invalid\}

Mark a choice the form refuses with `aria-invalid="true"`: the select takes the danger edge of a [field](/components/input#hint-and-error), which stays while it is focused or open, and a `field-error` in the same field shows and replaces the hint. A `required` select whose first option is empty draws the same through `:user-invalid`, once the reader has changed it or tried to send the form.
