Use `.select` directly on a native `<select>`. The browser keeps the keys, type-ahead and the form value; the class draws the well and a quiet chevron that reads in both themes. Where the browser supports the customizable select, the option list is drawn in the same material as the rest of the interface.

## The option list \{#the-option-list\}

With `appearance: base-select` the list is no longer drawn by the operating system. It becomes `::picker(select)`, a popover that the browser anchors to the control and flips at the viewport edge, and the stylesheet gives it the floating sheet: a 12px corner around 8px rows, 4px in. Put `select-option` on each `<option>`:

- The row under the pointer or the arrow keys takes a chip tone.
- The current option carries a check at its end, drawn on `::checkmark`.
- The control's chevron is `::picker-icon`; it turns over while the list is open.

A browser without the customizable select ignores all of this and shows the platform's own list, as it always has. Nothing in the markup changes, and `select-option` does no harm there.

## Raised \{#raised\}

In a toolbar or a filter row, `select-raised` makes the select a raised control beside buttons.

</select>

## Classes \{#classes\}

| Class | Description |
| --- | --- |
| `select` | A native select drawn as a well |
| `select-option` | An option in the customizable list |
| `select-raised` | A raised select for toolbars |
| `select-sm`, `select-lg` | 32px and 44px heights; the default is 40px |
