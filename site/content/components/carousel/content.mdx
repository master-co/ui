A carousel is a row of slides that scrolls and snaps. It is built from CSS alone: the track is a scroll container with scroll snapping, so touch, a trackpad, the keys and assistive technology all work as scrolling does. Where the browser supports them, the stylesheet adds previous and next buttons and a dot for each slide, which the browser generates as real, focusable controls.

## The controls \{#the-controls\}

Nothing in the markup stands for the buttons or the dots. They are pseudo-elements:

- `::scroll-button(inline-start)` and `::scroll-button(inline-end)` scroll the track by a page. The browser disables one at each end, and the stylesheet lets it step back.
- `::scroll-marker` on each slide is a dot; `::scroll-marker-group` gathers them under the track. The dot of the slide in view matches `:target-current`, lengthens and takes ink.

They are placed with anchor positioning against their own carousel, whose anchor name is scoped, so several carousels on a page do not share controls. In a browser without these pseudo-elements, the carousel is a swipeable, scrollable row and loses nothing else.

## Several in view \{#several-in-view\}

`carousel-2` and `carousel-3` show two or three slides at once. A slide's width is a share of the track less the gaps, so the last one in view ends on the track's edge. Set `--carousel-slide` to any width for a slide that peeks.

## Accessibility \{#accessibility\}

- Give the track `role="region"`, a label and `tabindex="0"`, so the arrow keys can scroll it.
- The generated buttons are named "Previous slide" and "Next slide" by the stylesheet. Each dot takes the name of its slide's content.
- A carousel does not move by itself. Content that advances on a timer needs a pause control, which is a script's job.
- With reduced motion the track jumps between slides instead of gliding.
