輪播是一排（或一欄）可捲動並自動貼齊的投影片。它完全以 CSS 實作：軌道是啟用捲動貼齊的捲動容器，因此觸控、觸控板、鍵盤和輔助技術都能依照一般捲動方式操作。瀏覽器支援時，樣式表會加上上一張和下一張按鈕，並為每張投影片加上圓點。瀏覽器會將它們產生為真正、可取得焦點的控制項。

## 控制項 \{#the-controls\}

標記中沒有對應按鈕或圓點的元素，兩者都是偽元素：

- `::scroll-button(inline-start)` 和 `::scroll-button(inline-end)` 每次將軌道捲動一頁。它們和其他按鈕一樣帶有浮起效果，指標移入時會抬高，按下時會下沉。到達任一端時，瀏覽器會停用對應的按鈕，樣式表則將它淡出並隱藏，避免遮住下方的投影片。
- 每張投影片的 `::scroll-marker` 是一個圓點，`::scroll-marker-group` 將這些圓點集中在軌道下方。目前可見投影片的圓點會符合 `:target-current`，拉長並填上墨色。每個圓點周圍都有內距以擴大操作範圍，觸控螢幕上還會再加大，手指不必精準點中 6px 的圓點。

這些控制項以各自的輪播為錨點定位。錨點名稱的作用範圍限於個別輪播，因此同一頁上的多組輪播可各自使用自己的控制項。瀏覽器不支援這些偽元素時，輪播只會少了這些控制項，仍是一排可滑動、可捲動的投影片。

## 讀取與設定目前投影片 \{#view\}

如果頁面需要知道目前顯示的是哪一張投影片，或要切換到某一張，請將軌道放進 `carousel-view`，並自行加上上一張、下一張按鈕和一排圓點。在這個檢視容器內，自動產生的控制項會退讓，因此畫面上只有一組按鈕。[`carousel` 行為](/guide/behaviors)負責驅動這些控制項：

- 它以 `IntersectionObserver` 觀察哪一張投影片的可見比例最大（可見比例相同時取順序在前的一張），並在捲動停止後將它設為目前投影片：時機是 `scrollend`，瀏覽器不支援 `scrollend` 時則在短暫停頓之後。
- 上一張、下一張和圓點會請平台依投影片自身的貼齊對齊方式將它捲入可見範圍；啟用減少動態效果時則立即跳到該位置。行為本身從不設定捲動位置。
- 目前投影片的圓點帶有 `aria-current="true"`，到達兩端時會停用上一張或下一張按鈕。畫面上可能同時顯示多張投影片，但目前投影片仍只有一張，其他投影片也不會被隱藏。
- 每張投影片以其 `data-value`（或 `id`）作為代表值，因此在它之前插入投影片時，目前投影片仍維持不變。讀者造成的變更會觸發 `input` 和 `change`；行為傳回的函式帶有可讀寫的 `value`，以程式設定它則不會觸發任何事件。

## 無障礙 \{#accessibility\}

- 在軌道上設定 `role="region"`、標籤和 `tabindex="0"`，讓使用者能以方向鍵捲動。
- 樣式表將產生的按鈕命名為 "Previous slide" 和 "Next slide"。每個圓點都以對應投影片的內容命名。
- 輪播本身不會自行捲動。若用計時器自動切換內容，必須透過腳本提供暫停控制項。
- 啟用減少動態效果時，軌道會直接跳到另一張投影片，省略平滑捲動。
- 在強制色彩模式下，按鈕會以系統按鈕色繪製外框，圓點也會保留系統色彩，其中目前可見投影片的圓點會使用醒目提示色。
- 在 `carousel-view` 中，請用頁面的語言為按鈕和圓點命名；圓點應說明它前往的是共幾張中的第幾張。

## React、Svelte 和 Vue \{#frameworks\}

`carousel` 元件依項目產生投影片（每個項目帶有一個在項目變動時保持不變的 `value`），並在旁邊產生檢視容器的按鈕與圓點；它的值就是目前投影片。使用 `npx master-ui add carousel` 將它複製到專案中；[React、Svelte 和 Vue](/guide/frameworks) 說明了這些元件的建構與使用方式。不需要讀取目前投影片的輪播不需要元件，上方的標記就足夠了。
