カンバンは列を並べたボードです。各列は名前の付いたセクションで、リストを 1 つ持ちます。項目は、同じ列の別の位置にも、別の列にも移動できます。各項目には小さなコントロールが 2 つあります。ポインターやキー操作で項目を運ぶハンドルと、移動フォームを開くボタンです。移動フォームでは、ドラッグせずに列と位置を選べます。項目に何を表示するかはページ側で決めます。この例では、[バッジ](/components/badge)と[アバター](/components/avatar)を載せた[カード](/components/card)です。移動は `kanban` の[ビヘイビア](/guide/behaviors)が担い、移動を確定するまでは何も動きません。

## スタイルシートの描画内容 \{#what-the-stylesheet-draws\}

- **ボード**　横方向にスクロールする行です。上の例の `h(376)` や、[ボード](/pages/board)ページのメイン領域のように高さを与えると、列はその高さで止まります。
- **列**　トレイです。色調と細い罫線で一段くぼんで見え、幅は `--kanban-column-width` です。ただし、ボードの幅から 2rem を引いた値を超えないため、スマートフォンでは次の列が端にのぞきます。高さは中身に合わせて決まります。スクロールするのは列のリスト `kanban-items` だけで、ヘッダーはその上にとどまります。
- **角丸は 1 つ、線も 1 本**　ボードに置いたカードには `--kanban-radius` と `--kanban-padding` が適用されます。列の角丸は、この角丸に、項目のまわりの余白である `--kanban-inset` を加えた値です。列のタイトルは、カードのテキストと同じ線から始まります。
- **2 つのコントロール**　1 組として並び、それぞれ 24px、指で操作するときのターゲットは高さ 44px で、互いの中間までしか広がらないため、隣のコントロールの代わりに反応することはありません。6 つの点で描いたグリップであるハンドルと、すれ違う 2 本の矢印で描いた `kanban-move` です。どちらも、ポインターやキー操作が届くまではグリフだけを描きます。`touch-action: none` が指定されるのはハンドルだけなので、カードのほかの部分から始めたスワイプでは通常どおりスクロールします。`kanban-controls` は、この 1 組を項目の最初の行の末尾に収めます。グリップの点がボックスの内側に入っている分にあたる .5rem だけカードのパディングにはみ出すため、グリップは、その下のアバターが終わる端にそろいます。縦方向はタイトルの最初の行の中央に合わせます。
- **移動ボタンは待機します**　ポインターをホバーできる環境では、`kanban-move` はポインターやキー操作がその項目に届くまで描かれません。そのためボードには、カードごとにグリップが 1 つだけ表示されます。タッチ画面では常に表示されます。
- **運ばれている項目**　項目は元の位置にとどまったまま薄くなるため、どこから運んできたかがわかります。グリップはくぼみに収まります。
- **移動先**　隙間の中央に引かれる線です。`kanban-item-target` が付いた項目の前、または `kanban-items-target` が付いたリストの最後の項目の後ろに描かれます。ほかの項目は場所を空けません。ポインターの下でボードが動かないため、移動先が自身を追いかけるように揺れ動くことはありません。
- **空の列**　リストの代わりに `kanban-empty` を表示します。浅いくぼみに収めた短い文言です。この列が移動先になると、くぼみは目印の色のリングで囲まれます。
- **運ばれているシート**　`kanban-preview` は、浮き上がった小さなシートに項目の名前を載せたもので、幅は項目と同じです。手動のポップオーバーなので最上位レイヤーに表示され、どの列のスクロールにも切り取られません。カードの複製は持たないため、id、フィールド、画像が重複することもありません。ポインターを離すと、項目が収まった位置まで滑るように移動して消えます。

動きを抑える設定では、シートは滑るように移動せず、項目のフェードインも行いません。強制カラーモードでは、列、くぼみ、シートに輪郭線が付き、線はシステムのハイライト色で描かれます。

## ビヘイビア \{#behavior\}

`kanban` は、`kanban` クラスを持つルート要素を受け取り、ビヘイビアを解除する関数を返します。

```js name=app.js
import { kanban } from '@master/ui/behaviors/kanban.js'

const board = kanban(document.querySelector('.kanban'))

board.value
// [{ value: 'backlog', items: ['emails', 'pricing', 'tour', 'translate'] }, { value: 'progress', items: ['post', 'table'] }, …]

board.move('pricing', 'review', 0)

// The board dispatches input, then change, once for each move that changed it.
document.querySelector('.kanban').addEventListener('change', (event) => {
  if (event.target === event.currentTarget) save(board.value)
})
```

- **ポインター**　ハンドルを押したまま 4px を超えて動かすと、項目が持ち上がります。マウス、ペン、タッチのどれでも同じで、項目を動かせるのは、ドラッグを始めたポインターだけです。移動先の列は、ポインターの下にある列、なければ横方向で最も近い列です。その列の中では、中央がポインターより下にある最初の項目の前が移動先になります。ポインターが端に近づくと、ボードは横方向に、その列のリストは縦方向にスクロールします。ポインターを離すと移動が確定します。持ち上げた位置で離した場合は何も変わりません。ボードの外で離したとき、<kbd class="kbd">Escape</kbd> を押したとき、ポインターがキャンセルされたとき、キャプチャーが失われたときは、いずれも項目は元の位置のままです。
- **項目全体（マウス）**　マウスでは、リンク、ボタン、フィールド以外であれば項目のどこを押しても持ち上げられ、その場所ではカーソルが手の形になります。指ではハンドルだけが項目を運びます。項目のほかの部分を押す操作は、リストをスクロールするためのものだからです。項目を押しても動かさなければ、その位置にあるものへのクリックにとどまります。
- **キー操作**　ハンドルで <kbd class="kbd">Enter</kbd> または <kbd class="kbd">Space</kbd> を押すと、項目が持ち上がります。ポインターを動かさずにハンドルを押した場合も同じです。続けて矢印キーで移動先を選ぶと、線がその位置を示します。矢印キーは項目を持ち上げるまで何もしないため、スクリーンリーダー独自の矢印キー操作はそのまま使えます。<kbd class="kbd">Enter</kbd> または <kbd class="kbd">Space</kbd> で確定し、<kbd class="kbd">Escape</kbd> で取り消します。ハンドルからフォーカスが外れた場合も確定します。
- **移動フォーム**　項目の中にあるボタンの `popovertarget` が、`kanban-mover` フォームを収めたポップオーバーを指していれば、そのボタンはその項目のために移動フォームを開きます。ポップオーバーの開閉はブラウザーが行います。ビヘイビアは、`column` という名前のセレクトに列を、`position` という名前のセレクトに選ばれた列の中の位置を書き込み、フォームを送信すると移動が確定します。ドラッグができずキーボードもない場合や、タッチ画面でスクリーンリーダーを使う場合の手段です。
- **経路は 1 つ**　ポインター、キー操作、移動フォームは、どれも `move(item, column, index)` を通して確定します。この関数は直接呼び出すこともできます。`index` は、その列のほかの項目の中での位置です。`0` が先頭で、末尾を超える数値は末尾として扱います。確定によってボードが変わる場合は、項目のノードそのものを移動します。ブラウザーが `moveBefore()` に対応していればそれを使うため、フィールドのテキストとフォーカスが保たれます。続けて項目を表示範囲に入れ、そのハンドルにフォーカスを移し、イベントを発行します。項目がすでにある位置への確定では、イベントは発行されません。
- **移動は描画されます**　ブラウザーが要素をスコープとするビュー遷移に対応していれば、確定のたびにボードで遷移を開始します。各項目は所属するリストで切り抜かれたまま新しい位置へ滑らかに移動し、確定は 1 フレーム後に完了するため、このとき `move` は Promise を返します。それ以外のブラウザーや、動きを減らす設定では、項目はすぐに新しい位置に置かれます。移動には 160ms かかり、その間ボードは押下を受け付けません。
- **ページが移動するとき**　ページから呼び出した `move` は、項目を表示範囲に入れず、フォーカスも移しません。非表示の列には移動せず、前の移動の描画が終わっていない間は拒否されます。ハンドルが `disabled` の項目は、移動フォームを含むどの方法でも元の位置にとどまります。
- **値**　ボードの配置です。列ごとに 1 つの `{ value, items }` が、列の順に並びます。確定済みの配置であり、選んでいる途中の移動先は含みません。代入するとボードをその配置に並べ替えますが、イベントは発行されません。ボードにない列や項目を指す値、同じものを 2 回指す値は拒否され、ボードはそのまま残ります。そのため、途中でカードが失われることはありません。値に含まれていない項目は元の列に残り、値が指す項目の後ろに並びます。
- **移動の途中**　項目を運んでいる間に、値の代入や `move` の呼び出しなど、ボードを並べ替える操作が行われると、まずその移動が取り消されます。
- **読み上げ**　持ち上げ、移動先の選択、ドロップ、取り消しのたびに、`kanban-status` 領域で項目の名前、列、位置を伝えます（例：「Price the annual plan: In review, position 1 of 1.」）。ページの言語で伝えるには `messages` を渡します。項目は `aria-label`、なければ項目内の最初のテキストで呼ばれ、列はタイトルで呼ばれます。

列の順序はマークアップの順序です。`hidden` を指定した列は項目を受け取らず、キー操作でも飛ばされます。

カード内のフィールドや移動フォーム自体のセレクトが発行する `input` と `change` も、フォームの場合と同じようにボードを通って伝わります。移動によるイベントは、`target` がボードであるものです。

### このビヘイビアが計測するもの \{#measuring\}

[ビヘイビア](/guide/behaviors)は属性を動かし、ジオメトリーはスタイルシートに任せます。ただし、スクロールする列をまたぐドラッグの位置は、その方法では求められません。そのためこのビヘイビアだけは、コントラクトに定めた範囲内で計測を行います。ポインターが列と項目のどこにあるかを読み取り、端の近くでボードとリストをスクロールし、運ばれているシートに `--kanban-x`、`--kanban-y`、`--kanban-width` の 3 つのカスタムプロパティを書き込みます。色、影、そのほかのスタイルは設定しません。移動先の目印は、スタイルシートが描くクラスです。

## スクリプトなしの場合 \{#without-script\}

ボードはセクション、見出し、リストでできているため、ビヘイビアを適用しなくても、列ごとに順番どおり読め、スクロールもできます。ただし、何も移動できません。移動には、ビヘイビアか、順序を自分で書き換えるページが必要です。何もしないハンドルや移動ボタンは、ないよりも悪いため、スクリプトなしで動く可能性があるページでは、スクリプトが読み込まれてからこれらを描画します。

ブラウザーがポップオーバー API に対応していない場合、ドラッグ中にポインターに追従するものはありません。その場合も、薄くなった項目と線によって、何を運んでいて、どこに移動するのかがわかります。

## アクセシビリティ \{#accessibility\}

- 各列は、タイトルを名前とする `<section>` です。そのため、スクリーンリーダーで直接移動できる領域になります。列の項目はネイティブのリストなので、項目の数も伝わります。ボードは、名前を付けた `role="group"` です。
- ドラッグだけが手段になることはありません。ポインターでできる操作は、すべてキー操作でもできます。移動フォームでは、2 つのセレクトと 1 つのボタンで同じ操作ができます。これは [WCAG 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) が求めるものです。キーボードによる代替手段だけでは、タッチで操作していてドラッグができない利用者には届きません。
- 2 つのコントロールには、どちらも移動する対象を含む名前を付けます（例：「Drag Price the annual plan」「Move Price the annual plan」）。
- ステータス領域は、最初から空の状態でページに置いておきます。読み上げる瞬間に追加した領域は、読み上げられないことがよくあります。
- 移動の後、フォーカスは移動した項目のハンドルにあり、項目は表示範囲に入っています。<kbd class="kbd">Tab</kbd> でハンドルを離れると移動が確定し、フォーカスが引き戻されることはありません。
- 配置は、ページのほかのデータと同じ方法で、`change` のときに保存します。移動が利用者に見えない影響を及ぼす場合は、ボードの近くでそのことを説明します。

## React、Svelte、Vue \{#frameworks\}

`kanban` コンポーネントは、`columns`、`items`、保持している配置から列とその項目を書き出し、2 つのボタンの属性を、展開して使えるように項目のマークアップへ渡し、ビヘイビアを適用します。移動が確定すると、ビヘイビアは描画すべき配置をコンポーネントに渡し、その描画を待ってからフォーカスを戻してイベントを発行します。配置を受け取らない所有者の場合、ボードは元のまま残ります。`npx master-ui add kanban` でプロジェクトにコピーできます。コンポーネントの構成と使い方は [React、Svelte、Vue](/guide/frameworks) を参照してください。

列が変わった項目は、新しいリストの中で描画し直されます。親が変わった項目をフレームワークが描画し直すのと同じです。カードに表示する内容は、カード内の状態ではなく、データとして保持してください。
