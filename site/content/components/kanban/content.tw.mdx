看板由多個欄組成，每一欄都是一個具名的區段，內含一份清單；項目可以移到同一欄的其他位置，也可以移到另一欄。每個項目有兩個小型控制項：一個是把手，用指標或按鍵搬移項目；另一個是按鈕，用來開啟移動表單，不必拖曳就能選擇欄和位置。項目要顯示什麼由頁面決定：這裡是一張帶有[徽章](/components/badge)和[頭像](/components/avatar)的[卡片](/components/card)。`kanban` [行為](/guide/behaviors)負責移動；在確認移動之前，任何東西都不會移動。

## 樣式表繪製的內容 \{#what-the-stylesheet-draws\}

- **看板**是一列可橫向捲動的欄。為它設定高度（如上方的 `h(376)`，或像[看板頁面](/pages/board)的主區域那樣），各欄就會止於這個高度。
- **欄**是一個托盤：以色調和細線呈現凹陷，寬度為 `--kanban-column-width`，且不會超過看板寬度減去 2rem，因此在手機上，下一欄會從邊緣露出。欄的高度隨內容而定。欄內的清單 `kanban-items` 是唯一會捲動的部分，上方的標頭則留在原位。
- **同一個圓角，同一條線。** 看板中的卡片採用 `--kanban-radius` 和 `--kanban-padding`。欄的圓角是這個圓角半徑加上 `--kanban-inset`，也就是項目周圍的空間；欄的標題則與卡片的文字從同一條線開始。
- **兩個控制項**成對出現，各為 24px，以手指觸控時目標高 44px，且各自只延伸到兩者中間，不會替對方回應：把手是由六個點組成的握把，`kanban-move` 則是兩個交錯的箭頭。在指標或按鍵移到它們之前，兩者都只繪製圖示。只有把手設有 `touch-action: none`，因此從卡片其他位置開始的滑動仍會捲動。`kanban-controls` 把這對控制項放在項目第一行的結尾：它會伸入卡片的內距，距離為 .5rem，也就是握把的點在其方框內的內縮量，讓握把貼齊下方頭像結束的邊緣，並對齊標題第一行的中線。
- **移動按鈕會等待。** 在指標可以懸停的裝置上，`kanban-move` 要等指標或按鍵到達所屬項目才會繪製，因此看板上每張卡片只顯示一個握把；在觸控螢幕上它一律顯示。
- **搬移中**的項目會留在原位並淡化，讓讀者看得出它從哪裡來，它的握把則落在凹槽中。
- **落點**是間距正中央的一條線，繪製在標有 `kanban-item-target` 的項目之前，或標有 `kanban-items-target` 的清單最後一個項目之後。沒有項目會讓出空間：看板在指標下方保持不動，落點才不會自己追著自己跑。
- **空的欄**會顯示 `kanban-empty` 取代清單，也就是淺凹槽中的幾個字。當它成為項目的落點時，凹槽會以標記的顏色繪製一圈外環。
- **搬移面板** `kanban-preview` 是一張略為凸起的小面板，寬度與項目相同，上面寫著項目的名稱。它是手動彈出面板，因此位於頂層，不會被任何一欄的捲動範圍裁切；它也不含卡片的複本，所以不會出現第二個 id、欄位或圖片。放開時，它會滑到項目的新位置，然後消失。

啟用減少動態效果時，搬移面板不會滑動，項目也不會淡入。在強制色彩模式下，欄、凹槽和搬移面板都會加上外框，落點線則以系統的醒目提示色繪製。

## 行為 \{#behavior\}

`kanban` 接收根元素，也就是帶有 `kanban` 類別的元素，並傳回用來解除行為的函式。

```js name=app.js
import { kanban } from '@master/ui/behaviors/kanban.js'

const board = kanban(document.querySelector('.kanban'))

board.value
// [{ value: 'backlog', items: ['emails', 'pricing', 'tour', 'translate'] }, { value: 'progress', items: ['post', 'table'] }, …]

board.move('pricing', 'review', 0)

// The board dispatches input, then change, once for each move that changed it.
document.querySelector('.kanban').addEventListener('change', (event) => {
  if (event.target === event.currentTarget) save(board.value)
})
```

- **指標。** 在把手上按下並移動超過 4px 時，就會拿起項目；滑鼠、觸控筆和觸控都一樣，而且只有開始拖曳的那個指標能移動項目。指標下方的欄（或橫向最接近的欄）就是項目會落入的欄，落點在中點低於指標的第一個項目之前。指標靠近邊緣時，看板會橫向捲動，該欄的清單則會縱向捲動。放開指標即確認移動。在拿起項目的位置放開不會有任何變更；在看板外放開、按 <kbd class="kbd">Escape</kbd>、指標被取消，以及指標擷取被取走，都會讓項目留在原位。
- **整個項目（滑鼠）。** 使用滑鼠時，按住項目上連結、按鈕或欄位以外的任何位置也能拿起項目，游標在這些位置會顯示為手形。手指只能從把手搬移：在項目其他位置按下是捲動清單的方式。在項目上按下但沒有移動，仍然只是對該處內容的一次點按。
- **按鍵。** 在把手上按 <kbd class="kbd">Enter</kbd> 或 <kbd class="kbd">Space</kbd> 會拿起項目，在把手上按下而不移動也有相同的效果。接著用方向鍵選擇位置，並由落點線標示；在拿起項目之前，方向鍵不會有任何作用，因此螢幕閱讀器自己的方向鍵操作仍可正常使用。按 <kbd class="kbd">Enter</kbd> 或 <kbd class="kbd">Space</kbd> 會確認移動，按 <kbd class="kbd">Escape</kbd> 會取消，焦點離開把手時也會確認。
- **移動表單。** 項目中的按鈕，只要 `popovertarget` 指向內含 `kanban-mover` 表單的彈出面板，就會為該項目開啟移動表單。彈出面板由瀏覽器開啟和關閉；行為會把各欄寫入名為 `column` 的下拉選單，把所選欄中的各個位置寫入名為 `position` 的下拉選單，提交表單即確認移動。無法拖曳又沒有鍵盤的讀者，以及在觸控螢幕上使用螢幕閱讀器的讀者，都靠這個方式移動項目。
- **單一路徑。** 指標、按鍵和移動表單都透過 `move(item, column, index)` 確認移動，你也可以直接呼叫它。`index` 是項目在該欄其他項目之間的位置：`0` 是第一個，超出結尾的數字則代表結尾。若確認的移動改變了看板，行為會移動項目節點本身（瀏覽器支援時使用 `moveBefore()`，因此欄位中的文字和焦點會保留下來），將項目捲入可見範圍，讓它的把手取得焦點，並派送事件。若確認的位置就是項目目前所在的位置，則不會派送任何事件。
- **移動過程會繪製出來。** 瀏覽器支援以元素為範圍的 view transition 時，確認移動會在看板上啟動一次：每個項目都滑到它的新位置，並由所屬清單裁切；確認會晚一個影格完成，因此 `move` 這時回傳 promise。其他瀏覽器以及啟用減少動態效果時，項目會直接就位。滑動歷時 160ms，期間看板不接受按壓。
- **頁面自行移動時。** 由頁面呼叫的 `move` 不會把項目捲入可見範圍，也不會移動焦點；它不會把項目移入隱藏的欄，而且在前一次移動尚未繪製完成時會被拒絕。把手為 `disabled` 的項目不論用哪種方式都留在原位，移動表單也不例外。
- **值**就是排列方式：每一欄一個 `{ value, items }`，依欄的順序排列。它代表已確認的結果，絕不是正在選擇的位置。設定它即可排列看板，且不會派送任何事件。如果值指名了看板沒有的欄或項目，或同一個欄或項目出現兩次，就會遭到拒絕，看板維持原狀，因此卡片絕不會在途中遺失。值未列出的項目會留在原本的欄，排在值所列的項目之後。
- **移動進行中。** 在搬移項目期間設定值、呼叫 `move`，或以其他方式重新排列看板，都會先取消那次移動。
- **朗讀內容。** 每次拿起、選擇位置、放下和取消，都會在 `kanban-status` 區域中說出項目名稱、欄和位置，例如「Price the annual plan: In review, position 1 of 1.」傳入 `messages` 即可改用頁面的語言。項目以其 `aria-label` 稱呼，沒有時則用它所含的前幾個字；欄則以其標題稱呼。

欄的順序就是標記中的順序。帶有 `hidden` 的欄不接受任何項目，按鍵操作也會略過它。

卡片內的欄位和移動表單自己的下拉選單，也會讓 `input` 和 `change` 經過看板，就像經過表單一樣。屬於移動的事件，是 `target` 為看板的那些。

### 這個行為測量的內容 \{#measuring\}

[行為](/guide/behaviors)只變更屬性，幾何則交給樣式表。但在可捲動的欄之間拖曳，無法用這種方式判斷位置，因此唯獨這個行為會進行測量，測量的範圍則明訂在它的契約中：它讀取指標在各欄與各項目之間的位置，在指標靠近邊緣時捲動看板和清單，並在搬移面板上寫入三個自訂屬性：`--kanban-x`、`--kanban-y` 和 `--kanban-width`。它不設定顏色、陰影或其他樣式，落點的標記則是由樣式表繪製的類別。

## 沒有腳本時 \{#without-script\}

看板由區段、標題和清單組成，因此沒有行為時，內容仍可依序逐欄閱讀，也能捲動。但無法移動任何項目：移動需要行為，或由頁面自行寫入順序。沒有作用的把手和移動按鈕比沒有更糟，因此可能在沒有腳本的情況下執行的頁面，應該等腳本就緒後再渲染它們。

瀏覽器不支援 popover API 時，拖曳期間不會有任何東西跟隨指標；淡化的項目和落點線仍會說明正在搬移什麼、會落在哪裡。

## 無障礙 \{#accessibility\}

- 每一欄都是以其標題命名的 `<section>`，因此是螢幕閱讀器可以直接跳到的區域；欄內的項目是原生清單，會說出項目的數量。看板則是帶有名稱的 `role="group"`。
- 拖曳絕不是唯一的方式。指標能做到的，按鍵都能做到；移動表單則用兩個下拉選單和一個按鈕完成同樣的事，這正是 [WCAG 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) 的要求：只提供鍵盤替代方式，無法顧及使用觸控且無法拖曳的讀者。
- 以所移動的內容為兩個控制項命名，例如「Drag Price the annual plan」和「Move Price the annual plan」。
- 從一開始就在頁面中放好空白的狀態區域：在要朗讀時才加入的區域，常常不會被讀出。
- 移動之後，焦點會落在被移動項目的把手上，項目也會在可見範圍內。用 <kbd class="kbd">Tab</kbd> 離開把手會確認移動，且不會把焦點拉回來。
- 以頁面儲存其他資料的方式，在 `change` 時儲存排列；若移動會產生讀者看不到的影響，請在看板附近說明。

## React、Svelte 和 Vue \{#frameworks\}

`kanban` 元件會依 `columns`、`items` 和它保存的排列寫入各欄及其項目，把兩個按鈕的屬性交給項目的標記展開，並掛上行為。確認移動時，行為會把要繪製的排列交給元件，等這次渲染完成後才交還焦點並派送事件；如果擁有者不接受這個排列，看板就會維持原狀。用 `npx master-ui add kanban` 將元件複製到專案中。元件的建置與使用方式請參閱 [React、Svelte 和 Vue](/guide/frameworks)。

換欄的項目會在新的清單中重新渲染，框架對任何更換父層的項目都是如此。請把卡片顯示的內容保存在你的資料中，不要放在卡片內部的狀態裡。
