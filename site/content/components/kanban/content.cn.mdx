看板由多列组成，每一列是一个带名称的区段，其中有一个列表；项目可以移到本列的其他位置，也可以移入另一列。每个项目有两个小控件：一个是手柄，用指针或键盘拿起并移动项目；另一个是按钮，用来打开移动面板，无需拖动即可选择列和位置。项目中显示什么由页面自行决定：这里是带有[徽标](/components/badge)和[头像](/components/avatar)的[卡片](/components/card)。移动由 `kanban` [行为脚本](/guide/behaviors)完成；在移动提交之前，任何内容都不会移动。

[可排序列表](/components/sortable)为一个列表排序。如果项目还会换到另一个列表，而且它所在的列表本身就说明了它的某种情况，例如所处阶段、负责人或状态，就使用看板。

## 样式表绘制的内容 \{#what-the-stylesheet-draws\}

- **看板**是一个横向滚动的行。为它设置高度后，各列的高度就以此为限，例如上例中的 `h(376)`，或[看板页](/pages/board)的主区域。
- **列**是一个托盘：以色调和一条细线呈现下沉效果，宽度为 `--kanban-column-width`，且始终不超过看板宽度减去 2rem，因此在手机上，下一列会在边缘露出一部分。列的高度由其内容决定。列表 `kanban-items` 是其中唯一滚动的部分，上方的标题栏保持不动。
- **同一个圆角，同一条线。** 看板中的卡片采用 `--kanban-radius` 和 `--kanban-padding`。列的圆角是这个半径加上 `--kanban-inset`，即项目四周的留白；列标题与卡片文字从同一条线开始。
- **两个控件**成对出现，各为 24px，触控目标高 44px，并且各自只延伸到两者中间，不会替对方响应：手柄内放握把图标，`kanban-move` 内放两个方向相反的箭头图标，两者都是写在标记里的 [Master Icons](/components/icon#master-icons) 图稿。指针或键盘到达之前，两者都只显示图标。只有手柄设置了 `touch-action: none`，因此从卡片其他位置开始的滑动仍会滚动。`kanban-controls` 把这对控件放在项目首行的末端：它向卡片的内边距探出一段距离，为 .5rem，也就是握把的点在自身方框内缩进的量，使握把与下方头像的末端边缘对齐；它还与标题的首行垂直居中。
- **移动按钮会等待。** 在指针可以悬停的设备上，`kanban-move` 要等指针或键盘到达所在项目才会绘制，因此看板上每张卡片只显示一个握把；在触摸屏上它始终显示。
- **被拿起的项目**留在原位并变淡，读者可以看出它来自哪里；它的握把则沉入凹槽。
- **落点**是间隙正中的一条线，绘制在带有 `kanban-item-target` 的项目之前，或带有 `kanban-items-target` 的列表的最后一个项目之后。没有项目会让出空间：看板在指针下方保持静止，落点因此不会追着自己跑。
- **空列**显示 `kanban-empty`，即浅凹槽中的几个字，用来代替列表。空列成为落点时，凹槽会以标记色绘出一圈环线。
- **拖动预览** `kanban-preview` 是一小块凸起面板，宽度与项目相同，上面只有项目的名称。它是手动弹出层，因此位于顶层，不会被任何列的滚动裁剪；它不包含卡片的副本，因此不会出现重复的 id、字段或图片。松开后，它在原处以一次按压的时间消失，期间带有 `kanban-preview-landing`；移动的则是恢复原样的项目本身：只有名称的预览若滑向项目的新位置，就会成为项目第二个、较小的画面，在项目上方滑过。

启用减少动态效果时，没有任何滑动；被拿起的项目变淡和恢复原样时也没有过渡。在强制颜色模式下，列、凹槽和拖动预览都带有轮廓线，落点线使用系统的高亮色。

## 行为脚本 \{#behavior\}

`kanban` 接收根元素，即带有 `kanban` 类的元素，并返回一个用于解除绑定的函数。

```js name=app.js
import { kanban } from '@master/ui/behaviors/kanban.js'

const board = kanban(document.querySelector('.kanban'))

board.value
// [{ value: 'backlog', items: ['emails', 'pricing', 'tour', 'translate'] }, { value: 'progress', items: ['post', 'table'] }, …]

board.move('pricing', 'review', 0)

// The board dispatches input, then change, once for each move that changed it.
document.querySelector('.kanban').addEventListener('change', (event) => {
  if (event.target === event.currentTarget) save(board.value)
})
```

- **指针。** 在手柄上按下并移动超过 4px 时，会拿起项目；鼠标、触控笔和触摸都一样，而且只有开始拖动的那个指针能移动它。指针下方的列（或横向上最近的列）就是它将落入的列，落点位于中点在指针下方的第一个项目之前。指针靠近看板的两端时，看板会横向滚动；靠近该列列表的两端时，列表会纵向滚动。松开即提交：手柄随即松开，项目恢复原样，并由项目本身移到新位置。在拿起项目的位置松开不会有任何变化；在看板之外松开、按 <kbd class="kbd">Esc</kbd>、指针被取消或指针捕获被夺走，都会让项目留在原处。
- **整个项目（鼠标）。** 使用鼠标时，按住项目上链接、按钮或字段以外的任何位置也能拿起项目，指针在这些位置显示为手形。手指只能通过手柄拿起项目：在项目其他位置按下是滚动列表的方式。在项目上按下但没有移动，仍然只是对该处内容的一次点击。
- **键盘。** 在手柄上按 <kbd class="kbd">Enter</kbd> 或 <kbd class="kbd">空格键</kbd> 会拿起项目，效果与按下但不移动相同。随后用方向键选择位置，落点线会标出它；拿起项目之前，方向键不起作用，因此屏幕阅读器自身的方向键操作仍然可用。按 <kbd class="kbd">Enter</kbd> 或 <kbd class="kbd">空格键</kbd> 提交，按 <kbd class="kbd">Esc</kbd> 取消，焦点离开手柄也会提交。
- **移动面板。** 项目中的按钮，只要其 `popovertarget` 指向包含 `kanban-mover` 表单的弹出层，就会为该项目打开移动面板。弹出层的打开和关闭由浏览器负责；行为脚本把各列写入名为 `column` 的下拉选择框，把所选列中的各个位置写入名为 `position` 的下拉选择框，提交表单即提交移动。无法拖动又没有键盘的用户，以及在触屏上使用屏幕阅读器的用户，都可以通过这种方式移动项目。
- **同一条路径。** 指针、键盘和移动面板都通过 `move(item, column, index)` 提交，这个方法也可以直接调用。`index` 是项目在该列其他项目中的位置：`0` 表示第一个，超出末尾的数字表示末尾。如果提交改变了看板，行为脚本会移动项目节点本身（浏览器支持 `moveBefore()` 时使用该方法，因此字段中的文字和焦点得以保留），把项目滚动到可见范围内，让它的手柄获得焦点，并派发事件。提交到项目当前所在的位置时，不派发任何事件。
- **移动过程会绘制出来。** 浏览器支持以元素为范围的视图过渡（view transition）时，提交会在看板上启动一次：每个项目滑到它的新位置，并由所在列表裁剪；提交会晚一帧完成，因此 `move` 此时返回 promise。其他浏览器以及启用减少动态效果时，项目直接就位。滑动历时 160ms，期间看板不接受按压。
- **页面自行移动时。** 由页面调用的 `move` 不会把项目滚动到可见范围，也不会移动焦点；它不会把项目移入隐藏的列，并且在上一次移动尚未绘制完成时会被拒绝。手柄为 `disabled` 的项目无论用哪种方式都留在原位，移动面板也不例外。
- **值**就是排列：每列对应一个 `{ value, items }`，按列的顺序排列。它反映的是已提交的结果，而不是正在选择的位置。为它赋值可以排列看板，但不会派发任何事件。如果值中提到了看板没有的列或项目，或者同一个列或项目出现了两次，赋值会被拒绝，看板保持原样，因此卡片绝不会在中途丢失。值中未列出的项目留在原来的列，排在已列出的项目之后。
- **移动期间。** 项目被拿起时，为值赋值、调用 `move` 或以其他方式重新排列看板，都会先取消这次移动。
- **播报。** 每次拿起、选择位置、放下和取消都会在 `kanban-status` 区域中播报，内容包括项目名称、列和位置，例如“Price the annual plan: In review, position 1 of 1.”。传入 `messages` 可使用页面的语言播报。项目以其 `aria-label` 称呼，未设置时取其开头的文字；列以其标题称呼。

列的顺序以标记为准。带有 `hidden` 的列不接收项目，键盘操作也会跳过它。

卡片内的字段和移动面板自身的下拉选择框也会经由看板冒泡 `input` 和 `change`，就像经由表单一样。属于移动的事件，是 `target` 为看板本身的那些。

### 这个行为脚本测量什么 \{#measuring\}

[行为脚本](/guide/behaviors)只切换属性，几何布局交给样式表。跨越多个滚动列的拖动无法用这种方式判断，因此唯独这个行为脚本会进行测量，测量的范围也写进了它的契约：它读取指针在各列和各项目之间的位置，在指针靠近两端时滚动看板和列表，并在拖动预览上写入三个自定义属性：`--kanban-x`、`--kanban-y` 和 `--kanban-width`。它不设置颜色、阴影或其他任何样式；落点的标记是由样式表绘制的类。

## 没有脚本时 \{#without-script\}

看板由区段、标题和列表组成，因此没有行为脚本时，它仍按顺序逐列呈现，并且可以滚动。但无法移动任何项目：移动需要行为脚本，或者由页面自行写入顺序。不起作用的手柄和移动按钮比没有更糟，因此可能在无脚本环境下运行的页面，应在脚本就绪后再渲染它们。

浏览器不支持 popover API 时，拖动期间没有内容跟随指针；变淡的项目和落点线仍能说明拿起的是什么、将落在哪里。

## 无障碍 \{#accessibility\}

- 每一列都是以标题命名的 `<section>`，因此是屏幕阅读器可以直接跳转到的区域；列中的项目是原生列表，会报出其中的项目数量。看板是带名称的 `role="group"`。
- 拖动从来都不是唯一的方式。指针能做的，键盘都能做；移动面板则用两个下拉选择框和一个按钮完成同样的操作，这正是 [WCAG 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) 的要求：仅提供键盘替代方式，无法照顾到使用触屏且不能拖动的读者。
- 用所移动的内容为两个控件命名，例如“Drag Price the annual plan”和“Move Price the annual plan”。
- 让状态区域从一开始就以空内容存在于页面中：在需要播报时才添加的区域往往不会被读出。
- 移动之后，焦点位于被移动项目的手柄上，项目也在可见范围内。按 <kbd class="kbd">Tab</kbd> 离开手柄会提交移动，焦点不会被拉回。
- 像页面保存其他内容一样，在 `change` 时保存排列；如果移动会产生读者看不到的影响，请在看板附近说明。

## React、Svelte 和 Vue \{#frameworks\}

`kanban` 组件根据 `columns`、`items` 和它持有的排列写入各列及其项目，把两个按钮的属性交给项目的标记展开使用，并绑定行为脚本。移动提交时，行为脚本把要绘制的排列交给组件，等这次渲染完成后再恢复焦点并派发事件；如果所有者不接受这个排列，看板就保持原样。使用 `npx master-ui add kanban` 将组件复制到项目中。有关这些组件的实现和用法，请参阅 [React、Svelte 和 Vue](/guide/frameworks)。

换列的项目会在新的列表中重新渲染，框架对任何更换父级的项目都是如此。请把卡片显示的内容保存在数据中，而不是卡片内部的状态里。
