スケジュールは、1 日の時刻を縦軸に並べ、各予定の所要時間を高さで表します。カレンダーの日表示、会議の会場別プログラム、クリニックの予約表などに使えます。予定は順序付きリストで、各項目にタイトルと時刻をテキストで記述します。スタイルシートが予定を時間軸上に配置し、1 時間ごとに極細線と時刻ラベルを表示します。重なる予定は横に並びます。スクリプトや寸法の計測は不要です。

終日続く予定は、時間帯の上の帯に表示します。月表示では各日の予定をレーンに並べ、アジェンダでは日ごとに一覧表示します。[スケジュールビュー](#schedule-view)は、読み手が操作するスケジュールで、日、週、月、アジェンダで表示でき、`schedule` ビヘイビアで動作します。

## 予定の配置 \{#how-an-event-gets-its-place\}

時間軸の開始時刻`--schedule-from`と終了時刻`--schedule-to`は`schedule`に設定します。1 時間分の高さは`--schedule-hour`で、指定がなければ 48px です。各`schedule-event`には`--start`と`--end`を時間軸と同じ時刻の数値で指定します。たとえば 10 時 30 分は 10.5、午後 1 時 45 分は 13.75 です。予定はその時刻に合わせて配置され、上下の極細線から 1px ずつ離れるため、時刻が連続する予定の間にも線が残ります。

`schedule-rail`には、`--schedule-from`から`--schedule-to`まで、終了時刻も含めて 1 時間ごとのラベルを入れます。各ラベルは、対応する極細線の高さに中央をそろえて配置されます。読者になじみのある時刻表記を使ってください。時刻欄の幅は 48px（`--schedule-rail`）です。

1 時間あたり 48px で 1 日全体を表示すると、高さは 1,100px を超えます。必要な時間帯に絞るか、スケジュールを[スクロール領域](/components/scroll-area)に入れてスクロールできるようにします。

## 重なる予定 \{#events-that-overlap\}

時間が重なる予定は、表示幅を分け合います。それぞれに、横に並ぶ予定の数を表す`--lanes`と、先頭を 0 とした並び位置を表す`--lane`を指定します。上の例では、デザインレビューと面接が同じ時間帯に 2 列で並んでいます。どの列に割り当てるかはデータに基づいてリストの描画側が決め、スタイルシートは指定された位置に配置します。

## 短い予定 \{#short-events\}

各予定はサイズコンテナーで、高さに応じてテキストの表示が変わります。

- 既定の高さ設定では、1 時間以上の予定はタイトルの下に時刻を表示します。
- それより短い予定では、タイトルと時刻を 1 行に並べ、予定の中央に配置します。両方が収まらない場合は時刻を非表示にします。
- 既定の高さで 15 分の予定を表示する場合など、1 行分の高さもないときは、淡い色の面だけを表示します。テキストは支援技術が参照できるようリスト内に残り、時刻は時間軸上の位置で分かります。

## 現在時刻と現在の予定 \{#now\}

スケジュールに`schedule-now`を付けると、予定と同じ時間単位で指定した`--now`の位置にインク色の線が引かれ、その日の列の先頭に点が付きます。線は予定の背面を通るため、テキストに重なりません。

`aria-current="true"`を付けた予定は、インク色の面で表示されます。進行中の予定や、スケジュールの横に詳細を開いている予定に使います。

## 複数日の表示 \{#several-days\}

数日分を横に並べるには、各日の`schedule-events`を`schedule-day`の中に置き、その上に`schedule-heading`を配置します。各日は横幅と時間軸を共有し、見出しと時刻の位置がそろいます。今日の列に`aria-current="date"`を付けると、見出しが強いインク色になり、現在時刻の線は今日の列では点付きで、ほかの日の列では極細線で表示されます。

予定の詳細を開けるようにする場合は、リスト項目自体ではなく、その中のリンクまたはボタンに`schedule-event`を指定します。配置は同じで、ポインターを重ねると色が一段濃くなり、キーボードでフォーカスするとフォーカスリングが表示されます。

## 終日の予定 \{#whole-days\}

## 月表示 \{#month\}

`schedule-month` は、1 か月を 7 日ずつの週で表示します。各 `schedule-week` は、日付、その日に始まる予定、「さらに表示」ボタンの順に書き出すため、スクリーンリーダーは日付の順に読み上げます。スタイルシートがそれぞれを列とレーンに配置します。日付の数字 `schedule-date-number` は、その日を開く丸いボタンで、今日はインク色で表示されます。1 日に表示する予定は `--lanes` 件（既定は 3 件）で、残りは `schedule-more` ボタンにまとめられます。このボタンは、残りの予定を一覧にした[ポップオーバー](/components/popover)を開きます。月表示の短い予定は、シートのない簡素な表示 `schedule-event-plain` になり、ドット、時刻、タイトルだけを表示します。

36rem より狭い領域ではレーンを使わず、各日の数字の下に予定ごとのドットを最大 3 つ表示します。数字を押すとその日が開きます。7 つの狭い列にテキストを詰め込むことはしません。

`schedule-agenda` は、同じ予定を日ごとに一覧表示します。各行の先頭に日付を置き、その横の `schedule-list` に予定を並べます。狭い領域では予定を日付の下に並べます。スマートフォンや印刷物、図を見るより文章で読みたい読者に適しています。

月表示とアジェンダは予定データから書き出すため、下のビューのように、ビヘイビアかフレームワークのコンポーネントで生成します。

### 予定 \{#the-events\}

各予定には、`id`、`title`、`start`、`end` を指定します。同じ予定には常に同じ ID を使います。終日の予定には `allDay: true` を指定し、開始と終了を日付 `YYYY-MM-DD` で表します。それ以外の予定はローカル時刻 `YYYY-MM-DDTHH:mm` で表します。`end` はその時点を含みません。13 日だけの終日の予定では終了日に 14 日を指定します。午前 0 時に終わる予定は、その直前の日までの予定として扱います。`category` はパレットの名前で、たとえば `blue` は `category-blue` を表します。`href` を指定すると予定はリンクになります。指定しない場合は、予定の id を `value` に持つボタンになり、ページはその操作を受け取れます。

時刻は、スケジュールを表示するタイムゾーンにすでに変換されている必要があります。繰り返しの予定は、開催回ごとに個別の予定として渡します。タイムゾーンと繰り返しはアプリケーション側で解決します。日数はカレンダーに従って正午を基準に数えるため、夏時間の切り替えで終日の予定が前日にずれることはありません。ビューは予定を編集、移動、保存しません。予定を表示し、どの予定が押されたかを伝えるだけです。

### ビヘイビア \{#behavior\}

```js name=app.js
import { schedule } from '@master/ui/behaviors/schedule.js'

const team = schedule(document.querySelector('.schedule-view'), { events, today: '2026-11-13' })
team.value // { date: '2026-11-13', view: 'month' }
```

| オプション | 既定値 | |
| --- | --- | --- |
| `events` | `[]` | 上記の形式の予定 |
| `value` | 今日を含む月 | 最初に表示する日付とビュー。`{ date, view }` の形で、ビューは `day`、`week`、`month`、`agenda` のいずれか |
| `today` | ブラウザーの日付 | 今日の日付（`YYYY-MM-DD`）。サーバーでスケジュールを描画する場合に指定し、サーバーとブラウザーで結果を一致させます |
| `locale` | ページの `lang` | 曜日と月の名前に使う BCP 47 タグ |
| `weekStart` | ロケールの既定 | 週の最初の曜日。0（日曜日）から 6（土曜日） |
| `lanes` | `3` | 月表示の 1 日に表示する予定の数。残りは「さらに表示」ボタンにまとめます |
| `from`, `to` | `8`, `18` | 日表示と週表示で最低限表示する時間帯。それより早い予定や遅い予定があれば範囲が広がります |
| `messages` | 英語 | 帯の名前、「さらに表示」ボタンの表示文言とアクセシブルな名前、アジェンダが空のときの文 |
| `draw` | なし | タイトルと本体の書き出しを引き受けます。自分で書き出すレンダラー向けです |

読み手の操作では、ルートから `input` と `change` が発行されます。ビヘイビアが返す関数には読み書きできる `value` があり、値を設定してもイベントは発行されません。`scheduleLayout(value, options)` は、ビューが表示する内容をデータとして返します。各予定のレーンを含む週、各予定の位置を含む時間帯、帯、アジェンダの日付です。そのため、サーバー、フレームワーク、ビヘイビアのいずれでも、同じ予定が同じように配置されます。

## スケジュール、ガントチャート、カレンダー \{#schedule-gantt-or-calendar\}

スケジュールは、時間軸上に配置した予定のためのものです。1 日の時間の流れを上から下へ読む場合も、1 か月の日付を見る場合も使えます。計画の各項目を1行ずつ割り当て、共通の時間軸に期間を示すには[ガントチャート](/components/gantt)を使います。月表示から日付や日付の範囲を選ぶには[カレンダー](/components/calendar)、出来事を発生順に並べるには[タイムライン](/components/timeline)を使います。

## アクセシビリティ \{#accessibility\}

- 予定を時刻順に`<ol>`に並べ、アクセシブルな名前を付けます。1日分なら`aria-label`を使い、複数日なら各日の`schedule-day`に`aria-labelledby`を指定して、その日の見出しを参照します。
- 各予定にはタイトルと時刻をテキストで記載し、時刻には`<time datetime>`を使います。これにより、図がなくても「デザインレビュー、10:00から11:30まで」と読み上げられます。時刻欄は同じ時間軸を視覚化したものなので、`aria-hidden="true"`で支援技術から隠します。
- 現在の予定と今日の列には`aria-current`を指定し、スクリーンリーダーがその状態を読み上げられるようにします。現在時刻の線はスタイルシートで描画されるため、時刻を伝える必要がある箇所にはテキストでも記載します。
- 強制カラーモードでは、各予定に輪郭が付き、現在の予定はハイライト色で塗りつぶされます。細い罫線と現在時刻の線にはシステムカラーが使われます。
- 月表示は日付グリッドではありません。日付は、その日を開く数字で、各予定はリンクまたはボタンで、その予定のタイトルと日時をアクセシブルな名前に含めます。「さらに表示」ボタンには、何日の何件の予定を一覧にするかを含めます。カテゴリーの色だけで予定を区別させることはしません。
- ビューのコントロールで表示期間を移動しても、操作したコントロールにフォーカスが残ります。日付の数字は月表示とともに消えるため、開いた日の名前にフォーカスを移します。
- 読者が別のタイムゾーンにいる可能性があるときは、「時刻は台北時間（GMT+8）」のように、時刻がどのタイムゾーンのものかをタイトルの近くに示します。時間軸と予定が示すのは時計の時刻だけです。

## React、Svelte、Vue \{#frameworks\}

`schedule` コンポーネントは、`scheduleLayout()` から期間を書き出すため、サーバーが最初に送る HTML にスケジュールが含まれます。また、ヘッダーと日付の数字に応答するビヘイビアを適用します。値は `{ date, view }` で、`href` のない予定が押されると `onEventClick`（Vue では `eventClick`）で受け取れます。サーバーで描画する場合は `today` と `locale` を指定します。`npx master-ui add schedule` でプロジェクトにコピーできます。構成と使い方は [React、Svelte、Vue](/guide/frameworks) を参照してください。
