日程表沿著垂直時間軸排列一天的時段，每個事件的高度對應其持續時間。可用於行事曆的單日檢視、研討會各會議室的議程，或診所的預約。事件以有序清單呈現，每項都用文字標示標題和時間。樣式表依小時刻度配置事件，每個整點都有一條細線和一個標籤。時間重疊的事件會並排顯示。整個版面配置不使用腳本，也不量測任何尺寸。

持續一整天或連續多個整天的事件會放在時段上方的橫帶中。月檢視將每天的事件排成多列，議程則依日期列出事件。[日程檢視](#schedule-view)是讀者實際操作的日程表，可依日、週、月或議程切換，由 `schedule` 行為驅動。

## 事件的定位方式 \{#how-an-event-gets-its-place\}

時間刻度從 `--schedule-from` 到 `--schedule-to`，兩者都在 `schedule` 上設定。每小時的高度由 `--schedule-hour` 指定，預設為 48px。每個 `schedule-event` 都以同一套小時刻度設定 `--start` 和 `--end`，例如上午十點半是 10.5，下午一點四十五分是 13.75。事件依指定時間開始和結束，上下各與細線留出 1px 的間距，因此前後相接的事件之間仍會保留一條線。

`schedule-rail` 包含從 `--schedule-from` 到 `--schedule-to` 的每個整點標籤，起訖整點都包含在內。每個標籤都垂直置中於對應的細線。請採用讀者慣用的時間格式。時間軸寬 48px（`--schedule-rail`）。

若每小時高 48px，一整天就會超過 1,100px。可只顯示需要的時段，或將日程表放進[捲動區域](/components/scroll-area)，讓使用者捲動查看。

## 時間重疊的事件 \{#events-that-overlap\}

時間重疊的事件會共用可用寬度。為每個事件設定 `--lanes`，表示該處並排的事件數，再設定 `--lane`，表示它在這些事件中的位置，從 0 開始。上例中的設計審查和面試在同一段時間各占一欄。產生清單的程式碼依資料決定各事件所在的欄，樣式表只負責定位。

## 短時間事件 \{#short-events\}

每個事件都是尺寸容器，會透過容器查詢依自身高度調整文字版面配置。

- 在預設尺寸下，持續一小時以上的事件會將標題放在時間上方。
- 較短的事件會將標題和時間排在同一行，並在事件內垂直置中。如果一行放不下兩者，就會隱藏時間。
- 如果連一行文字都放不下，例如預設尺寸下長度為 15 分鐘的事件，畫面上只會顯示帶底色的區塊。文字仍保留在清單中，供輔助技術讀取，事件在時間軸上的位置則表示其發生時間。

## 目前時間與目前事件 \{#now\}

在日程表上設定 `schedule-now`，就會在 `--now` 畫出一條深色線，並在線條與當日欄位起始邊緣的交點加上圓點。位置和事件一樣以小時為單位。線條從事件底下穿過，因此不會劃過事件文字。

以 `aria-current="true"` 標記的事件會使用深色底色，表示它正在進行，或其詳細資料已在日程表旁開啟。

## 多日檢視 \{#several-days\}

若要並排顯示多天，請將每天的 `schedule-events` 放進 `schedule-day`，並在上方加上 `schedule-heading`。各天平分可用寬度並共用時間軸，標題和小時刻度會彼此對齊。以 `aria-current="date"` 標記今天的欄位，讓標題使用較深的文字色。目前時間線會帶著圓點穿過今天的欄位，並以細線延伸至其他日期。

## 可開啟詳細資料的事件 \{#events-that-open-something\}

如果事件可開啟詳細資料，請將 `schedule-event` 從清單項目移到項目內的連結或按鈕上。定位方式相同，指標移入時底色會加深一階，使用鍵盤聚焦時則會顯示焦點外框。

## 全天事件 \{#whole-days\}

持續一天以上的事件放在 `schedule-allday` 中，這條橫帶位於標題下方、時段上方，並在時間軸那一欄顯示它的名稱，例如「全天」。其中每個事件都是 `schedule-event-lane`：從第 `--column` 天開始，橫跨 `--span` 天，位於第 `--lane` 列。橫帶橫跨所有日期，因此每個 `schedule-day` 都要以 `--column` 標明自己是第幾欄，日程表則以 `--schedule-days` 說明共有幾欄。

## 月檢視 \{#month\}

`schedule-month` 將一個月呈現為數週、每週七天。每個 `schedule-week` 都按日期逐天輸出，每天依序放入日期、當天開始的事件，以及當天的「更多」按鈕，因此螢幕閱讀器會依日期順序讀到它們；樣式表則將它們放到各自的欄與列。日期數字 `schedule-date-number` 是可開啟該日的圓形按鈕，今天的按鈕會以深色填滿。每天顯示 `--lanes` 個事件（預設三個），其餘事件收進 `schedule-more` 按鈕，按下後會開啟列出這些事件的[彈出面板](/components/popover)。月檢視中的短事件使用不帶面板的簡潔樣式 `schedule-event-plain`：只有圓點、時間和標題。

可用空間窄於 36rem 時，事件列會退讓：每天只在日期數字下方為每個事件顯示一個圓點（最多三個），點按日期數字即可開啟當天。不會把文字硬塞進七個狹窄的欄位中。

`schedule-agenda` 依日期列出相同的事件：每列開頭是日期，旁邊是當天事件的 `schedule-list`；空間較窄時，事件會改放在日期下方。它適合手機、列印，以及偏好閱讀文字而非瀏覽圖面的讀者。

月檢視和議程是依事件資料寫出的，因此由行為或框架元件產生，如下方的檢視所示。

### 事件 \{#the-events\}

每個事件都有一個固定不變的 `id`，以及 `title`、`start` 和 `end`。全天事件設定 `allDay: true`，起訖以日期表示（`YYYY-MM-DD`）；其他事件則使用當地時間（`YYYY-MM-DDTHH:mm`）。`end` 不包含在內：只在 13 日的全天事件結束於 14 日，在午夜結束的事件則算在前一天。`category` 指定一組色盤，例如 `blue` 對應 `category-blue`；`href` 會讓事件成為連結，若沒有 `href`，事件會是一個 `value` 為其 id 的按鈕，由頁面監聽。

時間應已換算成日程表顯示時所在的時區，重複事件則應以各次發生的事件傳入：時區和重複規則由應用程式負責處理。日期依曆法計算並固定在正午，因此日光節約時間的切換不會讓全天事件移到前一天。檢視不會編輯、移動或儲存事件；它只負責顯示事件，並告知哪一個事件被按下。

### 行為 \{#behavior\}

```js name=app.js
import { schedule } from '@master/ui/behaviors/schedule.js'

const team = schedule(document.querySelector('.schedule-view'), { events, today: '2026-11-13' })
team.value // { date: '2026-11-13', view: 'month' }
```

| 選項 | 預設值 | |
| --- | --- | --- |
| `events` | `[]` | 事件，格式如上 |
| `value` | 今天所在的月份 | 一開始要顯示的日期與檢視：`{ date, view }`，檢視為 `day`、`week`、`month` 或 `agenda` 之一 |
| `today` | 瀏覽器的日期 | 今天，格式為 `YYYY-MM-DD`；由伺服器渲染日程表時請提供，讓兩端的日期一致 |
| `locale` | 頁面的 `lang` | 用於星期與月份名稱的 BCP 47 標籤 |
| `weekStart` | 依語言區域 | 一週的第一天，0 為星期日，6 為星期六 |
| `lanes` | `3` | 月檢視中每天顯示的事件數，其餘收進「更多」按鈕 |
| `from`、`to` | `8`、`18` | 單日或一週至少顯示的時段；若有更早或更晚的事件，範圍會隨之延伸 |
| `messages` | 英文 | 橫帶的名稱、「更多」按鈕的文字與名稱，以及議程沒有事件時的句子 |
| `draw` | 無 | 接手寫出標題和內容，供自行輸出這些內容的渲染程式使用 |

讀者的操作會從根元素觸發 `input` 和 `change`；行為傳回的函式帶有可讀寫的 `value`，以程式設定它則不會觸發任何事件。`scheduleLayout(value, options)` 會以資料形式傳回檢視要顯示的內容：各週及每個事件所在的列、各時段及每個事件的位置、橫帶，以及議程的各天。因此伺服器、框架與行為能以相同方式排列相同的事件。

## 日程表、甘特圖或月曆 \{#schedule-gantt-or-calendar\}

日程表用來呈現依時間排列的事件：由上往下查看一天中的各個時段，或查看一個月中的各天。[甘特圖](/components/gantt)用同一條時間刻度呈現計畫中各項工作的起訖時間，每項工作各占一列。[月曆](/components/calendar)用來從整月檢視中選取一個日期或一段日期範圍，[時間軸](/components/timeline)則按發生順序呈現各個時間點。

## 無障礙 \{#accessibility\}

- 將事件依時間順序寫成 `<ol>`，並為清單命名。單日檢視使用 `aria-label`，多日檢視則透過 `aria-labelledby` 引用當日標題作為其 `schedule-day` 的名稱。
- 每個事件都用文字寫出標題和時間，並用 `<time datetime>` 標記時間。即使沒有視覺版面，也能讀出「設計審查，10:00 至 11:30」。時間軸只是同一套刻度的視覺呈現，請用 `aria-hidden="true"` 將它從輔助技術中隱藏。
- 目前事件與今天都以 `aria-current` 標記，螢幕閱讀器會讀出這些狀態。目前時間線由樣式表繪製，請在需要提供目前時間的地方用文字標示。
- 在強制色彩模式下，每個事件都有外框，目前事件會填入醒目提示色，整點細線與目前時間線則沿用系統色彩。
- 月檢視不是日期格線：其中的日期是可開啟該日的數字，事件則是連結或按鈕，各自以標題和時間命名。「更多」按鈕會說明它列出幾個事件，以及是哪一天的事件。分類色從來不是區分事件的唯一方式。
- 操作檢視的控制項時，焦點會留在使用中的控制項上；日期數字會隨月份一起被換掉，因此會將焦點交給它所開啟那一天的名稱。

## React、Svelte 和 Vue \{#frameworks\}

`schedule` 元件以 `scheduleLayout()` 寫出期間內容，因此伺服器送出的第一份 HTML 就已包含它；元件也會掛上行為，由行為回應標頭和日期數字的操作。它的值是 `{ date, view }`；按下沒有 `href` 的事件時，會觸發 `onEventClick`（在 Vue 中為 `eventClick`）。在伺服器上渲染時，請提供 `today` 和 `locale`。使用 `npx master-ui add schedule` 將它複製到專案中；[React、Svelte 和 Vue](/guide/frameworks) 說明了這些元件的建構與使用方式。
