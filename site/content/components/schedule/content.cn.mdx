日程表沿时间轴从上到下显示一天中的各个小时，事件的高度对应其持续时间，适用于日历的日视图、会议各会场的安排或诊所的预约。事件按有序列表组织，每项都用文字写明标题和时间。样式表按小时刻度放置事件，并在每个整点绘制带标签的细线。时间重叠的事件并排显示。整个布局无需脚本或尺寸测量。

持续一整天或多天的事件显示在小时刻度上方的横栏中。月视图在泳道中显示每天的事件，日程列表则按天列出事件。[日程视图](#schedule-view)是供读者操作的日程表，可按日、周、月或日程列表查看，由 `schedule` 行为脚本驱动。

## 事件如何定位 \{#how-an-event-gets-its-place\}

在 `schedule` 上将时间范围设为从 `--schedule-from` 到 `--schedule-to`。每小时的高度由 `--schedule-hour` 指定，默认为 48px。每个 `schedule-event` 都用 `--start` 和 `--end` 在同一时间刻度上指定起止时刻，以小时为单位，因此上午 10 点半写作 10.5，下午 1 点 45 分写作 13.75。事件从对应的开始时刻延伸到结束时刻，上下各与细线留出 1px 的间距，让首尾相接的事件之间仍有一条细线。

`schedule-rail` 为从 `--schedule-from` 到 `--schedule-to` 的每个整点各放一个标签，包含最后一个整点，并将各标签放在对应细线的高度中央。按读者习惯的时间格式编写标签。时间轴宽 48px（`--schedule-rail`）。

按每小时 48px 计算，一整天的高度超过 1,100px。可以只显示所需时段，也可以将日程表放在[滚动区域](/components/scroll-area)内，使其可以滚动。

## 时间重叠的事件 \{#events-that-overlap\}

时间重叠的事件共享可用宽度。为每个事件设置 `--lanes`，表示该时段的并排事件数，再设置 `--lane`，表示它在其中的位置，从 0 开始编号。上例中的设计评审和面试占据同一时段的两列。渲染列表的一方根据数据分配列，样式表只负责按列放置事件。

## 短时事件 \{#short-events\}

每个事件都是尺寸查询容器，文字布局随事件自身的高度调整：

- 在默认尺寸下，持续时间达到一小时，标题就显示在时间上方。
- 持续时间更短时，标题和时间在事件内居中显示在同一行。两者放不下时，隐藏时间。
- 连一行文字都放不下时，例如默认尺寸下持续 15 分钟的事件，只显示带底色的面板。文字仍保留在列表中供辅助技术读取，事件在时间轴上的位置表明它的时间。

## 当前时间与当前事件 \{#now\}

日程表上的 `schedule-now` 在 `--now` 指定的位置绘制一条墨色线，和事件一样以小时为单位，并在线与当天区域起始边缘的交点画一个圆点。时间线绘制在事件的底层，因此不会划过事件文字。

用 `aria-current="true"` 标记的事件显示为墨色面板，表示该事件正在进行，或其详情已在日程表旁打开。

## 并排显示多天 \{#several-days\}

要并排显示几天，将每天的 `schedule-events` 放入一个 `schedule-day`，并在其上方放置 `schedule-heading`。各天共享可用宽度和时间轴，标题和小时刻度彼此对齐。用 `aria-current="date"` 标记今天所在的列。今天的标题使用更浓的墨色，当前时间线带着圆点穿过这一列，并以细线贯穿其他日期列。

## 全天事件 \{#whole-days\}

持续一天或更长时间的事件放在 `schedule-allday` 中。这条横栏位于标题下方、小时刻度上方，其名称（例如“All day”）显示在时间轴所在的列。横栏中的每个事件都是一个 `schedule-event-lane`：从第 `--column` 天开始，跨越 `--span` 天，位于第 `--lane` 条泳道。横栏横跨所有日期，因此每个 `schedule-day` 都用 `--column` 标明自己所在的列，日程表则用 `--schedule-days` 说明共有几列。

## 月视图 \{#month\}

`schedule-month` 以每周七天的形式显示一个月。每个 `schedule-week` 依次写出一天、从这天开始的事件，以及这天的“更多”按钮，因此屏幕阅读器会按日期顺序读到它们；样式表再把每一项放到对应的列和泳道中。日期数字 `schedule-date-number` 是一个打开当天的圆形按钮，今天使用墨色。每天显示 `--lanes` 个事件（默认为三个），其余事件收进 `schedule-more` 按钮，点击后会打开列出这些事件的[弹出层](/components/popover)。月视图中的短时事件使用简洁样式 `schedule-event-plain`：只有一个圆点、时间和标题，没有面板。

可用宽度小于 36rem 时，泳道会让位：每天在日期数字下方为每个事件显示一个圆点，最多三个，点击日期数字即可打开当天。不会把文字硬塞进七个窄列中。

`schedule-agenda` 按天列出同样的事件：每行开头是日期，旁边的 `schedule-list` 列出当天的事件；空间较窄时，事件列在日期下方。它适合手机、打印，以及更愿意阅读文字而非看图的读者。

月视图和日程列表是根据事件数据生成的，因此需要由行为脚本或框架组件来渲染，如下面的视图所示。

### 事件 \{#the-events\}

每个事件都有一个稳定的 `id`、一个 `title`、一个 `start` 和一个 `end`。全天事件设置 `allDay: true`，起止用日期表示，格式为 `YYYY-MM-DD`；其他事件使用本地时间，格式为 `YYYY-MM-DDTHH:mm`。`end` 是排除在事件范围之外的结束边界：仅占 13 日一天的全天事件以 14 日为结束日期，在午夜结束的事件则持续到前一天结束为止。`category` 指定一个色板，例如 `blue` 对应 `category-blue`；设置 `href` 后事件成为链接，否则它是一个按钮，其 `value` 为事件 id，由页面监听。

时间应当已经是日程表显示所用的时区，重复事件应以逐次发生的事件传入：时区和重复规则由应用自行处理。日期按日历计数，并固定在中午，因此夏令时切换不会把全天事件移到前一天。视图不会编辑、移动或存储事件，只负责显示事件，并告知哪个事件被点击。

### 行为脚本 \{#behavior\}

```js name=app.js
import { schedule } from '@master/ui/behaviors/schedule.js'

const team = schedule(document.querySelector('.schedule-view'), { events, today: '2026-11-13' })
team.value // { date: '2026-11-13', view: 'month' }
```

| 选项 | 默认值 | |
| --- | --- | --- |
| `events` | `[]` | 事件，格式如上所述 |
| `value` | 今天所在的月份 | 首先显示的日期和视图：`{ date, view }`，视图为 `day`、`week`、`month` 或 `agenda` 之一 |
| `today` | 浏览器的当前日期 | 今天的日期，格式为 `YYYY-MM-DD`；由服务器渲染日程表时请提供，使两端保持一致 |
| `locale` | 页面的 `lang` | 用于星期和月份名称的 BCP 47 标签 |
| `weekStart` | 由语言区域决定 | 一周的第一天，0 表示星期日，6 表示星期六 |
| `lanes` | `3` | 月视图中每天显示多少个事件，其余事件收进“更多”按钮 |
| `from`, `to` | `8`, `18` | 日视图或周视图至少显示的小时范围；有更早或更晚的事件时会相应扩展 |
| `messages` | 英文 | 全天横栏的名称、“更多”按钮的文字和名称，以及日程列表为空时显示的句子 |
| `draw` | 无 | 接管标题和主体的写入，供自行渲染这些内容的渲染器使用 |

读者的操作会从根元素派发 `input` 和 `change` 事件；行为脚本返回的函数带有可读写的 `value`，通过代码设置它不会派发任何事件。`scheduleLayout(value, options)` 以数据形式返回视图要显示的内容：各周及每个事件所在的泳道、各小时及每个事件的位置、全天横栏以及日程列表中的各天。因此服务器、框架和行为脚本会以相同方式排布相同的事件。

## 日程表、甘特图或日历 \{#schedule-gantt-or-calendar\}

日程表用于按时间排布事件：从上到下显示一天中的各个小时，或者显示一个月中的各天。要在同一时间刻度上显示计划中各事项的起止时间，每项占一行，使用[甘特图](/components/gantt)。要从一个月中选择某一天或一段日期，使用[日历](/components/calendar)。要按发生顺序呈现各个时间点，使用[时间线](/components/timeline)。

## 无障碍 \{#accessibility\}

- 按时间顺序将事件写成一个 `<ol>`，并为列表提供无障碍名称。只显示一天时使用 `aria-label`，多天并排时，在每天的 `schedule-day` 上用 `aria-labelledby` 引用各自的标题。
- 每个事件都用文字写明标题和时间，并用 `<time datetime>` 标记时刻，这样即使脱离图形布局，也能读出“设计评审，10:00 至 11:30”。时间轴以图形方式呈现同一时间刻度，请用 `aria-hidden="true"` 将其从无障碍树中隐藏。
- 用 `aria-current` 标记当前事件和今天，屏幕阅读器会读出相应状态。当前时间线由样式表绘制，需要传达当前时间时，用文字写明。
- 在强制颜色模式下，每个事件都有轮廓线，当前事件以高亮色填充，细线和当前时间线使用系统颜色。
- 月视图不是日期网格：其中的日期是打开当天的数字按钮，事件是链接或按钮，名称包含标题和时间。“更多”按钮应说明它列出了哪一天的几个事件。分类颜色绝不能是区分事件的唯一方式。
- 视图的控件在内容变化时保持焦点；日期数字会随月视图一起消失，因此焦点会移到所打开那一天的名称上。

## React、Svelte 和 Vue \{#frameworks\}

`schedule` 组件用 `scheduleLayout()` 写出当前时段，使服务器发送的初始 HTML 就包含这些内容，并接入行为脚本，由行为脚本响应标题栏和日期数字。组件的值为 `{ date, view }`；点击没有 `href` 的事件时会触发 `onEventClick`，在 Vue 中为 `eventClick`。在服务器上渲染时，请提供 `today` 和 `locale`。用 `npx master-ui add schedule` 将组件复制到项目中。[React、Svelte 和 Vue](/guide/frameworks) 介绍了这些组件的实现和用法。
