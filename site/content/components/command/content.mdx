A command palette is one search field over a list of commands, opened from anywhere with a shortcut. It is a [dialog](/components/dialog) with a different interior: add `command` beside `dialog`, and put a `command-search` row, a [listbox](/components/listbox) and an optional `command-footer` inside. Because it is a native `<dialog>`, a button opens it with `command="show-modal"`, and the browser supplies the scrim, the focus trap and <kbd>Esc</kbd>.

## Parts \{#parts\}

- `command-search` is a `<label>`, so the whole row focuses the input. It holds an [`icon`](/components/icon), the `command-input` and an optional hint.
- `command-input` has no material of its own: the dialog is its surface, and a hairline parts it from the results.
- `command-list` goes on the listbox. It takes the remaining height and scrolls inside the dialog.
- `command-footer` holds `command-hint` groups: keys in [`kbd`](/components/kbd), then what they do.

The palette opens near the top of the viewport and grows downward, so the field stays where it is while the list under it changes length.

## The behavior \{#behavior\}

The dialog opens and closes without script. The `command` [behavior](/guide/behaviors) adds what a palette has beyond a dialog. It takes the dialog and returns the function that detaches it.

```js name=app.js
import { command } from '@master/ui/behaviors/command.js'

command(document.querySelector('.command'))

document.getElementById('cmd-new').addEventListener('click', () => {
  // Create the project.
})
```

- **The shortcut.** <kbd>⌘K</kbd> or <kbd>Ctrl</kbd> <kbd>K</kbd> opens the palette from anywhere in the document and closes it again.
- **Filtering.** Typing in `command-input` sets `hidden` on the options that do not match and makes the first match the active option. The [listbox](/components/listbox#filtering) shows its empty state, and hides a group whose commands are all filtered out, by itself.
- **The active option** has `aria-selected="true"` and is named by `aria-activedescendant` on the field. The arrow keys move it, and the palette has one from the start, so <kbd>Enter</kbd> has something to run.
- **Running a command.** <kbd>Enter</kbd> clicks the active option, so an option that is a link navigates and a `click` listener on an option runs, as for a pointer. A click on an option, from <kbd>Enter</kbd> or the pointer, closes the palette. The behavior dispatches no event of its own: the `click` is the event.

| Option | What it sets |
| --- | --- |
| `shortcut` | The key that opens and closes the palette with Command or Control. `'k'` by default, `false` for none |

Without the behavior the button still opens the dialog, the field takes text and <kbd>Esc</kbd> closes it. Nothing filters, and the arrow keys do not move through the list.

## Accessibility \{#accessibility\}

- Name the dialog with `aria-label`. Put `autofocus` on the input so typing starts at once.
- The input is a combobox that controls the listbox, as in a [combobox](/components/combobox#accessibility); here the list is always expanded.
- Every command in the palette must be reachable some other way. A palette is a shortcut, not the only door.
