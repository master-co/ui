A tags field turns what is typed into values, each a [chip](/components/chip) in the well. It is an [input group](/components/input#several-values) with `input-group-wrap` and the `tags` class: the well, its states and the concentric chips are the input group's, and the field after the chips takes the next value. The `tags` [behavior](/guide/behaviors) turns the text into chips and moves focus between them.

## What it adds to the input group \{#what-it-adds\}

- **A value arrives.** A new chip grows out of the place the caret stood in, a short scale from 80% with the quick duration, instead of appearing. With reduced motion it only fades in.
- **Room for a word.** The field keeps at least `--tags-field-min`, 6rem by default, and takes a line of its own below that, so the caret is never squeezed into a sliver at the end of a line.
- **A value the keys are on** wears the focus ring as a whole, since <kbd class="kbd">Backspace</kbd> there removes all of it, and its cross takes the pressed tone. The ring is the chip's: a chip with a `chip-remove` draws it wherever it stands.
- **A value that is refused** marks the field `aria-invalid="true"`, which the input group draws as the danger edge until the text changes.

Without `@starting-style` a new value appears at once.

## The behavior \{#behavior\}

`tags` takes the root, the input group with the `tags` class, and returns the function that detaches it.

```js name=app.js
import { tags } from '@master/ui/behaviors/tags.js'

const detach = tags(document.querySelector('.tags'), { max: 10 })
```

- **Adding.** <kbd class="kbd">Enter</kbd>, and a delimiter, a comma by default, turn the field's text into a value: a chip is written before the field and the field is emptied. Pasted text with delimiters, line breaks or tabs in it becomes as many values, and what follows the last delimiter stays in the field.
- **Refusing.** A value that is empty, already there, past `max` or refused by `validate` is not added. The field keeps the text, so nothing typed is lost, and says `aria-invalid="true"` until it changes.
- **Removing.** A chip's remove button removes it on a click, and focus returns to the field.
- **The form.** A chip carries a hidden input with its value when the chips already carry one with a `name`, or when `name` is given, so a form submits every value under that name. A form's reset puts back the values the field started with.
- **Events.** The root dispatches `input` and `change` each time a value is added or removed. The function it returns has a `value`, the values in order; set it to replace them, which dispatches nothing.

| Option | Default | |
| --- | --- | --- |
| `delimiters` | `[',']` | Keys that add the value as <kbd class="kbd">Enter</kbd> does; `[]` leaves only <kbd class="kbd">Enter</kbd> |
| `max` | none | How many values the field holds at most |
| `validate` | none | A function that says whether a value may be added |
| `name` | the chips' | The name of the hidden input a new chip carries |
| `removeLabel` | `Remove <value>` | The accessible name of a chip's remove button, in the page's language |
| `draw` | none | Takes over writing the chips, for a renderer that writes them from its own list |

A chip stands for its `data-value`, or for its text. Without the behavior the field is a text input and its chips are fixed: a form still submits the hidden inputs they carry.

## Keyboard \{#keyboard\}

The field is the one tab stop. The chips are reached from it, and their remove buttons are out of the tab order with `tabindex="-1"`. While an input method composes, <kbd class="kbd">Enter</kbd> belongs to it.

## Accessibility \{#accessibility\}

- Label the field, with a `<label>` or `aria-label`. Say how a value is added in a hint under it: a comma or <kbd class="kbd">Enter</kbd> is not obvious.
- Name each remove button with the value it removes, in the page's language: `removeLabel` does that for the chips the behavior writes.
- A value that is refused leaves the text in the field and marks it invalid; say why in the field's hint or error, as for any field.
