分类表示一条数据的归属，例如项目、日历、团队或标签。Master UI 用预设中 23 套具名色板之一来标明分类，每套色板提供四种角色：带色调的**表面**（surface）、在该表面上清晰可读的**文字**（text）、用于装饰的**线条**（line），以及用于圆点或色条的**标记**（mark）。`category-<name>` 类会为元素自身及其内部内容设置这四种角色，选择接入的部件再读取它们。

## 界面、状态、分类与内容 \{#roles-of-color\}

界面元素默认为中性色；状态色说明事物处于什么状况，分类色说明它属于哪里，内容色如实呈现数据本身，品牌色只在属于它的那一处出现。

- **状态**是组件的一种色调，例如 `badge-success`：已完成、失败、有风险。它总是与表达同样含义的文字一起出现。
- **分类**是包在数据外层的类，例如 `category-blue`：一个项目、一个日历、一个标签。这里的红色只是在命名一个分类，绝不表示危险；一个徽标要么表示状态，要么表示分类，不能两者兼有。
- **内容**是数据本身的颜色：一种涂料、一个主题的强调色、图表的一个系列。[色样](/components/swatch)按原样展示这种颜色。

分类内部的按钮、输入框、对话框等其他界面元素保持中性外观：只有 `badge-category`、`chip-category`、`schedule-event-category` 和 `icon-frame-category` 会读取这些角色。

## 色板 \{#palettes\}

同一角色在各套色板中的明度一致，因此没有哪个分类比其他分类更显眼；每种角色在 Moonstone、Obsidian 和 Paper 中都满足对比度要求：无论放在自身表面上，还是放在基础面和凸起面上，文字都达到 4.5:1，标记都达到 3:1。色相和彩度由各色板自行决定；黄色的文字会像预设中较深的色阶那样偏向琥珀色，而不会变成橄榄色。

## 一个分类，只声明一次 \{#scope\}

把类加在属于该分类的元素上，比如一行、一张卡片或一个日程事件，其内部所有选择接入的部件都会读取它。外层没有分类的部件会回退到中性角色。

## 同时用文字说明 \{#words\}

颜色绝不能是区分分类的唯一方式。在徽标或胶囊标签里，或在圆点旁边写出分类名称；分不清青绿色和绿色的读者、灰度打印件以及屏幕阅读器都需要这些文字。用户自选的分类颜色不属于主题的角色，也没有经过对比度检查：请把它映射到最接近的具名色板，或者把它当作内容放在色样中展示。

在强制颜色模式下，系统颜色会取代这些色调：文字、边缘和已选中的筛选项保持系统颜色，只有色样因为颜色就是其内容而保留自身颜色。

## 调整色板 \{#retune\}

这些角色都是主题令牌：`--color-category-<name>-surface`、`-text`、`-line` 和 `-mark`，因此主题调整色板的方式与调整其他颜色相同：在单独的主题中设置这四个令牌，并保证它们的对比度。若要让某个作用域使用自己的色板，在该作用域上设置四个公开的自定义属性即可。

```css name=theme.css
@theme {
  --color-category-teal-surface: light-dark(oklch(96% .03 190), oklch(28% .04 190));
  --color-category-teal-text: light-dark(oklch(45% .08 190), oklch(87% .09 190));
}
```
