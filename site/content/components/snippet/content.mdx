A snippet is one command to copy: the line a reader runs in a terminal, its prompt, and a button that copies it. It is a [well](/components/surface#well) in the mono face, as a [code block](/components/code#block) is, and as tall as a button, so it can stand beside one. The prompt cannot be selected, the command never wraps, and the button sits 4px in from the end, quiet until it is pointed at.

## The line \{#line\}

`snippet` holds three things in three columns. `snippet-prompt` is the glyph a terminal shows before a command, `$` or `>`, in a quieter ink; it cannot be selected, so a reader who selects the line by hand takes the command alone, and it is marked `aria-hidden` so it is not read aloud. `snippet-command` is the command, on a `<code>`. Then the button, a quiet square [button](/components/button) whose height and corner the snippet sets: the line less 4px on each side.

A command longer than the line does not wrap: it scrolls sideways, without a scrollbar, and the edge where it goes on fades. The fade is read from the scroll position, so the start is clean until the line has been scrolled. Give the command `tabindex="0"`, so the arrow keys can scroll it; the whole line then takes the focus ring.

## Copying \{#copying\}

Copying needs a script: hand the command's text to `navigator.clipboard`. The state it leaves is not a class. Beside the button is an empty `<output>`, `snippet-status`, which the reader never sees: the script writes "Copied" into it, which a screen reader announces, and empties it two seconds later. While it is not empty, the stylesheet turns the copy icon into a check, so the eye is told the same thing as the ear.

The script in the previews is the whole of it: find the command that is shown, write it to the clipboard, then fill and empty the status. The clipboard is there only on pages served over HTTPS or from localhost. Where scripting is off the button is not drawn, and the command is still text to select and copy by hand.

## Package managers \{#package-managers\}

To give the same command for npm, pnpm, bun and yarn, put a [segmented control](/components/segmented) of native radios first in the snippet and write one `snippet-command` for each option, in the same order. The control gives up its own well and lies along the top of the snippet, over a hairline; the chosen option rises as a sheet that glides to the next. The command in the chosen option's place is the one shown, with no script, for up to six options.

## Sizes \{#sizes\}

The line is 38px, the height of a button. `snippet-sm` is 32px in 12px type, for a dense page or a table; `snippet-lg` is 44px in 14px type, for the head of a page, where it stands level with a large button. On a touch screen every size is 44px.

## Snippet or code \{#snippet-or-code\}

A snippet is one line to run. Several lines, a file or output to read belong in a [code block](/components/code#block), and a command named inside a sentence is inline [code](/components/code). A key to press is a [kbd](/components/kbd).

## Accessibility \{#accessibility\}

- Mark the prompt `aria-hidden="true"`: it is decoration, and the command is what is read.
- Give the copy button an `aria-label`, such as "Copy command". Its icons are `aria-hidden`.
- Leave `snippet-status` empty in the markup, with no white space inside it. The script's "Copied" is announced from it; an `<output>` is a polite live region of its own.
- Give the command `tabindex="0"`, so a command longer than the line can be scrolled from the keyboard.
- In forced colors the fade is removed, the well is drawn with an outline and the prompt takes the system's gray text.
