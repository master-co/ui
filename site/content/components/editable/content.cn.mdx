行内编辑平时将值显示为文本，需要编辑时就在原位显示输入框，适用于标题、名称或表格单元格等内容。静止时，它是沿用所在容器字体排印的纯文本；指针悬停时，文字周围出现一道浅淡的凹槽，末端显示铅笔图标；按下后，凹槽变为已聚焦的[输入框](/components/input)，并选中其中的值。预览和输入框共用同一个网格单元格、同一种字体、同样的内边距和圆角，因此两者互相替换时，文字不会移动分毫。`editable` [行为脚本](/guide/behaviors)负责在两者之间切换并保存值。

## 文字的位置 \{#geometry\}

值与所在列的文字对齐：根元素向两侧各外扩 `--editable-padding-x`，因此凹槽在文字周围展开，而不会把文字向内挤。内边距以 `em` 为单位，因此标题的凹槽相对其字号同样宽裕，单元格的凹槽也是如此。

- **静止时**，预览是纯文本。它是一个按钮，因此可以获得焦点，文字之后的铅笔图标 `editable-pencil` 会随焦点环一起显示。
- **指针悬停时**，文字周围出现内嵌色调和半像素轮廓，铅笔图标位于最后一个词之后。在没有悬停指针的屏幕上，铅笔图标始终显示，只是稍微淡一些：这是文字可以修改的唯一提示。
- **编辑时**，输入框与已聚焦的输入框一样，是升到面板层级的凹槽，带有一道墨色轮廓和光晕。预览虽然隐藏，仍会撑开单元格，因此下方内容不会移动。浏览器支持 `field-sizing: content` 时，输入框会随值变长而超出预览的宽度；不支持时，文字在预览宽度内滚动。
- **等待中。** 值正在提交时，为根元素设置 `aria-busy="true"`：预览显示为弱化样式，并且不响应按下。

## 多行 \{#several-lines\}

以 `<textarea>` 作为输入框时，可以容纳多行值。在其中按 <kbd class="kbd">Enter</kbd> 会换行，因此要按 <kbd class="kbd">Control</kbd> 或 <kbd class="kbd">Command</kbd> 加 <kbd class="kbd">Enter</kbd> 保存。值为空时，预览在 `editable-placeholder` 中显示输入框的 `placeholder`。

## 行为脚本 \{#behavior\}

`editable` 接收根元素，即带有 `editable` 类的元素，并返回一个用于解除绑定的函数。

```js name=app.js
import { editable } from '@master/ui/behaviors/editable.js'

const title = editable(document.querySelector('.editable'))

title.edit() // open the field
title.value // the saved value
```

- **打开。** 按下预览会将其隐藏，显示带有已保存值的输入框，并选中其中的文字。
- **保存。** 按 <kbd class="kbd">Enter</kbd> 会保存，离开输入框也会保存。输入框自身的约束（`required`、`maxlength`、`pattern`）不接受的值不会被保存：按 <kbd class="kbd">Enter</kbd> 时输入框保持打开，由浏览器说明原因；离开输入框时则恢复已保存的值。传入 `blur: 'cancel'` 可让离开输入框改为取消编辑。
- **取消。** 按 <kbd class="kbd">Esc</kbd> 会恢复已保存的值。
- **焦点**在按 <kbd class="kbd">Enter</kbd> 和 <kbd class="kbd">Esc</kbd> 后回到预览；如果用户已将焦点移到别处，则不会移回。
- **事件。** 保存一个不同的值时，脚本会将其写入预览，并从输入框派发 `input` 和 `change`。返回的函数带有 `value`（已保存的值）和 `edit()`；为 `value` 赋值会同时写入预览和输入框，但不会派发任何事件。

值之后要送往何处由页面决定。值正在提交时，为根元素设置 `aria-busy="true"`。如果服务器拒绝了这个值，可以将值改回原样并在旁边说明原因，或者调用 `edit()` 并将输入框标记为 `aria-invalid="true"`，显示危险色轮廓：已输入的内容会保留下来，供读者修改。

没有行为脚本时，预览是一个不执行任何操作的按钮，值仍然可读。

给字段设置 `name` 后，它的值会随表单提交。如果浏览器在行为脚本挂载前恢复了草稿，预览会显示草稿内容。重置表单会将预览和 `value` 恢复为字段的默认值。提交时，如果收起的字段未通过验证，它会展开，以便浏览器将焦点移到出错的位置并给出提示。

## 适用场景 \{#choosing-it\}

行内编辑适合阅读远多于修改、并且在原位逐个修改的值。如果需要同时修改多个值并一次性保存，使用由[输入框](/components/input)和“保存”按钮组成的表单，能更清楚地说明保存了什么、何时保存。

## 无障碍 \{#accessibility\}

- 用值所代表的含义为值和输入框命名。示例中，可见的标签为输入框命名，预览则通过 `aria-labelledby` 同时以标签和自身命名，因此会被读作“Title, Quarterly report, button”。
- 确保已保存的值在没有脚本时仍然可读：它就是预览的文本。
- 保存失败时，在值旁边用文字说明，不要只依靠危险色轮廓。

## React、Svelte 和 Vue \{#frameworks\}

`editable` 组件在首次渲染时显示初始值，并绑定行为脚本，此后由行为脚本写入预览。组件传出的值始终是已保存的值，而不是正在输入的内容。使用 `npx master-ui add editable` 将组件复制到项目中。有关这些组件的实现和用法，请参阅 [React、Svelte 和 Vue](/guide/frameworks)。
