A table sets rows of data on hairlines. Headings are quiet captions on a firmer rule, and the rows carry the ink. Every part is reached by class: `table` on the `<table>`, `table-row` on each `<tr>`, `table-heading` on each `<th>` and `table-cell` on each `<td>`. The table has no surface of its own, so put it in a [sheet](/components/surface#sheet) or a [card](/components/card).

## Cells \{#cells\}

- `table-primary` marks the cell that identifies the row and gives it strong ink. The other cells stay in body ink, so the eye finds the name first.
- `table-numeric` on a heading and its cells sets them on the end edge in tabular figures. Digits then stack in columns and amounts can be compared by length.

## Sorting \{#sorting\}

A heading with `aria-sort="ascending"` or `aria-sort="descending"` takes strong ink and a chevron that points the way the values run. Put a button inside the heading to change the order; the stylesheet reads the attribute, and your script or your server sets it.

## Wide tables \{#wide-tables\}

A table keeps its columns: it does not restack into cards, because a restacked table loses the comparison a table exists for. When it can be wider than its column, wrap it in a [scroll area](/components/scroll-area) that scrolls along the inline axis; the edge fades where columns continue. `table-sticky` keeps the headings in view while rows scroll under them.

## Accessibility \{#accessibility\}

- Use a real `<table>` with `<thead>`, `<tbody>` and `scope="col"` on headings, so each cell is announced with its column.
- A scrolling wrapper needs `tabindex="0"`, `role="region"` and a label, so the keys can scroll it.
- Selection is said twice on purpose: `aria-selected` on the row and the state of its checkbox.
