A splitter is two panes and the handle between them that sets how they share the space: a file list beside an editor, an editor over a terminal. The panes meet at a hairline. Under the pointer, or with focus, the line takes ink and a small grip appears on it.

A splitter is a component, not a layout, though layouts use it: its handle has a material, states and a keyboard contract. For two panes that need no resizing, see [master-detail](/layouts/master-detail).

The stylesheet draws the splitter and lays it out; the `splitter` [behavior](/guide/behaviors) moves it. The behavior writes the first pane's size to `--splitter-size` on the container and the same number to the handle's `aria-valuenow`. Nothing else changes hands.

## The behavior \{#behavior\}

`splitter` takes the root, the element with the `splitter` class, and returns the function that detaches it. The handle it moves is the `splitter-handle` that is a child of the root, so a pane may hold a splitter of its own.

```js name=app.js
import { splitter } from '@master/ui/behaviors/splitter.js'

const root = document.querySelector('.splitter')
splitter(root, { step: 10 })

root.addEventListener('change', (event) => {
  localStorage.setItem('files-width', event.target.getAttribute('aria-valuenow'))
})
```

- **Dragging.** On `pointerdown` it captures the pointer on the handle and, while the pointer moves, writes its place inside the container as a percentage.
- **The keys.** An arrow of the handle's own axis moves it by a step; <kbd class="kbd">Home</kbd> and <kbd class="kbd">End</kbd> go to the least and the greatest size.
- **Each change** sets `--splitter-size` on the root and `aria-valuenow` on the handle. The size stays between the handle's `aria-valuemin` and `aria-valuemax`, 0 and 100 when it has none.
- **Events.** The handle dispatches `input` each time the size changes, and `change` when a drag ends or a key moved it. Both bubble. Read `aria-valuenow` on the handle.
- **Disabled.** A handle with `aria-disabled="true"` does not move.

| Option | What it sets |
| --- | --- |
| `step` | How far an arrow key moves the handle, in percent. 5 by default |

The stylesheet keeps the first pane `--splitter-min` away from both ends whatever size is asked for, stops text selection while the handle is held, and switches the layout by the handle's orientation. Without the behavior the panes keep the share `--splitter-size` gives them and the handle does not move.

## Stacked panes \{#stacked\}

`aria-orientation` says which way the line runs. A separator is vertical by default, between panes side by side. With `aria-orientation="horizontal"` the panes stack, and the handle becomes a horizontal line; the container reads the attribute, so there is no modifier class to keep in step.

## Accessibility \{#accessibility\}

- The handle is a focusable `role="separator"` with a label that names what it resizes, and `aria-valuenow`, `aria-valuemin` and `aria-valuemax` as percentages of the first pane. That makes it a window splitter to assistive technology.
- The keyboard must do everything the pointer does: arrows to move, Home and End for the ends. The behavior covers these.
- The line is one pixel in the layout with a 9px target across it, and 25px on touch screens, where the grip is always shown.
- A pane scrolls by itself. Give a pane that scrolls a label and `tabindex="0"` when it holds no focusable content, so the keyboard can reach it.
