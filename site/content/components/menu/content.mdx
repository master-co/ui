A menu is a popover that holds a list of actions. Add the `popover` attribute and `.menu` to a container, fill it with `menu-item` buttons and links, and point a button at it with `popovertarget`. The browser opens and closes it; CSS anchor positioning places it against the button and flips it at the viewport edge.

## Items \{#items\}

A `menu-item` is a `<button>` for an action or an `<a>` for navigation. The row under the pointer takes a chip tone at once, without a fade, so the menu keeps up with a moving pointer; a row reached by the keys also takes an ink outline. Put [`icon`](/components/icon) on an icon: the item sets its size and keeps it quiet until the row is in use.

- A link closes the menu by navigating. A button closes it with `popovertarget` and `popovertargetaction="hide"`, as above; leave them out to keep the menu open.
- `menu-item-danger` gives a destructive action the danger ink.
- `menu-shortcut` sets a shortcut at the end of the row.
- A disabled button drops to the disabled ink. For a link, use `aria-disabled="true"` and remove the `href`.

## Groups \{#groups\}

`menu-label` captions a group and `menu-separator` on an `<hr>` draws a hairline between groups, running to the menu's edges.

## Checkable items \{#checkable-items\}

For options that stay on, make the item a `<label>` around a native checkbox or radio with `menu-input`. The input covers the row invisibly and keeps the state, the keys and the form value; the row shows a check at its end and reserves that space, so labels do not move.

## Placement \{#placement\}

A menu opens below its button, lined up with the start edge. `menu-end` lines it up with the end edge, for a button at the end of a row or a toolbar; `menu-top` opens it above. It flips on its own when there is no room.

## Submenu \{#submenu\}

An item can open another menu. Give the item `popovertarget` and `aria-haspopup="menu"`, and put a `menu menu-sub` right after it, inside the parent menu. The item gains a chevron and stays lit while its submenu is open. The submenu opens beside the item, lined up with it, and flips to the other side when there is no room. Popovers nest, so the parent stays open, and <kbd>Esc</kbd> closes one level at a time.

A submenu opens on a click, which works the same for a pointer, a finger and the keys. Opening it on hover as well is a script's choice.

## The behavior \{#behavior\}

Without script a menu is complete: the browser opens and closes it, <kbd>Tab</kbd> moves through the items and <kbd>Esc</kbd> returns focus to the button. The `menu` [behavior](/guide/behaviors) is optional. It adds the keys of a menu, for an application whose readers expect the arrows.

`menu` takes the element with the `menu` class and the `popover` attribute, has no options, and returns the function that detaches it. A submenu is a menu: attach the behavior to it too, as `attach()` does.

```js name=app.js
import { menu } from '@master/ui/behaviors/menu.js'

for (const element of document.querySelectorAll('.menu')) menu(element)
```

- **Opening.** When the menu opens, focus moves to its first item.
- **Moving.** The arrow keys, <kbd>Home</kbd>, <kbd>End</kbd> and typed letters move focus through the items, skipping hidden and disabled ones. <kbd>Tab</kbd> closes the menu.
- **Submenus.** On an item with `aria-haspopup="menu"` that a `menu-sub` follows, the arrow that points into the submenu opens it, and the opposite arrow closes it and returns to the item. The two change places in a right-to-left menu.
- **Items stay native.** A button, a link, and the checkbox or radio of a label item run with <kbd>Enter</kbd> and <kbd>Space</kbd> as they always do. The behavior sets no state and dispatches no event: listen for `click` on an item and `change` on a `menu-input`.
- **Roles.** The behavior adds none. Write `role="menu"` on the menu and `role="menuitem"` on its items together with it, as the preview does.

## Context menu \{#context-menu\}

`menu-context` opens a menu at the pointer instead of against a button. The platform has no declarative way to open a popover from a right click, so the menu behavior exports `contextMenu(target, menu)` for it. On `contextmenu`, which a right click and a long press send, it prevents the browser's own menu, writes the pointer's position into `--menu-x` and `--menu-y` and calls `showPopover()`. The stylesheet does the rest. The menu opens down and to the end of that point, and `@position-try` turns it toward the middle when it would cross an edge of the viewport, with no measuring.

  <button type="button" class="menu-item" role="menuitem" popovertarget="canvas-menu" popovertargetaction="hide">Duplicate</button>

  MasterUI.contextMenu(document.getElementById('canvas'), document.getElementById('canvas-menu'))
})
</script>`} />

A context menu belongs to a target that only the page knows, so `attach()` does not attach one. The preview calls `contextMenu` itself; `MasterUI` is the bundle a preview loads. In a project, import both functions: `contextMenu` opens the menu, and `menu` gives it the keys inside, which `attach()` did in the preview.

```js name=app.js
import { contextMenu, menu } from '@master/ui/behaviors/menu.js'

const target = document.getElementById('canvas')
const list = document.getElementById('canvas-menu')

contextMenu(target, list)
menu(list)
```

The ContextMenu key and <kbd>Shift</kbd> <kbd>F10</kbd> open the menu at the middle of the target. The target must be focusable to hear them, so it has `tabindex="0"`. Not every browser sends `contextmenu` for these keys, so the behavior listens for the keys as well. `contextMenu` returns the function that detaches it; calling it again for the same target replaces the first call.

## Accessibility \{#accessibility\}

- Without script, a menu is a popover of buttons and links: <kbd>Tab</kbd> moves through the items, <kbd>Esc</kbd> closes it and focus returns to the button. That is complete and correct as it stands, so do not add `role="menu"`.
- `role="menu"` and `role="menuitem"` promise arrow-key navigation. Add them only together with the `menu` behavior, or with a script of your own that provides the same keys.
- Give an icon-only button an accessible name with `aria-label`.
