A menu is a popover that holds a list of actions. Add the `popover` attribute and `.menu` to a container, fill it with `menu-item` buttons and links, and point a button at it with `popovertarget`. The browser opens and closes it; CSS anchor positioning places it against the button and flips it at the viewport edge.

## Items \{#items\}

A `menu-item` is a `<button>` for an action or an `<a>` for navigation. The row under the pointer takes a chip tone at once, without a fade, so the menu keeps up with a moving pointer; a row reached by the keys also takes an ink outline. Put [`icon`](/components/icon) on an icon: the item sets its size and keeps it quiet until the row is in use.

- A link closes the menu by navigating. A button closes it with `popovertarget` and `popovertargetaction="hide"`, as above; leave them out to keep the menu open.
- `menu-item-danger` gives a destructive action the danger ink.
- `menu-shortcut` sets a shortcut at the end of the row.
- A disabled button drops to the disabled ink. For a link, use `aria-disabled="true"` and remove the `href`.

## Groups \{#groups\}

`menu-label` captions a group and `menu-separator` on an `<hr>` draws a hairline between groups, running to the menu's edges.

## Checkable items \{#checkable-items\}

For options that stay on, make the item a `<label>` around a native checkbox or radio with `menu-input`. The input covers the row invisibly and keeps the state, the keys and the form value; the row shows a check at its end and reserves that space, so labels do not move.

## Placement \{#placement\}

A menu opens below its button, lined up with the start edge. `menu-end` lines it up with the end edge, for a button at the end of a row or a toolbar; `menu-top` opens it above. It flips on its own when there is no room.

## Submenu \{#submenu\}

An item can open another menu. Give the item `popovertarget` and `aria-haspopup="menu"`, and put a `menu menu-sub` right after it, inside the parent menu. The item gains a chevron and stays lit while its submenu is open. The submenu opens beside the item, lined up with it, and flips to the other side when there is no room. Popovers nest, so the parent stays open, and <kbd>Esc</kbd> closes one level at a time.

A submenu opens on a click, which works the same for a pointer, a finger and the keys. Opening it on hover as well is a script's choice.

## Context menu \{#context-menu\}

`menu-context` opens a menu at the pointer instead of against a button. The platform has no declarative way to open a popover from a right click, so this takes three lines of script: on `contextmenu`, write the pointer's position into `--menu-x` and `--menu-y` and call `showPopover()`. The stylesheet does the rest. The menu opens down and to the end of that point, and `@position-try` turns it toward the middle when it would cross an edge of the viewport, with no measuring.

<ComponentPreview name="context" title="Context menu" bodyClass="p-lg min-h(300)" html={`<div class="well flex items-center justify-center h(200) text-sm fg-text-muted" id="canvas" tabindex="0">Right-click, or press the menu key</div>

<div id="canvas-menu" popover class="menu menu-context">
  <button type="button" class="menu-item" popovertarget="canvas-menu" popovertargetaction="hide">Copy<span class="menu-shortcut">⌘C</span></button>
  <button type="button" class="menu-item" popovertarget="canvas-menu" popovertargetaction="hide">Paste<span class="menu-shortcut">⌘V</span></button>
  <button type="button" class="menu-item" popovertarget="canvas-menu" popovertargetaction="hide">Duplicate</button>
  <hr class="menu-separator">
  <button type="button" class="menu-item menu-item-danger" popovertarget="canvas-menu" popovertargetaction="hide">Delete</button>
</div>
<script>
document.getElementById('canvas').addEventListener('contextmenu', function (event) {
  event.preventDefault()
  var menu = document.getElementById('canvas-menu')
  var box = this.getBoundingClientRect()
  menu.style.setProperty('--menu-x', (event.clientX || box.left + 16) + 'px')
  menu.style.setProperty('--menu-y', (event.clientY || box.top + 16) + 'px')
  menu.hidePopover()
  menu.showPopover()
})
</script>`} />

The `contextmenu` event also fires for the keyboard's menu key and for a long press on a touch screen, so one listener covers all three. When the event has no pointer position, as from the keyboard, the example falls back to the element's corner.

## Accessibility \{#accessibility\}

- Without script, a menu is a popover of buttons and links: <kbd>Tab</kbd> moves through the items, <kbd>Esc</kbd> closes it and focus returns to the button. That is complete and correct as it stands, so do not add `role="menu"`.
- `role="menu"` and `role="menuitem"` promise arrow-key navigation. Add them only together with a script that provides it; the framework bindings will.
- Give an icon-only button an accessible name with `aria-label`.

## Classes \{#classes\}

| Class | Description |
| --- | --- |
| `menu` | The floating list, on an element with the `popover` attribute |
| `menu-item` | An action: a `button`, an `a`, or a `label` around a `menu-input` |
| `menu-item-danger` | A destructive action |
| `menu-input` | The checkbox or radio inside a label item |
| `menu-shortcut` | A shortcut at the end of an item |
| `menu-label`, `menu-separator` | A group caption and a hairline between groups |
| `menu-end`, `menu-top` | Line up with the button's end edge; open above it |
| `menu-sub` | A submenu, beside the item that opens it |
| `menu-context` | Opens at `--menu-x` and `--menu-y` |

## Custom properties \{#custom-properties\}

| Property | Default | Description |
| --- | --- | --- |
| `--menu-inset` | `4px` | Padding around the items |
| `--menu-item-radius` | `var(--radius-control-sm)` | Row corner; the menu's corner is this plus the inset |
| `--anchored-gap` | `6px` | Distance from the button |
| `--menu-x`, `--menu-y` | `0px` | Where a context menu opens, set by script |
