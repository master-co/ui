## 項目 \{#items\}

`menu-item`には、アクション用の`<button>`か、ページ移動用の`<a>`を使います。ポインターが重なった行はフェードを挟まずすぐにチップと同じ色調に切り替わるため、ポインターの移動に追従します。キー操作でフォーカスした行には、文字色の輪郭線も付きます。アイコンには[`icon`](/components/icon)を指定します。アイコンのサイズは項目側で決まり、行が操作対象になるまでは控えめな色で表示されます。

- リンクは、移動先を開くとメニューが閉じます。ボタンで閉じるには、上の例のように`popovertarget`と`popovertargetaction="hide"`を指定します。メニューを開いたままにするには、両方を省略します。
- `menu-item-danger`は、破壊的なアクションを危険を示す文字色で表示します。
- `menu-shortcut`は、行の末尾にショートカットを表示します。
- 無効なボタンは、無効状態の文字色で表示されます。リンクを無効にするには、`aria-disabled="true"`を指定し、`href`を削除します。

## グループ \{#groups\}

`menu-label`はグループの見出しを表示します。`<hr>`に`menu-separator`を指定すると、グループ間にメニューの両端まで伸びる細い区切り線が入ります。

## 選択状態を持つ項目 \{#checkable-items\}

選択状態を保持する項目には、`menu-input`を付けたネイティブのチェックボックスまたはラジオボタンを`<label>`で囲みます。入力要素は見えない状態で行全体を覆い、選択状態の保持、キー操作、フォーム値の管理を担います。選択すると行の末尾にチェックマークが表示されます。そのスペースは常に確保されるため、選択状態が変わってもラベルの位置は変わりません。

## サブメニュー \{#submenu\}

項目から別のメニューを開けます。項目に`popovertarget`と`aria-haspopup="menu"`を付け、親メニュー内でその項目の直後に`menu menu-sub`を置きます。項目にはシェブロンが付き、サブメニューが開いている間は強調表示されます。サブメニューは項目の横に、項目と位置をそろえて開きます。スペースが足りない場合は反対側に開きます。ポップオーバーは入れ子にできるため、親メニューは開いたままになり、<kbd>Esc</kbd>で一階層ずつ閉じられます。

## ビヘイビア \{#behavior\}

メニューはスクリプトなしで使えます。開閉はブラウザーが処理し、<kbd>Tab</kbd>で項目間を移動でき、<kbd>Esc</kbd>でフォーカスがボタンに戻ります。`menu`の[ビヘイビア](/guide/behaviors)は任意です。矢印キーでの移動が期待されるアプリケーション向けに、メニューのキーボード操作を追加します。

`menu`は、`menu`クラスと`popover`属性を持つ要素を受け取ります。オプションはなく、ビヘイビアを解除する関数を返します。サブメニューにも、`attach()`と同じようにビヘイビアを適用します。

```js name=app.js
import { menu } from '@master/ui/behaviors/menu.js'

for (const element of document.querySelectorAll('.menu')) menu(element)
```

- **開く。** メニューが開くと、最初の項目にフォーカスが移ります。
- **移動する。** 矢印キー、<kbd>Home</kbd>、<kbd>End</kbd>、文字キーで項目間のフォーカスを移動します。非表示の項目と無効な項目は飛ばします。<kbd>Tab</kbd>を押すとメニューが閉じます。
- **サブメニュー。** `aria-haspopup="menu"`を持ち、直後に`menu-sub`がある項目では、サブメニューの方向を指す矢印キーで開きます。反対の矢印キーで閉じると、フォーカスは元の項目に戻ります。右から左に表示するメニューでは、左右のキーが入れ替わります。
- **項目のネイティブ動作。** ボタン、リンク、ラベル付き項目内のチェックボックスやラジオボタンは、従来どおり<kbd>Enter</kbd>と<kbd>Space</kbd>で操作できます。ビヘイビアは状態の設定もイベントの発行も行いません。項目の`click`イベントと`menu-input`の`change`イベントを監視してください。
- **ロール。** ビヘイビアはロールを追加しません。プレビューと同様に、ビヘイビアを適用するときは、メニューに`role="menu"`、各項目に`role="menuitem"`を指定します。

## コンテキストメニュー \{#context-menu\}

`menu-context`はボタンを基準にせず、ポインターの位置にメニューを開きます。右クリックでポップオーバーを開く宣言的な仕組みがないため、メニューのビヘイビアは`contextMenu(target, menu)`をエクスポートします。右クリックや長押しで発生する`contextmenu`を受けると、ブラウザー標準のメニューを抑止し、ポインターの位置を`--menu-x`と`--menu-y`に設定して`showPopover()`を呼び出します。以降の配置はスタイルシートが処理します。メニューはその位置から下方向とインラインの終了方向に広がります。ビューポートの端を越える場合は、寸法を計測せずに`@position-try`で内側へ開くように切り替わります。

コンテキストメニューの対象はページごとに決まるため、`attach()`は自動で関連付けを行いません。プレビューでは`contextMenu`を明示的に呼び出します。`MasterUI`はプレビューが読み込むバンドルです。プロジェクトでは両方の関数をインポートします。`contextMenu`でメニューを開き、`menu`でメニュー内のキー操作を追加します。プレビューでは後者を`attach()`が行います。

```js name=app.js
import { contextMenu, menu } from '@master/ui/behaviors/menu.js'

const target = document.getElementById('canvas')
const list = document.getElementById('canvas-menu')

contextMenu(target, list)
menu(list)
```

ContextMenuキーまたは<kbd>Shift</kbd> + <kbd>F10</kbd>を押すと、対象の中央にメニューが開きます。キー入力を受け取れるように、対象には`tabindex="0"`を付けてフォーカス可能にします。これらのキー操作で`contextmenu`を発行しないブラウザーもあるため、ビヘイビアはキー入力自体も監視します。`contextMenu`は関連付けを解除する関数を返します。同じ対象に対して再度呼び出すと、先の関連付けが置き換わります。

## アクセシビリティ \{#accessibility\}

- スクリプトを使わないメニューは、ボタンやリンクを含むポップオーバーです。<kbd>Tab</kbd>で項目間を移動でき、<kbd>Esc</kbd>で閉じるとフォーカスがボタンに戻ります。この構成だけで適切に操作できるため、`role="menu"`は追加しないでください。
- `role="menu"`と`role="menuitem"`は、矢印キーで移動できることを示します。`menu`ビヘイビア、または同等のキー操作を提供する独自のスクリプトと併用する場合に限り追加してください。
- アイコンだけのボタンには、`aria-label`でアクセシブルな名前を付けます。

## React、Svelte、Vue \{#frameworks\}

`menu`コンポーネントは、データから項目を描画し、メニューを起動要素に関連付けて、ビヘイビアを適用します。起動要素の代わりに対象を渡すと、コンテキストメニューになります。`npx master-ui add menu`でプロジェクトにコピーできます。コンポーネントの構成と使い方は[React、Svelte、Vue](/guide/frameworks)を参照してください。
