## 메뉴 항목 \{#items\}

`menu-item`에는 작업을 실행하는 `<button>` 또는 다른 곳으로 이동하는 `<a>`를 사용합니다. 포인터가 가리키는 행은 페이드 효과 없이 즉시 칩 색조로 바뀌어 포인터 움직임을 따라갑니다. 키보드로 포커스를 옮긴 행에는 잉크 색상의 윤곽선도 표시됩니다. 아이콘에 [`icon`](/components/icon) 클래스를 적용하세요. 메뉴 항목이 아이콘 크기를 정하고, 행에 포인터나 키보드 포커스가 없을 때는 아이콘을 은은하게 표시합니다.

- 링크는 이동하면서 메뉴를 닫습니다. 버튼으로 메뉴를 닫으려면 위 예시처럼 `popovertarget`와 `popovertargetaction="hide"`를 사용하세요. 메뉴를 열린 상태로 두려면 두 속성을 생략하세요.
- `menu-item-danger`는 삭제처럼 되돌리기 어려운 작업에 위험 상태의 잉크 색상을 적용합니다.
- `menu-shortcut` 클래스는 행 끝에 단축키를 표시합니다.
- 비활성화된 버튼에는 비활성 상태의 잉크 색상이 적용됩니다. 링크를 비활성화하려면 `aria-disabled="true"`를 사용하고 `href`를 제거하세요.

## 선택 가능한 항목 \{#checkable-items\}

선택 상태를 유지하는 옵션은 `menu-input` 클래스를 적용한 네이티브 체크박스나 라디오 버튼을 `<label>`로 감싸 만드세요. 입력 요소는 보이지 않는 상태로 행 전체를 덮으며 선택 상태, 키보드 조작, 폼 값을 처리합니다. 옵션을 선택하면 행 끝에 체크 표시가 나타납니다. 이 공간은 항상 확보해 두므로 레이블 위치가 바뀌지 않습니다.

## 하위 메뉴 \{#submenu\}

메뉴 항목에서 다른 메뉴를 열 수 있습니다. 항목에 `popovertarget`와 `aria-haspopup="menu"`를 지정하고, 상위 메뉴 안에서 해당 항목 바로 뒤에 `menu menu-sub` 클래스를 적용한 메뉴를 배치하세요. 항목에 꺾쇠 화살표가 표시되며 하위 메뉴가 열려 있는 동안 강조 표시가 유지됩니다. 하위 메뉴는 항목 옆에 높이를 맞춰 열리고, 공간이 부족하면 반대쪽에 열립니다. 팝오버는 중첩할 수 있으므로 상위 메뉴는 열린 상태를 유지하며, <kbd>Esc</kbd>를 누를 때마다 한 단계씩 닫힙니다.

## 메뉴 동작 \{#behavior\}

메뉴는 스크립트 없이도 사용할 수 있습니다. 브라우저가 메뉴를 열고 닫으며, <kbd>Tab</kbd>으로 항목 사이를 이동하고 <kbd>Esc</kbd>로 버튼에 포커스를 돌려보낼 수 있습니다. `menu` [동작](/guide/behaviors)은 선택 사항입니다. 사용자가 방향키 조작을 기대하는 애플리케이션에서 메뉴용 키보드 조작을 추가합니다.

`menu`는 `menu` 클래스와 `popover` 속성이 있는 요소를 받습니다. 옵션은 없으며, 연결을 해제하는 함수를 반환합니다. 하위 메뉴도 메뉴이므로 `attach()`에서처럼 같은 동작을 연결하세요.

```js name=app.js
import { menu } from '@master/ui/behaviors/menu.js'

for (const element of document.querySelectorAll('.menu')) menu(element)
```

- **열기.** 메뉴가 열리면 첫 번째 항목으로 포커스가 이동합니다.
- **이동.** 방향키, <kbd>Home</kbd>, <kbd>End</kbd> 또는 문자 키를 누르면 숨겨져 있거나 비활성화된 항목을 건너뛰며 포커스가 이동합니다. <kbd>Tab</kbd> 키를 누르면 메뉴가 닫힙니다.
- **하위 메뉴.** `aria-haspopup="menu"`가 지정된 항목 바로 뒤에 `menu-sub` 클래스가 적용된 메뉴가 있으면, 하위 메뉴 쪽 방향키로 열고 반대 방향키로 닫으면서 해당 항목으로 포커스를 돌려보냅니다. 오른쪽에서 왼쪽으로 표시하는 메뉴에서는 두 방향키의 역할이 바뀝니다.
- **항목의 기본 동작 유지.** 버튼, 링크, 레이블로 만든 항목의 체크박스나 라디오 버튼은 <kbd>Enter</kbd> 및 <kbd>Space</kbd> 키에 각 요소의 기본 동작대로 반응합니다. 이 동작은 상태를 설정하거나 이벤트를 디스패치하지 않습니다. 항목의 `click` 이벤트와 `menu-input`의 `change` 이벤트를 수신하세요.
- **역할.** 동작은 역할을 추가하지 않습니다. 미리보기처럼 동작을 연결할 때 메뉴에는 `role="menu"`를, 각 항목에는 `role="menuitem"`을 지정하세요.

## 컨텍스트 메뉴 \{#context-menu\}

`menu-context`를 적용한 메뉴는 버튼을 기준으로 배치하는 대신 포인터 위치에서 열립니다. 웹 플랫폼에는 오른쪽 클릭으로 팝오버를 여는 선언적 방법이 없으므로 메뉴 동작은 이를 위한 `contextMenu(target, menu)`를 내보냅니다. 오른쪽 클릭이나 길게 누르기로 `contextmenu` 이벤트가 발생하면 브라우저 기본 메뉴가 열리지 않도록 하고, 포인터 위치를 `--menu-x`와 `--menu-y`에 기록한 뒤 `showPopover()`를 호출합니다. 나머지는 스타일시트가 처리합니다. 메뉴는 해당 지점에서 아래쪽과 끝 방향으로 열립니다. 뷰포트 가장자리를 넘어갈 경우 `@position-try`가 위치나 크기를 따로 측정하지 않고 뷰포트 안쪽으로 방향을 바꿉니다.

컨텍스트 메뉴를 열 대상은 페이지에서만 알 수 있으므로 `attach()`는 컨텍스트 메뉴를 연결하지 않습니다. 미리보기에서는 `contextMenu`를 직접 호출하며, `MasterUI`는 미리보기가 불러오는 번들입니다. 프로젝트에서는 두 함수를 모두 가져오세요. `contextMenu`는 메뉴를 열고, `menu`는 미리보기의 `attach()`처럼 메뉴 안에서 키보드 조작을 지원합니다.

```js name=app.js
import { contextMenu, menu } from '@master/ui/behaviors/menu.js'

const target = document.getElementById('canvas')
const list = document.getElementById('canvas-menu')

contextMenu(target, list)
menu(list)
```

ContextMenu 키와 <kbd>Shift</kbd> <kbd>F10</kbd>은 대상의 중앙에 메뉴를 엽니다. 대상이 이 키 입력을 받으려면 포커스를 받을 수 있어야 하므로 `tabindex="0"` 속성을 지정합니다. 이 키를 눌렀을 때 `contextmenu` 이벤트를 보내지 않는 브라우저도 있으므로 동작은 키 입력도 직접 수신합니다. `contextMenu`는 연결을 해제하는 함수를 반환합니다. 같은 대상으로 다시 호출하면 기존 연결을 대체합니다.

## 접근성 \{#accessibility\}

- 스크립트가 없으면 메뉴는 버튼과 링크가 들어 있는 팝오버로 동작합니다. <kbd>Tab</kbd>으로 항목 사이를 이동하고, <kbd>Esc</kbd>를 누르면 메뉴가 닫히면서 포커스가 버튼으로 돌아갑니다. 이 상태로 올바르게 동작하므로 `role="menu"`를 추가하지 마세요.
- `role="menu"`와 `role="menuitem"`은 방향키로 이동할 수 있음을 나타냅니다. `menu` 동작이나 동일한 키보드 조작을 제공하는 자체 스크립트와 함께 사용할 때만 이 역할을 지정하세요.
- 아이콘만 있는 버튼에는 `aria-label`로 접근 가능한 이름을 지정하세요.
