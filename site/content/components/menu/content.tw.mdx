選單是在彈出視窗中列出可執行操作的元件。為容器加上 `popover` 屬性和 `.menu`，在容器內放入帶有 `menu-item` 的按鈕和連結，再用 `popovertarget` 讓按鈕指向容器。瀏覽器負責開關選單，CSS 錨點定位會將選單對齊按鈕，並在檢視區邊緣空間不足時翻轉方向。

## 項目 \{#items\}

`menu-item` 可用 `<button>` 執行操作，或用 `<a>` 導覽。指標移到某列時，該列會立即套用膠囊標籤的底色，沒有淡入效果，讓反白跟得上指標移動。用鍵盤將焦點移到某列時，該列還會顯示與文字同色的外框。在圖示上加上 [`icon`](/components/icon)，項目便會設定圖示大小，並在該列未使用時淡化圖示。

- 點擊連結會透過頁面導覽關閉選單。若要讓按鈕關閉選單，請如上例加上 `popovertarget` 和 `popovertargetaction="hide"`。若要保持選單開啟，省略這兩個屬性即可。
- `menu-item-danger` 會為具破壞性的操作套用危險文字色。
- `menu-shortcut` 會在列尾顯示快速鍵。
- 停用的按鈕會使用停用文字色。若要停用連結，請加上 `aria-disabled="true"` 並移除 `href`。

## 群組 \{#groups\}

`menu-label` 為群組加上標題。在 `<hr>` 上加上 `menu-separator`，就能在群組之間畫出一條延伸至選單兩側邊緣的細線。

## 子選單 \{#submenu\}

選單項目可以開啟另一個選單。為該項目加上 `popovertarget` 和 `aria-haspopup="menu"`，再將 `menu menu-sub` 緊接在項目後方，兩者都放在父選單內。該項目會顯示尖括形箭頭，並在子選單開啟期間保持反白。子選單會在該項目旁開啟並與其對齊，空間不足時會翻到另一側。彈出視窗可以巢狀排列，因此父選單會保持開啟，按 <kbd>Esc</kbd> 每次只會關閉一層。

## 選單行為 \{#behavior\}

選單無須腳本即可完整運作。瀏覽器負責開關，<kbd>Tab</kbd> 可在項目間移動焦點，<kbd>Esc</kbd> 會將焦點移回按鈕。`menu` [行為](/guide/behaviors)為選用功能。如果應用程式的使用者預期能用方向鍵操作選單，可套用這個行為來提供完整的選單鍵盤操作。

`menu` 接收帶有 `menu` 類別及 `popover` 屬性的元素，沒有選項，並傳回解除行為的函式。子選單也是選單，請比照 `attach()`，一併為子選單套用行為。

```js name=app.js
import { menu } from '@master/ui/behaviors/menu.js'

for (const element of document.querySelectorAll('.menu')) menu(element)
```

- **開啟。** 選單開啟時，焦點會移到第一個項目。
- **移動。** 方向鍵、<kbd>Home</kbd>、<kbd>End</kbd> 和字母鍵可在項目間移動焦點，並略過隱藏及停用的項目。按 <kbd>Tab</kbd> 會關閉選單。
- **子選單。** 若項目有 `aria-haspopup="menu"`，且後方緊接著 `menu-sub`，按指向子選單的方向鍵就會開啟子選單。按反方向鍵則會關閉子選單，並將焦點移回該項目。從右到左排列的選單會對調這兩個方向鍵。
- **保留項目的原生行為。** 按鈕、連結，以及標籤項目內的核取方塊或單選按鈕，都維持 <kbd>Enter</kbd> 和 <kbd>Space</kbd> 的原生操作方式。此行為不會設定狀態或派送事件。請在項目上監聽 `click`，並在 `menu-input` 上監聽 `change`。
- **角色。** 此行為不會新增角色。套用時請比照預覽，在選單上加上 `role="menu"`，並在項目上加上 `role="menuitem"`。

## 快顯選單 \{#context-menu\}

`menu-context` 會在指標所在位置開啟選單，不必靠著按鈕。網頁平台無法以宣告方式在按下滑鼠右鍵時開啟彈出視窗，因此選單行為匯出 `contextMenu(target, menu)` 來處理。按下右鍵或長按觸發 `contextmenu` 時，函式會阻止瀏覽器開啟原生選單，將指標位置寫入 `--menu-x` 和 `--menu-y`，再呼叫 `showPopover()`。其餘由樣式表處理。選單會從該點向下、朝結尾側展開。若會超出檢視區邊緣，`@position-try` 會讓它改朝檢視區中央展開，無須量測。

快顯選單要綁定至由頁面指定的目標，因此 `attach()` 不會自動綁定。預覽會自行呼叫 `contextMenu`，而 `MasterUI` 是預覽載入的套件。在專案中請匯入兩個函式，由 `contextMenu` 開啟選單，再由 `menu` 提供選單內的鍵盤操作。預覽中的鍵盤操作是由 `attach()` 設定的。

```js name=app.js
import { contextMenu, menu } from '@master/ui/behaviors/menu.js'

const target = document.getElementById('canvas')
const list = document.getElementById('canvas-menu')

contextMenu(target, list)
menu(list)
```

按 ContextMenu 鍵或 <kbd>Shift</kbd> <kbd>F10</kbd> 會在目標中央開啟選單。目標必須能取得焦點才能接收這些按鍵，因此加上了 `tabindex="0"`。部分瀏覽器在按下這些鍵時不會送出 `contextmenu`，所以此行為也會直接監聽按鍵。`contextMenu` 會傳回解除綁定的函式。對同一個目標再次呼叫時，會取代先前的綁定。

## 無障礙 \{#accessibility\}

- 未使用腳本時，選單就是由按鈕和連結組成的彈出視窗。<kbd>Tab</kbd> 可在項目間移動焦點，<kbd>Esc</kbd> 會關閉選單並將焦點移回按鈕。這樣已具備完整且正確的操作方式，請勿加上 `role="menu"`。
- `role="menu"` 和 `role="menuitem"` 表示選單支援方向鍵導覽。只有在套用 `menu` 行為，或自行以腳本提供相同的鍵盤操作時，才加上這些角色。
- 只有圖示的按鈕，請用 `aria-label` 提供無障礙名稱。

## React、Svelte 和 Vue \{#frameworks\}

`menu` 元件會根據資料算繪項目、將選單連結至觸發元件，並套用行為。若以目標元素取代觸發元件，元件就會建立快顯選單。使用 `npx master-ui add menu` 將元件複製到專案。[React、Svelte 和 Vue](/guide/frameworks) 說明如何建置及使用這些元件。
