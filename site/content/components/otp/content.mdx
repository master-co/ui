An OTP field takes a short code, one character to a slot: the six digits from a text message or an authenticator. Each slot is a native input drawn as a small well, the same material as a [text field](/components/input), so it rises to the sheet with an ink contour while it has focus. On a touch screen it can be filled from a [keypad](/components/keypad) drawn on the page.

## The behavior \{#behavior\}

Without script every slot is an ordinary input: the reader types a character and presses <kbd>Tab</kbd>. The `otp` [behavior](/guide/behaviors) makes the slots one field to the hand. It takes the root, the element with the `otp` class, and returns the function that detaches it.

```js name=app.js
import { otp } from '@master/ui/behaviors/otp.js'

const root = document.querySelector('.otp')
otp(root)

root.addEventListener('change', (event) => {
  if (event.detail) verify(event.detail.value)
})
```

- **Typing.** After a character, focus moves to the next slot. A character the slot does not allow is refused. A slot that takes focus has its character selected, so typing replaces it.
- **Going back.** <kbd>Backspace</kbd> clears the slot; in an empty slot it moves to the slot before and clears that one.
- **Pasting and autofill.** A pasted or autofilled code is spread over the slots: from the first slot when it is a whole code, from the slot it landed in when it is part of one.
- **Events.** A slot the script writes to dispatches `input`, as it does when typed in. When every slot is filled, the root dispatches a bubbling `change` with the code in `detail.value`. A slot's own `change` bubbles through the root too and has no `detail`, which is why the listener above checks for it.

| Option | What it sets |
| --- | --- |
| `pattern` | A regular expression one character must match. By default the `pattern` attribute of the first slot, and a digit when it has none |

Autofill is why the first slot carries `autocomplete="one-time-code"`. A phone that offers the code from a text message fills one field with all of it, and `maxlength="1"` would cut that code to one character before the script saw it. While attached, the behavior removes `maxlength` from the slots and keeps each to one character itself; detaching gives the attribute back. Without the script the attribute stays, and only the first character of an offered code arrives, which is a reason to prefer [one field](#one-field-is-enough) when codes arrive by message.

## One field is enough \{#one-field-is-enough\}

Slots are a visual convention, not a requirement. A single [input](/components/input) with `autocomplete="one-time-code"`, `inputmode="numeric"` and `maxlength="6"` takes the same code with no script, pastes naturally and is easier for a screen reader. Use slots when the product's voice calls for them.

## Accessibility \{#accessibility\}

- Group the slots in a `<fieldset>` with a label, and name each slot, since a slot has no visible label.
- `inputmode="numeric"` brings up the number pad without making the slot a number field.
- Do not clear the slots on an error. Mark them invalid and let the reader correct or paste again.
