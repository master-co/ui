스크롤 영역은 페이지 안에서 따로 스크롤할 수 있는 영역입니다. 패널 안의 긴 목록이나 폭이 넓은 표, 로그 등에 사용합니다. 플랫폼 기본 스크롤 동작을 유지하면서 가늘고 눈에 덜 띄는 스크롤바를 표시합니다. 콘텐츠가 가장자리 너머로 이어지는 곳은 서서히 흐려지고, 콘텐츠가 끝나는 곳은 선명하게 유지됩니다. 채팅이나 빌드 로그처럼 읽는 동안 끝부분에 내용이 추가되는 영역은 [새로 추가되는 내용을 따라갈](#follow) 수도 있습니다.

## 가장자리 페이드 동작 \{#how-the-fade-knows\}

페이드는 두 정지점을 사용자 지정 속성 `--scroll-area-start`와 `--scroll-area-end`로 지정한 마스크로 구현합니다. 영역 자체의 스크롤 타임라인에서 두 애니메이션이 이 속성을 제어합니다. 하나는 처음 1.5rem을 스크롤하는 동안 시작 가장자리에 페이드를 적용하고, 다른 하나는 마지막 1.5rem을 스크롤하는 동안 끝 가장자리의 페이드를 없앱니다. 스크립트나 스크롤 위치 감지용 요소는 사용하지 않습니다. 콘텐츠가 영역 밖으로 넘치지 않으면 타임라인이 비활성 상태로 유지되고 양쪽 가장자리 모두 선명하게 표시됩니다.

스크롤 기반 애니메이션을 지원하지 않는 브라우저에서도 스크롤 동작은 같으며 페이드 효과만 표시되지 않습니다.

## 영역 경계에서의 스크롤 동작 \{#scrolling-past-it\}

블록 축에서는 스크롤 영역의 끝에 도달하면 페이지 스크롤로 이어집니다. 영역 안에서 휠을 굴리거나 스와이프할 때 해당 방향으로 더 스크롤할 내용이 없으면, 페이지의 다른 콘텐츠 위에서와 마찬가지로 페이지가 스크롤됩니다. 스크롤 전파는 인라인 축에서만 차단됩니다. 따라서 가로로 스와이프하다가 행의 끝에 도달하면 그 자리에서 멈추고 브라우저의 뒤로 가기 제스처가 실행되지 않습니다.

## 새로 추가되는 내용 따라가기 \{#follow\}

채팅, 빌드 로그, 스트리밍되는 답변은 읽는 동안 끝부분에 내용이 추가됩니다. 영역에 `role="log"`를 지정하고 `follow` [동작](/guide/behaviors)을 연결하세요. 동작은 콘텐츠가 추가되는 동안 끝부분을 계속 보이게 하고, 사용자가 끝에서 벗어나도록 스크롤하는 즉시 따라가기를 멈추며, 다시 끝으로 돌아오면 따라가기를 재개합니다. 콘텐츠 뒤에 `hidden`을 지정한 `scroll-area-latest` 버튼을 두세요. 이 버튼은 영역이 따라가지 않는 동안에만 나타나며, 누르면 끝으로 스크롤하고 다시 따라갑니다.

동작은 다음과 같이 판단합니다.

- **따라가기.** 동작을 연결한 순간부터 영역은 따라가기 상태입니다. 영역을 끝까지 스크롤하고, 행이 추가되거나 스트리밍된 단어가 마지막 메시지에 들어오거나 이미지 로딩이 끝나는 등 담긴 내용이 늘어날 때마다 다시 끝까지 스크롤합니다.
- **멈추기.** 휠, 손가락, 스크롤바, <kbd>↑</kbd>, <kbd>Page Up</kbd>, <kbd>Home</kbd> 등 무엇으로든 시작 방향으로 스크롤하면 따라가기가 멈춥니다. 휠을 시작 방향으로 돌리면 영역이 움직이기 전에 즉시 멈추므로, 그 순간 단어가 추가되어도 사용자를 다시 끝으로 끌어당기지 않습니다.
- **다시 따라가기.** <kbd>End</kbd> 키, 스크롤바, 버튼으로 다시 끝에 도달하면 따라가기를 재개합니다. 끝에서 몇 픽셀 모자란 위치도 끝으로 간주합니다.
- **이벤트.** 사용자의 조작으로 따라가기가 시작되거나 멈출 때마다 영역은 `change`를 발생시킵니다. 동작의 `value`는 따라가기 여부를 나타냅니다. 사용자가 메시지를 보냈을 때처럼 사용자를 끝으로 데려가려면 `true`로 설정하세요. 값을 설정해도 이벤트는 발행하지 않습니다.

```js name=app.js
import { follow } from '@master/ui/behaviors/follow.js'

const log = document.querySelector('.scroll-area[role="log"]')
const following = follow(log)

form.addEventListener('submit', () => { following.value = true })
```

동작이 없으면 영역은 일반 스크롤 영역으로, 사용자가 둔 위치에 머무르며 버튼은 숨겨진 상태로 남습니다. 버튼은 스크롤하는 동안 영역의 아래쪽 가장자리에 붙어 있으며, 콘텐츠와 페이드 효과보다 앞에 표시됩니다., 마지막 행 위에 겹쳐 표시되므로 버튼이 나타나도 콘텐츠의 높이가 늘어나지 않습니다.

## 읽던 위치 유지 \{#keeping-the-place\}

위쪽에서 이전 메시지를 불러오는 것처럼 사용자가 보고 있는 부분보다 위에 콘텐츠를 삽입하면, 읽고 있던 내용이 아래로 밀려납니다. 브라우저는 스크롤 앵커링으로 이를 자체적으로 방지합니다. 영역이 위쪽 콘텐츠와 함께 움직이므로 읽고 있던 메시지가 제자리에 머무릅니다. 스타일시트는 영역에 `overflow-anchor: auto`를 유지하고, 브라우저가 고정 기준으로 삼지 않아야 하는 버튼에는 `none`을 지정합니다. 스크롤 앵커링을 지원하지 않는 브라우저에서는 `follow` 동작이 위쪽 콘텐츠가 움직인 만큼 직접 같은 처리를 합니다. 추가 내용을 불러오는 중이라는 안내처럼 그 아래에 행이 삽입되는 맨 위의 줄에도 `overflow-anchor: none`을 지정하세요. 그러면 브라우저가 그 줄 대신 행을 고정 기준으로 삼습니다.

## 접근성 \{#accessibility\}

- 스크롤할 수 있는 영역에는 키보드로 접근할 수 있어야 합니다. 영역 안에 포커스를 받을 수 있는 콘텐츠가 없다면 영역에 `tabindex="0"`과 `region` 같은 `role`, 그리고 레이블을 지정하세요.
- 마스크는 같은 가장자리에서 영역 자체의 스크롤바도 흐리게 표시합니다. 강제 색상 모드에서는 마스크를 제거합니다.
- 영역의 높이나 최대 높이를 지정하세요. 둘 다 지정하지 않으면 콘텐츠에 맞춰 영역이 늘어나므로 스크롤이 생기지 않습니다.
- `role="log"`는 정중한(polite) 라이브 영역입니다. 여기에 추가된 내용은 포커스를 옮기지 않고 안내됩니다. 메시지에 답변이 스트리밍되는 동안 해당 메시지에 `aria-busy="true"`를 지정하고 답변이 완료되면 제거하세요. 그러면 단어 하나하나가 아니라 완성된 메시지가 한 번에 읽힙니다.
- `scroll-area-latest` 버튼은 표시되는 동안 탭 순서에 포함되는 실제 버튼입니다. 누르면 버튼이 숨겨지고 포커스가 영역으로 이동하므로, 이후 키보드로 영역을 스크롤할 수 있습니다.
- 따라가기는 포커스를 옮기지 않으며 사용자가 스크롤해 벗어나는 즉시 멈춥니다. 따라서 계속 추가되는 콘텐츠 때문에 읽던 내용이 사용자 눈앞에서 사라지지 않습니다.
