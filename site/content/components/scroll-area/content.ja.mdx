スクロール領域は、パネル内の長いリスト、幅の広いテーブル、ログなどをページ内でスクロールできるようにする領域です。プラットフォーム標準のスクロール動作を保ち、細く控えめなスクロールバーを表示します。コンテンツが領域の外に続く側の端にはフェードがかかり、コンテンツの終端ではフェードが消えます。チャットやビルドログのように、読んでいる間に末尾が伸びていく領域では、[追加される内容に追従](#follow)させることもできます。

## フェードの仕組み \{#how-the-fade-knows\}

フェードにはマスクを使い、その2つの色停止点をカスタムプロパティ`--scroll-area-start`と`--scroll-area-end`で指定します。領域自体のスクロールタイムライン上で2つのアニメーションがこれらの値を変化させます。最初の1.5remで始端のフェードが現れ、最後の1.5remで終端のフェードが消えます。スクリプトも監視用の要素も不要です。コンテンツがはみ出していないときはタイムラインが無効になり、どちらの端にもフェードはかかりません。

スクロール駆動アニメーションに対応していないブラウザーでも、領域は同じようにスクロールします。フェードは表示されません。

## スクロールの連鎖 \{#scrolling-past-it\}

ブロック軸では、スクロール領域の端に達したあともページを続けてスクロールできます。領域内をそれ以上スクロールできない状態で、その上からホイール操作やスワイプを始めると、ほかのコンテンツ上と同じようにページがスクロールします。スクロールの連鎖を抑えるのはインライン軸だけです。横にスワイプして行の端に達すると、そこで止まり、ブラウザーの「戻る」ジェスチャーは作動しません。

## インライン軸のスクロール \{#inline\}

`scroll-area-inline`は横方向にスクロールし、インライン軸の始端と終端にフェードをかけます。横一列に並んだカードや、カラム幅に収まらない[テーブル](/components/table#wide-tables)に使えます。

## 追加される内容への追従 \{#follow\}

チャット、ビルドログ、ストリーミングされる回答は、読んでいる間に末尾が伸びていきます。領域に`role="log"`を指定し、`follow`[ビヘイビア](/guide/behaviors)を適用します。ビヘイビアは、内容が追加される間は末尾を表示し続け、読者が末尾からスクロールして離れた時点で追従をやめ、末尾に戻ると再び追従します。内容の後に`hidden`を指定した`scroll-area-latest`ボタンを置きます。このボタンは領域が追従していない間だけ表示され、押すと末尾までスクロールして再び追従します。

判断の仕組みは次のとおりです。

- **追従。** ビヘイビアを適用した時点から追従します。領域を末尾までスクロールし、行の追加、最後のメッセージへのストリーミングされた単語の到着、画像の読み込み完了など、内容が増えるたびに再び末尾までスクロールします。
- **停止。** ホイール、指、スクロールバー、<kbd>↑</kbd>、<kbd>Page Up</kbd>、<kbd>Home</kbd>など、どの方法でも先頭方向にスクロールすると追従をやめます。ホイールを先頭方向に回した場合は、領域が動く前に即座に停止するため、その瞬間に届いた単語が読者を引き戻すことはありません。
- **再開。** <kbd>End</kbd>、スクロールバー、ボタンのいずれかで再び末尾に達すると、追従を再開します。末尾まで数ピクセル足りない位置も末尾とみなします。
- **イベント。** 読者の操作で追従を開始または停止するたびに、領域は`change`を発行します。ビヘイビアの`value`は追従しているかどうかを示します。読者がメッセージを送信したときのアプリケーションのように、読者を末尾に移動させるには`true`を設定します。設定してもイベントは発行されません。

```js name=app.js
import { follow } from '@master/ui/behaviors/follow.js'

const log = document.querySelector('.scroll-area[role="log"]')
const following = follow(log)

form.addEventListener('submit', () => { following.value = true })
```

ビヘイビアがない場合、領域は通常のスクロール領域です。読者が最後にスクロールした位置を保ち、ボタンは非表示のままです。ボタンにはスティッキー配置が適用され、領域の下端に張り付いて、内容や端のフェードより手前に表示されます。最後の行の後ではなく上に重なるため、ボタンを表示しても内容の高さは変わりません。

## 読んでいる位置の維持 \{#keeping-the-place\}

上部に読み込まれる古いメッセージのように、読者が見ている位置より上に内容が挿入されると、読んでいる内容が下に押し下げられてしまいます。ブラウザーはスクロールアンカリングによってこれを自動的に防ぎます。上に追加された内容に合わせて領域内のスクロール位置を補正するため、読んでいるメッセージは表示上の位置を保ちます。スタイルシートは、領域に`overflow-anchor: auto`、ボタンに`none`を指定します。ボタンがブラウザーの固定する要素になることはありません。スクロールアンカリングに対応していないブラウザーでは、`follow`ビヘイビアが、上の内容が動いた分だけスクロール位置を補正します。さらに読み込み中であることを示す注記など、行がその下に挿入される上部の行にも`overflow-anchor: none`を指定します。これにより、ブラウザーはその行ではなく、内容の行を固定します。

## アクセシビリティ \{#accessibility\}

- スクロール領域はキーボードでフォーカスできる必要があります。すでにフォーカス可能なコンテンツが含まれている場合を除き、領域に`tabindex="0"`、`region`などの`role`、ラベルを指定します。
- マスクは、同じ端で領域自体のスクロールバーにもフェードをかけます。強制カラーモードではマスクが解除されます。
- 領域には高さまたは最大の高さを指定します。指定しないと、領域はコンテンツに合わせて伸び、スクロールしません。
- `role="log"`を指定したライブリージョンでは、aria-live の既定値は polite です。追加された内容はフォーカスを動かさずに読み上げられます。回答がメッセージにストリーミングされている間は、そのメッセージに`aria-busy="true"`を指定し、回答が完了したら削除します。これにより、メッセージは単語ごとではなく、完成した状態で一度だけ読み上げられます。
- `scroll-area-latest`ボタンは、表示されている間はタブ順序に含まれる実際のボタンです。押すとボタンは非表示になり、フォーカスは領域に移ります。その後はキー操作で領域をスクロールできます。
- 追従によってフォーカスが動くことはなく、読者がスクロールして離れるとすぐに停止します。そのため、内容が次々に追加されても、読んでいる位置を保てます。
