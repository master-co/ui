## 표시 및 닫기 \{#showing-and-dismissing\}

- `open` 속성이 있는 토스트는 페이지가 로드될 때 표시됩니다. 양식이 POST로 제출된 뒤 서버에서 렌더링하는 메시지에 적합합니다.
- 스크립트에서는 영역에 새 `<dialog open class="toast">`를 추가하거나, 영역 안에 있는 토스트에 `open`을 설정하세요. 두 경우 모두 `@starting-style` 규칙이 토스트 등장 동작의 시작 프레임을 지정합니다. `show()`는 호출하지 마세요. 사용자가 하던 작업에서 토스트 안으로 포커스를 옮깁니다.
- 버튼을 `<form method="dialog">` 요소로 감싸거나 버튼에 `commandfor`와 `command="close"`를 지정하면 버튼을 눌러 토스트를 닫을 수 있습니다. `display` 속성은 `allow-discrete`와 함께 전환되므로, 토스트가 차지하던 공간이 사라지기 전에 닫히는 동작이 재생됩니다.

## 자동 닫기 \{#timed\}

`toast-timed` 클래스를 사용하면 토스트가 6초 후에 자동으로 닫힙니다. 시간은 `display: none`으로 끝나는 CSS 애니메이션으로 제어합니다. 포인터가 토스트 위에 있거나 키보드 포커스가 토스트 안에 있으면 애니메이션이 일시 정지되어 내용을 읽을 시간을 확보할 수 있습니다. 토스트 아래쪽의 가는 선은 남은 시간에 따라 줄어들고 타이머가 멈추면 함께 멈춥니다. 시간을 변경하려면 `--toast-duration` 사용자 지정 속성을 설정하세요. 작업 중 상태의 토스트에는 타이머가 없으며, 작업이 끝나야 타이머가 시작됩니다.

## 동작 버튼 \{#with-an-action\}

토스트에는 닫기 버튼 옆에 실행 취소나 보기처럼 동작 버튼 하나를 둘 수 있습니다. `toast-action`은 텍스트 뒤에 놓이며, `btn btn-sm`을 감싸는 `<form method="dialog">`입니다. 따라서 동작이 실행되면 토스트가 닫힙니다. 버튼에 `value`를 지정하세요. 그러면 대화 상자의 `returnValue`로 어느 버튼이 토스트를 닫았는지 알 수 있으므로, `close` 리스너 하나로 동작을 실행할 수 있습니다. 동작 버튼은 <kbd>Tab</kbd> 키로 접근할 수 있는 실제 버튼이며, 이 버튼에 포커스가 있거나 포인터가 토스트 위에 있는 동안에는 자동 닫기 타이머가 일시 정지됩니다.

토스트는 자동으로 사라지므로 사용자가 보지 못할 수도 있습니다. 따라서 토스트 안의 동작은 바로 가기일 뿐, 유일한 수단이 되어서는 안 됩니다. 삭제한 항목 복원이나 실패한 저장 재시도처럼 중요한 동작은 항목 자체의 메뉴, 휴지통, 실패한 폼 옆의 [알림](/components/alert)처럼 계속 남아 있는 곳에도 두세요. 상태를 지정하는 수정자는 아이콘에만 색을 적용하며 텍스트는 기본 글자색을 유지합니다.

## 진행 중 상태와 제자리 갱신 \{#pending\}

토스트는 진행 중인 작업을 알린 뒤, 같은 자리에서 작업이 어떻게 끝났는지 알릴 수 있습니다. 작업이 진행되는 동안 토스트에는 `aria-busy="true"`를 지정하고, 아이콘 자리에 `toast-icon`을 지정한 [스피너](/components/spinner)를 둡니다. 작업이 아무리 오래 걸려도 타이머는 흐르지 않습니다. 작업이 끝나면 같은 토스트의 텍스트, 상태, 아이콘을 바꾸고 `aria-busy`를 제거하세요. 토스트는 다시 등장하지 않고 쌓인 순서의 자리를 유지하며, 새 아이콘만 제자리에서 커지며 나타납니다.

## 토스트 영역 \{#the-region\}

`toast-region`은 하단의 인라인 끝 모서리에 고정되며 가장 최근 토스트를 맨 아래에 쌓습니다. 영역 자체는 포인터 이벤트를 받지 않으므로 빈 부분 아래에 있는 페이지를 계속 조작할 수 있습니다. 좁은 화면에서는 화면 너비 전체를 차지합니다.

| 클래스 | 배치 |
| --- | --- |
| `toast-region` | 하단의 인라인 끝 |
| `toast-region-top` | 상단. 토스트가 아래 방향으로 나타나며 가장 최근 토스트가 맨 위에 배치됩니다. |
| `toast-region-center` | 인라인 끝 대신 가운데에 배치 |

이 영역은 `z-index`가 지정된 일반 고정 배치 요소입니다. 열린 모달 [대화 상자](/components/dialog) 위에 토스트를 표시하려면 영역에 `popover="manual"`를 지정하고 해당 영역에서 `showPopover()`를 한 번 호출하세요. 그러면 영역이 최상위 레이어에 배치됩니다.

## 접근성 \{#accessibility\}

- 토스트가 나타날 때 스크린 리더가 읽도록 `aria-live="polite"`를 지정해 라이브 영역으로 만들고, `aria-label`로 영역의 접근 가능한 이름을 지정하세요.
- 각 토스트에는 제목을 가리키는 `aria-labelledby` 속성이나 `aria-label` 속성으로 접근 가능한 이름을 지정하세요.
- 제자리에서 텍스트가 바뀌는 토스트에는 `aria-atomic="true"`를 지정하세요. 그러면 변경 내용이 조각조각이 아니라 토스트 전체로 한 번 안내됩니다. 작업 중 상태인 동안에는 스크린 리더가 작업이 끝날 때까지 안내를 보류할 수 있습니다.
- 토스트는 작업 결과를 확인하는 용도입니다. 사용자가 토스트를 놓쳐도 필요한 정보나 기능에 접근할 수 있어야 하므로, 어떤 동작을 실행하는 유일한 수단을 토스트 안에 두지 마세요.
- 토스트는 나타날 때 포커스를 가져가지 않습니다. 동작 버튼과 닫기 버튼은 탭 순서에 포함되며, 둘 중 하나에 포커스가 있는 동안에는 자동 닫기 타이머가 일시 정지됩니다.
- 동작 줄이기가 설정되어 있으면 토스트는 제자리에서 서서히 나타나고 사라지며, 새 아이콘은 크기 변화 없이 서서히 나타납니다.

## React, Svelte 및 Vue \{#frameworks\}

`toast` 컴포넌트는 토스트를 큐로 관리합니다. 어디서든 호출할 수 있는 `toast()` 함수와 큐의 내용을 표시하는 영역으로 구성되며, 영역은 한 번만 렌더링합니다. `npx master-ui add toast`를 사용해 프로젝트에 복사하세요. 컴포넌트의 구성과 사용법은 [React, Svelte 및 Vue](/guide/frameworks)에서 확인할 수 있습니다.

- `toast(message)`는 토스트를 표시하고 핸들을 반환합니다. `update(message)`는 다시 등장하지 않고 같은 토스트에 다른 내용을 표시하며 타이머를 다시 시작합니다. `dismiss()`는 토스트 자체의 버튼을 누른 것처럼 토스트를 닫습니다. 메시지에는 `title`, `description`, `status`, 밀리초 단위의 `duration`(`false`이면 토스트가 계속 남음), `action`이 있으며, 문자열을 전달하면 설명으로 사용합니다.
- `status: 'pending'`은 스피너를 표시하고 `aria-busy`를 설정하며, 토스트가 갱신될 때까지 유지합니다.
- `action: { label, onClick }`은 토스트가 제공하는 하나의 버튼입니다. `onClick`을 실행한 뒤 토스트를 닫습니다. 단, 핸들러가 `event.preventDefault()`를 호출하면 닫지 않습니다.
- `toast.promise(promise, { loading, success, error })`는 `loading`을 진행 중 상태의 토스트로 표시한 뒤, 같은 토스트를 성공 시 `success` 메시지로, 실패 시 `danger` 상태의 error 메시지로 갱신합니다. 성공 메시지는 이행 값을, 실패 메시지는 거부 사유를 받는 함수로 지정할 수 있습니다. 전달한 프로미스를 반환하므로 완료를 기다리거나 후속 처리를 연결할 수 있습니다.

```tsx
toast({ title: 'Project archived', action: { label: 'Undo', onClick: () => restore(project) } })

await toast.promise(deploy(project), {
  loading: { title: 'Deploying Atlas' },
  success: (release) => ({ title: 'Deployed to production', description: `${release.url} is live.` }),
  error: (error) => ({ title: 'The deploy failed', description: String(error), duration: false }),
})
```
