A toast is a brief message over the page about something that just happened (saved, deployed, copied), or about work under way whose end it will report. Each toast is a non-modal `<dialog>` inside a fixed `toast-region`. Being a dialog, it can be dismissed without script, and it enters and leaves with motion the stylesheet writes in CSS.

## Showing and dismissing \{#showing-and-dismissing\}

- A toast with the `open` attribute is shown when the page loads, which suits a message rendered by the server after a form post.
- From script, append a new `<dialog open class="toast">` to the region, or set `open` on a toast that is there. `@starting-style` gives the toast the frame it arrives from in both cases. Do not call `show()`: it moves focus into the toast, away from what the reader was doing.
- A `<form method="dialog">` around a button dismisses the toast, as does a button with `commandfor` and `command="close"`. `display` transitions with `allow-discrete`, so the exit plays before the toast stops taking space.
- A toast that has left stays in the document. Where a page appends a toast for each message, the `toast` [behavior](/guide/behaviors) removes each one once it has run out, or been dismissed and left: `toast(region)`. `attach()` leaves it out, since a page that opens the same toast again keeps it.

## Timed \{#timed\}

`toast-timed` makes a toast leave by itself after six seconds. The clock is a CSS animation that ends in `display: none`, and it pauses while the pointer or the keyboard is on the toast, so a reader is never raced. A hairline along the toast's foot runs out with the clock and stops when the clock does. Set `--toast-duration` to change the time. A busy toast keeps no clock; its clock starts once the work has ended.

## With an action \{#with-an-action\}

A toast may offer one action beside its dismiss button, such as Undo or View. `toast-action` sits after the words: a `<form method="dialog">` around a `btn btn-sm`, so the action dismisses the toast once it has run. Give the button a `value`: the dialog's `returnValue` then says which button closed it, and one `close` listener runs the action. The action is a real button, reached with <kbd>Tab</kbd>, and a timed toast waits while the action holds focus or the pointer is on the toast.

A toast leaves by itself and a reader may never see it, so an action in it is a shortcut, never the only way. Anything important (restoring what was deleted, retrying a failed save) also lives somewhere that stays: the item's own menu, a trash, an [alert](/components/alert) beside the failed form. A status modifier colors the icon only; the words stay in ink.

## Pending, then updated in place \{#pending\}

A toast can report work as it runs and then say how it ended, in the same place. While the work runs, the toast carries `aria-busy="true"` and holds a [spinner](/components/spinner) with `toast-icon` where its icon goes; its clock does not run, however long the work takes. When the work ends, change the same toast: its words, its status, its icon, and remove `aria-busy`. The toast does not enter again and keeps its place in the stack; only the new icon grows into place.

The same toast can change again, from one count to the next while files upload, or from a failure to a retry. Each change starts its clock again, so a reader gets the whole time for the new words. A busy toast is not the place to follow a long task that matters: [progress](/components/progress) beside the work stays where it is.

## Rich content \{#rich-content\}

A toast holds more than words with the components that already draw them: an [avatar](/components/avatar) at its start for who did something, a [file](/components/file) in its body for what arrived, and a file's progress for an upload still running. The toast keeps its own geometry: the picture stands where the status icon would, and the file takes the width of the words.

An upload that is still running is a toast without `toast-timed`, so it stays until the work ends; the toast that says it is done is the same toast updated in place, as [above](#pending). Keep what matters reachable elsewhere: the file in its folder, the mention in its thread.

## The region \{#the-region\}

`toast-region` is fixed to the bottom end corner and stacks toasts with the newest at the bottom. It takes no pointer events itself, so the page under its empty space stays usable. On a narrow screen it spans the width.

| Class | Placement |
| --- | --- |
| `toast-region` | Bottom, at the end edge |
| `toast-region-top` | Top; toasts arrive downward and the newest is on top |
| `toast-region-center` | Centered instead of at the end edge |

The region is an ordinary fixed element with a `z-index`. To show toasts above an open modal [dialog](/components/dialog), give the region `popover="manual"` and call `showPopover()` on it once: it then joins the top layer.

## Accessibility \{#accessibility\}

- Make the region a live region with `aria-live="polite"`, so a toast is announced when it appears, and name the region with `aria-label`.
- Name each toast with `aria-labelledby` pointing at its title, or with `aria-label`.
- Give a toast whose words change in place `aria-atomic="true"`, so a change is announced once, as the whole toast, not piece by piece. While it is busy, a screen reader may hold the announcement until the work has ended.
- A toast is for confirmation. A reader must be able to miss it without losing anything, so do not put the only way to an action in one.
- A toast does not take focus when it appears. Its action and dismiss buttons are in the tab order, and a timed toast waits while either holds focus.
- With reduced motion a toast fades in place, and a new icon fades in at its size.

## React, Svelte and Vue \{#frameworks\}

The `toast` component is a queue: a `toast()` function to call from anywhere, and the region, rendered once, that shows what is in it. Copy it into the project with `npx master-ui add toast`; [React, Svelte and Vue](/guide/frameworks) says how the components are built and used.

- `toast(message)` shows a toast and returns a handle. `update(message)` says something else in the same toast, with no second entrance, and starts its clock again; `dismiss()` lets it leave as its own button would. A message has a `title`, a `description`, a `status`, a `duration` in milliseconds (`false` keeps the toast) and an `action`; a string is a description.
- `status: 'pending'` shows the spinner and sets `aria-busy`, and keeps the toast until it is updated.
- `action: { label, onClick }` is the one button the toast offers. It runs `onClick`, then dismisses the toast, unless the handler calls `event.preventDefault()`.
- `toast.promise(promise, { loading, success, error })` shows `loading` as a pending toast, then turns the same toast into `success`, or into a failure with the `danger` status. Either may be a function of the value or of the reason. It returns the promise, to await or chain.

```tsx
toast({ title: 'Project archived', action: { label: 'Undo', onClick: () => restore(project) } })

await toast.promise(deploy(project), {
  loading: { title: 'Deploying Atlas' },
  success: (release) => ({ title: 'Deployed to production', description: `${release.url} is live.` }),
  error: (error) => ({ title: 'The deploy failed', description: String(error), duration: false }),
})
```
