浮動通知是在頁面上方短暫顯示的訊息，用來告知使用者剛發生的事（例如已儲存、已部署或已複製），或告知正在進行、之後會回報結果的工作。每則通知都是固定定位的 `toast-region` 內的非模態 `<dialog>`，可透過對話框的原生機制關閉，無須腳本，進出場動畫則由 CSS 樣式表處理。

## 顯示與關閉 \{#showing-and-dismissing\}

- 帶有 `open` 屬性的通知會在頁面載入時顯示，適合在表單以 POST 送出後，由伺服器直接算繪訊息。
- 在腳本中，在區域內附加新的 `<dialog open class="toast">`，或為區域內現有的通知設定 `open`。兩種做法都會透過 `@starting-style` 設定通知進場時的起始樣式。請勿呼叫 `show()`：它會把焦點移入通知，讓使用者離開正在進行的操作。
- 將按鈕放在 `<form method="dialog">` 裡，或在按鈕上設定 `commandfor` 和 `command="close"`，都能關閉通知。`display` 透過 `allow-discrete` 進行轉場，讓退場動畫播完後，通知才停止占用空間。

## 限時 \{#timed\}

`toast-timed` 會讓通知在六秒後自動消失。計時由 CSS 動畫控制，動畫結束時套用 `display: none`。指標停在通知上或鍵盤焦點位於通知內時，計時會暫停，讓使用者有足夠時間閱讀。通知底部的細線會隨剩餘時間縮短，並與計時同步暫停。用 `--toast-duration` 調整顯示時間。忙碌中的通知不會計時；工作結束後才開始計時。

## 附操作按鈕 \{#with-an-action\}

通知可以在關閉按鈕旁提供一個操作，例如「復原」或「檢視」。`toast-action` 放在文字之後：用 `<form method="dialog">` 包住一個 `btn btn-sm`，讓操作執行後關閉通知。請為按鈕設定 `value`：對話框的 `returnValue` 就會指出是哪個按鈕關閉了它，只需一個 `close` 監聽器即可執行操作。操作是真正的按鈕，可用 <kbd>Tab</kbd> 移到它；當操作取得焦點或指標停在通知上時，限時通知會暫停計時。

通知會自動消失，使用者可能根本沒看到，因此通知中的操作只是捷徑，絕不能是唯一的途徑。重要的操作（例如還原已刪除的項目、重試儲存失敗的內容）也要放在會持續存在的地方：項目本身的選單、垃圾桶，或失敗表單旁的[提示訊息](/components/alert)。狀態修飾類別只改變圖示的顏色，文字維持原本的前景色。

## 先顯示進行中，再原地更新 \{#pending\}

通知可以在工作進行時回報狀態，並在同一個位置說明結果。工作進行期間，通知帶有 `aria-busy="true"`，並在圖示的位置放一個帶有 `toast-icon` 的[旋轉指示器](/components/spinner)；無論工作進行多久，計時都不會開始。工作結束時，請直接修改同一則通知：更換文字、狀態和圖示，並移除 `aria-busy`。通知不會再次進場，在堆疊中的位置也不變；只有新的圖示會放大出現。

同一則通知可以再次變更，例如在上傳檔案時從一個數量更新到下一個，或從失敗變成重試。每次變更都會重新開始計時，讓使用者有完整的時間閱讀新文字。忙碌中的通知不適合用來追蹤重要的長時間工作：放在工作旁邊的[進度](/components/progress)會持續留在原處。

## 通知區域 \{#the-region\}

`toast-region` 固定在底部靠末端的一角，將通知堆疊起來，最新一則排在最下方。區域本身不接收指標事件，透過區域的空白處仍可操作被覆蓋的頁面。在窄螢幕上，通知區域會橫跨整個寬度。

| 類別 | 位置 |
| --- | --- |
| `toast-region` | 底部，靠末端邊緣 |
| `toast-region-top` | 頂部，通知向下進場，最新一則排在最上方 |
| `toast-region-center` | 水平置中 |

通知區域是設有 `z-index` 的一般固定定位元素。要讓通知顯示在已開啟的模態[對話框](/components/dialog)上方，請為區域設定 `popover="manual"`，再對它呼叫一次 `showPopover()`，即可將它放入頂層。

## 無障礙 \{#accessibility\}

- 用 `aria-live="polite"` 將通知區域設為即時區域，讓通知出現時能由輔助技術朗讀，並以 `aria-label` 為區域命名。
- 每則通知都應設定名稱，可用 `aria-labelledby` 指向標題，或直接設定 `aria-label`。
- 為原地更新文字的通知設定 `aria-atomic="true"`，讓每次變更都以整則通知的形式播報一次，而不是逐一播報片段。通知忙碌期間，螢幕閱讀器可能會等到工作結束才播報。
- 浮動通知用來確認結果。使用者即使錯過通知，也應能取得所需資訊或完成操作，因此請在通知之外保留操作入口。
- 通知出現時不會取得焦點。它的操作按鈕和關閉按鈕都在 Tab 順序中，其中任一個取得焦點時，限時通知會暫停計時。
- 啟用減少動態效果時，通知會在原地淡入淡出，新的圖示也會以原尺寸淡入。

## React、Svelte 和 Vue \{#frameworks\}

`toast` 元件以佇列管理通知。你可以從任何地方呼叫 `toast()` 函式，只需算繪一次通知區域，即可顯示佇列中的通知。使用 `npx master-ui add toast` 將元件複製到專案中，並參閱 [React、Svelte 和 Vue](/guide/frameworks) 瞭解元件的建構方式和用法。

- `toast(message)` 會顯示一則通知並傳回一個控制代碼。`update(message)` 會在同一則通知中顯示其他內容，不會再次進場，並重新開始計時；`dismiss()` 會讓通知像按下它自己的關閉按鈕一樣離開。訊息包含 `title`、`description`、`status`、以毫秒為單位的 `duration`（設為 `false` 會讓通知保留）以及 `action`；傳入字串時視為 description。
- `status: 'pending'` 會顯示旋轉指示器並設定 `aria-busy`，通知會保留到被更新為止。
- `action: { label, onClick }` 是通知提供的唯一按鈕。它會執行 `onClick`，接著關閉通知，除非處理函式呼叫了 `event.preventDefault()`。
- `toast.promise(promise, { loading, success, error })` 會以進行中的通知顯示 `loading`，再把同一則通知變成 `success`，或變成帶有 `danger` 狀態的失敗訊息。兩者都可以是接收值或失敗原因的函式。它會傳回該 promise，可供 await 或串接。

```tsx
toast({ title: 'Project archived', action: { label: 'Undo', onClick: () => restore(project) } })

await toast.promise(deploy(project), {
  loading: { title: 'Deploying Atlas' },
  success: (release) => ({ title: 'Deployed to production', description: `${release.url} is live.` }),
  error: (error) => ({ title: 'The deploy failed', description: String(error), duration: false }),
})
```
