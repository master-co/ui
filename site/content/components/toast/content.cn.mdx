轻提示是浮在页面上的简短消息，用来告知用户刚刚发生的事（例如已保存、已部署或已复制），或告知正在进行、完成后会报告结果的工作。每条轻提示都是固定定位的 `toast-region` 内的非模态 `<dialog>`。轻提示采用对话框，因此无需脚本即可关闭，入场和退场动画均由样式表中的 CSS 实现。

## 显示与关闭 \{#showing-and-dismissing\}

- 带有 `open` 属性的轻提示会在页面加载时显示，适用于表单提交后由服务器渲染的消息。
- 在脚本中，向该区域追加一个新的 `<dialog open class="toast">`，或为区域内已有的轻提示设置 `open`。两种方式都由 `@starting-style` 定义轻提示入场时的起始帧。不要调用 `show()`：它会把焦点移入轻提示，打断用户正在进行的操作。
- 用 `<form method="dialog">` 包裹按钮，或为按钮设置 `commandfor` 和 `command="close"`，都能关闭轻提示。`display` 通过 `allow-discrete` 进行过渡，因此退场动画会在轻提示释放布局空间前播放完毕。
- 离开后的轻提示仍留在文档中。如果页面为每条消息追加一个新的轻提示，`toast` [行为脚本](/guide/behaviors)会在它到期，或被关闭并退场后将其移除：`toast(region)`。`attach()` 不包含它，因为重复打开同一个轻提示的页面需要保留它。

## 定时关闭 \{#timed\}

`toast-timed` 让轻提示在六秒后自动消失。计时由一个以 `display: none` 结束的 CSS 动画实现。指针悬停在轻提示上或键盘焦点位于其中时，计时会暂停，让用户有时间读完。轻提示底部的细线随倒计时逐渐缩短，并随计时一起暂停。设置 `--toast-duration` 可调整时长。处于忙碌状态的轻提示不计时，工作结束后才开始计时。

## 带操作按钮 \{#with-an-action\}

轻提示可以在关闭按钮旁提供一个操作，例如“撤销”或“查看”。`toast-action` 位于文字之后：它是包裹 `btn btn-sm` 的 `<form method="dialog">`，因此操作执行后会关闭轻提示。为按钮设置 `value`，对话框的 `returnValue` 就会表明是哪个按钮关闭了它，只需一个 `close` 监听器即可执行相应操作。该操作是真正的按钮，可用 <kbd>Tab</kbd> 键到达；操作按钮持有焦点或指针悬停在轻提示上时，定时关闭的轻提示会等待。

轻提示会自动消失，用户可能根本看不到它，因此其中的操作只是一条捷径，绝不能是唯一的途径。任何重要的操作（恢复已删除的内容、重试保存失败的内容）也要放在持续存在的地方：条目自身的菜单、回收站，或失败表单旁的[行内提示](/components/alert)。状态修饰类只为图标着色，文字保留墨色。

## 先显示进行中，再原地更新 \{#pending\}

轻提示可以在工作进行时报告进度，然后在同一位置说明结果。工作进行期间，轻提示带有 `aria-busy="true"`，并在图标的位置放一个带有 `toast-icon` 的[加载指示器](/components/spinner)；无论工作持续多久，其计时都不会开始。工作结束后，修改同一条轻提示：更新文字、状态和图标，并移除 `aria-busy`。轻提示不会再次入场，在堆叠中的位置也保持不变，只有新图标会放大出现。

同一条轻提示可以再次变化，例如上传文件时从一个计数变为下一个，或从失败变为重试。每次变化都会重新开始计时，让用户有完整的时间阅读新文字。重要的长时间任务不适合用忙碌的轻提示来跟踪：放在工作旁边的[进度条](/components/progress)会一直留在原处。

## 富内容 \{#rich-content\}

轻提示可以借助已有的组件容纳文字以外的内容：开头放一个[头像](/components/avatar)表示是谁做了某件事，主体中放一个[文件](/components/file)表示收到了什么，仍在进行的上传则显示文件的进度。轻提示保持自身的几何结构：图片占据状态图标原本的位置，文件与文字同宽。

仍在进行的上传是一个不带 `toast-timed` 的轻提示，因此会一直显示到工作结束；告知已完成的轻提示就是原地更新后的同一个轻提示，如[上文](#pending)所述。重要内容应当在其他地方也能找到：文件在它所在的文件夹中，提及在它所在的讨论串中。

## 轻提示区域 \{#the-region\}

`toast-region` 固定在底边与行内末端边缘相交的角落，轻提示在其中堆叠，最新一条位于底部。区域本身不接收指针事件，因此其空白处下方的页面仍可操作。在窄屏上，区域横跨整个屏幕宽度。

| 类名 | 位置 |
| --- | --- |
| `toast-region` | 底部，靠行内末端边缘 |
| `toast-region-top` | 顶部，轻提示向下入场，最新一条位于最上方 |
| `toast-region-center` | 沿行内方向居中 |

该区域是带有 `z-index` 的普通固定定位元素。要让轻提示显示在已打开的模态[对话框](/components/dialog)上方，为该区域设置 `popover="manual"`，再对其调用一次 `showPopover()`，即可将区域放入顶层。

## 无障碍 \{#accessibility\}

- 用 `aria-live="polite"` 将该区域设为实时区域，让轻提示出现时得到播报，并用 `aria-label` 为该区域提供无障碍名称。
- 为每条轻提示提供无障碍名称，可以用 `aria-labelledby` 指向其标题，也可以用 `aria-label`。
- 为原地更改文字的轻提示设置 `aria-atomic="true"`，使每次变化作为整条轻提示播报一次，而不是逐段播报。轻提示处于忙碌状态时，屏幕阅读器可能会等到工作结束后再播报。
- 轻提示用于确认操作结果。用户即使错过轻提示，也应能获取所需信息并执行所需操作，因此应将操作入口保留在轻提示之外。
- 轻提示出现时不获取焦点。其操作按钮和关闭按钮位于 Tab 键顺序中，任一按钮持有焦点时，定时关闭的轻提示都会等待。
- 启用减少动态效果时，轻提示会在原地淡入淡出，新图标会以原尺寸淡入。

## React、Svelte 和 Vue \{#frameworks\}

`toast` 组件维护一个队列。`toast()` 函数可在任意位置调用，轻提示区域只渲染一次，用于显示队列中的消息。使用 `npx master-ui add toast` 将组件复制到项目中。有关这些组件的实现和用法，请参阅 [React、Svelte 和 Vue](/guide/frameworks)。

- `toast(message)` 显示一条轻提示并返回一个句柄。`update(message)` 在同一条轻提示中显示其他内容，不会再次入场，并重新开始计时；`dismiss()` 让它像点击自身按钮一样离开。消息包含 `title`、`description`、`status`、以毫秒为单位的 `duration`（`false` 表示一直保留）和 `action`；传入字符串时，作为 `description`。
- `status: 'pending'` 显示加载指示器并设置 `aria-busy`，轻提示会一直保留，直到被更新。
- `action: { label, onClick }` 定义轻提示在关闭按钮之外可提供的一个操作按钮。它先运行 `onClick`，然后关闭轻提示，除非处理函数调用了 `event.preventDefault()`。
- `toast.promise(promise, { loading, success, error })` 先将 `loading` 显示为进行中的轻提示，然后更新同一条轻提示，成功时显示 `success`，失败时显示 error 并设为 `danger` 状态。成功和失败的内容都可以由函数返回，函数分别接收结果值和失败原因。它返回该 promise，可用于 await 或链式调用。

```tsx
toast({ title: 'Project archived', action: { label: 'Undo', onClick: () => restore(project) } })

await toast.promise(deploy(project), {
  loading: { title: 'Deploying Atlas' },
  success: (release) => ({ title: 'Deployed to production', description: `${release.url} is live.` }),
  error: (error) => ({ title: 'The deploy failed', description: String(error), duration: false }),
})
```
