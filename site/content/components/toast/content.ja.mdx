トーストは、保存、デプロイ、コピーなど直前に起きたこと、または進行中で終了時に結果を知らせる作業について、ページ上で伝える短いメッセージです。各トーストは、固定配置の `toast-region` 内に置く非モーダルの `<dialog>` です。ダイアログなのでスクリプトなしで閉じられ、表示と終了のアニメーションはスタイルシートの CSS で制御されます。

## 表示と終了 \{#showing-and-dismissing\}

- `open` 属性が付いたトーストはページの読み込み時に表示されます。フォーム送信後にサーバーが描画するメッセージに適しています。
- スクリプトから表示するには、表示領域に新しい `<dialog open class="toast">` を追加するか、表示領域内のトーストに `open` を設定します。どちらの場合も、`@starting-style` が表示アニメーションの開始状態を指定します。`show()` は呼び出さないでください。フォーカスがトースト内に移り、読者が行っていた作業から離れてしまいます。
- ボタンを `<form method="dialog">` で囲むか、ボタンに `commandfor` と `command="close"` を指定すると、トーストを閉じられます。`display` は `allow-discrete` で遷移するため、終了アニメーションが完了してからトーストの占有スペースがなくなります。

## 自動で閉じる \{#timed\}

`toast-timed` を指定すると、トーストは 6 秒後に自動で閉じます。時間の計測には `display: none` で終わる CSS アニメーションを使います。ポインターがトーストに重なっている間や、キーボードフォーカスがトースト内にある間は一時停止するため、操作を急ぐ必要はありません。下端の細い線は残り時間に合わせて短くなり、計測が止まると線も止まります。表示時間は `--toast-duration` で変更できます。処理中のトーストは時間を計測しません。計測は作業が終わってから始まります。

## アクション付き \{#with-an-action\}

トーストには、閉じるボタンの横に「元に戻す」や「表示」などのアクションを 1 つ置けます。`toast-action` はテキストの後に置き、`btn btn-sm` を `<form method="dialog">` で囲みます。これにより、アクションの実行後にトーストが閉じます。ボタンには `value` を指定してください。ダイアログの `returnValue` でどのボタンで閉じたかがわかるため、1 つの `close` リスナーでアクションを実行できます。アクションは <kbd>Tab</kbd> で移動できる実際のボタンです。自動で閉じるトーストは、アクションにフォーカスがある間やポインターがトーストに重なっている間は待機します。

トーストは自動で閉じ、読者が目にしない可能性もあるため、トースト内のアクションは近道であり、唯一の手段にしてはいけません。削除したものの復元や、失敗した保存の再試行など、重要な操作は、項目自体のメニュー、ゴミ箱、失敗したフォームの横の[アラート](/components/alert)など、表示が持続する場所にも用意してください。ステータス修飾子で色が変わるのはアイコンだけで、テキストは既定の前景色のままです。

## 処理中の表示と、その場での更新 \{#pending\}

トーストは、進行中の作業を知らせ、その結果を同じ場所で伝えることができます。作業の実行中、トーストは `aria-busy="true"` を持ち、アイコンの位置に `toast-icon` を付けた[スピナー](/components/spinner)を表示します。作業にどれだけ時間がかかっても、時間は計測されません。作業が終わったら、同じトーストのテキスト、ステータス、アイコンを変更し、`aria-busy` を削除します。トーストは再び表示アニメーションを行わず、スタック内の位置も保ちます。新しいアイコンだけが拡大しながら表示されます。

同じトーストは、ファイルのアップロード中に件数を更新したり、失敗から再試行に切り替えたりと、さらに変更できます。変更のたびに時間の計測がやり直されるため、読者は新しいテキストを読む時間を十分に得られます。重要な長い作業を追うのに、処理中のトーストは適していません。作業のそばに置いた[進捗](/components/progress)なら、その場に残ります。

## リッチコンテンツ \{#rich-content\}

トーストには、文言以外の内容も、それを描画する既存のコンポーネントで入れられます。誰が何かをしたことを示す[アバター](/components/avatar)を先頭に、届いたものを示す[ファイル](/components/file)を本文に、実行中のアップロードにはファイルの進捗を入れます。トーストは自身の形状を保ちます。画像はステータスアイコンの位置に置かれ、ファイルは文言と同じ幅になります。

## 表示領域 \{#the-region\}

`toast-region` は下端の末尾側の角に固定され、最新のトーストが一番下になるように縦に並べます。表示領域自体はポインターイベントを受け取らないため、空いている部分の下にあるページも操作できます。画面が狭いときは、画面幅いっぱいに広がります。

| クラス | 配置 |
| --- | --- |
| `toast-region` | 下端の末尾側 |
| `toast-region-top` | 上端。トーストは下向きに移動しながら現れ、最新のものが一番上 |
| `toast-region-center` | 中央揃え |

表示領域は `z-index` を持つ通常の固定配置要素です。開いているモーダル[ダイアログ](/components/dialog)より手前にトーストを表示するには、表示領域に `popover="manual"` を指定し、その要素で `showPopover()` を一度呼び出します。これで表示領域がトップレイヤーに入ります。

## アクセシビリティ \{#accessibility\}

- トーストの表示時に読み上げられるよう、表示領域に `aria-live="polite"` を指定してライブリージョンにし、`aria-label` で名前を付けます。
- 各トーストには、タイトルを参照する `aria-labelledby` または `aria-label` で名前を付けます。
- テキストがその場で変わるトーストには `aria-atomic="true"` を指定します。これにより、変更は部分ごとではなく、トースト全体として一度だけ読み上げられます。処理中の間は、スクリーンリーダーが作業の終了まで読み上げを保留することがあります。
- トーストは、操作の結果を知らせるために使います。見逃しても支障がないように、操作への唯一の導線をトーストに置かないでください。
- トーストは表示時にフォーカスを受け取りません。アクションボタンと閉じるボタンはタブ順序に含まれ、自動で閉じるトーストは、いずれかにフォーカスがある間は待機します。
- 動きを減らす設定では、トーストは位置を変えずにフェードし、新しいアイコンは元の大きさのままフェードインします。

## React、Svelte、Vue \{#frameworks\}

`toast` コンポーネントはトーストをキューで管理します。どこからでも呼び出せる `toast()` 関数と、一度だけレンダリングしてキュー内のトーストを表示する領域で構成されます。`npx master-ui add toast` でプロジェクトにコピーできます。コンポーネントの仕組みと使い方は [React、Svelte、Vue](/guide/frameworks) を参照してください。

- `toast(message)` はトーストを表示し、ハンドルを返します。`update(message)` は、もう一度表示アニメーションを行わずに同じトーストで別の内容を伝え、時間の計測をやり直します。`dismiss()` は、トースト自体のボタンと同じようにトーストを閉じます。メッセージは `title`、`description`、`status`、ミリ秒単位の `duration`（`false` でトーストを閉じずに残します）、`action` を持ちます。文字列を渡した場合は `description` になります。
- `status: 'pending'` はスピナーを表示して `aria-busy` を設定し、更新されるまでトーストを残します。
- `action: { label, onClick }` は、トーストが提供する唯一のボタンです。`onClick` を実行した後にトーストを閉じます。ただし、ハンドラーが `event.preventDefault()` を呼び出した場合は閉じません。
- `toast.promise(promise, { loading, success, error })` は、`loading` を処理中のトーストとして表示し、同じトーストを `success`、または `danger` ステータスの失敗に切り替えます。どちらも、値または理由を受け取る関数にできます。Promise を返すため、`await` やチェーンで使えます。

```tsx
toast({ title: 'Project archived', action: { label: 'Undo', onClick: () => restore(project) } })

await toast.promise(deploy(project), {
  loading: { title: 'Deploying Atlas' },
  success: (release) => ({ title: 'Deployed to production', description: `${release.url} is live.` }),
  error: (error) => ({ title: 'The deploy failed', description: String(error), duration: false }),
})
```
