A signature is a well to sign in with a finger, a pen or a mouse, and a field to type the name instead. The pad is the same well as a [text field](/components/input), with a hairline to sign on and a fine cross where the name begins. Each stroke is written into an inline `<svg>` as a filled outline, as wide as the pen pressed, and the drawing goes into the form as an SVG document. The group is a native `<fieldset>`: its legend names what is signed, and `disabled` on it stops the pad and disables everything inside.

## The behavior \{#behavior\}

The pad needs a script to draw. The `signature` [behavior](/guide/behaviors) takes the root, the element with the `signature` class, and returns the function that detaches it.

```js name=app.js
import { signature } from '@master/ui/behaviors/signature.js'

const pad = signature(document.querySelector('.signature'))

pad.value // [[[x, y, pressure], …], …], one list of points a stroke
pad.svg   // '<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 400 160" …>…</svg>', or '' when nothing is drawn
```

- **Strokes.** A stroke is the points the pointer passed through, in the units of the drawing's `viewBox`, each with a pressure from 0 to 1. A pen gives its own; a finger and a mouse give none, so a stroke is drawn heavier where it moved slowly, as ink pools where a pen lingers. Each stroke becomes a `signature-stroke` path: a filled outline `--signature-weight` wide at an even pressure, smoothed by curves through its points, with round ends. Where the browser merges pointer moves, the merged ones are read too, so a fast hand keeps its curves.
- **The value.** `value` is the strokes, and setting it draws them and dispatches nothing. `svg` is the drawing as an SVG document, and the `signature-value` field holds the same document, so a form submits it. The paths take `currentColor`, which is black in an image.
- **Events.** The field dispatches `input` as a stroke is drawn and `change` when it ends, and both when Undo or Clear takes strokes back.
- **Undo and Clear.** Undo takes back the last stroke and Clear every one. Until there is a stroke they wait out of sight; the script marks them `aria-disabled` while there is nothing to take, so the one that just emptied the pad keeps its focus and says so.
- **Status.** `signature-status` says "Signature drawn" when the first stroke ends, "Signature cleared" when the pad is emptied and "Last stroke removed" after Undo.

| Option | What it sets |
| --- | --- |
| `drawn` | What the status says when the first stroke ends. "Signature drawn" by default |
| `cleared` | What it says when the pad is emptied. "Signature cleared" by default |
| `undone` | What it says when Undo takes a stroke back. "Last stroke removed" by default |

The behavior also exports `signaturePath(stroke, weight)` and `signatureSvg(strokes, { viewBox, weight })`, which turn strokes into a path and a document without a page: a server can draw a saved signature into its first HTML with them.

## A typed name \{#a-typed-name\}

A drawing has no keyboard. Someone who signs with a keyboard, a switch or a screen reader, or whose hand will not hold a stroke, signs by typing their name, so the typed name is part of the pattern and not an extra. It is a native [input](/components/input) with the `signature-name` class, set in a script face from `--signature-font`, a stack of the faces systems ship ("Snell Roundhand" on Apple systems, "Segoe Script" on Windows) that ends at `cursive`. Its placeholder stays in the face of the interface.

Without the script, the pad cannot draw, and the typed name is the whole signature: the form submits it under its own `name`, as any field.

## In a form \{#in-a-form\}

Mark the typed name `required` when a signature is. The drawing answers the same requirement: while there is a stroke the behavior lifts `required` from the typed name, and gives it back when the pad is emptied. A reader who submits with neither gets the browser's own message on the typed name, and once they have tried, `:user-invalid` draws the danger contour on the field and on the pad, and a `field-error` in the field shows.

## Read-only and disabled \{#read-only-and-disabled\}

`signature-readonly` on the root shows a signature as it was given: nothing draws on it, and Undo and Clear step aside. Give the typed name `readonly` as well, or leave it out. `disabled` on the `<fieldset>` stops the pad, turns the ink and the words to disabled ink and disables every control inside, as a fieldset does.

## Proportions and ink \{#proportions-and-ink\}

The drawing's `viewBox` sets the pad's proportions and the units of a stroke: the pad is as wide as its column and as tall as the `viewBox` makes it, so a signature drawn on a phone and shown on a desktop keeps its shape. `0 0 400 160` suits a line of a form; a wider box such as `0 0 480 140` suits a page with room. The ink is `--signature-ink`, the strong text color by default, and `--signature-weight` is a stroke's width at an even pressure, in the units of the `viewBox`, read when a stroke is written. The pad's corner is `--signature-radius`.

## A picture of it \{#a-picture-of-it\}

The drawing leaves as SVG, which scales and stays small. Where a PNG is wanted, for a PDF library or an email, the application draws the SVG on a canvas:

```js name=png.js
async function png(svg, scale = 2) {
  const url = URL.createObjectURL(new Blob([svg], { type: 'image/svg+xml' }))
  const image = new Image()
  image.src = url
  await image.decode()
  const canvas = document.createElement('canvas')
  canvas.width = image.naturalWidth * scale
  canvas.height = image.naturalHeight * scale
  canvas.getContext('2d').drawImage(image, 0, 0, canvas.width, canvas.height)
  URL.revokeObjectURL(url)
  return new Promise((resolve) => canvas.toBlob(resolve, 'image/png'))
}

const blob = await png(pad.svg)
```

The document carries its size in `width` and `height`, taken from the `viewBox`, so `scale` sets the resolution. The canvas is transparent where nothing is drawn.

## Accessibility \{#accessibility\}

- Group the pad and the typed name in a `<fieldset>` whose legend says what is being signed.
- Name the drawing as an image, `role="img"` with an `aria-label`, and hide the line and the placeholder with `aria-hidden="true"`: the drawing's name already says where to sign.
- The pad takes no focus, because no key draws. Give the typed name a visible label that offers it as the other way to sign.
- The status is polite: it speaks when the pad is signed or emptied, not with every stroke.
- On the pad a finger draws instead of scrolling the page (`touch-action: none`). Keep the pad no taller than a signature needs, so a reader on a phone can still scroll past it.
- In forced colors the strokes are drawn in `CanvasText`, the line and the cross in `GrayText`, and the pad keeps an outline.
- What makes a mark a signature in law, such as consent, the signer's identity and a record of when, belongs to the application and its jurisdiction, not to the component.

## React, Svelte and Vue \{#frameworks\}

The `signature` component renders the group, attaches the behavior and passes the strokes in and out; the typed name is a second value, `typed`. A first value is drawn into the first render, so a server sends the signature already on the pad.
