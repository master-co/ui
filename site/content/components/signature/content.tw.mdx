簽名板是一塊可以用手指、觸控筆或滑鼠簽名的凹槽區域，另外附有一個可改為輸入姓名的欄位。簽名區與[文字欄位](/components/input)使用相同的內凹樣式，上面有一道供簽名的細線，並在姓名起點處標有一個細小的十字。每一筆都會以填色輪廓寫入內嵌的 `<svg>`，寬度依筆壓而定，整張簽名則以 SVG 文件的形式納入表單。整組元件是原生的 `<fieldset>`：它的 legend 說明要簽署的內容，在它上面加上 `disabled` 會停用簽名區及其中的所有控制項。

## 行為 \{#behavior\}

簽名區需要腳本才能繪製。`signature` [行為](/guide/behaviors)接收根元素，也就是帶有 `signature` 類別的元素，並傳回用來解除行為的函式。

```js name=app.js
import { signature } from '@master/ui/behaviors/signature.js'

const pad = signature(document.querySelector('.signature'))

pad.value // [[[x, y, pressure], …], …], one list of points a stroke
pad.svg   // '<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 400 160" …>…</svg>', or '' when nothing is drawn
```

- **筆畫。** 一筆就是指標經過的各個點，以圖形 `viewBox` 的單位表示，每個點都帶有 0 到 1 的筆壓。觸控筆會提供自己的筆壓；手指和滑鼠不提供，因此移動較慢的地方會畫得較粗，就像筆停留處墨水會暈開一樣。每一筆都會成為一條 `signature-stroke` 路徑：在均勻筆壓下寬度為 `--signature-weight` 的填色輪廓，以通過各點的曲線平滑處理，兩端為圓頭。若瀏覽器會合併指標移動事件，被合併的移動也會一併讀取，因此快速書寫時也能保留曲線。
- **值。** `value` 是所有筆畫，設定它會繪製這些筆畫，且不會觸發任何事件。`svg` 是以 SVG 文件表示的整張簽名，`signature-value` 欄位也保存同一份文件，因此表單會將它送出。路徑使用 `currentColor`，在圖片中會是黑色。
- **事件。** 繪製筆畫期間，欄位會觸發 `input`，筆畫結束時觸發 `change`；Undo 或 Clear 收回筆畫時，兩者都會觸發。
- **Undo 和 Clear。** Undo 會收回最後一筆，Clear 會清除所有筆畫。在有筆畫之前，兩者都會隱藏起來；沒有可收回的內容時，腳本會將它們標為 `aria-disabled`，因此剛清空簽名區的那個按鈕會保留焦點，並表明自己目前無法使用。
- **狀態。** 第一筆結束時，`signature-status` 會說「Signature drawn」，簽名區清空時說「Signature cleared」，按 Undo 後則說「Last stroke removed」。

| 選項 | 設定內容 |
| --- | --- |
| `drawn` | 第一筆結束時狀態朗讀的文字。預設為「Signature drawn」 |
| `cleared` | 簽名區清空時朗讀的文字。預設為「Signature cleared」 |
| `undone` | Undo 收回一筆時朗讀的文字。預設為「Last stroke removed」 |

行為也匯出 `signaturePath(stroke, weight)` 和 `signatureSvg(strokes, { viewBox, weight })`，不需要頁面就能將筆畫轉為路徑和文件：伺服器可以用它們將儲存的簽名繪製到初始 HTML 中。

## 輸入姓名 \{#a-typed-name\}

繪圖無法用鍵盤操作。使用鍵盤、切換裝置或螢幕閱讀器簽名的人，或手無法穩定畫出筆畫的人，會以輸入姓名的方式簽名，因此輸入姓名是這個模式的一部分，而不是附加功能。它是帶有 `signature-name` 類別的原生[輸入欄位](/components/input)，以 `--signature-font` 指定的手寫字體顯示；這是一組系統內建字體的清單（Apple 系統上為「Snell Roundhand」，Windows 上為「Segoe Script」），最後以 `cursive` 結尾。它的預留位置文字則維持介面字體。

沒有腳本時，簽名區無法繪製，輸入的姓名就是完整的簽名：表單會和任何欄位一樣，以它自己的 `name` 送出。

## 在表單中 \{#in-a-form\}

簽名為必填時，請將輸入姓名的欄位標為 `required`。繪製的簽名也能滿足同一項要求：只要有筆畫，行為就會移除輸入姓名欄位上的 `required`，簽名區清空時再加回去。讀者既沒有繪製也沒有輸入就送出時，會在輸入姓名欄位上看到瀏覽器內建的訊息；嘗試送出後，`:user-invalid` 會在欄位和簽名區上繪製危險輪廓，欄位中的 `field-error` 也會顯示。

## 唯讀與停用 \{#read-only-and-disabled\}

## 比例與筆跡 \{#proportions-and-ink\}

圖形的 `viewBox` 決定簽名區的比例和筆畫的單位：簽名區的寬度與所在欄位相同，高度則由 `viewBox` 決定，因此在手機上簽的名在桌面上顯示時仍能保持原本的形狀。`0 0 400 160` 適合表單中的一行；較寬的方框例如 `0 0 480 140` 則適合空間充裕的頁面。筆跡顏色為 `--signature-ink`，預設為強調文字色；`--signature-weight` 是均勻筆壓下的筆畫寬度，以 `viewBox` 的單位計算，在寫入筆畫時讀取。簽名區的圓角為 `--signature-radius`。

## 輸出成圖片 \{#a-picture-of-it\}

簽名以 SVG 輸出，可以縮放且檔案很小。若需要 PNG，例如供 PDF 函式庫或電子郵件使用，應用程式可以將 SVG 繪製到 canvas 上：

```js name=png.js
async function png(svg, scale = 2) {
  const url = URL.createObjectURL(new Blob([svg], { type: 'image/svg+xml' }))
  const image = new Image()
  image.src = url
  await image.decode()
  const canvas = document.createElement('canvas')
  canvas.width = image.naturalWidth * scale
  canvas.height = image.naturalHeight * scale
  canvas.getContext('2d').drawImage(image, 0, 0, canvas.width, canvas.height)
  URL.revokeObjectURL(url)
  return new Promise((resolve) => canvas.toBlob(resolve, 'image/png'))
}

const blob = await png(pad.svg)
```

文件會在 `width` 和 `height` 中帶有取自 `viewBox` 的尺寸，因此 `scale` 決定解析度。canvas 上沒有繪製的地方是透明的。

## 無障礙 \{#accessibility\}

- 請將簽名區和輸入姓名欄位放在同一個 `<fieldset>` 中，並以 legend 說明要簽署的內容。
- 請將繪圖命名為圖片，即 `role="img"` 搭配 `aria-label`，並以 `aria-hidden="true"` 隱藏細線和預留位置文字：繪圖的名稱已經說明要在哪裡簽名。
- 簽名區不會取得焦點，因為沒有任何按鍵能繪製。請為輸入姓名欄位提供可見的標籤，說明這是另一種簽名方式。
- 狀態採 polite 方式：只在簽名區已簽名或已清空時朗讀，而不是每一筆都朗讀。
- 在簽名區上，手指會繪製而不是捲動頁面（`touch-action: none`）。簽名區的高度請不要超過簽名所需，讓使用手機的讀者仍能捲動越過它。
- 強制色彩模式下，筆畫以 `CanvasText` 繪製，細線和十字以 `GrayText` 繪製，簽名區則保留外框線。
- 讓一個標記在法律上成為簽名的條件，例如同意、簽署人身分以及簽署時間的紀錄，屬於應用程式及其所在法域的責任，而不是元件的責任。

## React、Svelte 和 Vue \{#frameworks\}

`signature` 元件會算繪整組元件、掛上行為，並支援傳入及傳出筆畫；輸入的姓名是第二個值 `typed`。初始值會繪製在第一次渲染中，因此伺服器送出的頁面上，簽名區已經帶有簽名。用 `npx master-ui add signature` 將元件複製到專案中。元件的建置與使用方式請參閱 [React、Svelte 和 Vue](/guide/frameworks)。
