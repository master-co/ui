並べ替えリストは、ハンドルのドラッグまたはキー操作で項目の順序を変えられるリストです。並べ替えリスト自体は項目の行を生成しません。[リスト](/components/list)、カードのスタック、[テーブル](/components/table)の `<tbody>` など、項目を収める任意の要素に適用し、各項目にハンドルを付けます。ハンドルは、移動する対象を名前に含めたボタンです。`sortable` の[ビヘイビア](/guide/behaviors)は、ほかの項目が場所を空けるなかで項目を運び、ドロップしたときに一度だけそのノードを移動します。

## スタイルシートの描画内容 \{#what-the-stylesheet-draws\}

- **ハンドル**　グリップアイコンを入れたボタンです。ポインターやキー操作が届くまでは控えめに表示され、カーソルは握った手の形になります。ハンドルの大きさは 24×28px です。タッチ画面では、グリップの位置を変えずに操作領域が 44px まで広がります。`touch-action: none` が指定されているため、ハンドルから始めたドラッグでページがスクロールすることはありません。項目のほかの部分では、通常どおりスクロールできます。
- **運ばれている項目**　静止時の描画をそのまま保ちます。大きさは変わらず、文字も元の位置のままで、浮き上がるだけです。フローティングの影を持つ浮き上がったシートの上に乗り、ビヘイビアが書き込む `--sortable-offset` によってポインターに追従します。ポインターと項目の間にイージングはかかりません。シートは項目の左右に `--sortable-inset`（8px）、上下にその半分だけはみ出すため、リストの行のように文字が端に接している行でも、シートに余白が生まれます。リストの細い罫線のように行の下に描かれる線は、項目と一緒には動きません。
- **場所を空ける動き**　運ばれている項目の元の位置と移動先の間にある項目が、`--sortable-size` の分だけ滑るように位置をずらします。先頭方向へは `sortable-item-back`、末尾方向へは `sortable-item-forward` です。`--sortable-size` は、持ち上げた時点で計測した、運ばれている項目の大きさとその後ろの間隔を合わせた値です。空いた隙間が移動先になります。元の位置は空いたままなので、どこから運んできたかがわかります。
- **ドロップ**　場所を空けた項目はすでに移動先に並んでいるため、空けた場所の解消と隙間へのノードの配置が 1 回の変更で行われます。各項目を `view-transition-name: match-element` によって個別の画像として扱うビュートランジションの中で、運ばれていた項目だけが、離した位置から移動先へ移動します。その間、ルート要素は `aria-busy="true"` を示し、ほかの項目は動きません。

ビュートランジションに対応していないブラウザーでは、運ばれていた項目はすぐに移動先に収まります。ほかの項目はすでに移動先にあります。動きを抑える設定では、滑るような移動もトランジションも行いません。

- **行はそのまま描画されます**　テーブルは、行が生成するボックスであれば通常のフローから外れたものにも列を割り当て、それ以降のセルをすべてずらします。そのため、運ばれている行は自身ではボックスを生成しません。代わりにハンドルを収めるセルがシートを描画し、行を基準に配置して行と同じ大きさにします。行のセルにはそれぞれ余白があるためです。テーブルのレイアウトにかかわらずセルは動かず、`--sortable-inset` も適用されません。各セルの下の罫線は、シートの上には描かれません。
- **ステータス領域**は、行しか収められない `<tbody>` の中にも、テーブルを構成する要素の間にも置けません。ビヘイビアが探す位置である `<table>` の直後に置いてください。
- **スクロールするボックスの中で**　配置先の列より幅の広いテーブルは、横方向にスクロールするボックスに収めます。運ばれている行のシートは行そのものなので、ボックスの中に収まり、ボックスが切り取るのは端の影だけです。`<tbody>` 自体はスクロールしません。テーブルを収めるボックスまたはページのどちらかの端にポインターが近づくと、ビヘイビアがそれをスクロールします。

## ビヘイビア \{#behavior\}

`sortable` は、`sortable` クラスを持つルート要素を受け取り、ビヘイビアを解除する関数を返します。

```js name=app.js
import { sortable } from '@master/ui/behaviors/sortable.js'

const priorities = sortable(document.querySelector('.sortable'))

priorities.value // ['onboarding', 'billing', 'search', 'exports']
```

- **ポインター**　ハンドルを押したまま 4px を超えて動かすと、項目が持ち上がります。それ未満なら通常の押下として扱います。運んでいる間、ハンドルは `aria-pressed="true"` を示し、項目はポインターに追従し、通過した項目が場所を空けます。移動先は、場所を空ける途中の位置ではなく、レイアウト上の項目の位置から判定するため、移動先が自身を追いかけるように揺れ動くことはありません。ポインターを離すと項目が移動し、<kbd class="kbd">Escape</kbd> を押すと、ほかの項目が元の位置へ滑って戻るなかで項目も元の位置に戻ります。リストをスクロールさせる要素（リスト自体、リストを収めるボックス、またはページ）のどちらかの端にポインターが近づくと、その要素がスクロールし、端に寄るほど速くなります。ホイールによるスクロールを含め、ポインターの下でページが動いても、項目はポインターの下にとどまります。項目を動かせるのは、ドラッグを始めたポインターだけです。
- **ドラッグしない操作**　ハンドルを動かさずに押す、つまりクリックやタップをすると、<kbd class="kbd">Enter</kbd> と同じように項目が持ち上がり、そのハンドルにフォーカスが移ります。続けてほかの項目のハンドルを押すと、その位置へ移動してドロップします。自分のハンドルをもう一度押すと、その場でドロップします。ドラッグできないポインターや、スクリーンリーダーのダブルタップでも、この方法でリストを並べ替えられます。
- **キー操作**　ハンドルで <kbd class="kbd">Enter</kbd> または <kbd class="kbd">Space</kbd> を押すと、項目が持ち上がります。リストの並びに沿った矢印キーで、項目を 1 つずつ移動します。矢印キーは項目を持ち上げるまで何もしないため、スクリーンリーダー独自の矢印キー操作はそのまま使えます。<kbd class="kbd">Enter</kbd> または <kbd class="kbd">Space</kbd> でドロップし、<kbd class="kbd">Escape</kbd> で持ち上げた位置に戻します。ハンドルからフォーカスが外れた場合もドロップします。
- **読み上げ**　持ち上げ、移動、ドロップ、取り消しのたびに、`sortable-status` 領域で項目の名前と位置を伝えます（例：「Billing, position 3 of 4.」）。この領域は、ルート要素の中、またはその直後に置く `role="status"` の要素です。ルート要素がテーブルの `<tbody>` の場合は、テーブルの直後に置きます。ページの言語で伝えるには `messages` を渡します。
- **移動**　移動するのは項目のノードそのものです。ブラウザーが `moveBefore()` に対応していればそれを使うため、項目内の状態（フィールドのテキスト、再生中の動画、フォーカス）が保たれます。対応していない場合は項目を挿入し直し、ハンドルにフォーカスを戻します。
- **イベント**　ドロップによって順序が変わると、ルート要素が `input` と `change` を発行します。返される関数の `value` は項目の順序で、各項目の `data-value`、なければテキストを並べたものです。`value` に代入するとその順序に並べ替えますが、イベントは発行されません。

ビヘイビアを適用しない場合も、リストは元の順序のまま読めます。

並べ替えリストは 1 つのリストです。ボードの段階のように、項目がリストの間も移動する場合は、[カンバン](/components/kanban)を使います。

## アクセシビリティ \{#accessibility\}

- 各ハンドルには、移動する対象を含む名前を付けます（例：「Move Billing」）。ハンドルは項目の順序を変える唯一のコントロールですが、ドラッグだけが手段になることはありません。押すと項目が持ち上がり、ほかのハンドルを押すとそこへ移動します。ポインターでできる移動は、すべてキー操作でもできます。
- ステータス領域は、最初から空の状態でページに置いておきます。読み上げる瞬間に追加した領域は、読み上げられないことがよくあります。
- 優先度やワークフローの手順など、順序がページの動作に関わる場合は、リストの近くでそのことを説明し、新しい順序はページのほかのデータと同じ方法で保存します。

## React、Svelte、Vue \{#frameworks\}

`sortable` コンポーネントは、保持している順序で項目を描画してビヘイビアを適用し、ビヘイビアから求められると自身のリスト内で項目を移動します。そのため、フレームワークが管理する行とページの表示が一致します。`npx master-ui add sortable` でプロジェクトにコピーできます。コンポーネントの構成と使い方は [React、Svelte、Vue](/guide/frameworks) を参照してください。このコンポーネントが描画するのはリストです。テーブルの行を並べ替えるには、フレームワークでテーブルを描画し、`move` を指定してビヘイビアを `<tbody>` に適用します。`move` は、コンポーネントと同じように、各移動をフレームワーク自身の行に委ねます。
