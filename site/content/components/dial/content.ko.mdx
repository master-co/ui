다이얼은 원을 따라 손잡이를 돌려 값을 정합니다. 노브처럼 돌려 정하는 레벨, 각도, 방향에 사용합니다. 다이얼은 [게이지](/components/gauge)의 입력용 짝입니다. 채움 색과 같은 잉크를 옅게 깐 둥근 트랙이 시작 지점부터 값까지 잉크로 채워지고, 그 위 값의 각도에 [슬라이더](/components/slider)와 같은 진주빛 손잡이가 놓입니다. 가운데에는 숫자가 고정폭 숫자로 표시됩니다. 이에 해당하는 네이티브 요소가 없으므로 다이얼은 `role="slider"`가 있는 요소이며, `dial` [동작](/guide/behaviors)이 다이얼을 돌립니다.

기본적으로 다이얼은 노브입니다. 아래쪽이 트인 270도 범위로, 왼쪽 아래의 최솟값부터 오른쪽 아래의 최댓값까지 이어집니다. 트랙을 누르면 값이 그 위치로 이동하고, 손잡이를 누르면 현재 위치에서 손잡이를 잡으므로 값이 튀지 않고 돌아갑니다. 드래그가 한쪽 끝을 넘어가면 포인터가 돌아올 때까지 값은 아래쪽 틈을 지나는 동안에도 그 끝에 머무릅니다.

## 각도 \{#angle\}

`dial-full`은 위쪽에서 시작하는 원 전체로, `aria-valuemin` 0부터 `aria-valuemax` 360까지의 각도나 방향에 사용합니다. 최댓값을 넘어가면 키로 조작하든 위쪽을 지나 드래그하든 다시 최솟값으로 돌아오며, 360은 같은 위치인 0으로 작성됩니다. <kbd class="kbd">End</kbd> 키는 그보다 한 단계 앞에서 멈춥니다.

레이블과 `aria-valuetext`는 숫자 주위에 작성된 문구를 그대로 유지하므로, 페이지에 스크립트가 없어도 "135°"가 "136°"가 됩니다. 다른 형태의 문구가 필요하면 [동작](#behavior)에서 보듯이 동작에 `text` 함수를 전달하세요.

## 눈금과 표시 \{#ticks-and-marks\}

`dial-ticks` 요소는 회전 범위를 `--dial-ticks`개의 같은 간격으로 나누어, 손잡이가 지나는 경로 바로 바깥에 가는 선으로 그립니다. 노브에서는 양 끝에 하나씩 있으므로 눈금이 간격 수보다 하나 많고, 원 전체에서는 간격 수와 같습니다. `dial-mark`는 테두리에 놓이는 짧은 단어나 숫자로, 스타일시트가 `--dial-at`이 나타내는 값의 위치에 배치합니다. 둘 다 다이얼 상자 안쪽의 테두리 공간을 차지하므로 트랙은 그만큼 작아집니다. 표시가 있는 다이얼에는 큰 크기를 사용하세요.

## 크기 \{#sizes\}

다이얼의 지름은 120px입니다. `dial-sm`은 88px로 컨트롤이 나란히 놓인 행에 사용하고, `dial-lg`는 160px로 패널의 중심이 되는 하나의 값이나 표시가 있는 다이얼에 사용합니다. 트랙은 너비의 1/20이며 숫자는 트랙에 맞춰 크기가 바뀝니다. 손잡이는 포인터 종류와 관계없이 슬라이더와 같은 18px을 유지합니다.

## 폼에서 사용하기 \{#form\}

`role="slider"`는 폼 컨트롤이 아니므로 다이얼은 숨겨진 입력 요소를 담습니다. 동작은 값이 바뀔 때마다 다이얼 안의 첫 번째 `<input type="hidden">`에 값을 작성하며, 폼은 그 입력 요소의 `name`으로 값을 제출합니다. 다이얼의 `input`과 `change` 이벤트는 네이티브 컨트롤처럼 폼까지 버블링됩니다. 폼을 초기화해도 숨겨진 입력 요소에는 영향이 없으므로 다이얼은 그대로 있습니다. 초기화할 때 다이얼도 움직여야 한다면 페이지에서 값을 다시 설정하세요.

## 비활성화 \{#disabled\}

`aria-disabled="true"`를 설정하면 다이얼이 흐려지고 키, 포인터, 휠 입력을 모두 받지 않습니다. `tabindex="-1"`로 탭 순서에서 제외하고, 폼이 값을 제출하지 않도록 숨겨진 입력 요소에도 `disabled`를 설정하세요.

## 회전 방향 \{#direction\}

어떤 쓰기 방향에서든 시계 방향이 값을 늘리는 방향입니다. 다이얼은 시계나 기기의 노브처럼 돌아가며, 이런 것들은 오른쪽에서 왼쪽으로 쓰는 언어에서도 좌우가 반전되지 않습니다. 따라서 다이얼도 반전되지 않으며, 방향키의 의미도 바뀌지 않습니다. <kbd class="kbd">→</kbd>와 <kbd class="kbd">↑</kbd> 키는 항상 값을 올립니다. 시선이 처음 닿는 다이얼의 위쪽에서는 시계 방향이 오른쪽이며, 그 위치에서 값을 올리는 방향키도 오른쪽 방향키입니다.

## 동작 \{#behavior\}

`dial`은 `dial` 클래스가 있는 루트 요소를 받아, 연결한 동작을 해제하는 함수를 반환합니다. 이 함수에는 숫자인 `value`가 있습니다. 외부에서 다이얼을 돌리려면 이 값을 설정하세요. 이때는 이벤트가 발생하지 않습니다.

```js name=app.js
import { dial } from '@master/ui/behaviors/dial.js'

const root = document.querySelector('.dial')
const turn = dial(root, { step: 15, text: (value) => `${value}°` })

root.addEventListener('change', () => save(turn.value))
```

- **값이 바뀔 때마다** 루트의 `aria-valuenow`와 `--dial-value`, `dial-value`의 텍스트, `aria-valuetext`가 있거나 `text`가 지정된 경우 `aria-valuetext`, 그리고 숨겨진 입력 요소에 값을 작성합니다. 연결할 때도 같은 방식으로 첫 값을 작성하며, 속성을 읽지 못하는 브라우저를 위해 `aria-valuemin`과 `aria-valuemax`를 `--dial-min`과 `--dial-max`에 복사합니다.
- **값**은 `aria-valuemin`부터 단계 간격에 맞춰지며, `aria-valuemin`과 `aria-valuemax` 사이에 머무릅니다. 두 속성을 생략하면 0과 100입니다. 원 전체에서는 범위를 넘으면 반대쪽 끝으로 돌아옵니다.
- **드래그.** `pointerdown`에서 포인터를 캡처하고 다이얼 중심을 기준으로 포인터의 각도를 읽은 뒤, 스타일시트가 그릴 때 사용하는 것과 같은 `--dial-start`와 `--dial-sweep`으로 그 각도를 값으로 바꿉니다. 회전 범위가 360도인 다이얼은 `dial-full` 여부와 관계없이 끝에서 반대쪽 끝으로 돌아옵니다. 가운데의 숫자 근처를 눌러도 값은 바뀌지 않습니다.
- **키.** 방향키는 한 단계씩, <kbd class="kbd">Page Up</kbd>과 <kbd class="kbd">Page Down</kbd> 키는 더 큰 단계로 돌리며, <kbd class="kbd">Home</kbd>과 <kbd class="kbd">End</kbd> 키는 양 끝으로 이동합니다.
- **휠**은 요청한 경우에만, 그리고 <kbd class="kbd">Alt</kbd>(<kbd class="kbd">Option</kbd>) 키를 누르고 있는 동안에만 한 칸마다 다이얼을 한 단계씩 돌립니다. 페이지를 스크롤하다 다이얼 위를 지나가도 다이얼이 돌아가지는 않습니다.
- **이벤트.** 루트는 값이 바뀔 때마다 `input`을 발생시키고, 드래그가 끝나거나 키나 휠로 값을 돌렸을 때 `change`를 발생시킵니다. 두 이벤트 모두 버블링됩니다.
- **비활성화.** `aria-disabled="true"`가 설정된 다이얼은 키, 포인터, 휠 입력을 받지 않습니다.

| 옵션 | 설정하는 내용 |
| --- | --- |
| `step` | 방향키 한 번으로 값이 바뀌는 크기이자, 드래그한 값을 맞추는 간격입니다. 기본값은 1입니다 |
| `page` | Page Up과 Page Down 키로 값이 바뀌는 크기입니다. 기본값은 범위의 1/10이며, 단계 간격에 맞춥니다 |
| `text` | 값을 받아 문구를 반환하는 함수로, 반환값은 `dial-value`와 `aria-valuetext`에 작성됩니다 |
| `wheel` | `true`이면 Alt 키를 누르고 있는 동안 휠로 다이얼을 돌릴 수 있습니다. 기본값은 `false`입니다 |

`attach()`는 옵션을 전달하지 않습니다. 옵션이 필요한 다이얼은 `attach()`가 실행된 뒤 따로 연결하세요. 한 루트에서 다시 호출하면 첫 번째 호출을 대체하며, 이 미리보기의 스크립트도 그렇게 합니다. `MasterUI`는 미리보기가 불러오는 번들입니다. 프로젝트에서는 위와 같이 `dial`을 import하세요.

## 접근성 \{#accessibility\}

- 루트는 포커스를 받을 수 있는 `role="slider"` 요소로, `aria-label`이나 `aria-labelledby`로 접근 가능한 이름을 가지며, `aria-valuemin`과 `aria-valuemax` 사이의 값을 `aria-valuenow`에 담습니다. 원을 따라 도는 슬라이더에는 의미 있는 방향이 없으므로 `aria-orientation`은 생략하세요.
- 숫자만으로 이해하기 어렵고 단위나 문구가 필요하다면 `aria-valuetext`를 작성하세요(예: "135°", "21 degrees", "Loud"). 동작이 이 값을 값과 맞춰 갱신합니다.
- 숫자, 눈금, 표시 등 슬라이더 안의 모든 요소는 보조 기술에 대해 표현용으로만 취급됩니다. 드래그로 할 수 있는 모든 일은 키로도 할 수 있고, 트랙을 한 번 누르기만 해도 값이 설정되므로 드래그로 돌리는 것이 유일한 방법이 되는 일은 없습니다.
- 슬라이더와 마찬가지로 포커스 링은 손잡이에 표시됩니다. 터치 화면에서는 다이얼 전체가 손가락 입력을 받아 페이지를 스크롤하는 대신 다이얼이 돌아가므로, 손잡이는 크기를 유지합니다.
- 동작 줄이기 설정이 켜져 있으면 잡은 손잡이가 커지지 않습니다. 강제 색상 모드에서는 채움에 시스템 강조색을, 트랙과 눈금에 시스템 회색을, 손잡이에 버튼 텍스트 색을 사용합니다.

`dial` 컴포넌트는 동작을 연결하고 값을 받아 외부로 전달합니다. 눈금과 표시는 데이터로부터 렌더링하며, `name`을 지정하면 숨겨진 입력 요소도 렌더링합니다. `npx master-ui add dial` 명령을 실행해 프로젝트에 복사하세요. 컴포넌트의 구성과 사용 방법은 [React, Svelte, Vue](/guide/frameworks)에서 확인할 수 있습니다.
