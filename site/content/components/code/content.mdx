Code is literal text in the mono face: a command, a value, a file name. Inline, `.code` on a `<code>` is a small chip that sits in the line. As a block, `code-block` on a `<pre>` is a [well](/components/surface#well) that scrolls on its own when a line is long.

## Block \{#block\}

Put `code-block` on the `<pre>` and keep a `<code>` inside it for semantics. Lines keep their breaks, and the block scrolls sideways instead of wrapping. Give it `tabindex="0"` when its lines can be longer than the block, so the keys can scroll it.

<ComponentPreview name="block" height={208} title="Block" background="plain" bodyClass="p-lg" html={`<pre class="code-block" tabindex="0"><code>@import '@master/css';
@import '@master/ui';

@theme {
  --color-brand: var(--color-indigo-50);
}</code></pre>`} />

## Lines \{#lines\}

To say something about one line, make each line a `code-line`. The block then lays its lines out as a grid: every line is as wide as the longest one, so a band on a line runs the whole scrolling width, and the line breaks between the elements cost nothing, because white space between grid items is not drawn. Write one element per line of code.

`code-line-highlight` is the line being talked about: a tint, and a rule of ink at its start. `code-numbered` on the block numbers the lines with a CSS counter, in a gutter that is not selected or copied with the code.

<code class="code-line">  corner-shape: var(--corner-shape);</code>

## A diff \{#diff\}

`code-line-added` and `code-line-removed` mark the lines of a change. The hue agrees with the sign the line already starts with: keep the `+` and the `-` in the text, as a patch has them, so the change reads without color and copies as a patch.

<ComponentPreview name="diff" height={184} title="A diff" background="plain" bodyClass="p-lg" html={`<pre class="code-block" tabindex="0"><code class="code-line">  @theme {</code>
<code class="code-line code-line-removed">-   --radius-control: .5rem;</code>
<code class="code-line code-line-added">+   --radius-control: .625rem;</code>
<code class="code-line">    --radius-surface: 1rem;</code>
<code class="code-line">  }</code></pre>`} />

## Panel \{#panel\}

`code-panel` puts a header over the block, in one well: the file's name in `code-title` and a control at the end, which sits 4px in with the concentric corner. The block inside gives up its own well.

Set `--code-radius` on a standalone `code-block` or on the `code-panel` that owns it. The default is `var(--radius-control)`; a root held directly in a [tray](/components/surface#tray) uses `var(--radius-surface)` so its corner follows the holder's inset. A panel's inner block stays square and transparent, keeping one contour around the composition.

Copying needs a script, and three lines are enough: read the block's text and hand it to the clipboard.

  navigator.clipboard.writeText(button.closest('.code-panel').querySelector('.code-block').textContent).then(function () {

  })

## Code or kbd \{#code-or-kbd\}

Use `code` for what a reader types as text or reads from a program, and [`kbd`](/components/kbd) for a key to press. The stylesheet does not highlight syntax; a highlighter's spans keep their own colors inside a block.

## Accessibility \{#accessibility\}

- Give a block `tabindex="0"` when a line can be longer than the block, so the keys can scroll it.
- Line numbers are generated content: they are not read aloud, selected or copied.
- A highlight is visual. When the text around the block refers to a line, name what is on it rather than its color or its number.
