## 開啟與關閉 \{#opening-and-closing\}

以下三個屬性可取代以往操作模態對話框所需的腳本。

- 在按鈕上同時設定 `commandfor="id"` 和 `command="show-modal"`，即可用模態方式開啟對話框。`command="close"` 會關閉對話框，並將焦點移回原先開啟它的按鈕。
- 在對話框上設定 `closedby="any"` 後，點擊遮罩也能關閉對話框，<kbd>Esc</kbd> 則照常可用。如果要避免誤點就捨棄工作，請省略這個屬性。瀏覽器即使不支援這個屬性，仍可用 <kbd>Esc</kbd> 或關閉按鈕關閉對話框。
- 對話框內的 `<form method="dialog">` 會在送出時關閉對話框，並透過對話框的 `returnValue` 回報使用了哪個按鈕。

模態對話框開啟期間，後方的頁面無法互動或捲動。

## 尺寸 \{#sizes\}

對話框預設寬 28rem。`dialog-sm` 寬 22rem，適合只需一句話的確認訊息，`dialog-lg` 則寬 40rem。在窄螢幕上，各尺寸都會與檢視區左右邊緣各保留 1rem。頁尾透過容器查詢依對話框本身的寬度調整版面配置。寬度小於 22rem 時，按鈕會改為垂直排列，每個按鈕都占滿寬度，主要動作排在最上方。

滑動由以下部分組成：

- **由瀏覽器移動面板。** 軌道是帶有貼齊點的捲動容器：一個是開啟時的停駐位置，另一個是超出邊緣、與檢視區一樣大的區段，面板放開後會移到那裡。手指、觸控板和滾輪都能捲動它，因此跟隨手部動作、快速撥動的慣性，以及決定停在哪裡，都由瀏覽器自己處理。軌道是反向的 flex 排列，面板位在末端，因此不需要腳本就會從開啟時的停駐位置開始。
- **由行為處理捲動做不到的事。** 無論面板以何種方式離開軌道，行為都會在它離開後關閉對話框。它讓 `closedby="any"` 重新生效：軌道蓋住了瀏覽器監聽的遮罩，因此改由行為在使用者按下面板旁邊的區域時關閉對話框。滑鼠無法透過拖曳來捲動，因此行為讓滑鼠可以從把手或控制項與 dialog-body 以外的區域抓住面板，放開時移到它被甩向的停駐位置或較近的那一個；精確指標按住面板期間，軌道會停止貼齊。它會把剩下多少遮罩寫入 `--dialog-scrim`，讓遮罩隨面板離開而變淡。
- **對話框仍是對話框。** <kbd>Esc</kbd>、關閉按鈕、焦點限制、焦點回到觸發元件，以及滑入滑出的動畫，都與一般的抽屜或底部面板相同。
- **可捲動的內文保有自己的捲動。** 使用滑鼠或滾輪時，在 `dialog-body` 中拖曳會捲動它或選取文字。在觸控螢幕上，拖曳到內文頂端後會接著移動底部面板。

滑動只是捷徑：請保留關閉按鈕或可關閉對話框的操作，並保留 <kbd>Esc</kbd>。

### 停駐高度 \{#detents\}

在可滑動的底部面板加上 `dialog-detents`，它就會停在兩個高度：檢視區的一半（開啟時的高度）和全高。拖曳或快速撥動會在兩者之間移動；從全高往下快速撥動會停在一半，只有從一半高度撥動才會放開它。請把把手做成具有可存取名稱的 `<button>`：按下它、<kbd>Enter</kbd> 或 <kbd>Space</kbd> 會把底部面板移到另一個高度，<kbd>↑</kbd> 會展開到全高，<kbd>↓</kbd> 會縮回一半。它的 `aria-expanded` 表示底部面板是否位於全高。

### 缺少某項功能時 \{#swipe-fallbacks\}

- 沒有腳本時，超出邊緣的區段不是停駐位置（`@media (scripting: enabled)`）：放開的面板會彈回原位，<kbd>Esc</kbd> 和關閉按鈕仍可關閉對話框。請在所有會執行腳本的地方掛載行為，否則放開的面板會停在畫面外，而頁面仍維持無法操作。
- 沒有行為時，遮罩會維持完整，直到對話框關閉。它不是捲動驅動動畫：在反向的捲動容器中，Chromium 和 WebKit 執行捲動與檢視時間軸的方向相反。
- 支援 `scroll-initial-target` 的瀏覽器（Chromium）中，有停駐高度的底部面板在任何腳本執行前就會以一半高度開啟；其他瀏覽器則會以全高開啟，直到行為移動它。

滑動已在 Chromium 和 WebKit 中以滑鼠、滾輪驗證，並在 Chromium 中以觸控驗證。捲動貼齊、反向 flex 捲動和 `scrollend` 在所有目前的瀏覽器中都可使用。

## 動態效果 \{#motion\}

對話框從原尺寸的 97%、下移半個 rem 的位置開始淡入，進場耗時 280ms，退場耗時 160ms。進場與退場都由樣式表中的 CSS 控制。`@starting-style` 定義首次繪製時的樣式，`display` 和 `overlay` 則透過 `allow-discrete` 套用轉場，讓退場動畫播完後，對話框才離開頂層。啟用減少動態效果時，只保留淡入淡出。

## 無障礙 \{#accessibility\}

- 將 `aria-labelledby` 指向對話框的 `dialog-title`，為對話框提供可存取名稱。
- 用 `show-modal` 開啟時，焦點會移入對話框，關閉時則移回開啟它的按鈕。請在使用者應先操作的欄位上設定 `autofocus`。如果是確認破壞性操作，請將該屬性設在安全的選項上。
- 目前版本的 Chrome、Edge、Firefox 和 Safari 支援 `command` 和 `commandfor`。在較舊的瀏覽器中，可從點擊事件處理函式呼叫 `dialog.showModal()`，並沿用同一份樣式表。
- 滑動絕不是唯一的關閉方式：請保留關閉按鈕或可關閉的操作，<kbd>Esc</kbd> 也仍然有效。在有停駐高度的底部面板中，把手是具有可存取名稱（例如「底部面板高度」）的按鈕，可按下或使用鍵盤調整高度，效果與拖曳相同；沒有停駐高度時，它是對輔助技術隱藏的凹槽。它的操作目標為 64 × 24px，在觸控螢幕上高 44px。

## React、Svelte 和 Vue \{#frameworks\}

`dialog` 元件會依應用程式的狀態開啟或關閉對話框，也會在瀏覽器開啟或關閉對話框時通知應用程式。觸發元件和對話框內的各個部分仍由頁面自己的標記定義。它會在每個對話框上掛載 `drawer` 行為，因此加上 `dialog-swipe` 和 `dialog-panel` 的抽屜或底部面板放開後即可關閉，並像其他關閉方式一樣回報；對沒有 `dialog-swipe` 的對話框，這個行為不會做任何事。執行 `npx master-ui add dialog` 將元件複製到專案中。[React、Svelte 和 Vue](/guide/frameworks) 說明元件的建置與使用方式。
