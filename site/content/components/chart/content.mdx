A chart draws numbers in the form the reader's question calls for: a line, bars, a donut, a histogram, a funnel and [more than twenty in all](#forms). Whatever the form, it is one SVG that fits the width it is given: what stands on a scale is placed by percentages, the lines keep their weight however far the plot stretches, and the text is never scaled. A chart of one series is ink, as a [progress bar](/components/progress) fills with ink; several series take the colors of a [category](/components/category). Each point is a list item that says its values in words.

## How it is drawn \{#how-it-is-drawn\}

The plot is an `<svg>` with no `viewBox`: it is as wide as its room and `--chart-height` tall, 14rem unless you say otherwise. A hairline, a tick, a bar and a dot are written with percentages of it, so a bar at `x="42%"` stays at 42% at any width while its corners keep their radius and its text keeps its size.

Only what must be a path, a line, an area or a slice, is drawn in `chart-canvas`: a nested SVG whose box is 100 by 100 and stretches to the plot. Its strokes do not scale with it, so a line is `--chart-stroke` wide in a narrow card and in a wide one.

Nothing is measured and nothing is drawn again when the width changes, so the same markup comes from a server, from a [framework component](#frameworks) and from the behavior. A chart fills the width it is given: in a row of things, give it a width or let it grow.

## Draw one \{#draw\}

The behavior writes a chart into an element with the class `chart`. `label` says what the chart shows and in what unit; `labels` names the steps of the scale and each series holds one value for each.

```js name=app.js
import { chart } from '@master/ui/behaviors/chart.js'

chart(document.querySelector('.chart'), {
  type: 'line',
  label: 'Latency by region, in milliseconds',
  labels: ['Jan', 'Feb', 'Mar', 'Apr'],
  series: [
    { name: 'Tokyo', values: [42, 44, 41, 47] },
    { name: 'Frankfurt', values: [61, 58, 63, 66] },
  ],
})
```

On a server, `chartMarkup()` returns the same chart as a string, with every word in it escaped; put it in the element and the page reads before any script runs. `chartLayout()` returns what the drawing holds as data: the scale and its ticks, each series' path, and every point with its marks and the sentence that says it.

```js name=server.js
import { chartMarkup } from '@master/ui/behaviors/chart.js'

const html = `<figure class="chart">${chartMarkup({ type: 'bar', label, labels, series })}</figure>`
```

Calling `chart()` on that element with no series works the chart as it is written, and `attach()` from `@master/ui/behaviors` does so for every chart on the page.

### Only the forms a page draws \{#forms-only\}

`chart.js` has every form: about 16 kB minified and gzipped. A page that draws one or two can carry those alone. `chart-core.js` is the chart with no form of its own, about 6 kB, and each form is a module that `chartForms()` takes: lines, areas and bars together add about 2 kB, since they share a scale, and every other form under 1 kB.

```js name=app.js
import { chartCore, chartForms } from '@master/ui/behaviors/chart-core.js'
import { chartCartesian } from '@master/ui/behaviors/chart-cartesian.js'

chartForms(chartCartesian)
chartCore(document.querySelector('.chart'), { type: 'line', label, labels, series })
```

| Module | Draws |
| --- | --- |
| `chart-cartesian.js` | `line`, `area`, `bar` |
| `chart-scatter.js` | `scatter` |
| `chart-pie.js` | `pie`, `donut` |
| `chart-rings.js`, `chart-radar.js`, `chart-sunburst.js` | `rings`, `radar`, `sunburst` |
| `chart-waterfall.js`, `chart-range.js` | `waterfall`; `range`, `dumbbell` |
| `chart-slope.js`, `chart-bump.js` | `slope`, `bump` |
| `chart-marimekko.js`, `chart-funnel.js`, `chart-waffle.js`, `chart-treemap.js` | `marimekko`, `funnel`, `waffle`, `treemap` |
| `chart-histogram.js`, `chart-box.js`, `chart-heatmap.js` | `histogram`, `box`, `heatmap` |

A type no form draws throws an error that names what to import, so a missing form is found at once.

| --- | --- | --- |

| [Area chart](/charts/area) | `area` | A line with a wash of its color under it, alone or stacked into a total. |
| [Slope chart](/charts/slope) | `slope` | What rose, what fell and what crossed between two moments, read from the slopes. |
| [Bump chart](/charts/bump) | `bump` | How the ranks of a few things changed, as lines that cross where one overtakes another. |
| [Bar chart](/charts/bar) | `bar` | Amounts compared as bars on a baseline: side by side, stacked or across. |

| [Waterfall chart](/charts/waterfall) | `waterfall` | How a figure became another, as steps up and down from the first to the last. |
| [Range chart](/charts/range) | `range` | Spans between two values: where each begins and where it ends. |
| [Dumbbell chart](/charts/dumbbell) | `dumbbell` | Two values of each thing joined by a stem, so the gap between them is the mark. |
| [Pie chart](/charts/pie) | `pie` | What one whole is made of, as slices of a circle. |
| [Donut chart](/charts/donut) | `donut` | The parts of a whole around one figure that stands in the middle. |
| [Rings](/charts/rings) | `rings` | A few readings, each filling a ring of its own toward its whole. |
| [Marimekko chart](/charts/marimekko) | `marimekko` | Columns as wide as their totals, each split into its parts. |
| [Funnel chart](/charts/funnel) | `funnel` | The stages of one flow, each narrowing to the next. |
| [Waffle chart](/charts/waffle) | `waffle` | A hundred cells, each one percent of the whole. |
| [Treemap](/charts/treemap) | `treemap` | Many parts of a whole as tiles, each as large as its share. |
| [Sunburst chart](/charts/sunburst) | `sunburst` | A whole, its parts and the parts of each part, in two rings. |
| [Histogram](/charts/histogram) | `histogram` | How readings are spread: bins between round numbers, each as tall as its count. |
| [Box plot](/charts/box) | `box` | The spread of several groups in five figures each: a box, its median and its whiskers. |
| [Heatmap](/charts/heatmap) | `heatmap` | A pattern across two scales: cells as dark as their values. |
| [Scatter plot](/charts/scatter) | `scatter` | Two measures against each other, one dot to a thing. |

Lines, areas and bars share one scale and may stand in one chart: a series with a `type` of its own is drawn as that mark, such as a line over bars.

## The readout and the keys \{#readout\}

`chart-tip` is the readout: the point's name, then a row for each series with a stroke of its color, its name and its value. It stands beside the point on the side with more room and slides along its own height, so it never leaves the plot and never needs to be placed by a script. The behavior fills it from what the point's marks carry and passes the point's place on as `--chart-x`, `--chart-y` and `--chart-reach`.

The plot is one stop in the tab order, however many points it has. The arrow keys move from point to point and show each one's readout; a finger does the same by moving along the chart.

## Legend \{#legend\}

A chart of two series or more has a legend: a color is never the only way a series is told apart. Each entry is a label around a checkbox, so it is reached with Tab and toggled with Space; unchecked, its series leaves the chart, the scale fits what is left, and the others keep their colors. A chart of one series has none, since its title already says what is drawn.

`toggle: false` writes the legend as a plain list, and `legend: false` leaves it out, for a chart whose series are named in the words around it. The chart's value is the names of the hidden series: read it from what `chart()` returns, or set it to hide a series from outside.

## Color \{#color\}

A chart with one series is drawn in `--chart-color`, the ink. Series of a chart with several, and the parts of a whole, take a category each in a fixed order: blue, orange, teal, violet, amber, pink, green and sky. Neighbors in that order stay apart for the common kinds of color blindness, in both schemes. Past eight the order begins again, so fold the rest into "Other" or draw a second chart.

Give a series its own `category` when the color follows the thing: Tokyo is blue in the chart, in its [badge](/components/badge) and in its row of a table, wherever it stands in the list. A status color never stands for a series; a series that is failing says so in words.

## Scale and figures \{#scale\}

The scale starts at zero, or under it for a value under zero, and ends at a round number above the highest value, marked in about four steps. `min` and `max` hold either end, and `ticks` asks for another number of steps. A bar's scale should start at zero: a bar's length is its value.

`format` writes a value in the readout and at a bar's end, and `tickFormat` a figure of the scale, which is written in full under 10,000 and compact above it. Both take the number and return a string. `locale` is a BCP 47 tag for the numbers, `en-US` by default; give it when a server writes the chart, so both sides agree.

| Option | Default | |
| --- | --- | --- |
| `type` | `'bar'` | The form: one of the types in [Forms](#forms) |
| `label` | none | What the chart shows and in what unit: the plot's accessible name |
| `labels` | `[]` | The names along the scale, around a radar or over a heatmap's columns |
| `series` | `[]` | Each with a `name` and what its form reads: `values`, a `value`, `points`, `ranges` or `children`; optionally a `category`, a `type`, `low` and `high`, and a ring's `max` |
| `stacked` | `false` | Bars, or areas, stand on each other; `'percent'` makes every stack a whole, and `'stream'` centers stacked areas on a middle line |
| `horizontal` | `false` | Bars, ranges, dumbbells and boxes run across |
| `mark` | `'bar'` | `'lollipop'` draws a bar as a stem with a dot at its end |
| `curve` | `'smooth'` | `smooth`, `linear` or `step` |
| `min`, `max`, `ticks` | fit, `4` | The ends of the scale and about how many steps mark it; `xMin`, `xMax` and `xTicks` for a scatter's scale across |
| `axis` | `true` | Whether the scale's figures are written; `false` keeps the hairlines alone, for a small chart in a tile |
| `format`, `tickFormat` | the locale's | How a value and a tick are written; `xFormat` for a scatter's scale across |
| `dots`, `values` | `false` | Mark every point of a line; write every bar's value |
| `current` | none | The index of the point marked `aria-current` |
| `legend`, `toggle` | with two series, `true` | Whether a legend is written, and whether its entries are checkboxes |
| `hole`, `center` | `.7`, none | A donut's hole, and what stands in the middle of a donut or rings |
| `total` | none | A waterfall's closing bar: its name |
| `bins` | from the count | About how many bins a histogram sorts its readings into |
| `ascending` | `false` | In a bump chart, the lowest value ranks first |
| `words` | English | The names of a box plot's five figures: `min`, `q1`, `median`, `q3` and `max` |
| `hidden` | `[]` | The names of the series left out |
| `locale` | `'en-US'` | A BCP 47 tag for the numbers |
| `draw` | none | Takes over the writing: called with the hidden names, for a renderer that writes the chart itself |

## Motion \{#motion\}

Marks draw themselves in when they first appear: bars rise from the baseline one after another, a line runs in from the start, slices and a radar's shapes open from the center and a ring fills. The readout glides from point to point, while what marks the point, the hairline, the dots and the stepped-back bars, answers at once, because a highlight has to keep up with a hand. With reduced motion nothing travels: marks appear drawn and the readout changes place at once.

## What the platform does \{#platform\}

- **Corners and the rise of a bar** are a `clip-path` on the SVG shape. A browser that does not clip an SVG shape with a CSS shape draws square bars at their full length.
- **The fade of an area** is a `mask-image` on the path. Without it the area is an even tint.
- **The radius of a dot** is the CSS `r` property, set by `--chart-dot`. Without it a dot keeps the radius its markup carries.
- **Thinning labels** is a container query on the plot's body. Without one every label stays.
- **Drawing in** is `@starting-style`. Without it marks appear drawn.

## When a chart is not enough \{#limits\}

A chart is drawn for a few hundred marks, each an element a reader can reach. Thousands of points, values that stream in, a zoom, a brush, a map or a candlestick belong to a charting engine that draws on a canvas. For less than a chart, there are smaller things: a [sparkline](/components/sparkline) for a trend in a sentence, a [stat](/components/stat) for one figure, a [meter](/components/meter) or a [gauge](/components/gauge) for one reading, a [breakdown](/components/breakdown) for the parts of a total along one bar and a [heatmap](/components/heatmap) for a pattern across many small values. [Charts](/guide/charts) says which to choose.

## Accessibility \{#accessibility\}

- Give `label` a sentence that says what is measured and in what unit: it is the plot's name, and the plot is a list.
- Each point is a list item named with its values, such as "Thu: Tokyo 71, Osaka 49", so a screen reader reads the chart as it reads a list, with no script and no table. The hairlines, the ticks and the readout are hidden from it: they repeat what the points say.
- The readout is a convenience for the eye. It appears on hover, on focus and under a finger, and <kbd class="kbd">Esc</kbd> hides it.
- Color is never alone: a series is named in the legend, and the readout names it beside its value. A category is not a status.
- A point with the focus is outlined on its band, its dot, its slice or its ring, not around a box.
- In forced colors the ink and the hairlines take the system's colors, and the focus is drawn in the highlight color. Series keep the colors they were given, so name them in the legend.
- The scale runs from the left in every language. Names, values and the legend follow the page's direction.

## React, Svelte and Vue \{#frameworks\}

The `chart` component writes the chart from `chartLayout()`, so the first HTML a server sends holds it, and attaches the behavior, which fills the readout and answers the keys. It takes the options above as props, and its value is the names of the hidden series. Copy it into the project with `npx master-ui add chart`; [React, Svelte and Vue](/guide/frameworks) says how the components are built and used.
