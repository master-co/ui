## Rows \{#rows\}

- `tree-item` is a row: a link, a button, or the `<summary>` of a branch. Rows are 28px, dense and quiet; the one under the pointer takes a chip tone, and the current one rises as a small raised sheet in strong ink.
- `tree-toggle` on a branch's row takes a `tree-chevron` icon first, in the leading column, which turns down while the branch is open. Every row keeps that column, so a leaf lines up with the branches beside it.
- `tree-sub` holds the rows under a branch, one level in, on a hairline that runs down from the chevron.

## The behavior \{#behavior\}

The WAI-ARIA tree pattern gives one tab stop and arrow keys that walk and fold the tree. That needs a script, the `tree` [behavior](/guide/behaviors), and the same classes serve it: put `role="tree"` on the list, `role="treeitem"` and `aria-expanded` on each branch's row, and `role="group"` on its `tree-sub`. The chevron then follows `aria-expanded`, a row that says `aria-expanded="false"` hides the `tree-sub` that follows it, and `aria-selected="true"` marks the selected row.

`tree` takes the root, the element with the `tree` class, and returns the function that detaches it. Its options turn on [renaming](#rename): `rename: true` and `renameLabel`, the accessible name of the field, `Rename <label>` by default.

```js name=app.js
import { tree } from '@master/ui/behaviors/tree.js'

const root = document.querySelector('.tree')
const files = tree(root)

root.addEventListener('change', () => console.log(files.value))
```

- **One tab stop.** The behavior keeps one row in the tab order with `tabindex`: the row the markup gave `tabindex="0"`, or the selected or current row, or the first. A row that takes focus becomes the tab stop. Detaching gives every row back the `tabindex` it had.
- **Walking.** The keys skip rows inside a closed branch, `hidden` rows and disabled ones.
- **Activation.** A summary, a link and a button keep the activation the browser gives them. A row that has none, `role="treeitem"` on a `div`, is activated by <kbd>Enter</kbd>, <kbd>Space</kbd> and a click: a branch opens or closes, and a leaf becomes the selected row. `aria-selected="true"` moves to it from the row that had it.
- **The value.** The function `tree` returns has a `value`: what the selected row stands for, its `data-value` or its text, null when none is. In a [multiselectable tree](#several) and a [checkbox tree](#checkbox) it is a list. Set it to select or check rows from outside; that dispatches nothing.
- **Events.** Each bubbles from the root, with the row in `detail.item`. Selecting or checking dispatches `input`, then `change`. Opening a branch dispatches `expand`, with what the row stands for in `detail.value`. Renaming dispatches `rename`, with `detail.value` and the new label in `detail.label`.
- **Disabled.** A row with `disabled` or `aria-disabled="true"` does nothing: its link is not followed, its branch stays as it is, and it is not selected, checked or renamed.

The behavior serves a tree of `<details>` too, as in the first two previews, which run without it. It opens and closes a `tree-group` through `open`, and the tree becomes one tab stop walked with the same keys. `attach()` attaches it to every tree; to keep a tree of `<details>` as the platform has it, import behaviors by name.

## Several rows \{#several\}

With `aria-multiselectable="true"` on the tree, any number of leaves are selected, the way a file list selects. Every row that can be selected says `aria-selected`, `true` or `false`; a branch is not selected, it folds. The value is the list of the selected rows, in the order of the tree.

- **A click** selects that row alone. <kbd>Control</kbd> or <kbd>Command</kbd> with a click selects or unselects one row and keeps the others. <kbd>Enter</kbd> does what a click does.
- **<kbd>Space</kbd>** selects or unselects the row in focus. The arrow keys only move.
- **A run.** The row chosen last is the anchor. <kbd>Shift</kbd> with a click, with <kbd>Space</kbd> or with <kbd>ArrowDown</kbd> or <kbd>ArrowUp</kbd> selects every visible row from it to the row; <kbd>Control</kbd> or <kbd>Command</kbd> with <kbd>Shift</kbd> and <kbd>Home</kbd> or <kbd>End</kbd> runs to the first or the last. Rows inside a closed branch and disabled rows are passed over.
- **Everything.** <kbd>Control</kbd> or <kbd>Command</kbd> with <kbd>A</kbd> selects every visible row, or none when they all are.

## Checkbox tree \{#checkbox\}

When its rows carry `aria-checked`, the tree is a checkbox tree: each row has a check, and checking a branch checks every row under it, inside closed branches too. A branch says what its rows say: `true` when all are checked, `false` when none is, `mixed` otherwise. Put `tree-check` with `aria-hidden="true"` in each row, after the chevron's column and before the label: it is the [checkbox](/components/checkbox)'s own well, drawn from the row's `aria-checked`, so the row says its state once.

- **<kbd>Space</kbd>** checks or unchecks the row in focus, a branch with all its rows. A mixed branch is checked, or unchecked when every row under it that can change is checked already.

Put `aria-multiselectable="true"` on the tree as well: a checkbox tree is one where any number of rows are chosen, and it is announced as one.

## Renaming \{#rename\}

With `rename: true`, <kbd>F2</kbd> on a row turns its label into an [editable](/components/editable) in place, its text selected. The label must be a `tree-label`, which also ends a long name in an ellipsis. <kbd>Enter</kbd> saves and <kbd>Escape</kbd> puts the label back; either way focus returns to the row. Leaving the field saves it, and an empty label is not saved.

`attach()` passes no options, so this preview calls `tree` itself after `attach()` has run: a second call on one root replaces the first.

The behavior writes the new label into the `tree-label` and dispatches `rename` from the root, with what the row stood for in `detail.value` and the new label in `detail.label`; the field's own `input` and `change` stay inside it. Saving the label is the page's: if the server refuses it, write the old label back. Give each row a `data-value` that does not change with its name, so the value it stands for survives the rename.

A reader without <kbd>F2</kbd>, on a touch screen, needs another way in: `edit(row)` on the function `tree` returns does what <kbd>F2</kbd> does, with or without the option, for a Rename item in a [context menu](/components/menu) or a button.

```js name=app.js
const pages = tree(root, { rename: true })

root.addEventListener('rename', async (event) => {
  const { item, value, label } = event.detail
  const saved = await fetch(`/api/pages/${value}`, { method: 'PATCH', body: JSON.stringify({ title: label }) })
  if (!saved.ok) item.querySelector('.tree-label').textContent = previous(value)
})

renameItem.addEventListener('click', () => pages.edit(selectedRow))
```

## Accessibility \{#accessibility\}

- With `<details>`, do not add tree roles: the native disclosure is announced correctly as it is, and without the behavior every row is a tab stop.
- Mark the current row with `aria-current="page"`, or `aria-selected="true"` inside the tree pattern.
- Several rows, checks, loading and renaming are the tree pattern's, and need `role="tree"` and the behavior.
- In a checkbox tree the row says `aria-checked`; its `tree-check` is `aria-hidden="true"`, so the state is announced once.
- A busy branch says so with `aria-busy="true"`; its spinner is `aria-hidden="true"`.
- The rename field is named `Rename <label>`; pass `renameLabel` in the page's language.
- A row keeps its height on a touch screen, so the lines that join the levels keep their rhythm.

## React, Svelte and Vue \{#frameworks\}

The `tree` component renders the rows from data, attaches the behavior and passes the selected row in and out. Copy it into the project with `npx master-ui add tree`; [React, Svelte and Vue](/guide/frameworks) says how the components are built and used.

- `multiple` selects any number of rows, and `checkable` gives every row a check; with either, the value is a list. The first value is drawn into the first render, a branch's mixed check among it.
- A node with `children: []` is a branch whose rows come later: it holds a spinner, and `onExpand` (Vue: `@expand`) is called with its value when it opens. Give it its children in `nodes`.
- `onRename` (Vue: `@rename`) turns renaming on and is called with the row's value and its new label. Keep the label in `nodes`.
