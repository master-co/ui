## Rows \{#rows\}

- `tree-item` is a row: a link, a button, or the `<summary>` of a branch. Rows are 28px, dense and quiet; the one under the pointer and the current one take a chip tone.
- `tree-toggle` on a branch's row draws a chevron in the leading column, which turns down while the branch is open. Every row keeps that column, so a leaf lines up with the branches beside it.
- `tree-sub` holds the rows under a branch, one level in, on a hairline that runs down from the chevron.

## The behavior \{#behavior\}

The WAI-ARIA tree pattern gives one tab stop and arrow keys that walk and fold the tree. That needs a script, the `tree` [behavior](/guide/behaviors), and the same classes serve it: put `role="tree"` on the list, `role="treeitem"` and `aria-expanded` on each branch's row, and `role="group"` on its `tree-sub`. The chevron then follows `aria-expanded`, a row that says `aria-expanded="false"` hides the `tree-sub` that follows it, and `aria-selected="true"` marks the selected row.

`tree` takes the root, the element with the `tree` class, has no options, and returns the function that detaches it.

```js name=app.js
import { tree } from '@master/ui/behaviors/tree.js'

const root = document.querySelector('.tree')
tree(root)

root.addEventListener('change', (event) => console.log(event.detail.item))
```

- **One tab stop.** The behavior keeps one row in the tab order with `tabindex`: the row the markup gave `tabindex="0"`, or the selected or current row, or the first. A row that takes focus becomes the tab stop. Detaching gives every row back the `tabindex` it had.
- **Walking.** The keys skip rows inside a closed branch, `hidden` rows and disabled ones.
- **Activation.** A summary, a link and a button keep the activation the browser gives them. A row that has none, `role="treeitem"` on a `div`, is activated by <kbd>Enter</kbd>, <kbd>Space</kbd> and a click: a branch opens or closes, and a leaf becomes the selected row. `aria-selected="true"` moves to it from the row that had it.
- **The event.** Selecting a row dispatches a bubbling `change` from the root with the row in `detail.item`.
- **Disabled.** A row with `disabled` or `aria-disabled="true"` does nothing: its link is not followed and its branch stays as it is.

The behavior serves a tree of `<details>` too, as in the first two previews, which run without it. It opens and closes a `tree-group` through `open`, and the tree becomes one tab stop walked with the same keys. `attach()` attaches it to every tree; to keep a tree of `<details>` as the platform has it, import behaviors by name.

## Tree or nav \{#tree-or-nav\}

A [nav](/components/nav) is a short list of destinations with one level of grouping, and its current row rises as a sheet. A tree is for depth: many levels, dense rows, and a chevron that leads each branch.

## Accessibility \{#accessibility\}

- With `<details>`, do not add tree roles: the native disclosure is announced correctly as it is, and without the behavior every row is a tab stop.
- Mark the current row with `aria-current="page"`, or `aria-selected="true"` inside the tree pattern.
- On touch screens a row is 44px.
