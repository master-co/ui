A listbox is a list of options to choose from. It is the surface a [combobox](/components/combobox) and a [command palette](/components/command) open, and it can stand in the page on its own. The stylesheet draws every state from ARIA, and a script moves the attributes: which option is active, what a key does, what is chosen. For a listbox that stands in the page that script is the `listbox` [behavior](/guide/behaviors); a combobox and a command palette drive their list from their own field.

## Two states, two attributes \{#two-states\}

A listbox tells apart where the keys are and what has been chosen.

- **Active** is `aria-selected="true"`: the option the arrow keys are on, the one <kbd>Enter</kbd> would take. It takes a chip tone. The pointer gives the same tone to the row under it, at once and without a fade.
- **Chosen** is `aria-checked="true"`: a value that is set. It carries a check at its end. An option with `aria-checked` in either state keeps room for the check, so labels do not move.

Focus usually stays on the list or on a text field, and `aria-activedescendant` names the active option. When an option takes real focus instead, it also draws an ink outline.

## Rich options \{#rich-options\}

Put [`icon`](/components/icon) on a leading icon. `listbox-body` stacks a title over a `listbox-description`, and `listbox-end` sets a shortcut or a hint at the end of the row. `listbox-group` wraps a set of options with its `listbox-label`, and `listbox-separator` rules between groups.

## Filtering \{#filtering\}

A script filters by setting the `hidden` attribute on the options that do not match. Two things then happen without more script, through `:has()`:

- `listbox-empty` shows once every option is hidden, and hides again when one returns.
- A `listbox-group`, a `role="group"` element around a caption and its options, hides while all of its options are hidden, so a caption never stands over nothing.

## The behavior \{#behavior\}

`listbox` drives a listbox that stands in the page and holds focus itself, so the listbox has `tabindex="0"`. It takes the element with `role="listbox"`, has no options, and returns the function that detaches it.

```js name=app.js
import { listbox } from '@master/ui/behaviors/listbox.js'

const list = document.querySelector('.listbox')
listbox(list)

list.addEventListener('change', () => {
  const chosen = list.querySelectorAll('[aria-checked="true"]')
})
```

- **The active option.** The keys and a click move `aria-selected="true"` to one option, name it in `aria-activedescendant` on the listbox and scroll it into view. Focus never leaves the listbox. An option without an `id` is given one. When focus arrives and no option is active, the chosen option becomes active, or the first one.
- **Choosing.** <kbd>Enter</kbd>, <kbd>Space</kbd> or a click sets `aria-checked="true"` on the option and `false` on the others.
- **Events.** The listbox dispatches `input`, then `change`, each time what is chosen changes. Read the options with `aria-checked="true"`.
- **Skipped.** Hidden options and those with `aria-disabled="true"` are never active and cannot be chosen.

With `aria-multiselectable="true"` on the listbox, an option is checked or unchecked by itself and the others keep their state.

A listbox that a text field controls belongs to that field's behavior, which drives the list from the field. `listbox` leaves alone a listbox named by the `aria-controls` of a `role="combobox"` field, and `attach()` skips one inside a [combobox](/components/combobox) or a [command palette](/components/command). Without a script a listbox is drawn as its attributes say and does not change.

## Floating \{#floating\}

With the `popover` attribute a listbox is a floating sheet: a 12px corner around 8px rows, placed against its anchor and flipped at the viewport edge, with the same motion in and out as a [menu](/components/menu). Use `popover="manual"` when a text field owns it, so typing does not dismiss it. The [combobox](/components/combobox) shows this.

## Listbox, menu or select \{#listbox-menu-or-select\}

- A [select](/components/select) is the native control for one value from a list. Use it when the options are plain text; it needs no script.
- A [menu](/components/menu) holds actions, as native buttons and links.
- A listbox holds values or results that a script filters, groups or loads: a combobox, a command palette, a multi-select.

## Keyboard \{#keyboard\}

## Accessibility \{#accessibility\}

- Give the container `role="listbox"` and a label, and each option `role="option"`. A `listbox-group` is `role="group"`, labelled by its caption with `aria-labelledby`.
- The behavior moves `aria-selected` and `aria-activedescendant` together and scrolls the active option into view; options keep a scroll margin so it clears the list's edge.
- A disabled option has `aria-disabled="true"` and is skipped by the keys.
