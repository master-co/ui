Master-detail sets a list beside whatever is chosen in it: keys and a key, messages and a message, files and a file. Each pane scrolls by itself, so the list keeps its place while the reader moves through the detail.

This one is written with utilities alone. It is small enough to live inside a page, and it answers to its own width with container queries, so it works in a wide page and in a narrow panel alike.

## How it is built \{#how-it-is-built\}

- **`container-inline` on the frame** makes it a size container. Every `@container(…)` utility inside measures the frame, not the screen.
- **A row with a fixed height.** `flex h(440)` gives both panes the same height; `overflow-y-auto` on each makes them scroll alone. In a full-height app, take the height from a [fixed shell](/layouts/app-shell#fixed) instead of a number.
- **The list is fixed and the detail is fluid.** The list is `w-full` until the frame reaches 48rem, then `w(300)@container(--3xl)` with `shrink(0)`. The detail is `grow(1) basis(0) min-w(0)`: it takes the rest and never pushes the list.
- **Below 48rem there is one pane.** The detail is `hidden` and returns with `flex@container(--3xl)`. A narrow screen shows the list; choosing a row goes to the detail on its own page. That is navigation, so it belongs to your router, not to the layout.
- **The line between the panes** is `bxe(1)@container(--3xl) bxe-solid@container(--3xl)`: it exists only while there are two panes.

The current row is marked with `aria-current="true"` on a `list-row` in a [`list-interactive`](/components/list).

## Three ways to build it \{#three-ways\}

| When | Use |
| --- | --- |
| The panes are a region of a page | Utilities and a container, as above |
| The reader resizes the panes | A [splitter](/components/splitter) |
| The panes are the whole app | A [fixed shell](/layouts/app-shell#fixed), with the list as its sidebar |

## Accessibility \{#accessibility\}

- The list is a list of links, each to a detail. `aria-current="true"` marks the one on show.
- Label the frame, and give the detail a heading that names what was chosen, so a reader who lands in it knows where they are.
- A pane that scrolls and holds nothing focusable needs `tabindex="0"`, so the keyboard can scroll it.
- When the detail is hidden on a narrow screen it is `display: none`, out of the accessibility tree; do not leave a control that points at it.
