## How it is built \{#how-it-is-built\}

| Region | Classes | Holds |
| --- | --- | --- |
| Header | `navbar shell-header` | The brand, a search field, a way to the product |
| Sidebar | `shell-sidebar` | A [nav](/components/nav) with `nav-label` over each group |
| Main | `shell-main` | An `<article>` at `max-w(720) mx-auto` |
| Aside | `shell-aside` | A [table of contents](/components/toc) |

- **The article sets the measure.** 720px holds about 75 characters of body text, the upper end of a comfortable line. The column around it takes whatever is left, so the article stays centered between the side columns.
- **The side columns scroll by themselves.** Each is as tall as the viewport under the header, so a long navigation never moves the page and the page never moves the navigation.
- **The contents mark themselves.** The [table of contents](/components/toc) follows the page's scroll where the browser supports `scroll-target-group`; elsewhere, set `aria-current` from a script.
- **Headings clear the header.** `scroll-mt(80)` on each heading leaves room for the sticky bar when a link jumps to it.

The search field is hidden with `hidden flex@container(--xl)`: it appears when the navbar, which is a size container, is at least 36rem wide.

## Accessibility \{#accessibility\}

- Three navigations need three labels: the site's ("Documentation"), the page's ("On this page") and the breadcrumb's.
- The order in the source is header, navigation, article, contents. A reader of the page in order meets the article's `<h1>` after the navigation; offer a "Skip to content" link at the top.
- On a narrow screen the contents are not shown. That loses a convenience, not content: every heading is still in the article.
