An auto grid holds as many equal columns as fit, none narrower than a minimum. It needs no query: the grid counts its own columns from the room it is given, so the same markup is four tiles across a dashboard, two in a sidebar and one down a phone.

It is a layout class because the rule behind it, `repeat(auto-fill, minmax(min(100%, 16rem), 1fr))`, is one a utility cannot write and one that is easy to get subtly wrong. The `min(100%, …)` is what keeps a single column from being wider than a narrow screen.

## The minimum \{#minimum\}

`--auto-grid-min` is the narrowest a column may be, 16rem by default. A smaller minimum makes more, narrower columns: 11rem suits figures, 20rem suits cards with a paragraph in them.

## Fill or fit \{#fill-or-fit\}

By default empty columns keep their place, so two tiles in a wide grid stay the size of tiles. `auto-grid-fit` collapses the empty columns and lets the tiles that exist share the whole row. Use the default for a collection that grows; use fit for a fixed set that should always fill its row.

## When not to use it \{#when-not\}

When the number of columns is part of the design, say so: `grid grid-cols(3)` and a container variant such as `grid-cols(3)@container(--4xl)`. An auto grid decides for itself, which is right for collections and wrong for a layout where the third column means something.

## Accessibility \{#accessibility\}

- The grid changes how many columns there are, never the order: items read left to right, top to bottom, in source order.
- Use a list, `<ul class="auto-grid">`, when the tiles are a set of like things, so their number is announced.
