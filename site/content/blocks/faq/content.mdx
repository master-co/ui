Blocks are markup to copy. They take the page's own text color and size; the previews set `fg-text-body text-sm` on the body. Each block is a size container, so it reflows by its own width.

## What is in it \{#anatomy\}

- **A reading measure.** `max-w(720) mx-auto`: questions and answers are prose, and prose wants a column.
- **One open at a time.** The rows share a `name`, which makes the browser close one when another opens. Leave the `name` out to let several stay open.
- **The first is open.** It shows the pattern, and its answer is usually the one most people came for.
- **A way out.** One line under the list for the question that is not there.

Write the question the way a visitor would ask it, and answer in the first sentence. An answer that starts with "Great question" has not started.

## Accessibility \{#accessibility\}

- Each question is a `<summary>`: a button to assistive technology, with its open state. Find-in-page opens a closed row that holds a match.
- If the questions are the main content of the page, make each a heading inside its summary: `<summary class="accordion-trigger"><h3>…</h3></summary>`.
- For search engines, add `FAQPage` structured data from the same source as the markup, so the two cannot drift.
