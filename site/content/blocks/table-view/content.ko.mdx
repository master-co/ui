테이블 뷰에는 표를 사용하는 데 필요한 제목과 기본 작업, 필터와 정렬, 행 선택, 행별 작업, 페이지 탐색이 들어갑니다. 각각은 별도의 컴포넌트이며, 블록은 이들을 하나의 시트에 배치하는 방법을 보여 줍니다.

<PagePreview name="default" title="테이블 뷰" example="table-view" touchHeight={{ desktop: 860, tablet: 860, phone: 1064 }} caption="프로젝트를 검색, 필터링, 정렬하고 페이지를 넘겨 보거나, 사람과 파일로 전환해 보세요. 행을 선택해 삭제할 수도 있습니다." />

블록은 복사해 사용하는 마크업입니다. 페이지의 텍스트 색상과 크기를 따르며, 미리보기에서는 body에 `fg-text-body text-sm` 클래스를 설정합니다. 각 블록은 크기 컨테이너이므로 넓은 페이지, 사이드바 너비의 공간, 대화 상자 어디서든 자체 너비에 맞춰 배치가 바뀝니다.

## 구성 요소 \{#anatomy\}

- **하나의 [시트](/components/surface#sheet).** 시트 안에 카드를 겹쳐 넣는 대신 얇은 구분선 `bt(1) bt-solid b-line-hair`로 영역을 나눕니다.
- **헤더는 두 부분으로 나뉩니다.** 한쪽에는 워크스페이스 이름과 조건에 맞는 행의 개수를, 다른 쪽에는 프로젝트·사람·파일을 전환하는 [세그먼트 컨트롤](/components/segmented)과 기본 작업을 배치합니다. `flex flex-wrap items-center justify-between`을 적용하므로 시트가 좁으면 세그먼트 컨트롤과 기본 작업이 제목 아래로 내려갑니다.
- **검색, 필터, 정렬은 공간이 부족하면 줄바꿈되는 한 행에 배치합니다.** 200px에서 320px까지 늘어나는 검색 [입력 그룹](/components/input#input-group), [필터 바](/blocks/filter-bar)의 버튼, 정렬 순서를 고르는 볼록한 [셀렉트](/components/select)가 들어가며, 셀렉트는 `ml-auto`로 행의 끝에 배치합니다. 적용한 필터는 그 아래 별도의 줄에 [칩](/components/chip#values)으로 표시되며, 각 칩으로 필터를 하나씩 해제할 수 있습니다.
- **정렬 상태는 열 머리글에 표시합니다.** 정렬 기준 열의 머리글에 `aria-sort`를 지정하면 [표](/components/table#sorting)는 해당 머리글을 진한 글자색과 셰브런으로 표시합니다. 정렬 순서는 셀렉트에서 바꿉니다.
- **표는 자체 영역에서 스크롤됩니다.** `scroll-area-inline` 클래스를 적용한 [스크롤 영역](/components/scroll-area)에 표를 넣습니다. 시트가 좁아지면 페이지가 아니라 표만 스크롤되고, 열이 더 이어지는 가장자리는 흐리게 표시됩니다.
- **데이터 종류마다 첫 번째 셀이 다릅니다.** 프로젝트는 이름 아래에 도메인을, 사람은 [아바타](/components/avatar) 옆에 이름과 이메일을, 파일은 [아이콘 프레임](/components/icon-frame) 옆에 이름을 표시합니다. 첫 번째 셀은 `<th scope="row">`이므로 보조 기술은 같은 행의 데이터 셀을 읽을 때 이 행 머리글도 함께 읽습니다.
- **선택은 조건에 맞는 행을 대상으로 합니다.** 선택된 행에는 `table-row`에 `aria-selected="true"`를 지정해 선택 상태의 색상을 표시하고, 해당 행의 체크박스도 체크합니다. 헤더 체크박스는 모든 페이지에서 검색어와 필터에 맞는 행을 모두 선택하며, 일부만 선택되어 있으면 `indeterminate` 상태가 됩니다. 조건에 더 이상 맞지 않는 행은 선택에서 빠지므로 “15개 중 3개 선택됨”은 검색과 필터에 맞는 행만 집계합니다.
- **푸터는 두 부분으로 나뉩니다.** 한쪽에는 선택 상태와, 선택한 행이 있을 때 표시되는 삭제 및 선택 해제 버튼을, 다른 쪽에는 표시 범위와 버튼으로 구성한 [페이지네이션](/components/pagination)을 배치합니다. 첫 페이지에서는 이전 버튼이, 마지막 페이지에서는 다음 버튼이 비활성화됩니다. 페이지가 많으면 첫 페이지, 마지막 페이지, 현재 페이지의 앞뒤 페이지를 남기고 그 사이는 생략 표시로 나타냅니다.
- **행별 작업은 행 끝의 눈에 띄지 않는 버튼으로 여는 [메뉴](/components/menu)에 들어갑니다.** 버튼 이름에는 “Atlas 작업”처럼 해당 행의 이름을 포함합니다.
- **조건에 맞는 항목이 없으면 그 사실을 알립니다.** [빈 상태](/components/empty)가 본문을 채우고, 검색어와 필터를 지워 돌아갈 방법을 제공합니다.

## 스크립트가 필요한 동작 \{#script\}

행은 데이터이므로 예제의 `main.js`가 `data.js`의 데이터를 마크업에 들어 있는 데이터 종류별 템플릿에 작성합니다. 스타일시트와 유틸리티는 마크업에서, 텍스트는 데이터에서 가져옵니다. 이 예제는 [필터 바](/blocks/filter-bar)의 두 모듈을 공유합니다. `query.js`는 일반 행을 검색, 필터링, 정렬하고 페이지로 나누며, `filters.js`는 필터 바를 동작시킵니다. 실제 제품에서는 이런 질의를 데이터 소스에 보내며, 블록은 각 결과를 어떻게 표시하는지 보여 줍니다. 스크립트 없이 사용하려면 모든 영역을 하나의 `<form method="get">`으로 감싸세요. 검색 필드, 셀렉트, 체크박스가 서버에서 처리할 수 있는 쿼리 문자열이 되고, 페이지네이션은 링크가 됩니다.

## 접근성 \{#accessibility\}

- 시트는 `<section>`이며, 시트의 제목을 접근 가능한 이름으로 사용합니다. 표의 이름도 이 제목으로 지정합니다.
- 각 체크박스 이름에는 “Atlas 선택”처럼 해당 행의 이름을 포함합니다. 헤더 체크박스의 이름은 “프로젝트 15개 모두 선택”처럼 무엇을 선택하는지 알려 줍니다.
- 제목 아래의 개수는 일반 텍스트입니다. `sr-only`를 지정한 상태 영역이 “3페이지 중 2페이지”, “프로젝트 3개 삭제됨”처럼 작업 결과를 알립니다. 포커스는 누른 요소에 남으며, 그 요소가 있던 행이 사라지면 헤더 체크박스로 이동합니다.
- 작업 열의 제목은 화면에서 숨기되 보조 기술에서 읽을 수 있게 합니다.
- 페이지 탐색에는 레이블이 있는 `<nav>`를 사용합니다. 페이지는 현재 화면을 그 자리에서 바꾸므로 버튼으로 작성하고, 현재 페이지에는 `aria-current="page"`를 지정합니다.
- 각 행의 첫 번째 셀은 `<th scope="row">`입니다. 따라서 스크린 리더는 셀을 읽을 때 해당 프로젝트, 사람 또는 파일의 이름도 함께 읽습니다.
- 필터는 “프로젝트 필터”라는 이름의 팝오버에서 열립니다. 행과 메시지를 읽는 방식은 [필터 바](/blocks/filter-bar#accessibility)를 참고하세요.
- 표는 스크롤 영역 안에서 가로로 스크롤됩니다. 표 안의 체크박스와 버튼을 통해 키보드로 스크롤 영역에 접근할 수 있습니다. 표 안에 포커스를 받을 수 있는 요소가 없다면 스크롤 영역에 `tabindex="0"`, 역할, 접근 가능한 이름을 지정해야 합니다.
