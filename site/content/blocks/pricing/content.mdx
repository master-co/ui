Blocks are markup to copy. They take the page's own text color and size; the previews set `fg-text-body text-sm` on the body. Each block is a size container, so it reflows by its own width.

## What is in it \{#anatomy\}

- **Three [sheets](/components/surface#sheet) in a grid.** One column until 56rem of block, then `grid-cols(3)@container(--4xl)`. `items-start` lets each plan be as tall as its own list.
- **The recommended plan is lifted, not colored.** It is a `sheet` at the default elevation among `sheet-raised` neighbors, with a `badge-ink` and the page's one `btn-brand`. Depth, a word and the one hued button: three quiet signals, no colored border.
- **The price is a [price](/components/price)**: large figures, the currency mark hung small from their top, and the period beside them in muted ink on the same baseline.
- **The button comes before the list.** A visitor who has decided should not have to pass the features to act.
- **What is included is [bullets](/components/bullets) with `bullets-check`**: a check in ink hangs before each line, as decoration. The line reads without it.

Order the plans cheapest first. If one plan fits nearly everyone, say so in its description instead of adding a fourth.

## A comparison \{#comparison\}

A check and a dash are not words: each is hidden from assistive technology and carries visually hidden text, "Included" or "Not included". The scroll area has `tabindex="0"` and takes the heading's name, so the keyboard can scroll it.

## Accessibility \{#accessibility\}

- Each plan is an `<article>` with its name as an `<h3>` under the block's `<h2>`.
- The badge is text, "Most popular", so the recommendation is not carried by position or depth alone.
- In the table, the first cell of each row is a `<th scope="row">`, so a cell is announced with its feature and its plan.
- Write the period into the price. "$20" alone is not a price.
