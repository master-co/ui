Blocks are markup to copy. They take the page's own text color and size; the previews set `fg-text-body text-sm` on the body. Each block is a size container, so it reflows by its own width.

## What is in it \{#anatomy\}

- **A description list.** Each label is a `<dt>` and its figure a `<dd>`, in a `<div>` inside a `<dl>`, so the pair is announced as a pair. The label comes first in the source, as a description list requires; `flex-col-reverse` on the group draws the figure over it. Both orders read well, which is what makes reversing them safe.
- **The figure borrows the heading's type.** `heading heading-2xl` on the `<dd>` gives it the size, the ink and the tight tracking of a title without making it one.
- **Two columns, then four.** `grid-cols(2) grid-cols(4)@container(--4xl)`: four across from 56rem of block.
- **A hairline over the row**, `bt(1) bt-solid b-line-hair`, ties the figures to the header above.

For a figure in an application, with a label over it and a change beside it, use the [stat](/components/stat) component; see the [dashboard](/pages/dashboard) layout.

## Accessibility \{#accessibility\}

- Write the unit into the figure ("38 s", "99.99%"), so it reads without its label.
- A number that changes over time needs a date somewhere near it.
- Do not animate the figures counting up. It delays the one thing the block is for, and it is motion with no meaning.
