依使用者要完成的操作和預期的行為選擇元件。必須先確認才能繼續時，應使用對話框。若只是顯示詳細資訊，且點擊外部即可關閉，就適合使用彈出面板。兩者的標記都可能有效，因此檢查工具無法代替你做這個決定。

先找出符合需求的那一列，再到元件頁面查看標記、腳本需求，以及瀏覽器不支援時的備援行為。每份契約都在 [`use` 和 `instead`](#in-the-contract) 欄位提供該元件的相同選用指引。

選擇前，先確認內容是否必須保持可見、值是否應納入表單，以及操作是否會阻擋其他工作。這些條件通常比控制項的外觀更重要。

## 哪些用途不屬於元件 \{#not-a-component\}

有些用途未列在上方，因為沒有元件負責這些用途。

| 用途 | 類型 | 寫法 |
| --- | --- | --- |
| 區域內部的排列方式，例如堆疊、磚塊排列或閱讀欄 | [版面配置](/components#layouts) | 使用 utility。若 utility 無法表達所需配置，則使用版面配置類別，例如 [`auto-grid`](/components/auto-grid)、[`bento`](/components/bento)、[`masonry`](/components/masonry)、[`breakout`](/components/breakout)、[`sticky-stack`](/components/sticky-stack)、[`form`](/components/form) |
| 頁面中有特定用途的一段，例如主視覺區、價格表或登入卡片 | [區塊](/blocks) | 複製該區塊的標記，其中已組合好元件與 utility |
| 整個畫面中各區域的位置，以及哪些部分會捲動 | [頁面](/pages) | 把它的標記複製到兩種框架之一：[`page`](/pages/page) 或 [`shell`](/pages/app-shell) |

以這些範例為起點，將既有類別與 utility 搭配使用。[介紹](/guide/introduction#tiers) 說明何時應將共用的素材、狀態、平台行為或幾何配置封裝成元件類別。

## 契約也提供相同的選用指引 \{#in-the-contract\}

每份契約都有 `use` 欄位，說明何時該選用這個元件，以及 `instead` 清單，列出其他情境下更合適的相近元件。可從命令列查看：

```bash
npx master-ui contract combobox
```

指令會輸出完整契約。要判斷元件是否適用，請查看下列欄位：

```json
{
  "name": "combobox",
  "use": "One value from a list too long to scan, found by typing.",
  "instead": [
    { "when": "The list is short enough to read without typing", "use": "select" },
    { "when": "The list runs commands instead of filling a field", "use": "command" }
  ]
}
```

`contract` 也接受類別名稱，因此 `npx master-ui contract dialog-drawer` 會輸出對話框的契約。`npx master-ui list` 會列出所有契約及其說明，每份契約各占一行。

本頁的表格從任務出發，引導你選擇元件。`instead` 則從元件出發，引導你考慮其他選項。代理程式如果已經選定元件，直接讀取契約就能再確認一次，無須閱讀本頁。

選定合適的元件後，複製範例，並在接入頁面前檢查 `script` 和 `platform` 欄位。執行[標記檢查工具](/guide/contracts#diagnostics)，再用鍵盤和指標實際操作，完成預定任務。通過檢查只代表標記符合限制，元件是否適合這項任務仍須透過實際操作確認。
