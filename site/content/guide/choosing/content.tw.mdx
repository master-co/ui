依據讀者需要做什麼，以及結果應該如何表現來選擇元件。會阻擋下一步動作的確認需要對話框；點擊外部即可關閉的詳細資訊則適合 popover。兩者的標記都可能有效，因此檢查器無法替你做這個決定。

閱讀符合該工作的那一列，再到元件頁面查看它的標記、腳本需求與瀏覽器備援方式。每份契約都針對單一元件附有相同的選擇指引，寫在 [`use` 與 `instead`](#in-the-contract) 中。

選擇之前，請先決定內容是否必須保持可見、某個值是否屬於表單，以及該動作是否會阻擋其他工作。這些限制通常比控制項的外形更重要。

## 它不是元件 \{#not-a-component\}

有些工作在上面沒有對應的列，因為沒有任何元件負責它們。

| 工作 | 它是什麼 | 該寫什麼 |
| --- | --- | --- |
| 區域內的空間如何安排：堆疊、磚塊、閱讀欄 | [版面](/components#layouts) | utility，或在 utility 無法表達時使用版面 class：[`auto-grid`](/components/auto-grid)、[`bento`](/components/bento)、[`masonry`](/components/masonry)、[`breakout`](/components/breakout)、[`sticky-stack`](/components/sticky-stack)、[`form`](/components/form) |
| 頁面中具有目的的一段：主視覺、價格表、登入卡片 | [區塊](/blocks) | 複製它的標記：由元件與 utility 組成 |
| 一整個畫面的區域放在哪裡、哪些部分會捲動 | [頁面](/pages) | 複製它的標記，建立在兩種框架之一上：[`page`](/pages/page) 或 [`shell`](/pages/app-shell) |

從這些範例開始，以 utility 組合既有的 class。[簡介](/guide/introduction#tiers)說明了在什麼情況下，共用的材質、狀態、平台行為或幾何值得擁有一個元件 class。

## 契約中的相同指引 \{#in-the-contract\}

每份契約都有 `use` 欄位，說明何時該使用這個元件；還有 `instead` 清單，列出在其他情況下適合的相鄰元件。從命令列讀取它們：

```bash
npx master-ui contract combobox
```

輸出是完整的契約。以下是回答「這是不是正確的選擇」的欄位：

```json
{
  "name": "combobox",
  "use": "One value from a list too long to scan, found by typing.",
  "instead": [
    { "when": "The list is short enough to read without typing", "use": "select" },
    { "when": "The list runs commands instead of filling a field", "use": "command" }
  ]
}
```

`contract` 也接受 class 名稱，因此 `npx master-ui contract dialog-drawer` 會印出對話框的契約。`npx master-ui list` 會印出每份契約及其描述，每份一行。

本頁的表格從工作出發，引導到某個元件。`instead` 則從某個元件出發，引導到其他元件。已經選定元件的代理會閱讀它的契約，不必閱讀本頁就能得到第二道檢查。

確定某個元件合適後，請複製它的範例；接入頁面之前，先檢查它的 `script` 與 `platform` 欄位。執行[標記檢查器](/guide/contracts#diagnostics)，再以鍵盤與指標實際操作預期的任務；檢查沒有問題只代表標記符合限制，並不代表這個元件適合該任務。
