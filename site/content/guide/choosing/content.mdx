Choose a component by what the reader needs to do and how the result should behave. A confirmation that blocks the next action needs a dialog; details that can be dismissed by clicking outside fit a popover. Both can have valid markup, so the checker cannot make this decision for you.

Read the row that matches the job, then check the component page for its markup, script requirement and browser fallback. Each contract carries the same choice guidance for one component, in [`use` and `instead`](#in-the-contract).

Before choosing, decide whether the content must stay visible, whether a value belongs in a form, and whether the action blocks other work. Those constraints usually matter more than the shape of the control.

## It is not a component \{#not-a-component\}

Some jobs have no row above because no component does them.

| The job | What it is | What to write |
| --- | --- | --- |
| Where regions go and what scrolls | A [layout](/layouts) | Utilities. [`page`](/layouts/page), [`shell`](/layouts/app-shell), [`auto-grid`](/layouts/auto-grid) and [`form`](/layouts/form) are the only layout classes |

## The same guidance in a contract \{#in-the-contract\}

Every contract has a `use` field, which says when to reach for the component, and an `instead` list, which names the neighbor that is right in another situation. Read them from the command line:

```bash
npx master-ui contract combobox
```

The output is the whole contract. These are the fields that answer "is this the right one":

```json
{
  "name": "combobox",
  "use": "One value from a list too long to scan, found by typing.",
  "instead": [
    { "when": "The list is short enough to read without typing", "use": "select" },
    { "when": "The list runs commands instead of filling a field", "use": "command" }
  ]
}
```

`contract` also takes a class name, so `npx master-ui contract dialog-drawer` prints the contract of the dialog. `npx master-ui list` prints every contract with its description, one line each.

The tables on this page start from the job and lead to a component. `instead` starts from a component and leads away from it. An agent that has already picked a component reads its contract and gets the second check without reading this page.

Once a component fits, copy its example and check its `script` and `platform` fields before wiring it into the page. Run the [markup checker](/guide/contracts#diagnostics), then exercise the intended task with the keyboard and pointer; a clean check establishes markup constraints, not that the component suits the task.
