사용자가 해야 할 일과 그 결과가 어떻게 동작해야 하는지에 따라 컴포넌트를 선택하세요. 확인을 마칠 때까지 다음 작업을 막아야 한다면 대화 상자가 필요합니다. 바깥을 클릭해 닫을 수 있는 세부 정보에는 팝오버가 적합합니다. 두 컴포넌트 모두 유효한 마크업으로 작성할 수 있으므로 검사기로는 어느 쪽이 적합한지 판단할 수 없습니다.

하려는 작업에 해당하는 행을 읽은 뒤, 컴포넌트 페이지에서 마크업, 스크립트 필요 여부, 브라우저 폴백을 확인하세요. 각 컴포넌트의 계약 문서에도 해당 컴포넌트에 대한 동일한 선택 지침이 [`use` 및 `instead`](#in-the-contract)에 나와 있습니다.

컴포넌트를 고르기 전에 콘텐츠를 계속 표시해야 하는지, 값을 폼에 포함해야 하는지, 해당 작업이 다른 작업을 막아야 하는지 판단하세요. 대개 이런 조건이 컨트롤의 모양보다 중요합니다.

## 컴포넌트가 담당하지 않는 용도 \{#not-a-component\}

위 표에 빠진 용도 중에는 이를 담당하는 컴포넌트가 없는 경우도 있습니다.

| 용도 | 유형 | 작성 방법 |
| --- | --- | --- |
| 영역 내부의 배치 방식(스택, 타일, 읽기용 열 등) | [레이아웃](/components#layouts) | 유틸리티를 쓰고, 유틸리티만으로 배치를 표현하기 어려우면 레이아웃 클래스를 사용합니다. [`auto-grid`](/components/auto-grid), [`bento`](/components/bento), [`masonry`](/components/masonry), [`breakout`](/components/breakout), [`sticky-stack`](/components/sticky-stack), [`form`](/components/form) |
| 히어로, 요금표, 로그인 카드처럼 특정 목적을 가진 페이지 구간 | [블록](/blocks) | 컴포넌트와 유틸리티를 조합한 블록의 마크업을 복사합니다. |
| 전체 화면의 영역 배치와 스크롤되는 영역 | [페이지](/pages) | 페이지 마크업을 복사해 두 프레임 중 하나에 배치합니다. [`page`](/pages/page) 또는 [`shell`](/pages/app-shell) |

이 예제에서 시작해 기존 클래스와 유틸리티를 조합하세요. [소개](/guide/introduction#tiers)에서는 공통으로 쓰이는 표면 재질, 상태, 플랫폼 동작 또는 형태와 치수를 컴포넌트 클래스로 정의해야 하는 경우를 설명합니다.

## 컴포넌트 계약에 담긴 선택 기준 \{#in-the-contract\}

모든 계약에는 컴포넌트를 언제 사용하는지 설명하는 `use` 필드와, 다른 상황에 적합한 유사 컴포넌트를 알려 주는 `instead` 목록이 있습니다. 명령줄에서 확인하세요.

```bash
npx master-ui contract combobox
```

출력에는 계약 전체가 표시됩니다. 다음 필드에서 선택한 컴포넌트가 용도에 맞는지 확인할 수 있습니다.

```json
{
  "name": "combobox",
  "use": "One value from a list too long to scan, found by typing.",
  "instead": [
    { "when": "The list is short enough to read without typing", "use": "select" },
    { "when": "The list runs commands instead of filling a field", "use": "command" }
  ]
}
```

`contract`에는 클래스 이름도 전달할 수 있으므로 `npx master-ui contract dialog-drawer` 명령을 실행하면 대화 상자의 계약이 출력됩니다. `npx master-ui list`를 실행하면 모든 계약이 설명과 함께 한 줄씩 출력됩니다.

이 페이지의 표에서는 용도에 맞는 컴포넌트를 찾습니다. `instead`에서는 이미 고른 컴포넌트에서 출발해 다른 선택지를 살펴봅니다. 컴포넌트를 이미 고른 에이전트는 이 페이지를 읽지 않고도 계약을 읽어 선택이 적절한지 다시 확인할 수 있습니다.

용도에 맞는 컴포넌트를 찾았다면 예제를 복사하고, 페이지에 연결하기 전에 `script` 필드와 `platform` 필드를 확인하세요. [마크업 검사기](/guide/contracts#diagnostics)를 실행한 다음 키보드와 포인터로 의도한 작업을 직접 수행해 보세요. 검사를 통과하면 마크업 제약을 충족했음을 확인할 수 있으며, 작업에 적합한지는 실제 조작으로 판단해야 합니다.
