독자가 해야 할 일과 결과가 어떻게 동작해야 하는지에 따라 컴포넌트를 선택하세요. 다음 작업을 막는 확인 절차에는 대화 상자가 필요하고, 바깥을 클릭해 닫을 수 있는 세부 정보에는 팝오버가 적합합니다. 둘 다 유효한 마크업일 수 있으므로, 검사기가 이 결정을 대신 내려 줄 수는 없습니다.

작업에 맞는 행을 읽은 다음, 컴포넌트 페이지에서 마크업, 스크립트 요구 사항, 브라우저 폴백을 확인하세요. 각 계약에는 해당 컴포넌트에 대한 같은 선택 지침이 [`use`와 `instead`](#in-the-contract)로 들어 있습니다.

선택하기 전에 콘텐츠가 계속 보여야 하는지, 값이 폼에 속하는지, 액션이 다른 작업을 막는지 결정하세요. 이러한 제약은 보통 컨트롤의 모양보다 더 중요합니다.

## 컴포넌트가 아닌 것 \{#not-a-component\}

어떤 작업은 그것을 하는 컴포넌트가 없기 때문에 위의 표에 행이 없습니다.

| 작업 | 정체 | 작성할 것 |
| --- | --- | --- |
| 영역 안의 공간을 배치하는 방식: 스택, 타일, 읽기용 열 | [레이아웃](/components#layouts) | 유틸리티, 또는 유틸리티로 표현할 수 없는 경우 레이아웃 클래스: [`auto-grid`](/components/auto-grid), [`bento`](/components/bento), [`masonry`](/components/masonry), [`breakout`](/components/breakout), [`sticky-stack`](/components/sticky-stack), [`form`](/components/form) |
| 목적이 있는 페이지의 한 구간: 히어로, 가격표, 로그인 카드 | [블록](/blocks) | 복사한 마크업: 컴포넌트와 유틸리티를 조합한 것 |
| 화면 전체의 영역이 놓이는 위치와 스크롤되는 부분 | [페이지](/pages) | 두 프레임 [`page`](/pages/page) 또는 [`shell`](/pages/app-shell) 중 하나를 바탕으로 복사한 마크업 |

이러한 예제에서 시작해 기존 클래스를 유틸리티와 조합하세요. 공유되는 재질, 상태, 플랫폼 동작 또는 기하 구조가 언제 컴포넌트 클래스를 정당화하는지는 [소개](/guide/introduction#tiers)에서 설명합니다.

## 계약 안의 같은 지침 \{#in-the-contract\}

모든 계약에는 언제 그 컴포넌트를 사용하는지 알려 주는 `use` 필드와, 다른 상황에서 적합한 이웃 컴포넌트를 알려 주는 `instead` 목록이 있습니다. 명령줄에서 읽어 보세요.

```bash
npx master-ui contract combobox
```

출력은 계약 전체입니다. "이것이 맞는 컴포넌트인가"에 답하는 필드는 다음과 같습니다.

```json
{
  "name": "combobox",
  "use": "One value from a list too long to scan, found by typing.",
  "instead": [
    { "when": "The list is short enough to read without typing", "use": "select" },
    { "when": "The list runs commands instead of filling a field", "use": "command" }
  ]
}
```

`contract`는 클래스 이름도 받으므로 `npx master-ui contract dialog-drawer`는 dialog의 계약을 출력합니다. `npx master-ui list`는 모든 계약을 설명과 함께 한 줄씩 출력합니다.

이 페이지의 표는 작업에서 출발해 컴포넌트로 이어집니다. `instead`는 컴포넌트에서 출발해 그 컴포넌트에서 벗어나는 방향으로 이어집니다. 이미 컴포넌트를 고른 에이전트는 그 계약을 읽음으로써 이 페이지를 읽지 않고도 두 번째 확인을 거치게 됩니다.

컴포넌트가 적합하다면 그 예제를 복사하고, 페이지에 연결하기 전에 `script`와 `platform` 필드를 확인하세요. [마크업 검사기](/guide/contracts#diagnostics)를 실행한 다음, 키보드와 포인터로 의도한 작업을 직접 수행해 보세요. 검사를 통과했다는 것은 마크업 제약을 충족했다는 뜻이지, 컴포넌트가 작업에 적합하다는 뜻은 아닙니다.
