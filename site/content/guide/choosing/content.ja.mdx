ユーザーが何をする必要があり、操作の結果がどう振る舞うべきかに応じてコンポーネントを選びます。次の操作を止めて確認を求めるならダイアログが必要です。外側をクリックして閉じられる詳細表示にはポップオーバーが適しています。どちらもマークアップとしては妥当になり得るため、チェッカーで用途に合った選択かどうかは判断できません。

用途に合う行を探し、コンポーネントのページでマークアップ、スクリプトの要件、ブラウザーのフォールバックを確認します。各コントラクトの[`use`と`instead`](#in-the-contract)にも、そのコンポーネントについて同じ選択の目安が記載されています。

選ぶ前に、コンテンツを表示し続ける必要があるか、値をフォームに含めるか、操作中にほかの作業を止めるかを決めます。通常は、コントロールの形状よりもこうした条件が選択を左右します。

## コンポーネント以外の選択肢 \{#not-a-component\}

上の表には、対応するコンポーネントがない用途は載せていません。

| 用途 | 使うもの | 実装方法 |
| --- | --- | --- |
| 縦積み、タイル、本文用のカラムなど、領域内の要素の配置 | [レイアウト](/components#layouts) | ユーティリティ。ユーティリティで表現できない場合は、[`auto-grid`](/components/auto-grid)、[`bento`](/components/bento)、[`masonry`](/components/masonry)、[`breakout`](/components/breakout)、[`sticky-stack`](/components/sticky-stack)、[`form`](/components/form)などのレイアウトクラス |
| ヒーロー、料金表、サインインカードなど、特定の目的を持つページ内の区画 | [ブロック](/blocks) | コンポーネントとユーティリティを組み合わせたマークアップをコピー |
| 画面全体の領域の配置と、スクロールする範囲 | [ページ](/pages) | マークアップをコピーし、[`page`](/pages/page)または[`shell`](/pages/app-shell)のどちらかのフレームを使用 |

これらの例を起点に、既存のクラスとユーティリティを組み合わせます。[はじめに](/guide/introduction#tiers)では、質感、状態、プラットフォームのビヘイビア、形状のいずれかを共有していることが、どのような場合にコンポーネントクラスを用意する理由になるかを説明しています。

## コントラクトで用途を確認する \{#in-the-contract\}

すべてのコントラクトには、そのコンポーネントを使う場面を示す `use` フィールドと、別の場面に適した関連コンポーネントを挙げる `instead` リストがあります。コマンドラインで確認できます。

```bash
npx master-ui contract combobox
```

コントラクトは全体が出力されます。選んだコンポーネントが適しているかは、次のフィールドで確認できます。

```json
{
  "name": "combobox",
  "use": "One value from a list too long to scan, found by typing.",
  "instead": [
    { "when": "The list is short enough to read without typing", "use": "select" },
    { "when": "The list runs commands instead of filling a field", "use": "command" }
  ]
}
```

`contract` にはクラス名も渡せます。たとえば `npx master-ui contract dialog-drawer` はダイアログのコントラクトを出力します。`npx master-ui list` はすべてのコントラクトを説明付きで1件につき1行で出力します。

このページの表では、用途からコンポーネントを探せます。`instead` では、選んだコンポーネントを起点に、別の候補も確認できます。すでにコンポーネントを選んだエージェントは、そのコントラクトを読めば、このページを参照せずに選択が適切か再確認できます。

用途に合うコンポーネントが見つかったら、例をコピーし、`script` と `platform` のフィールドを確認してからページに組み込みます。[マークアップチェッカー](/guide/contracts#diagnostics)を実行し、キーボードとポインターの両方で目的の操作を試してください。チェッカーで確認できるのはマークアップが制約を満たすことまでです。用途に合うかどうかは実際の操作で確かめます。
