読み手が何をする必要があるか、そして結果がどう振る舞うべきかでコンポーネントを選びます。次の操作を妨げる確認にはダイアログが必要です。外側をクリックして閉じられる詳細情報にはポップオーバーが適しています。どちらも妥当なマークアップになり得るため、チェッカーがこの判断を代わりに行うことはできません。

用途に合う行を読み、その後コンポーネントのページでマークアップ、スクリプトの要件、ブラウザーのフォールバックを確認してください。各コントラクトには、1 つのコンポーネントについて同じ選択の指針が [`use` と `instead`](#in-the-contract) として含まれています。

選ぶ前に、内容を表示し続ける必要があるか、値がフォームに属するか、その操作がほかの作業を妨げるかを決めておきます。通常、こうした制約のほうがコントロールの形よりも重要です。

## コンポーネントではないもの \{#not-a-component\}

上の表に行がない用途もあります。それを担うコンポーネントがないためです。

| 用途 | 何であるか | 書くもの |
| --- | --- | --- |
| 領域内のスペースをどう配置するか。スタック、タイル、読み物のカラムなど | [レイアウト](/components#layouts) | ユーティリティ。ユーティリティで表せない場合はレイアウトクラス：[`auto-grid`](/components/auto-grid)、[`bento`](/components/bento)、[`masonry`](/components/masonry)、[`breakout`](/components/breakout)、[`sticky-stack`](/components/sticky-stack)、[`form`](/components/form) |
| 目的を持つページの一区間。ヒーロー、料金表、サインインカードなど | [ブロック](/blocks) | そのマークアップをコピーしたもの。コンポーネントとユーティリティを組み合わせたもの |
| 画面全体の領域をどこに置き、何をスクロールさせるか | [ページ](/pages) | そのマークアップをコピーしたもの。2 つのフレーム [`page`](/pages/page) または [`shell`](/pages/app-shell) のいずれかの上に構成します |

これらの例から始め、既存のクラスをユーティリティと組み合わせてください。共有するマテリアル、状態、プラットフォームの振る舞い、ジオメトリーがどのような場合にコンポーネントクラスに値するかは、[Master UI の紹介](/guide/introduction#tiers)で説明しています。

## コントラクト内の同じ指針 \{#in-the-contract\}

すべてのコントラクトには、そのコンポーネントをいつ使うかを示す `use` フィールドと、別の状況で適切な隣接コンポーネントを挙げる `instead` リストがあります。コマンドラインから読み取れます。

```bash
npx master-ui contract combobox
```

出力はコントラクト全体です。「これが適切なものか」に答えるのは次のフィールドです。

```json
{
  "name": "combobox",
  "use": "One value from a list too long to scan, found by typing.",
  "instead": [
    { "when": "The list is short enough to read without typing", "use": "select" },
    { "when": "The list runs commands instead of filling a field", "use": "command" }
  ]
}
```

`contract` はクラス名も受け付けるため、`npx master-ui contract dialog-drawer` はダイアログのコントラクトを出力します。`npx master-ui list` は、すべてのコントラクトを説明とともに 1 行ずつ出力します。

このページの表は、用途から出発してコンポーネントにたどり着きます。`instead` はコンポーネントから出発して、そこから離れる方向に導きます。すでにコンポーネントを選んだエージェントは、そのコントラクトを読むことで、このページを読まずに 2 つ目のチェックを得られます。

コンポーネントが合うと判断したら、その例をコピーし、ページに組み込む前に `script` と `platform` のフィールドを確認してください。[マークアップチェッカー](/guide/contracts#diagnostics)を実行し、その後キーボードとポインターで意図した作業を試します。チェックに問題がないことで確認できるのはマークアップの制約であり、そのコンポーネントが作業に適していることではありません。
