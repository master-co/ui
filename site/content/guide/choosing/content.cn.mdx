先明确用户要完成什么任务，以及界面应如何响应。必须先确认才能继续操作时，使用对话框。可以通过点击外部关闭的详情，适合放进弹出层。两者的标记都可以符合规范，因此检查器无法替你判断该选哪一个。

找到与任务对应的表格行，再到组件页面查看标记、脚本要求和浏览器回退方案。每份契约都在 [`use` 和 `instead`](#in-the-contract) 中提供该组件的选用指引。

选择前，先确定内容是否必须保持可见、值是否属于表单，以及操作是否会阻止其他操作。这些条件通常比控件的外形更重要。

## 在契约中查看同样的选型指引 \{#in-the-contract\}

每份契约都有一个 `use` 字段，说明何时适合使用该组件，以及一个 `instead` 列表，列出其他情形下适用的相近组件。可通过命令行查看这些内容：

```bash
npx master-ui contract combobox
```

命令会输出完整契约。可根据以下字段判断组件是否适用：

```json
{
  "name": "combobox",
  "use": "One value from a list too long to scan, found by typing.",
  "instead": [
    { "when": "The list is short enough to read without typing", "use": "select" },
    { "when": "The list runs commands instead of filling a field", "use": "command" }
  ]
}
```

`contract` 也接受类名，因此 `npx master-ui contract dialog-drawer` 会输出对话框的契约。`npx master-ui list` 会逐行输出所有契约及其描述，每份契约占一行。

本页的表格从用途出发，帮你找到组件。`instead` 从已选组件出发，指出何时该换用其他组件。已经选定组件的智能体可以直接读取契约，跳过本页并完成复核。

选到合适的组件后，复制其示例，并在接入页面前查看 `script` 和 `platform` 字段。运行[标记检查器](/guide/contracts#diagnostics)，再分别用键盘和指针完成预期任务。通过检查只说明标记符合约束，组件是否适合任务还需实际操作验证。
