プロジェクトは、クラス名、カスタムプロパティ、インポート、コマンドを通じて Master UI に依存します。ライブラリを使って実装する際は、以下の公開インターフェースを使い、アップグレード時にはそれらを確認してください。

Master UI は実験段階にあり、0.x のリリースでは公開インターフェースも変わることがあります。「公開」は現行バージョンでサポートされる利用方法を示すもので、次のリリースとの互換性は保証されません。[アップグレードの手順](#experimental)に沿って、プロジェクトに影響する変更を確認してください。

## 公開インターフェース \{#public\}

| 項目 | 定義箇所 | 例 |
| --- | --- | --- |
| クラス名 | コントラクトの `classes` | `btn`, `btn-primary`, `dialog-header` |
| クラスが要求する要素と属性 | そのクラスの `elements`、`attributes`、`label` | `switch` は `type="checkbox"` と `role="switch"` を持つ `<input>` に付けます。アクセシブルな名前も必要です。 |
| 状態を表すマーカー | コントラクトの `states` | `btn` の `aria-pressed="true"`、`switch` の `:checked` |
| コンポーネントのカスタムプロパティ | コントラクトの `properties` | `--btn-height`, `--splitter-size` |
| テーマトークン | `theme.css` の `@theme`。各トークンとその値は `@master/ui/theme.json` に記載されています。 | `--color-surface-raised`, `--radius-control`, `--lift` |
| ミックスイン名 | `theme.css` の `@mixin` | `--surface-sheet`, `--focus-ring`, `--anchored` |
| コントラクトのスキーマ | `@master/ui/contract.schema.json` | コントラクトのフィールドとその意味 |
| ビヘイビア | `@master/ui/behaviors` のエクスポート | `combobox(root)`、`attach()`、`calendarMonth()`、それぞれが返す関数とその `value` |
| フレームワーク向けコンポーネントの名前 | `master-ui add` が参照する `frameworks/manifest.json` | `combobox`, `dialog`, `toast` |
| チェッカー | `@master/ui/check` のエクスポート | `check`, `createIndex`, `parse`, `format`, `owners` |
| コマンド | `master-ui` | `list`, `contract`, `check`, `init`, `own`, `add`, `status`, `diff`, `accept` |
| インポートパス | パッケージの `package.json` にある `exports` | 下の表 |

各コントラクトには、対応するコンポーネントがインストール済みのバージョンで提供するインターフェースが記載されています。クラスやプロパティを使う前に、対象のコントラクトを表示して確認してください。

```bash
npx master-ui contract button
```

コントラクトの `properties` 一覧は、そのコンポーネント固有の拡張ポイントを定義します。一覧にない内部プロパティは変わることがあります。共通のテーマトークンは別の公開インターフェースで、`theme.css` に定義されています。

### インポートパス \{#import-paths\}

| パス | 内容 |
| --- | --- |
| `@master/ui`, `@master/ui/master.css` | テーマ、全コンポーネント、レイアウトクラスの Master CSS ソース |
| `@master/ui/theme.css` | 既定テーマのトークンとミックスイン |
| `@master/ui/components/<name>.css`, `@master/ui/layouts/<name>.css` | 個別のスタイルシート |
| `@master/ui/components/<name>.json`, `@master/ui/layouts/<name>.json` | 対応するコントラクト |
| `@master/ui/themes/<name>.css` | `paper` などの別テーマ |
| `@master/ui/contract.schema.json` | コントラクトの JSON Schema |
| `@master/ui/contracts.json` | 全コントラクトをまとめたファイル |
| `@master/ui/theme.json` | テーマの全トークンとその値 |
| `@master/ui/standalone.css` | 標準 CSS にコンパイルされたテーマと全コンポーネント |
| `@master/ui/base.css` | コンポーネントが前提とする最小限のリセット |
| `@master/ui/behaviors`, `@master/ui/behaviors/<name>.js` | `attach()` を含む全ビヘイビア、または個別のビヘイビア。いずれも TypeScript の型定義付き |
| `@master/ui/check` | コントラクトチェッカーのモジュール |

コンパイル済みのファイルは、CDN の配信パスである `@master/ui/dist/` 配下からも取得できます。対象は `dist/standalone.css`、`dist/base.css`、`dist/themes/<name>.css`、`dist/contracts.json`、`dist/theme.json` です。

## 非公開の実装詳細 \{#private\}

| 項目 | 例 | 利用できる代替手段 |
| --- | --- | --- |
| コンポーネントのコントラクトに記載されていない内部プロパティ | ボタンが自身のルール間で移動量を受け渡すために使う `--btn-lift` | コントラクトに記載されたプロパティ、または `--lift` などのテーマトークン |
| セレクターの構造 | ルールの入れ子構造、マーカーの描画に使う疑似要素、`components` レイヤー内でのセレクターの詳細度 | クラスと状態マーカー。要素に適用したユーティリティは、どのコンポーネントルールよりも優先されます。 |
| 既定テーマの値 | `--shadow-raised` に使うシャドウのリストや、`--surface-sheet` のグラデーションの色停止点 | トークン名やミックスイン名を使い、独自テーマで値や定義を上書き |
| スタイルシート内の宣言やルールの順序 | 2 つのルールのうち、どちらが後に記述されるか | ファイルの外部からこの順序に依存する箇所はありません。 |
| `behaviors/internal.js` | コンボボックス、コマンド、リストボックス、メニューのビヘイビアが共有するヘルパーです。ファイルの冒頭にも、ビヘイビアには該当しないことが明記されています。 | ビヘイビアの関数を使うか、[ビヘイビアを自分で管理する](/guide/behaviors#own-a-behavior)手順に従い、同じディレクトリにヘルパーファイルのコピーを置きます。 |
| このページに記載されていない `dist/` 配下のファイル | ビルドでその場所に生成されるその他のファイル | 上の表に記載されたパス |
| `frameworks/` 配下のファイル | パッケージに収録されている [React、Svelte、Vue のコンポーネント](/guide/frameworks)です。ソースをコピーして使う形式で、モジュールとしてのインポートはサポートされません。props はリリース間で変わることがあります。 | `npx master-ui add <name>` で対象を 1 つコピーできます。コピーはプロジェクト側で管理し、パッケージがリリースされても変わりません。 |

コントラクトを維持したまま、実装の詳細が変わることがあります。たとえば、コンポーネントが受け付けるマークアップを維持したまま、シャドウを調整したり、マーカーを別の疑似要素に移したりできます。表示結果は変わり得るため、アップグレード時は見た目も確認してください。

```css name=app.css
/* Public: the button contract lists --btn-height. */
.checkout .btn {
  --btn-height: 2.75rem;
}

/* Private: no contract lists --btn-lift, so a release may rename it. */
.checkout .btn {
  --btn-lift: 0px;
}

/* The public way to say the same thing is the theme token. */
.checkout {
  --lift: 0px;
}
```

## 変更の扱い \{#what-a-change-means\}

| 変更内容 | 破壊的変更 |
| --- | --- |
| 公開名の削除または改名。対象はクラス、必須属性、状態マーカー、コントラクトに記載されたプロパティ、トークン、ミックスイン、エクスポート、コマンド、インポートパスです。 | はい |
| 既定テーマの色調、シャドウ、グラデーション、時間の値の調整 | いいえ |
| 非公開の実装詳細に挙げた項目の変更 | いいえ |
| パッケージに収録されたフレームワーク向けコンポーネントの prop やマークアップの変更 | いいえ。プロジェクト内のコピーは取り込んだ時点のままです。上流の変更は `master-ui status` で確認できます。 |

コントラクトを維持したまま、見た目を調整できます。インストールするリリース、個々のコンポーネントの実装、テーマの値のうち、プロジェクト側でどれを管理する必要があるか決めてください。

**コンポーネントを自分で管理します。** `own` はスタイルシートとコントラクトをコピーし、ビヘイビアがあればそれもコピーします。ページがこれらのコピーを参照するように設定すると、以後のパッケージ更新で実装が置き換わることはありません。コピーしたスタイルシートは引き続きテーマトークンを参照するため、コンポーネントのコピーだけでは見た目まで固定できません。詳しくは[カスタマイズ](/guide/customization#own-a-component)を参照してください。

```bash
npx master-ui own button
```

### テーマをプロジェクト内で管理する \{#pin-the-theme\}

`node_modules/@master/ui/theme.css` をプロジェクトにコピーし、ライブラリの後にインポートします。コピー側のトークンとミックスインの定義が、パッケージ側の定義より優先されます。コピーした値は保持されますが、新しいトークンの追加や、コンポーネントによるトークンの使い方の変更は、表示に影響することがあります。ファイルの管理方法は[テーマ設定](/guide/theming)を参照してください。

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import './ui/theme.css';
```

## 実験段階での運用 \{#experimental\}

Master UI は実験段階にあり、バージョンは 0.x です。1.0 までは、上の表は各名前の位置づけを示すもので、名前の維持を保証するものではありません。どのリリースでも公開名が変更または削除される可能性があり、非推奨期間、互換レイヤー、移行ガイドは提供されません。変更点はリリースノートに記載されます。

インストールするバージョンを固定し、アップグレードは明示的に行ってください。

```bash
npm install @master/ui --save-exact
```

`--save-exact` は、許容するバージョン範囲の代わりに、選んだバージョンをそのまま記録します。別のチェックアウトでも同じ依存関係がインストールされるよう、パッケージマニフェストとロックファイルを一緒にコミットしてください。これにより、プロジェクト内のテーマやコンポーネントのコピーを、特定のリリースと照らし合わせて確認できます。

プロジェクトで管理しているコンポーネントについては、コマンドラインツールで上流の変更を確認できます。`status` は管理対象の各コンポーネントをインストール済みのパッケージと比較し、取り込み後に上流で変更されたファイルを一覧表示します。

```bash
npx master-ui status
```

管理対象のコンポーネントに上流の変更があると終了コード 2 を返すため、アップグレード後に実行するジョブで変更を検出して報告できます。`npx master-ui diff button` は、保存した比較基準とインストール済みのパッケージとの差分を表示します。差分を確認して自分でマージしたら、`npx master-ui accept button` で比較基準を更新します。このコマンドは作業コピーのマージや編集を行いません。各コマンドの使い方は[カスタマイズ](/guide/customization#upstream-changes)を参照してください。

<GuideFigure name="stability" title="上流の変更をマージする">

**差分を確認してマージし、新しい比較基準を記録します。** `diff` は、保存済みの比較基準とインストール済みのパッケージを比較します。作業コピーは比較の対象外です。取り込みたい変更を作業コピーにマージしたら、`accept` を実行します。インストール済みの上流ファイルが新たな比較基準として保存され、管理記録が更新されます。マージ済みの作業コピーには変更が加わりません。図のファイルに付いた印は模式的なもので、特定のリリースの差分を示すものではありません。

</GuideFigure>

アップグレードのたびに、次の手順を実行してください。

1. リリースノートを読み、固定している依存関係のバージョンとロックファイルを更新します。
2. プロジェクトのマークアップに対して `npx master-ui check` を実行し、コントラクトに合わなくなったクラス、要素、属性を検出します。
3. 管理対象のコンポーネントと追加したコンポーネントについて、`status` と `diff` を確認します。新しい比較基準を記録する前に、変更をマージしてください。
4. アプリケーションをビルドし、影響を受けるコントロールやオーバーレイ、キーボードでの操作手順を試します。プロジェクト内のテーマも含め、ライトモードとダークモードそれぞれの表示を比較します。

チェッカーが検証するのは、マークアップがコントラクトに適合しているかどうかです。アプリケーションの動作や描画結果が変わっていないかは、チェッカーでは確認できません。
