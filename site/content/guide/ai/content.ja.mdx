コーディングエージェントには、プロジェクトで使っているバージョンのコントラクトを渡し、変更したマークアップを検査させます。コントラクトには、クラス名、必須要素、状態を示す属性、公開カスタムプロパティが定義されています。チェッカーは、ページをレンダリングせずに、よくある構造上の誤りを検出します。

エージェントにライブラリーをインストールさせるには、[セットアップ用プロンプト](/guide/installation#set-up-with-an-ai-agent)を貼り付けます。スキルと後述のガイダンスも併せて導入されます。

変更前に、エージェントは Master UI の読み込み方、使用中のテーマ、プロジェクトで管理するコンポーネントが `master-ui.json` に記録されているかを確認します。ローカルのコントラクトが、パッケージの既定のコントラクトより優先されます。変更後の静的検査とブラウザーでの確認では、それぞれ異なる問題を確認します。マークアップが正しくても、レイアウトが意図どおりにならなかったり、操作にアクセシビリティ上の問題があったり、ビヘイビアスクリプトが不足していたりすることがあります。

<GuideFigure name="ai" title="コントラクトの検査とブラウザーでの確認">

**ソースとレンダリング結果を確認します。** インストール済みパッケージまたはプロジェクトで管理しているコントラクトに従ってマークアップを書きます。CLI は読み取れる要素、クラス、属性を検査し、ブラウザーではレイアウト、キーボード操作、各状態での動作を確認します。どちらの確認で見つかった問題も、変更を受け入れる前に解消します。

</GuideFigure>

## スキル \{#the-skill\}

`master-ui` スキルは、このライブラリーを使うプロジェクトで作業するエージェント向けです。次のコマンドでインストールします。

```bash
npx skills add master-co/ui --skill master-ui
```

| ファイル | 内容 |
| --- | --- |
| `SKILL.md` | ライブラリーがどのように導入されているかと、どのコンポーネントをプロジェクトで管理しているかの調べ方、コントラクトに沿ったマークアップの書き方、ライブラリーに必要な機能がない場合の対処、検証方法 |
| `references/choosing.md` | 複数の候補があるときのコンポーネントの選び方。ページに重ねる表示、メッセージ、選択肢、数値、ナビゲーション、レコードの一覧 |
| `references/customizing.md` | [カスタマイズの段階](/guide/customization)と、コンポーネントをプロジェクトで管理する条件 |
| `references/frameworks.md` | [React、Svelte、Vue](/guide/frameworks) でそのままマークアップとして書ける部分、コピーできるコンポーネントがあるパターン、そのようなコンポーネントの作り方 |

このスキルは、すでに Master UI を読み込んでいるプロジェクトで Master UI を使うようエージェントに指示します。別のライブラリーを使っているプロジェクトに Master UI を導入することはありません。

## プログラム向けの公開データ \{#for-programs\}

サイトでは構造化データと、他の環境でも利用できる Markdown を公開しています。コンポーネントの Markdown はコントラクトから生成し、ガイド、レイアウト、ブロック、ページは執筆された各ページから書き出します。公開データにはテキストとコードが含まれ、サイト上のインタラクションは含まれません。

| URL | 内容 |
| --- | --- |
| `https://ui.master.co/llms.txt` | インデックス。Master UI のマークアップ規則と、全ページの Markdown へのリンク |
| `https://ui.master.co/<section>/<slug>.md` | 各ページの Markdown。セクションは `guide`、`components`、`blocks`、`pages` のいずれかです。コンポーネントのページはコントラクトから生成され、マークアップ、クラス、状態、プロパティ、スクリプト、キーボード操作、プラットフォームの機能を記載します。コンポーネントに含まれるレイアウトは、執筆されたページ本文の後にコントラクトを掲載します。 |
| `https://ui.master.co/contracts.json` | 全コントラクトの構造化データ |
| `https://ui.master.co/contract.schema.json` | すべてのコントラクトが従う JSON Schema |
| `https://ui.master.co/theme.json` | テーマの全トークンとその値 |
| `https://ui.master.co/r/registry.json` | [レジストリー](/guide/registry)。プロジェクトにコピーできるソース |

シェルを使えないエージェントは `llms.txt` から始め、`https://ui.master.co/components/dialog.md` など、該当するコンポーネントのページを参照します。公開サイトの説明はサイトにデプロイされたバージョンに対応しており、プロジェクトにインストール済みのバージョンとは異なる場合があります。パッケージを利用できる場合は、同梱の `@master/ui/contracts.json` と `@master/ui/theme.json` を優先し、プロジェクトにローカルのコントラクトがある場合は後述の CLI を使います。

## コントラクトを調べる \{#look-up-a-contract\}

[パッケージをインストール](/guide/installation)してから、プロジェクトのルートで CLI を実行します。CLI はインストール済みのパッケージとプロジェクトからコントラクトを読み取ります。未インストールのコマンドを実行して、参照時に別のバージョンを取得させないでください。

```bash
npx master-ui list             # every contract, one line each
npx master-ui contract dialog  # one contract as JSON
```

名前にはクラス名を指定できます。たとえば `npx master-ui contract btn-primary` はボタンのコントラクトを出力します。`npx master-ui list --json` は一覧をデータ形式で出力します。

どちらのコマンドも、`master-ui.json` で設定したディレクトリー（既定は `ui/`）と、同ファイルで指定した追加のコントラクトパスからも読み取ります。プロジェクトで[管理するコンポーネント](/guide/customization#own-a-component)にはローカルコピーのコントラクトが使われ、[プロジェクト独自のコンポーネント](/guide/contracts#your-own)はライブラリーのコンポーネントと同じ一覧に表示されます。

## マークアップを検査する \{#check-the-markup\}

`npx master-ui check` はマークアップを読み取り、コントラクトに違反している箇所を報告します。たとえば、このファイルにはエラーが 3 件、警告が 1 件あります。

```html name=page.html
<button type="button" class="btn-primary">Save changes</button>
<button type="button" class="btn btn-outline">Cancel</button>
<button type="button" class="btn btn-square">
  <svg aria-hidden="true" viewBox="0 0 16 16"><path d="M4 4l8 8M12 4l-8 8"/></svg>
</button>
<div class="dialog">
  <h2 class="dialog-title">Delete this project?</h2>
</div>
```

```bash
npx master-ui check page.html
```

```
page.html:1:1 error missing-base "btn-primary" modifies "btn": write class="btn btn-primary".
page.html:2:1 warning unknown-class "btn-outline" is not a class of btn. It has: btn, btn-primary, btn-quiet, btn-brand, btn-danger, btn-sm, btn-lg, btn-square, btn-pill, btn-group.
page.html:3:1 error label "btn-square" needs an accessible name: text of its own, aria-label, aria-labelledby, or a <label> that wraps or points at it.
page.html:6:1 error element "dialog" goes on <dialog>, not <div>.

1 files checked: 3 errors, 1 warnings.
```

各行には、該当箇所、重大度、コード、修正方法が表示されます。エージェントはマークアップを修正し、指摘がなくなるまでコマンドを再実行できます。コードの一覧は[コントラクト](/guide/contracts#diagnostics)にあります。

- **検査対象のパス。** 引数を省略すると、作業ディレクトリー以下の `.html`、`.htm`、`.astro`、`.svelte`、`.vue`、`.jsx`、`.tsx`、`.mdx`、`.erb`、`.php`、`.njk`、`.liquid`、`.hbs` の各ファイルを検査します。`node_modules` とビルド出力は対象外です。ファイル、ディレクトリー、または glob パターンを渡して対象を絞り込めます。
- **検査できる範囲。** ブラウザーを起動せず、タグ、クラス、属性を読み取ります。式から求めるクラスや、ルート要素が別のファイルにあるパーツなど、静的に判定できないものは報告しません。
- **`--json`** は検査結果をデータ形式で出力します。ファイル数に加え、指摘のあったファイルごとに診断情報を出力します。各診断には `code`、`severity`、`className`、`contract`、`message`、`line`、`column` が含まれます。
- **`--strict`** は `unknown-class` をエラーとして報告します。コンポーネントのルートクラス名にハイフンを続けた文字列で始まり、どのコントラクトにも含まれないクラスは、ユーティリティの可能性があるため、既定では警告になります。プロジェクトに Master CSS がインストールされていれば、チェッカーはプリセットのユーティリティを認識します。プロジェクト独自のクラスに対する診断も確認してください。指摘がなくても、すべてのカスタムユーティリティや動的に決まるクラスの妥当性が保証されるわけではありません。

エラーを検出すると終了コード 1 を返すため、そのまま CI ステップに組み込めば、エラー時にステップが失敗します。

```json name=package.json
{
  "scripts": {
    "check:ui": "master-ui check --strict"
  }
}
```

プログラムから検査するには `@master/ui/check` を使います。チェッカーが読み取るデータについては[コントラクト](/guide/contracts)を参照してください。エージェントの完了条件にはブラウザーでの確認も含め、変更の影響を受けるキーボード操作、状態、狭い画面でのレイアウト、各カラースキームでの表示を検証します。必要なビヘイビアが要素に適用されていることも確認します。

## エージェントへの指示 \{#agents-md\}

エージェントはプロジェクト固有の指示を優先します。次の内容を `AGENTS.md` またはエージェントが読み取るファイルに貼り付けます。

```md name=AGENTS.md
## Master UI

This project builds its interface with Master UI: classes on native elements, each described by a contract.

- Read the contract before writing a component's markup: `npx master-ui contract <name>`, and `npx master-ui list` to find one. Do not write markup from memory.
- Never invent a Master UI component class. Use the installed or locally owned contract, and keep project-defined classes outside the library's class families.
- Mark a state with the attribute the contract lists (`disabled`, `aria-pressed="true"`, `open`). Never add a class for a state.
- A component is a class on a native element in any framework. Do not wrap one in a component to rename it. The patterns that hold state have a component to copy: `npx master-ui add` lists them, and `ui/` may already hold one.
- To change how something looks, take the lowest step that works: a utility on the element, a theme token, a public custom property, a theme file, and only then `npx master-ui own <name>`. A project rule may select a library class to set its documented custom properties; change its implementation through owned source.
- Run `npx master-ui check` after changing markup. Fix every error and read each warning. Check the affected interactions in a browser, including the keyboard, a narrow viewport and both color schemes.
```

## MCP \{#mcp\}

Master UI パッケージには、前述の CLI とコントラクトファイルが含まれています。エージェントを Master CSS MCP サーバーにも接続している場合は、コンポーネントのコントラクトを検索する前に、その接続で使えるツールを確認します。利用できるツールは接続先のサーバーによって異なります。プロジェクトで実際に適用されるコントラクトは、インストール済みの CLI から直接参照できます。

## チャットのサンドボックスやアーティファクトで使う \{#without-a-build\}

CSS をコンパイルしないチャットのアーティファクトや静的 HTML のプロトタイプでは、サイトのコンパイル済みスタイルシートをリンクします。環境にリセット CSS が用意されていなければ、サイトの基本リセットも読み込みます。

```html
<link rel="stylesheet" href="https://ui.master.co/base.css">
<link rel="stylesheet" href="https://ui.master.co/standalone.css">

<button type="button" class="btn btn-primary">Save changes</button>
```

これらの URL はサイトにデプロイされたバージョンに追従するため、一時的なプロトタイプに適しています。継続して保守するプロジェクトでは、[バージョンを固定したパッケージからコンパイル済みファイルを配信し](/guide/installation#without-master-css)、同じバージョンのコントラクトを参照します。CSS を読み込んでもビヘイビアスクリプトは適用されません。スクリプトが必要なパターンには、ブラウザーモジュールまたはフレームワークのコンポーネントも必要です。

この環境ではユーティリティを使えません。`flex` や `gap-md` のようなクラスを使うには Master CSS による生成が必要なので、`style` 属性や短いスタイルブロックに CSS を書いてレイアウトを整えます。テーマのトークンはカスタムプロパティなので利用できます。`color: var(--color-text-muted)` でテーマの値を参照できます。
