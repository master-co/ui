코딩 에이전트에 프로젝트에서 사용하는 버전의 계약을 제공한 뒤, 에이전트가 변경한 마크업을 검사하게 하세요. 계약에는 클래스 이름, 필수 요소, 상태 속성, 공개 사용자 지정 속성이 명시되어 있습니다. 검사기는 페이지를 렌더링하지 않고도 흔한 구조 오류를 찾아냅니다.

에이전트가 라이브러리를 설치하도록 하려면 [설치 프롬프트](/guide/installation#set-up-with-an-ai-agent)를 에이전트에 붙여 넣으세요. 스킬과 아래 지침도 함께 설치됩니다.

수정하기 전에 에이전트는 프로젝트에서 Master UI를 가져오는 방식과 사용하는 테마를 확인하고, `master-ui.json`에 프로젝트가 직접 관리하는 컴포넌트가 기록되어 있는지 살펴봐야 합니다. 프로젝트의 로컬 계약이 패키지의 기본 계약보다 우선합니다. 수정 후에는 정적 검사와 브라우저 검토로 서로 다른 항목을 확인합니다. 마크업이 유효해도 레이아웃이 잘못되거나, 상호작용에 접근성 문제가 있거나, 동작 스크립트가 빠져 있을 수 있습니다.

<GuideFigure name="ai" title="계약 검사와 브라우저 검토">

**소스와 렌더링 결과를 모두 확인하세요.** 설치된 계약이나 프로젝트에서 직접 관리하는 계약에 따라 마크업을 작성하세요. CLI는 읽을 수 있는 요소, 클래스, 속성을 검사하고, 브라우저에서는 레이아웃과 키보드 및 상태 동작을 확인할 수 있습니다. 어느 쪽에서든 문제가 발견되면 수정한 뒤 변경 사항을 반영하세요.

</GuideFigure>

## 스킬 \{#the-skill\}

`master-ui` 스킬은 이 라이브러리를 사용하는 프로젝트에서 작업하는 에이전트용입니다. 다음 명령으로 설치하세요.

```bash
npx skills add master-co/ui --skill master-ui
```

| 파일 | 내용 |
| --- | --- |
| `SKILL.md` | 프로젝트에서 라이브러리를 가져오는 방식과 직접 관리하는 항목을 확인하는 방법, 계약에 따른 마크업 작성 규칙, 라이브러리에 필요한 기능이 없을 때의 대응 방법, 검증 방법 |
| `references/choosing.md` | 후보가 여러 개일 때 용도에 맞는 컴포넌트를 고르는 기준. 페이지 위에 띄우는 요소, 메시지, 옵션 선택, 숫자, 탐색, 레코드 모음 |
| `references/customizing.md` | [사용자 지정 단계](/guide/customization)와 컴포넌트를 직접 관리하는 조건 |
| `references/frameworks.md` | [React, Svelte, Vue](/guide/frameworks)에서 마크업으로 유지되는 부분, 복사할 수 있는 컴포넌트가 마련된 패턴, 컴포넌트 작성 방법 |

스킬은 이미 Master UI를 가져오는 프로젝트에서 Master UI를 사용하도록 에이전트에 지시합니다. 다른 라이브러리를 사용하는 프로젝트에는 Master UI를 도입하지 않습니다.

## 사이트에서 공개하는 프로그램용 자료 \{#for-programs\}

사이트에서는 구조화된 데이터와 다른 환경에서도 사용할 수 있는 Markdown을 공개합니다. 컴포넌트의 Markdown은 계약에서 생성하며, 가이드, 레이아웃, 블록, 페이지는 작성된 원본 페이지에서 내보냅니다. 내보낸 자료에는 텍스트와 코드가 포함되며 사이트의 상호작용은 제공하지 않습니다.

| URL | 내용 |
| --- | --- |
| `https://ui.master.co/llms.txt` | 색인. Master UI 마크업 작성 규칙과 모든 페이지의 Markdown 링크 |
| `https://ui.master.co/<section>/<slug>.md` | `guide`, `components`, `blocks` 또는 `pages` 섹션에 속하는 모든 페이지의 Markdown. 컴포넌트 페이지는 계약을 바탕으로 작성되며 마크업, 클래스, 상태, 속성, 스크립트, 키보드, 플랫폼을 다룹니다. 컴포넌트 섹션에 속한 레이아웃은 작성된 원본 페이지를 유지하고 그 뒤에 계약을 덧붙입니다. |
| `https://ui.master.co/contracts.json` | 데이터 형식으로 제공되는 모든 계약 |
| `https://ui.master.co/contract.schema.json` | 모든 계약이 따르는 JSON Schema |
| `https://ui.master.co/theme.json` | 테마의 모든 디자인 토큰과 각 토큰의 값 |
| `https://ui.master.co/r/registry.json` | 프로젝트에 복사할 소스를 제공하는 [레지스트리](/guide/registry) |

셸을 사용할 수 없는 에이전트는 `llms.txt`에서 시작해 `https://ui.master.co/components/dialog.md`와 같은 관련 컴포넌트 페이지를 읽습니다. 공개 사이트의 문서는 사이트에 배포된 라이브러리 버전을 기준으로 하므로 프로젝트에 설치된 버전과 다를 수 있습니다. 패키지를 사용할 수 있다면 패키지의 `@master/ui/contracts.json`과 `@master/ui/theme.json`을 우선 사용하고, 프로젝트에 로컬 계약이 있다면 아래 CLI를 사용하세요.

## 계약 조회 \{#look-up-a-contract\}

[패키지를 설치한](/guide/installation) 뒤 프로젝트 루트에서 CLI를 실행하세요. CLI는 설치된 패키지와 프로젝트에서 계약을 읽습니다. 조회할 때는 설치되지 않은 명령이 프로젝트와 무관한 버전을 내려받지 않도록 하세요.

```bash
npx master-ui list             # every contract, one line each
npx master-ui contract dialog  # one contract as JSON
```

클래스 이름을 조회 이름으로 쓸 수 있으므로 `npx master-ui contract btn-primary`를 실행하면 버튼의 계약이 출력됩니다. `npx master-ui list --json`은 목록을 데이터 형식으로 출력합니다.

두 명령 모두 `master-ui.json`에 설정된 디렉터리(기본값은 `ui/`)와 추가 계약 경로를 읽습니다. 프로젝트가 [직접 관리하는](/guide/customization#own-a-component) 컴포넌트는 프로젝트에 복사한 계약을 기준으로 표시되며, [프로젝트에서 작성한 컴포넌트](/guide/contracts#your-own)는 라이브러리 컴포넌트와 함께 목록에 표시됩니다.

## 마크업 검사 \{#check-the-markup\}

`npx master-ui check` 명령은 마크업을 읽고 계약을 위반한 위치를 보고합니다. 예를 들어 다음 파일에는 오류 3개와 경고 1개가 있습니다.

```html name=page.html
<button type="button" class="btn-primary">Save changes</button>
<button type="button" class="btn btn-outline">Cancel</button>
<button type="button" class="btn btn-square">
  <svg aria-hidden="true" viewBox="0 0 16 16"><path d="M4 4l8 8M12 4l-8 8"/></svg>
</button>
<div class="dialog">
  <h2 class="dialog-title">Delete this project?</h2>
</div>
```

```bash
npx master-ui check page.html
```

```
page.html:1:1 error missing-base "btn-primary" modifies "btn": write class="btn btn-primary".
page.html:2:1 warning unknown-class "btn-outline" is not a class of btn. It has: btn, btn-primary, btn-quiet, btn-brand, btn-danger, btn-sm, btn-lg, btn-square, btn-pill, btn-group.
page.html:3:1 error label "btn-square" needs an accessible name: text of its own, aria-label, aria-labelledby, or a <label> that wraps or points at it.
page.html:6:1 error element "dialog" goes on <dialog>, not <div>.

1 files checked: 3 errors, 1 warnings.
```

각 줄에 위치, 심각도, 코드, 수정 방법이 표시되므로 에이전트는 마크업을 수정하고 문제가 더 이상 보고되지 않을 때까지 명령을 다시 실행할 수 있습니다. 모든 코드는 [계약](/guide/contracts#diagnostics) 문서에 나와 있습니다.

- **검사 경로.** 인수 없이 실행하면 작업 디렉터리 아래의 모든 `.html`, `.htm`, `.astro`, `.svelte`, `.vue`, `.jsx`, `.tsx`, `.mdx`, `.erb`, `.php`, `.njk`, `.liquid`, `.hbs` 파일을 검사합니다. `node_modules`와 빌드 출력물은 검사 대상에서 제외됩니다. 파일, 디렉터리 또는 글로브 패턴을 전달해 검사 범위를 좁히세요.
- **검사 범위의 한계.** 검사기는 브라우저를 실행하지 않고 태그, 클래스, 속성을 읽습니다. 표현식으로 정해지는 클래스나 컴포넌트의 루트 요소가 다른 파일에 있는 부분처럼 읽은 내용만으로 판단할 수 없는 항목은 보고하지 않습니다.
- **`--json`** 옵션은 결과를 데이터 형식으로 출력합니다. 파일 수와 문제가 발견된 파일별 진단이 포함되며, 각 진단에는 `code`, `severity`, `className`, `contract`, `message`, `line`, `column`이 들어 있습니다.
- **`--strict`** 옵션은 `unknown-class`를 오류로 보고합니다. 컴포넌트의 루트 클래스 이름에 하이픈을 붙인 문자열로 시작하면서 어느 계약에도 없는 클래스는 유틸리티일 수 있으므로 기본적으로 경고로 처리됩니다. 프로젝트에 Master CSS가 설치되어 있으면 검사기는 프리셋 유틸리티를 인식합니다. 프로젝트에서 정의한 클래스에 대한 진단도 검토하세요. 문제가 보고되지 않아도 모든 사용자 지정 유틸리티나 동적으로 계산되는 클래스가 검증된 것은 아닙니다.

이 명령은 오류를 발견하면 종료 코드 1을 반환합니다. CI 단계에서 이 명령을 그대로 실행하면 오류가 발견될 때 해당 단계가 실패합니다.

```json name=package.json
{
  "scripts": {
    "check:ui": "master-ui check --strict"
  }
}
```

프로그램에서 검사하려면 `@master/ui/check` 모듈을 사용하세요. 검사기가 읽는 데이터는 [계약](/guide/contracts) 문서에 설명되어 있습니다. 에이전트의 작업 완료 기준에 브라우저 검사를 포함하세요. 변경의 영향을 받는 키보드 조작, 상태, 좁은 화면에서의 레이아웃, 색상 모드를 테스트하고, 필요한 동작이 연결되어 있는지도 확인하세요.

## 에이전트에 전달할 지침 \{#agents-md\}

에이전트는 프로젝트 자체 지침을 먼저 따릅니다. 다음 내용을 `AGENTS.md` 또는 에이전트가 읽는 파일에 붙여 넣으세요.

```md name=AGENTS.md
## Master UI

This project builds its interface with Master UI: classes on native elements, each described by a contract.

- Read the contract before writing a component's markup: `npx master-ui contract <name>`, and `npx master-ui list` to find one. Do not write markup from memory.
- Never invent a Master UI component class. Use the installed or locally owned contract, and keep project-defined classes outside the library's class families.
- Mark a state with the attribute the contract lists (`disabled`, `aria-pressed="true"`, `open`). Never add a class for a state.
- A component is a class on a native element in any framework. Do not wrap one in a component to rename it. The patterns that hold state have a component to copy: `npx master-ui add` lists them, and `ui/` may already hold one.
- To change how something looks, take the lowest step that works: a utility on the element, a theme token, a public custom property, a theme file, and only then `npx master-ui own <name>`. A project rule may select a library class to set its documented custom properties; change its implementation through owned source.
- Run `npx master-ui check` after changing markup. Fix every error and read each warning. Check the affected interactions in a browser, including the keyboard, a narrow viewport and both color schemes.
```

## MCP \{#mcp\}

Master UI 패키지는 위에서 설명한 CLI와 계약 파일을 제공합니다. 에이전트가 Master CSS MCP 서버에도 연결되어 있다면 그 연결로 컴포넌트 계약을 조회하기 전에 사용 가능한 도구를 확인하세요. 사용할 수 있는 도구는 연결된 서버에 따라 달라집니다. 설치된 CLI를 사용하면 프로젝트에 실제로 적용되는 계약을 직접 읽을 수 있습니다.

## 채팅 샌드박스 또는 아티팩트에서 사용 \{#without-a-build\}

CSS를 컴파일하지 않는 채팅 아티팩트나 정적 HTML 프로토타입에서는 사이트에서 컴파일한 스타일시트를 연결하세요. 환경에서 기본 리셋을 제공하지 않는다면 사이트의 기본 리셋도 포함하세요.

```html
<link rel="stylesheet" href="https://ui.master.co/base.css">
<link rel="stylesheet" href="https://ui.master.co/standalone.css">

<button type="button" class="btn btn-primary">Save changes</button>
```

이 URL들은 현재 배포된 사이트의 파일을 가리키므로 일회성 프로토타입에 적합합니다. 지속적으로 관리하는 프로젝트에서는 [버전을 고정한 패키지에서 컴파일된 파일을 제공하고](/guide/installation#without-master-css) 같은 버전의 계약을 읽으세요. CSS를 불러와도 동작 스크립트는 연결되지 않습니다. 스크립트가 필요한 패턴에는 브라우저 모듈이나 프레임워크 컴포넌트가 필요합니다.

이 환경에서는 유틸리티를 사용할 수 없습니다. `flex` 또는 `gap-md` 같은 클래스는 Master CSS에서 생성해야 하므로 `style` 속성이나 짧은 스타일 블록에 CSS를 직접 작성해 페이지 레이아웃을 구성하세요. 테마의 디자인 토큰은 사용자 지정 속성이므로 이 환경에서도 사용할 수 있습니다. `color: var(--color-text-muted)` 선언은 테마에서 값을 읽습니다.
