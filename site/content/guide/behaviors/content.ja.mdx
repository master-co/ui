ほとんどのコンポーネントでは、スタイルを適用する要素に必要な動作が備わっているため、スクリプトは不要です。コンボボックス、カレンダーグリッド、スプリッターなど、一部のパターンには対応するネイティブ要素がありません。こうしたパターンでは、スタイルシートが ARIA 属性とネイティブ属性に応じて状態を表示し、ビヘイビアと呼ばれる参照実装のスクリプトが入力、フォーカス、選択を制御します。このガイドでは、ビヘイビアを適用し、値を読み取り、要素がページから取り除かれたときにリスナーを解除する方法を説明します。

## ビヘイビアとは \{#what-a-behavior-is\}

ビヘイビアは 1 ファイルで構成され、パターンと同名の関数を 1 つ持ちます。この関数はルート要素を受け取り、リスナー、オブザーバー、タイマーを停止するクリーンアップ関数を返します。クリーンアップを実行しても元のマークアップには戻りません。たとえばカレンダーでは、描画した月がそのまま残ります。標準の ES モジュールで、依存関係やフレームワークはなく、ビルドも不要です。

| ビヘイビアが行う処理 | ビヘイビアが行わない処理 |
| --- | --- |
| ARIA 属性とネイティブ属性（`aria-selected`、`aria-checked`、`aria-expanded`、`aria-activedescendant`、`aria-valuenow`、`hidden`、`tabindex`、`open`）や、入力欄の値の設定・解除 | スタイル、状態を示すクラス、サイズ、位置の設定 |
| フォーカスの移動と、プラットフォーム API（`showPopover()`、`showModal()`、`stepUp()`、`scrollIntoView()`）の呼び出し | プラットフォーム機能の再実装。ポップオーバーやダイアログを開く処理、ライトディスミス、モーダル内へのフォーカスの閉じ込め、Esc キーによるモーダルの終了 |
| イベントからしか得られない情報を、コントラクトで公開するカスタムプロパティ（`--menu-x`、`--splitter-size`）を通じて渡す | 要素の配置や制約の適用。どちらもスタイルシートがプロパティを読み取って行います。 |
| 表示月の各週のように、データをもとに繰り返す行をコントラクトのクラスで生成する | コントラクトの範囲外の読み書き。パーツの特定には、コントラクトで定義されたクラスとロールを使います。 |

同じコントラクトに従う別のスクリプトでも、スタイルシートは機能します。その場合も、属性、値、キーボード操作をコントラクトに合わせる必要があります。フレームワーク向けのコンポーネントも同じビヘイビアを適用し、共通のキー操作を利用します。

<GuideFigure name="behaviors" title="入力から状態表示まで">

**DOM 属性がビヘイビアと見た目をつなぎます。** リストボックスのアクティブな選択肢で Enter キーを押すと、ビヘイビアが `aria-checked="true"` を設定します。スタイルシートはその属性を参照してチェックマークを表示します。スクリプトが選択肢を選択し、CSS が選択状態を描画します。

## ビヘイビア一覧 \{#the-behaviors\}

各ビヘイビアは `@master/ui/behaviors/<name>.js` からインポートします。最後の列は[コントラクト](/guide/contracts)の `script` フィールドに対応します。`required` はパターンの動作にスクリプトが必要であることを示し、`optional` はマークアップだけで動作するパターンに、スクリプトで機能を追加できることを示します。

| パターン | インポート名 | スクリプトの動作 | スクリプトの要否 |
| --- | --- | --- | --- |
| [カレンダー](/components/calendar) | `calendar` | 表示月の各週を生成し、今日、選択した日付や期間、選択できない日付を示し、グリッド内の移動を処理 | 必須 |
| [コンボボックス](/components/combobox) | `combobox` | 入力に一致しない選択肢を非表示にし、アクティブな選択肢の移動とリストの開閉を処理し、選択した項目を入力欄に反映 | 必須 |
| [コマンドパレット](/components/command) | `command` | コマンドを絞り込み、アクティブな項目を移動し、Enter キーでその項目をクリックしてダイアログを閉じる。ページ内のどこからでもショートカットで開く | 必須 |
| [画像比較](/components/compare) | `compare` | スクロール駆動アニメーションに未対応のブラウザーで、範囲入力の値を `--compare-position` にコピー。対応ブラウザーでは変更なし | 必須 |
| [リストボックス](/components/listbox) | `listbox` | 矢印キーと文字入力でアクティブな選択肢を移動し、選択した項目にチェックを付ける。複数選択できるリストでは選択した複数の項目にチェックを付ける | 必須 |
| [メニュー](/components/menu) | `menu`, `contextMenu` | 矢印キーと文字入力で項目間のフォーカスを移動し、サブメニューの方向を指す矢印キーでサブメニューを開く。`contextMenu` はポインターの位置にメニューを開く | 任意 |
| [OTP](/components/otp) | `otp` | スロット間でフォーカスを移動し、貼り付けや自動入力で受け取ったコードを各スロットに振り分ける | 必須 |
| [スプリッター](/components/splitter) | `splitter` | ドラッグやキー操作でハンドルを動かすと、先頭ペインのサイズを `--splitter-size` と `aria-valuenow` に書き込む | 必須 |
| [ステッパー](/components/stepper) | `stepper` | 2 つのボタンで数値入力欄の `stepDown()` と `stepUp()` をそれぞれ呼び出し、上限または下限に達した側のボタンを無効にする | 必須 |
| [タブ](/components/tabs#tab-panels) | `tabs` | `role="tablist"` では、タブ順序に含めるタブを 1 つに絞り、矢印キーでタブを移動・選択し、選択中のタブのパネルを表示 | 任意 |
| [ツリー](/components/tree) | `tree` | ツリー全体を 1 つのタブストップにし、矢印キーで項目間の移動や折りたたみを行う | 任意 |
| [ホイール](/components/wheel) | `wheel` | 目印の位置で止まった選択肢に `aria-selected` を移し、フォーカス中の列をリストボックスと同じキーで操作できるようにする | 必須 |

## ビヘイビアを個別に適用する \{#attach-one\}

まず[スタイルシートを読み込み](/guide/installation)、コントラクトに従ってマークアップを記述します。ルート要素が生成された後にモジュールを実行し、ルートクラスが付いた要素を渡します。以下のようにパッケージ名だけでインポートするには、アプリケーションが npm モジュールを解決できる必要があります。ブラウザーでモジュールを直接読み込む場合は、解決可能な URL またはインポートマップが必要です。

```html
<div class="combobox">
  <div class="input-group">
    <input class="input-group-field" id="region" role="combobox" aria-expanded="false" aria-controls="region-list" aria-autocomplete="list" autocomplete="off" aria-label="Region">
    <button type="button" class="combobox-toggle" tabindex="-1" aria-label="Show regions"></button>
  </div>
  <div id="region-list" popover="manual" class="listbox" role="listbox" aria-label="Regions">
    <div class="listbox-option" role="option" id="region-hnd" data-value="hnd" aria-checked="false">Tokyo</div>
    <div class="listbox-option" role="option" id="region-sin" data-value="sin" aria-checked="false">Singapore</div>
    <div class="listbox-empty">No regions match.</div>
  </div>
</div>
```

```js name=app.js
import { combobox } from '@master/ui/behaviors/combobox.js'

const detach = combobox(document.querySelector('.combobox'))
```

「Tok」と入力して ArrowDown、Enter の順に押し、入力欄に Tokyo が表示され、`detach.value` が `hnd` になっていることを確認します。要素をページから取り除くときは `detach()` を呼び出します。同じルートに同じビヘイビアを再度適用すると、以前のインスタンスが解除されます。アプリケーションが追加したリスナーは、アプリケーション側で解除してください。

## すべてのビヘイビアを適用する \{#attach-all\}

`attach()` はルートクラスを使って各パターンを見つけ、対応するビヘイビアを適用します。検索範囲はドキュメント全体、または渡した要素とその配下です。戻り値は、適用したすべてのビヘイビアを解除する 1 つの関数です。

```js name=app.js
import { attach } from '@master/ui/behaviors'

const detach = attach()
```

個別のインポートに代えて使う場合は、以下を確認してください。

- 任意のビヘイビアも適用されます。すべての `menu` で矢印キーが使えるようになり、各 `tree` は 1 つのタブストップになり、`role="tablist"` である各 `tabs` ではパネルが切り替わります。プラットフォーム標準の動作を残したいパターンがある場合は、必要なビヘイビアを名前でインポートします。
- 一括適用ではオプションは渡されません。期間を選択できるカレンダーや、選択可能な最初と最後の日付を指定するカレンダーには、ビヘイビアを名前でインポートして適用します。
- コンテキストメニューの対象はページ側で決まるため、`attach()` の適用対象外です。`contextMenu(target, menu)` を呼び出してください。

ドキュメントの変更は監視しません。後から追加したマークアップには、その追加部分を対象に `attach(element)` を呼び出し、その呼び出しで返された解除関数も保持します。対応するルートを削除する前に、それぞれの解除関数を呼び出してください。

## フレームワークで使う \{#in-a-framework\}

React、Svelte、Vue 向けに、各パターンをプロジェクトにコピーして使えるコンポーネントを用意しています。コンポーネントはマークアップのレンダリング、ビヘイビアの適用、値の受け渡しを行います。一覧は [React、Svelte、Vue](/guide/frameworks) を参照してください。ここからは、自作のコンポーネントにビヘイビアを適用する方法を説明します。

以下のコード例は、ビヘイビアの適用と解除のみを示しています。各ルートの内側には、「[ビヘイビアを個別に適用する](#attach-one)」節のコンボボックスのマークアップをすべて配置してください。設定オプションが変わったら、ビヘイビアを適用し直します。アプリケーション側で値を扱う場合やオプションが変化する場合は、コピーしたフレームワーク用コンポーネントか、その[アダプターヘルパー](/guide/frameworks#your-own)を使う方法が適しています。

React では、`useEffect` のクリーンアップ関数として解除関数を返します。

```jsx name=Combobox.jsx
import { useEffect, useRef } from 'react'
import { combobox } from '@master/ui/behaviors/combobox.js'

export function Combobox({ children }) {
  const root = useRef(null)
  useEffect(() => combobox(root.current), [])
  return <div className="combobox" ref={root}>{children}</div>
}
```

Svelte では、ビヘイビアのシグネチャがアタッチメントと同じなので、`{@attach}` にそのまま渡せます。

```svelte name=Combobox.svelte
<script>
  import { combobox } from '@master/ui/behaviors/combobox.js'
</script>

<div class="combobox" {@attach combobox}>
  <!-- the field and the listbox -->
</div>
```

アクションはオブジェクトを返します。アタッチメントに未対応の Svelte では、`const action = (node) => ({ destroy: combobox(node) })` でビヘイビアをラップしてから `use:action` を使います。

Vue では、コンポーネントのマウント時に適用し、アンマウント時に解除します。

```vue name=Combobox.vue
<script setup>
import { onMounted, onUnmounted, ref } from 'vue'
import { combobox } from '@master/ui/behaviors/combobox.js'

const root = ref(null)
let detach

onMounted(() => { detach = combobox(root.value) })
onUnmounted(() => detach?.())
</script>

<template>
  <div class="combobox" ref="root"><slot /></div>
</template>
```

## オプション \{#options\}

以下のビヘイビアは、第 2 引数にオプションオブジェクトを受け取ります。たとえば `calendar(root, options)` のように指定します。

### カレンダー \{#calendar-options\}

- `value`：選択した日付を `YYYY-MM-DD` で指定するか、期間の開始日と終了日を指定します。
- `month`：最初に表示する月を `YYYY-MM` で指定します。
- `min`、`max`：選択できる最初の日付と最後の日付を指定します。
- `range`：2 つの日付と、その間のすべての日付を選択できるようにします。
- `weekStart`：先頭列の曜日を、日曜日の 0 から土曜日の 6 までの値で指定します。
- `locale`：表示名に使う BCP 47 言語タグを指定します。
- `disabled`：指定の日付が選択不可かどうかを返す関数を指定します。
- `draw`：[ビヘイビアに代わってグリッドをレンダリングする](#a-grid-of-your-own)関数を指定します。

### コンボボックス \{#combobox-options\}

`filter` の既定値は `true` です。ビヘイビアは、入力された文字列を含まない選択肢を非表示にします。[アプリケーションが一致する選択肢を用意する](#options-from-a-server)場合は、`false` に設定します。

### コマンドパレット \{#command-options\}

`shortcut` は、Command または Control と組み合わせてパレットを開閉するキーです。既定値は `'k'` です。ショートカットを無効にするには `false` に設定します。`filter` はコンボボックスと同じように動作します。

### OTP \{#otp-options\}

`pattern` は、各文字が一致する必要のある正規表現です。省略すると、ビヘイビアは先頭スロットの `pattern` 属性を参照します。その属性もなければ、数字のみを受け付けます。

### スプリッター \{#splitter-options\}

`step` は、矢印キーでハンドルを動かす量をパーセントポイント単位で指定します。既定値は 5 です。

## イベント \{#events\}

ビヘイビアは、ネイティブコントロールと同じように、バブリングする DOM イベントで変更を通知します。`addEventListener` でリッスンするか、フレームワークが提供するネイティブイベント用のバインディングを使います。

| ビヘイビア | イベント | 発火元 | 取得できる値 |
| --- | --- | --- | --- |
| `combobox` | 選択肢を選んだときに `input`、続いて `change` | 入力欄 | 入力欄の `value` が値 |
| `listbox` | `input`、続いて `change` | リストボックス | 各選択肢の `aria-checked="true"` を参照 |
| `stepper` | ボタン操作で数値が変わったときに `input`、続いて `change` | 入力欄 | 入力欄の `value` が値 |
| `splitter` | サイズが変わるたびに `input`。ドラッグが終わったとき、またはキー操作でハンドルが移動したときに `change` | ハンドル | `aria-valuenow` を参照 |
| `otp` | スクリプトが値を書き込んだスロットから `input`。すべてのスロットが埋まったときに `change` | input はスロット、change はルート | `detail.value`：コード |
| `calendar` | `change` | ルート | `detail.value`：日付を表す `YYYY-MM-DD`。期間の開始日と終了日が両方選ばれた場合は `[start, end]` |
| `wheel` | 列が別の選択肢の位置で止まったときに `change` | 列 | `detail.value`：選択肢の `data-value` またはテキスト。`detail.option`：要素 |
| `tree` | `role="treeitem"` を持つ末端の行が選択されたときに `change` | ルート | `detail.item`：行 |
| `tabs` | 別のタブが選択されたときに `change` | タブリスト | `detail.value`：タブの `data-value` またはテキスト。`detail.tab`：要素 |

OTP 入力欄、カレンダー、ホイール、ツリー、タブリストでは、値を 1 つのネイティブコントロールに保持しないため、`change` は `CustomEvent` です。OTP 入力欄の各スロットはネイティブの入力要素なので、スロット自身の `change` もルートを通ってバブリングし、そのイベントには `detail` がありません。コマンドパレット、メニュー、比較は独自のイベントを発火しません。コマンドは選択肢の `click` で実行され、このイベントは Enter キーでも発火します。メニューの項目にはネイティブのボタン、リンク、入力要素を使います。

```js name=app.js
import { calendar } from '@master/ui/behaviors/calendar.js'

const root = document.querySelector('.calendar')
const detach = calendar(root, { value: '2026-11-13', min: '2026-11-01' })

root.addEventListener('change', (event) => {
  console.log(event.detail.value)
})
```

## 値の取得と設定 \{#the-value\}

パターンの値を 1 つのネイティブコントロールで保持できない場合、ビヘイビアが返す関数に `value` が備わっています。これを読み取ると現在の選択を取得できます。外部から値を設定すると選択状態が更新されます。ネイティブの入力要素の `value` を設定した場合と同じように、イベントは発火しません。

| ビヘイビア | `value` |
| --- | --- |
| `calendar` | 日付は `YYYY-MM-DD`、期間は `[start, end]`。終了日を選ぶまでは終了日の値は `null`、選択がなければ `null`。設定すると、新しい値に対応する月を表示 |
| `combobox` | 選択した項目が表す値。入力欄のテキストに対応する項目が選ばれていない間は `null`。設定すると、その項目のテキストを入力欄に反映 |
| `listbox` | 選択した項目が表す値。選択がなければ `null`。リストボックスに `aria-multiselectable="true"` がある場合は、選択した項目の値のリスト |
| `otp` | 各スロットに入っている文字を順に並べたもの |
| `splitter` | 先頭ペインのサイズ（パーセント） |
| `stepper` | 入力欄の数値。空欄の場合は `null` |
| `compare` | 範囲入力の数値 |
| `tabs`, `tree` | 選択したタブまたは行が表す値。選択がなければ `null` |
| `wheel` | 各列で選択した項目が表す値を列順に並べたもの |

選択肢、タブ、行が表す値は、その要素の `data-value` です。指定がなければ、要素のテキストが値になります。表示テキストとアプリケーションが保存する値が異なる場合は、`data-value` を指定します。たとえば、Tokyo と表示する選択肢には `data-value="hnd"` を指定します。

```js name=app.js
import { combobox } from '@master/ui/behaviors/combobox.js'

const region = combobox(document.querySelector('.combobox'))
region.value = 'hnd'        // checks the option, writes "Tokyo" into the field
console.log(region.value)   // "hnd"
```

スクリプトが入力欄に値を書き込むときは、要素のプロトタイプにあるセッターを使います。React は入力要素自体に `value` プロパティを定義してプロトタイプの定義を隠し、自身による書き込みを追跡します。また、、すでに把握している値に対する `input` イベントを無視します。プロトタイプのセッターを使えば、選択した値も文字入力と同じように `onChange` に届きます。

## サーバーから選択肢を取得する \{#options-from-a-server\}

既定では、コンボボックスとコマンドパレットはマークアップ内の選択肢を絞り込みます。サーバーへの問い合わせやインデックス検索でページ側が一致する項目を決める場合は、`filter: false` を渡します。この設定ではスクリプトによる非表示処理が無効になり、ページ側が入力に応じて選択肢のマークアップを生成します。リストを開いている間に選択肢が届くと、アクティブな項目が設定し直されるため、引き続き <kbd>Enter</kbd> で最初に一致した項目を選択できます。

```js name=app.js
import { combobox } from '@master/ui/behaviors/combobox.js'

const root = document.querySelector('.combobox')
const list = root.querySelector('[role="listbox"]')
const selection = combobox(root, { filter: false })
let request = 0

root.querySelector('[role="combobox"]').addEventListener('input', async (event) => {
  const current = ++request
  if (selection.value !== null) return // Choosing an option also dispatches input.
  const regions = await search(event.target.value)
  if (current !== request || !root.isConnected) return
  list.replaceChildren(...regions.map(option))
})
```

ここでは、`search(text)` がアプリケーションの非同期検索関数で、`option(region)` は `listbox-option`、`role="option"`、一意の ID、`data-value`、`aria-checked="false"` を持つ要素を 1 つ生成します。サーバーから受け取ったラベルはテキストとして扱い、HTML として挿入しないでください。リクエストのカウンターにより、古い応答が新しい結果を上書きするのを防ぎます。読み込み中、結果がない場合、エラー時の表示はアプリケーション側で用意してください。

## カレンダーのグリッドを自前で描画する \{#a-grid-of-your-own\}

要素を生成するビヘイビアはカレンダーだけで、表示月の各週を生成します。テンプレートやサーバーでレンダリングするフレームワークなど、レンダラー側で週の要素を生成する場合は、`draw` を渡します。この場合、スクリプトによる要素の生成は行われません。表示すべき月とグリッド内の月が異なるたびに、スクリプトは表示すべき月を `YYYY-MM` として `draw` に渡します。日付の要素がそろうと、今日、選択した日付、選択できない日付、タブ順序に含める日付をそれぞれ示します。

`calendarMonth()` は、スクリプトが描画に使う月のデータを返します。データには月のタイトル、7 つの曜日名、各週が含まれます。各日付は `calendar-day` ボタンで表し、その `value` に日付を指定します。これにより、スクリプトが自分で生成していない日付も識別できます。`value` を指定し、期間の両端を扱う場合は `range` も指定すると、各日の描画に使う `selected`、タブ順序に含める 1 日を示す `tab`、期間内の日付のクラスを示す `range` も得られます。レンダラーがこれらを描画すれば、スクリプトの実行前から最初の HTML に選択済みの日付が反映されます。

```js
import { calendarMonth } from '@master/ui/behaviors/calendar.js'

const month = calendarMonth('2026-11', {
  value: '2026-11-13',
  locale: 'en-GB'
})

const chosen = month.weeks.flat().find(day => day.selected)
console.log(chosen.date) // "2026-11-13"
console.log(chosen.tab)  // true
```

レンダラーは、そのデータからコントラクトに沿ったマークアップを生成します。

| データ | レンダリング結果 |
| --- | --- |
| `title` | `calendar-title` のテキスト |
| `weekdays` | 略称をテキスト、正式名を `aria-label` に指定した `calendar-weekday` の列見出し |
| `weeks` | 週ごとに `calendar-week` の行を 1 つ |
| 各日付の `date`、`text`、`label` | ボタンの `value`、テキスト、`aria-label` |
| `selected`, `tab` | 初期状態で選択された日付には `aria-selected` と `tabindex="0"`、それ以外の日付には `-1` |
| `outside`, `range` | 必要に応じて `calendar-day-outside` と、返された期間用のクラス名 |

グリッドの生成後、同じ初期値とロケールで `calendar(root, { value, locale, draw })` を適用します。`draw(month)` コールバックで別の月の行をレンダリングすると、行がそろった時点でビヘイビアが現在の選択状態とフォーカスを反映します。行を置き換えるときは、タイトル、曜日の見出し、グリッドのラベル付けを維持してください。

React、Svelte、Vue 向けの[カレンダーコンポーネント](/guide/frameworks)はこの方法で実装されているため、最初の HTML に月のグリッドが含まれます。

## キー操作 \{#the-keys\}

コントラクトの `keyboard` リストには、パターンに組み込まれているキー操作が定義されています。`npx master-ui contract combobox` で確認できます。

| キー | 操作 |
| --- | --- |
| ArrowDown、ArrowUp | リストを開き、アクティブな選択肢を移動。先頭と末尾を越えると反対側に移動 |
| Home、End | リストが開いている間、先頭または末尾の選択肢に移動 |
| Enter | アクティブな選択肢を選び、リストを閉じる |
| Escape | 入力欄のテキストを残したままリストを閉じる |
| 文字入力 | 選択肢を絞り込み、最初に一致した項目をアクティブにしてリストを開く |

ビヘイビアがキー操作を処理する場合は `preventDefault()` を呼び出します。処理対象外のキーは通常どおり動作するため、アクティブな選択肢がないコンボボックスで Enter キーを押すと、フォームが送信されます。非表示の項目や `disabled` または `aria-disabled="true"` が設定された項目はスキップします。左右の矢印キーはテキストの方向に従います。

## ビヘイビアをプロジェクトで管理する \{#own-a-behavior\}

パッケージ付属のビヘイビアがアプリケーションの要件を満たす間は、引き続きパッケージからインポートすれば、更新時に修正も取り込めます。キー操作や選択時の動作を変える必要がある場合は、ソースをコピーしてプロジェクト側で実装を管理します。

```bash
npx master-ui own combobox
```

`own` は、コンポーネントのスタイルシート、コントラクト、ビヘイビアをプロジェクトにコピーします。既定のコピー先は、それぞれ `ui/combobox.css`、`ui/combobox.json`、`ui/combobox.js` です。以降はスクリプトをプロジェクト側で管理し、コピー先からインポートします。コンポーネントの管理に関するその他の手順は、[カスタマイズ](/guide/customization#own-a-component)を参照してください。

コンボボックス、コマンドパレット、リストボックス、メニューのビヘイビアは、`./internal.js` から共通ヘルパーをインポートします。`own` はそのファイルも同じディレクトリーにコピーします。

編集後も、実装とコントラクトが一致するようにしてください。スクリプトが更新する属性はスタイルシートが参照する属性とそろえ、`keyboard` リストは変更後のキー操作に合わせて更新します。

## スクリプトなしで使う \{#without-any-script\}

一覧に載っているのは、パッケージに含まれるビヘイビアです。アプリケーション独自の操作にも JavaScript が必要になる場合があります。ネイティブコントロールは、ブラウザーが対応している場合に標準の操作を提供します。機能拡張のフォールバックについては、[ブラウザーサポートガイド](/guide/browser-support)を参照してください。表にあるパターンの一部は、ビヘイビアを適用せずに使うこともできます。

- **タブ**にはリンクやラジオボタンを使えます。任意のビヘイビアは、選択したタブに対応するパネルを表示するタブリスト向けです。
- **ツリー**は、`<summary>`を行とする`<details>`要素を入れ子にしたものです。枝の開閉は要素自体が行い、Tab キーで各行にフォーカスできます。
- **メニュー**は、ボタンやリンクを含むポップオーバーです。ブラウザーが開閉を処理し、Tab キーで項目間を移動し、Escape キーでボタンにフォーカスが戻ります。`role="menu"`を付ける場合は、そのロールが矢印キーでの操作を前提とするため、必ずビヘイビアも追加します。

一部のコントラクトでは、スクリプトを`optional`と記載し、ビヘイビア名を指定していません。チェックボックスの`indeterminate`状態など、HTML 属性では指定できない機能を 1〜2 行のスクリプトで補います。スクリプトがなくてもコンポーネントは動作します。
