대부분의 컴포넌트는 스타일을 적용하는 요소에 이미 필요한 동작이 있어 스크립트가 필요하지 않습니다. 콤보박스, 달력 그리드, 분할 조절기처럼 대응하는 네이티브 요소가 없는 패턴도 있습니다. 이런 패턴에서는 스타일시트가 ARIA 속성과 네이티브 속성을 읽어 상태를 표시하고, 참조 스크립트인 동작이 입력, 포커스, 선택을 조율합니다. 이 가이드에서는 요소에 동작을 연결하고, 값을 읽고, 요소가 페이지에서 제거될 때 리스너를 해제하는 방법을 설명합니다.

## 동작의 정의 \{#what-a-behavior-is\}

동작은 패턴 이름을 딴 함수 하나를 담은 파일입니다. 이 함수는 루트 요소를 받아 리스너를 해제하고 옵저버와 타이머를 중지하는 정리 함수를 반환합니다. 정리 함수는 원래 마크업을 복원하지 않습니다. 예를 들어 달력에는 이미 그려진 월이 그대로 남습니다. 동작은 일반 ES 모듈이며 종속성, 프레임워크, 빌드 단계가 필요하지 않습니다.

| 동작이 하는 일 | 동작이 하지 않는 일 |
| --- | --- |
| ARIA 속성과 네이티브 속성을 설정하고 제거합니다. `aria-selected`, `aria-checked`, `aria-expanded`, `aria-activedescendant`, `aria-valuenow`, `hidden`, `tabindex`, `open`, 필드 값이 이에 해당합니다. | 스타일, 상태를 나타내는 클래스, 크기 또는 위치를 설정합니다. |
| 포커스를 이동하고 플랫폼 API인 `showPopover()`, `showModal()`, `stepUp()`, `scrollIntoView()`를 호출합니다. | 팝오버나 대화 상자 열기, 바깥을 눌러 닫기, 모달의 포커스 가두기와 Escape 키 처리 등 플랫폼 기능을 다시 구현합니다. |
| 이벤트에서만 알 수 있는 정보를 계약에 명시된 `--menu-x`, `--splitter-size` 등의 사용자 지정 속성을 통해 전달합니다. | 요소의 위치를 지정하거나 제약을 적용합니다. 두 작업 모두 스타일시트가 속성을 읽어 처리합니다. |
| 한 달의 각 주처럼 데이터에 따라 반복되는 행을 계약에 명시된 클래스로 생성합니다. | 계약 범위 밖의 정보를 읽거나 씁니다. 동작은 계약에 명시된 클래스와 역할로 구성 요소를 찾습니다. |

같은 계약을 따르는 다른 스크립트도 스타일시트와 함께 사용할 수 있습니다. 속성, 값, 키보드 동작은 계약과 일치해야 합니다. 프레임워크용 컴포넌트는 키 처리를 다시 구현하는 대신 이 동작을 그대로 연결합니다.

<GuideFigure name="behaviors" title="입력에서 상태 표시까지">

**DOM 속성이 동작과 화면 표시를 연결합니다.** 목록 상자에서 옵션이 활성화된 상태로 Enter 키를 누르면 동작이 `aria-checked="true"`를 설정합니다. 스타일시트는 이 속성을 읽어 체크 표시를 보여 줍니다. 스크립트가 옵션을 선택하고 CSS가 선택 상태를 표시합니다.

</GuideFigure>

## 동작 목록 \{#the-behaviors\}

각 동작은 `@master/ui/behaviors/<name>.js`에서 가져옵니다. 마지막 열은 [계약](/guide/contracts)의 `script` 필드입니다. `required`는 스크립트가 없으면 패턴이 작동하지 않는다는 뜻이고, `optional`은 이미 작동하는 마크업에 스크립트가 기능을 더한다는 뜻입니다.

| 패턴 | 가져오기 | 스크립트 기능 | 스크립트 |
| --- | --- | --- | --- |
| [달력](/components/calendar) | `calendar` | 표시할 월의 주별 행을 생성하고, 오늘과 선택한 날짜 또는 기간, 선택할 수 없는 날짜를 표시하며, 그리드 안에서 이동할 수 있게 합니다. | 필수 |
| [콤보박스](/components/combobox) | `combobox` | 입력한 내용과 일치하지 않는 옵션을 숨기고, 활성 옵션을 바꾸고, 목록을 열고 닫으며, 선택한 옵션을 필드에 입력합니다. | 필수 |
| [명령 팔레트](/components/command) | `command` | 명령을 필터링하고 활성 옵션을 바꿉니다. Enter 키를 누르면 활성 옵션을 클릭하고 대화 상자를 닫습니다. 어디서든 단축키로 대화 상자를 열 수 있습니다. | 필수 |
| [이미지 비교](/components/compare) | `compare` | 브라우저가 스크롤 기반 애니메이션을 지원하지 않으면 범위 입력 요소의 값을 `--compare-position`에 복사합니다. 지원하는 경우에는 아무것도 변경하지 않습니다. | 필수 |
| [목록 상자](/components/listbox) | `listbox` | 방향키나 문자 입력으로 활성 옵션을 바꾸고, 선택한 옵션에 체크 표시를 합니다. 다중 선택 목록에서는 여러 옵션에 체크 표시를 할 수 있습니다. | 필수 |
| [메뉴](/components/menu) | `menu`, `contextMenu` | 방향키나 문자 입력으로 항목 사이에서 포커스를 이동하고, 하위 메뉴가 있는 방향의 방향키로 하위 메뉴를 엽니다. `contextMenu`는 포인터 위치에서 메뉴를 엽니다. | 선택 사항 |
| [OTP](/components/otp) | `otp` | 입력 칸 사이에서 포커스를 이동하고, 붙여 넣거나 자동으로 채운 코드를 각 칸에 나누어 넣습니다. | 필수 |
| [분할 조절기](/components/splitter) | `splitter` | 손잡이를 드래그하거나 키로 움직일 때 첫 번째 패널의 크기를 `--splitter-size`와 `aria-valuenow`에 기록합니다. | 필수 |
| [스테퍼](/components/stepper) | `stepper` | 두 버튼이 숫자 입력 필드의 `stepDown()`과 `stepUp()`을 각각 호출하게 하고, 필드 값이 최솟값이나 최댓값에 도달하면 해당 버튼을 비활성화합니다. | 필수 |
| [탭](/components/tabs#tab-panels) | `tabs` | `role="tablist"`에서 탭 하나만 Tab 키 이동 순서에 두고, 방향키로 탭을 이동하고 선택하며, 선택한 탭의 패널을 표시합니다. | 선택 사항 |
| [트리](/components/tree) | `tree` | 트리 전체를 Tab 키 이동 순서에서 한 지점으로 취급하고, 방향키로 항목을 탐색하고 접을 수 있게 합니다. | 선택 사항 |
| [휠](/components/wheel) | `wheel` | `aria-selected`를 표시 아래에 멈춘 옵션으로 옮기고, 포커스가 있는 열에 목록 상자와 같은 키보드 동작을 적용합니다. | 필수 |

## 동작 하나 연결 \{#attach-one\}

먼저 [스타일시트를 불러온](/guide/installation) 다음 계약에 맞게 마크업을 작성하세요. 루트 요소가 생성된 뒤 모듈을 실행하고 루트 클래스가 지정된 요소를 전달하세요. 아래 예제처럼 패키지 이름만으로 가져오려면 애플리케이션이 npm 모듈을 해석할 수 있어야 합니다. 브라우저에서 모듈을 직접 실행하려면 브라우저가 해석할 수 있는 URL이나 임포트 맵이 필요합니다.

```html
<div class="combobox">
  <div class="input-group">
    <input class="input-group-field" id="region" role="combobox" aria-expanded="false" aria-controls="region-list" aria-autocomplete="list" autocomplete="off" aria-label="Region">
    <button type="button" class="combobox-toggle" tabindex="-1" aria-label="Show regions"></button>
  </div>
  <div id="region-list" popover="manual" class="listbox" role="listbox" aria-label="Regions">
    <div class="listbox-option" role="option" id="region-hnd" data-value="hnd" aria-checked="false">Tokyo</div>
    <div class="listbox-option" role="option" id="region-sin" data-value="sin" aria-checked="false">Singapore</div>
    <div class="listbox-empty">No regions match.</div>
  </div>
</div>
```

```js name=app.js
import { combobox } from '@master/ui/behaviors/combobox.js'

const detach = combobox(document.querySelector('.combobox'))
```

“Tok”을 입력한 뒤 ArrowDown과 Enter를 차례로 누르세요. 필드에 Tokyo가 표시되고 `detach.value` 값이 `hnd`인지 확인하세요. 요소가 페이지에서 제거될 때 `detach()`를 호출하세요. 같은 루트에 동일한 동작을 두 번 연결하면 이전 인스턴스의 연결이 해제되지만, 애플리케이션이 추가한 리스너는 그대로 남습니다.

## 모든 동작 연결 \{#attach-all\}

`attach()`는 루트 클래스로 각 패턴을 찾아 해당 동작을 연결합니다. 요소를 전달하면 그 요소 자체와 하위 요소를 검색하고, 전달하지 않으면 문서 전체를 검색합니다. 연결한 모든 동작을 한꺼번에 해제하는 함수 하나를 반환합니다.

```js name=app.js
import { attach } from '@master/ui/behaviors'

const detach = attach()
```

동작을 한꺼번에 연결하기 전에 다음 사항을 확인합니다.

- 선택 사항인 동작도 연결합니다. 모든 `menu`에서 방향키를 사용할 수 있고, 각 `tree`는 Tab 키로 이동할 때 포커스 지점 하나로 취급되며, `role="tablist"`에 해당하는 모든 `tabs`에서 패널을 전환할 수 있습니다. 특정 패턴에 플랫폼 기본 동작을 유지하려면 필요한 동작만 이름으로 가져오세요.
- 옵션은 전달하지 않습니다. 날짜 범위를 선택하거나 선택 가능한 첫날과 마지막 날을 지정하는 달력은 동작을 이름으로 가져와 연결하세요.
- 컨텍스트 메뉴의 대상은 페이지에서만 알 수 있으므로 `attach()`는 컨텍스트 메뉴를 연결하지 않습니다. `contextMenu(target, menu)`를 호출하세요.

문서의 변경 사항은 감시하지 않습니다. 나중에 마크업을 추가했다면 추가한 요소에 `attach(element)`를 호출하고, 그 호출에서 반환된 정리 함수도 보관하세요. 각 루트를 제거하기 전에 해당 정리 함수를 호출하세요.

## 프레임워크에서의 동작 연결 \{#in-a-framework\}

React, Svelte, Vue에서는 패턴별 컴포넌트를 프로젝트에 복사해 사용할 수 있습니다. 각 컴포넌트는 마크업을 렌더링하고 동작을 연결하며 값을 주고받습니다. 컴포넌트 목록은 [React, Svelte, Vue](/guide/frameworks)에서 확인할 수 있습니다. 이 절의 나머지 부분에서는 직접 작성한 컴포넌트에 동작을 연결하는 방법을 다룹니다.

아래 코드 예제는 동작을 연결하고 해제하는 방법만 보여 줍니다. 각 루트 안에 [동작 하나 연결](#attach-one)에 나온 콤보박스 마크업 전체를 넣으세요. 설정 옵션이 바뀌면 동작을 다시 연결하세요. 애플리케이션의 값을 연동하거나 옵션이 바뀌는 경우에는 복사한 프레임워크 컴포넌트나 해당 컴포넌트의 [어댑터 헬퍼](/guide/frameworks#your-own)를 사용하는 편이 좋습니다.

React에서는 `useEffect`가 연결 해제 함수를 정리 함수로 받습니다.

```jsx name=Combobox.jsx
import { useEffect, useRef } from 'react'
import { combobox } from '@master/ui/behaviors/combobox.js'

export function Combobox({ children }) {
  const root = useRef(null)
  useEffect(() => combobox(root.current), [])
  return <div className="combobox" ref={root}>{children}</div>
}
```

Svelte에서는 동작의 함수 시그니처가 어태치먼트와 같으므로 `{@attach}`에 그대로 전달할 수 있습니다.

```svelte name=Combobox.svelte
<script>
  import { combobox } from '@master/ui/behaviors/combobox.js'
</script>

<div class="combobox" {@attach combobox}>
  <!-- the field and the listbox -->
</div>
```

액션은 객체를 반환합니다. 어태치먼트를 지원하지 않는 Svelte 버전에서는 `const action = (node) => ({ destroy: combobox(node) })`로 동작을 감싼 다음 `use:action`으로 연결합니다.

Vue에서는 컴포넌트가 마운트될 때 동작을 연결하고 언마운트될 때 연결을 해제하세요.

```vue name=Combobox.vue
<script setup>
import { onMounted, onUnmounted, ref } from 'vue'
import { combobox } from '@master/ui/behaviors/combobox.js'

const root = ref(null)
let detach

onMounted(() => { detach = combobox(root.value) })
onUnmounted(() => detach?.())
</script>

<template>
  <div class="combobox" ref="root"><slot /></div>
</template>
```

## 옵션 \{#options\}

아래 동작은 두 번째 인수로 옵션 객체를 받습니다. 호출 예시는 `calendar(root, options)`입니다.

### 달력 \{#calendar-options\}

- `value`: 선택한 날짜를 나타내는 `YYYY-MM-DD` 값 또는 선택 범위의 시작일과 종료일.
- `month`: 처음 표시할 월을 나타내는 `YYYY-MM` 값.
- `min`, `max`: 선택 가능한 첫날과 마지막 날.
- `range`: 두 날짜를 선택하면 그 사이의 날짜도 모두 선택하는 옵션.
- `weekStart`: 첫 번째 열에 표시할 요일. 일요일은 0, 토요일은 6입니다.
- `locale`: 표시할 이름의 언어를 지정하는 BCP 47 언어 태그.
- `disabled`: 해당 날짜를 선택할 수 없는지 여부를 반환하는 함수.
- `draw`: [동작을 대신해 그리드를 렌더링하는](#a-grid-of-your-own) 함수.

### 콤보박스 \{#combobox-options\}

`filter`의 기본값은 `true`입니다. 이때 동작은 입력한 텍스트를 포함하지 않는 옵션을 숨깁니다. [애플리케이션에서 일치하는 옵션을 제공하는 경우](#options-from-a-server)에는 `false`로 설정하세요.

### 명령 팔레트 \{#command-options\}

`shortcut`은 Command 또는 Control과 함께 눌러 팔레트를 열고 닫는 키입니다. 기본값은 `'k'`이며, 단축키를 비활성화하려면 `false`로 설정하세요. `filter`는 콤보박스와 동일하게 동작합니다.

### OTP \{#otp-options\}

`pattern`은 각 문자가 일치해야 하는 정규 표현식입니다. 생략하면 동작이 첫 번째 슬롯의 `pattern` 속성을 읽습니다. 해당 속성도 없으면 숫자만 허용합니다.

### 분할 조절기 \{#splitter-options\}

`step`은 방향키를 한 번 누를 때 손잡이가 얼마나 이동하는지 퍼센트포인트 단위로 지정합니다. 기본값은 5입니다.

## 이벤트 \{#events\}

동작은 네이티브 컨트롤과 마찬가지로 버블링되는 DOM 이벤트로 변경 사항을 알립니다. `addEventListener` 또는 프레임워크가 제공하는 네이티브 이벤트 바인딩으로 이벤트를 수신하세요.

| 동작 | 이벤트 | 이벤트 발생 요소 | 전달 값 |
| --- | --- | --- | --- |
| `combobox` | 옵션을 선택하면 `input`, 이어서 `change` | 필드 | 필드의 `value` 값 |
| `listbox` | `input`, 이어서 `change` | 목록 상자 | 목록 상자의 각 옵션에서 `aria-checked="true"`를 읽으세요 |
| `stepper` | 버튼으로 숫자가 바뀌면 `input`, 이어서 `change` | 필드 | 필드의 `value` 값 |
| `splitter` | 크기가 바뀔 때마다 `input`, 드래그가 끝나거나 키로 손잡이를 움직이면 `change` | 손잡이 | `aria-valuenow`를 읽으세요 |
| `otp` | 스크립트가 값을 쓴 슬롯에서 `input`, 모든 슬롯이 채워지면 `change` | 각각 슬롯과 루트 | `detail.value`: 코드 |
| `calendar` | `change` | 루트 | `detail.value`: 날짜를 나타내는 `YYYY-MM-DD` 값 또는 범위의 시작일과 종료일을 모두 선택했을 때의 `[start, end]` 값 |
| `wheel` | 열이 다른 옵션 위치에서 멈추면 `change` | 열 | `detail.value`: 옵션의 `data-value` 값 또는 옵션 텍스트, `detail.option`: 옵션 요소 |
| `tree` | `role="treeitem"`이 있고 분기 노드가 아닌 행을 선택할 때 `change` | 루트 요소 | `detail.item`: 해당 행 |
| `tabs` | 다른 탭을 선택할 때 `change` | 탭 목록 | `detail.value`: 탭의 `data-value` 또는 탭의 텍스트, `detail.tab`: 해당 요소 |

OTP 필드, 달력, 휠, 트리, 탭 목록의 `change`는 `CustomEvent`입니다. 값을 보유하는 단일 네이티브 컨트롤이 없기 때문입니다. OTP 필드의 각 슬롯은 네이티브 입력 요소이므로, 슬롯 자체의 `change`도 `detail` 없이 루트를 거쳐 버블링됩니다. 명령 팔레트, 메뉴, 비교 컴포넌트는 자체 이벤트를 발생시키지 않습니다. 명령은 해당 옵션의 `click` 이벤트로 실행되며, Enter 키도 같은 이벤트를 발생시킵니다. 메뉴 항목은 네이티브 버튼, 링크, 입력 요소입니다.

```js name=app.js
import { calendar } from '@master/ui/behaviors/calendar.js'

const root = document.querySelector('.calendar')
const detach = calendar(root, { value: '2026-11-13', min: '2026-11-01' })

root.addEventListener('change', (event) => {
  console.log(event.detail.value)
})
```

## 값 \{#the-value\}

패턴의 값을 단일 네이티브 컨트롤이 보유하지 않는 경우, 동작이 반환하는 함수에 `value`가 있습니다. 이 속성을 읽으면 현재 선택된 값을 확인할 수 있습니다. 외부에서 값을 선택하려면 이 속성을 설정하세요. 네이티브 입력 요소의 `value`를 설정할 때와 마찬가지로 선택 상태만 표시되고 이벤트는 발생하지 않습니다.

| 동작 | `value` |
| --- | --- |
| `calendar` | 날짜는 `YYYY-MM-DD`, 범위는 `[start, end]`입니다. 종료 날짜는 선택하기 전까지 `null`이며, 선택한 값이 없으면 `null`입니다. 값을 설정하면 새 값에 해당하는 달을 표시합니다. |
| `combobox` | 선택한 옵션이 나타내는 값입니다. 필드에 텍스트가 있고 그에 해당하는 옵션을 선택하지 않은 상태에서는 `null`입니다. 값을 설정하면 옵션의 텍스트가 필드에 입력됩니다. |
| `listbox` | 선택한 옵션이 나타내는 값입니다. 선택 항목이 없으면 `null`입니다. 목록 상자에 `aria-multiselectable="true"`가 설정되어 있으면 선택한 옵션의 값 목록입니다. |
| `otp` | 각 슬롯에 입력된 문자를 슬롯 순서대로 나열한 값 |
| `splitter` | 첫 번째 패널의 크기(%) |
| `stepper` | 필드의 숫자 값입니다. 필드가 비어 있으면 `null`입니다. |
| `compare` | 범위 입력 요소의 숫자 값 |
| `tabs`, `tree` | 선택한 탭이나 행이 나타내는 값입니다. 선택 항목이 없으면 `null`입니다. |
| `wheel` | 각 열에서 선택한 옵션이 나타내는 값을 열 순서대로 나열한 목록 |

옵션, 탭, 행은 각자의 `data-value` 속성값을 사용하며, 이 속성이 없으면 텍스트를 값으로 사용합니다. 표시 텍스트와 애플리케이션에 저장하는 값이 다르면 `data-value` 속성을 지정합니다. 예를 들어 화면에 Tokyo로 표시되는 옵션에는 `data-value="hnd"`를 지정합니다.

```js name=app.js
import { combobox } from '@master/ui/behaviors/combobox.js'

const region = combobox(document.querySelector('.combobox'))
region.value = 'hnd'        // checks the option, writes "Tokyo" into the field
console.log(region.value)   // "hnd"
```

스크립트가 필드에 값을 쓸 때는 요소의 프로토타입에 정의된 세터를 사용합니다. React는 자신이 쓴 값을 추적하기 위해 입력 요소에 자체 `value`를 정의하고, 이미 확인한 값에 대해서는 `input` 이벤트를 무시합니다. 프로토타입의 세터로 값을 쓰면 사용자가 직접 입력했을 때처럼 선택한 값이 `onChange`에 전달됩니다.

## 서버에서 가져온 옵션 \{#options-from-a-server\}

기본적으로 콤보박스와 명령 팔레트는 마크업에 있는 옵션을 필터링합니다. 서버에 질의하거나 색인을 검색해 페이지에서 일치 항목을 결정한다면 `filter: false`를 전달하세요. 스크립트는 옵션을 숨기지 않으며, 사용자가 입력하는 동안 페이지에서 옵션을 렌더링합니다. 목록이 열린 상태에서 새 옵션이 도착하면 활성 옵션을 다시 지정하므로, <kbd>Enter</kbd> 키를 누르면 여전히 첫 번째 일치 항목이 선택됩니다.

```js name=app.js
import { combobox } from '@master/ui/behaviors/combobox.js'

const root = document.querySelector('.combobox')
const list = root.querySelector('[role="listbox"]')
const selection = combobox(root, { filter: false })
let request = 0

root.querySelector('[role="combobox"]').addEventListener('input', async (event) => {
  const current = ++request
  if (selection.value !== null) return // Choosing an option also dispatches input.
  const regions = await search(event.target.value)
  if (current !== request || !root.isConnected) return
  list.replaceChildren(...regions.map(option))
})
```

여기서 `search(text)`는 애플리케이션의 비동기 검색 함수이며, `option(region)`은 `listbox-option`, `role="option"`, 고유 ID, `data-value`, `aria-checked="false"`를 갖춘 요소 하나를 만듭니다. 서버에서 받은 레이블은 텍스트로 처리하고 HTML로 삽입하지 마세요. 요청 카운터는 이전 요청의 응답이 최신 결과를 덮어쓰는 것을 막습니다. 애플리케이션에서 로딩 중, 결과 없음, 오류 상태를 표시하세요.

## 사용자 정의 그리드 \{#a-grid-of-your-own\}

달력 동작만 요소를 생성하며, 표시할 달의 주별 행을 만듭니다. 템플릿이나 서버에서 렌더링하는 프레임워크처럼 렌더러가 요소를 직접 생성해야 한다면 `draw` 콜백을 전달합니다. 이 경우 스크립트는 요소를 생성하지 않습니다. 표시할 달이 그리드의 달과 다를 때마다 스크립트는 표시할 달을 `YYYY-MM` 형식으로 `draw`에 전달해 호출합니다. 날짜 요소가 렌더링되면 오늘, 선택된 날짜, 선택할 수 없는 날짜, 탭 이동 순서에 포함되는 날짜를 표시합니다.

`calendarMonth()`은 스크립트가 렌더링에 사용하는 것과 같은 월별 데이터를 반환합니다. 여기에는 달의 제목, 일곱 요일의 이름, 각 주가 포함됩니다. 각 날짜는 `calendar-day` 버튼이며, 버튼의 `value`에 날짜를 지정합니다. 스크립트는 이 값으로 자신이 생성하지 않은 날짜 요소를 식별합니다. `value`를 전달하면 데이터에 날짜별 렌더링 정보가 포함됩니다. 범위의 시작일과 종료일을 선택하는 모드에서는 `range` 옵션도 전달합니다. 날짜별 정보에는 선택 상태인 `selected`, Tab 키로 이동할 수 있는 날짜 하나를 나타내는 `tab`, 범위 내 날짜에 적용할 클래스 정보인 `range`가 포함됩니다. 렌더러가 날짜 요소를 직접 생성하면 스크립트가 실행되기 전부터 초기 HTML에 선택한 날짜가 포함됩니다.

```js
import { calendarMonth } from '@master/ui/behaviors/calendar.js'

const month = calendarMonth('2026-11', {
  value: '2026-11-13',
  locale: 'en-GB'
})

const chosen = month.weeks.flat().find(day => day.selected)
console.log(chosen.date) // "2026-11-13"
console.log(chosen.tab)  // true
```

렌더러는 이 데이터로 다음과 같이 계약에 맞는 마크업을 생성합니다.

| 데이터 | 렌더링 결과 |
| --- | --- |
| `title` | `calendar-title`의 텍스트 |
| `weekdays` | `calendar-weekday` 열 헤더. 축약 요일 이름은 텍스트로, 전체 요일 이름은 `aria-label`로 지정 |
| `weeks` | 주마다 `calendar-week` 행 하나 |
| 날짜의 `date`, `text`, `label` | 버튼의 `value`, 텍스트, `aria-label` |
| `selected`, `tab` | 처음에 선택된 날짜에는 `aria-selected` 속성과 `tabindex="0"`을 지정하고, 나머지 날짜에는 `-1`을 탭 인덱스로 지정 |
| `outside`, `range` | 필요한 경우 `calendar-day-outside` 클래스와 반환된 범위 클래스 이름 |

그리드가 생성되면 동일한 초기값과 로캘을 사용해 `calendar(root, { value, locale, draw })`를 호출해 동작을 연결합니다. `draw(month)` 콜백은 다른 달의 행을 렌더링합니다. 행이 렌더링되면 동작이 현재 선택과 포커스 상태를 표시합니다. 행을 교체할 때는 제목, 요일 헤더, 그리드의 레이블 지정을 유지하세요.

React, Svelte, Vue용 [달력 컴포넌트](/guide/frameworks)는 이 방식으로 구현되어 표시할 달이 초기 HTML에 포함됩니다.

## 키보드 조작 \{#the-keys\}

계약의 `keyboard` 목록에는 패턴과 함께 제공되는 키보드 동작이 명시되어 있습니다. `npx master-ui contract combobox` 명령으로 이 목록을 확인할 수 있습니다.

| 키 | 동작 |
| --- | --- |
| ArrowDown, ArrowUp | 목록을 열고 활성 옵션을 이동합니다. 목록 끝을 지나면 반대쪽 끝으로 이동합니다. |
| Home, End | 목록이 열린 상태에서 첫 번째 또는 마지막 옵션으로 이동합니다. |
| Enter | 활성 옵션을 선택하고 목록을 닫습니다. |
| Escape | 목록을 닫고 필드의 텍스트를 유지합니다. |
| 텍스트 입력 | 옵션을 필터링하고 목록을 연 뒤 첫 번째 일치 항목을 활성화합니다. |

동작이 키를 처리할 때는 `preventDefault()`를 호출합니다. 처리 대상이 아닌 키는 기본 동작을 유지하므로, 콤보박스에 활성 옵션이 없을 때 Enter 키를 누르면 양식이 제출됩니다. 숨겨진 항목과 `disabled` 또는 `aria-disabled="true"`가 있는 항목은 건너뛰며, 좌우 화살표 키는 텍스트 방향에 따라 동작합니다.

## 동작 직접 관리 \{#own-a-behavior\}

패키지에서 제공하는 동작이 애플리케이션의 요구사항을 충족하는 동안에는 패키지에서 계속 가져오세요. 그러면 패키지를 업그레이드할 때 수정 사항도 적용됩니다. 프로젝트에 다른 키보드 동작이나 선택 방식이 필요하면 다음과 같이 소스 코드를 복사해 직접 유지보수하세요.

```bash
npx master-ui own combobox
```

`own`은 컴포넌트의 스타일시트, 계약, 동작을 프로젝트에 복사합니다. 기본 경로는 각각 `ui/combobox.css`, `ui/combobox.json`, `ui/combobox.js`입니다. 복사한 스크립트는 프로젝트에서 직접 관리하므로 프로젝트 내 경로에서 가져오세요. 컴포넌트 직접 관리에 관한 나머지 내용은 [사용자 정의](/guide/customization#own-a-component)에서 다룹니다.

콤보박스, 명령 팔레트, 목록 상자, 메뉴의 동작은 `./internal.js`에서 공통 보조 함수를 가져옵니다. `own`은 이 파일을 해당 동작 파일과 같은 위치에 복사합니다.

수정할 때도 계약을 지키세요. 스크립트가 변경하는 속성은 스타일시트가 참조하는 속성과 일치해야 하며, `keyboard` 목록에는 변경된 키 동작을 반영해야 합니다.

## 스크립트 없는 동작 \{#without-any-script\}

이 표는 패키지에서 제공하는 동작만 정리합니다. 애플리케이션에서 JavaScript가 필요할 수 있는 모든 작업을 다루지는 않습니다. 브라우저가 지원하는 경우 네이티브 컨트롤은 자체적으로 상호작용을 처리합니다. 기능을 보강할 때 적용할 폴백은 [브라우저 지원 가이드](/guide/browser-support)를 참고하세요. 표에 나온 패턴 중 일부는 동작을 연결하지 않고도 구성할 수 있습니다.

- **탭**은 링크나 라디오 컨트롤로 구성할 수 있습니다. 탭을 선택하면 그에 연결된 패널을 표시하는 탭 목록에는 선택 사항인 동작을 연결할 수 있습니다.
- **트리**는 중첩된 `<details>` 요소로 구성되며, 각 요소의 `<summary>`가 행에 해당합니다. 분기 노드는 자체적으로 펼쳐지고 접히며, 모든 행은 Tab 키로 포커스할 수 있습니다.
- **메뉴**는 버튼과 링크를 담은 팝오버입니다. 브라우저가 팝오버를 열고 닫으며, Tab 키로 항목 사이를 이동하고 Escape 키로 포커스를 버튼에 돌려보낼 수 있습니다. 이 역할은 방향키 조작을 지원한다는 의미이므로 `role="menu"`는 동작을 연결할 때만 추가하세요.

다른 컴포넌트 계약 중 일부는 스크립트를 `optional`로 표시하고 동작 이름은 명시하지 않습니다. 이런 스크립트는 체크박스의 `indeterminate` 상태처럼 HTML에 해당 속성이 없는 기능을 한두 줄로 처리합니다. 스크립트 없이도 컴포넌트는 작동합니다.
