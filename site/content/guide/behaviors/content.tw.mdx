大多數元件不需要腳本，因為套用樣式的元素本身就具備所需的行為。組合方塊、日曆格線和分隔器等少數模式沒有對應的原生元素。這些模式由樣式表根據 ARIA 和原生屬性呈現各種狀態，並由稱為「行為」的參考腳本協調輸入、焦點與選取。這份指南說明如何掛載行為、讀取其值，以及在元素離開頁面時移除事件監聽器。

## 什麼是行為 \{#what-a-behavior-is\}

每個行為各有一個檔案，內含一個以模式命名的函式。函式接收根元素，並回傳清理函式，用來移除事件監聽器、停止觀察器及取消計時器。清理時不會還原原始標記。例如，日曆會保留已繪製的月份。行為是純 ES 模組，無須相依套件、框架或建置步驟。

| 行為負責 | 行為不負責 |
| --- | --- |
| 設定及移除 ARIA 和原生屬性，包括 `aria-selected`、`aria-checked`、`aria-expanded`、`aria-activedescendant`、`aria-valuenow`、`hidden`、`tabindex`、`open` 以及欄位的值 | 設定樣式、狀態類別、尺寸或位置 |
| 移動焦點並呼叫平台 API，包括 `showPopover()`、`showModal()`、`stepUp()`、`scrollIntoView()` | 重新實作平台功能，包括開啟彈出式容器或對話框、點擊外部關閉，以及模態對話框的焦點限制與 Escape 鍵處理 |
| 透過契約公開的自訂屬性 `--menu-x`、`--splitter-size` 傳遞只有事件能提供的資訊 | 定位元素或套用限制。樣式表會讀取屬性並處理這兩項工作 |
| 模式需要依資料產生重複列時，使用契約定義的類別建立這些列，例如月份中的各週 | 讀寫契約範圍以外的內容。行為依契約定義的類別與角色尋找各部分 |

樣式表也能搭配其他遵循同一契約的腳本，前提是屬性、值和鍵盤行為一致。各框架的元件直接掛載這些行為，共用同一套按鍵處理邏輯。

## 行為一覽 \{#the-behaviors\}

各行為皆從 `@master/ui/behaviors/<name>.js` 匯入。最後一欄對應[契約](/guide/contracts)中的 `script` 欄位。`required` 表示模式需要腳本才能運作，`optional` 表示腳本會為原本即可運作的標記增添功能。

| 模式 | 匯入 | 腳本功能 | 腳本 |
| --- | --- | --- | --- |
| [日曆](/components/calendar) | `calendar` | 產生目前顯示月份的各週，標記今天、已選取的日期或日期範圍，以及無法選取的日期，並支援在格線內移動 | 必要 |
| [組合方塊](/components/combobox) | `combobox` | 隱藏與輸入內容不符的選項，切換作用中的選項，開啟及關閉清單，並將選取的選項寫入欄位 | 必要 |
| [指令面板](/components/command) | `command` | 篩選指令並切換作用中的選項。按 Enter 時點擊該選項並關閉對話框，也可在頁面任何位置用快捷鍵開啟對話框 | 必要 |
| [比較](/components/compare) | `compare` | 瀏覽器不支援捲動驅動動畫時，將範圍輸入欄位的值複製到 `--compare-position`。支援時不做任何變更 | 必要 |
| [清單方塊](/components/listbox) | `listbox` | 使用方向鍵或輸入字母切換作用中的選項，並勾選選取的選項。清單支援多選時，可勾選多個選項 | 必要 |
| [選單](/components/menu) | `menu`, `contextMenu` | 使用方向鍵或輸入字母在項目間移動焦點，並以指向子選單的方向鍵開啟子選單。`contextMenu` 會在指標所在位置開啟選單 | 選用 |
| [OTP](/components/otp) | `otp` | 在各輸入格之間移動焦點，並將貼上或自動填入的驗證碼逐字分配到各格 | 必要 |
| [分隔器](/components/splitter) | `splitter` | 拖曳把手或以按鍵移動把手時，將第一個窗格的尺寸寫入 `--splitter-size` 和 `aria-valuenow` | 必要 |
| [數值調整器](/components/stepper) | `stepper` | 讓兩個按鈕分別在數字欄位上呼叫 `stepDown()` 和 `stepUp()`，並在數值到達上限或下限時停用對應的按鈕 | 必要 |
| [分頁](/components/tabs#tab-panels) | `tabs` | 在 `role="tablist"` 中只保留一個分頁標籤在 Tab 導覽順序內，使用方向鍵移動並選取分頁標籤，並顯示所選分頁的面板 | 選用 |
| [樹狀檢視](/components/tree) | `tree` | 讓整個樹狀檢視只占一個 Tab 停駐點，並可使用方向鍵瀏覽、展開與收合節點 | 選用 |
| [滾輪](/components/wheel) | `wheel` | 將 `aria-selected` 移至停在標記下方的選項，並讓取得焦點的欄支援清單方塊的按鍵操作 | 必要 |

## 掛載單一行為 \{#attach-one\}

先[載入樣式表](/guide/installation)，再依契約撰寫標記。等根元素存在後再執行模組，並傳入帶有根類別的元素。下方直接以套件名稱匯入的寫法，假設應用程式能解析 npm 模組。若直接在瀏覽器中執行模組，則需要可解析的 URL 或匯入對應表。

```html
<div class="combobox">
  <div class="input-group">
    <input class="input-group-field" id="region" role="combobox" aria-expanded="false" aria-controls="region-list" aria-autocomplete="list" autocomplete="off" aria-label="Region">
    <button type="button" class="combobox-toggle" tabindex="-1" aria-label="Show regions"></button>
  </div>
  <div id="region-list" popover="manual" class="listbox" role="listbox" aria-label="Regions">
    <div class="listbox-option" role="option" id="region-hnd" data-value="hnd" aria-checked="false">Tokyo</div>
    <div class="listbox-option" role="option" id="region-sin" data-value="sin" aria-checked="false">Singapore</div>
    <div class="listbox-empty">No regions match.</div>
  </div>
</div>
```

```js name=app.js
import { combobox } from '@master/ui/behaviors/combobox.js'

const detach = combobox(document.querySelector('.combobox'))
```

輸入「Tok」，按下 ArrowDown，再按 Enter，確認欄位顯示 Tokyo，且 `detach.value` 為 `hnd`。元素移出頁面時，呼叫 `detach()`。在同一個根元素上重複掛載相同行為時，先前的實例會被卸載，但應用程式自行加入的事件監聽器會保留。

## 掛載所有行為 \{#attach-all\}

`attach()` 會依根類別找出所有模式，並掛載各自的行為。它會搜尋整份文件，或搜尋傳入的元素及其後代元素，並傳回一個函式，可卸載該次呼叫掛載的所有行為。

```js name=app.js
import { attach } from '@master/ui/behaviors'

const detach = attach()
```

選擇一次掛載所有行為前，請先了解以下限制與行為。

- 它也會掛載選用行為。每個 `menu` 都會支援方向鍵，每個 `tree` 都會成為單一 Tab 焦點停駐點，每個屬於 `role="tablist"` 的 `tabs` 都會切換面板。若要讓其中某個模式保留平台原生行為，請依名稱匯入所需的行為。
- 它不會傳入任何設定選項。若日曆要選取日期範圍，或設有可選日期的起訖限制，請依名稱匯入並掛載其行為。
- 快顯選單須綁定到只有頁面知道的目標，因此 `attach()` 不會掛載快顯選單。請呼叫 `contextMenu(target, menu)`。

它不會監看文件變動。若稍後加入標記，請對新增的部分呼叫 `attach(element)`，並保留該次呼叫傳回的清理函式。移除對應的根元素前，請呼叫各自的清理函式。

## 在框架中使用 \{#in-a-framework\}

在 React、Svelte 和 Vue 中，這些模式各有可複製到專案的元件。元件會產生標記、掛載行為，並接收及傳出值。元件清單請見 [React、Svelte 和 Vue](/guide/frameworks)。本節其餘內容說明如何在自訂元件中自行掛載行為。

以下程式碼片段只示範掛載與清理。請將[掛載單一行為](#attach-one)中的完整組合方塊標記放入各個根元素。設定選項變更時，請重新掛載。若要處理應用程式的值或會變動的設定選項，建議使用複製到專案的框架元件，或使用其[轉接輔助函式](/guide/frameworks#your-own)。

在 React 中，將卸載函式從 `useEffect` 的回呼傳回，供 React 清理時呼叫。

```jsx name=Combobox.jsx
import { useEffect, useRef } from 'react'
import { combobox } from '@master/ui/behaviors/combobox.js'

export function Combobox({ children }) {
  const root = useRef(null)
  useEffect(() => combobox(root.current), [])
  return <div className="combobox" ref={root}>{children}</div>
}
```

在 Svelte 中，行為的函式簽章符合 attachment 的要求，因此 `{@attach}` 可直接使用該行為。

```svelte name=Combobox.svelte
<script>
  import { combobox } from '@master/ui/behaviors/combobox.js'
</script>

<div class="combobox" {@attach combobox}>
  <!-- the field and the listbox -->
</div>
```

action 會傳回物件，因此若使用的 Svelte 版本不支援 attachment，請包裝該行為：先用 `const action = (node) => ({ destroy: combobox(node) })`，再用 `use:action`。

在 Vue 中，請在元件掛載時掛載行為，並在元件卸載時卸載行為。

```vue name=Combobox.vue
<script setup>
import { onMounted, onUnmounted, ref } from 'vue'
import { combobox } from '@master/ui/behaviors/combobox.js'

const root = ref(null)
let detach

onMounted(() => { detach = combobox(root.value) })
onUnmounted(() => detach?.())
</script>

<template>
  <div class="combobox" ref="root"><slot /></div>
</template>
```

## 設定選項 \{#options\}

下列行為接受設定物件作為第二個引數，例如 `calendar(root, options)`。

### 日曆 \{#calendar-options\}

- `value` 指定選取的日期，格式為 `YYYY-MM-DD`，也可指定日期範圍的起訖兩端。
- `month` 指定最先顯示的月份，格式為 `YYYY-MM`。
- `min`、`max` 分別指定可選取的最早與最晚日期。
- `range` 可選取兩個日期及兩者之間的所有日期。
- `weekStart` 指定第一欄的星期幾，從 0（星期日）到 6（星期六）。
- `locale` 是指定顯示名稱所用語言的 BCP 47 語言標籤。
- `disabled` 是判斷某個日期是否無法選取的函式。
- `draw` 是[代替行為產生日曆格線](#a-grid-of-your-own)的函式。

### 組合方塊 \{#combobox-options\}

`filter` 預設為 `true`，行為會隱藏文字中未包含輸入內容的選項。若[應用程式會提供符合的選項](#options-from-a-server)，請將它設為 `false`。

### 指令面板 \{#command-options\}

`shortcut` 指定搭配 Command 或 Control 鍵開關面板的按鍵。預設為 `'k'`，設為 `false` 即可停用快捷鍵。`filter` 的用法與組合方塊相同。

### OTP \{#otp-options\}

`pattern` 是每個字元都必須符合的正規表示式。省略時，行為會讀取第一個輸入格的 `pattern` 屬性。若無此屬性，則只接受數字。

### 分隔器 \{#splitter-options\}

`step` 設定每按一次方向鍵時把手移動的幅度，以百分點為單位。預設為 5。

## 事件 \{#events\}

行為與原生控制項一樣，會透過可冒泡的 DOM 事件通知變更。請使用 `addEventListener` 或框架提供的原生事件繫結方式來監聽。

| 行為 | 事件 | 派發來源 | 事件資料 |
| --- | --- | --- | --- |
| `combobox` | 選取選項時，先派發 `input`，再派發 `change` | 欄位 | 值取自欄位的 `value` |
| `listbox` | 先派發 `input`，再派發 `change` | 清單方塊 | 讀取其選項上的 `aria-checked="true"` |
| `stepper` | 按鈕使數值變更時，先派發 `input`，再派發 `change` | 欄位 | 值取自欄位的 `value` |
| `splitter` | 每次尺寸變更時派發 `input`。拖曳結束或按鍵使把手移動時派發 `change` | 把手 | 讀取 `aria-valuenow` |
| `otp` | 腳本寫入某個輸入格時，該輸入格觸發 `input`；所有輸入格都填滿時，根元素觸發 `change` | 輸入格、根元素 | `detail.value`：驗證碼 |
| `calendar` | `change` | 根元素 | `detail.value`：日期以 `YYYY-MM-DD` 表示，範圍的兩端都選定後則以 `[start, end]` 表示 |
| `wheel` | 滾輪欄停在另一個選項時觸發 `change` | 該欄 | `detail.value`：選項的 `data-value`，若未設定則取其文字。`detail.option`：該元素 |
| `tree` | 選取帶有 `role="treeitem"` 的非分支列時觸發 `change` | 根元素 | `detail.item`：該列 |
| `tabs` | 選取另一個分頁時觸發 `change` | 分頁清單 | `detail.value`：分頁的 `data-value`，若未設定則取其文字。`detail.tab`：該元素 |

一次性驗證碼欄位、日曆、滾輪、樹狀檢視和分頁清單的 `change` 都是 `CustomEvent`，因為這些元件的值並非由單一原生控制項持有。一次性驗證碼欄位的每個輸入格都是原生輸入元素，因此它自己的 `change` 也會冒泡經過根元素，且不帶 `detail`。指令面板、選單和比較元件本身都不會派送事件。選項收到 `click` 時會執行對應指令，按 Enter 也會觸發同一事件。選單項目使用原生按鈕、連結和輸入元素。

```js name=app.js
import { calendar } from '@master/ui/behaviors/calendar.js'

const root = document.querySelector('.calendar')
const detach = calendar(root, { value: '2026-11-13', min: '2026-11-01' })

root.addEventListener('change', (event) => {
  console.log(event.detail.value)
})
```

## 值 \{#the-value\}

如果元件模式的值並非由單一原生控制項持有，其行為傳回的函式就會提供 `value`。讀取此屬性可取得目前的選取值。從外部設定此屬性會更新元件的選取標記，且不會派送事件，與設定原生輸入元素的 `value` 相同。

| 行為 | `value` |
| --- | --- |
| `calendar` | 日期以 `YYYY-MM-DD` 表示，範圍則以 `[start, end]` 表示。尚未選定結束日期時，範圍的第二個值為 `null`。完全沒有選取時，整個值為 `null`。設定此值會顯示新值所在的月份 |
| `combobox` | 所選選項代表的值。若欄位中的文字未透過選取選項填入，則為 `null`。設定此值會將選項文字寫入欄位 |
| `listbox` | 所選選項代表的值，未選取時為 `null`。清單方塊帶有 `aria-multiselectable="true"` 時，會傳回所選值的清單 |
| `otp` | 各輸入格中的字元，依輸入格順序排列 |
| `splitter` | 第一個窗格的大小，以百分比表示 |
| `stepper` | 欄位中的數值，空白時為 `null` |
| `compare` | 範圍輸入元素的數值 |
| `tabs`, `tree` | 所選分頁或列代表的值，未選取時為 `null` |
| `wheel` | 各欄所選選項代表的值，依各欄的排列順序列出 |

選項、分頁和列都以各自的 `data-value` 作為值，未設定時則使用其文字。若應用程式儲存的值與顯示文字不同，請設定 `data-value`，例如在顯示 Tokyo 的選項上加上 `data-value="hnd"`。

```js name=app.js
import { combobox } from '@master/ui/behaviors/combobox.js'

const region = combobox(document.querySelector('.combobox'))
region.value = 'hnd'        // checks the option, writes "Tokyo" into the field
console.log(region.value)   // "hnd"
```

腳本將值寫入欄位時，會透過元素原型上的 setter。React 會在輸入元素本身定義 `value` 屬性，以追蹤自己寫入的值。如果 `input` 事件帶來的值已經記錄過，React 就會忽略該事件。透過原型上的 setter 寫入時，選取結果就會像使用者直接輸入一樣傳到 `onChange`。

## 從伺服器取得選項 \{#options-from-a-server\}

預設情況下，組合方塊和指令面板會篩選標記中已有的選項。如果由頁面查詢伺服器或搜尋索引來決定哪些選項符合條件，請傳入 `filter: false`。這樣腳本就不會隱藏任何選項，頁面會隨使用者輸入更新選項。如果清單開啟時收到新選項，清單會重新指定作用中的選項，因此按 <kbd>Enter</kbd> 仍會選取第一筆符合的結果。

```js name=app.js
import { combobox } from '@master/ui/behaviors/combobox.js'

const root = document.querySelector('.combobox')
const list = root.querySelector('[role="listbox"]')
const selection = combobox(root, { filter: false })
let request = 0

root.querySelector('[role="combobox"]').addEventListener('input', async (event) => {
  const current = ++request
  if (selection.value !== null) return // Choosing an option also dispatches input.
  const regions = await search(event.target.value)
  if (current !== request || !root.isConnected) return
  list.replaceChildren(...regions.map(option))
})
```

此處的 `search(text)` 是應用程式的非同步搜尋函式，`option(region)` 則建立一個元素，包含 `listbox-option`、`role="option"`、唯一的 ID、`data-value` 和 `aria-checked="false"`。請以純文字呈現標籤，避免將伺服器傳回的字串當成 HTML 插入。請求計數器可防止較早發出的請求回應覆蓋較新的結果。請在應用程式中顯示載入中、沒有結果及發生錯誤的狀態。

## 自訂日曆格線 \{#a-grid-of-your-own\}

日曆是唯一會產生元素的行為，產生的是目前顯示月份的各週。若要由範本或在伺服器端呈現內容的框架自行產生這些元素，請傳入 `draw`。此時腳本不會產生任何元素。每當要顯示的月份與格線中的月份不同，腳本就會呼叫 `draw`，以 `YYYY-MM` 傳入要顯示的月份。日期元素就緒後，腳本會標記今天、已選取和無法選取的日期，以及唯一納入 Tab 鍵導覽順序的日期。

`calendarMonth()` 會傳回腳本產生月份格線所用的資料，包含月份標題、一週七天各自的名稱和各週。每一天都是帶有 `calendar-day` 的按鈕，其 `value` 為對應日期，讓腳本能辨識由外部程式產生的日期元素。提供 `value`，並在要選取範圍兩端時提供 `range`，資料就會一併指出每一天的呈現方式。`selected` 表示是否選取，`tab` 標記唯一納入 Tab 鍵導覽順序的日期，`range` 則提供範圍內日期的類別名稱。由外部程式自行產生日期元素時，選定的日期在任何腳本執行前就已出現在初始 HTML 中。

```js
import { calendarMonth } from '@master/ui/behaviors/calendar.js'

const month = calendarMonth('2026-11', {
  value: '2026-11-13',
  locale: 'en-GB'
})

const chosen = month.weeks.flat().find(day => day.selected)
console.log(chosen.date) // "2026-11-13"
console.log(chosen.tab)  // true
```

負責呈現格線的程式會用這些資料產生契約所規定的標記。

| 資料 | 呈現方式 |
| --- | --- |
| `title` | `calendar-title` 的文字 |
| `weekdays` | 欄標題使用 `calendar-weekday` 類別，以星期簡稱作為顯示文字、全名作為 `aria-label` |
| `weeks` | 每週各用一個 `calendar-week` 列 |
| 日期的 `date`、`text`、`label` | 按鈕的 `value`、文字及 `aria-label` |
| `selected`, `tab` | 初始選定的日期使用 `aria-selected` 和 `tabindex="0"`，其餘日期使用 `-1` |
| `outside`, `range` | 需要時加上 `calendar-day-outside`，並套用傳回的範圍類別名稱 |

格線建立後，請以相同的初始值和語系呼叫 `calendar(root, { value, locale, draw })` 來掛載行為。`draw(month)` 回呼負責產生另一個月份的各列。這些列就緒後，行為會標記目前的選取狀態與焦點。替換各列時，請保留標題、星期欄標題及格線的標籤。

React、Svelte 和 Vue 的[日曆元件](/guide/frameworks)都採用這種做法，因此初始 HTML 就包含月份內容。

## 按鍵 \{#the-keys\}

契約中的 `keyboard` 清單列出此模式內建的行為。使用 `npx master-ui contract combobox` 即可讀取這份清單。

| 按鍵 | 動作 |
| --- | --- |
| ArrowDown、ArrowUp | 開啟清單並切換作用中的選項，到達任一端時繞回另一端 |
| Home、End | 清單開啟時，移至第一個或最後一個選項 |
| Enter | 選取目前作用中的選項並關閉清單 |
| Escape | 關閉清單，保留欄位中的文字 |
| 輸入文字 | 篩選選項，開啟清單並將第一個符合的選項設為作用中 |

按下行為會處理的按鍵時，會呼叫 `preventDefault()`。其他按鍵維持原有作用，因此當組合方塊沒有作用中的選項時，按 Enter 仍會送出表單。隱藏的項目以及帶有 `disabled` 或 `aria-disabled="true"` 的項目都會略過，左右方向鍵則依文字方向運作。

## 自行維護行為 \{#own-a-behavior\}

只要套件提供的行為仍符合應用程式的需求，就繼續從套件匯入，這樣升級套件時也能一併取得修正。若專案需要不同的鍵盤操作或選取行為，就複製原始程式碼並自行維護：

```bash
npx master-ui own combobox
```

`own` 會將元件的樣式表、契約和行為複製到專案中，預設分別為 `ui/combobox.css`、`ui/combobox.json` 和 `ui/combobox.js`。此後，腳本由專案自行維護，請改從專案中的檔案匯入。[自訂](/guide/customization#own-a-component) 說明自行維護元件時的其他事項。

組合方塊、指令面板、清單方塊和選單的行為都會從 `./internal.js` 匯入共用輔助程式。`own` 會將這個檔案複製到這些行為所在的目錄。

修改時請維持契約一致。腳本更新的屬性必須與樣式表讀取的屬性一致，`keyboard` 清單也應反映修改後的按鍵操作。

## 不使用腳本 \{#without-any-script\}

表格只列出套件提供的行為。應用程式中的其他操作也可能需要 JavaScript。瀏覽器支援的原生控制項自有互動功能，增強功能無法使用時的替代方案請參閱[瀏覽器支援指南](/guide/browser-support)。表格中的幾種模式也有無須搭配行為的用法：

- **分頁標籤**可以使用連結或單選按鈕。若分頁標籤清單需要選取標籤並顯示對應的面板，可搭配選用的行為。
- **樹狀檢視**由巢狀的 `<details>` 元素組成，每個元素的 `<summary>` 就是一列。分支可自行展開或收合，每一列都能透過 Tab 鍵取得焦點。
- **選單**是由按鈕和連結組成的彈出式容器。瀏覽器負責開啟和關閉選單，按 Tab 可在項目間移動焦點，按 Escape 則會將焦點移回按鈕。只有搭配行為時才加入 `role="menu"`，因為這個角色必須支援方向鍵操作。

少數其他契約會將腳本標記為 `optional`，且未指定任何行為。這類腳本只有一兩行，用於處理 HTML 沒有對應屬性的功能，例如核取方塊的 `indeterminate` 狀態。省略腳本時，元件仍可運作。
