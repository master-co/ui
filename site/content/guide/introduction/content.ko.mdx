Master UI는 HTML 인터페이스에 공통으로 사용할 컴포넌트 클래스와 디자인 토큰을 제공하고, 각 상태를 문서로 설명합니다. `<button class="btn">` 같은 네이티브 마크업을 작성하고 서버 템플릿, React, Svelte, Vue에서 같은 클래스를 사용합니다. 패키지에는 CSS, 마크업 계약, 그리고 일부 패턴에 필요한 스크립트가 포함되어 있습니다.

마크업을 직접 관리하면서 프로젝트 전체에서 컴포넌트의 모양과 동작을 통일하고 싶을 때 사용하세요. 기본 테마인 moonstone과 obsidian으로 시작하거나, 테마의 토큰을 조정하거나, 컴포넌트 소스를 프로젝트에 가져와 사용할 수 있습니다. Master UI는 실험 단계이므로 [설치 버전을 고정하고 업그레이드 시 변경 사항을 검토하세요](/guide/stability#experimental).

## 계약과 구현 \{#a-contract-and-an-implementation\}

계약은 스타일시트가 지원하는 마크업을 정의합니다. 여기에는 클래스, 요소, 상태를 나타내는 속성, 공개 사용자 지정 속성이 포함됩니다. 사람과 코딩 에이전트는 계약을 바탕으로 같은 용어를 사용하고 흔한 실수를 점검할 수 있습니다. 실제 모양과 동작은 구현에서 제공됩니다.

<GuideFigure name="introduction" title="마크업, 계약, 구현">

**계약은 마크업과 구현을 연결합니다.** 버튼의 `btn` 클래스는 HTML과 CSS에서 같은 인터페이스를 가리킵니다. 계약에는 요소, 상태를 나타내는 속성, 공개 사용자 지정 속성도 정의됩니다. 테마를 바꾸면 재질을 표현하는 값이 달라지며, 계약에 정의된 이름은 그대로 사용할 수 있습니다. 스크립트가 필요한 패턴에서는 입력에 따라 속성이 바뀌고 CSS가 그 상태를 화면에 표시합니다.

</GuideFigure>

| 항목 | 제공 내용 | 사용 방법 |
| --- | --- | --- |
| [계약](/guide/contracts) | 각 스타일시트와 함께 제공되는 JSON 명세와 올바른 마크업 예제 | 마크업을 작성하기 전에 설치된 계약을 확인하세요 |
| 구현 | 계약에 정의된 모양을 구현하는 스타일시트 | [토큰, 테마 또는 직접 복사한 소스](/guide/customization)를 조정하세요 |
| [동작](/guide/behaviors) | 키보드 입력, 값 또는 포커스 처리가 필요한 패턴을 위한 참조 스크립트 | 직접 연결하거나 제공되는 프레임워크 컴포넌트를 통해 연결하세요 |
| 검사 | 검사기가 읽을 수 있는 마크업에 대한 정적 진단 | 수정 후와 CI에서 검사를 실행한 다음 렌더링된 인터페이스를 확인하세요 |

계약은 명시된 범위만 허용합니다. 계약에 `btn-outline`이 정의되어 있지 않은데 마크업에 사용하면 검사기가 이를 보고합니다. 구현은 자유롭게 바꿀 수 있습니다. 토큰을 조정하거나, [테마](/guide/theming)로 재질을 바꾸거나, 컴포넌트 소스를 프로젝트에 가져와 사용하세요. 토큰이나 테마를 바꿔도 계약은 유지됩니다. 직접 관리하는 컴포넌트의 구조나 상태를 바꿀 때는 해당 컴포넌트의 로컬 계약과 이를 사용하는 코드도 함께 수정하세요. 에이전트가 읽는 파일과 실행하는 명령은 [AI와 함께 작업하기](/guide/ai)에서 다룹니다.

## 구성과 역할 \{#how-it-fits-together\}

| 레이어 | 담당 | 예시 |
| --- | --- | --- |
| 디자인 토큰 | Master CSS 프리셋과 `@master/ui/theme.css` | `--color-surface-raised`, `--shadow-raised` |
| 컴포넌트 스타일 | `@master/ui` | `.btn`, `.btn-primary`, `.input` |
| 레이아웃 클래스 | `@master/ui` | `.page`, `.shell`, `.auto-grid`, `.form` |
| 개별 조정 | 직접 작성한 마크업 | `w-full`, `mt-md`, `px-lg` |

컴포넌트 클래스는 `components` 캐스케이드 레이어에 속하고 유틸리티는 그보다 뒤에 오는 `utilities` 캐스케이드 레이어에 속합니다. 따라서 개별 인스턴스에 적용한 유틸리티는 `!important`를 쓰거나 선택자를 변형할 필요 없이 항상 우선합니다.

```html
<button type="button" class="btn btn-primary w-full">Save changes</button>
```

## 컴포넌트, 레이아웃, 블록, 페이지 \{#tiers\}

라이브러리는 개별 요소부터 화면 전체까지 네 단계로 구성됩니다. 크기와 관계없이, 클래스로 정의해 둘 규칙이 있는지가 분류 기준입니다.

| 단계 | 정의 | 제공 형태 |
| --- | --- | --- |
| [컴포넌트](/components) | 재질, 상태, 플랫폼 동작 또는 내부 요소가 공유하는 형태와 크기 규칙을 갖는 개별 요소 | `@master/ui`의 시맨틱 클래스 |
| [레이아웃](/components#layouts) | 영역 내부의 배치 방식. 스택, 자동 그리드, 벤토, 메이슨리, 그림이 열 너비를 넘어 배치되는 레이아웃 등이 해당합니다 | 유틸리티를 사용하고, 유틸리티로 표현할 수 없는 경우에는 레이아웃 클래스를 사용합니다. 레이아웃 클래스는 컴포넌트 목록에 함께 표시됩니다 |
| [블록](/blocks) | 히어로, 요금표, 푸터처럼 특정 목적을 가진 페이지의 한 구간 | 컴포넌트와 유틸리티를 조합해 복사해서 쓸 수 있도록 제공하는 마크업 |
| [페이지](/pages) | 각 영역의 위치와 어느 부분이 스크롤되는지를 정한 전체 화면 | 두 프레임 `page`와 `shell` 중 하나를 기반으로 하며 복사해서 쓸 수 있는 마크업 |

다음 네 가지 중 하나 이상을 표현할 때 클래스를 정의합니다.

1. **재질.** 재질의 단계 체계를 따라야 하는 표면, 윤곽선, 그림자 또는 모서리입니다.
2. **상태.** 호버, 포커스, 선택됨, 열림, 비활성화, 유효하지 않음 등의 상태를 네이티브 속성이나 ARIA 속성에서 읽습니다.
3. **플랫폼 동작.** 앵커 위치 지정, 스크롤 상태 쿼리, 최상위 레이어에 표시하기처럼 유틸리티로 표현할 수 없는 동작입니다.
4. **컴포넌트 내부 요소가 공유하는 형태와 크기 규칙.** 안쪽 여백에 맞춰 중첩되는 모서리나, 자신을 담는 요소의 크기를 따르는 자식 요소가 해당합니다.

버튼에는 재질, 상태, 형태와 크기 규칙이 모두 적용됩니다. 링크를 여러 열에 배치한 푸터는 유틸리티로 구성한 블록이므로 별도의 컴포넌트 클래스가 필요하지 않습니다. 여기서 세 가지 원칙이 나옵니다.

- **컴포넌트는 페이지 배치를 결정하지 않습니다.** 위치 지정이 컴포넌트 자체의 동작인 경우에만 위치를 정합니다. 예를 들어 내비게이션 바는 스크롤 시 특정 위치에 붙고, 대화 상자는 최상위 레이어에 표시됩니다.
- **레이아웃은 재질을 결정하지 않습니다.** 레이아웃은 영역의 배치와 스크롤 방식을 정하고, 각 영역의 표면은 시트, 트레이, 카드가 구성합니다.
- **클래스는 규칙을 담아야 합니다.** 마크업이 반복되기만 한다면 별도의 클래스 이름을 붙일 필요 없이 복사해 사용합니다.

일부 레이아웃에는 `dvh` 단위의 높이, 휴대전화의 안전 영역, 컨테이너 크기의 임계값, 그리드 트랙 목록처럼 유틸리티로 표현할 수 없는 규칙이 있습니다. 이에 해당하는 레이아웃 클래스는 두 프레임인 [`page`](/pages/page)와 [`shell`](/pages/app-shell), 그리고 [`auto-grid`](/components/auto-grid), [`bento`](/components/bento), [`masonry`](/components/masonry), [`breakout`](/components/breakout), [`sticky-stack`](/components/sticky-stack), [`form`](/components/form)입니다.

## 설계 원칙 \{#principles\}

- **네이티브 요소 우선.** 컴포넌트는 용도에 맞는 의미를 이미 갖춘 요소를 사용하고, 가능한 한 그 요소의 기본 동작을 유지합니다. 패턴에 맞는 네이티브 요소가 없으면 스타일시트가 ARIA 속성을 바탕으로 상태를 표현하고 [작은 스크립트가 상태를 전환합니다](#patterns-that-need-a-script).
- **스크립트보다 플랫폼 우선.** 브라우저가 자체적으로 처리할 수 있는 기능은 컴포넌트에서 다시 구현하지 않습니다. 아래의 [플랫폼](#the-platform)을 참고하세요.
- **장식 대신 빛.** 주변보다 높게 떠 있는 표면의 가장자리에는 가느다란 빛이 맺히고, 아래에는 옅어지며 사라지는 짧은 그림자가 드리웁니다. 오목한 영역은 주변 표면보다 낮게 들어갑니다. 상태는 색상이 아닌 깊이로 구분하며, 가장자리는 부드럽게 처리합니다. [기본 테마](/guide/theme)를 참고하세요.
- **하드코딩 대신 디자인 토큰.** 표면, 선, 표면의 높낮이, 모서리 반경, 모션은 테마의 디자인 토큰으로 정합니다. 컴포넌트에 색상을 직접 지정하면 테스트가 실패합니다. 토큰 하나를 재정의하면 모든 컴포넌트에 변경 사항이 반영됩니다.
- **최소한의 공개 인터페이스.** 기본 클래스 하나, `btn-primary`와 `btn-sm` 같은 몇 가지 변형 클래스, 그리고 `--btn-height`처럼 문서화된 사용자 지정 속성을 제공합니다.
- **스타일시트 하나로 라이트 및 다크 테마 지원.** 의미 기반 디자인 토큰의 값은 `light-dark()`를 통해 페이지의 색상 구성표에 따라 결정됩니다.

## 플랫폼 \{#the-platform\}

네이티브 요소는 이미 지원하는 기능을 직접 처리합니다. 체크박스는 선택 여부를 저장하고, 셀렉트는 폼에 참여하며, 모달 대화 상자가 열리면 뒤에 있는 페이지와 상호작용할 수 없습니다. Master UI는 이러한 요소의 속성과 상태에 맞춰 스타일을 적용합니다.

스타일시트를 사용하려면 브라우저가 최소 지원 요건을 충족해야 합니다. 캐스케이드 레이어, 중첩, `light-dark()` 등의 기능은 필수입니다. 앵커 위치 지정이나 연속형 모서리 같은 선택 기능은 기본 동작이 가능한 환경에서 표현을 개선합니다. 일부 폴백에는 애플리케이션 코드가 필요합니다. 예를 들어 호출자 명령을 지원하지 않는 브라우저에서는 `dialog.showModal()`을 호출하는 클릭 핸들러가 필요합니다.

최소 지원 요건, 선택 기능의 폴백, 애플리케이션에서 사용하는 기능의 테스트 방법은 [브라우저 지원](/guide/browser-support)을 참고하세요. 각 컴포넌트 페이지에서는 예제와 함께 해당 폴백을 안내합니다.

## 스크립트가 필요한 패턴 \{#patterns-that-need-a-script\}

아직 대응하는 네이티브 요소가 없는 패턴도 있습니다. [콤보박스](/components/combobox), [명령 팔레트](/components/command), [달력](/components/calendar), 방향키로 탐색하는 [트리](/components/tree), [컨텍스트 메뉴](/components/menu#context-menu), 다음 칸으로 자동 이동하는 [OTP 입력란](/components/otp), 두 패널 사이에서 드래그하는 [분할 조절기](/components/splitter), 같은 위치에서 패널을 전환하는 [탭](/components/tabs#tab-panels)이 이에 해당합니다. Master UI는 각 패턴에 스타일시트를 하나씩 제공합니다. 역할 분담은 모든 패턴에서 같습니다.

- **스타일시트는 모든 상태를 ARIA 속성에 따라 표현합니다**. 활성 옵션은 `aria-selected`, 선택된 옵션은 `aria-checked`, 펼쳐진 트리 분기는 `aria-expanded`, 오늘 날짜는 `aria-current="date"`, 분할기의 방향은 `aria-orientation`으로 나타냅니다. 스타일시트는 표면의 배치와 애니메이션도 처리하며, 빈 상태처럼 CSS에서 판단할 수 있는 상태는 `:has()`로 판별합니다.
- **스크립트는 입력을 처리하고 상태를 갱신합니다.** 패키지는 참조 구현으로 [동작](/guide/behaviors)을 제공하며, 각 동작은 계약에 명시된 키를 기준으로 테스트합니다. 동작은 네이티브 속성과 ARIA 속성을 갱신합니다. 포인터 위치처럼 CSS에서 자체적으로 구할 수 없는 값은 사용자 지정 속성으로 전달할 수 있습니다. 표면의 재질과 배치 규칙은 CSS가 담당합니다.
- **컨테이너에는 용도에 맞는 네이티브 요소가 있으면 그 요소를 사용합니다.** 명령 팔레트는 `command="show-modal"`로 여는 `<dialog>`입니다. 날짜 선택기의 달력은 `popover` 안에 배치하며, 스크립트가 없는 트리는 `<details>`를 중첩해 구성합니다.

이러한 속성에 맞춰 작성한 마크업이 계약을 이룹니다. 따라서 템플릿, 프레임워크 컴포넌트, 에이전트 중 무엇으로 렌더링하든 같은 방식으로 동작합니다.

## React, Svelte, Vue에서의 사용 \{#in-a-framework\}

라이브러리의 대부분은 일반 페이지와 프레임워크에서 같은 방식으로 사용합니다. 프레임워크 문법에 맞춰 네이티브 요소에 클래스를 지정하면 됩니다. `btn btn-primary`의 이름만 바꾸는 `<Button>`은 기능을 추가하지 않으며, [검사기](/guide/ai#check-the-markup)가 해당 클래스를 찾지 못하게 합니다.

프레임워크가 직접 관리할 대상이 있을 때만 프레임워크 컴포넌트를 제공합니다. 애플리케이션이 읽거나 설정하는 값, 데이터에서 렌더링하는 행, 여러 부분을 연결하는 ID, 생명 주기 등이 이에 해당합니다. 위에서 설명한 패턴과 함께 상태에 따라 열리는 대화 상자, 토스트 대기열, 레이블과 오류 메시지가 있는 입력 필드가 대표적인 예입니다. 각 컴포넌트는 계약에 맞는 마크업을 렌더링하고 패키지에서 제공하는 동작을 연결합니다. 컴포넌트 자체의 소스 코드는 `npx master-ui add combobox` 명령으로 프로젝트에 복사합니다. 목록은 [React, Svelte, Vue](/guide/frameworks)에서 확인하세요.

## 이번 알파 릴리스의 공개 범위 \{#what-comes-next\}

이번 알파 릴리스에서는 계약, 스타일시트, 동작, 두 번째 테마, 검사기, 복사해 쓸 소스 코드 [레지스트리](/guide/registry), 그리고 상태를 유지하는 패턴을 위한 React, Svelte, Vue 컴포넌트를 제공합니다. 프레임워크 컴포넌트는 별도의 바인딩 패키지 대신 `@master/ui`에서 소스 코드로 제공합니다. 공통 상호작용 로직은 동작에 두고, 각 프레임워크 컴포넌트는 자체 렌더링과 생명 주기를 관리합니다. 공개 범위와 변경될 수 있는 항목은 [안정성](/guide/stability)을 참고하세요.

[설치](/guide/installation)를 진행한 뒤 [사용할 컴포넌트를 선택](/guide/choosing)하거나 [컴포넌트 목록](/components)을 둘러보세요.
