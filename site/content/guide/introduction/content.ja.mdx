Master UI は、HTML インターフェースに共通のコンポーネントクラスとデザイントークンを提供し、各コンポーネントの状態を文書化しています。`<button class="btn">` のようにネイティブ要素を書けば、サーバーテンプレートでも React、Svelte、Vue でも同じクラスを使えます。パッケージには CSS、マークアップのコントラクト、必要なパターン向けのスクリプトが含まれます。

マークアップを自分で管理しながら、コンポーネントの見た目と動作をプロジェクト全体で揃えるためのライブラリです。moonstone と obsidian を使った既定のテーマをそのまま使うことも、トークンを調整することも、コンポーネントのソースをプロジェクトに取り込むこともできます。Master UI は実験段階です。[インストールするバージョンを固定し、更新時に変更点を確認してください](/guide/stability#experimental)。

## コントラクトと実装 \{#a-contract-and-an-implementation\}

コントラクトは、スタイルシートが扱うクラス、要素、状態を表す属性、公開カスタムプロパティを定めた仕様です。開発者とコーディングエージェントが共通の名前を使い、よくある記述ミスを検査できます。その仕様に従って見た目と動作を提供するのが実装です。

<GuideFigure name="introduction" title="マークアップ、コントラクト、実装">

**コントラクトがマークアップと実装をつなぎます。** ボタンの `btn` クラスは、HTML と CSS で同じインターフェースを指します。コントラクトには、クラスのほかに要素、状態を表す属性、公開プロパティも記載されています。テーマを替えると見た目を構成する値が変わり、これらの名前は引き続き使えます。スクリプトが必要なパターンでは、操作に応じて属性が更新され、CSS がその状態を表示します。

</GuideFigure>

| 構成要素 | 提供するもの | 使い方 |
| --- | --- | --- |
| [コントラクト](/guide/contracts) | 各スタイルシートに付属する JSON 仕様。正しい使用例を含みます。 | マークアップを書く前に、インストール済みのコントラクトを読む |
| 実装 | コントラクトに沿って表示するスタイルシート | [トークン、テーマ、取り込んだソース](/guide/customization)のいずれかを調整する |
| [ビヘイビア](/guide/behaviors) | キー操作、値、フォーカスを扱うパターン向けのリファレンススクリプト | 直接取り付けるか、付属のフレームワークコンポーネントを使う |
| 検査 | チェッカーが読み取れるマークアップの静的診断 | 編集後と CI で実行し、その後ブラウザーで表示と動作を確かめる |

コントラクトで使える名前は明示的に定義されています。たとえば `btn-outline` が定義されていなければ、書いてもチェッカーが報告します。実装はトークンで調整したり、[テーマ](/guide/theming)で見た目を差し替えたり、コンポーネントのソースを取り込んで変更したりできます。トークンやテーマを変更しても、コントラクトはそのまま保たれます。プロジェクトで管理するコンポーネントの構造や状態を変える場合は、ローカルのコントラクトと利用箇所をあわせて更新します。エージェントが参照する資料と実行するコマンドは[AI との開発](/guide/ai)で説明します。

## スタイルの構成 \{#how-it-fits-together\}

| レイヤー | 定義元 | 例 |
| --- | --- | --- |
| デザイントークン | Master CSS プリセットと `@master/ui/theme.css` | `--color-surface-raised`, `--shadow-raised` |
| コンポーネントのスタイル | `@master/ui` | `.btn`, `.btn-primary`, `.input` |
| レイアウトクラス | `@master/ui` | `.page`, `.shell`, `.auto-grid`, `.form` |
| 個別の調整 | 利用側のマークアップ | `w-full`, `mt-md`, `px-lg` |

コンポーネントクラスは `components` レイヤーに、ユーティリティは後の `utilities` レイヤーに入ります。個々の要素に付けたユーティリティはコンポーネントのスタイルより常に優先されるので、`!important` やセレクターの詳細度を上げる工夫は不要です。

```html
<button type="button" class="btn btn-primary w-full">Save changes</button>
```

## コンポーネント、レイアウト、ブロック、ページ \{#tiers\}

ライブラリは、画面の一部から画面全体までを 4 段階で扱います。分類の基準は大きさではなく、クラスとして定義すべき共通の仕様があるかどうかです。

| 分類 | 役割 | 提供形式 |
| --- | --- | --- |
| [コンポーネント](/components) | 質感、状態、ブラウザーの機能による動作、または内部で共有する形状を持つ部品 | `@master/ui` のセマンティッククラス |
| [レイアウト](/components#layouts) | 領域内の配置。縦積み、自動グリッド、ベントー、メイソンリー、本文幅を越えて図を広げる段組みなど | ユーティリティと、ユーティリティで表現できないときに使うレイアウトクラス。コンポーネント一覧に掲載 |
| [ブロック](/blocks) | ヒーロー、料金表、フッターなど、特定の役割を持つページ内の一領域 | コンポーネントとユーティリティを組み合わせた、コピーして使えるマークアップ |
| [ページ](/pages) | 領域の配置とスクロールする範囲を定めた画面全体 | `page` または `shell` の枠組みを使った、コピーして使えるマークアップ |

次のいずれかを表現する場合に、クラスを定義します。

1. **質感。** 質感の段階に沿って定まる面、輪郭、影、角の形。
2. **状態。** ネイティブ属性や ARIA から読み取るホバー、フォーカス、選択済み、開いている状態、操作無効、値が妥当でない状態。
3. **ブラウザーの機能による動作。** アンカー配置、スクロール状態のクエリー、トップレイヤーへの表示など、ユーティリティで表現できない動作。
4. **内部で共有する形状。** 外側の角からの間隔に合わせて決まる内側の角の半径や、親要素に合わせて決まる子要素のサイズ。

ボタンは質感、状態、形状を組み合わせたコンポーネントです。リンクを列に並べるフッターは、ユーティリティで構成できるブロックなので、新しいコンポーネントクラスは不要です。ここから 3 つのルールが決まります。

- **コンポーネントが配置を決めるのは、配置自体が動作の一部である場合に限ります。** たとえば、スクロールに追従して所定の位置に留まるナビゲーションバーや、トップレイヤーに表示されるダイアログが該当します。
- **レイアウトは領域とスクロールを定めます。** 領域に見える面は、シート、トレイ、カードが表現します。
- **クラスは共通の仕様を表します。** マークアップが繰り返されるだけなら、そのままコピーして使います。

`dvh` で指定する高さ、スマートフォンのセーフエリア、コンテナーのしきい値、グリッドのトラック一覧など、ユーティリティで表せない指定を担うレイアウトクラスがあります。画面の枠組みを作る [`page`](/pages/page) と [`shell`](/pages/app-shell) のほか、[`auto-grid`](/components/auto-grid)、[`bento`](/components/bento)、[`masonry`](/components/masonry)、[`breakout`](/components/breakout)、[`sticky-stack`](/components/sticky-stack)、[`form`](/components/form) が該当します。

## 設計原則 \{#principles\}

- **役割に合うネイティブ要素を使います。** 可能な限り既存のセマンティクスと動作を活かします。対応するネイティブ要素がない場合は、スタイルシートが ARIA 属性に応じて状態を表示し、[小さなスクリプトで属性を更新します](#patterns-that-need-a-script)。
- **ブラウザー標準の機能を優先します。** ブラウザーがすでに処理できる動作は、その機能に任せます。詳しくは[ブラウザー標準の機能](#the-platform)を参照してください。
- **光と影で奥行きを伝えます。** 浮いた面の縁には細い光が走り、下に落ちる短い影は徐々に薄れます。くぼんだ面は周囲より低く見えます。状態は奥行きだけで示し、輪郭は柔らかく仕上げます。[既定のテーマ](/guide/theme)を参照してください。
- **共有する値はトークンにまとめます。** 面、線、浮き上がりの度合い、角の半径、動きはテーマトークンから決まります。コンポーネントに色を直接書くとテストが失敗します。トークンを一度変更すれば、対応するすべてのコンポーネントに反映されます。
- **公開する名前を絞ります。** ベースクラス、`btn-primary` や `btn-sm` など少数の修飾クラス、`--btn-height` など文書化したカスタムプロパティを提供します。
- **ライトとダークは 1 枚のスタイルシートで扱います。** セマンティックトークンは、ページの配色に従って `light-dark()` で値を切り替えます。

## ブラウザー標準の機能 \{#the-platform\}

チェックボックスはチェックの有無を保持し、セレクト要素はフォーム送信に選択値を渡し、モーダルダイアログは背後のページを操作できないようにします。これらの動作はネイティブ要素が担い、Master UI は要素の属性と状態に合わせてスタイルを適用します。

スタイルシートが動くために、カスケードレイヤー、ネスト、`light-dark()` などへの対応が必要です。アンカー配置や曲率が連続する角は任意の機能です。基本の表示や動作はこれらの機能がなくても利用でき、対応ブラウザーではさらに強化されます。一部のフォールバックはアプリ側で実装します。たとえば invoker commands に未対応のブラウザーでは、クリックハンドラーから `dialog.showModal()` を呼び出します。

必須機能、段階的な強化のフォールバック、アプリが使う機能の検証方法は[ブラウザー対応](/guide/browser-support)を参照してください。コンポーネントごとのフォールバックは、各ページの使用例の近くに記載しています。

## スクリプトが必要なパターン \{#patterns-that-need-a-script\}

対応するネイティブ要素がまだないパターンもあります。[コンボボックス](/components/combobox)、[コマンドパレット](/components/command)、[カレンダー](/components/calendar)、矢印キーで移動する[ツリー](/components/tree)、[コンテキストメニュー](/components/menu#context-menu)、入力すると次に進む [OTP フィールド](/components/otp)、2 つのペインの間をドラッグできる[スプリッター](/components/splitter)、その場でパネルを切り替える[タブ](/components/tabs#tab-panels)です。Master UI はパターンごとに 1 枚のスタイルシートを提供します。スタイルシートとスクリプトの役割分担は、どのパターンでも同じです。

- **スタイルシートは、すべての状態を ARIA 属性に基づいて描画します。** アクティブな選択肢は `aria-selected`、選択済みの項目は `aria-checked`、展開した枝は `aria-expanded`、今日の日付は `aria-current="date"`、スプリッターの向きは `aria-orientation` で表します。配置やアニメーションも CSS が担当し、空の状態など CSS だけで判定できるものは `:has()` を使います。
- **スクリプトは入力を受け取って状態を更新します。** パッケージには、各コントラクトに記載されたキー操作をテスト済みのリファレンス実装として[ビヘイビア](/guide/behaviors)が付属します。ビヘイビアはネイティブ属性と ARIA 属性を更新し、ポインターの位置など CSS から取得できない値をカスタムプロパティで渡すこともあります。質感と配置のルールは CSS が担います。
- **対応するコンテナーにはネイティブ要素を使います。** コマンドパレットは `command="show-modal"` で開く `<dialog>` です。日付ピッカーのカレンダーは `popover` に入り、スクリプトなしのツリーは `<details>` を入れ子にします。

これらの属性に沿ったマークアップがコントラクトです。そのため、テンプレート、フレームワークコンポーネント、エージェントのどれがマークアップを生成しても、同じように動作します。

## React、Svelte、Vue で使う \{#in-a-framework\}

ライブラリの大部分は、フレームワークの構文でネイティブ要素にクラスを付ければ、HTML と同じように使えます。`btn btn-primary` に別名を付けるだけの `<Button>` では機能が増えず、[チェッカー](/guide/ai#check-the-markup)がクラスを読み取れなくなります。

フレームワークコンポーネントを用意するのは、アプリが読み書きする値、データから生成する行、複数の要素を結び付ける ID、ライフサイクルなどをフレームワーク側で管理する場合に限ります。前述のパターンに加え、状態に応じて開くダイアログ、トーストのキュー、ラベルとエラー表示を伴う入力欄などが該当します。各コンポーネントはコントラクトに沿ってマークアップを生成し、パッケージのビヘイビアを取り付けます。コンポーネントのソースは `npx master-ui add combobox` などでプロジェクトにコピーできます。一覧は [React、Svelte、Vue](/guide/frameworks) を参照してください。

## アルファ版の公開範囲 \{#what-comes-next\}

コントラクト、スタイルシート、ビヘイビア、2 つ目のテーマ、チェッカー、コピーできるソースの[レジストリ](/guide/registry)、状態を持つパターン向けの React、Svelte、Vue コンポーネントを公開しています。フレームワークコンポーネントの配布形態は、`@master/ui` に同梱するソースのみです。操作の共通ロジックはビヘイビアに置き、各フレームワークコンポーネントは描画とライフサイクルを担当します。公開範囲と変更される可能性がある箇所は[安定性](/guide/stability)を参照してください。

[インストール](/guide/installation)を済ませたら、[コンポーネントの選び方](/guide/choosing)や[コンポーネント一覧](/components)に進んでください。
