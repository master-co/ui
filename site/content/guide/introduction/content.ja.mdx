Master UI は、HTML インターフェースに共通のコンポーネントクラス、デザイントークン、ドキュメント化された状態を提供します。`<button class="btn">` のようなネイティブのマークアップを書き、同じクラスをサーバーテンプレート、React、Svelte、Vue で使えます。パッケージは CSS、マークアップのコントラクト、そしてスクリプトを必要とするパターン向けのスクリプトを提供します。

マークアップを自分で制御しつつ、コンポーネントの見た目と振る舞いをプロジェクト全体で共有したいときに使ってください。既定の moonstone と obsidian のテーマから始め、そのトークンを調整することも、コンポーネントのソースをプロジェクトに取り込むこともできます。Master UI は実験段階です。[インストールしたバージョンを固定し、アップグレードを確認してください](/guide/stability#experimental)。

## コントラクトと実装 \{#a-contract-and-an-implementation\}

コントラクトは、スタイルシートが理解するマークアップ、つまりクラス、要素、状態属性、公開カスタムプロパティを記述します。人とコーディングエージェントが同じ語彙を使えるようにし、よくある誤りを確認する手段にもなります。実装は実際の見た目と振る舞いを提供します。

<GuideFigure name="introduction" title="マークアップ、コントラクト、実装">

**コントラクトはマークアップと実装を結び付けます。** ボタンの `btn` クラスは、HTML と CSS で同じインターフェースを指します。コントラクトは要素、状態属性、公開プロパティも記述します。テーマを変更するとマテリアルの値は置き換わりますが、それらの名前は引き続き使えます。スクリプトを必要とするパターンでは、入力が属性を変更し、CSS がその結果の状態を描画します。

</GuideFigure>

| 要素 | 提供するもの | 使い方 |
| --- | --- | --- |
| [コントラクト](/guide/contracts) | 各スタイルシートの隣に置かれる JSON の記述。正しい例を含みます | マークアップを書く前に、インストール済みのコントラクトを読みます |
| 実装 | コントラクトを描画するスタイルシート | [トークン、テーマ、または独自のコピー](/guide/customization)で調整します |
| [ビヘイビア](/guide/behaviors) | キーボード、値、フォーカスの処理を必要とするパターン向けのリファレンススクリプト | 直接アタッチするか、提供されるフレームワークコンポーネントを通じてアタッチします |
| チェック | チェッカーが読み取れるマークアップに対する静的診断 | 編集後と CI で実行し、その後レンダリングされたインターフェースを確認します |

コントラクトは閉じています。コントラクトに記載がない限り `btn-outline` は存在せず、それでも書かれた場合はチェッカーが報告します。実装は開かれています。トークンで調整することも、[テーマ](/guide/theming)でマテリアルを置き換えることも、コンポーネントのソースをプロジェクトに取り込むこともできます。トークンやテーマの変更では、コントラクトはそのまま保たれます。コンポーネントを自分で所有し、その構造や状態を変更する場合は、ローカルのコントラクトと利用側を一緒に更新してください。エージェントが何を読み、何を実行するかは [AI との協働](/guide/ai)で説明しています。

## 全体の構成 \{#how-it-fits-together\}

| レイヤー | 所有者 | 例 |
| --- | --- | --- |
| デザイントークン | Master CSS のプリセットと `@master/ui/theme.css` | `--color-surface-raised`、`--shadow-raised` |
| コンポーネントのスタイル | `@master/ui` | `.btn`、`.btn-primary`、`.input` |
| レイアウトクラス | `@master/ui` | `.page`、`.shell`、`.auto-grid`、`.form` |
| ローカルの調整 | あなたのマークアップ | `w-full`、`mt-md`、`px-lg` |

コンポーネントクラスは `components` レイヤーに、ユーティリティはその後の `utilities` レイヤーに置かれます。そのため、1 つのインスタンスに付けたユーティリティは、`!important` やセレクターの工夫なしに常に優先されます。

```html
<button type="button" class="btn btn-primary w-full">Save changes</button>
```

## コンポーネント、レイアウト、ブロック、ページ \{#tiers\}

ライブラリは、部品から画面全体まで 4 つの階層で構成されています。階層を分けるのは大きさではありません。クラスの背後に置く価値のある知識があるかどうかです。

| 階層 | 何であるか | 公開の形 |
| --- | --- | --- |
| [コンポーネント](/components) | マテリアル、状態、プラットフォームの振る舞い、または部品間で共有するジオメトリーを持つ部品 | `@master/ui` のセマンティックなクラス |
| [レイアウト](/components#layouts) | 領域内のスペースをどう配置するか。スタック、自動グリッド、ベントー、メイソンリー、図版がはみ出すカラムなど | ユーティリティ。ユーティリティで表せない場合はレイアウトクラス。コンポーネントと一緒に掲載されています |
| [ブロック](/blocks) | 目的を持つページの一区間。ヒーロー、料金表、フッターなど | コピーして使うマークアップ。コンポーネントとユーティリティを組み合わせたもの |
| [ページ](/pages) | 画面全体。領域をどこに置き、何をスクロールさせるか | コピーして使うマークアップ。`page` と `shell` の 2 つのフレームのいずれかの上に構成されます |

次の 4 種類の知識のうち少なくとも 1 つを持つものが、クラスに値します。

1. **マテリアル。** マテリアルの段階に沿う必要がある面、輪郭、影、角。
2. **状態。** ネイティブ属性または ARIA から読み取るホバー、フォーカス、選択、開閉、無効、不正。
3. **プラットフォームの振る舞い。** アンカー位置指定、スクロール状態クエリー、トップレイヤーへの登場など、ユーティリティでは書けないもの。
4. **部品間で共有するジオメトリー。** インセットに応じて入れ子になる角や、サイズが親に追従する子要素。

ボタンはマテリアル、状態、ジオメトリーを組み合わせたものです。リンクを列に並べたフッターには新しいコンポーネントクラスは不要で、ユーティリティで構築するブロックです。ここから 3 つのルールが導かれます。

- **コンポーネントはページを所有しません。** 自分の位置を決めることはありません。ただし、その位置にあることが振る舞いそのものである場合は例外です。ナビゲーションバーは固定され、ダイアログはトップレイヤーに入ります。
- **レイアウトはマテリアルを所有しません。** 領域とスクロールを決めます。それらの領域内の面はシート、トレイ、カードです。
- **クラスにする基準は繰り返しではなく知識です。** 繰り返されるマークアップは、名前を付けるのではなくコピーします。

いくつかのレイアウトは、`dvh` 単位の高さ、スマートフォンのセーフエリア、コンテナーのしきい値、グリッドトラックのリストなど、ユーティリティでは表せないものを持っています。それらがレイアウトクラスです。2 つのフレーム [`page`](/pages/page) と [`shell`](/pages/app-shell)、そして [`auto-grid`](/components/auto-grid)、[`bento`](/components/bento)、[`masonry`](/components/masonry)、[`breakout`](/components/breakout)、[`sticky-stack`](/components/sticky-stack)、[`form`](/components/form) です。

## 原則 \{#principles\}

- **ネイティブ要素を優先。** コンポーネントは、すでに適切なセマンティクスを持つ要素を使い、可能な限りそのネイティブの振る舞いを保ちます。ネイティブ要素がないパターンでは、スタイルシートが ARIA から状態を描画し、[小さなスクリプトがその状態を動かします](#patterns-that-need-a-script)。
- **スクリプトよりプラットフォーム。** ブラウザーが単独でできるようになったことを、コンポーネントが再実装することはありません。後述の[プラットフォーム](#the-platform)を参照してください。
- **装飾ではなく光。** 浮き上がった面は一筋の光を受け、消えていく短い影の上に載ります。ウェルは周囲より沈み込みます。状態は色ではなく奥行きで表し、エッジは柔らかくします。[既定のテーマ](/guide/theme)を参照してください。
- **ハードコードした値ではなくトークン。** サーフェス、線、エレベーション、角丸、モーションはテーマトークンから取得し、独自の色を書いたコンポーネントはテストで失敗します。トークンを一度上書きするだけで、すべてのコンポーネントを調整できます。
- **小さな公開語彙。** ベースクラス、`btn-primary` や `btn-sm` のような少数の修飾クラス、そして `--btn-height` のようなドキュメント化されたカスタムプロパティです。
- **1 つのスタイルシートでライトとダーク。** セマンティックトークンはページのカラースキームに従い、`light-dark()` で解決されます。

## プラットフォーム \{#the-platform\}

ネイティブ要素は、すでにサポートしている処理を担います。チェックボックスはチェック状態の値を保持し、セレクトはフォームに参加し、モーダルダイアログは背後のページを操作不能にします。Master UI はそれらの属性と状態にスタイルを適用します。

スタイルシートには、それでもブラウザーのベースラインがあります。カスケードレイヤー、ネスト、`light-dark()` などの機能は必須です。アンカー位置指定や連続曲率の角などの任意の機能は、動作するベースラインを強化するものです。フォールバックの中にはアプリケーションのコードを必要とするものもあります。invoker commands に対応していないブラウザーでは、`dialog.showModal()` を呼び出すクリックハンドラーが必要です。

ベースライン、エンハンスメントのフォールバック、アプリケーションで使う機能のテスト方法については[ブラウザーサポート](/guide/browser-support)を参照してください。各コンポーネントのページでは、例の横に該当するフォールバックを示しています。

## スクリプトを必要とするパターン \{#patterns-that-need-a-script\}

いくつかのパターンには、まだネイティブ要素がありません。[コンボボックス](/components/combobox)、[コマンドパレット](/components/command)、[カレンダー](/components/calendar)、矢印キーでたどる[ツリー](/components/tree)、[コンテキストメニュー](/components/menu#context-menu)、自動で次へ進む [OTP フィールド](/components/otp)、2 つのペインの間でドラッグする[スプリッター](/components/splitter)、その場でパネルを切り替える[タブ](/components/tabs#tab-panels)などです。Master UI はそれらにもそれぞれ 1 つのスタイルシートを提供します。役割分担は常に同じです。

- **スタイルシートはすべての状態を ARIA から描画します。** アクティブなオプションには `aria-selected`、選択済みのものには `aria-checked`、開いたブランチには `aria-expanded`、今日には `aria-current="date"`、スプリッターの向きには `aria-orientation` を使います。また、サーフェスの配置とアニメーションを行い、空の状態など導き出せるものは `:has()` で導き出します。
- **スクリプトは入力を処理し、状態を更新します。** パッケージにはリファレンスの[ビヘイビア](/guide/behaviors)が同梱されており、それぞれのコントラクトに記載されたキーに対してテストされています。ビヘイビアはネイティブ属性と ARIA 属性を更新します。ポインターの位置など CSS が導き出せない値は、カスタムプロパティ経由で渡されることがあります。マテリアルと配置のルールは CSS が担います。
- **ネイティブのコンテナーがある場合は、それを使います。** コマンドパレットは `command="show-modal"` で開く `<dialog>` です。日付ピッカーのカレンダーは `popover` の中に置かれます。スクリプトなしのツリーは入れ子の `<details>` です。

これらの属性に沿って書かれたマークアップがコントラクトであり、テンプレート、フレームワークコンポーネント、エージェントなど、何がレンダリングしても動作し続けます。

## React、Svelte、Vue では \{#in-a-framework\}

ライブラリの大部分は、フレームワークでも素のページでも同じです。ネイティブ要素に付けるクラスを、フレームワーク自身の構文で書くだけです。`btn btn-primary` を名前だけ変えた `<Button>` は何も付け加えず、クラスを[チェッカー](/guide/ai#check-the-markup)から隠してしまいます。

フレームワークコンポーネントは、フレームワークが何かを所有する場合にのみ存在します。アプリケーションが読み書きする値、データからレンダリングする行、あるパーツを別のパーツと結び付ける ID、またはライフタイムです。上記のパターン、状態から開くダイアログ、トーストのキュー、ラベルとエラーを伴うフィールドなどがその例です。それぞれがコントラクトのマークアップをレンダリングしてビヘイビアをアタッチし、ビヘイビア自体はパッケージに残ります。コンポーネント自体は、`npx master-ui add combobox` でプロジェクトにコピーするソースです。一覧は [React、Svelte、Vue](/guide/frameworks) にあります。

## このアルファ版で公開しているもの \{#what-comes-next\}

コントラクト、スタイルシート、ビヘイビア、2 つ目のテーマ、チェッカー、コピーして使うソースの[レジストリ](/guide/registry)、そして状態を持つパターン向けの React、Svelte、Vue コンポーネントです。フレームワークコンポーネントは、個別のバインディングパッケージではなく、`@master/ui` 内のソースとして提供されます。共通のインタラクションロジックはビヘイビアに残り、各フレームワークコンポーネントは自身のレンダリングとライフタイムを扱います。何が公開されていて何が変わる可能性があるかは[安定性](/guide/stability)に記載しています。

続いて[インストール](/guide/installation)に進み、その後[コンポーネントを選ぶ](/guide/choosing)か、[コンポーネント](/components)を一覧してください。
