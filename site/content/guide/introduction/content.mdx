Master UI is a set of interface components written as native HTML and CSS, in one material language: moonstone in light mode, obsidian in dark mode, lit from above, with half-pixel contours, short shadows that fade and corners that turn with continuous curvature. Each component is one stylesheet in `@layer components` that reads [Master CSS](https://css.master.co) design tokens, plus the semantic markup that uses it.

You copy the markup, not a dependency on a framework. A button is a `<button>`, a switch is a checkbox with `role="switch"`, a select is a real `<select>` and a dialog is a `<dialog>` opened by a button with `command="show-modal"`. Browsers keep their keyboard, form and accessibility behavior; Master UI supplies the appearance.

## How it fits together \{#how-it-fits-together\}

| Layer | Owner | Example |
| --- | --- | --- |
| Design tokens | Master CSS preset and `@master/ui/theme.css` | `--color-surface-raised`, `--shadow-raised` |
| Component styles | `@master/ui` | `.btn`, `.btn-primary`, `.input` |
| Local adjustments | Your markup | `w-full`, `mt-md`, `px-lg` |

Component classes live in the `components` layer and utilities in the later `utilities` layer, so a utility on one instance always wins without `!important` or selector tricks:

```html
<button type="button" class="btn btn-primary w-full">Save changes</button>
```

## Principles \{#principles\}

- **Native elements first.** Components style the element that already has the right semantics, so they work without JavaScript. Where a pattern has no native element, the stylesheet draws its states from ARIA and [the behavior is yours](#patterns-that-need-a-script).
- **The platform before script.** What a browser can now do by itself, a component does not reimplement. See [the platform](#the-platform) below.
- **Light, not decoration.** Raised faces catch a line of light and settle on short shadows that fade; wells sink below their surroundings. State is depth, not color, and edges are soft. See the [theme](/guide/theme).
- **Tokens, not hard-coded values.** Surfaces, lines, elevation, radii and motion come from theme tokens; override them once to retune every component.
- **Small public vocabulary.** A base class, a few modifier classes such as `btn-primary` and `btn-sm`, and documented custom properties such as `--btn-height`.
- **Light and dark from one stylesheet.** Semantic tokens resolve with `light-dark()`, following the page's color scheme.

## The platform \{#the-platform\}

Each component uses the web platform's own feature for its job and treats it as an enhancement: a browser without the feature gets a working component, plainer.

| Job | Platform feature | Used by | Without it |
| --- | --- | --- | --- |
| Open and close overlays | `<dialog>`, `popover`, `command` and `commandfor` | [Dialog](/components/dialog), [popover](/components/popover), [menu](/components/menu) | Call `showModal()` or `showPopover()` from a handler |
| Show a label on hover and focus | `popover="hint"` and `interestfor` | [Tooltip](/components/tooltip) | The control keeps its accessible name |
| Place a floating surface | CSS anchor positioning | Popover, menu, tooltip, [select](/components/select) | It appears centered, as the browser places a popover |
| Move one indicator between options | `anchor-name` and `anchor-scope` | [Segmented control](/components/segmented), [tabs](/components/tabs) | Each option draws its own state |
| Draw the option list | `appearance: base-select` | Select | The platform's own list |
| Adapt to the space given | `@container` | [Card](/components/card), dialog, [form](/components/form), [navbar](/components/navbar) | Not needed: it is supported everywhere |
| Read a state in a descendant | `:has()` | [Input group](/components/input#input-group), field, segmented control | Not needed: it is supported everywhere |
| Grow with the content | `field-sizing: content` | [Textarea](/components/input#textarea) | A resize handle |
| Animate in and out | `@starting-style`, `transition-behavior: allow-discrete` | Every overlay | It appears and leaves at once |
| Open to an unknown height | `interpolate-size`, `::details-content` | [Accordion](/components/accordion), [banner](/components/banner) | It opens at once |
| Show the first lines of a closed text | `::details-content` | [Expand](/components/expand) | The text is hidden while closed |
| Validate without script | `:user-invalid` | [Input](/components/input#native-validation) | Use `aria-invalid` |
| Fill a track up to its thumb | Scroll-driven animations | [Slider](/components/slider) | The track stays a well |
| Fade an edge where content continues | Scroll-driven animations | [Scroll area](/components/scroll-area) | Clean edges |
| Previous, next and a dot per slide | `::scroll-button()`, `::scroll-marker` | [Carousel](/components/carousel) | A swipeable, scrollable row |
| Dismiss a message, or let it leave | `<dialog>`, `display` in keyframes | [Toast](/components/toast) | It stays until dismissed |
| Fill stars and complete steps | `:has()` with a sibling | [Rating](/components/rating), [steps](/components/steps) | Not needed: it is supported everywhere |
| Turn a corner with continuous curvature | `corner-shape` | Every component | Circular corners at the same apparent size |
| Open a list under a whole field, at its width | `anchor-scope`, `anchor-size()` | [Combobox](/components/combobox) | Centered, as the browser places a popover |
| Keep a menu on screen at the pointer | `@position-try` | [Context menu](/components/menu#context-menu) | It opens down and to the end |
| Share columns between rows without a table | `subgrid` | [Calendar](/components/calendar), [data list](/components/data-list) | Not needed: it is supported everywhere |
| Show an empty state when a filter hides every option | `:has()` with `:not([hidden])` | [Listbox](/components/listbox#filtering) | Not needed: it is supported everywhere |
| Color a reading by its thresholds | `<meter>` with `low`, `high`, `optimum` | [Meter](/components/meter) | The platform's own meter |
| Draw a value written once, in an attribute | Typed `attr()` | [Progress ring](/components/progress#ring) | Set a custom property beside it |
| Give a sticky bar its material only once it is stuck | `container-type: scroll-state` | [Navbar](/components/navbar) | The material is always drawn |
| Mark the section in view | `scroll-target-group`, `:target-current` | [Table of contents](/components/toc) | Set `aria-current` from a script |
| Show how far the page has scrolled | A scroll timeline on the root | [Navbar](/components/navbar#progress) | No progress line |
| Start siblings one after another | `sibling-index()` | [Skeleton](/components/skeleton) | They start together |

## Patterns that need a script \{#patterns-that-need-a-script\}

A few patterns have no native element yet: a [combobox](/components/combobox), a [command palette](/components/command), a [calendar](/components/calendar), a [tree](/components/tree) walked with the arrow keys, a [context menu](/components/menu#context-menu), an [OTP field](/components/otp) that moves on by itself, a [splitter](/components/splitter) dragged between two panes. Master UI still gives them one stylesheet each. The division of work is the same every time:

- **The stylesheet draws every state from ARIA**: `aria-selected` for the active option, `aria-checked` for a chosen one, `aria-expanded` for an open branch, `aria-current="date"` for today, `aria-orientation` for the way a splitter runs. It also places and animates the surface, and derives what it can, such as an empty state, with `:has()`.
- **Your script or framework moves the attributes.** It never sets a style or measures a position. Each page shows the smallest script that drives the component, so the behavior is yours to keep or replace.
- **The container is native wherever one exists.** A command palette is a `<dialog>` opened by `command="show-modal"`; a date picker's calendar sits in a `popover`; a tree without script is nested `<details>`.

Markup written against these attributes is what the framework bindings will render, so it keeps working when they arrive.

## What comes next \{#what-comes-next\}

This alpha publishes the native HTML and CSS layer. Framework bindings for React, Svelte and Vue, and a copy-in registry in the style of shadcn/ui, are being designed on top of the same stylesheets, so markup written today keeps working.
