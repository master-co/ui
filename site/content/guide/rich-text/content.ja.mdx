Master UI には独自のエディターはありません。書式付きテキストの編集、つまりドキュメントモデル、選択範囲、履歴、貼り付け、入力メソッドによる未確定入力の処理は、大規模なエンジンの仕事であり、優れたエンジンがすでに存在します。Master UI がそのようなエンジンに提供するのは枠組みです。[`editor`](/components/editor) コントラクトが、ウェル、ツールバーの帯、状態、ドキュメントの内容を描画するため、リッチテキストフィールドもページ上のほかのフィールドと同じ見た目と振る舞いになります。このガイドでは、プレーンな JavaScript から [TipTap](https://tiptap.dev/docs/editor/getting-started/install/vanilla-javascript) を組み込みます。

## 役割分担 \{#who-does-what\}

| | 担当 |
| --- | --- |
| TipTap | ドキュメントとそのスキーマ、選択範囲、元に戻すとやり直し、キー操作とショートカット、貼り付け、入力メソッド、編集可能にする要素 |
| `editor` | 枠組みとその状態、ツールバーの帯、ドキュメントの大きさ、段落、見出し、リスト、引用、リンク、区切り線の見た目 |
| [`toolbar`](/components/toolbar) とそのビヘイビア | コントロール全体で 1 つのタブストップ、コントロール間の矢印キーでの移動、押された状態のボタン |
| ページ | 両者の接続。ボタンが実行するコマンド、ボタンの状態、値の送り先 |

`@master/ui` はどのエディターにも依存しておらず、エディターを包む React、Svelte、Vue のコンポーネントもありません。この例はサイト独自のもので、TipTap はサイトの依存関係です。例をコピーするか、ProseMirror、Lexical などのエンジンで同じ手順をたどってください。コントラクトは変わりません。

## エンジンを枠組みに入れる \{#frame\}

TipTap は要素を編集可能にし、その中にドキュメントを書き込みます。その要素に、フィールドのコントロールと同じロール、名前、説明とともに `editor-document` を付けるよう TipTap に指定し、描画するノードにエディターのクラスを書き込ませます。`editor` のスタイルシートは要素名で選択しないため、見出しにスタイルが付くのは `h2` だからではなく、`editor-heading` を持っているからです。インラインのコードとコードブロックには、ライブラリー自身の[コード](/components/code)のクラスを使います。

```js name=main.js
const editor = new Editor({
  element: root.querySelector('[data-editor]'),
  content: notes,
  extensions: [
    StarterKit.configure({
      heading: { levels: [2, 3] },
      paragraph: { HTMLAttributes: { class: 'editor-paragraph' } },
      bulletList: { HTMLAttributes: { class: 'editor-list' } },
      orderedList: { HTMLAttributes: { class: 'editor-list editor-list-numbered' } },
      listItem: { HTMLAttributes: { class: 'editor-item' } },
      blockquote: { HTMLAttributes: { class: 'editor-quote' } },
      code: { HTMLAttributes: { class: 'code' } },
      codeBlock: { HTMLAttributes: { class: 'code-block' } },
      horizontalRule: { HTMLAttributes: { class: 'editor-rule' } },
      link: { openOnClick: false, autolink: true, defaultProtocol: 'https', HTMLAttributes: { class: 'editor-link' } },
    }),
    headingClass,
  ],
  editorProps: {
    attributes: { class: 'editor-document', role: 'textbox', 'aria-multiline': 'true', 'aria-labelledby': 'rich-text-label', 'aria-describedby': 'rich-text-hint rich-text-error' },
  },
})
```

見出しはレベルを表す属性を描画しないため、小さな拡張機能（この例では `headingClass`）で各レベルにクラスを付けます。2 番目のレベルには `editor-heading`、3 番目のレベルには `editor-subheading` です。ドキュメントは `--editor-rows` 行（既定は 6 行）から `--editor-max-rows` 行まで伸び、それを超えるとスクロールします。

## ツールバーをつなぐ \{#toolbar\}

ツールバーは `editor-toolbar` を付けた[ツールバー](/components/toolbar)で、ウェルの上部に平らに配置されます。ツールバーのビヘイビアにより、ツールバー全体が 1 つのタブストップになり、内部のコントロール間を矢印キーで移動できます。ボタンの押された状態は `aria-pressed` で示します。各ボタンが何を行い、何を伝えるかはページが決めます。

- **押すとコマンドを実行し、フォーカスを戻します。** `editor.chain().focus().toggleBold().run()` を実行すると、読み手は TipTap が保持していた選択範囲とともに、書いていたドキュメントに戻ります。
- **選択範囲によって押された状態が決まります。** トランザクションのたびに、各ボタンの `aria-pressed` を `editor.isActive(...)` の結果にします。そのため、キャレットが太字のテキストの中にあれば「太字」は押された状態になり、テキストスタイルの選択欄にはキャレットがあるブロックの種類が表示されます。
- **実行できないものは無効にします。** `editor.can()` はコマンドを試験的に実行します。取り消せる操作がなければ「元に戻す」を無効にし、エディターが読み取り専用または無効のときはすべてのコントロールを無効にします。
- **リンクはプロンプトではなく小さなフォームです。** リンクボタンは、URL フィールドを備えた[ポップオーバー](/components/popover)を開きます。アドレスはフィールド自体の検証で確認します。「適用」は選択範囲にリンクを設定し、何も選択されていなければリンクをテキストとして挿入します。「削除」はリンクを解除します。TipTap は `javascript:` などのアドレスを拒否し、リンクには `rel="noopener noreferrer nofollow"` が付きます。

アイコンボタンにはそれぞれ名前を付け、TipTap がすでに処理しているショートカットを `aria-keyshortcuts` に指定します。これにより、スクリーンリーダーが両方を読み上げられます。

## 状態 \{#states\}

| 状態 | 目印 | この例での設定方法 |
| --- | --- | --- |
| フォーカス | `editor-document` の `:focus` | ドキュメントにフォーカスがあるとき、ブラウザーが設定します。フレームはフィールドのハローとともに浮き上がります |
| 無効な内容 | `editor-document` の `aria-invalid="true"` | 空のままにした場合です。読み手が再び書き始めるまで、フレームに危険色の縁が付き、フィールドの `field-error` が表示されます |
| 読み取り専用 | `editor-document` の `aria-readonly="true"` | `editor.setEditable(false)` と属性で設定します。文章は読むこともコピーすることもできます |
| 無効 | `editor` の `aria-disabled="true"` | `editor.setEditable(false)`、属性、すべてのコントロールの無効化で設定します |

状態は TipTap が要素に保持する属性です。要素に直接設定せず、`editor.setOptions({ editorProps: { attributes } })` で設定してください。直接設定すると、次の描画で取り除かれます。

## 値 \{#value\}

TipTap のドキュメントはデータです。アプリケーションが保存するのは `editor.getJSON()` の結果で、保存したドキュメントは `editor.commands.setContent(json)` で読み込みます。**別のメモを読み込む** と **リセット** はこの方法で読み込みます。この例では JSON を `textContent` で書き出すため、読み手が入力したものがマークアップとしてページに挿入されることはありません。エディターの外で内容を HTML として表示する必要がある場合は、サーバーでサニタイザーを通して JSON から描画します。

保存や検証には `update` を、ツールバーの描画には `transaction` を監視します。どちらもドキュメントを変更しません。ページはドキュメントに独自のキーハンドラーを追加しません。日本語、中国語、韓国語の入力メソッドは、文字の確定前に Enter キーや矢印キーを使います。TipTap は入力が未確定かどうかを認識します。検証はキー操作ではなく `blur` で行います。

## 破棄する \{#destroy\}

エディターは、リスナー、ビュー、履歴を保持しています。`mount()` が返す関数は、ツールバーのビヘイビアを解除し、ページのリスナーを削除し、`editor.destroy()` を呼び出します。フレームワークがコンポーネントをアンマウントするときと同じように、フィールドがページからなくなるときに呼び出してください。

## この例で扱わないもの \{#leaves-out\}

- **選択範囲に追従するツールバー。** 選択した文字の上に浮かぶツールバーには、選択範囲が描画される位置を追跡する仕組みが必要です。これは TipTap の `BubbleMenu` 拡張機能とその配置処理の役割で、このガイドではツールバーを固定しています。
- **メンション、テーブル、画像、共同編集。** それぞれが TipTap の拡張機能と独自のインターフェースです。
- **Markdown の入出力。** JSON をサーバーで変換してください。
