Master UI에는 자체 에디터가 없습니다. 서식 있는 텍스트 편집, 즉 문서 모델, 선택 영역, 실행 기록, 붙여넣기, 입력기의 글자 조합은 대규모 엔진이 할 일이며, 이미 좋은 엔진이 있습니다. Master UI는 그런 엔진에 틀을 제공합니다. [`editor`](/components/editor) 계약이 편집 영역, 도구 모음, 상태, 문서 콘텐츠의 모양을 정하므로, 서식 있는 텍스트 필드가 페이지의 다른 모든 필드와 같은 모양과 동작을 갖습니다. 이 가이드에서는 일반 JavaScript로 [Tiptap](https://tiptap.dev/docs/editor/getting-started/install/vanilla-javascript)을 이 틀에 넣습니다.

## 역할 분담 \{#who-does-what\}

| | 담당 |
| --- | --- |
| Tiptap | 문서와 스키마, 선택 영역, 실행 취소와 다시 실행, 키와 단축키, 붙여넣기, 입력기, 편집 가능하게 만드는 요소 |
| `editor` | 틀과 상태, 도구 모음 영역, 문서 크기, 문단·제목·목록·인용문·링크·구분선의 모양 |
| [`toolbar`](/components/toolbar)와 그 동작 | 컨트롤을 Tab 키 이동 순서에서 한 지점으로 묶기, 컨트롤 사이의 방향키 이동, 눌린 버튼 |
| 페이지 | 둘을 연결하는 일: 각 버튼이 실행하는 명령, 버튼의 상태, 값을 보낼 곳 |

`@master/ui`는 어떤 에디터에도 의존하지 않으며, 에디터를 감싸는 React, Svelte, Vue 컴포넌트도 없습니다. 이 예제는 사이트 자체의 예제이며 Tiptap은 사이트의 의존성입니다. 예제를 복사하거나, 같은 방식으로 ProseMirror, Lexical 등 다른 엔진을 적용하세요. 계약은 바뀌지 않습니다.

## 엔진을 틀에 넣기 \{#frame\}

Tiptap은 요소를 편집 가능하게 만들고 그 안에 문서를 작성합니다. 그 요소에 필드의 컨트롤이 갖는 역할, 이름, 설명과 함께 `editor-document`를 지정하도록 하고, 렌더링하는 노드에 에디터의 클래스를 작성하도록 Tiptap을 설정하세요. `editor` 스타일시트는 요소를 직접 선택하지 않으므로, 제목은 `h2`이기 때문이 아니라 `editor-heading`이 있기 때문에 스타일이 적용됩니다. 인라인 코드와 코드 블록에는 라이브러리의 [코드](/components/code) 클래스를 사용합니다.

```js name=main.js
const editor = new Editor({
  element: root.querySelector('[data-editor]'),
  content: notes,
  extensions: [
    StarterKit.configure({
      heading: { levels: [2, 3] },
      paragraph: { HTMLAttributes: { class: 'editor-paragraph' } },
      bulletList: { HTMLAttributes: { class: 'editor-list' } },
      orderedList: { HTMLAttributes: { class: 'editor-list editor-list-numbered' } },
      listItem: { HTMLAttributes: { class: 'editor-item' } },
      blockquote: { HTMLAttributes: { class: 'editor-quote' } },
      code: { HTMLAttributes: { class: 'code' } },
      codeBlock: { HTMLAttributes: { class: 'code-block' } },
      horizontalRule: { HTMLAttributes: { class: 'editor-rule' } },
      link: { openOnClick: false, autolink: true, defaultProtocol: 'https', HTMLAttributes: { class: 'editor-link' } },
    }),
    headingClass,
  ],
  editorProps: {
    attributes: { class: 'editor-document', role: 'textbox', 'aria-multiline': 'true', 'aria-labelledby': 'rich-text-label', 'aria-describedby': 'rich-text-hint rich-text-error' },
  },
})
```

제목은 수준을 나타내는 속성을 렌더링하지 않으므로, 예제의 `headingClass` 같은 작은 확장이 수준마다 클래스를 지정합니다. 두 번째 수준에는 `editor-heading`을, 세 번째 수준에는 `editor-subheading`을 지정합니다. 문서는 `--editor-rows`줄(기본값 6줄)에서 `--editor-max-rows`줄까지 늘어난 뒤 스크롤됩니다.

## 도구 모음 연결 \{#toolbar\}

도구 모음은 `editor-toolbar`를 지정한 [도구 모음](/components/toolbar)이며, 편집 영역 상단에 붙여 배치합니다. 도구 모음 동작은 이를 Tab 키 이동 순서에서 한 지점으로 만들어 방향키로 이동할 수 있게 하고, 버튼을 `aria-pressed`로 눌린 상태로 표시합니다. 각 버튼이 무엇을 하고 무엇을 알려 주는지는 페이지가 결정합니다.

- **버튼을 누르면 명령을 실행하고 포커스를 되돌립니다.** `editor.chain().focus().toggleBold().run()`을 실행하면 독자는 Tiptap이 유지한 선택 영역과 함께 작성하던 문서로 돌아갑니다.
- **선택 영역이 눌린 상태를 결정합니다.** 트랜잭션마다 각 버튼의 `aria-pressed`를 `editor.isActive(...)`로 설정하므로, 캐럿이 굵은 텍스트 안에 있으면 어디서든 굵게 버튼이 눌린 상태로 읽히고, 텍스트 스타일 선택 메뉴에는 캐럿이 속한 블록의 스타일이 표시됩니다.
- **실행할 수 없는 것은 비활성화합니다.** `editor.can()`은 문서를 변경하지 않고 명령을 실행할 수 있는지 확인합니다. 실행 취소할 내용이 없으면 실행 취소 버튼이 비활성화되고, 에디터가 읽기 전용이거나 비활성화되면 모든 컨트롤이 비활성화됩니다.
- **링크는 프롬프트가 아니라 작은 폼입니다.** 링크 버튼은 URL 필드가 있는 [팝오버](/components/popover)를 엽니다. 필드 자체의 유효성 검사가 주소를 확인하고, 적용 버튼은 선택 영역에 링크를 적용하거나 선택 영역이 없으면 주소를 텍스트로 삽입합니다. 제거 버튼은 링크를 제거합니다. Tiptap은 `javascript:` 같은 주소를 거부하며, 링크에는 `rel="noopener noreferrer nofollow"`가 지정됩니다.

각 아이콘 버튼에 이름을 지정하고, Tiptap이 이미 처리하는 단축키를 `aria-keyshortcuts`로 지정하세요. 그러면 스크린 리더가 둘 다 알려 줄 수 있습니다.

## 상태 \{#states\}

| 상태 | 표시 | 예제에서 설정하는 방법 |
| --- | --- | --- |
| 포커스 | `editor-document`의 `:focus` | 문서에 포커스가 있으면 브라우저가 설정합니다. 틀이 필드의 포커스 링과 함께 강조됩니다. |
| 유효하지 않음 | `editor-document`의 `aria-invalid="true"` | 내용이 비어 있으면 틀에 오류 상태를 나타내는 테두리가 표시되고 필드의 `field-error`가 나타나며, 독자가 다시 작성할 때까지 유지됩니다. |
| 읽기 전용 | `editor-document`의 `aria-readonly="true"` | `editor.setEditable(false)`와 속성. 텍스트를 읽고 복사할 수 있습니다. |
| 비활성화 | `editor`의 `aria-disabled="true"` | `editor.setEditable(false)`, 속성, 모든 컨트롤 비활성화 |

상태는 Tiptap이 자신의 요소에 유지하는 속성입니다. 요소에 직접 설정하지 말고 `editor.setOptions({ editorProps: { attributes } })`로 설정하세요. 그렇지 않으면 다음 렌더링에서 사라집니다.

## 값 \{#value\}

Tiptap의 문서는 데이터입니다. 애플리케이션은 `editor.getJSON()`의 반환값을 저장하고, **다른 메모 불러오기**와 **초기화** 버튼처럼 `editor.commands.setContent(json)`으로 저장된 문서를 불러옵니다. 예제는 JSON을 `textContent`로 작성하므로, 독자가 입력한 내용이 마크업으로 페이지에 들어가지 않습니다. 에디터 밖에서 콘텐츠를 HTML로 표시해야 한다면 서버에서 JSON으로 HTML을 렌더링하고 새니타이저를 거치게 하세요.

저장이나 유효성 검사에는 `update`를, 도구 모음을 그릴 때는 `transaction`을 수신하세요. 둘 다 문서를 바꾸지 않습니다. 페이지는 문서에 별도의 키 처리기를 추가하지 않습니다. 일본어, 중국어, 한국어를 조합하는 입력기는 Enter 키와 방향키를 사용하며, Tiptap은 글자 조합이 진행 중인지 알고 있습니다. 유효성 검사는 키 입력이 아니라 `blur`에서 하세요.

## 정리 \{#destroy\}

에디터는 리스너, 뷰, 실행 기록을 보유합니다. `mount()`는 도구 모음 동작을 해제하고, 페이지의 리스너를 제거하고, `editor.destroy()`를 호출하는 함수를 반환합니다. 필드가 페이지에서 사라질 때, 예를 들어 프레임워크에서 컴포넌트가 마운트 해제될 때 이 함수를 호출하세요.

## 이 예제에서 다루지 않는 것 \{#leaves-out\}

- **선택 영역을 따라다니는 도구 모음.** 선택한 텍스트 위에 떠 있는 도구 모음을 만들려면 선택 영역이 그려지는 위치를 추적해야 합니다. 이는 Tiptap의 `BubbleMenu` 확장과 그 위치 지정 기능이 담당하며, 이 가이드에서는 도구 모음을 고정해 둡니다.
- **멘션, 표, 이미지, 공동 편집.** 각각 Tiptap 확장과 별도의 인터페이스가 필요합니다.
- **Markdown 가져오기와 내보내기.** 서버에서 JSON을 변환하세요.
