패키지를 업그레이드할 때 컴포넌트 구현도 함께 업데이트하려면 패키지에서 가져오세요. 프로젝트에서 구현을 수정해야 한다면 소스를 복사하세요. 두 방식을 함께 써서 Master UI 컴포넌트 대부분은 패키지에서 가져오고 일부만 프로젝트에서 직접 관리할 수도 있습니다.

<GuideFigure name="registry" title="패키지에서 가져오기와 소스 직접 관리">

**어떤 방식으로 복사하느냐에 따라 업데이트를 추적하는 방법이 달라집니다.** 가져오기는 설치된 패키지를 참조합니다. `own`과 `add`는 설치된 패키지의 소스를 프로젝트로 복사하고, `status`와 `diff`에서 사용할 기준 파일과 소유권 기록을 저장합니다. 레지스트리 클라이언트는 호스팅된 파일을 프로젝트로 복사하며 Master UI의 기준 파일과 소유권 기록을 남기지 않으므로, 업데이트 이력을 직접 관리해야 합니다.

</GuideFigure>

소스를 어디에서 가져올지, 이후 변경 사항을 어떻게 추적할지에 따라 복사 도구를 선택하세요.

| 가져오는 방식 | 소스 | 프로젝트에 업데이트를 반영하는 방법 |
| --- | --- | --- |
| `@master/ui` 가져오기 | 설치된 패키지 | 의존성 업그레이드 |
| `master-ui own` 또는 `master-ui add` | 설치된 패키지 | `status`와 `diff`를 검토한 뒤 로컬 복사본에 병합 |
| 레지스트리 클라이언트 | 레지스트리 URL에서 제공하는 파일 | 자체 작업 흐름에 따라 복사한 파일을 검토하고 병합 |

복사본이 설치된 버전과 일치해야 한다면 공식 명령을 사용하세요. 호스팅된 레지스트리는 사이트에 게시된 소스를 따르며, 프로젝트의 잠금 파일은 레지스트리에서 가져올 버전에 영향을 주지 않습니다.

## 기본 방식은 패키지 사용 \{#the-package\}

패키지에서 가져온 컴포넌트에는 패키지를 업데이트할 때 포커스 링이나 강제 색상 모드의 윤곽선에 대한 수정 사항, 새로운 플랫폼 기능이 반영됩니다. 컴포넌트의 모양은 대부분 소스를 수정하지 않고도 바꿀 수 있습니다. 유틸리티, 디자인 토큰, 공개 사용자 지정 속성 또는 테마를 사용하면 됩니다. [커스터마이징](/guide/customization)에서는 어떤 경우에 [컴포넌트를 직접 관리](/guide/customization#own-a-component)하는 것이 적절한지 설명합니다.

## 복사할 수 있는 항목 \{#always-source\}

- **블록과 페이지는 페이지 마크업을 제공합니다.** 코드 보기, 페이지의 Markdown 또는 해당 레지스트리 항목에서 마크업을 복사한 뒤 콘텐츠를 수정하세요. 마크업에서 사용하는 컴포넌트의 스타일은 설치된 상태로 유지하세요. `page`, `shell`, `auto-grid` 또는 `form` 같은 레이아웃 클래스를 사용하는 마크업에는 해당 레이아웃의 스타일도 필요합니다.
- **동작은 패키지에서 계속 가져올 수 있습니다.** `@master/ui/behaviors/combobox.js` 같은 참조 스크립트를 가져오세요. 키 입력 처리, 포커스 또는 선택 동작을 다르게 구현해야 한다면 컴포넌트와 함께 제공되는 스크립트 복사본을 사용하세요. 스타일시트만 복사하면 기존 동작 스크립트를 가져오는 경로는 그대로 유지됩니다. [동작](/guide/behaviors)을 참고하세요.
- **프레임워크 컴포넌트는 프로젝트에서 소스를 직접 관리합니다.** `add`는 React, Svelte 또는 Vue 컴포넌트와 함께 로컬 헬퍼를 복사합니다. 패키지 업데이트에 소스 개선 사항이 포함되더라도 직접 병합해야 복사본에 반영됩니다. 동작 스크립트는 일반적으로 계속 패키지에서 가져옵니다. [React, Svelte, Vue](/guide/frameworks)를 참고하세요.

## 레지스트리 \{#the-registry\}

레지스트리는 패키지와 동일한 소스에서 생성한 JSON 파일 모음입니다.

| URL | 포함 내용 |
| --- | --- |
| `https://ui.master.co/r/registry.json` | 모든 항목과 각 파일의 경로를 담은 인덱스. 파일 내용은 생략 |
| `https://ui.master.co/r/<name>.json` | 단일 항목과 각 파일의 내용 |

각 항목은 [shadcn registry-item 스키마](https://ui.shadcn.com/docs/registry/registry-item-json)를 따릅니다. 항목에는 `registry:item`을 사용하고, 항목의 파일에는 `registry:file`을 사용하며 대상 경로를 명시합니다. 따라서 레지스트리는 Tailwind 스타일시트 없이도 CSS, HTML, 프레임워크 소스를 배포할 수 있습니다. 다음은 파일 내용을 생략한 버튼 항목의 구조입니다.

```json name=button.json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "button",
  "type": "registry:item",
  "title": "Button",
  "description": "A raised control that lifts on hover and sinks when pressed.",
  "dependencies": ["@master/css"],
  "registryDependencies": [
    "https://ui.master.co/r/theme.json",
    "https://ui.master.co/r/icon.json",
    "https://ui.master.co/r/spinner.json"
  ],
  "files": [
    { "path": "ui/button.css", "type": "registry:file", "target": "~/ui/button.css", "content": "…" },
    { "path": "ui/button.json", "type": "registry:file", "target": "~/ui/button.json", "content": "…" }
  ],
  "categories": ["Actions"],
  "docs": "Import ui/button.css after ui/theme.css. Its contract is ui/button.json; markup: https://ui.master.co/components/button.md"
}
```

`registryDependencies`에는 테마와 컴포넌트가 조합해 사용하는 계약의 이름이 들어갑니다. 컴포넌트 항목의 `meta` 키에는 계층, 스크립트 필요 여부, 클래스, 스타일시트가 참조하는 디자인 토큰과 믹스인이 들어갑니다.

## 레지스트리 항목 \{#items\}

| 항목 | 이름 | 파일 |
| --- | --- | --- |
| 테마 | `theme` | `ui/theme.css` |
| Paper 테마 | `theme-paper` | `ui/themes/paper.css` |
| 컴포넌트 또는 레이아웃 클래스 | 해당 계약의 이름(`button`, `dialog`, `shell`) | `ui/<name>.css`와 `ui/<name>.json`. 동작이 있으면 `ui/<behavior>.js`와 이 파일이 가져오는 헬퍼인 `ui/internal.js`도 포함 |
| 프레임워크 컴포넌트 | `<framework>-<name>`(예: `react-combobox`, `svelte-dialog`, `vue-toast`) | 컴포넌트 파일(예: `ui/combobox.tsx`, `ui/Dialog.svelte` 또는 `ui/Toaster.vue`)과 컴포넌트가 같은 디렉터리에서 가져오는 헬퍼 |
| 블록 | `block-<slug>`(예: `block-hero`) | `ui/blocks/<slug>.html` |
| 페이지 | `page-<slug>`(예: `page-dashboard`) | `ui/pages/<slug>.html` |

블록이나 페이지의 파일에는 해당 문서 페이지의 첫 번째 미리보기에 쓰인 마크업이 들어 있습니다. 항목의 `registryDependencies`에는 해당 마크업이 사용하는 컴포넌트가 들어갑니다.

## master-ui로 컴포넌트 복사 \{#master-ui\}

패키지에서 제공하는 `master-ui`는 소스를 복사하는 공식 명령입니다. 설치된 패키지에서 복사하므로 소스는 프로젝트에서 이미 사용 중인 버전과 일치합니다.

[Master UI가 설치된](/guide/installation) 프로젝트의 루트에서 다음 명령을 실행하세요.

```bash
npx master-ui init        # once: ui/index.css, one @import per stylesheet
npx master-ui own button  # ui/button.css and ui/button.json; the import now points at the copy
```

전체 `@master/ui`를 가져오는 대신 생성된 `ui/index.css`를 사용하세요. 버튼을 가져오는 경로가 `./button.css`를 가리키는지 확인하세요. 경로가 다르면 페이지에 계속 패키지의 버튼이 표시됩니다. [컴포넌트 직접 관리](/guide/customization#own-a-component)에서 스타일시트 설정 방법을 확인할 수 있습니다.

이 명령은 기준 복사본을 `ui/.base/`에, 해시를 `master-ui.json`에 기록합니다. 다른 체크아웃에서도 직접 관리하는 소스를 나중에 설치한 패키지와 비교할 수 있도록 이 파일들을 소스와 함께 커밋하세요. 업데이트 절차는 [업스트림 변경 사항 검토](/guide/customization#upstream-changes)를 참고하세요.

`own`은 계약이 있는 컴포넌트와 레이아웃 클래스를 복사합니다. 블록과 페이지는 각각의 문서 페이지나 레지스트리에서 복사하세요.

프레임워크 컴포넌트는 `add`로 복사합니다. 같은 방식으로 기록되므로 `status`, `diff`, `accept`도 사용할 수 있습니다.

```bash
npx master-ui add combobox --framework=react   # ui/combobox.tsx and ui/use-behavior.ts
npx master-ui add dialog                       # the framework is remembered
```

## shadcn CLI 사용 \{#shadcn-cli\}

호스팅된 카탈로그에서 항목을 가져오려면 레지스트리 클라이언트를 사용하세요. 블록이나 페이지의 마크업도 이 방식으로 가져올 수 있습니다. shadcn CLI를 사용할 때는 `components.json`에 네임스페이스를 추가하세요. 기존 설정이 있다면 다음 필드를 병합하세요.

```json name=components.json
{
  "registries": {
    "@master": "https://ui.master.co/r/{name}.json"
  }
}
```

그다음 이름으로 항목을 추가하세요.

```bash
npx shadcn@latest add @master/button
```

파일은 각각 대상 경로인 `ui/button.css`와 `ui/button.json`에 저장됩니다. 항목의 `docs`에 명시된 대로 테마를 가져온 뒤에 스타일시트를 가져오세요.

프레임워크 컴포넌트도 같은 방식으로 `@master/react-combobox`를 사용해 추가하거나, `components.json` 없이 주소를 직접 지정해 추가할 수 있습니다.

```bash
npx shadcn@latest add https://ui.master.co/r/react-combobox.json
```

대상이 명시된 범용 항목은 `registries`만 포함한 구성으로 사용할 수 있으며 Tailwind 프로젝트가 필요하지 않습니다. [레지스트리 API 문서](https://ui.shadcn.com/docs/registry/api-reference)를 참고하세요. 항목에 지정된 대상에 따라 이 파일들은 프로젝트의 `ui/` 디렉터리에 배치됩니다.

프레임워크 항목은 `@master/ui`와 해당 프레임워크를 의존성으로 선언하고, 스타일시트 항목은 `@master/css`와 해당 레지스트리 의존성을 선언합니다. 설치 후 패키지 매니페스트와 잠금 파일을 검토한 다음, 복사한 소스가 설치된 의존성과 함께 제대로 작동하는지 확인하세요. 페이지를 실행해 복사한 컴포넌트의 상태와 키보드 동작을 확인하세요.

레지스트리를 통해 설치하면 Master UI의 기준 사본과 소유권 기록이 생성되지 않습니다. 따라서 `master-ui status`와 `master-ui diff`로는 해당 설치를 추적할 수 없습니다. 업데이트 워크플로를 사용하려면 `own` 또는 `add`를 선택하세요.

## 유지되는 사항 \{#what-stays-the-same\}

컴포넌트를 직접 관리하면 스타일시트의 유지보수 주체가 바뀝니다. 컴포넌트의 계약은 그대로 유지됩니다.

- 컴포넌트를 복사하면 계약인 `ui/<name>.json`도 함께 복사됩니다. 이 프로젝트에서는 사본이 라이브러리의 계약을 대신하며, `master-ui check`, `master-ui contract` 및 에이전트가 이 사본을 읽습니다.
- 컴포넌트를 가져오는 시점에는 클래스, 각 클래스가 적용되는 요소, 상태 속성, 공개 사용자 지정 속성이 원본과 같습니다. 블록과 동작, 문서도 이전과 마찬가지로 적용됩니다.
- 사본도 테마의 디자인 토큰을 읽고 믹스인을 적용하므로 직접 만든 테마를 포함해 적용된 테마를 따릅니다.

계약이 실제 구현과 일치하는 동안에는 이 상태가 유지됩니다. 스타일시트에 클래스를 추가하거나 클래스 이름을 바꾸거나 클래스를 삭제하면 계약도 그에 맞춰 변경해야 합니다. [계약](/guide/contracts) 문서에서 계약에 포함되는 내용을 설명합니다.
