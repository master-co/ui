업그레이드로 구현이 갱신되기를 원한다면 컴포넌트를 패키지에 그대로 두세요. 프로젝트에서 소스를 편집해야 한다면 소스를 복사하세요. 두 방식을 함께 쓸 수도 있습니다. Master UI 대부분은 가져와서 쓰고, 몇몇 컴포넌트만 로컬에서 유지 관리하는 식입니다.

<GuideFigure name="registry" title="가져오기와 소스 소유">

**복사 경로에 따라 업데이트를 추적하는 방법이 정해집니다.** 가져오기는 설치된 패키지를 읽습니다. `own`과 `add`는 설치된 소스를 프로젝트에 복사하고, `status`와 `diff`를 위해 기준 파일과 소유 기록을 저장합니다. 레지스트리 클라이언트는 호스팅된 파일을 프로젝트에 복사하지만 이러한 Master UI 기록은 남기지 않으므로, 업데이트 이력은 직접 관리해야 합니다.

</GuideFigure>

소스를 어디서 가져와야 하는지, 이후의 변경을 어떻게 추적할지에 따라 복사 도구를 선택하세요.

| 경로 | 소스 | 업데이트가 프로젝트에 반영되는 방식 |
| --- | --- | --- |
| `@master/ui` 가져오기 | 설치된 패키지 | 의존성을 업그레이드합니다 |
| `master-ui own` 또는 `master-ui add` | 설치된 패키지 | `status`와 `diff`를 검토한 뒤 로컬 복사본에 병합합니다 |
| 레지스트리 클라이언트 | 레지스트리 URL에서 제공되는 파일 | 자체 워크플로로 복사한 파일을 검토하고 병합합니다 |

복사본이 설치된 버전과 일치해야 한다면 퍼스트 파티 명령을 사용하세요. 호스팅된 레지스트리는 사이트에 게시된 소스를 따르며, 프로젝트의 lockfile에 따라 선택되지 않습니다.

## 기본은 패키지 \{#the-package\}

패키지의 컴포넌트는 계속 업스트림을 따릅니다. 포커스 링 수정, 강제 색상 윤곽선, 새로운 플랫폼 기능이 업데이트와 함께 프로젝트에 반영됩니다. 컴포넌트의 외형을 바꾸는 대부분의 변경에는 소스가 필요하지 않습니다. 유틸리티, 토큰, 공개 사용자 지정 속성, 테마로 충분하며, [컴포넌트 소유](/guide/customization#own-a-component)가 올바른 선택인 조건은 [사용자 지정](/guide/customization)에 나와 있습니다.

## 복사할 수 있는 것 \{#always-source\}

- **블록과 페이지는 페이지 마크업을 제공합니다.** 코드 보기, 페이지의 Markdown, 또는 레지스트리 항목에서 복사한 다음 콘텐츠를 맞게 고치세요. 마크업이 사용하는 컴포넌트 스타일은 설치된 상태로 두세요. `page`, `shell`, `auto-grid`, `form` 같은 레이아웃 클래스를 사용하는 마크업에는 해당 레이아웃의 스타일도 필요합니다.
- **동작은 패키지에 남겨 둘 수 있습니다.** `@master/ui/behaviors/combobox.js` 같은 참조 스크립트를 가져오거나, 키, 포커스, 선택이 달라야 한다면 컴포넌트와 함께 오는 복사본을 사용하세요. 스타일시트만 복사해서는 기존 동작의 가져오기 경로가 바뀌지 않습니다. [동작](/guide/behaviors)을 참고하세요.
- **프레임워크 컴포넌트는 로컬 소스입니다.** `add`는 React, Svelte, Vue 컴포넌트와 그 로컬 헬퍼를 복사합니다. 패키지 업데이트로 그 소스가 개선될 수 있지만, 복사본은 병합할 때만 바뀝니다. 그 동작 가져오기는 보통 계속 패키지를 사용합니다. [React, Svelte, Vue](/guide/frameworks)를 참고하세요.

## 레지스트리 \{#the-registry\}

레지스트리는 패키지와 같은 소스에서 생성된 JSON 파일 모음입니다.

| URL | 담는 내용 |
| --- | --- |
| `https://ui.master.co/r/registry.json` | 인덱스: 모든 항목과 그 파일의 경로(내용은 제외) |
| `https://ui.master.co/r/<name>.json` | 항목 하나와 각 파일의 내용 |

각 항목은 [shadcn registry-item 스키마](https://ui.shadcn.com/docs/registry/registry-item-json)를 따릅니다. 항목은 `registry:item`을 사용하고, 그 파일은 명시적인 대상을 가진 `registry:file`을 사용합니다. 이 덕분에 레지스트리는 Tailwind 스타일시트 없이도 CSS, HTML, 프레임워크 소스를 배포할 수 있습니다. 다음은 파일 내용을 생략한 버튼 항목의 구조입니다.

```json name=button.json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "button",
  "type": "registry:item",
  "title": "Button",
  "description": "A raised control that lifts on hover and sinks when pressed.",
  "dependencies": ["@master/css"],
  "registryDependencies": [
    "https://ui.master.co/r/theme.json",
    "https://ui.master.co/r/icon.json",
    "https://ui.master.co/r/spinner.json"
  ],
  "files": [
    { "path": "ui/button.css", "type": "registry:file", "target": "~/ui/button.css", "content": "…" },
    { "path": "ui/button.json", "type": "registry:file", "target": "~/ui/button.json", "content": "…" }
  ],
  "categories": ["Actions"],
  "docs": "Import ui/button.css after ui/theme.css. Its contract is ui/button.json; markup: https://ui.master.co/components/button.md"
}
```

`registryDependencies`는 테마와, 컴포넌트가 구성하는 계약을 지정합니다. 컴포넌트 항목에는 `meta` 키도 있으며, 여기에는 단계(tier), 스크립트 필요 여부, 클래스, 스타일시트가 읽는 토큰과 믹스인이 들어 있습니다.

## 항목 \{#items\}

| 항목 | 이름 | 파일 |
| --- | --- | --- |
| 테마 | `theme` | `ui/theme.css` |
| Paper 테마 | `theme-paper` | `ui/themes/paper.css` |
| 컴포넌트 또는 레이아웃 클래스 | 계약의 이름: `button`, `dialog`, `shell` | `ui/<name>.css`와 `ui/<name>.json`. 동작이 있으면 `ui/<behavior>.js`와 그것이 가져오는 헬퍼인 `ui/internal.js` |
| 프레임워크 컴포넌트 | `react-combobox`, `svelte-dialog`, `vue-toast` 같은 `<framework>-<name>` | `ui/combobox.tsx`, `ui/Dialog.svelte`, `ui/Toaster.vue` 같은 컴포넌트, 그리고 컴포넌트가 옆에서 가져오는 헬퍼 |
| 블록 | `block-hero` 같은 `block-<slug>` | `ui/blocks/<slug>.html` |
| 페이지 | `page-dashboard` 같은 `page-<slug>` | `ui/pages/<slug>.html` |

블록이나 페이지의 파일은 해당 페이지에 있는 첫 번째 미리 보기의 마크업입니다. 그 `registryDependencies`는 마크업이 사용하는 컴포넌트입니다.

## master-ui로 컴포넌트 가져오기 \{#master-ui\}

패키지에 포함된 `master-ui` 명령이 퍼스트 파티 경로입니다. 설치된 패키지에서 복사하므로, 소스가 프로젝트에서 이미 실행 중인 버전과 일치합니다.

[Master UI가 설치된](/guide/installation) 프로젝트에서 시작하세요. 프로젝트 루트에서 다음 명령을 실행합니다.

```bash
npx master-ui init        # once: ui/index.css, one @import per stylesheet
npx master-ui own button  # ui/button.css and ui/button.json; the import now points at the copy
```

전체 `@master/ui` 가져오기 대신 생성된 `ui/index.css`를 사용하세요. 그 안의 버튼 가져오기가 `./button.css`를 가리키는지 확인하세요. 그렇지 않으면 페이지는 여전히 패키지의 버튼을 그리고 있습니다. 스타일시트 설정은 [컴포넌트 소유하기](/guide/customization#own-a-component)에 나와 있습니다.

이 명령은 기준 복사본을 `ui/.base/`에, 해시를 `master-ui.json`에 기록합니다. 다른 체크아웃에서도 나중에 설치된 패키지와 비교할 수 있도록, 소유한 소스와 함께 이들을 커밋하세요. 업데이트 워크플로는 [업스트림 변경 검토하기](/guide/customization#upstream-changes)를 참고하세요.

`own`은 계약이 있는 것, 즉 컴포넌트와 레이아웃 클래스를 가져옵니다. 블록과 페이지는 해당 페이지나 레지스트리에서 복사합니다.

프레임워크 컴포넌트는 `add`로 가져옵니다. 같은 방식으로 기록되므로 `status`, `diff`, `accept`도 이를 다룹니다.

```bash
npx master-ui add combobox --framework=react   # ui/combobox.tsx and ui/use-behavior.ts
npx master-ui add dialog                       # the framework is remembered
```

## shadcn CLI 사용하기 \{#shadcn-cli\}

블록이나 페이지의 마크업을 포함해 호스팅된 카탈로그의 항목이 필요하다면 레지스트리 클라이언트를 사용하세요. shadcn CLI의 경우 `components.json`에 네임스페이스를 추가합니다. 기존 설정이 있다면 이 필드를 병합하세요.

```json name=components.json
{
  "registries": {
    "@master": "https://ui.master.co/r/{name}.json"
  }
}
```

그런 다음 이름으로 항목을 추가합니다.

```bash
npx shadcn@latest add @master/button
```

파일은 대상 위치인 `ui/button.css`와 `ui/button.json`에 놓입니다. 항목의 `docs`에 나온 대로 테마 다음에 스타일시트를 가져오세요.

프레임워크 컴포넌트도 같은 방식으로 `@master/react-combobox`로 추가하거나, `components.json` 없이 주소로 추가할 수 있습니다.

```bash
npx shadcn@latest add https://ui.master.co/r/react-combobox.json
```

명시적인 대상을 가진 범용 항목은 `registries`만 담은 설정으로도 사용할 수 있으며, Tailwind 프로젝트가 필요하지 않습니다. [레지스트리 API 문서](https://ui.shadcn.com/docs/registry/api-reference)를 참고하세요. 항목의 대상 설정에 따라 이 파일들은 프로젝트의 `ui/` 디렉터리 아래에 놓입니다.

프레임워크 항목은 `@master/ui`와 해당 프레임워크를 의존성으로 선언하고, 스타일시트 항목은 `@master/css`와 레지스트리 의존성을 선언합니다. 설치 후 패키지 매니페스트와 lockfile을 검토하고, 복사한 소스와 설치된 의존성이 함께 동작하는지 확인하세요. 페이지를 실행해 복사한 컴포넌트의 상태와 키보드 동작을 확인하세요.

레지스트리로 설치하면 Master UI의 기준 복사본과 소유 기록이 만들어지지 않습니다. 따라서 `master-ui status`와 `master-ui diff`는 그 설치를 추적할 수 없습니다. 이 업데이트 워크플로를 원한다면 `own`이나 `add`를 선택하세요.

## 그대로 유지되는 것 \{#what-stays-the-same\}

컴포넌트를 소유하면 스타일시트를 누가 유지 관리하는지가 바뀝니다. 계약은 바뀌지 않습니다.

- 복사본은 계약 `ui/<name>.json`과 함께 옵니다. 이 프로젝트에서는 그것이 라이브러리의 계약을 대체합니다. `master-ui check`, `master-ui contract`, 에이전트가 복사본을 읽습니다.
- 컴포넌트를 가져온 시점에는 클래스, 각 클래스가 놓이는 요소, 상태 속성, 공개 사용자 지정 속성이 같습니다. 블록, 동작, 문서가 이전과 마찬가지로 들어맞습니다.
- 복사본은 여전히 테마의 토큰을 읽고 믹스인을 적용하므로, 직접 만든 테마를 포함해 테마를 따릅니다.

이 상태는 계약을 사실과 맞게 유지하는 동안 지속됩니다. 스타일시트에 클래스가 추가되거나, 이름이 바뀌거나, 제거되면 계약도 함께 바뀌어야 합니다. 계약이 담는 내용은 [계약](/guide/contracts)에서 설명합니다.
