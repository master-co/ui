アップグレードでコンポーネントの実装を更新したい場合は、コンポーネントをパッケージに置いたままにします。プロジェクトでソースを編集する必要がある場合は、ソースをコピーします。両方を組み合わせることもできます。Master UI の大部分はインポートし、いくつかのコンポーネントだけをローカルで保守するという方法です。

<GuideFigure name="registry" title="インポートとソースの所有">

**コピーの経路によって、更新を追跡する方法が決まります。** インポートはインストール済みのパッケージを読み取ります。`own` と `add` は、そのインストール済みのソースをプロジェクトにコピーし、`status` と `diff` のためのベースファイルと所有の記録を保存します。レジストリクライアントは、ホストされたファイルを Master UI の記録なしにプロジェクトにコピーするため、更新履歴は自分で管理することになります。

</GuideFigure>

ソースをどこから取得するか、後の変更をどう追跡するかによって、コピーに使うツールを選んでください。

| 経路 | ソース | 更新がプロジェクトに届く方法 |
| --- | --- | --- |
| `@master/ui` をインポート | インストール済みのパッケージ | 依存関係をアップグレードします |
| `master-ui own` または `master-ui add` | インストール済みのパッケージ | `status` と `diff` を確認し、ローカルのコピーにマージします |
| レジストリクライアント | レジストリの URL で配信されるファイル | 独自のワークフローでコピーしたファイルを確認し、マージします |

コピーがインストール済みのバージョンと一致しなければならない場合は、公式のコマンドを使ってください。ホストされたレジストリはサイトで公開されているソースに従い、プロジェクトのロックファイルによって選ばれるわけではありません。

## 既定はパッケージ \{#the-package\}

パッケージのコンポーネントは、アップストリームに従い続けます。フォーカスリングの修正、強制カラーのアウトライン、新しいプラットフォーム機能は、更新とともにプロジェクトに届きます。コンポーネントの見た目に関する変更のほとんどには、ソースは必要ありません。ユーティリティ、トークン、公開カスタムプロパティ、テーマで対応でき、[コンポーネントを所有する](/guide/customization#own-a-component)ことが適切な手段となる条件は[カスタマイズ](/guide/customization)に記載しています。

## コピーできるもの \{#always-source\}

- **ブロックとページはページのマークアップを提供します。** Code ビュー、ページの Markdown、またはそのレジストリ項目からコピーし、内容を調整します。マークアップが使うコンポーネントのスタイルはインストールしたままにしてください。`page`、`shell`、`auto-grid`、`form` のようなレイアウトクラスを使うマークアップには、そのレイアウトのスタイルも必要です。
- **ビヘイビアはパッケージに置いたままにできます。** `@master/ui/behaviors/combobox.js` のようなリファレンススクリプトをインポートするか、キー操作、フォーカス、選択を変えたい場合はコンポーネントに付属するコピーを使います。スタイルシートをコピーしただけでは、既存のビヘイビアのインポート先は変わりません。[ビヘイビア](/guide/behaviors)を参照してください。
- **フレームワークコンポーネントはローカルのソースです。** `add` は React、Svelte、Vue のコンポーネントと、そのローカルのヘルパーをコピーします。パッケージの更新でそのソースが改善されることはありますが、コピーが変わるのはそれをマージしたときだけです。そのビヘイビアのインポートは、通常は引き続きパッケージを使います。[React、Svelte、Vue](/guide/frameworks) を参照してください。

## レジストリ \{#the-registry\}

レジストリは、パッケージと同じソースから生成される JSON ファイルの集まりです。

| URL | 内容 |
| --- | --- |
| `https://ui.master.co/r/registry.json` | インデックス：すべての項目とそのファイルのパス。内容は含みません |
| `https://ui.master.co/r/<name>.json` | 1 つの項目と、各ファイルの内容 |

各項目は [shadcn の registry-item スキーマ](https://ui.shadcn.com/docs/registry/registry-item-json)に従います。項目は `registry:item` を使い、そのファイルは明示的なターゲットを持つ `registry:file` を使います。これにより、Tailwind のスタイルシートを必要とせずに、CSS、HTML、フレームワークのソースを配布できます。以下はボタンの項目の構造で、ファイルの内容は省略しています。

```json name=button.json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "button",
  "type": "registry:item",
  "title": "Button",
  "description": "A raised control that lifts on hover and sinks when pressed.",
  "dependencies": ["@master/css"],
  "registryDependencies": [
    "https://ui.master.co/r/theme.json",
    "https://ui.master.co/r/icon.json",
    "https://ui.master.co/r/spinner.json"
  ],
  "files": [
    { "path": "ui/button.css", "type": "registry:file", "target": "~/ui/button.css", "content": "…" },
    { "path": "ui/button.json", "type": "registry:file", "target": "~/ui/button.json", "content": "…" }
  ],
  "categories": ["Actions"],
  "docs": "Import ui/button.css after ui/theme.css. Its contract is ui/button.json; markup: https://ui.master.co/components/button.md"
}
```

`registryDependencies` は、テーマと、コンポーネントが組み合わせるコントラクトを指定します。コンポーネントの項目には `meta` キーもあり、その階層、スクリプトが必要かどうか、クラス、スタイルシートが読み取るトークンとミックスインが含まれます。

## 項目 \{#items\}

| 項目 | 名前 | ファイル |
| --- | --- | --- |
| テーマ | `theme` | `ui/theme.css` |
| Paper テーマ | `theme-paper` | `ui/themes/paper.css` |
| コンポーネントまたはレイアウトクラス | そのコントラクトの名前：`button`、`dialog`、`shell` | `ui/<name>.css` と `ui/<name>.json`。ビヘイビアがある場合は `ui/<behavior>.js` と、それがインポートするヘルパー `ui/internal.js` |
| フレームワークコンポーネント | `react-combobox`、`svelte-dialog`、`vue-toast` のような `<framework>-<name>` | `ui/combobox.tsx`、`ui/Dialog.svelte`、`ui/Toaster.vue` のようなコンポーネントと、それが隣からインポートするヘルパー |
| ブロック | `block-hero` のような `block-<slug>` | `ui/blocks/<slug>.html` |
| ページ | `page-dashboard` のような `page-<slug>` | `ui/pages/<slug>.html` |

ブロックやページのファイルは、そのページにある最初のプレビューのマークアップです。その `registryDependencies` は、マークアップが使うコンポーネントです。

## master-ui でコンポーネントを取り込む \{#master-ui\}

パッケージに含まれる `master-ui` コマンドが公式の経路です。インストール済みのパッケージからコピーするため、ソースはプロジェクトがすでに使っているバージョンと一致します。

[Master UI をインストールした](/guide/installation)プロジェクトから始めます。そのルートで次のコマンドを実行します。

```bash
npx master-ui init        # once: ui/index.css, one @import per stylesheet
npx master-ui own button  # ui/button.css and ui/button.json; the import now points at the copy
```

`@master/ui` 全体のインポートの代わりに、生成された `ui/index.css` を使います。そのボタンのインポートが `./button.css` を指していることを確認してください。そうでなければ、ページは引き続きパッケージのボタンを描画しています。スタイルシートの設定は[コンポーネントを所有する](/guide/customization#own-a-component)で説明しています。

このコマンドは、ベースのコピーを `ui/.base/` に、ハッシュを `master-ui.json` に記録します。別のチェックアウトで後のインストール済みパッケージと比較できるよう、所有したソースと一緒にコミットしてください。更新のワークフローは[アップストリームの変更を確認する](/guide/customization#upstream-changes)を参照してください。

`own` が取り込むのは、コントラクトを持つもの、つまりコンポーネントとレイアウトクラスです。ブロックとページは、それぞれのページかレジストリからコピーします。

フレームワークコンポーネントは `add` で取り込みます。同じ方法で記録されるため、`status`、`diff`、`accept` もこれを対象にします。

```bash
npx master-ui add combobox --framework=react   # ui/combobox.tsx and ui/use-behavior.ts
npx master-ui add dialog                       # the framework is remembered
```

## shadcn CLI を使う \{#shadcn-cli\}

ブロックやページのマークアップを含め、ホストされたカタログから項目を取得したい場合は、レジストリクライアントを使います。shadcn CLI では、`components.json` に名前空間を追加します。既存の設定がある場合は、このフィールドをマージしてください。

```json name=components.json
{
  "registries": {
    "@master": "https://ui.master.co/r/{name}.json"
  }
}
```

その後、名前で項目を追加します。

```bash
npx shadcn@latest add @master/button
```

ファイルはそのターゲットである `ui/button.css` と `ui/button.json` に配置されます。項目の `docs` にあるとおり、スタイルシートはテーマの後にインポートしてください。

フレームワークコンポーネントも、`@master/react-combobox` として同じ方法で追加できます。また、`components.json` がなくてもアドレスで追加できます。

```bash
npx shadcn@latest add https://ui.master.co/r/react-combobox.json
```

明示的なターゲットを持つ汎用的な項目は、`registries` だけを含む設定で使えます。Tailwind のプロジェクトは必要ありません。[レジストリ API のドキュメント](https://ui.shadcn.com/docs/registry/api-reference)を参照してください。項目のターゲットにより、これらのファイルはプロジェクトの `ui/` ディレクトリー配下に配置されます。

フレームワークの項目は `@master/ui` とそのフレームワークを依存関係として宣言し、スタイルシートの項目は `@master/css` とそのレジストリ依存関係を宣言します。インストール後はパッケージマニフェストとロックファイルを確認し、コピーしたソースとインストールされた依存関係が一緒に機能することを確かめてください。ページを実行し、コピーしたコンポーネントの状態とキーボード操作を確認します。

レジストリからのインストールでは、Master UI のベースのコピーと所有の記録は作成されません。そのため、`master-ui status` と `master-ui diff` ではそのインストールを追跡できません。それらの更新ワークフローを使いたい場合は、`own` か `add` を選んでください。

## 変わらないもの \{#what-stays-the-same\}

コンポーネントを所有すると、そのスタイルシートを誰が保守するかが変わります。コントラクトは変わりません。

- コピーはコントラクト `ui/<name>.json` と一緒に届きます。このプロジェクトでは、それがライブラリのコントラクトに取って代わり、`master-ui check`、`master-ui contract`、エージェントはコピーを読み取ります。
- コンポーネントを取り込んだ時点では、クラス、各クラスを置く要素、状態の属性、公開カスタムプロパティは同じです。ブロック、ビヘイビア、ドキュメントは以前と同じように当てはまります。
- コピーは引き続きテーマのトークンを読み取り、そのミックスインを適用するため、独自のテーマを含め、テーマに従います。

これはコントラクトを正しく保っている限り変わりません。スタイルシートでクラスが追加、改名、削除されたら、コントラクトもそれに合わせて変更します。コントラクトの内容は[コントラクト](/guide/contracts)で説明しています。
