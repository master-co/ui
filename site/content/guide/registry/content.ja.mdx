パッケージの更新に合わせて実装も更新したい場合は、パッケージのコンポーネントを使います。プロジェクトで実装を編集する必要がある場合は、ソースをコピーします。両方を併用し、Master UI の大半をインポートしながら、一部のコンポーネントだけをローカルで管理することもできます。

<GuideFigure name="registry" title="インポートとソースの管理">

**ソースの取得方法によって、更新の追跡方法が変わります。** インポートでは、インストール済みパッケージを参照します。`own` と `add` は、そのパッケージのソースをプロジェクトにコピーし、`status` と `diff` が使う基準ファイルと、プロジェクトで管理するファイルの記録を保存します。レジストリクライアントは、公開されているファイルをプロジェクトにコピーします。その際、Master UI の基準ファイルや管理記録は作成されないため、更新履歴はプロジェクト側で管理します。

</GuideFigure>

ソースの取得元と、後から変更を追跡する方法に合わせて、取得方法を選びます。

| 取得方法 | 取得元 | プロジェクトへの更新の反映方法 |
| --- | --- | --- |
| `@master/ui` をインポート | インストール済みパッケージ | 依存パッケージを更新 |
| `master-ui own` または `master-ui add` | インストール済みパッケージ | `status` と `diff` で状態と差分を確認し、ローカルのコピーにマージ |
| レジストリクライアント | レジストリの URL で配信されるファイル | 独自の手順でコピーしたファイルを確認してマージ |

コピーをインストール済みのバージョンに合わせる必要がある場合は、公式コマンドを使ってください。公開レジストリはサイトで公開されているソースに追従し、プロジェクトのロックファイルによるバージョン指定は適用されません。

## 既定はパッケージの利用 \{#the-package\}

パッケージのコンポーネントは上流の変更に追従します。フォーカスリングや強制カラーモードでのアウトラインの修正、プラットフォームの新機能への対応は、パッケージの更新を通じてプロジェクトに反映されます。見た目の変更の多くは、ソースを編集せずに、ユーティリティ、トークン、公開カスタムプロパティ、テーマで対応できます。[カスタマイズ](/guide/customization)では、[コンポーネントをプロジェクト側で管理する](/guide/customization#own-a-component)のが適切な条件を説明しています。

## コピーできるもの \{#always-source\}

- **ブロックとページは、ページ用のマークアップを提供します。** コードビュー、ページの Markdown、レジストリ項目のいずれかからコピーし、内容を調整してください。マークアップが使うコンポーネントのスタイルは、インストールしたままにしてください。`page`、`shell`、`auto-grid`、`form` などのレイアウトクラスを使う場合は、対応するレイアウトのスタイルも必要です。
- **ビヘイビアはパッケージから使い続けられます。** `@master/ui/behaviors/combobox.js` などの参照実装スクリプトをインポートできます。キー操作、フォーカス、選択の挙動を変える場合は、コンポーネントに付属するビヘイビアをコピーします。スタイルシートをコピーするだけでは、既存のビヘイビアのインポート先は変わりません。[ビヘイビア](/guide/behaviors)を参照してください。
- **フレームワーク用コンポーネントはローカルのソースとして管理します。** `add` は React、Svelte、Vue のいずれかのコンポーネントと、同じディレクトリに置くヘルパーをコピーします。パッケージの更新でソースが改善されても、ローカルのコピーに反映されるのは変更をマージしたときだけです。ビヘイビアは通常、引き続きパッケージからインポートされます。[React、Svelte、Vue](/guide/frameworks)を参照してください。

## レジストリ \{#the-registry\}

レジストリは、パッケージと同じソースから生成した JSON ファイルの集まりです。

| URL | 内容 |
| --- | --- |
| `https://ui.master.co/r/registry.json` | インデックス。全項目と各ファイルのパス（ファイルの内容は含まない） |
| `https://ui.master.co/r/<name>.json` | 単一の項目。各ファイルの内容を含む |

各項目は [shadcn の registry-item スキーマ](https://ui.shadcn.com/docs/registry/registry-item-json)に準拠します。項目には `registry:item` を、各ファイルには `registry:file` を使用し、ファイルの配置先を明示します。これにより、Tailwind のスタイルシートを必要とせずに、CSS、HTML、フレームワーク用のソースを配布できます。以下はボタンのレジストリ項目の構造です。各ファイルの内容は省略しています。

```json name=button.json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "button",
  "type": "registry:item",
  "title": "Button",
  "description": "A raised control that lifts on hover and sinks when pressed.",
  "dependencies": ["@master/css"],
  "registryDependencies": [
    "https://ui.master.co/r/theme.json",
    "https://ui.master.co/r/icon.json",
    "https://ui.master.co/r/spinner.json"
  ],
  "files": [
    { "path": "ui/button.css", "type": "registry:file", "target": "~/ui/button.css", "content": "…" },
    { "path": "ui/button.json", "type": "registry:file", "target": "~/ui/button.json", "content": "…" }
  ],
  "categories": ["Actions"],
  "docs": "Import ui/button.css after ui/theme.css. Its contract is ui/button.json; markup: https://ui.master.co/components/button.md"
}
```

`registryDependencies` には、テーマと、そのコンポーネントが組み合わせて使うコントラクトを指定します。コンポーネントの項目には `meta` キーもあり、階層、スクリプトの要否、クラス、スタイルシートが参照するトークンとミックスインが記録されています。

## レジストリ項目の一覧 \{#items\}

| 項目 | 名前 | ファイル |
| --- | --- | --- |
| テーマ | `theme` | `ui/theme.css` |
| Paper テーマ | `theme-paper` | `ui/themes/paper.css` |
| コンポーネントまたはレイアウトクラス | コントラクト名（`button`、`dialog`、`shell` など） | `ui/<name>.css` と `ui/<name>.json`。ビヘイビアがある場合は `ui/<behavior>.js` と、そこからインポートされるヘルパーの `ui/internal.js` も含む |
| フレームワーク用コンポーネント | `<framework>-<name>`（例：`react-combobox`、`svelte-dialog`、`vue-toast`） | コンポーネント（`ui/combobox.tsx`、`ui/Dialog.svelte`、`ui/Toaster.vue` など）と、同じディレクトリからインポートするヘルパー |
| ブロック | `block-<slug>`（例：`block-hero`） | `ui/blocks/<slug>.html` |
| ページ | `page-<slug>`（例：`page-dashboard`） | `ui/pages/<slug>.html` |

ブロックやページのファイルには、そのドキュメントページの最初のプレビューに使われるマークアップが入っています。`registryDependencies` には、そのマークアップで使うコンポーネントが指定されています。

## master-ui でコンポーネントをコピーする \{#master-ui\}

パッケージに含まれる `master-ui` は、公式のコピーコマンドです。インストール済みパッケージからコピーするため、取得したソースはプロジェクトで使用中のバージョンと一致します。

[Master UI をインストール済み](/guide/installation)のプロジェクトを用意し、そのルートで以下のコマンドを実行します。

```bash
npx master-ui init        # once: ui/index.css, one @import per stylesheet
npx master-ui own button  # ui/button.css and ui/button.json; the import now points at the copy
```

`@master/ui` 全体をインポートする代わりに、生成された `ui/index.css` を使います。ボタンのインポート先が `./button.css` であることを確認してください。別の場所を指していると、ページには引き続きパッケージのボタンが表示されます。スタイルシートの設定方法は[コンポーネントを自分で管理する](/guide/customization#own-a-component)を参照してください。

このコマンドは、比較の基準となるコピーを `ui/.base/` に、ハッシュを `master-ui.json` に記録します。管理対象のソースと一緒にコミットしておくと、別のチェックアウトでも、そのソースを新しいバージョンのインストール済みパッケージと比較できます。更新手順は[上流の変更を確認する](/guide/customization#upstream-changes)を参照してください。

`own` で取り込めるのは、コントラクトを持つコンポーネントとレイアウトクラスです。ブロックやページは、それぞれのドキュメントページかレジストリからコピーします。

フレームワーク向けコンポーネントは `add` で取り込みます。同じ方法で記録されるため、`status`、`diff`、`accept` も利用できます。

```bash
npx master-ui add combobox --framework=react   # ui/combobox.tsx and ui/use-behavior.ts
npx master-ui add dialog                       # the framework is remembered
```

## shadcn CLI を使う \{#shadcn-cli\}

公開カタログから項目を取り込むには、レジストリクライアントを使います。ブロックやページのマークアップも取得できます。shadcn CLI では、名前空間を `components.json` に追加します。既存の設定がある場合は、次のフィールドをその設定に追加してください。

```json name=components.json
{
  "registries": {
    "@master": "https://ui.master.co/r/{name}.json"
  }
}
```

次に、項目名を指定して追加します。

```bash
npx shadcn@latest add @master/button
```

ファイルは指定先の `ui/button.css` と `ui/button.json` に配置されます。項目の `docs` に従い、スタイルシートはテーマの後にインポートしてください。

フレームワーク向けコンポーネントも同様に、`@master/react-combobox` のように追加できます。アドレスを直接指定する場合は、`components.json` 自体が不要です。

```bash
npx shadcn@latest add https://ui.master.co/r/react-combobox.json
```

配置先が明示された汎用項目には、`registries` だけを含む設定を使えます。Tailwind プロジェクトは不要です。詳しくは[レジストリ API のドキュメント](https://ui.shadcn.com/docs/registry/api-reference)を参照してください。ファイルは項目で指定された配置先に従って、プロジェクトの `ui/` ディレクトリ配下に置かれます。

フレームワーク向け項目は `@master/ui` と対象フレームワークを依存関係として宣言します。スタイルシートの項目は `@master/css` と、依存するレジストリ項目を宣言します。インストール後はパッケージマニフェストとロックファイルを確認し、コピーしたソースがインストール済みの依存関係と組み合わせて動作することを確かめてください。ページを開き、コピーしたコンポーネントの各状態とキーボード操作を確認します。

レジストリからインストールした場合、Master UI が使う比較用のコピーと管理記録は作成されません。そのため、`master-ui status` と `master-ui diff` では変更を追跡できません。これらのコマンドで更新を管理したい場合は、`own` または `add` を使ってください。

## 変わらない点 \{#what-stays-the-same\}

コンポーネントを自分で管理すると、スタイルシートの保守をプロジェクト側で行うようになります。コントラクトはそのままです。

- コピーにはコントラクト `ui/<name>.json` が付属します。プロジェクト内ではライブラリ側のコントラクトに代わり、`master-ui check`、`master-ui contract`、エージェントがコピーを参照します。
- 取り込んだ時点では、クラス、各クラスを付ける要素、状態を表す属性、公開カスタムプロパティはいずれも元のコンポーネントと同じです。ブロックやビヘイビア、ドキュメントも引き続きそのまま使えます。
- コピーも引き続きテーマのトークンを参照し、ミックスインを適用します。独自のテーマを使った場合も、その定義が反映されます。

この互換性を保つには、コントラクトを実装と一致させてください。スタイルシートでクラスを追加、改名、削除したら、コントラクトも更新します。コントラクトに記載する内容は[コントラクト](/guide/contracts)を参照してください。
