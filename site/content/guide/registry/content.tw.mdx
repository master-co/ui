如果你希望升級時一併更新元件的實作，就讓元件留在套件中。當專案需要編輯原始碼時，再複製原始碼。兩者可以並用：匯入大部分的 Master UI，同時自行維護少數本地元件。

<GuideFigure name="registry" title="匯入與原始碼的擁有權">

**複製的途徑決定你如何追蹤更新。** 匯入會讀取已安裝的套件。`own` 與 `add` 會將已安裝的原始碼複製到專案中，並為 `status` 與 `diff` 儲存基準檔案與擁有權紀錄。登錄庫用戶端則將託管的檔案複製到專案中，但不會產生這些 Master UI 紀錄，因此你需要自行維護它們的更新歷程。

</GuideFigure>

請依原始碼應來自何處，以及之後如何追蹤變更，來選擇複製工具：

| 途徑 | 來源 | 更新如何進入專案 |
| --- | --- | --- |
| 匯入 `@master/ui` | 已安裝的套件 | 升級相依套件 |
| `master-ui own` 或 `master-ui add` | 已安裝的套件 | 審視 `status` 與 `diff`，再合併到本地副本 |
| 登錄庫用戶端 | 登錄庫 URL 所提供的檔案 | 以你自己的工作流程審視並合併複製的檔案 |

當副本必須與已安裝的版本相符時，請使用官方指令。託管的登錄庫跟隨網站所發布的原始碼；它不會依你專案的 lockfile 選擇版本。

## 預設使用套件 \{#the-package\}

來自套件的元件會持續跟隨上游：焦點環的修正、強制色彩模式的外框，或新的平台功能，都會隨著更新進入專案。大多數關於元件外觀的變更並不需要它的原始碼。utility、token、公開的自訂屬性或主題就能涵蓋這些變更，而[自訂](/guide/customization)列出了在哪些條件下[擁有元件](/guide/customization#own-a-component)才是正確的做法。

## 你可以複製什麼 \{#always-source\}

- **區塊與頁面提供頁面標記。** 從程式碼檢視、頁面的 Markdown 或其登錄庫項目複製標記，再調整內容。請讓它所使用的元件樣式保持安裝；使用版面 class（例如 `page`、`shell`、`auto-grid` 或 `form`）的標記，也需要該版面的樣式。
- **行為可以留在套件中。** 匯入 `@master/ui/behaviors/combobox.js` 之類的參考腳本；或者當按鍵、焦點或選取應有所不同時，取得隨元件一併提供的副本。單獨複製的樣式表不會改變既有的行為匯入路徑。請參閱[行為](/guide/behaviors)。
- **框架元件是本地原始碼。** `add` 會複製 React、Svelte 或 Vue 元件及其本地輔助函式。套件更新可能會改進該原始碼，但你的副本只會在你合併這些更新時才改變。它的行為匯入通常仍使用套件。請參閱 [React、Svelte 與 Vue](/guide/frameworks)。

## 登錄庫 \{#the-registry\}

登錄庫是一組從與套件相同的原始碼所產生的 JSON 檔案。

| URL | 內容 |
| --- | --- |
| `https://ui.master.co/r/registry.json` | 索引：每個項目及其檔案路徑，不含檔案內容 |
| `https://ui.master.co/r/<name>.json` | 單一項目，包含每個檔案的內容 |

每個項目都遵循 [shadcn registry-item 結構描述](https://ui.shadcn.com/docs/registry/registry-item-json)。項目使用 `registry:item`，其檔案使用帶有明確目標的 `registry:file`。這讓登錄庫能發布 CSS、HTML 與框架原始碼，而不需要 Tailwind 樣式表。以下是按鈕項目的結構，省略了檔案內容：

```json name=button.json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "button",
  "type": "registry:item",
  "title": "Button",
  "description": "A raised control that lifts on hover and sinks when pressed.",
  "dependencies": ["@master/css"],
  "registryDependencies": [
    "https://ui.master.co/r/theme.json",
    "https://ui.master.co/r/icon.json",
    "https://ui.master.co/r/spinner.json"
  ],
  "files": [
    { "path": "ui/button.css", "type": "registry:file", "target": "~/ui/button.css", "content": "…" },
    { "path": "ui/button.json", "type": "registry:file", "target": "~/ui/button.json", "content": "…" }
  ],
  "categories": ["Actions"],
  "docs": "Import ui/button.css after ui/theme.css. Its contract is ui/button.json; markup: https://ui.master.co/components/button.md"
}
```

`registryDependencies` 指名主題以及該元件所組合的契約。元件的項目還有一個 `meta` 鍵，記載其層級、是否需要腳本、它的 class，以及其樣式表讀取的 token 與 mixin。

## 項目 \{#items\}

| 項目 | 名稱 | 檔案 |
| --- | --- | --- |
| 主題 | `theme` | `ui/theme.css` |
| Paper 主題 | `theme-paper` | `ui/themes/paper.css` |
| 元件或版面 class | 其契約的名稱：`button`、`dialog`、`shell` | `ui/<name>.css` 與 `ui/<name>.json`；有行為時，另有 `ui/<behavior>.js` 及其匯入的輔助檔案 `ui/internal.js` |
| 框架元件 | `<framework>-<name>`，例如 `react-combobox`、`svelte-dialog`、`vue-toast` | 元件本身，例如 `ui/combobox.tsx`、`ui/Dialog.svelte` 或 `ui/Toaster.vue`，以及它從旁邊匯入的輔助函式 |
| 區塊 | `block-<slug>`，例如 `block-hero` | `ui/blocks/<slug>.html` |
| 頁面 | `page-<slug>`，例如 `page-dashboard` | `ui/pages/<slug>.html` |

區塊或頁面的檔案，是其頁面上第一個預覽的標記。它的 `registryDependencies` 是該標記所使用的元件。

## 以 master-ui 取得元件 \{#master-ui\}

套件中的 `master-ui` 指令是官方途徑。它從已安裝的套件複製，因此原始碼會與專案目前執行的版本相符。

從一個[已安裝 Master UI](/guide/installation) 的專案開始。在其根目錄執行以下指令：

```bash
npx master-ui init        # once: ui/index.css, one @import per stylesheet
npx master-ui own button  # ui/button.css and ui/button.json; the import now points at the copy
```

以產生的 `ui/index.css` 取代完整的 `@master/ui` 匯入。請確認其中的按鈕匯入指向 `./button.css`；否則頁面繪製的仍是套件中的按鈕。[擁有元件](/guide/customization#own-a-component)說明了樣式表的設定方式。

這個指令會將基準副本記錄在 `ui/.base/`，並將雜湊值記錄在 `master-ui.json`。請將它們與擁有的原始碼一起提交，讓另一份 checkout 能將其與之後安裝的套件比較。更新的工作流程請參閱[審視上游變更](/guide/customization#upstream-changes)。

`own` 取得的是有契約的東西：元件與版面 class。區塊與頁面則從它們的頁面或登錄庫複製。

框架元件以 `add` 取得。它會以相同的方式記錄，因此 `status`、`diff` 與 `accept` 也涵蓋它。

```bash
npx master-ui add combobox --framework=react   # ui/combobox.tsx and ui/use-behavior.ts
npx master-ui add dialog                       # the framework is remembered
```

## 使用 shadcn CLI \{#shadcn-cli\}

當你想從託管的目錄取得項目（包括區塊或頁面的標記）時，請使用登錄庫用戶端。若使用 shadcn CLI，請將命名空間加入 `components.json`；將此欄位合併到既有的設定中：

```json name=components.json
{
  "registries": {
    "@master": "https://ui.master.co/r/{name}.json"
  }
}
```

接著依名稱加入項目：

```bash
npx shadcn@latest add @master/button
```

檔案會放在其目標位置：`ui/button.css` 與 `ui/button.json`。依照項目的 `docs` 所述，在主題之後匯入樣式表。

框架元件也以相同方式加入，名稱為 `@master/react-combobox`；也可以完全不使用 `components.json`，直接以其網址加入：

```bash
npx shadcn@latest add https://ui.master.co/r/react-combobox.json
```

帶有明確目標的通用項目，可以使用只包含 `registries` 的設定；它們不需要 Tailwind 專案。請參閱[登錄庫 API 文件](https://ui.shadcn.com/docs/registry/api-reference)。項目的目標會將這些檔案放在專案的 `ui/` 目錄下。

框架項目將 `@master/ui` 與該框架宣告為相依套件；樣式表項目則宣告 `@master/css` 及其登錄庫相依項目。安裝後請審視套件清單與 lockfile，再確認複製的原始碼與已安裝的相依套件能一起運作。執行頁面，並檢查複製元件的狀態與鍵盤行為。

透過登錄庫安裝，並不會建立 Master UI 的基準副本與擁有權紀錄。因此 `master-ui status` 與 `master-ui diff` 無法追蹤這次安裝。若需要它們的更新工作流程，請選擇 `own` 或 `add`。

## 保持不變的部分 \{#what-stays-the-same\}

擁有元件改變的是由誰維護其樣式表，而不會改變其契約。

- 副本會連同其契約 `ui/<name>.json` 一起提供。在這個專案中，它會取代元件庫的契約：`master-ui check`、`master-ui contract` 與代理都會讀取這份副本。
- 在取得元件的當天，class、每個 class 所在的元素、狀態屬性與公開的自訂屬性都相同。區塊、行為與文件依然適用。
- 副本仍會讀取主題的 token 並套用其 mixin，因此它會跟隨主題，包括你自己的主題。

只要契約保持正確，就會維持這樣的狀態：當樣式表新增、重新命名或移除 class 時，契約也要隨之變更。[契約](/guide/contracts)說明了契約包含的內容。
