如果希望升級套件時一併更新元件實作，就直接從套件匯入。專案需要修改元件時，再複製原始碼。兩種方式可以並用：大部分元件從 Master UI 匯入，少數元件留在專案內自行維護。

<GuideFigure name="registry" title="匯入與原始碼的維護權">

**複製方式決定如何追蹤更新。** 匯入會讀取已安裝的套件。`own` 和 `add` 會將套件內的原始碼複製到專案，並儲存基準檔案和維護權紀錄，供 `status` 和 `diff` 使用。登錄庫用戶端會將託管的檔案複製到專案，但不會建立這些 Master UI 紀錄，因此你需要自行追蹤更新紀錄。

</GuideFigure>

依照原始碼的來源和日後追蹤變更的方式，選擇適合的工具：

| 方式 | 來源 | 如何將更新帶入專案 |
| --- | --- | --- |
| 匯入 `@master/ui` | 已安裝的套件 | 升級相依套件 |
| `master-ui own` 或 `master-ui add` | 已安裝的套件 | 查看 `status` 和 `diff`，再將變更合併至本機副本 |
| 登錄庫用戶端 | 登錄庫網址提供的檔案 | 依自己的工作流程檢視並合併複製的檔案 |

如果副本必須與已安裝的版本一致，請使用官方指令。託管的登錄庫以網站發布的原始碼為準，專案的鎖定檔不會決定其版本。

## 預設使用套件 \{#the-package\}

從套件匯入的元件會隨上游更新。只要升級套件，專案就能取得焦點環或強制色彩模式外框的修正，以及新的平台功能。調整元件外觀通常不必修改原始碼，使用 utility、token、公開自訂屬性或主題即可。[自訂](/guide/customization)說明哪些情況適合[接手維護元件](/guide/customization#own-a-component)。

## 可以複製的內容 \{#always-source\}

- **區塊與頁面提供頁面標記。** 從「程式碼」檢視、該頁的 Markdown 或對應的登錄庫項目複製標記，再依需求調整內容。請保留已安裝的元件樣式，供這些標記使用。若標記使用 `page`、`shell`、`auto-grid` 或 `form` 等版面配置類別，也需要安裝對應的版面配置樣式。
- **行為可以繼續使用套件版本。** 你可以匯入 `@master/ui/behaviors/combobox.js` 之類的參考腳本。如果需要調整按鍵操作、焦點或選取行為，可以使用隨元件一併複製的版本。只複製樣式表不會改變現有行為腳本的匯入來源。請參閱[行為](/guide/behaviors)。
- **框架元件的原始碼由專案維護。** `add` 會複製 React、Svelte 或 Vue 元件及其本機輔助程式。套件更新可能會改進原始碼，你的副本則要等到合併後才會更新。元件通常仍會從套件匯入行為腳本。請參閱 [React、Svelte 與 Vue](/guide/frameworks)。

## 登錄庫 \{#the-registry\}

登錄庫由一組 JSON 檔案構成，這些檔案以套件的同一份原始碼產生。

| 網址 | 內容 |
| --- | --- |
| `https://ui.master.co/r/registry.json` | 索引，列出所有項目和各自的檔案路徑，不含檔案內容 |
| `https://ui.master.co/r/<name>.json` | 單一項目，包含各個檔案的內容 |

每個項目都遵循 [shadcn 登錄庫項目結構描述](https://ui.shadcn.com/docs/registry/registry-item-json)。項目使用 `registry:item`，其中的檔案使用 `registry:file`，並明確指定目標路徑。這讓登錄庫能在不需要 Tailwind 樣式表的情況下發佈 CSS、HTML 和框架原始碼。以下是按鈕項目的結構，已省略檔案內容：

```json name=button.json
{
  "$schema": "https://ui.shadcn.com/schema/registry-item.json",
  "name": "button",
  "type": "registry:item",
  "title": "Button",
  "description": "A raised control that lifts on hover and sinks when pressed.",
  "dependencies": ["@master/css"],
  "registryDependencies": [
    "https://ui.master.co/r/theme.json",
    "https://ui.master.co/r/icon.json",
    "https://ui.master.co/r/spinner.json"
  ],
  "files": [
    { "path": "ui/button.css", "type": "registry:file", "target": "~/ui/button.css", "content": "…" },
    { "path": "ui/button.json", "type": "registry:file", "target": "~/ui/button.json", "content": "…" }
  ],
  "categories": ["Actions"],
  "docs": "Import ui/button.css after ui/theme.css. Its contract is ui/button.json; markup: https://ui.master.co/components/button.md"
}
```

`registryDependencies` 列出元件使用的主題和組成該元件的契約。元件項目也有 `meta` 鍵，記錄元件的層級、是否需要腳本、類別，以及樣式表使用的 token 和 mixin。

## 項目 \{#items\}

| 項目 | 名稱 | 檔案 |
| --- | --- | --- |
| 主題 | `theme` | `ui/theme.css` |
| Paper 主題 | `theme-paper` | `ui/themes/paper.css` |
| 元件或版面配置類別 | 契約名稱，例如 `button`、`dialog`、`shell` | `ui/<name>.css` 和 `ui/<name>.json`。若有行為，還包含 `ui/<behavior>.js` 及其匯入的輔助程式 `ui/internal.js` |
| 框架元件 | `<framework>-<name>`，例如 `react-combobox`、`svelte-dialog`、`vue-toast` | 元件檔案，例如 `ui/combobox.tsx`、`ui/Dialog.svelte` 或 `ui/Toaster.vue`，以及元件從同一個目錄匯入的輔助程式 |
| 區塊 | `block-<slug>`，例如 `block-hero` | `ui/blocks/<slug>.html` |
| 頁面 | `page-<slug>`，例如 `page-dashboard` | `ui/pages/<slug>.html` |

區塊或頁面的檔案包含其文件頁面中第一個預覽的標記。`registryDependencies` 列出該標記使用的元件。

## 使用 master-ui 複製元件 \{#master-ui\}

套件內建的 `master-ui` 是官方指令。它會從已安裝的套件複製原始碼，確保原始碼與專案目前使用的版本一致。

在[已安裝 Master UI](/guide/installation) 的專案根目錄執行以下指令：

```bash
npx master-ui init        # once: ui/index.css, one @import per stylesheet
npx master-ui own button  # ui/button.css and ui/button.json; the import now points at the copy
```

改用產生的 `ui/index.css`，取代原本匯入整套 `@master/ui` 的寫法。確認其中的按鈕樣式匯入指向 `./button.css`，否則頁面仍會使用套件的按鈕樣式。[接手維護元件](/guide/customization#own-a-component)說明如何設定樣式表。

指令會將基準副本儲存在 `ui/.base/`，並將雜湊值記錄在 `master-ui.json`。請將它們與接手維護的原始碼一併提交，這樣在其他工作副本中也能和日後安裝的套件版本比對。更新流程請參閱[檢視上游變更](/guide/customization#upstream-changes)。

`own` 可複製有契約的元件與版面配置類別。區塊和頁面則可從各自的文件頁面或登錄庫複製。

使用 `add` 複製框架元件。它會以相同方式建立紀錄，因此也能使用 `status`、`diff` 和 `accept`。

```bash
npx master-ui add combobox --framework=react   # ui/combobox.tsx and ui/use-behavior.ts
npx master-ui add dialog                       # the framework is remembered
```

## 使用 shadcn CLI \{#shadcn-cli\}

要從託管目錄取得項目，包括區塊或頁面的標記，請使用登錄庫用戶端。若使用 shadcn CLI，請將命名空間加到 `components.json`。如果已有設定，請將以下欄位合併進去：

```json name=components.json
{
  "registries": {
    "@master": "https://ui.master.co/r/{name}.json"
  }
}
```

接著依名稱新增項目：

```bash
npx shadcn@latest add @master/button
```

檔案會寫入指定的目標路徑 `ui/button.css` 和 `ui/button.json`。依照項目 `docs` 的說明，在匯入主題後再匯入樣式表。

框架元件也能用同樣的方式新增，例如 `@master/react-combobox`。也可以直接使用項目網址，完全不需要 `components.json`：

```bash
npx shadcn@latest add https://ui.master.co/r/react-combobox.json
```

明確指定目標路徑的通用項目可使用僅含 `registries` 的設定，無須使用 Tailwind 專案。請參閱[登錄庫 API 文件](https://ui.shadcn.com/docs/registry/api-reference)。這些項目的目標路徑會將檔案放在專案的 `ui/` 目錄下。

框架項目會將 `@master/ui` 和所用框架宣告為相依套件。樣式表項目會宣告 `@master/css` 和所依賴的登錄庫項目。安裝後，請檢查套件資訊檔與鎖定檔，確認複製的原始碼能與已安裝的相依套件一起運作。執行頁面，檢查複製的元件在各種狀態下的表現，以及鍵盤操作行為。

從登錄庫安裝項目時，不會建立 Master UI 的基準副本和維護權紀錄，因此 `master-ui status` 和 `master-ui diff` 無法追蹤這類安裝。若要使用這套更新流程，請選擇 `own` 或 `add`。

## 接手後有哪些內容維持不變 \{#what-stays-the-same\}

接手維護元件後，樣式表改由專案維護，元件契約維持不變。

- 副本會附帶契約 `ui/<name>.json`。在此專案中，`master-ui check`、`master-ui contract` 和代理程式都會讀取這份契約，以它取代程式庫中的版本。
- 複製元件時，類別、各類別適用的元素、狀態屬性和公開自訂屬性都維持原樣。區塊、行為和文件也一樣適用。
- 副本仍會讀取主題的 token 並套用其中的 mixin，因此也會跟隨主題設定，包括你自己的主題。

只要契約持續反映實際的樣式表，以上行為就會維持一致。當樣式表新增、重新命名或移除類別時，請同步更新契約。[契約](/guide/contracts)說明契約包含哪些內容。
