无状态组件可以直接写成原生标记。应用需要管理值、根据数据生成内容、为部件关联 ID，或管理生命周期时，再复制相应的框架组件。这些组件在 React、Svelte 和 Vue 中按相同的契约渲染，并挂载随包提供的行为脚本。先按[安装](/guide/installation)中的步骤引入样式，复制组件时不会自动导入其 CSS。

## 直接使用标记 \{#markup\}

在 React、Svelte 和 Vue 中，按钮都是带有 `btn btn-primary` 的 `<button>`。库中没有 `Button` 组件，项目也不应编写只负责将 props 转换为类名的组件。

```tsx name=Toolbar.tsx
export function Toolbar({ saving }: { saving: boolean }) {
  return (
    <button type="button" className="btn btn-primary" disabled={saving} aria-busy={saving}>
      Save changes
    </button>
  )
}
```

- **按钮无需由组件管理。** 它没有要传递的值、要渲染的条目、用来关联各部分的 ID，也无需挂载行为脚本。按钮的状态由框架已设置的属性表示。
- **检查器读取类名。** [`master-ui check`](/guide/ai#check-the-markup) 读取 `.jsx`、`.tsx`、`.svelte`、`.vue` 和 `.astro` 文件。它能看到 `className="btn btn-outline"`，并报告该类名不存在，但无法看到 `<Button variant="outline">`。
- **标记无需客户端脚本。** 带有类名的原生元素在服务端完成渲染。在 React Server Components 中，这种写法不会增加客户端打包体积。

只有语法不同：

| 在 HTML 中 | 在 JSX 中 | 在 Svelte 和 Vue 中 |
| --- | --- | --- |
| `class="btn btn-primary"` | `className="btn btn-primary"` | 相同 |
| `for="email"` | `htmlFor="email"` | 相同 |
| `tabindex="-1"`, `popovertarget="share"` | `tabIndex={-1}`, `popoverTarget="share"` | 相同 |
| `commandfor="confirm"` 搭配 `command="show-modal"`，以及 `interestfor="tip"` | 如果 React 的类型尚未列出这些属性，就用展开语法传入 | 相同 |

项目中出现重复标记时，请按项目惯用的写法将其封装为自己的组件，并在组件内部以字符串字面量保留契约中的类名。

## 框架负责管理的内容 \{#what-a-framework-owns\}

框架至少需要管理以下四项中的一项，才需要使用框架组件：

1. **应用读取或设置的值。** 例如组合框选中了什么、对话框是否打开。
2. **根据数据渲染的条目。** 例如列表框的选项、一个月中的各个日期、菜单项。
3. **关联各部分的 ID。** 例如标签与控件、按钮与其打开的弹出层、标签页与对应的面板。
4. **生命周期。** 在元素存在时挂载[行为脚本](/guide/behaviors)，在元素移除时卸载。

库判断是否需要新增[类名](/guide/introduction#tiers)时也采用同样的标准：必须有可封装的逻辑或规则，单凭标记重复还不够。有 17 种模式符合这一标准。

| 组件 | 对应的渲染契约 | 框架负责管理的内容 |
| --- | --- | --- |
| `calendar` | [日历](/components/calendar) | 值和显示的月份 |
| `combobox` | [组合框](/components/combobox) | 值和选项 |
| `command` | [命令面板](/components/command) | 打开状态和命令 |
| `compare` | [对比](/components/compare) | 位置 |
| `dialog` | [对话框](/components/dialog) | 打开状态和触发元素引用的 ID |
| `field` | [表单字段](/components/input#hint-and-error) | 关联标签、控件、提示和错误信息的 ID |
| `listbox` | [列表框](/components/listbox) | 值和选项 |
| `menu` | [菜单](/components/menu) | 菜单项、触发元素引用的 ID，以及上下文菜单的目标 |
| `otp` | [OTP](/components/otp) | 验证码和输入格数量 |
| `popover` | [弹出层](/components/popover) | 打开状态和触发元素引用的 ID |
| `splitter` | [分隔条](/components/splitter) | 尺寸 |
| `stepper` | [步进器](/components/stepper) | 数值 |
| `tabs` | [标签页](/components/tabs#tab-panels) | 选中的标签页，以及关联标签页与对应面板的 ID |
| `toast` | [轻提示](/components/toast) | 队列，由 `toast()` 函数和显示队列内容的区域组成 |
| `tooltip` | [工具提示](/components/tooltip) | 关联控件及其标签的 ID |
| `tree` | [树形视图](/components/tree) | 选中的行和所有行 |
| `wheel` | [滚轮](/components/wheel) | 各列的值、选项 |

其余契约均以标记实现。选择框使用 `<select class="select">`，开关使用带 `role="switch"` 的复选框，折叠面板使用 `<details>`。浏览器管理这些控件的状态，框架按原生控件的方式绑定这些状态。

## 添加组件 \{#add\}

组件以源码形式存放在项目中，无需从包中导入。使用 `master-ui` 命令复制组件：

```bash
npx master-ui add combobox --framework=react
```

```
Add combobox: ui/combobox.tsx, ui/use-behavior.ts.
  It renders the markup of "master-ui contract combobox" and needs that stylesheet from @master/ui.
```

- 如果 `package.json` 只指定了 React、Svelte 或 Vue 中的一个，就从中读取框架。首次确定后，框架选择会保存在 `master-ui.json` 中。
- 组件从同一目录导入的辅助文件也会一并复制。React 和 Vue 使用 `use-behavior.ts`，Svelte 使用 `behavior.svelte.ts`。
- 默认将文件复制到项目根目录下的 `ui/`。用 `--directory` 指定其他目录，设置会被保存。例如，源码位于 `src` 下的 SvelteKit 项目可指定 `--directory=src/lib/ui`，Nuxt 项目可指定 `--directory=app/ui`。
- 同一目录下的 `ui/.base/` 保存每个文件刚复制时的原始版本。之后 `diff` 会用这份副本与上游比较，请保留原样。
- 运行 `npx master-ui add` 时省略组件名，即可列出所有组件。
- 已有副本会保留，因为它属于项目，可能已经过修改。

复制到项目中的组件负责渲染、生命周期和值同步。组件从 `@master/ui/behaviors` 导入行为脚本，升级该依赖即可获得键盘交互和焦点管理的修复。上游组件本身有更新时，使用 [`status` 和 `diff`](/guide/customization#upstream-changes) 查看差异，并将所需改动合并到工作副本。随后运行 `accept`，将当前安装的包版本记录为新的比较基准。该命令更新 `.base/` 和跟踪元数据，保留工作文件原样。[注册表](/guide/registry#items) 以 `react-combobox`、`svelte-combobox` 和 `vue-combobox` 为条目名提供相同的文件。

## 使用组件 \{#use\}

针对所用框架运行 `add combobox`，再从文件实际所在的目录导入副本。以下示例假定默认的 `ui/` 目录与示例文件位于同一级。各示例按各自框架的惯用写法实现同一个组合框。Svelte 示例可以实际操作。它使用复制到项目时获得的组件和行为脚本，在服务端渲染，并在预览中通过客户端水合启用交互。代码视图展示的就是该文件。

```tsx name=Region.tsx
'use client'
import { useState } from 'react'
import { Combobox } from './ui/combobox'

const regions = [
  { value: 'hnd', label: 'Tokyo' },
  { value: 'sin', label: 'Singapore' },
  { value: 'fra', label: 'Frankfurt', description: 'Germany' },
]

export function Region() {
  const [region, setRegion] = useState<string | null>(null)
  return (
    <Combobox options={regions} value={region} onValueChange={setRegion}
      aria-label="Region" listLabel="Regions" toggleLabel="Show regions" empty="No regions match." />
  )
}
```

<FrameworkPreview name="Region" height={304} title="Region.svelte" bodyClass="flex items-start justify-center p-lg min-h(300)" caption="输入文字筛选，按 Enter 或点击选中一项，再输入文字覆盖所选内容。应用保存的值会随操作更新。" />

```vue name=Region.vue
<script setup lang="ts">
import { ref } from 'vue'
import Combobox from './ui/Combobox.vue'

const regions = [
  { value: 'hnd', label: 'Tokyo' },
  { value: 'sin', label: 'Singapore' },
  { value: 'fra', label: 'Frankfurt', description: 'Germany' },
]
const region = ref<string | null>(null)
</script>

<template>
  <Combobox :options="regions" v-model="region"
    aria-label="Region" list-label="Regions" toggle-label="Show regions" empty="No regions match." />
</template>
```

选择东京，确认应用保存的值为 `hnd`，输入框显示该选项的标签。输入文字覆盖当前选项后，值会变为 `null`，直到再次选中某个选项。模型只保存选项值，搜索文本只用于筛选。

| | 值 | 是否打开 | 其他输出 |
| --- | --- | --- | --- |
| React | `value`，或用 `defaultValue` 让组件自行管理值，以及 `onValueChange` | `open`, `onOpenChange` | `onComplete`, `onValueCommit`, `onSearch` |
| Svelte | `bind:value` 和 `onValueChange` | `bind:open` 和 `onOpenChange` | 相同的回调 prop |
| Vue | `v-model` | `v-model:open` | `@complete`, `@value-commit`, `@search` |

各框架适配组件对值的管理方式不同。在 React 中，值由传入的 `value` 决定。用户修改组件的值后，如果调用方未在 `onValueChange` 中接纳变更，组件就会恢复到传入的值，行为与受控的 `<input>` 一致。`open` 也遵循同样的规则。在 Svelte 和 Vue 中，传值时若未使用 `bind:` 或 `v-model`，传入的值只作为初始值，之后由组件保留用户的选择。要拒绝更改，请将绑定值设回原值。

组件未自行处理的 prop 会传给相应的元素，也就是组合框的输入框、对话框的 `<dialog>` 或列表框的根元素。组合框的 `aria-label`、`placeholder` 和 `name` 都通过这种方式传入。

### 页面自身的标记 \{#the-pages-own-markup\}

使用这些示例前，请先添加所需组件，例如 `npx master-ui add dialog --framework=react` 或 `--framework=vue`。对话框、弹出层、菜单和工具提示都由页面提供的控件打开。触发按钮由页面负责渲染。组件将用于指向自身的属性交给页面，页面把这些属性展开到自己的按钮上，浏览器便会像处理普通页面一样打开对话框。

```tsx name=DeleteProject.tsx
'use client'
import { useState } from 'react'
import { Dialog } from './ui/dialog'

export function DeleteProject({ remove }: { remove: () => Promise<void> }) {
  const [open, setOpen] = useState(false)
  async function confirm() {
    await remove()
    setOpen(false)
  }
  return (
    <Dialog id="delete-project" aria-labelledby="delete-project-title"
      open={open} onOpenChange={setOpen}
      trigger={attributes => <button type="button" className="btn" {...attributes}>Delete project</button>}>
      <header className="dialog-header">
        <h2 className="dialog-title" id="delete-project-title">Delete this project?</h2>
        <p className="dialog-description">Atlas and its 14 deployments are removed.</p>
      </header>
      <footer className="dialog-footer">
        <button type="button" className="btn" {...{ commandfor: 'delete-project', command: 'close' }}>Cancel</button>
        <button type="button" className="btn btn-primary" onClick={confirm}>Delete project</button>
      </footer>
    </Dialog>
  )
}
```

<FrameworkPreview name="DeleteProject" height={320} title="DeleteProject.svelte" bodyClass="flex items-start justify-center p-lg min-h(320)" caption="按钮通过 commandfor 打开对话框，按钮本身无需事件处理函数。应用收到对话框已打开的通知，并在项目被删除时通过自身状态关闭对话框。" />

```vue name=DeleteProject.vue
<script setup lang="ts">
import { ref } from 'vue'
import Dialog from './ui/Dialog.vue'

const props = defineProps<{ remove: () => Promise<void> }>()
const open = ref(false)
async function confirm() {
  await props.remove()
  open.value = false
}
</script>

<template>
  <Dialog id="delete-project" aria-labelledby="delete-project-title" v-model:open="open">
    <template #trigger="attributes">
      <button type="button" class="btn" v-bind="attributes">Delete project</button>
    </template>
    <header class="dialog-header">
      <h2 class="dialog-title" id="delete-project-title">Delete this project?</h2>
      <p class="dialog-description">Atlas and its 14 deployments are removed.</p>
    </header>
    <footer class="dialog-footer">
      <button type="button" class="btn" commandfor="delete-project" command="close">Cancel</button>
      <button type="button" class="btn btn-primary" @click="confirm">Delete project</button>
    </footer>
  </Dialog>
</template>
```

这里的 `remove` 是调用方提供的应用删除函数。示例在该函数成功完成后关闭对话框。请为这个请求补上应用的处理中和错误状态。对话框内部各部分都是契约规定的标记。`dialog-header`、`dialog-title` 和 `dialog-footer` 仅提供结构，无需管理任何值、数据、ID 或生命周期。仅在应用决定何时打开或关闭对话框时传入 `open`，例如请求失败后打开对话框，或路由变化时关闭对话框。省略该参数时，由触发器和浏览器处理整个过程。

[字段](/components/input#hint-and-error) 以同样的方式反向传递信息。它管理 ID，并为页面中的控件提供包含这些 ID 的属性：

```tsx name=Email.tsx
import { Field } from './ui/field'

export function Email({ error }: { error?: string }) {
  return (
    <Field label="Work email" hint="We only send receipts." error={error}>
      {control => <input className="input" type="email" name="email" {...control} />}
    </Field>
  )
}
```

### 轻提示 \{#toasts\}

轻提示在事件发生时才会生成元素，因此轻提示组件管理一个队列。`toast()` 函数可在任意位置调用，显示队列内容的区域只渲染一次。

```tsx name=App.tsx
'use client'
import { toast, Toaster } from './ui/toast'

export function ToastExample() {
  return (
    <>
      <Toaster />
      <button type="button" className="btn" onClick={() => toast({
        title: 'Preview ready', description: 'The build can now be reviewed.', status: 'success'
      })}>Show notification</button>
    </>
  )
}
```

在 Svelte 和 Vue 中，`toast` 分别由 `Toaster.svelte` 和 `Toaster.vue` 具名导出。轻提示会在 6 秒后自动消失。`duration` 可设置其他时长，`duration: false` 则会让轻提示一直显示，直到被关闭。

## 逻辑由谁负责 \{#where-the-logic-is\}

对于带行为脚本的模式，适配器将键盘操作和选择规则交给行为脚本处理。适配器有三项职责：

- **渲染契约规定的标记**，并在其中写入初始值。这样，在任何脚本运行前，初始 HTML 就已正确反映该值。
- **挂载行为脚本**，并在配置项变化时重新挂载。
- **同步值。** 应用设置新值时，写入行为脚本的 [`value`](/guide/behaviors#the-value)。每当 `input` 或 `change` 事件到达根元素时，读取该值。

首次渲染后，行为脚本像在普通页面上一样更新属性。各框架共用同一套行为代码，键盘操作集中在一处处理。共用的测试场景会检查每个框架的适配器，依次挂载组件、对照契约检查标记、按键、读取操作后的值、设置值，再卸载组件。

要改变按键的作用或选择操作的含义，请[自行维护行为脚本](/guide/behaviors#own-a-behavior)。之后运行 `master-ui add` 创建新的组件文件时，会使用本地的行为脚本。如果已添加该组件，请手动更新它的导入语句，因为 `add` 会保留现有文件。

## 服务端渲染 \{#on-a-server\}

<GuideFigure name="frameworks" title="渲染和行为脚本的生命周期">

**渲染和交互的生命周期不同。** 列表框的选中值已在服务端 HTML 中标记。挂载后，适配器挂载行为脚本，并在应用和行为脚本之间同步值。卸载时调用清理函数，移除监听器并停止观察。清理过程不会恢复原始标记。

</GuideFigure>

- **初始 HTML 包含状态。** 选中的选项、选中的标签页、分隔条的尺寸，以及日历显示的月份和选中的日期，都写在服务端发送的标记中。只有浏览器才能确定的标记会在行为脚本挂载时出现，例如日历中的当天标记。
- **在服务端渲染日历时，请指定其 `locale`**。月份和星期的名称来自 `Intl`，而服务端和浏览器采用的语言可能不同。
- **在 React Server Components 中，** 挂载行为脚本或持有状态的组件属于客户端组件，并声明 `'use client'`。如果一个文件向这类组件传入函数，例如 `trigger`、`onValueChange` 或某一项的 `onSelect`，该文件也属于客户端组件。因此，上面的示例以 `'use client'` 开头。服务端组件无法向客户端组件传递函数。`Field` 和 `Tooltip` 只负责通过 ID 关联元素，因此可以在服务端渲染，前提是所在文件不渲染其他客户端内容。纯标记可在其所在位置直接渲染。
- **ID 由框架生成。** React 和 Vue 使用 `useId`，Svelte 使用 `$props.id()`，从而让服务端和浏览器生成相同的 ID。Vue 在每个应用内单独编号。如果一个页面挂载多个 Vue 应用，例如使用岛屿架构时，请为每个应用设置 `app.config.idPrefix`，否则其中两个应用会把不同的元素都命名为 `v-0`。

## 编写自己的组件 \{#your-own\}

需要沿用同一行为脚本并采用不同的渲染方式时，请使用 `master-ui add` 复制的辅助函数。例如，为所选框架添加 `listbox` 以获取辅助函数，然后在 `ui/` 目录旁编写 `Sizes` 组件。下方的导入语句采用的就是这个目录结构。将初始选择写入标记，确保服务端 HTML 正确，再由辅助函数同步后续的值。在 React 中，该辅助函数是一个返回 ref 的 Hook：

```tsx name=Sizes.tsx
'use client'
import { useState } from 'react'
import { listbox } from '@master/ui/behaviors/listbox.js'
import { useBehavior } from './ui/use-behavior'

export function Sizes({ value, onValueChange }: { value: string, onValueChange: (value: string | string[] | null) => void }) {
  const ref = useBehavior(listbox, undefined, { value, onValueChange })
  const [first] = useState(() => value)
  return (
    <div className="listbox" role="listbox" aria-label="Size" tabIndex={0} ref={ref}>
      {['Small', 'Medium', 'Large'].map(size => (
        <div className="listbox-option" role="option" aria-checked={size === first} key={size}>{size}</div>
      ))}
    </div>
  )
}
```

第二个参数是行为的选项，第三个参数提供值及其变化的监听器。在 Svelte 中，辅助函数创建一个 attachment；在 Vue 中，它是一个接收模板引用和模型的组合式函数：

```svelte name=Sizes.svelte
<script lang="ts">
  import { untrack } from 'svelte'
  import { listbox } from '@master/ui/behaviors/listbox.js'
  import { behavior } from './ui/behavior.svelte.js'

  let { value = $bindable() }: { value?: string | string[] | null } = $props()
  const first = untrack(() => [value ?? []].flat())
  const attach = behavior(listbox, undefined, { value: () => value, change: next => { value = next } })
</script>

<div class="listbox" role="listbox" aria-label="Size" tabindex="0" {@attach attach}>
  {#each ['Small', 'Medium', 'Large'] as size}
    <!-- The behavior writes aria-selected on the active option. -->
    <!-- svelte-ignore a11y_role_has_required_aria_props -->
    <div class="listbox-option" role="option" aria-checked={first.includes(size)}>{size}</div>
  {/each}
</div>
```

```vue name=Sizes.vue
<script setup lang="ts">
import { useTemplateRef } from 'vue'
import { listbox } from '@master/ui/behaviors/listbox.js'
import { useBehavior } from './ui/use-behavior'

const value = defineModel<string | string[] | null>()
const first = [value.value ?? []].flat()
useBehavior(useTemplateRef<HTMLElement>('root'), listbox, undefined, value)
</script>

<template>
  <div class="listbox" role="listbox" aria-label="Size" tabindex="0" ref="root">
    <div v-for="size in ['Small', 'Medium', 'Large']" :key="size" class="listbox-option" role="option" :aria-checked="first.includes(size)">{{ size }}</div>
  </div>
</template>
```

[行为脚本](/guide/behaviors#in-a-framework)展示了如何在各框架中直接挂载行为，无需辅助函数。

## 其他无样式组件库 \{#headless-libraries\}

随库提供的组件使用浏览器原生能力和 Master UI 的行为脚本，无需依赖任何无样式组件库。

如果应用需要使用其他库的行为，将契约中的类加到该库对应的元素上，并对照契约逐项检查状态、键盘操作和焦点转移。如果适配器写入的属性与契约不同，项目可能需要自行维护样式表。仅添加 CSS 类无法保证兼容。先完成并验证一个完整的交互，再将集成方式推广到整个项目。
