無狀態的元件請使用原生標記；當應用程式需要協調值、資料、id 或生命週期時，再複製框架元件。複製的元件會在 React、Svelte 與 Vue 中渲染相同的契約，並掛上套件中的行為。請先完成[安裝](/guide/installation)，讓它們的樣式可用；複製元件並不會匯入它的 CSS。

## 標記就是標記 \{#markup\}

無論在 React、Svelte 或 Vue 中，按鈕都是帶有 `btn btn-primary` 的 `<button>`。沒有 `Button` 元件，專案也不應該撰寫只是把 props 轉成 class 的元件。

```tsx name=Toolbar.tsx
export function Toolbar({ saving }: { saving: boolean }) {
  return (
    <button type="button" className="btn btn-primary" disabled={saving} aria-busy={saving}>
      Save changes
    </button>
  )
}
```

- **沒有需要元件擁有的東西。** 按鈕沒有要傳遞的值、沒有要渲染的列、沒有要連結的 id，也沒有要掛上的東西。它的狀態就是框架本來就會設定的屬性。
- **檢查器讀取的是 class。** [`master-ui check`](/guide/ai#check-the-markup) 會讀取 `.jsx`、`.tsx`、`.svelte`、`.vue` 與 `.astro` 檔案。它看得到 `className="btn btn-outline"` 並指出沒有這個 class；但它看不到 `<Button variant="outline">`。
- **標記不需要用戶端腳本。** 帶有 class 的原生元素在伺服器上渲染後就停留在那裡。在 React Server Components 中，它不會為用戶端的打包結果增加任何內容。

只有語法不同：

| 在 HTML 中 | 在 JSX 中 | 在 Svelte 與 Vue 中 |
| --- | --- | --- |
| `class="btn btn-primary"` | `className="btn btn-primary"` | 相同 |
| `for="email"` | `htmlFor="email"` | 相同 |
| `tabindex="-1"`、`popovertarget="share"` | `tabIndex={-1}`、`popoverTarget="share"` | 相同 |
| `commandfor="confirm"` 搭配 `command="show-modal"`、`interestfor="tip"` | 在 React 的型別尚未列出它們時，以展開方式傳入 | 相同 |

當標記在專案中重複出現時，請以專案自己的慣用寫法，將它包裝成專案自己的元件，並在其中以字面字串保留契約的 class。

## 框架擁有什麼 \{#what-a-framework-owns\}

當框架至少擁有以下四者之一時，才會有框架元件：

1. **應用程式讀取或設定的值。** combobox 中選擇了什麼、對話框是否開啟。
2. **由資料渲染的列。** listbox 的選項、一個月的各天、選單的項目。
3. **連結各部件的 id。** 標籤與其控制項、按鈕與它開啟的 popover、分頁與其面板。
4. **生命週期。** 在元素存在時掛上、在元素離開時卸下的[行為](/guide/behaviors)。

這和元件庫判斷是否需要 [class](/guide/introduction#tiers) 的標準相同：看的是知識，而不是重複的標記。有十七個模式通過這項標準。

| 元件 | 渲染的契約 | 框架擁有的東西 |
| --- | --- | --- |
| `calendar` | [日曆](/components/calendar) | 值，以及它繪製的月份 |
| `combobox` | [Combobox](/components/combobox) | 值、選項 |
| `command` | [命令面板](/components/command) | 是否開啟、命令 |
| `compare` | [Compare](/components/compare) | 位置 |
| `dialog` | [對話框](/components/dialog) | 是否開啟、其觸發元素所指名的 id |
| `field` | [欄位](/components/input#hint-and-error) | 連結標籤、控制項、提示與錯誤的 id |
| `listbox` | [Listbox](/components/listbox) | 值、選項 |
| `menu` | [選單](/components/menu) | 項目、其觸發元素所指名的 id、右鍵選單的目標 |
| `otp` | [OTP](/components/otp) | 代碼、格位數量 |
| `popover` | [Popover](/components/popover) | 是否開啟、其觸發元素所指名的 id |
| `splitter` | [分隔條](/components/splitter) | 尺寸 |
| `stepper` | [Stepper](/components/stepper) | 數字 |
| `tabs` | [分頁](/components/tabs#tab-panels) | 所選的分頁、連結分頁與面板的 id |
| `toast` | [Toast](/components/toast) | 佇列：一個 `toast()` 函式，以及顯示它的區域 |
| `tooltip` | [工具提示](/components/tooltip) | 連結控制項與其標籤的 id |
| `tree` | [樹狀結構](/components/tree) | 所選的列、各列 |
| `wheel` | [Wheel](/components/wheel) | 每一欄的值、選項 |

其他所有契約都只是標記。select 是 `<select class="select">`，開關是帶有 `role="switch"` 的核取方塊，accordion 是 `<details>`：它們的狀態由瀏覽器保存，框架則像繫結任何原生控制項一樣繫結它。

## 加入元件 \{#add\}

元件是你專案中的原始碼，而不是從套件匯入的東西。由 `master-ui` 指令複製它：

```bash
npx master-ui add combobox --framework=react
```

```
Add combobox: ui/combobox.tsx, ui/use-behavior.ts.
  It renders the markup of "master-ui contract combobox" and needs that stylesheet from @master/ui.
```

- 當 `package.json` 恰好只列出 React、Svelte 與 Vue 其中之一時，會從中讀取框架，並在第一次之後記錄於 `master-ui.json`。
- 元件從旁邊匯入的小型輔助函式會一併複製：React 與 Vue 為 `use-behavior.ts`，Svelte 為 `behavior.svelte.ts`。
- 檔案會放在專案根目錄的 `ui/`。`--directory` 可指定其他位置，並會被記住：原始碼位於 `src` 下的 SvelteKit 可用 `--directory=src/lib/ui`，Nuxt 則可用 `--directory=app/ui`。
- 在它們旁邊，`ui/.base/` 保存每個檔案取得時的原樣。之後 `diff` 會拿這份副本與上游比較；請不要更動它。
- 不帶名稱的 `npx master-ui add` 會列出所有元件。
- 已經存在的副本會被保留。它屬於你，而且可能已經被編輯過。

複製的元件負責渲染、生命週期與值的同步。它從 `@master/ui/behaviors` 匯入其行為，因此升級該相依套件時，就會帶來鍵盤與焦點的修正。當元件本身在上游有所變更時，請使用 [`status` 與 `diff`](/guide/customization#upstream-changes) 審視差異，並將你需要的變更合併到你的工作副本中。接著執行 `accept`，將已安裝套件的版本記錄為新的已儲存基準；它會更新 `.base/` 與追蹤用的中繼資料，而不會改變你的工作檔案。[登錄庫](/guide/registry#items)以 `react-combobox`、`svelte-combobox` 與 `vue-combobox` 提供相同的檔案。

## 使用元件 \{#use\}

以你使用的框架執行 `add combobox`，再從複製檔案的實際目錄匯入它。以下範例假設預設的 `ui/` 目錄位於範例檔案旁邊。每個範例都以該框架自己的慣用寫法呈現同一個 combobox。Svelte 版本可以實際執行：它在伺服器上渲染，並在預覽中完成 hydration，使用的是專案會取得的同一個元件與行為。它的程式碼檢視就是該檔案。

```tsx name=Region.tsx
'use client'
import { useState } from 'react'
import { Combobox } from './ui/combobox'

const regions = [
  { value: 'hnd', label: 'Tokyo' },
  { value: 'sin', label: 'Singapore' },
  { value: 'fra', label: 'Frankfurt', description: 'Germany' },
]

export function Region() {
  const [region, setRegion] = useState<string | null>(null)
  return (
    <Combobox options={regions} value={region} onValueChange={setRegion}
      aria-label="Region" listLabel="Regions" toggleLabel="Show regions" empty="No regions match." />
  )
}
```

<FrameworkPreview name="Region" height={304} title="Region.svelte" bodyClass="flex items-start justify-center p-lg min-h(300)" caption="輸入文字以篩選，按 Enter 或點擊進行選擇，再覆寫已選的內容：應用程式保存的值會跟著改變。" />

```vue name=Region.vue
<script setup lang="ts">
import { ref } from 'vue'
import Combobox from './ui/Combobox.vue'

const regions = [
  { value: 'hnd', label: 'Tokyo' },
  { value: 'sin', label: 'Singapore' },
  { value: 'fra', label: 'Frankfurt', description: 'Germany' },
]
const region = ref<string | null>(null)
</script>

<template>
  <Combobox :options="regions" v-model="region"
    aria-label="Region" list-label="Regions" toggle-label="Show regions" empty="No regions match." />
</template>
```

選擇 Tokyo，並確認應用程式保存的是 `hnd`；欄位則顯示選項的標籤。覆寫該選擇後，在再次選擇某個選項之前，值會變成 `null`。model 保存的是選項的值，而不是任意的搜尋文字。

| | 值 | 是否開啟 | 其他輸出 |
| --- | --- | --- | --- |
| React | `value`，或讓元件自行保存的 `defaultValue`，以及 `onValueChange` | `open`、`onOpenChange` | `onComplete`、`onValueCommit`、`onSearch` |
| Svelte | `bind:value`，以及 `onValueChange` | `bind:open`，以及 `onOpenChange` | 相同的回呼 props |
| Vue | `v-model` | `v-model:open` | `@complete`、`@value-commit`、`@search` |

各轉接元件對值的歸屬並不相同。在 React 中，`value` 由擁有者說了算：當讀者改變了元件，而擁有者沒有在 `onValueChange` 中接受該變更時，元件會回到它被給予的值，就像受控的 `<input>` 一樣。`open` 也是如此。Svelte 與 Vue 沒有這樣的規則。未透過 `bind:` 或 `v-model` 傳入的值只是元件的起始值，之後元件會保留讀者所選的內容。若要在這些框架中拒絕某個變更，請自行將繫結的值設回去。

不屬於元件本身的 props 會傳給讀者預期的元素：combobox 的欄位、對話框的 `<dialog>`、listbox 的根元素。combobox 就是這樣取得其 `aria-label`、`placeholder` 與 `name`。

### 頁面自己的標記 \{#the-pages-own-markup\}

使用這些範例之前，請先加入所需的元件，例如 `npx master-ui add dialog --framework=react` 或 `--framework=vue`。對話框、popover、選單與工具提示，是由屬於頁面的控制項開啟的。元件不會渲染自己的按鈕。它將指名自己的屬性交給頁面，由頁面展開到自己的按鈕上；接著由瀏覽器開啟對話框，就像在一般頁面上一樣。

```tsx name=DeleteProject.tsx
'use client'
import { useState } from 'react'
import { Dialog } from './ui/dialog'

export function DeleteProject({ remove }: { remove: () => Promise<void> }) {
  const [open, setOpen] = useState(false)
  async function confirm() {
    await remove()
    setOpen(false)
  }
  return (
    <Dialog id="delete-project" aria-labelledby="delete-project-title"
      open={open} onOpenChange={setOpen}
      trigger={attributes => <button type="button" className="btn" {...attributes}>Delete project</button>}>
      <header className="dialog-header">
        <h2 className="dialog-title" id="delete-project-title">Delete this project?</h2>
        <p className="dialog-description">Atlas and its 14 deployments are removed.</p>
      </header>
      <footer className="dialog-footer">
        <button type="button" className="btn" {...{ commandfor: 'delete-project', command: 'close' }}>Cancel</button>
        <button type="button" className="btn btn-primary" onClick={confirm}>Delete project</button>
      </footer>
    </Dialog>
  )
}
```

<FrameworkPreview name="DeleteProject" height={320} title="DeleteProject.svelte" bodyClass="flex items-start justify-center p-lg min-h(320)" caption="按鈕透過 commandfor 開啟對話框，本身沒有處理函式。應用程式會得知對話框已開啟，並在專案刪除後由自己的狀態將其關閉。" />

```vue name=DeleteProject.vue
<script setup lang="ts">
import { ref } from 'vue'
import Dialog from './ui/Dialog.vue'

const props = defineProps<{ remove: () => Promise<void> }>()
const open = ref(false)
async function confirm() {
  await props.remove()
  open.value = false
}
</script>

<template>
  <Dialog id="delete-project" aria-labelledby="delete-project-title" v-model:open="open">
    <template #trigger="attributes">
      <button type="button" class="btn" v-bind="attributes">Delete project</button>
    </template>
    <header class="dialog-header">
      <h2 class="dialog-title" id="delete-project-title">Delete this project?</h2>
      <p class="dialog-description">Atlas and its 14 deployments are removed.</p>
    </header>
    <footer class="dialog-footer">
      <button type="button" class="btn" commandfor="delete-project" command="close">Cancel</button>
      <button type="button" class="btn btn-primary" @click="confirm">Delete project</button>
    </footer>
  </Dialog>
</template>
```

此處的 `remove` 是應用程式的刪除函式，由呼叫端提供。範例會在它完成後關閉對話框；請在該請求周圍加上應用程式的忙碌與錯誤狀態。對話框內的部件是契約的標記，而不是元件：`dialog-header`、`dialog-title` 與 `dialog-footer` 不擁有任何東西。只有在由應用程式決定時才傳入 `open`，例如在請求失敗後開啟對話框，或在路由改變時關閉對話框。沒有它時，整件事由觸發元素與瀏覽器完成。

[欄位](/components/input#hint-and-error)以相反方向的相同方式運作。它擁有 id，並將攜帶這些 id 的屬性交給頁面的控制項：

```tsx name=Email.tsx
import { Field } from './ui/field'

export function Email({ error }: { error?: string }) {
  return (
    <Field label="Work email" hint="We only send receipts." error={error}>
      {control => <input className="input" type="email" name="email" {...control} />}
    </Field>
  )
}
```

### Toast \{#toasts\}

toast 在事情發生之前沒有任何元素，因此它的元件是一個佇列：一個可從任何地方呼叫的 `toast()` 函式，以及一個只渲染一次、用來顯示佇列內容的區域。

```tsx name=App.tsx
'use client'
import { toast, Toaster } from './ui/toast'

export function ToastExample() {
  return (
    <>
      <Toaster />
      <button type="button" className="btn" onClick={() => toast({
        title: 'Preview ready', description: 'The build can now be reviewed.', status: 'success'
      })}>Show notification</button>
    </>
  )
}
```

在 Svelte 與 Vue 中，`toast` 是 `Toaster.svelte` 與 `Toaster.vue` 的具名匯出。toast 會在六秒後自行離開；`duration` 可設定其他時間，`duration: false` 則讓它保留到被關閉為止。

## 邏輯在哪裡 \{#where-the-logic-is\}

對於有行為的模式，轉接元件會將鍵盤處理與選取規則交給該行為。它有三項職責：

- **渲染契約的標記**，並在其中繪製好第一個值。第一份 HTML 在任何腳本執行之前就是正確的。
- **掛上行為**，並在選項改變時重新掛上。
- **傳遞值。** 當應用程式設定另一個值時，它會寫入行為的 [`value`](/guide/behaviors#the-value)；並在每個抵達根元素的 `input` 與 `change` 上讀取它。

第一次渲染之後，由行為變動屬性，就像在一般頁面上一樣。共用的行為程式碼讓鍵盤處理集中在一處。共用的測試情境會檢查每個框架轉接元件：掛載、依契約檢查標記、按下按鍵、讀取產生的值、設定值、卸載。

若要改變某個按鍵的作用或選取的意義，請[自行擁有該行為](/guide/behaviors#own-a-behavior)。之後執行 `master-ui add` 建立新的元件檔案時，會使用那個本地行為。若你已經加入了該元件，請自行更新它的匯入；`add` 會保留既有檔案。

## 在伺服器上 \{#on-a-server\}

<GuideFigure name="frameworks" title="渲染與行為的生命週期">

**渲染與互動有不同的生命週期。** 已選的 listbox 值在伺服器 HTML 中就已標示。掛載之後，轉接元件會掛上行為，並將應用程式的值與其同步。卸載時會呼叫清理函式，停止監聽器與觀察器；清理不會還原原本的標記。

</GuideFigure>

- **第一份 HTML 就保有狀態。** 已選的選項、所選的分頁、分隔條的尺寸、日曆的月份及其已選日期，都在伺服器送出的標記中。只有瀏覽器才知道的標示，例如日曆中的今天，會在行為掛上時出現。
- **在伺服器上渲染日曆時，請提供 `locale`。** 月份與星期的名稱來自 `Intl`，而伺服器與瀏覽器對要使用的語言不一定看法一致。
- **在 React Server Components 中，** 掛上行為或保存狀態的元件都是用戶端元件，並宣告 `'use client'`。將函式（`trigger`、`onValueChange` 或項目的 `onSelect`）交給這些元件的檔案，本身也是用戶端元件，這就是上述範例以 `'use client'` 開頭的原因：Server Component 無法將函式傳給用戶端元件。`Field` 與 `Tooltip` 只負責連結 id，因此它們會在伺服器上渲染，所在的檔案不會渲染其他來自用戶端的東西。所有屬於標記的內容都在撰寫它的地方渲染。
- **id 由框架產生：** React 與 Vue 使用 `useId`，Svelte 使用 `$props.id()`，因此伺服器與瀏覽器之間的 id 會一致。Vue 在單一應用程式內為它們編號。若頁面掛載數個 Vue 應用程式（例如 islands 架構），請為每個應用程式設定 `app.config.idPrefix`，否則其中兩個會將不同的元素都命名為 `v-0`。

## 你自己的元件 \{#your-own\}

當你需要在同一個行為周圍使用不同的渲染方式時，請使用 `master-ui add` 複製的輔助函式。例如，為所選框架加入 `listbox` 以取得其輔助函式，然後在 `ui/` 目錄旁撰寫一個 `Sizes` 元件，如下方的匯入所假設。將初始選擇渲染到標記中，讓伺服器 HTML 保持正確，並讓輔助函式同步之後的值。在 React 中，輔助函式是一個回傳 ref 的 hook：

```tsx name=Sizes.tsx
'use client'
import { useState } from 'react'
import { listbox } from '@master/ui/behaviors/listbox.js'
import { useBehavior } from './ui/use-behavior'

export function Sizes({ value, onValueChange }: { value: string, onValueChange: (value: string | string[] | null) => void }) {
  const ref = useBehavior(listbox, undefined, { value, onValueChange })
  const [first] = useState(() => value)
  return (
    <div className="listbox" role="listbox" aria-label="Size" tabIndex={0} ref={ref}>
      {['Small', 'Medium', 'Large'].map(size => (
        <div className="listbox-option" role="option" aria-checked={size === first} key={size}>{size}</div>
      ))}
    </div>
  )
}
```

它的第二個引數是行為的選項，第三個引數是值以及接收值的對象。在 Svelte 中，輔助函式會產生一個 attachment；在 Vue 中，它是一個接收樣板 ref 與 model 的 composable：

```svelte name=Sizes.svelte
<script lang="ts">
  import { untrack } from 'svelte'
  import { listbox } from '@master/ui/behaviors/listbox.js'
  import { behavior } from './ui/behavior.svelte.js'

  let { value = $bindable() }: { value?: string | string[] | null } = $props()
  const first = untrack(() => [value ?? []].flat())
  const attach = behavior(listbox, undefined, { value: () => value, change: next => { value = next } })
</script>

<div class="listbox" role="listbox" aria-label="Size" tabindex="0" {@attach attach}>
  {#each ['Small', 'Medium', 'Large'] as size}
    <!-- The behavior writes aria-selected on the active option. -->
    <!-- svelte-ignore a11y_role_has_required_aria_props -->
    <div class="listbox-option" role="option" aria-checked={first.includes(size)}>{size}</div>
  {/each}
</div>
```

```vue name=Sizes.vue
<script setup lang="ts">
import { useTemplateRef } from 'vue'
import { listbox } from '@master/ui/behaviors/listbox.js'
import { useBehavior } from './ui/use-behavior'

const value = defineModel<string | string[] | null>()
const first = [value.value ?? []].flat()
useBehavior(useTemplateRef<HTMLElement>('root'), listbox, undefined, value)
</script>

<template>
  <div class="listbox" role="listbox" aria-label="Size" tabindex="0" ref="root">
    <div v-for="size in ['Small', 'Medium', 'Large']" :key="size" class="listbox-option" role="option" :aria-checked="first.includes(size)">{{ size }}</div>
  </div>
</template>
```

[行為](/guide/behaviors#in-a-framework)說明了在各框架中不使用輔助函式、直接掛上行為的方式。

## 其他 headless 元件庫 \{#headless-libraries\}

隨附的元件使用瀏覽器平台與 Master UI 的行為。它們不相依於任何 headless 元件庫。

若應用程式需要其他元件庫的行為，請將契約的 class 放在其對應的元素上，並依照契約檢查每個狀態、鍵盤動作與焦點轉移。寫入不同屬性的轉接層，可能需要自行擁有的樣式表。單憑 CSS class 並不能確立相容性；請先完成一個完整的互動，再將整合方式套用到整個專案。
