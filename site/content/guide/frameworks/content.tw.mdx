無狀態元件可直接使用原生標記。當應用程式需要協調值、資料、ID 或生命週期時，再複製框架元件。複製的元件會在 React、Svelte 和 Vue 中算繪符合相同契約的標記，並掛載套件提供的行為。先依照[安裝](/guide/installation)設定樣式，因為複製元件時不會一併匯入 CSS。

## 直接使用標記 \{#markup\}

在 React、Svelte 和 Vue 中，按鈕都是套用 `btn btn-primary` 的 `<button>`。Master UI 沒有提供 `Button` 元件，如果只是要把 props 轉成 class，專案也不應另外寫一個。

```tsx name=Toolbar.tsx
export function Toolbar({ saving }: { saving: boolean }) {
  return (
    <button type="button" className="btn btn-primary" disabled={saving} aria-busy={saving}>
      Save changes
    </button>
  )
}
```

- **按鈕沒有需要元件管理的內容。** 它不必傳遞值、算繪列、用 ID 連結元素或掛載行為。它的狀態由框架原本就會設定的屬性表示。
- **檢查工具會讀取 class。** [`master-ui check`](/guide/ai#check-the-markup) 會讀取 `.jsx`、`.tsx`、`.svelte`、`.vue` 和 `.astro` 檔案。它能讀到 `className="btn btn-outline"` 並回報沒有這個 class，但讀不到 `<Button variant="outline">`。
- **標記不需要用戶端腳本。** 帶有 class 的原生元素在伺服器上算繪即可。在 React Server Components 中，這類元素不會增加打包後的用戶端程式碼。

各框架的差異只在語法：

| HTML | JSX | Svelte 和 Vue |
| --- | --- | --- |
| `class="btn btn-primary"` | `className="btn btn-primary"` | 同 HTML |
| `for="email"` | `htmlFor="email"` | 同 HTML |
| `tabindex="-1"`, `popovertarget="share"` | `tabIndex={-1}`, `popoverTarget="share"` | 同 HTML |
| `commandfor="confirm"` 搭配 `command="show-modal"`，以及 `interestfor="tip"` | 若 React 的型別尚未列出這些屬性，請用展開語法傳入 | 同 HTML |

同一段標記在專案中反覆出現時，可以用專案慣用的寫法將它封裝成自己的元件，並在元件內以字串常值保留契約指定的 class。

## 框架負責管理哪些內容 \{#what-a-framework-owns\}

只要框架需要負責下列至少一項，就適合使用框架元件：

1. **應用程式讀取或設定的值。** 例如組合方塊選了哪一項、對話框是否開啟。
2. **由資料算繪的列。** 例如清單方塊的選項、某個月的日期、選單的項目。
3. **用來連結各部位的 ID。** 例如標籤與其控制項、按鈕與它開啟的彈出框、分頁標籤與其面板。
4. **生命週期。** 元素出現時掛載[行為](/guide/behaviors)，移除時卸載。

這也是程式庫判斷是否需要提供 [class](/guide/introduction#tiers) 的標準。重點在於是否有需要封裝的知識，單純重複的標記不構成理由。共有 17 種模式符合這個標準。

| 元件 | 算繪的標記契約 | 框架負責管理 |
| --- | --- | --- |
| `calendar` | [行事曆](/components/calendar) | 值與顯示的月份 |
| `combobox` | [組合方塊](/components/combobox) | 值與選項 |
| `command` | [指令面板](/components/command) | 開啟狀態與指令 |
| `compare` | [比較](/components/compare) | 位置 |
| `dialog` | [對話框](/components/dialog) | 開啟狀態與觸發控制項指定的 ID |
| `field` | [欄位](/components/input#hint-and-error) | 用來連結標籤、控制項、提示與錯誤訊息的 ID |
| `listbox` | [清單方塊](/components/listbox) | 值與選項 |
| `menu` | [選單](/components/menu) | 項目、觸發控制項指定的 ID，以及快顯選單的目標 |
| `otp` | [OTP](/components/otp) | 驗證碼與輸入格數 |
| `popover` | [彈出框](/components/popover) | 開啟狀態與觸發控制項指定的 ID |
| `splitter` | [分隔器](/components/splitter) | 尺寸 |
| `stepper` | [數值步進器](/components/stepper) | 數值 |
| `tabs` | [分頁標籤](/components/tabs#tab-panels) | 選取的分頁標籤，以及連結標籤與面板的 ID |
| `toast` | [浮動通知](/components/toast) | 佇列，包括 `toast()` 函式與顯示通知的區域 |
| `tooltip` | [工具提示](/components/tooltip) | 用來連結控制項與其標籤的 ID |
| `tree` | [樹狀清單](/components/tree) | 選取的列與所有列 |
| `wheel` | [滾輪](/components/wheel) | 各欄的值與選項 |

其他契約都直接用標記實作。選取清單用 `<select class="select">`，開關用帶有 `role="switch"` 的核取方塊，手風琴用 `<details>`。這些元素的狀態由瀏覽器管理，框架會像處理其他原生控制項一樣繫結其狀態。

## 新增元件 \{#add\}

元件會成為專案中的原始碼，無須從套件匯入。用 `master-ui` 指令複製元件：

```bash
npx master-ui add combobox --framework=react
```

```
Add combobox: ui/combobox.tsx, ui/use-behavior.ts.
  It renders the markup of "master-ui contract combobox" and needs that stylesheet from @master/ui.
```

- 若 `package.json` 只列出 React、Svelte 和 Vue 其中一種，指令會自動辨識框架，並在第一次執行後將選擇記錄在 `master-ui.json`。
- 元件從同目錄匯入的輔助檔案也會一併複製。React 和 Vue 使用 `use-behavior.ts`，Svelte 使用 `behavior.svelte.ts`。
- 檔案預設放在專案根目錄的 `ui/`。可用 `--directory` 指定其他位置，指令會記住這項設定。例如 SvelteKit 的原始碼放在 `src` 下，可指定 `--directory=src/lib/ui`，Nuxt 則可指定 `--directory=app/ui`。
- 同一目錄下的 `ui/.base/` 會保留各檔案複製當下的版本。之後 `diff` 會用這份副本與上游比對，請保留原樣。
- 執行 `npx master-ui add` 時省略名稱，即可列出可用的元件。
- 如果元件副本已存在，指令會保留它，讓你先前的修改得以保留。

複製到專案的元件負責算繪、生命週期和值的同步。它會從 `@master/ui/behaviors` 匯入行為，因此升級這項相依套件時，也會取得鍵盤操作與焦點處理的修正。上游元件本身有變更時，可用 [`status` 和 `diff`](/guide/customization#upstream-changes) 檢視差異，再將需要的變更合併到工作副本。接著執行 `accept`，將已安裝套件的版本記為新的比對基準。這會更新 `.base/` 和追蹤用的中繼資料，並保留工作檔案原樣。[登錄庫](/guide/registry#items)中的 `react-combobox`、`svelte-combobox` 和 `vue-combobox` 提供的是同一批檔案。

## 使用元件 \{#use\}

針對你使用的框架執行 `add combobox`，再從檔案實際所在的目錄匯入複製的檔案。以下範例假設預設的 `ui/` 目錄就在範例檔案旁。各範例都以框架慣用的寫法呈現同一個組合方塊。Svelte 範例可以直接操作。它先在伺服器上算繪，再於預覽中完成 hydration，使用的元件與行為和專案取得的相同。「程式碼」檢視會顯示該範例檔案。

```tsx name=Region.tsx
'use client'
import { useState } from 'react'
import { Combobox } from './ui/combobox'

const regions = [
  { value: 'hnd', label: 'Tokyo' },
  { value: 'sin', label: 'Singapore' },
  { value: 'fra', label: 'Frankfurt', description: 'Germany' },
]

export function Region() {
  const [region, setRegion] = useState<string | null>(null)
  return (
    <Combobox options={regions} value={region} onValueChange={setRegion}
      aria-label="Region" listLabel="Regions" toggleLabel="Show regions" empty="No regions match." />
  )
}
```

<FrameworkPreview name="Region" height={304} title="Region.svelte" bodyClass="flex items-start justify-center p-lg min-h(300)" caption="輸入文字來篩選，按 Enter 或點選某個選項，再輸入文字覆蓋選取結果。應用程式持有的值會跟著更新。" />

```vue name=Region.vue
<script setup lang="ts">
import { ref } from 'vue'
import Combobox from './ui/Combobox.vue'

const regions = [
  { value: 'hnd', label: 'Tokyo' },
  { value: 'sin', label: 'Singapore' },
  { value: 'fra', label: 'Frankfurt', description: 'Germany' },
]
const region = ref<string | null>(null)
</script>

<template>
  <Combobox :options="regions" v-model="region"
    aria-label="Region" list-label="Regions" toggle-label="Show regions" empty="No regions match." />
</template>
```

選取東京，確認應用程式持有的值為 `hnd`，而欄位會顯示該選項的標籤。輸入文字覆蓋選取結果後，值會變成 `null`，直到再次選取選項。模型只儲存選項的值，搜尋欄位中的文字不會寫入模型。

| | 值 | 開啟狀態 | 其他輸出 |
| --- | --- | --- | --- |
| React | `value`（或用 `defaultValue` 讓元件自行管理）與 `onValueChange` | `open`、`onOpenChange` | `onComplete`, `onValueCommit`, `onSearch` |
| Svelte | `bind:value` 與 `onValueChange` | `bind:open` 與 `onOpenChange` | 與 React 相同的回呼 props |
| Vue | `v-model` | `v-model:open` | `@complete`, `@value-commit`, `@search` |

各框架的轉接元件管理值的方式不同。在 React 中，傳入的 `value` 由呼叫端決定。使用者操作元件後，如果呼叫端沒有在 `onValueChange` 中採用新值，元件就會回到原先傳入的值，與受控的 `<input>` 相同。`open` 也適用同樣的規則。在 Svelte 和 Vue 中，若傳值時未使用 `bind:` 或 `v-model`，傳入的值只用於初始化，之後由元件保留使用者選取的值。若要拒絕變更，請自行將繫結的值設回原值。

元件沒有自行處理的 props 會傳給對應的元素，例如組合方塊的欄位、對話框的 `<dialog>`，或清單方塊的根元素。因此，你可以直接在組合方塊元件上設定 `aria-label`、`placeholder` 和 `name`。

### 由頁面提供的標記 \{#the-pages-own-markup\}

使用這些範例前，請先新增所需元件，例如執行 `npx master-ui add dialog --framework=react`，或改用 `--framework=vue`。對話框、彈出框、選單與工具提示都由頁面自己的控制項開啟。元件不會自行算繪按鈕。元件會把指向自身的屬性交給頁面，讓頁面用展開語法將它們套用到自己的按鈕。接著，瀏覽器就會像在純 HTML 頁面上一樣開啟對話框。

```tsx name=DeleteProject.tsx
'use client'
import { useState } from 'react'
import { Dialog } from './ui/dialog'

export function DeleteProject({ remove }: { remove: () => Promise<void> }) {
  const [open, setOpen] = useState(false)
  async function confirm() {
    await remove()
    setOpen(false)
  }
  return (
    <Dialog id="delete-project" aria-labelledby="delete-project-title"
      open={open} onOpenChange={setOpen}
      trigger={attributes => <button type="button" className="btn" {...attributes}>Delete project</button>}>
      <header className="dialog-header">
        <h2 className="dialog-title" id="delete-project-title">Delete this project?</h2>
        <p className="dialog-description">Atlas and its 14 deployments are removed.</p>
      </header>
      <footer className="dialog-footer">
        <button type="button" className="btn" {...{ commandfor: 'delete-project', command: 'close' }}>Cancel</button>
        <button type="button" className="btn btn-primary" onClick={confirm}>Delete project</button>
      </footer>
    </Dialog>
  )
}
```

<FrameworkPreview name="DeleteProject" height={320} title="DeleteProject.svelte" bodyClass="flex items-start justify-center p-lg min-h(320)" caption="按鈕透過 commandfor 開啟對話框，無需另外設定事件處理函式。應用程式會收到對話框已開啟的通知，並在專案刪除後透過自身的狀態關閉對話框。" />

```vue name=DeleteProject.vue
<script setup lang="ts">
import { ref } from 'vue'
import Dialog from './ui/Dialog.vue'

const props = defineProps<{ remove: () => Promise<void> }>()
const open = ref(false)
async function confirm() {
  await props.remove()
  open.value = false
}
</script>

<template>
  <Dialog id="delete-project" aria-labelledby="delete-project-title" v-model:open="open">
    <template #trigger="attributes">
      <button type="button" class="btn" v-bind="attributes">Delete project</button>
    </template>
    <header class="dialog-header">
      <h2 class="dialog-title" id="delete-project-title">Delete this project?</h2>
      <p class="dialog-description">Atlas and its 14 deployments are removed.</p>
    </header>
    <footer class="dialog-footer">
      <button type="button" class="btn" commandfor="delete-project" command="close">Cancel</button>
      <button type="button" class="btn btn-primary" @click="confirm">Delete project</button>
    </footer>
  </Dialog>
</template>
```

這裡的 `remove` 是由呼叫端提供的應用程式刪除函式。範例會等它成功完成後關閉對話框。請為這項請求加上應用程式的處理中與錯誤狀態。對話框內的 `dialog-header`、`dialog-title` 和 `dialog-footer` 都是契約定義的標記，各自無須管理狀態或行為。只有在應用程式需要決定開啟狀態時才傳入 `open`，例如請求失敗後開啟對話框，或切換路由時關閉對話框。省略這項設定時，觸發控制項與瀏覽器就能處理開關。

[欄位](/components/input#hint-and-error)也採用同樣的做法，但連結的方向相反。欄位元件管理 ID，並把帶有這些 ID 的屬性交給頁面自己的控制項：

```tsx name=Email.tsx
import { Field } from './ui/field'

export function Email({ error }: { error?: string }) {
  return (
    <Field label="Work email" hint="We only send receipts." error={error}>
      {control => <input className="input" type="email" name="email" {...control} />}
    </Field>
  )
}
```

### 浮動通知 \{#toasts\}

浮動通知在事件發生前沒有對應的元素，因此元件以佇列運作。你可以在任何地方呼叫 `toast()`，而通知會顯示在只需算繪一次的區域中。

```tsx name=App.tsx
'use client'
import { toast, Toaster } from './ui/toast'

export function ToastExample() {
  return (
    <>
      <Toaster />
      <button type="button" className="btn" onClick={() => toast({
        title: 'Preview ready', description: 'The build can now be reviewed.', status: 'success'
      })}>Show notification</button>
    </>
  )
}
```

在 Svelte 和 Vue 中，`toast` 分別是 `Toaster.svelte` 和 `Toaster.vue` 的具名匯出。浮動通知預設會在 6 秒後自動消失。可用 `duration` 調整顯示時間，或用 `duration: false` 讓通知一直保留到被關閉為止。

## 邏輯放在哪裡 \{#where-the-logic-is\}

對於有行為的模式，轉接元件會把鍵盤操作與選取規則交給行為處理。轉接元件有三項職責：

- **算繪契約規定的標記**，並一併呈現初始值。初次產生的 HTML 在任何腳本執行前就已正確反映狀態。
- **掛載行為**，並在設定選項變更時重新掛載。
- **傳遞值。** 當應用程式設定新值時，轉接元件會寫入行為的 [`value`](/guide/behaviors#the-value)。每當 `input` 或 `change` 事件傳到根元素時，就會讀取該值。

首次算繪後，行為會像在純 HTML 頁面上一樣更新屬性。各框架共用同一份行為程式碼，集中處理鍵盤操作。共用的測試情境會檢查各框架的轉接元件，包括掛載元件、核對標記是否符合契約、按鍵、讀取輸出的值、設定值，以及卸載元件。

若要變更按鍵的作用或選取規則，請[自行維護行為](/guide/behaviors#own-a-behavior)。之後執行 `master-ui add` 建立新的元件檔案時，指令會使用專案中的這份行為。如果已經新增元件，請自行更新匯入路徑，因為 `add` 會保留現有檔案。

## 在伺服器上算繪 \{#on-a-server\}

<GuideFigure name="frameworks" title="算繪與行為的生命週期">

**算繪與互動各有自己的生命週期。** 伺服器產生的 HTML 已標記清單方塊中選取的值。掛載後，轉接元件會掛載行為，並與應用程式的值同步。卸載時會呼叫清理函式來停止監聽與觀察，原先的標記則不會還原。

</GuideFigure>

- **初始 HTML 就帶有狀態。** 伺服器送出的標記包含選取的選項、選取的分頁標籤、分隔器的尺寸，以及行事曆的月份與選取日期。只有瀏覽器才能判定的標記，例如行事曆上的今天，會在掛載行為時補上。
- 在伺服器上算繪行事曆時，**請為行事曆指定 `locale`**。月份與星期的名稱由 `Intl` 產生，而伺服器與瀏覽器使用的語言可能不同。
- **在 React Server Components 中，** 會掛載行為或保有狀態的元件是用戶端元件，並宣告 `'use client'`。若某個檔案會將函式傳給這類元件，例如 `trigger`、`onValueChange` 或項目的 `onSelect`，該檔案也是用戶端元件。這就是上方範例以 `'use client'` 開頭的原因，因為 Server Component 無法將函式傳給用戶端元件。`Field` 和 `Tooltip` 只透過 ID 連結元素，因此可以在伺服器上算繪，前提是同一檔案沒有算繪其他用戶端元件。純標記則可在所在位置直接算繪。
- **ID 由框架產生：** React 和 Vue 使用 `useId`，Svelte 使用 `$props.id()`，讓伺服器與瀏覽器產生一致的 ID。Vue 會在各個應用程式內各自編號。若頁面掛載多個 Vue 應用程式，例如採用島嶼架構的頁面，請為每個應用程式指定不同的 `app.config.idPrefix`，以免兩個應用程式都將不同的元素命名為 `v-0`。

## 建立自己的元件 \{#your-own\}

如果想沿用相同的行為但改用不同的標記，可以使用 `master-ui add` 一併複製的輔助程式。例如，先針對選用的框架新增 `listbox` 以取得輔助程式，再依照下方範例的匯入路徑，將 `Sizes` 元件放在 `ui/` 目錄旁。在標記中呈現初始選取值，確保伺服器產生的 HTML 正確，再由輔助程式同步後續的值。React 的輔助程式是一個會傳回 ref 的 hook：

```tsx name=Sizes.tsx
'use client'
import { useState } from 'react'
import { listbox } from '@master/ui/behaviors/listbox.js'
import { useBehavior } from './ui/use-behavior'

export function Sizes({ value, onValueChange }: { value: string, onValueChange: (value: string | string[] | null) => void }) {
  const ref = useBehavior(listbox, undefined, { value, onValueChange })
  const [first] = useState(() => value)
  return (
    <div className="listbox" role="listbox" aria-label="Size" tabIndex={0} ref={ref}>
      {['Small', 'Medium', 'Large'].map(size => (
        <div className="listbox-option" role="option" aria-checked={size === first} key={size}>{size}</div>
      ))}
    </div>
  )
}
```

它的第二個引數是行為的設定選項，第三個引數則包含值及接收值變更的回呼。Svelte 的輔助程式會建立 attachment，Vue 的輔助程式則是接收範本 ref 和模型的 composable：

```svelte name=Sizes.svelte
<script lang="ts">
  import { untrack } from 'svelte'
  import { listbox } from '@master/ui/behaviors/listbox.js'
  import { behavior } from './ui/behavior.svelte.js'

  let { value = $bindable() }: { value?: string | string[] | null } = $props()
  const first = untrack(() => [value ?? []].flat())
  const attach = behavior(listbox, undefined, { value: () => value, change: next => { value = next } })
</script>

<div class="listbox" role="listbox" aria-label="Size" tabindex="0" {@attach attach}>
  {#each ['Small', 'Medium', 'Large'] as size}
    <!-- The behavior writes aria-selected on the active option. -->
    <!-- svelte-ignore a11y_role_has_required_aria_props -->
    <div class="listbox-option" role="option" aria-checked={first.includes(size)}>{size}</div>
  {/each}
</div>
```

```vue name=Sizes.vue
<script setup lang="ts">
import { useTemplateRef } from 'vue'
import { listbox } from '@master/ui/behaviors/listbox.js'
import { useBehavior } from './ui/use-behavior'

const value = defineModel<string | string[] | null>()
const first = [value.value ?? []].flat()
useBehavior(useTemplateRef<HTMLElement>('root'), listbox, undefined, value)
</script>

<template>
  <div class="listbox" role="listbox" aria-label="Size" tabindex="0" ref="root">
    <div v-for="size in ['Small', 'Medium', 'Large']" :key="size" class="listbox-option" role="option" :aria-checked="first.includes(size)">{{ size }}</div>
  </div>
</template>
```

[行為](/guide/behaviors#in-a-framework)說明如何在各框架中直接掛載行為，無須使用輔助程式。

## 其他 headless 程式庫 \{#headless-libraries\}

Master UI 提供的元件使用瀏覽器原生功能和 Master UI 的行為，無須依賴 headless 元件程式庫。

如果應用程式需要使用其他程式庫的行為，請將契約指定的 class 套用到對應的元素，逐一核對各種狀態、鍵盤操作與焦點切換是否符合契約。如果轉接元件設定的屬性不同，可能需要自行維護樣式表。單靠 CSS class 無法確保相容性。請先驗證一套完整的互動流程，再將整合方式套用到整個專案。
