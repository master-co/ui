상태가 없는 컴포넌트에는 네이티브 마크업을 사용하고, 애플리케이션에서 값, 데이터, ID 또는 수명 주기를 관리해야 할 때는 프레임워크 컴포넌트를 복사해 사용하세요. 복사한 컴포넌트는 React, Svelte, Vue에서 동일한 계약에 따른 마크업을 렌더링하고 패키지에서 제공하는 동작을 연결합니다. 컴포넌트를 복사해도 CSS는 자동으로 가져오지 않으므로 먼저 [설치](/guide/installation) 안내에 따라 스타일시트를 설정합니다.

## 마크업을 그대로 사용하는 경우 \{#markup\}

React, Svelte, Vue에서 버튼은 모두 `btn btn-primary` 클래스를 적용한 `<button>`입니다. `Button` 컴포넌트는 제공하지 않으며, props를 클래스로 바꾸기만 하는 컴포넌트는 프로젝트에서 따로 만들지 않습니다.

```tsx name=Toolbar.tsx
export function Toolbar({ saving }: { saving: boolean }) {
  return (
    <button type="button" className="btn btn-primary" disabled={saving} aria-busy={saving}>
      Save changes
    </button>
  )
}
```

- **컴포넌트가 관리할 것이 없습니다.** 버튼에는 전달할 값도, 렌더링할 행도, 요소를 연결할 ID도, 연결할 동작도 없습니다. 버튼의 상태는 프레임워크에서 이미 설정하는 속성으로 표현됩니다.
- **검사기는 클래스를 읽습니다.** [`master-ui check`](/guide/ai#check-the-markup)는 `.jsx`, `.tsx`, `.svelte`, `.vue`, `.astro` 파일을 읽습니다. 검사기는 `className="btn btn-outline"`에서 클래스 이름을 읽고 해당 클래스가 없으면 보고하지만, `<Button variant="outline">`에서는 검사할 클래스 이름을 찾을 수 없습니다.
- **마크업에는 클라이언트 스크립트가 필요하지 않습니다.** 클래스가 지정된 네이티브 요소는 서버에서 렌더링되는 것으로 충분합니다. React Server Components에서는 클라이언트 번들에 아무것도 추가하지 않습니다.

문법만 다릅니다:

| HTML | JSX | Svelte와 Vue |
| --- | --- | --- |
| `class="btn btn-primary"` | `className="btn btn-primary"` | 동일 |
| `for="email"` | `htmlFor="email"` | 동일 |
| `tabindex="-1"`, `popovertarget="share"` | `tabIndex={-1}`, `popoverTarget="share"` | 동일 |
| `command="show-modal"`과 함께 쓰는 `commandfor="confirm"`, `interestfor="tip"` | React 타입에 아직 선언되지 않은 속성은 스프레드 구문으로 전달 | 동일 |

프로젝트에서 같은 마크업이 반복되면 프로젝트의 관례에 맞게 자체 컴포넌트로 감싸고, 계약에 지정된 클래스는 컴포넌트 안에 문자열 리터럴로 유지합니다.

## 프레임워크가 관리하는 항목 \{#what-a-framework-owns\}

프레임워크가 다음 네 가지 중 하나 이상을 관리할 때 프레임워크 컴포넌트를 사용합니다:

1. **애플리케이션이 읽거나 설정하는 값.** 콤보박스에서 선택한 값이나 대화상자가 열려 있는지 여부입니다.
2. **데이터를 바탕으로 렌더링하는 행.** 리스트박스의 옵션, 달력에 표시되는 한 달의 날짜, 메뉴 항목이 이에 해당합니다.
3. **요소를 연결하는 ID.** 레이블과 컨트롤, 버튼과 그 버튼으로 여는 팝오버, 탭과 해당 패널을 연결합니다.
4. **수명 주기.** 요소가 생성되면 [동작](/guide/behaviors)을 연결하고, 요소가 제거되면 연결을 해제합니다.

라이브러리가 [클래스](/guide/introduction#tiers)에 적용하는 기준도 같습니다. 마크업이 반복되는지가 아니라 관리할 정보가 있는지를 봅니다. 이 기준을 충족하는 패턴은 17개입니다.

| 컴포넌트 | 구현하는 계약 | 프레임워크가 관리하는 항목 |
| --- | --- | --- |
| `calendar` | [달력](/components/calendar) | 값, 표시하는 월 |
| `combobox` | [콤보박스](/components/combobox) | 값, 옵션 |
| `command` | [명령 팔레트](/components/command) | 열림 여부, 명령 목록 |
| `compare` | [비교](/components/compare) | 위치 |
| `dialog` | [대화상자](/components/dialog) | 열림 여부, 트리거가 참조하는 ID |
| `field` | [필드](/components/input#hint-and-error) | 레이블, 컨트롤, 도움말, 오류 메시지를 연결하는 ID |
| `listbox` | [리스트박스](/components/listbox) | 값, 옵션 |
| `menu` | [메뉴](/components/menu) | 메뉴 항목, 트리거가 참조하는 ID, 컨텍스트 메뉴의 대상 |
| `otp` | [OTP](/components/otp) | 코드, 슬롯 수 |
| `popover` | [팝오버](/components/popover) | 열림 여부, 트리거가 참조하는 ID |
| `splitter` | [분할 조절기](/components/splitter) | 크기 |
| `stepper` | [숫자 조절기](/components/stepper) | 숫자 값 |
| `tabs` | [탭](/components/tabs#tab-panels) | 선택된 탭, 탭과 패널을 연결하는 ID |
| `toast` | [토스트](/components/toast) | 대기열을 구성하는 `toast()` 함수와 표시 영역 |
| `tooltip` | [툴팁](/components/tooltip) | 컨트롤과 해당 레이블을 연결하는 ID |
| `tree` | [트리](/components/tree) | 선택된 행, 행 목록 |
| `wheel` | [휠](/components/wheel) | 각 열의 값과 옵션 |

나머지 계약은 모두 마크업으로 이루어집니다. 셀렉트는 `<select class="select">`이고, 스위치는 `role="switch"` 속성을 지정한 체크박스이며, 아코디언은 `<details>`입니다. 브라우저가 상태를 관리하고 프레임워크는 다른 네이티브 컨트롤과 같은 방식으로 상태를 바인딩합니다.

## 컴포넌트 추가 \{#add\}

컴포넌트는 프로젝트에 소스 파일로 들어갑니다. 패키지에서 가져오는 대신 `master-ui` 명령으로 복사합니다.

```bash
npx master-ui add combobox --framework=react
```

```
Add combobox: ui/combobox.tsx, ui/use-behavior.ts.
  It renders the markup of "master-ui contract combobox" and needs that stylesheet from @master/ui.
```

- `package.json`에 React, Svelte, Vue 중 정확히 하나가 지정되어 있으면 해당 프레임워크를 사용합니다. 처음 확인한 프레임워크는 `master-ui.json`에 저장해 이후에도 사용합니다.
- 컴포넌트가 같은 디렉터리에서 가져오는 작은 헬퍼도 함께 복사됩니다. React와 Vue에서는 `use-behavior.ts`, Svelte에서는 `behavior.svelte.ts` 파일을 사용합니다.
- 파일은 프로젝트 루트의 `ui/`에 저장됩니다. `--directory`로 다른 경로를 지정하면 그 경로를 기억합니다. 소스가 `src` 아래에 있는 SvelteKit에서는 `--directory=src/lib/ui`를, Nuxt에서는 `--directory=app/ui`를 지정할 수 있습니다.
- 같은 위치의 `ui/.base/`에는 각 파일을 처음 가져온 상태 그대로 보관합니다. 나중에 `diff` 명령이 이 사본을 업스트림과 비교하므로 사본은 그대로 둡니다.
- 컴포넌트 이름 없이 `npx master-ui add` 명령을 실행하면 컴포넌트 목록이 표시됩니다.
- 이미 복사한 파일은 그대로 둡니다. 프로젝트에서 직접 관리하는 파일이므로 이미 수정했을 수 있습니다.

복사한 컴포넌트는 렌더링, 수명 주기, 값 동기화를 담당합니다. 동작은 `@master/ui/behaviors`에서 가져오므로 이 의존성을 업그레이드하면 키보드와 포커스 관련 수정 사항이 적용됩니다. 업스트림에서 컴포넌트 자체가 바뀌면 [`status` 및 `diff`](/guide/customization#upstream-changes)로 차이를 검토하고 원하는 변경 사항을 작업 사본에 병합하세요. 그런 다음 `accept`를 실행해 설치된 패키지 버전을 새 기준으로 기록하세요. 이 명령은 작업 파일을 그대로 두고 `.base/` 디렉터리와 추적 메타데이터를 갱신합니다. [레지스트리](/guide/registry#items)에는 `react-combobox`, `svelte-combobox`, `vue-combobox`와 동일한 파일이 들어 있습니다.

## 컴포넌트 사용 \{#use\}

사용하는 프레임워크에 맞춰 `add combobox` 명령을 실행한 뒤 복사된 파일을 실제 디렉터리에서 가져옵니다. 아래 예제에서는 기본 `ui/` 디렉터리가 예제 파일과 같은 위치에 있다고 가정합니다. 각 예제는 같은 콤보박스를 해당 프레임워크의 관례에 맞게 구현합니다. Svelte 예제는 서버에서 렌더링되고 미리보기에서 하이드레이션되며, 실제 프로젝트에 제공되는 컴포넌트와 동작으로 실행됩니다. 코드 보기에는 해당 파일의 내용이 표시됩니다.

```tsx name=Region.tsx
'use client'
import { useState } from 'react'
import { Combobox } from './ui/combobox'

const regions = [
  { value: 'hnd', label: 'Tokyo' },
  { value: 'sin', label: 'Singapore' },
  { value: 'fra', label: 'Frankfurt', description: 'Germany' },
]

export function Region() {
  const [region, setRegion] = useState<string | null>(null)
  return (
    <Combobox options={regions} value={region} onValueChange={setRegion}
      aria-label="Region" listLabel="Regions" toggleLabel="Show regions" empty="No regions match." />
  )
}
```

```vue name=Region.vue
<script setup lang="ts">
import { ref } from 'vue'
import Combobox from './ui/Combobox.vue'

const regions = [
  { value: 'hnd', label: 'Tokyo' },
  { value: 'sin', label: 'Singapore' },
  { value: 'fra', label: 'Frankfurt', description: 'Germany' },
]
const region = ref<string | null>(null)
</script>

<template>
  <Combobox :options="regions" v-model="region"
    aria-label="Region" list-label="Regions" toggle-label="Show regions" empty="No regions match." />
</template>
```

Tokyo를 선택하고 애플리케이션의 값이 `hnd`인지 확인합니다. 필드에는 옵션의 레이블이 표시됩니다. 선택한 내용을 덮어쓰면 옵션을 다시 선택할 때까지 값은 `null`입니다. 모델에는 임의의 검색어가 아니라 옵션의 값이 저장됩니다.

| | 값 | 열림 여부 | 기타 출력 |
| --- | --- | --- | --- |
| React | `value` 또는 컴포넌트가 직접 관리하도록 하는 `defaultValue`, 그리고 `onValueChange` | `open`, `onOpenChange` | `onComplete`, `onValueCommit`, `onSearch` |
| Svelte | `bind:value` 및 `onValueChange` | `bind:open` 및 `onOpenChange` | 동일한 콜백 prop |
| Vue | `v-model` | `v-model:open` | `@complete`, `@value-commit`, `@search` |

값을 누가 관리하는지는 어댑터마다 다릅니다. React에서는 상위 코드가 `value`로 전달한 값이 기준입니다. 사용자가 값을 변경해도 상위 코드가 `onValueChange`에서 변경을 반영하지 않으면, 제어 방식의 `<input>`과 마찬가지로 컴포넌트는 전달받은 값으로 돌아갑니다. `open`에도 같은 규칙이 적용됩니다. Svelte와 Vue에서 `bind:`나 `v-model` 없이 전달한 값은 초깃값으로 쓰이며, 이후에는 컴포넌트가 사용자가 선택한 값을 유지합니다. 변경을 받아들이지 않으려면 바인딩된 값을 직접 되돌리세요.

컴포넌트 자체에서 사용하는 prop을 제외한 나머지는 사용자가 예상하는 요소에 전달됩니다. 콤보박스에서는 필드, 대화상자에서는 `<dialog>`, 리스트박스에서는 루트 요소입니다. 이 방식으로 콤보박스에 `aria-label`, `placeholder`, `name`을 전달할 수 있습니다.

### 페이지 자체 마크업 \{#the-pages-own-markup\}

이 예제를 사용하기 전에 `npx master-ui add dialog --framework=react` 또는 `--framework=vue`처럼 필요한 컴포넌트를 추가하세요. 대화상자, 팝오버, 메뉴, 툴팁은 페이지에 속한 컨트롤로 엽니다. 컴포넌트가 자체 버튼을 렌더링하는 대신 대상을 식별하는 속성을 페이지에 넘기면, 페이지는 그 속성을 자체 버튼에 펼쳐 적용합니다. 그러면 일반 페이지에서와 같이 브라우저가 대화상자를 엽니다.

```tsx name=DeleteProject.tsx
'use client'
import { useState } from 'react'
import { Dialog } from './ui/dialog'

export function DeleteProject({ remove }: { remove: () => Promise<void> }) {
  const [open, setOpen] = useState(false)
  async function confirm() {
    await remove()
    setOpen(false)
  }
  return (
    <Dialog id="delete-project" aria-labelledby="delete-project-title"
      open={open} onOpenChange={setOpen}
      trigger={attributes => <button type="button" className="btn" {...attributes}>Delete project</button>}>
      <header className="dialog-header">
        <h2 className="dialog-title" id="delete-project-title">Delete this project?</h2>
        <p className="dialog-description">Atlas and its 14 deployments are removed.</p>
      </header>
      <footer className="dialog-footer">
        <button type="button" className="btn" {...{ commandfor: 'delete-project', command: 'close' }}>Cancel</button>
        <button type="button" className="btn btn-primary" onClick={confirm}>Delete project</button>
      </footer>
    </Dialog>
  )
}
```

<FrameworkPreview name="DeleteProject" height={320} title="DeleteProject.svelte" bodyClass="flex items-start justify-center p-lg min-h(320)" caption="버튼은 별도 핸들러 없이 commandfor를 통해 대화상자를 엽니다. 애플리케이션은 대화상자가 열렸음을 통지받고, 프로젝트가 삭제되면 자체 상태를 갱신해 닫습니다." />

```vue name=DeleteProject.vue
<script setup lang="ts">
import { ref } from 'vue'
import Dialog from './ui/Dialog.vue'

const props = defineProps<{ remove: () => Promise<void> }>()
const open = ref(false)
async function confirm() {
  await props.remove()
  open.value = false
}
</script>

<template>
  <Dialog id="delete-project" aria-labelledby="delete-project-title" v-model:open="open">
    <template #trigger="attributes">
      <button type="button" class="btn" v-bind="attributes">Delete project</button>
    </template>
    <header class="dialog-header">
      <h2 class="dialog-title" id="delete-project-title">Delete this project?</h2>
      <p class="dialog-description">Atlas and its 14 deployments are removed.</p>
    </header>
    <footer class="dialog-footer">
      <button type="button" class="btn" commandfor="delete-project" command="close">Cancel</button>
      <button type="button" class="btn btn-primary" @click="confirm">Delete project</button>
    </footer>
  </Dialog>
</template>
```

여기서 호출자는 애플리케이션의 삭제 함수인 `remove`를 전달합니다. 예제에서는 함수가 성공적으로 완료된 뒤 대화상자를 닫습니다. 실제로 사용할 때는 요청의 처리 중 상태와 오류 상태를 추가하세요. 대화상자 안의 `dialog-header`, `dialog-title`, `dialog-footer`는 계약에 따른 마크업입니다. 이 부분은 컴포넌트로 구현하지 않으며 자체적으로 관리하는 항목도 없습니다. 요청이 실패한 뒤 대화상자를 열거나 경로가 바뀔 때 닫는 등 애플리케이션이 열림 여부를 결정하는 경우에만 `open`을 전달하세요. 이 값을 생략하면 트리거와 브라우저가 열고 닫는 동작을 모두 처리합니다.

[필드](/components/input#hint-and-error)도 같은 방식으로 작동하지만 속성을 전달하는 방향은 반대입니다. 필드가 ID를 관리하고, 그 ID를 담은 속성을 페이지의 컨트롤에 넘깁니다.

```tsx name=Email.tsx
import { Field } from './ui/field'

export function Email({ error }: { error?: string }) {
  return (
    <Field label="Work email" hint="We only send receipts." error={error}>
      {control => <input className="input" type="email" name="email" {...control} />}
    </Field>
  )
}
```

### 토스트 \{#toasts\}

토스트는 표시할 일이 생겨야 요소가 만들어지므로 컴포넌트는 큐로 구현됩니다. 어디서든 호출할 수 있는 `toast()` 함수와, 한 번만 렌더링되어 큐의 내용을 표시하는 영역으로 구성됩니다.

```tsx name=App.tsx
'use client'
import { toast, Toaster } from './ui/toast'

export function ToastExample() {
  return (
    <>
      <Toaster />
      <button type="button" className="btn" onClick={() => toast({
        title: 'Preview ready', description: 'The build can now be reviewed.', status: 'success'
      })}>Show notification</button>
    </>
  )
}
```

Svelte의 `Toaster.svelte`와 Vue의 `Toaster.vue`는 각각 `toast`를 이름으로 내보냅니다. 토스트는 6초 후 자동으로 사라집니다. `duration`으로 표시 시간을 바꿀 수 있고, `duration: false`로 설정하면 닫힐 때까지 표시됩니다.

## 로직의 위치 \{#where-the-logic-is\}

동작이 있는 패턴에서 어댑터는 키보드 입력 처리와 선택 규칙을 해당 동작에 맡깁니다. 어댑터는 다음 세 가지를 담당합니다.

- **계약에 따른 마크업을 렌더링합니다.** 초깃값을 미리 반영하므로 스크립트가 실행되기 전부터 HTML이 올바른 상태를 표시합니다.
- **동작을 연결합니다.** 옵션이 바뀌면 동작을 다시 연결합니다.
- **값을 전달합니다.** 애플리케이션이 새 값을 설정하면 동작의 [`value`](/guide/behaviors#the-value)에 그 값을 쓰고, `input` 및 `change` 이벤트가 루트에 도달할 때마다 그 값을 읽습니다.

첫 렌더링 이후에는 일반 페이지에서와 같이 동작이 속성을 갱신합니다. 공통 동작 코드 한 곳에서 키보드 입력을 처리합니다. 각 프레임워크 어댑터에는 공통 테스트 시나리오를 적용합니다. 컴포넌트를 마운트하고, 마크업이 계약에 맞는지 확인하고, 키를 누르고, 반환된 값을 읽고, 값을 설정한 뒤 언마운트합니다.

키를 눌렀을 때 수행할 작업이나 선택 방식을 바꾸려면 [동작을 직접 관리하세요](/guide/behaviors#own-a-behavior). 이후 `master-ui add` 명령으로 새 컴포넌트 파일을 만들면 로컬 동작을 사용합니다. 컴포넌트를 이미 추가했다면 가져오기 구문을 직접 수정합니다. `add` 명령은 기존 파일을 그대로 둡니다.

## 서버 렌더링 \{#on-a-server\}

<GuideFigure name="frameworks" title="렌더링과 동작의 수명 주기">

**렌더링과 상호작용의 수명 주기는 서로 다릅니다.** 리스트박스에서 선택된 값은 서버 HTML에 이미 표시됩니다. 마운트 후 어댑터는 동작을 연결하고 애플리케이션의 값을 동작과 동기화합니다. 언마운트하면 정리 함수를 호출해 리스너와 옵저버를 중지합니다. 정리 후에도 마크업은 원래 상태로 돌아가지 않습니다.

</GuideFigure>

- **초기 HTML에 상태가 반영됩니다.** 서버가 보내는 마크업에는 선택된 옵션과 탭, 분할 조절기의 크기, 달력에 표시되는 월과 선택된 날짜가 들어 있습니다. 달력의 오늘 날짜 표시처럼 브라우저에서만 확인할 수 있는 상태는 동작이 연결될 때 표시됩니다.
- **서버에서 달력을 렌더링할 때는 `locale`을 지정합니다.** 월과 요일의 이름은 `Intl`에서 가져오며, 서버와 브라우저가 서로 다른 언어를 사용할 수 있습니다.
- **React Server Components에서는** 동작을 연결하거나 상태를 유지하는 컴포넌트가 클라이언트 컴포넌트이며 `'use client'` 지시문을 선언합니다. 그런 컴포넌트에 함수, `trigger`, `onValueChange` 또는 항목의 `onSelect` 콜백을 넘기는 파일도 클라이언트 컴포넌트입니다. 서버 컴포넌트는 클라이언트 컴포넌트에 함수를 전달할 수 없으므로 위 예제는 `'use client'` 지시문으로 시작합니다. `Field`와 `Tooltip`은 ID를 연결하는 역할만 하므로 다른 클라이언트 컴포넌트를 렌더링하지 않는 파일에서는 서버에서 렌더링할 수 있습니다. 마크업으로만 이루어진 부분은 작성한 위치에서 그대로 렌더링됩니다.
- **ID는 프레임워크에서 생성합니다.** React와 Vue에서는 `useId`를, Svelte에서는 `$props.id()`를 사용하므로 서버와 브라우저의 ID가 일치합니다. Vue는 애플리케이션별로 ID에 번호를 매깁니다. 아일랜드 아키텍처처럼 한 페이지에 여러 Vue 애플리케이션을 마운트한다면 각 애플리케이션에 `app.config.idPrefix` 값을 지정합니다. 그렇지 않으면 서로 다른 애플리케이션의 요소에 같은 ID인 `v-0`이 지정될 수 있습니다.

## 커스텀 컴포넌트 \{#your-own\}

동작을 그대로 쓰면서 렌더링 방식을 바꾸려면 `master-ui add` 명령이 복사한 헬퍼를 사용합니다. 예를 들어 선택한 프레임워크의 `listbox` 컴포넌트를 추가해 헬퍼를 가져온 뒤, 아래 가져오기 구문에 맞춰 `Sizes` 컴포넌트를 `ui/` 디렉터리와 같은 위치에 작성하세요. 서버 HTML이 올바른 상태를 표시하도록 초기 선택을 마크업에 반영하고, 이후 값은 헬퍼가 동기화하도록 하세요. React의 헬퍼는 ref를 반환하는 훅입니다.

```tsx name=Sizes.tsx
'use client'
import { useState } from 'react'
import { listbox } from '@master/ui/behaviors/listbox.js'
import { useBehavior } from './ui/use-behavior'

export function Sizes({ value, onValueChange }: { value: string, onValueChange: (value: string | string[] | null) => void }) {
  const ref = useBehavior(listbox, undefined, { value, onValueChange })
  const [first] = useState(() => value)
  return (
    <div className="listbox" role="listbox" aria-label="Size" tabIndex={0} ref={ref}>
      {['Small', 'Medium', 'Large'].map(size => (
        <div className="listbox-option" role="option" aria-checked={size === first} key={size}>{size}</div>
      ))}
    </div>
  )
}
```

두 번째 인수로 동작의 옵션을 전달하고, 세 번째 인수로 값과 값 변경을 받는 콜백을 전달합니다. Svelte에서는 헬퍼가 어태치먼트를 만들고, Vue에서는 템플릿 ref와 모델을 받는 컴포저블입니다.

```svelte name=Sizes.svelte
<script lang="ts">
  import { untrack } from 'svelte'
  import { listbox } from '@master/ui/behaviors/listbox.js'
  import { behavior } from './ui/behavior.svelte.js'

  let { value = $bindable() }: { value?: string | string[] | null } = $props()
  const first = untrack(() => [value ?? []].flat())
  const attach = behavior(listbox, undefined, { value: () => value, change: next => { value = next } })
</script>

<div class="listbox" role="listbox" aria-label="Size" tabindex="0" {@attach attach}>
  {#each ['Small', 'Medium', 'Large'] as size}
    <!-- The behavior writes aria-selected on the active option. -->
    <!-- svelte-ignore a11y_role_has_required_aria_props -->
    <div class="listbox-option" role="option" aria-checked={first.includes(size)}>{size}</div>
  {/each}
</div>
```

```vue name=Sizes.vue
<script setup lang="ts">
import { useTemplateRef } from 'vue'
import { listbox } from '@master/ui/behaviors/listbox.js'
import { useBehavior } from './ui/use-behavior'

const value = defineModel<string | string[] | null>()
const first = [value.value ?? []].flat()
useBehavior(useTemplateRef<HTMLElement>('root'), listbox, undefined, value)
</script>

<template>
  <div class="listbox" role="listbox" aria-label="Size" tabindex="0" ref="root">
    <div v-for="size in ['Small', 'Medium', 'Large']" :key="size" class="listbox-option" role="option" :aria-checked="first.includes(size)">{{ size }}</div>
  </div>
</template>
```

[동작](/guide/behaviors#in-a-framework)에서는 각 프레임워크에서 헬퍼 없이 동작을 직접 연결하는 방법을 보여 줍니다.

## 다른 헤드리스 라이브러리 \{#headless-libraries\}

기본 제공 컴포넌트는 브라우저 기능과 Master UI의 동작을 사용합니다. 헤드리스 컴포넌트 라이브러리에 의존하지 않습니다.

애플리케이션에 다른 라이브러리의 동작이 필요하면 그 라이브러리의 대응 요소에 계약에서 지정한 클래스를 적용하고, 모든 상태와 키보드 조작, 포커스 전환이 계약에 부합하는지 확인하세요. 어댑터가 다른 속성을 기록한다면 직접 관리하는 스타일시트가 필요할 수 있습니다. CSS 클래스만으로는 호환성이 보장되지 않으므로, 먼저 하나의 상호작용을 처음부터 끝까지 확인한 뒤 프로젝트 전체에 적용하세요.
