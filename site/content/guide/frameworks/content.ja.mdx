状態を持たないコンポーネントにはネイティブのマークアップを使います。アプリケーションで値、データ、ID、ライフサイクルを管理する必要がある場合は、フレームワーク用のコンポーネントをコピーしてください。コピーしたコンポーネントは React、Svelte、Vue で同じコントラクトに沿ったマークアップをレンダリングし、パッケージに含まれるビヘイビアを適用します。スタイルを使えるように、まず[インストール](/guide/installation)の手順に従ってください。コンポーネントをコピーするだけでは、CSS はインポートされません。

## マークアップをそのまま使う \{#markup\}

React、Svelte、Vue のいずれでも、ボタンには `btn btn-primary` を指定した `<button>` を使います。`Button` コンポーネントは用意されていません。props をクラスに変換するだけのコンポーネントをプロジェクト側で作ることも避けてください。

```tsx name=Toolbar.tsx
export function Toolbar({ saving }: { saving: boolean }) {
  return (
    <button type="button" className="btn btn-primary" disabled={saving} aria-busy={saving}>
      Save changes
    </button>
  )
}
```

- **コンポーネントで管理するものはありません。** ボタンには、受け渡す値、レンダリングする行、パーツを関連付ける ID、適用するビヘイビアがありません。状態は、フレームワークがすでに設定する属性で表現できます。
- **チェッカーはクラスを読み取ります。** [`master-ui check`](/guide/ai#check-the-markup) は `.jsx`、`.tsx`、`.svelte`、`.vue`、`.astro` の各ファイルを読み取ります。`className="btn btn-outline"` は読み取って未定義のクラスだと報告できますが、`<Button variant="outline">` は検出できません。
- **マークアップにクライアントスクリプトは不要です。** クラスを付けたネイティブ要素は、サーバーでレンダリングするだけで使えます。React Server Components では、そのためのコードはクライアントバンドルに追加されません。

違いは構文だけです。

| HTML | JSX | Svelte と Vue |
| --- | --- | --- |
| `class="btn btn-primary"` | `className="btn btn-primary"` | 同じ |
| `for="email"` | `htmlFor="email"` | 同じ |
| `tabindex="-1"`, `popovertarget="share"` | `tabIndex={-1}`, `popoverTarget="share"` | 同じ |
| `commandfor="confirm"` と `command="show-modal"` の組み合わせ、および `interestfor="tip"` | React の型定義にまだ含まれていない属性は、スプレッドで渡す | 同じ |

プロジェクト内で同じマークアップを繰り返し使う場合は、そのプロジェクトの書き方に合わせて独自のコンポーネントにまとめ、コントラクトで定められたクラス名は文字列リテラルとして記述してください。

## フレームワークが担う範囲 \{#what-a-framework-owns\}

フレームワークが次の 4 項目のうち少なくとも 1 つを管理する場合に、フレームワーク用のコンポーネントを使います。

1. **アプリケーションが読み取る、または設定する値。** コンボボックスで選択された値や、ダイアログが開いているかどうかなどです。
2. **データからレンダリングする項目。** リストボックスの選択肢、カレンダーの各日、メニュー項目などです。
3. **パーツを関連付ける ID。** ラベルとコントロール、ボタンとそれが開くポップオーバー、タブとパネルなどを関連付けます。
4. **ライフサイクル。** 要素が用意できた時点で[ビヘイビア](/guide/behaviors)を取り付け、要素が取り除かれるときに解除します。

ライブラリーが[クラス](/guide/introduction#tiers)を設けるときも、同じ基準を使います。マークアップが繰り返されるかどうかより、管理すべき情報やビヘイビアがあるかどうかで判断します。17 のパターンがこの基準を満たします。

| コンポーネント | 対応するコントラクト | フレームワークの管理対象 |
| --- | --- | --- |
| `calendar` | [カレンダー](/components/calendar) | 値、表示する月 |
| `combobox` | [コンボボックス](/components/combobox) | 値、選択肢 |
| `command` | [コマンドパレット](/components/command) | 開閉状態、コマンド |
| `compare` | [比較](/components/compare) | 位置 |
| `dialog` | [ダイアログ](/components/dialog) | 開閉状態、トリガーが参照する ID |
| `field` | [フィールド](/components/input#hint-and-error) | ラベル、コントロール、ヒント、エラーを関連付ける ID |
| `listbox` | [リストボックス](/components/listbox) | 値、選択肢 |
| `menu` | [メニュー](/components/menu) | メニュー項目、トリガーが参照する ID、コンテキストメニューの対象 |
| `otp` | [OTP](/components/otp) | コード、入力枠の数 |
| `popover` | [ポップオーバー](/components/popover) | 開閉状態、トリガーが参照する ID |
| `splitter` | [スプリッター](/components/splitter) | サイズ |
| `stepper` | [ステッパー](/components/stepper) | 数値 |
| `tabs` | [タブ](/components/tabs#tab-panels) | 選択中のタブ、タブとパネルを関連付ける ID |
| `toast` | [トースト](/components/toast) | キュー（`toast()` 関数と、キューの内容を表示する領域） |
| `tooltip` | [ツールチップ](/components/tooltip) | コントロールとラベルを関連付ける ID |
| `tree` | [ツリー](/components/tree) | 選択中の行、行の一覧 |
| `wheel` | [ホイール](/components/wheel) | 各列の値、選択肢 |

それ以外のコントラクトは、マークアップだけで成立します。セレクトには `<select class="select">`、スイッチには `role="switch"` を付けたチェックボックス、アコーディオンには `<details>` を使います。状態はブラウザーが保持し、フレームワークは他のネイティブコントロールと同じようにバインドします。

## コンポーネントを追加する \{#add\}

コンポーネントは、パッケージからインポートするのではなく、プロジェクト内のソースとして使います。`master-ui` コマンドでコピーします。

```bash
npx master-ui add combobox --framework=react
```

```
Add combobox: ui/combobox.tsx, ui/use-behavior.ts.
  It renders the markup of "master-ui contract combobox" and needs that stylesheet from @master/ui.
```

- `package.json` に React、Svelte、Vue のうちちょうど1つが記載されていれば、そのフレームワークを使います。初回の実行後は、その選択が `master-ui.json` に保存されます。
- コンポーネントが同じディレクトリからインポートする小さなヘルパーも一緒にコピーされます。React と Vue では `use-behavior.ts`、Svelte では `behavior.svelte.ts` です。
- ファイルの既定の配置先は、プロジェクトルートの `ui/` です。`--directory` で別の配置先を指定すると、その設定が保存されます。たとえば、ソースを `src` 以下に置く SvelteKit では `--directory=src/lib/ui`、Nuxt では `--directory=app/ui` を指定します。
- 配置先にある `ui/.base/` には、各ファイルがコピー時の状態で保存されます。後で `diff` が上流のソースと比較する際の基準になるため、このコピーは編集しないでください。
- 名前を指定せずに `npx master-ui add` を実行すると、コンポーネントの一覧が表示されます。
- すでにコピーがある場合は、そのまま保持されます。プロジェクト側で編集している可能性があるためです。

コピーしたコンポーネントが、レンダリング、ライフサイクル、値の同期を担います。ビヘイビアは `@master/ui/behaviors` からインポートするため、その依存パッケージを更新すると、キーボード操作やフォーカスの修正が反映されます。コンポーネント自体が上流で変更された場合は、[`status` と `diff`](/guide/customization#upstream-changes) で差分を確認し、取り込みたい変更を作業中のコピーにマージします。その後、`accept` を実行し、インストール済みパッケージのバージョンを新しい比較基準として記録します。この操作は `.base/` と追跡用のメタデータを更新し、作業中のファイルには手を加えません。[レジストリ](/guide/registry#items) では、同じファイルを `react-combobox`、`svelte-combobox`、`vue-combobox` という項目名で提供しています。

## コンポーネントを使う \{#use\}

使用するフレームワークを指定して `add combobox` を実行し、コピーされたファイルを実際の配置先からインポートします。以下の例では、サンプルファイルと同じ階層に既定の `ui/` ディレクトリがあることを前提としています。どの例も同じコンボボックスを、各フレームワークの慣用的な書き方で実装しています。Svelte の例は実際に操作できます。プロジェクトに導入されるものと同じコンポーネントとビヘイビアを使い、サーバーでレンダリングした後、プレビューでハイドレーションします。コードビューには、そのファイルの内容が表示されます。

```tsx name=Region.tsx
'use client'
import { useState } from 'react'
import { Combobox } from './ui/combobox'

const regions = [
  { value: 'hnd', label: 'Tokyo' },
  { value: 'sin', label: 'Singapore' },
  { value: 'fra', label: 'Frankfurt', description: 'Germany' },
]

export function Region() {
  const [region, setRegion] = useState<string | null>(null)
  return (
    <Combobox options={regions} value={region} onValueChange={setRegion}
      aria-label="Region" listLabel="Regions" toggleLabel="Show regions" empty="No regions match." />
  )
}
```

<FrameworkPreview name="Region" height={304} title="Region.svelte" bodyClass="flex items-start justify-center p-lg min-h(300)" caption="文字を入力して候補を絞り込み、Enter キーまたはクリックで選択してから、選択後の表示を書き換えてみてください。操作に応じて、アプリケーションが保持する値も変わります。" />

```vue name=Region.vue
<script setup lang="ts">
import { ref } from 'vue'
import Combobox from './ui/Combobox.vue'

const regions = [
  { value: 'hnd', label: 'Tokyo' },
  { value: 'sin', label: 'Singapore' },
  { value: 'fra', label: 'Frankfurt', description: 'Germany' },
]
const region = ref<string | null>(null)
</script>

<template>
  <Combobox :options="regions" v-model="region"
    aria-label="Region" list-label="Regions" toggle-label="Show regions" empty="No regions match." />
</template>
```

Tokyo を選び、アプリケーションが `hnd` を保持していることを確認します。フィールドに表示されるのは選択肢のラベルです。その表示を書き換えると、次に選択肢を選ぶまで値は `null` になります。モデルに入るのは選択肢の値で、任意の検索テキストは入りません。

| | 値 | 開閉状態 | その他の出力 |
| --- | --- | --- | --- |
| React | `value`（コンポーネント側で値を保持する場合は `defaultValue`）と `onValueChange` | `open`, `onOpenChange` | `onComplete`, `onValueCommit`, `onSearch` |
| Svelte | `bind:value` と `onValueChange` | `bind:open` と `onOpenChange` | 同じコールバック props |
| Vue | `v-model` | `v-model:open` | `@complete`, `@value-commit`, `@search` |

値の管理方法はアダプターによって異なります。React では、親が渡した `value` が優先されます。ユーザーがコンポーネントを操作しても、親が `onValueChange` で変更を反映しなければ、制御された `<input>` と同様に、コンポーネントは渡された値に戻ります。`open` も同様です。Svelte と Vue では、`bind:` や `v-model` を使わずに渡した値は初期値として扱われ、その後はコンポーネントがユーザーの選択を保持します。変更を受け入れない場合は、バインドした値を明示的に元に戻してください。

コンポーネント固有の props 以外は、コンボボックスなら入力フィールド、ダイアログなら `<dialog>`、リストボックスならルート要素に渡されます。コンボボックスの `aria-label`、`placeholder`、`name` もこの仕組みで指定できます。

### ページ側のマークアップ \{#the-pages-own-markup\}

これらの例を使う前に、`npx master-ui add dialog --framework=react` や `--framework=vue` など、必要なコンポーネントを追加してください。ダイアログ、ポップオーバー、メニュー、ツールチップは、ページ側のコントロールで開きます。コンポーネントはボタンをレンダリングせず、自身を参照するための属性をページに渡します。ページ側でその属性をボタンにスプレッドすると、通常の HTML ページと同じようにブラウザーがダイアログを開きます。

```tsx name=DeleteProject.tsx
'use client'
import { useState } from 'react'
import { Dialog } from './ui/dialog'

export function DeleteProject({ remove }: { remove: () => Promise<void> }) {
  const [open, setOpen] = useState(false)
  async function confirm() {
    await remove()
    setOpen(false)
  }
  return (
    <Dialog id="delete-project" aria-labelledby="delete-project-title"
      open={open} onOpenChange={setOpen}
      trigger={attributes => <button type="button" className="btn" {...attributes}>Delete project</button>}>
      <header className="dialog-header">
        <h2 className="dialog-title" id="delete-project-title">Delete this project?</h2>
        <p className="dialog-description">Atlas and its 14 deployments are removed.</p>
      </header>
      <footer className="dialog-footer">
        <button type="button" className="btn" {...{ commandfor: 'delete-project', command: 'close' }}>Cancel</button>
        <button type="button" className="btn btn-primary" onClick={confirm}>Delete project</button>
      </footer>
    </Dialog>
  )
}
```

<FrameworkPreview name="DeleteProject" height={320} title="DeleteProject.svelte" bodyClass="flex items-start justify-center p-lg min-h(320)" caption="ボタンは独自のイベントハンドラーを持たず、commandfor を使ってダイアログを開きます。アプリケーションはダイアログが開いたことを検知し、プロジェクトが削除されたら、自身の状態を更新して閉じます。" />

```vue name=DeleteProject.vue
<script setup lang="ts">
import { ref } from 'vue'
import Dialog from './ui/Dialog.vue'

const props = defineProps<{ remove: () => Promise<void> }>()
const open = ref(false)
async function confirm() {
  await props.remove()
  open.value = false
}
</script>

<template>
  <Dialog id="delete-project" aria-labelledby="delete-project-title" v-model:open="open">
    <template #trigger="attributes">
      <button type="button" class="btn" v-bind="attributes">Delete project</button>
    </template>
    <header class="dialog-header">
      <h2 class="dialog-title" id="delete-project-title">Delete this project?</h2>
      <p class="dialog-description">Atlas and its 14 deployments are removed.</p>
    </header>
    <footer class="dialog-footer">
      <button type="button" class="btn" commandfor="delete-project" command="close">Cancel</button>
      <button type="button" class="btn btn-primary" @click="confirm">Delete project</button>
    </footer>
  </Dialog>
</template>
```

ここでの `remove` は、呼び出し元が渡すアプリケーションの削除関数です。例では、その関数が正常に完了した後でダイアログを閉じます。処理中とエラー時の状態は、アプリケーション側で追加してください。ダイアログ内部の `dialog-header`、`dialog-title`、`dialog-footer` は、コントラクトに沿ったマークアップです。いずれもコンポーネントではなく、管理するものはありません。リクエストの失敗後に開く場合や、ルートの変更時に閉じる場合など、アプリケーションが開閉を決めるときだけ `open` を渡します。省略した場合は、トリガーとブラウザーが開閉を処理します。

[フィールド](/components/input#hint-and-error) でも同じ仕組みを逆方向に使います。フィールドが ID を管理し、それらの ID を含む属性をページ側のコントロールに渡します。

```tsx name=Email.tsx
import { Field } from './ui/field'

export function Email({ error }: { error?: string }) {
  return (
    <Field label="Work email" hint="We only send receipts." error={error}>
      {control => <input className="input" type="email" name="email" {...control} />}
    </Field>
  )
}
```

### トースト \{#toasts\}

トーストの要素は通知が発生したときに初めて作られるため、コンポーネントはキューとして機能します。どこからでも呼び出せる `toast()` 関数と、キューの内容を表示する領域で構成されます。領域は一度だけレンダリングします。

```tsx name=App.tsx
'use client'
import { toast, Toaster } from './ui/toast'

export function ToastExample() {
  return (
    <>
      <Toaster />
      <button type="button" className="btn" onClick={() => toast({
        title: 'Preview ready', description: 'The build can now be reviewed.', status: 'success'
      })}>Show notification</button>
    </>
  )
}
```

Svelte と Vue では、`toast` はそれぞれ `Toaster.svelte` と `Toaster.vue` の名前付きエクスポートです。トーストは6秒後に自動で消えます。`duration` で表示時間を変更でき、`duration: false` を指定すると明示的に閉じられるまで表示されます。

## アダプターとビヘイビアの役割 \{#where-the-logic-is\}

ビヘイビアを持つパターンでは、アダプターはキーボード操作と選択のルールをビヘイビアに委ねます。アダプターの役割は次の3つです。

- **コントラクトに沿ったマークアップをレンダリングします。** 初期値を反映するため、スクリプトが実行される前から HTML は正しい状態です。
- **ビヘイビアを取り付けます。** オプションが変わると、取り付け直します。
- **値を同期します。** アプリケーションが別の値を設定すると、ビヘイビアの [`value`](/guide/behaviors#the-value) に書き込みます。ルート要素に `input` または `change` が届くたびに、その値を読み取ります。

初回レンダリング後は、通常の HTML ページと同じように、ビヘイビアが属性を更新します。キーボード操作の処理は、共通のビヘイビアコードに集約されています。各フレームワークのアダプターは、共通のテストシナリオで検証します。マウントし、マークアップがコントラクトに準拠していることを確かめ、キーを押して出力値を読み取り、値を設定した後にアンマウントします。

キーの動作や選択時の処理を変えるには、[ビヘイビアをプロジェクト側で管理](/guide/behaviors#own-a-behavior)します。その後に `master-ui add` で新しいコンポーネントファイルを作成すると、ローカルのビヘイビアが使われます。追加済みのコンポーネントでは、インポート先を手動で変更してください。`add` は既存のファイルを保持します。

## サーバーレンダリング \{#on-a-server\}

<GuideFigure name="frameworks" title="レンダリングとビヘイビアのライフサイクル">

**レンダリングとインタラクションではライフサイクルが異なります。** リストボックスで選択されている値は、サーバーが生成した HTML にすでに反映されています。マウント後、アダプターはビヘイビアを取り付け、アプリケーションの値と同期します。アンマウント時にはクリーンアップ関数を呼び出して、リスナーとオブザーバーを停止します。クリーンアップで元のマークアップに戻ることはありません。

</GuideFigure>

- **初期 HTML に状態が含まれます。** 選択された項目やタブ、スプリッターのサイズ、カレンダーの表示月や選択日は、サーバーが送るマークアップに含まれます。カレンダーでの今日の表示など、ブラウザーでしか確定できない状態は、ビヘイビアを取り付けた時点で反映されます。
- サーバーでレンダリングする場合は、**カレンダーに `locale` を指定してください。** 月や曜日の名前は `Intl` に基づくため、サーバーとブラウザーで使用言語が一致しないことがあります。
- **React Server Components では、** ビヘイビアを取り付けるコンポーネントや状態を保持するコンポーネントはクライアントコンポーネントで、`'use client'` を宣言します。こうしたコンポーネントに関数（`trigger`、`onValueChange`、項目の `onSelect` など）を渡すファイルも、クライアントコンポーネントにする必要があります。サーバーコンポーネントからクライアントコンポーネントに関数を渡せないため、上の例は `'use client'` で始まります。`Field` と `Tooltip` は ID で要素を関連付けるだけなので、ほかにクライアント側のコンポーネントをレンダリングしないファイルであれば、サーバーでレンダリングできます。マークアップだけの部分は、記述した側でそのままレンダリングされます。
- **ID はフレームワークが生成します。** React と Vue では `useId`、Svelte では `$props.id()` を使い、サーバーとブラウザーで ID を一致させます。Vue はアプリケーション単位で ID に連番を振ります。アイランド構成など、1ページに複数の Vue アプリケーションをマウントする場合は、それぞれに `app.config.idPrefix` を指定してください。指定しないと、別々のアプリケーションの異なる要素に同じ ID `v-0` が付くことがあります。

## 独自のコンポーネントを作る \{#your-own\}

同じビヘイビアを使ってレンダリングを変える場合は、`master-ui add` でコピーされるヘルパーを使います。たとえば、使用するフレームワーク向けに `listbox` を追加してヘルパーを取得し、`ui/` ディレクトリと同じ階層に `Sizes` コンポーネントを作成します。以下のインポートは、この配置を前提としています。初期選択をマークアップに反映してサーバーの HTML を正しい状態にし、以降の値の同期はヘルパーに任せます。React のヘルパーは ref を返すフックです。

```tsx name=Sizes.tsx
'use client'
import { useState } from 'react'
import { listbox } from '@master/ui/behaviors/listbox.js'
import { useBehavior } from './ui/use-behavior'

export function Sizes({ value, onValueChange }: { value: string, onValueChange: (value: string | string[] | null) => void }) {
  const ref = useBehavior(listbox, undefined, { value, onValueChange })
  const [first] = useState(() => value)
  return (
    <div className="listbox" role="listbox" aria-label="Size" tabIndex={0} ref={ref}>
      {['Small', 'Medium', 'Large'].map(size => (
        <div className="listbox-option" role="option" aria-checked={size === first} key={size}>{size}</div>
      ))}
    </div>
  )
}
```

第2引数にはビヘイビアのオプション、第3引数には値と変更を受け取るコールバックを渡します。Svelte のヘルパーはアタッチメントを作り、Vue のヘルパーはテンプレート ref とモデルを受け取るコンポーザブルです。

```svelte name=Sizes.svelte
<script lang="ts">
  import { untrack } from 'svelte'
  import { listbox } from '@master/ui/behaviors/listbox.js'
  import { behavior } from './ui/behavior.svelte.js'

  let { value = $bindable() }: { value?: string | string[] | null } = $props()
  const first = untrack(() => [value ?? []].flat())
  const attach = behavior(listbox, undefined, { value: () => value, change: next => { value = next } })
</script>

<div class="listbox" role="listbox" aria-label="Size" tabindex="0" {@attach attach}>
  {#each ['Small', 'Medium', 'Large'] as size}
    <!-- The behavior writes aria-selected on the active option. -->
    <!-- svelte-ignore a11y_role_has_required_aria_props -->
    <div class="listbox-option" role="option" aria-checked={first.includes(size)}>{size}</div>
  {/each}
</div>
```

```vue name=Sizes.vue
<script setup lang="ts">
import { useTemplateRef } from 'vue'
import { listbox } from '@master/ui/behaviors/listbox.js'
import { useBehavior } from './ui/use-behavior'

const value = defineModel<string | string[] | null>()
const first = [value.value ?? []].flat()
useBehavior(useTemplateRef<HTMLElement>('root'), listbox, undefined, value)
</script>

<template>
  <div class="listbox" role="listbox" aria-label="Size" tabindex="0" ref="root">
    <div v-for="size in ['Small', 'Medium', 'Large']" :key="size" class="listbox-option" role="option" :aria-checked="first.includes(size)">{{ size }}</div>
  </div>
</template>
```

[ビヘイビア](/guide/behaviors#in-a-framework) では、各フレームワークでヘルパーを使わずに直接取り付ける方法を紹介しています。

## 他のヘッドレスライブラリ \{#headless-libraries\}

提供するコンポーネントは、ブラウザー標準の機能と Master UI のビヘイビアを使います。ヘッドレスコンポーネントライブラリには依存しません。

アプリケーションで別のライブラリのビヘイビアが必要な場合は、対応する要素にコントラクトのクラスを付け、すべての状態、キーボード操作、フォーカスの移動がコントラクトに沿っているか確認してください。アダプターが異なる属性を書き込む場合は、プロジェクト側で管理するスタイルシートが必要になることがあります。CSS クラスを付けるだけでは互換性は確保できません。プロジェクト全体に適用する前に、まず1つの操作を最初から最後まで検証してください。
