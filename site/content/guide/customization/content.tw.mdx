**有四種自訂方式可沿用套件實作。** Utility、token、公開屬性和主題可調整版面配置、數值或材質。執行 `init` 後，`master-ui own` 會複製元件原始碼，並將樣式表的匯入路徑指向本機副本。要執行複製的行為，也要把使用該行為的程式碼改成匯入本機檔案。該元件的原始碼由你的專案維護，其餘元件仍由套件提供。各層級依維護責任劃分，與程式碼行數無關。

## 自訂層級一覽 \{#the-ladder\}

| 層級 | 做法 | 適用範圍 | 仍跟隨上游的部分 |
| --- | --- | --- | --- |
| 1. Utility | 在元素上加上 utility：`class="btn w-full"` | 單一實例 | 全部 |
| 2. Token | 在 `@theme` 中覆寫主題 token，或在元素上覆寫，讓其子樹一併套用 | 品牌色、圓角半徑、密度、焦點、位移距離、表面色調 | 全部 |
| 3. 屬性 | 在單一元素上設定元件的公開自訂屬性，或透過專案自訂類別設定 | 調整特定元件的尺寸或間距，可套用至所有實例或限定範圍 | 全部 |
| 4. 主題 | 撰寫主題檔案，定義 token，並在材質配方需要時定義 mixin | 不同材質，例如平面、描邊或帶色調的材質 | 所有元件 |
| 5. 接管 | `npx master-ui own <name>`：將樣式表、契約和行為複製到 `ui/`，並將樣式表的匯入路徑指向副本 | 結構、部件、狀態、行為 | 其餘元件跟隨上游，接管的元件視需要手動合併上游變更 |

「跟隨上游」表示實作來自你安裝的套件版本。升級時仍需檢查變更，原有的覆寫也會繼續取代指定的值。詳見[穩定性](/guide/stability#experimental)。

## 依變更層級判斷 \{#which-layer\}

接管元件沒有固定的比例門檻，例如「覆寫三分之一的宣告就該接管」。判斷依據是變更涉及哪一層，與程式碼行數無關。

定義兩百個 token 值的主題也只涉及主題層，屬於第 4 層，所有元件仍跟隨上游。如果只需一行宣告就能取消樣式表套用於按鈕按下狀態的外觀，而 token 或屬性都無法表達這項變更，就已經涉及元件狀態。即使只有一行，也屬於第 5 層。按行數判斷會高估前者的層級，也會低估後者。

先確認要改的是單一實例、所有元件都會讀取的值、由單一元件公開的值、材質，還是元件的結構、狀態與行為。要改的對象就決定了自訂層級。

## 1. Utility \{#utility\}

元件類別位於 `components` 層，utility 則位於順序較後的 `utilities` 層。因此，加在元素上的 utility 會優先套用，無須使用 `!important`，也無須在自己的樣式表中加規則。

```html
<button type="button" class="btn btn-primary w-full">Save changes</button>
```

用 utility 調整單一實例的寬度、外距，或它在版面配置中的位置。

## 2. Token \{#token\}

主題 token 控制色彩、陰影和圓角半徑等共用設計值。在匯入後覆寫 token，所有讀取它的元件都會採用新值。例如，調整 `--color-brand` 會改變品牌色表面的色調，一般按鈕則會維持原有的中性材質：

```css name=app.css
@import '@master/css';
@import '@master/ui';

@theme {
  --color-brand: oklch(58% .19 28);
}
```

需要調整共用值並保留原有材質時，使用這一層。[調整 token](/guide/theming#retune-tokens)說明如何搭配調整相關值，以及如何將覆寫限制在頁面的特定範圍。

## 3. 公開自訂屬性 \{#property\}

契約會列出元件公開的自訂屬性。執行 `npx master-ui contract button` 會列出 `--btn-height`、`--btn-padding-x`、`--btn-gap`、`--btn-font-size`、`--btn-radius` 和 `--icon-size`。這些屬性用來調整單一元件的尺寸與間距。

若只調整一個元素，直接在該元素上以行內樣式設定屬性：

```html
<button type="button" class="btn" style="--btn-height: 2rem">Filter</button>
```

若同一種變體會重複使用，建立一個只設定公開屬性的專案自訂類別，並與元件類別一起加在元素上：

```css name=app.css
.compact-control {
  --btn-height: 2rem;
  --btn-padding-x: .75rem;
}
```

```html
<button type="button" class="btn compact-control">Filter</button>
```

若要調整頁面某個區域內的所有按鈕，請將屬性直接設在該範圍內的按鈕上：

```css name=app.css
.editor-tools .btn {
  --btn-height: 2rem;
  --btn-padding-x: .75rem;
}
```

元件會在自己的類別上宣告這些屬性，因此只在祖先元素上設定的值無法套用到元件。所以上一條規則會選取 `.btn`，只設定契約公開的值，且不宣告表面、邊緣或陰影樣式。

替專案自訂類別命名時，請避開函式庫的命名範圍。類別名稱若以元件的根類別名稱加上連字號開頭，例如 `btn-compact`，[檢查工具](/guide/contracts#diagnostics)會回報 `unknown-class`。

## 4. 主題 \{#theme\}

若要變更材質，例如採用平面外觀、細線邊框或略帶色彩的中性色，請建立主題，也就是在函式庫之後匯入的 token 檔案。Paper 是套件隨附的第二套主題，所有元件都沿用原有實作。

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import '@master/ui/themes/paper.css';
```

主題負責設定 token 和定義材質配方，禁止直接選取元件。當多個值需要搭配調整才能呈現另一種材質時，就使用這一層。[主題設定](/guide/theming#paper)會介紹 Paper、它的原始碼，以及建立自訂主題的規則。

## 接管元件 \{#own-a-component\}

第 5 層適用於無法透過設定值來表達的變更，例如修改結構、部件、狀態或行為。將元件原始碼複製到專案內，再就地編輯。

符合以下任一條件時，就接管元件。其餘情況可使用第 1 到第 4 層。

- 變更需要樣式表目前沒有的選擇器，例如要選取不同的部件、巢狀結構或元素。
- 想要的狀態呈現無法透過主題 token 或元件的公開屬性來表達。
- 要改變元件行為，例如按鍵操作、焦點處理或選取的含義。
- 專案需要獨立維護這個元件的實作。若只需要掌控主題值，[保留本機主題](/guide/stability#pin-the-theme)即可。

### 複製原始碼 \{#take-the-source\}

```bash
npx master-ui init      # once: writes ui/index.css with one @import per stylesheet
npx master-ui own menu  # copies ui/menu.css, ui/menu.json and its behavior; repoints the import
```

`init` 會寫入 `ui/index.css` 和 `master-ui.json`。在匯入預設設定後匯入 `ui/index.css`，取代 `@import '@master/ui'`：

```css name=app.css
@import '@master/css';
@import './ui/index.css';
```

`own` 接著會執行以下四項操作：

| 操作 | 檔案或目錄 |
| --- | --- |
| 複製樣式表與契約 | `ui/menu.css`、`ui/menu.json` |
| 若契約有指定行為，則複製行為檔案 | `ui/menu.js` |
| 為每個檔案另存一份接管當下的副本 | `ui/.base/` |
| 記錄元件及各檔案的雜湊值 | `master-ui.json` |

它也會把 `ui/index.css` 中的 `@import '@master/ui/components/menu.css';` 改成 `@import './menu.css';`。如果專案裡沒有這行，`own` 會印出要手動替換的內容。只有傳入 `--force` 時，才會覆寫 `ui/` 中既有的檔案。

副本仍會讀取主題的 token 並套用其 mixin，因此會隨主題更新。其餘元件仍由套件提供。

### 讓契約與實作一致 \{#keep-the-contract-true\}

CLI 讀取專案設定時，會採用複製到本機的契約 `ui/menu.json`，取代函式庫的契約。代理也應讀取這份本機契約。在 `ui/menu.css` 中新增、重新命名或移除類別時，請同步修改 `ui/menu.json`。下方先示範在樣式表中新增部件，再列出要附加到契約 `classes` 陣列的項目：

```css name=ui/menu.css
@layer components {
  /* A quiet line under the last group: the account that is signed in. */
  .menu-note {
    padding: .4375rem .5rem;
    color: var(--color-text-muted);
    font-size: .71875rem;
  }
}
```

```json name=ui/menu.json
{ "name": "menu-note", "kind": "part", "of": "menu", "description": "A quiet line under the last group" }
```

保留既有的類別名稱與狀態屬性，就能讓區塊、行為與文件繼續適用。[契約](/guide/contracts)說明了每個鍵的用途。

對使用新部件的標記執行 `npx master-ui check`，接著在瀏覽器中檢查元件。檢查工具只驗證標記是否符合契約，副本 CSS 的狀態呈現、對比度或鍵盤行為是否符合預期，仍需在瀏覽器中確認。

### 同步上游變更 \{#upstream-changes\}

更新套件後，已接管的元件會繼續使用本機副本。以下三個指令可查看套件的變更，並記錄已合併的變更。

```bash
npx master-ui status       # which owned components changed upstream since they were taken
npx master-ui diff menu    # the change, against the copy kept in ui/.base/
npx master-ui accept menu  # after merging what is wanted: record the new base
```

`status` 會為每個已接管的元件輸出一行。只要其中有任何元件在上游有變更，指令就會以結束代碼 2 結束，方便排程工作回報：

```
menu  upstream changed: menu.css (master-ui diff menu); edited here: menu.css
```

`diff` 會比較接管當下的副本與套件目前的檔案，因此只會顯示上游的變更，排除專案自己的編輯：

```
# menu.css: taken (-) and upstream now (+)
    .menu-label {
      padding: .4375rem .5rem .3125rem;
      color: var(--color-text-muted);
+     font-size: .71875rem;
-     font-size: .6875rem;
      user-select: none;
      -webkit-user-select: none;
    }
```

將需要的變更手動合併到 `ui/menu.css`。接著用 `accept` 把套件目前的版本設為基準，`ui/` 中的工作副本會保留原樣。

### 恢復使用套件的元件 \{#give-back\}

將樣式表的匯入路徑改回套件，並將應用程式或框架中匯入該元件行為的路徑改回 `@master/ui/behaviors`。從 `master-ui.json` 的 `owned` 中移除該元件的項目，之後就會重新套用函式庫的契約。

只有在其他已接管或新增的元件都未使用某個檔案時，才刪除該工作檔案或基準檔案。不同的行為可能共用複製到本機的輔助檔案，例如 `ui/internal.js`，框架元件也可能匯入本機行為。先檢查這些匯入，再移除檔案，最後建置專案並實際操作已恢復由套件提供的元件。

### 接管了函式庫的大部分元件時 \{#own-all\}

如果在專案內統一維護實作，比協調本機副本與套件樣式更容易，就可以考慮接管更多原始碼。是否接管其餘元件，還要看維護需求，不能只看已複製的元件數量。Token、契約、檢查工具和[技能](/guide/ai#the-skill)仍然適用。[接管原始碼](/guide/registry)比較了套件與登錄庫的工作流程。

## 超出支援範圍的覆寫 \{#what-is-not\}

以下覆寫雖然能改變呈現結果，但會繞過支援的自訂方式。你需要自行追蹤被覆寫的實作。

- **以規則選取函式庫類別，重新宣告其表面、邊緣或陰影樣式。** 請使用 token、公開屬性，或接管元件。
- **使用文件未記載的元件屬性。** 請使用元件契約列出的屬性，或另有文件說明的主題 token。元件內部屬性可能在未事先通知的情況下變更。
- **從外部新增類別來重設函式庫元件的樣式**，例如在 `.my-btn.btn` 中加入材質宣告。專案自訂類別可設定公開屬性及版面配置。要使用新材質，請建立新元件或接管既有元件。
- **強行提高套用優先順序。** 請勿提高選擇器權重或使用 `!important` 來壓過元件樣式。Utility 所在的層本來就有較高優先順序。如果覆寫仍需要更高的優先順序，就該接管元件。

```css name=app.css
/* Not a customization: it redraws what button.css draws, and will not follow it. */
.btn {
  background: white;
  box-shadow: 0 1px 2px rgb(0 0 0 / .2);
}
```
