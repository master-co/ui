何を変える必要があるかでカスタマイズの方法を選びます。1 つのインスタンス、共通のデザイン値、コンポーネントのジオメトリー、マテリアル、あるいは実装そのものです。結果を表現できる最小の変更から始めれば、残りはパッケージが引き続き保守できます。

マテリアルと状態の関係の一貫性を保つには[デザイン](/guide/design#customization-boundaries)を参照してください。既定のトークンの役割と値については[既定のテーマ](/guide/theme)を参照してください。トークンやテーマの変更を選んだら、その実装は[テーマ設定](/guide/theming)で説明しています。

<GuideFigure name="customization" title="カスタマイズのレイヤーを選ぶ">

**4 つのカスタマイズポイントでは、パッケージの実装がそのまま使われます。** ユーティリティ、トークン、公開プロパティ、テーマは、レイアウト、値、マテリアルを変更します。`init` の後、`master-ui own` はコンポーネントのソースをコピーし、そのスタイルシートのインポート先を切り替えます。コピーしたビヘイビアを実行するには、その利用側のインポートもローカルファイルに変更してください。そのソースはプロジェクトが保守し、ほかのコンポーネントはパッケージに残ります。各段階が表すのは責任の所在であり、コードの長さではありません。

</GuideFigure>

## 段階 \{#the-ladder\}

| 段階 | 行うこと | 用途 | 引き続きアップストリームに従うもの |
| --- | --- | --- | --- |
| 1. ユーティリティ | 要素にユーティリティを追加します：`class="btn w-full"` | 1 つのインスタンス | すべて |
| 2. トークン | `@theme` 内で、または要素上でそのサブツリー向けに、テーマトークンを上書きします | ブランドカラー、角丸、密度、フォーカス、移動量、サーフェスのトーン | すべて |
| 3. プロパティ | コンポーネントの公開カスタムプロパティを、1 つの要素上で、またはプロジェクト独自のクラスを通じて設定します | 1 つのコンポーネントのサイズや間隔。全体またはスコープ内で | すべて |
| 4. テーマ | テーマファイルを書きます。トークンと、レシピに必要な場合はミックスイン | 別のマテリアル。フラット、枠線付き、色付きなど | すべてのコンポーネント |
| 5. 所有 | `npx master-ui own <name>`：スタイルシート、コントラクト、ビヘイビアが `ui/` にコピーされ、インポートがそのコピーを指すようになります | 構造、パーツ、状態、振る舞い | ほかのコンポーネント。このコンポーネントは要求に応じて |

「アップストリームに従う」とは、実装がインストールしたパッケージのバージョンから提供されることを意味します。アップグレードには引き続き確認が必要で、上書きした値は引き続きその値を置き換えます。[安定性](/guide/stability#experimental)を参照してください。

## 行数ではなく、どのレイヤーか \{#which-layer\}

「宣言の 3 分の 1 を上書きしたら」のように、コンポーネントを所有すべき割合というものはありません。基準は変更がどのレイヤーに触れるかであり、何行かかるかではありません。

200 個のトークン値からなるテーマは、テーマにしか触れません。これは段階 4 で、すべてのコンポーネントは引き続きアップストリームに従います。押されたボタンに対してスタイルシートが描画するものを打ち消す 1 つの宣言は、トークンやプロパティで表現できない限り、コンポーネントの状態に触れます。どれほど短くても、これは段階 5 です。行数で数えると、前者を高すぎる段階に、後者を低すぎる段階に置いてしまいます。

ですから、その変更が何に対するものかを問いかけてください。1 つのインスタンス、すべてのコンポーネントが読む値、1 つのコンポーネントが公開する値、マテリアル、あるいはコンポーネントの構造、状態、振る舞いです。その答えが段階です。

## 1. ユーティリティ \{#utility\}

コンポーネントクラスは `components` レイヤーに、ユーティリティはその後の `utilities` レイヤーにあるため、要素に付けたユーティリティは `!important` もスタイルシートのルールもなしに優先されます。

```html
<button type="button" class="btn btn-primary w-full">Save changes</button>
```

1 つのインスタンスに属するもの、つまり幅、マージン、レイアウト内での位置に使います。

## 2. トークン \{#token\}

テーマトークンは、色、影、角丸などの共通のデザイン値を制御します。インポートの後でトークンを上書きすると、それを読むすべてのコンポーネントが追従します。たとえば `--color-brand` を変更すると、通常のボタンはニュートラルなマテリアルのまま、ブランドのサーフェスが調整されます。

```css name=app.css
@import '@master/css';
@import '@master/ui';

@theme {
  --color-brand: oklch(58% .19 28);
}
```

マテリアルは同じままで共通の値を変える必要があるときに、この段階を使います。関連する値や、ページの一部に限定した上書きについては[トークンを調整する](/guide/theming#retune-tokens)で説明しています。

## 3. 公開カスタムプロパティ \{#property\}

コントラクトには、コンポーネントが公開するカスタムプロパティが記載されています。`npx master-ui contract button` を実行すると、`--btn-height`、`--btn-padding-x`、`--btn-gap`、`--btn-font-size`、`--btn-radius`、`--icon-size` が出力されます。これらは 1 つのコンポーネントのサイズと間隔のためのものです。

1 つの要素では、プロパティをインラインで設定します。

```html
<button type="button" class="btn" style="--btn-height: 2rem">Filter</button>
```

繰り返し使うバリアントには、公開プロパティだけを設定するプロジェクト独自のクラスを書き、コンポーネントクラスの横に付けます。

```css name=app.css
.compact-control {
  --btn-height: 2rem;
  --btn-padding-x: .75rem;
}
```

```html
<button type="button" class="btn compact-control">Filter</button>
```

ページの一部にあるすべてのボタンに対しては、そのスコープ内のボタンにプロパティを渡します。

```css name=app.css
.editor-tools .btn {
  --btn-height: 2rem;
  --btn-padding-x: .75rem;
}
```

コンポーネントはこれらのプロパティを自身のクラス上で宣言するため、祖先にだけ設定した値は届きません。最後のルールが `.btn` を指定しているのはそのためです。これはコントラクトが公開している値を設定するために指定しているのであり、面、エッジ、影は宣言していません。

プロジェクトのクラスには、ライブラリの名前と重ならない名前を付けてください。`btn-compact` のように、コンポーネントのルートとダッシュで始まるクラスは、[チェッカー](/guide/contracts#diagnostics)が `unknown-class` として報告します。

## 4. テーマ \{#theme\}

変更がマテリアルに対するもの、たとえばフラットな面、罫線のエッジ、色味を帯びたニュートラルである場合、それはテーマです。ライブラリの後にインポートするトークンのファイルです。Paper はパッケージで公開されている 2 つ目のテーマで、コンポーネントには何の変更も加えません。

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import '@master/ui/themes/paper.css';
```

テーマはトークンを設定し、マテリアルのレシピを定義します。コンポーネントを選択することはありません。複数の値を別のマテリアルとして連携させる必要があるときに、この段階を使います。Paper、そのソース、独自のテーマを作るためのルールについては[テーマ設定](/guide/theming#paper)で順を追って説明しています。

## コンポーネントを所有する \{#own-a-component\}

段階 5 は、どの値でも表現できない、構造、パーツ、状態、振る舞いの変更のためのものです。コンポーネントのソースをプロジェクトにコピーし、そこで編集します。

次のいずれか 1 つに当てはまる場合に、コンポーネントを所有してください。それまでは段階 1〜4 にとどまります。

- 変更に、スタイルシートにないセレクターが必要です。別のパーツ、別の入れ子、別の要素などです。
- 望む状態の表現を、テーマトークンやコンポーネントの公開プロパティで表現できません。
- 変更が振る舞いに対するものです。キー、フォーカス、選択が何を意味するかなどです。
- プロジェクトがこのコンポーネントの実装を独立して保守する必要があります。テーマの値を制御したいだけであれば、代わりに[ローカルのテーマを保持](/guide/stability#pin-the-theme)してください。

### ソースを取得する \{#take-the-source\}

```bash
npx master-ui init      # once: writes ui/index.css with one @import per stylesheet
npx master-ui own menu  # copies ui/menu.css, ui/menu.json and its behavior; repoints the import
```

`init` は `ui/index.css` と `master-ui.json` を書き出します。`@import '@master/ui'` の代わりに、プリセットの後で `ui/index.css` をインポートします。

```css name=app.css
@import '@master/css';
@import './ui/index.css';
```

次に、`own` は 4 つのことを行います。

| 内容 | 場所 |
| --- | --- |
| スタイルシートとコントラクトをコピーします | `ui/menu.css`、`ui/menu.json` |
| コントラクトがビヘイビアを指定している場合は、それをコピーします | `ui/menu.js` |
| 各ファイルの取得時点のコピーをもう 1 つ保持します | `ui/.base/` |
| コンポーネントと各ファイルのハッシュを記録します | `master-ui.json` |

また、`ui/index.css` の 1 行を `@import '@master/ui/components/menu.css';` から `@import './menu.css';` に変更します。プロジェクトにそのような行がない場合、`own` は手作業で行うべき置き換えを出力します。`--force` を渡さない限り、`ui/` にすでに存在するファイルを上書きすることはありません。

コピーは引き続きテーマのトークンを読み、そのミックスインを適用するため、テーマに追従します。ほかのすべてのコンポーネントは引き続きパッケージから提供されます。

### コントラクトを正しく保つ \{#keep-the-contract-true\}

CLI がこのプロジェクトの設定を読み取るとき、コピーしたコントラクト `ui/menu.json` がライブラリのものを置き換えます。エージェントもこのローカルのコントラクトを読むべきです。`ui/menu.css` でクラスを追加、名前変更、削除したときは、あわせて `ui/menu.json` も変更してください。次の例では、スタイルシートにパーツを追加し、続いてコントラクトの `classes` 配列に追加するエントリーを示しています。

```css name=ui/menu.css
@layer components {
  /* A quiet line under the last group: the account that is signed in. */
  .menu-note {
    padding: .4375rem .5rem;
    color: var(--color-text-muted);
    font-size: .71875rem;
  }
}
```

```json name=ui/menu.json
{ "name": "menu-note", "kind": "part", "of": "menu", "description": "A quiet line under the last group" }
```

既存のクラス名と状態属性を保てば、ブロック、ビヘイビア、ドキュメントは引き続き適合します。すべてのキーは[コントラクト](/guide/contracts)で説明しています。

新しいパーツを使うマークアップに対して `npx master-ui check` を実行し、その後ブラウザーでコンポーネントを確認してください。チェッカーが検証するのはマークアップのコントラクトです。コピーした CSS が意図した状態、コントラスト、キーボードの振る舞いを実装していることを証明するものではありません。

### アップストリームの変更に追従する \{#upstream-changes\}

所有したコンポーネントは、パッケージを更新しても変わらなくなります。3 つのコマンドで、パッケージが何を変更したかを確認し、何をマージしたかを記録します。

```bash
npx master-ui status       # which owned components changed upstream since they were taken
npx master-ui diff menu    # the change, against the copy kept in ui/.base/
npx master-ui accept menu  # after merging what is wanted: record the new base
```

`status` は所有するコンポーネントごとに 1 行を出力し、いずれかがアップストリームで変更されていた場合は終了コード 2 で終了します。そのため、定期実行のジョブで報告できます。

```
menu  upstream changed: menu.css (master-ui diff menu); edited here: menu.css
```

`diff` は取得したコピーとパッケージの現在のファイルを比較するため、プロジェクト自身の編集とは切り離して、アップストリームが行った変更だけを表示します。

```
# menu.css: taken (-) and upstream now (+)
    .menu-label {
      padding: .4375rem .5rem .3125rem;
      color: var(--color-text-muted);
+     font-size: .71875rem;
-     font-size: .6875rem;
      user-select: none;
      -webkit-user-select: none;
    }
```

必要な変更を手作業で `ui/menu.css` にマージします。その後、`accept` がパッケージの現在のバージョンをベースにします。`ui/` 内のコピーには触れません。

### コンポーネントを返却する \{#give-back\}

スタイルシートのインポートをパッケージに戻し、そのビヘイビアに対するアプリケーションやフレームワークのインポートを `@master/ui/behaviors` に戻します。`master-ui.json` の `owned` からそのコンポーネントのエントリーを削除すると、ライブラリのコントラクトが再び適用されます。

削除するのは、ほかの所有コンポーネントや追加コンポーネントがもう使っていない作業用ファイルとベースファイルだけにしてください。ビヘイビアは `ui/internal.js` のようなコピーされたヘルパーを共有することがあり、フレームワークコンポーネントがローカルのビヘイビアをインポートしていることもあります。ファイルを削除する前にそれらのインポートを確認し、その後ビルドして、返却したコンポーネントを動かしてみてください。

### ライブラリの多くを所有する場合 \{#own-all\}

ローカルのコピーをパッケージのスタイルと調整し続けるより、プロジェクト全体で一貫した実装を保守するほうが容易な場合は、より多くのソースを所有することを検討してください。コピーしたコンポーネントの数だけでは、残りを引き受ける理由にはなりません。トークン、コントラクト、チェッカー、[スキル](/guide/ai#the-skill)は引き続き適用されます。パッケージとレジストリのワークフローの比較は[ソースを所有する](/guide/registry)にあります。

## カスタマイズではないもの \{#what-is-not\}

次の上書きは結果を変えることはできますが、サポートされているカスタマイズポイントを迂回するものであり、置き換えた実装の追跡はあなたの責任になります。

- **ライブラリのクラスを選択し、その面、エッジ、影を宣言し直すルール。** トークンやプロパティを使うか、コンポーネントを所有してください。
- **ドキュメント化されていないコンポーネントのプロパティ。** コントラクトに記載されたプロパティか、別途ドキュメント化されたテーマトークンを使ってください。内部のコンポーネントプロパティは予告なく変更される可能性があります。
- **ライブラリのコンポーネントを外側からスタイルし直す新しいクラス。** マテリアルの宣言を持つ `.my-btn.btn` などです。プロジェクトのクラスは公開プロパティとレイアウトを設定できます。新しいマテリアルは、新しいコンポーネントか所有したコンポーネントです。
- **力ずくで優先させること。** コンポーネントに勝つために詳細度を上げたり `!important` を使ったりしないでください。ユーティリティはすでにレイヤーによって優先されており、それ以上が必要な上書きは、コンポーネントを所有する理由になります。

```css name=app.css
/* Not a customization: it redraws what button.css draws, and will not follow it. */
.btn {
  background: white;
  box-shadow: 0 1px 2px rgb(0 0 0 / .2);
}
```
