Master UI はチャートを独自に描画します。[チャート](/components/chart)はひとつの SVG で、折れ線グラフからサンバーストまで、20 種類以上の形式をテーマのトークンで描画します。各形式の詳細は[チャート一覧](/charts)にあります。単一の数値や傾向、割合を示す小さなコンポーネントもあります。このガイドでは、目的に合った形式の選び方、ひとつの期間選択で複数のチャートを連動させる方法、チャート描画エンジンが適した場面を紹介します。

## チャートの選び方 \{#choose\}

まず、読み手に何を見せる必要があるかを考え、そこから形式を選びます。どの形式もマークアップをもとに描画し、スクリプトなしでテーマに従い、数値をテキストで伝えます。

| 読み手が知りたいこと | 適した形式 |
| --- | --- |
| 時間とともに値がどう変化したか | [折れ線グラフ](/charts/line)、または 1〜2 系列なら[面グラフ](/charts/area) |
| 2 時点の間で何が増え、何が減ったか | [スロープグラフ](/charts/slope)。一覧の各項目に 2 つの値がある場合は[ダンベルチャート](/charts/dumbbell) |
| 順位がどう変化したか | [順位推移グラフ](/charts/bump) |
| 各項目の量の比較 | [棒グラフ](/charts/bar)。項目名が長い場合は[横棒グラフ](/charts/bar#across) |
| ある値が別の値になるまでの増減 | [ウォーターフォールグラフ](/charts/waterfall) |
| 2 つの値の間の範囲 | [範囲グラフ](/charts/range) |
| 時間の経過やグループ間で総量の内訳がどう異なるか | [積み上げ棒グラフ](/charts/bar#stacked)または[積み上げ面グラフ](/charts/area#stacked)。グループごとに総量が異なる場合は[マリメッコチャート](/charts/marimekko) |
| ひとつの全体の内訳 | 5 項目までなら[ドーナツグラフ](/charts/donut)または[円グラフ](/charts/pie)。1% 刻みなら[ワッフルチャート](/charts/waffle)、項目が多ければ[ツリーマップ](/charts/treemap)、2 階層なら[サンバーストチャート](/charts/sunburst)、1 本の棒で示すなら[内訳バー](/components/breakdown) |
| フローの各段階にどれだけ到達したか | [ファネルチャート](/charts/funnel) |
| それぞれに目標値がある複数の項目の達成度 | [リンググラフ](/charts/rings) |
| 複数の対象を共通の指標で比較 | [レーダーチャート](/charts/radar) |
| 測定値がどう分布しているか | [ヒストグラム](/charts/histogram)。複数のグループをまとめて比較するなら[箱ひげ図](/charts/box) |
| 2 つの尺度にまたがるパターン | [ヒートマップ](/charts/heatmap) |
| 2 つの指標の関係 | [散布図](/charts/scatter)。3 つ目の指標は[バブル](/charts/scatter#bubble)で表現 |
| ひとつの数値とその増減 | [統計値](/components/stat) |
| 文中や一覧の行で示す系列の傾向 | [スパークライン](/components/sparkline) |
| ひとつの測定値が上限にどれだけ近いか | [ゲージ](/components/gauge)または[メーター](/components/meter) |
| 目盛りを添えずに示す、多数の小さな値のパターン | セルで構成する[ヒートマップ](/components/heatmap) |
| 正確な数値を列で比較 | [テーブル](/components/table) |

数値だけで伝わるなら、グラフは省きます。2 本の棒を見比べるよりも、統計値と増減を併記した方がすばやく読み取れます。

## ダッシュボード \{#dashboard\}

ひとつの期間選択で、3 つの数値と 3 つのチャートを操作します。期間を選ぶと、すべてが同じデータに基づいて一斉に切り替わるので、表示される数値とチャートの内容は常に一致します。

<PagePreview name="dashboard" title="チャートダッシュボード" example="chart-dashboard" caption="期間を選んだり、日付にポインターを合わせたり、凡例から系列を非表示にしたりできます。" />

- **ひとつの操作で、その下にあるすべての表示を切り替えます。** 期間選択はカードの中に置かず、数値とチャートの上に独立した行として配置します。個別の期間が必要なチャートは、別のビューに置きます。
- **データからチャートを描き直します。** すでにチャートがある要素に `chart(element, options)` を呼び出すと、既存のチャートが置き換わります。戻り値の関数でチャートを停止できます。期間が変わったら、その期間のデータで呼び出します。
- **数値を先に伝え、チャートで補足します。** 各カードのタイトルには表示内容を記し、チャートの `label` にも同じ内容を単位付きで記して、図を見られない読み手に伝えます。
- **各形式にひとつの役割を持たせます。** 積み上げ面グラフは総量の推移と内訳を、ドーナツグラフは現在の内訳を示します。棒グラフは順位を示し、順位の比較に使う値も明記します。

## テーマの色 \{#colors\}

1 系列のチャートにはインク色を使います。色分けなしで読み取れ、周囲のモノクロのインターフェースにも自然になじみます。

複数の系列には、それぞれ[カテゴリー](/components/category)を割り当てます。既定では、青、オレンジ、ティール、紫、アンバー、ピンク、緑、スカイブルーの順です。どちらのカラースキームでも、一般的な色覚特性で隣り合う色を区別できる順序です。プロダクト全体で同じ対象に同じ色を使う場合は、系列の `category` を明示します。たとえば東京は、一覧のどの位置にあっても、チャート、凡例、バッジ、テーブルの行で青になります。

- **系列を非表示にしても、ほかの系列の色は変わりません。** 別の系列をチャートから外しても、各系列は割り当てられたカテゴリーを維持します。
- **カテゴリーとステータスは別です。** 成功、警告、危険は対象の状態を表します。系列に問題があることは、[バッジ](/components/badge)やチャートに添えた文で伝えます。ステータス色を使う形式は[ウォーターフォールグラフ](/charts/waterfall#inks)だけです。各段の増減は、統計値の変化と同じように符号付きの差分を表します。
- **テキストには系列色を使いません。** 名前と値にはテキスト用トークンを使い、隣に系列色のマークを置きます。棒や扇形には色の付いた四角、折れ線には線を使います。
- **1 色の濃淡は単一の指標を示すときに使います。** ヒートマップのセル、ファネルチャートの各段階、サンバーストの外周は、同じ色の濃淡で表します。
- **すべてのマークにテーマが反映されます。** マークはカテゴリーの `--color-category-<name>-mark` トークンを参照し、インク色は `--chart-color` を参照します。再描画なしで、カラースキーム、テーマ、特定の領域に限定した上書きが反映されます。

## 尺度はひとつ \{#scale\}

ひとつのチャートにはひとつの尺度を使います。訪問者数を千人単位で、比率をパーセントで示すような場合は、時間軸の目盛りをそろえた 2 つのチャートを上下に並べます。ひとつのチャートの左右に別々の尺度を置くと、読み手はどの線がどちらの尺度に対応するか判別しにくく、線の交点にも意味がありません。

棒の長さが値を表すため、棒グラフの尺度はゼロから始めます。折れ線グラフで変化に注目してもらいたい場合は、尺度の下限を引き上げてもかまいません。その場合は、チャートの `label` に明記します。

## アクセシビリティ \{#accessibility\}

- **チャートはリストとして読み上げられます。** 各点は値を名前に含むリスト項目なので、スクリプトなしでスクリーンリーダーが "Thu: New 1,420, Returning 820" と読み上げます。チャートを見ながら操作する場合も、矢印キーで同じ点を順にたどれます。
- **凡例で表示を切り替えられます。** 各項目のラベルはネイティブのチェックボックスを囲んでおり、Tab キーでフォーカスし、Space キーで切り替えられます。
- **値の詳細表示は補助機能です。** ポインターを合わせるか、フォーカスするか、タッチすると表示されます。詳細表示の値はすべてほかの場所でも確認できます。正確な数値が重要なら、棒が数本の場合は `values: true` で値を表示するか、チャートの隣に[テーブル](/components/table)を置きます。
- **色だけに頼りません。** 凡例と値の詳細表示には系列名を記載します。
- **アニメーションは読み手の設定に従います。** 動きを抑える設定が有効な場合、チャートは描画済みの状態で表示されます。

## チャート描画エンジンを使う場面 \{#engine\}

このチャートは数百個程度のマークを想定しており、どのマークにもキーボードで移動できます。次のような場合は、チャート描画エンジンを使います。

- 数千のデータ点を扱う場合や、値が 1 秒に何度もストリーミングで届く場合
- プロットのズーム、パン、ブラシ選択が必要な場合
- このチャートが描画できない形式が必要な場合。たとえば地図、ネットワーク図、ツリー図、ローソク足チャート、サンキー図、バイオリンプロットやリッジラインプロットのようにカーネル密度推定を使う形式です。

SVG で描画するエンジンは、テーマのトークンを `fill` と `stroke` にそのまま使えます。Canvas で描画するエンジンはカスタムプロパティを参照できず、トークンには `light-dark()` が使われるため、チャートを配置する場所で各色を解決します。チャートのルート要素に非表示の検証用要素を置き、その色にトークンを指定します。その色で描画した 1 ピクセルを読み取れば、色を `rgba()` として取得できます。カラースキームやテーマが変わったら色を再解決します。尺度はひとつにし、カテゴリーの順序を固定し、凡例に各系列名を明記し、数値をテキストで示すという原則はここでも適用します。

```js name=theme.js
const probe = document.createElement('span')
probe.style.cssText = 'position:absolute;visibility:hidden'
root.append(probe)

function resolve(token) {
  probe.style.color = `var(${token})`
  pixel.fillStyle = getComputedStyle(probe).color
  pixel.fillRect(0, 0, 1, 1)
  const [r, g, b, a] = pixel.getImageData(0, 0, 1, 1).data
  return `rgba(${r}, ${g}, ${b}, ${a / 255})`
}
```
