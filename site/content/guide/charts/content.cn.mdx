Master UI 自己绘制图表。[图表](/components/chart)是一个 SVG，用主题的令牌绘制折线、面积、条形、饼图、环形图、同心圆环、雷达图和散点图；每种类型在[图表](/charts)中都有自己的页面。此外还有一些更小的组件，用于单个数字、一个趋势或一份占比。本指南说明该选用哪一种，展示几个图表如何在同一个时段选择下协同工作，并说明何时图表引擎才是更合适的工具。

## 选用哪一种 \{#choose\}

从读者需要看到什么出发，而不是从形状出发。下面每一种都由标记绘制，无需脚本即可跟随主题，并用文字说出自己的数字。

| 读者需要看到 | 使用 |
| --- | --- |
| 数值随时间如何变化 | [折线图](/charts/line)；只有一两个数据系列时也可用[面积图](/charts/area) |
| 数量之间的比较 | [条形图](/charts/bar)；名称较长时用[横向条形](/charts/bar#across) |
| 总量由哪些部分组成，随时间变化或跨分组比较 | [堆叠条形](/charts/bar#stacked)或[堆叠面积](/charts/area#stacked) |
| 一个整体由哪些部分组成 | [环形图](/charts/donut)或[饼图](/charts/pie)，最多五个部分；沿一根条形展示时用[占比分布](/components/breakdown) |
| 少数几个目标，各有自己的整体 | [同心圆环](/charts/rings) |
| 少数几个对象在相同指标上的表现 | [雷达图](/charts/radar) |
| 两个指标相互对照 | [散点图](/charts/scatter) |
| 一个数字及其变化 | [统计指标](/components/stat) |
| 一个数据系列的走向，放在一句话或一行中 | [迷你趋势线](/components/sparkline) |
| 单个读数及其距离上限多近 | [仪表盘](/components/gauge)或[计量条](/components/meter) |
| 大量小数值中呈现的规律 | [热力图](/components/heatmap) |
| 精确的数字，按列比较 | [表格](/components/table) |

一个数字就能说清时，就不要画图：带有变化量的统计指标，比画着两根条形的图表读得更快。

## 数据看板 \{#dashboard\}

三个数字和三个图表，位于同一个时段选择之下。选择时段会让它们全部根据同一组数字一起更新，因此数字所说的和图表所示的始终一致。

<PagePreview name="dashboard" title="图表数据看板" example="chart-dashboard" caption="选择一个时段，指向某一天，或在图例中隐藏某个数据系列。" />

- **一个控件管辖其下的全部内容。** 时段单独占一行，位于数字和图表上方，绝不放在卡片内。需要独立时段的图表属于另一个视图。
- **图表根据数据重新写出。** 在已有图表的元素上调用 `chart(element, options)` 会替换原图表，它返回的函数用于停止图表。时段改变时，以该时段的数字再次调用它。
- **数字在前，图表解释。** 每张卡片在标题中写明所展示的内容；图表的 `label` 连同单位说出同样的内容，供看不到图形的读者使用。
- **每种类型只做一件事。** 堆叠面积图呈现总量如何变化及其组成，环形图呈现当前整体由什么组成，条形图则是写出数值的排名，因为排名要靠数字来读。

## 来自主题的颜色 \{#colors\}

只有一个数据系列的图表使用墨色。它无需颜色就能读懂，放在周围单色的界面旁也不会抢夺注意力。

有多个数据系列时，每个系列各取一种[类别](/components/category)。不另行指定时，图表按固定顺序分配：蓝色、橙色、蓝绿色、紫罗兰色、琥珀色、粉色、绿色和天蓝色；在两种配色方案下，这一顺序中相邻的颜色对常见类型的色觉障碍者而言都能区分开。颜色要在整个产品中跟随某个对象时，请自行为数据系列指定 `category`：无论 Tokyo 在列表中排在第几位，它在图表、图例、徽标以及表格中它的那一行里都是蓝色。

- **隐藏一个数据系列不会改变其他系列的颜色。** 另一个系列离开图表时，各系列保留自己的类别。
- **类别不是状态。** 成功、警告和危险说明事物处于什么状况；出现故障的数据系列要用文字说明，写在图表旁的[徽标](/components/badge)或一句话中。
- **文字从不使用数据系列的颜色。** 名称和数值使用文本令牌，旁边放一个该颜色的图形：条形或扇区用色块，折线用一道线条。
- **主题会作用到每个图形。** 图形读取类别的 `--color-category-<name>-mark` 令牌，墨色读取 `--chart-color`，因此配色方案、主题以及限定在某个区域的覆盖样式都会生效，无需重新绘制。

## 单一刻度 \{#scale\}

一个图表只有一个刻度。大小不同的两个指标，例如以千计的访客数和以百分比计的比率，应画成上下排列、时间间隔相同的两个图表，绝不画成两侧各有一个刻度的单个图表：读者分不清哪条线属于哪一侧，两条线相交的位置也没有任何意义。

条形图的刻度从零开始，因为条形的长度就是它的数值。当重点是变化而不是数量本身时，折线图的刻度可以从更高处开始；请在图表的 `label` 中说明这一点。

## 无障碍 \{#accessibility\}

- **图表是一个列表。** 每个数据点都是一个以其数值命名的列表项，因此屏幕阅读器无需脚本就会读出“Thu: New 1,420, Returning 820”；看得见图形的读者也可以用方向键逐一浏览同样的数据点。
- **图例是控件。** 每个图例项都是包裹真正复选框的 label，可以按 Tab 键到达，按空格键切换。
- **数值提示只是一种便利。** 它在指针下、获得焦点时和手指触碰时出现，绝不包含其他地方没有的数值。精确数字是重点时，请把它们写出来：在少量条形上使用 `values: true`，或在图表旁放一个[表格](/components/table)。
- **颜色从不单独承担含义。** 数据系列在图例和数值提示中都写有名称。
- **动态效果遵从读者设置。** 开启减少动态效果时，图表直接以画好的状态出现。

## 何时使用图表引擎 \{#engine\}

图表为几百个图形而设计，每个图形都是读者可以用键盘到达的元素。数据超出这个范围时，请改用图表引擎：

- 成千上万个数据点，或每秒流入多次的数值；
- 在绘图区上缩放、平移或刷选；
- 图表画不出的形状，例如地图、网络图或 K 线图。

在 SVG 中绘图的引擎可以直接在 `fill` 和 `stroke` 中使用主题的令牌。在 canvas 上绘图的引擎无法读取自定义属性，而令牌又是用 `light-dark()` 写的，因此要在图表所在的位置解析每种颜色：图表根元素内的一个隐藏探针以该令牌作为颜色，再用这个颜色绘制一个像素，即可得到 `rgba()` 形式的颜色。配色方案或主题改变时要重新解析，并遵守上文同样的规则：只用一个刻度，类别按固定顺序分配，图例写出每个数据系列的名称，数字以文本形式提供。

```js name=theme.js
const probe = document.createElement('span')
probe.style.cssText = 'position:absolute;visibility:hidden'
root.append(probe)

function resolve(token) {
  probe.style.color = `var(${token})`
  pixel.fillStyle = getComputedStyle(probe).color
  pixel.fillRect(0, 0, 1, 1)
  const [r, g, b, a] = pixel.getImageData(0, 0, 1, 1).data
  return `rgba(${r}, ${g}, ${b}, ${a / 255})`
}
```
