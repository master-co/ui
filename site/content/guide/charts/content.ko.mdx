Master UI는 몇 개의 숫자는 스크립트 없이 직접 그립니다. 몇 개의 막대, 문장 속 추세, 게이지, 막대 안의 비율 등입니다. 축의 범위가 데이터에 맞춰 바뀌어야 하거나, 데이터 점이 많거나, 포인터 아래에 툴팁이 필요하거나, 레이더처럼 특수한 모양이 필요한 차트는 차트 엔진이 담당합니다. 이 가이드에서는 차트 엔진 중 하나인 [Chart.js](https://www.chartjs.org/docs/latest/getting-started/integration.html)에 Master UI의 색상을 적용하고, 실제로 동작하는 범례와 같은 수치를 담은 표를 함께 제공합니다. 또한 차트를 테마와 동기화하고 정리하는 방법도 설명합니다.

이 예제에서 Chart.js는 라이브러리가 아니라 사이트의 의존성입니다. `@master/ui`는 Chart.js에 의존하지 않으며, 캔버스나 SVG로 그리는 엔진이라면 어떤 것이든 같은 방식으로 적용할 수 있습니다.

## 라이브러리의 차트와 차트 엔진 \{#choose\}

먼저 컴포넌트를 고려하세요. 컴포넌트는 마크업으로 그리므로 수치가 페이지에 텍스트로 들어 있고, 스크립트 없이 테마를 따르며, 인쇄도 됩니다.

| 필요한 것 | 사용할 것 |
| --- | --- |
| 일주일의 날짜처럼 하나의 척도 위에 놓인 몇 개의 숫자 | [차트](/components/chart) |
| 수치 옆이나 행 안에서 계열이 어느 방향으로 변했는지 | [스파크라인](/components/sparkline) |
| 하나의 측정값과 그 값이 한계에 얼마나 가까운지 | [게이지](/components/gauge) 또는 [반원형 진행률](/components/progress#half-ring) |
| 알려진 범위 안에서 어떤 양이 어디에 있는지 | [미터](/components/meter) |
| 하나의 막대를 따라 합계가 무엇으로 구성되는지 | [구성 내역](/components/breakdown) |
| 많은 작은 값에 걸친 패턴 | [히트맵](/components/heatmap) |

차트 엔진은 축이 데이터에 맞춰 바뀌어야 하거나, 데이터 점이 레이블보다 많거나, 독자가 포인터로 값을 살펴보거나, 계열을 표시하고 숨기거나, 여러 달에 걸친 선, 도넛, 고리, 레이더처럼 컴포넌트가 그리지 않는 모양이 필요할 때 그 무게만큼의 가치가 있습니다. 아래 예제는 각자의 미리보기에서만 Chart.js를 불러오며(각각 약 160 KB), 각 차트가 그리는 부분만 등록합니다.

## 선과 막대 \{#lines-and-bars\}

시간에 따른 여러 계열을 선이나 막대로 표시합니다. 전환 스위치는 같은 데이터를 다른 방식으로 그리고, 범례는 지역을 표시하거나 숨기며, 차트 아래의 표에는 모든 수치가 들어 있습니다.

<PagePreview name="series" title="선과 막대" example="chart-series" caption="막대로 전환하거나, 범례에서 지역을 숨기거나, 수치를 열어 보세요." />

- **그리는 것만 등록하세요.** `chart.js/auto`가 아니라 `chart.js`에서 `Chart.register(LineController, LineElement, PointElement, BarController, BarElement, CategoryScale, LinearScale, Tooltip)`을 호출하면 엔진의 나머지 부분이 번들에 포함되지 않습니다.
- **표시 요소는 가늘게 그립니다.** 선은 2px이며 포인터 아래에서만 점이 표시됩니다. 막대는 축에서 먼 쪽 끝이 둥글고, 표면 색의 테두리로 이웃한 막대와 구분됩니다. 그리드는 가로 방향의 가는 선뿐이며 세로선은 없습니다.
- **축은 하나만 사용합니다.** 척도가 다른 두 측정값은 양쪽에 축이 하나씩 있는 한 차트가 아니라 두 개의 차트로 표시합니다.

## 전체의 부분 \{#parts-of-a-whole\}

비율을 도넛이나 파이로 표시하고, 세 가지 목표를 동심원 고리로 표시합니다. 각 고리는 고유한 옅은 색의 트랙 위에 해당 색상으로 채워집니다.

<PagePreview name="parts" title="전체의 부분" example="chart-parts" caption="파이로 전환하거나, 종류나 목표를 숨기거나, 수치를 열어 보세요." />

범례에서 부분의 칩을 누르면 해당 조각이 숨겨지고 나머지 조각이 그 자리를 채웁니다. 고리의 트랙은 카테고리의 표면색이므로, 아직 남은 부분도 같은 목표로 읽히되 더 차분하게 보입니다. 전체는 네다섯 개의 부분으로 유지하고, 저장 공간 예시처럼 나머지는 “기타”로 묶으세요.

## 레이더 \{#radar\}

두 릴리스를 여섯 가지 측정값으로 비교합니다. 각 모양은 표시색으로 그리고 같은 색을 옅게 칠하므로, 두 모양이 서로 비쳐 보입니다.

<PagePreview name="radar" title="레이더" example="chart-radar" caption="범례에서 릴리스를 숨기거나, 수치를 열어 보세요." />

레이더는 몇 가지 대상을 같은 측정값으로 한눈에 비교하며, 점수는 표가 알려 줍니다. 측정값은 모두 같은 범위를 사용하며, 여기서는 0부터 100까지입니다.

## 테마의 색상 \{#colors\}

모든 계열은 [카테고리 색상](/components/category) 이름을 가지며, 카테고리가 색상을 결정합니다. Tokyo는 목록에서 어느 위치에 있든 차트, 범례 칩, 그리고 Tokyo를 표시하는 모든 배지에서 파란색입니다. 표시 요소는 카테고리의 `-mark` 역할을 사용하며, 이 색은 표면 대비 3:1을 유지합니다. 레이더의 옅은 색은 같은 표시색을 흐리게 한 것입니다. 그리드, 눈금, 툴팁은 테마의 선, 텍스트, 잉크 토큰을 사용합니다. 데이터에는 색상이 아니라 카테고리 이름만 들어 있습니다.

캔버스는 사용자 지정 속성을 읽을 수 없고 토큰은 `light-dark()`로 작성되어 있으므로, 각 예제는 차트가 놓인 위치에서 색상을 확인합니다. 차트 루트 안의 숨겨진 프로브 요소가 토큰을 색상으로 받고, 그 색으로 칠한 픽셀 하나에서 `rgba()` 색상을 얻습니다. 프로브가 차트와 같은 위치에 있으므로 Paper, 특정 영역에 한정된 재정의, 색 구성표가 모두 반영됩니다.

```js name=theme.js
const probe = document.createElement('span')
probe.style.cssText = 'position:absolute;visibility:hidden'
root.append(probe)

function resolve(token) {
  probe.style.color = `var(${token})`
  pixel.fillStyle = getComputedStyle(probe).color
  pixel.fillRect(0, 0, 1, 1)
  const [r, g, b, a] = pixel.getImageData(0, 0, 1, 1).data
  return `rgba(${r}, ${g}, ${b}, ${a / 255})`
}
```

예제에서는 파란색, 주황색, 청록색, 보라색의 네 가지 카테고리를 항상 이 순서로 사용합니다. 팔레트로 검사했을 때 이 색들은 두 색 구성표 모두에서 흔한 유형의 색각 이상에도 서로 구별됩니다. 다섯 번째 계열은 네 가지 색 중 하나와 너무 가까운 색을 부여하는 대신 “기타”로 묶거나 별도의 차트로 표시합니다.

## 접근성 \{#accessibility\}

- **범례는 컨트롤입니다.** 각 항목은 실제 체크박스를 감싼 [필터 칩](/components/chip#category)이며, 표시하는 대상에 따라 이름을 지정한 그룹에 들어 있습니다. 따라서 Tab 키로 이동하고 Space 키로 전환할 수 있습니다. 점은 카테고리를, 텍스트는 이름을 나타냅니다.
- **수치는 텍스트입니다.** 각 차트에는 펼치기 요소 뒤에 같은 값을 담은 표가 있으며, 캔버스에는 `role="img"`와 차트가 보여 주는 내용을 설명하는 문장이 있습니다. 포인터 아래의 툴팁은 편의 기능일 뿐이며, 값을 읽는 유일한 방법이 아닙니다.
- **색상만으로 전달하지 않습니다.** 계열의 이름은 범례와 표에 표시되며, 상태 색상을 계열에 사용하지 않습니다.
- **애니메이션은 독자의 설정을 따릅니다.** 동작 줄이기 설정에서는 차트가 서서히 나타나지 않고 바로 그려집니다.

## 동기화와 정리 \{#lifecycle\}

각 예제의 `main.js`는 `mount(root)`를 내보냅니다. 이 함수는 차트를 그리고, 차트를 중지하는 함수를 반환합니다.

- **크기.** 캔버스는 스타일시트가 높이를 정하는 컨테이너 안에 놓이며, Chart.js는 `responsive`와 `maintainAspectRatio: false`로 컨테이너의 너비를 따릅니다. 배치를 위해 측정하는 것은 없습니다.
- **테마.** 독자의 색 구성표가 바뀌거나 루트 요소의 class, style, `data-theme`이 바뀌면 색상을 다시 확인해 차트를 다시 그립니다.
- **정리.** 마운트를 해제하면 각 차트의 `destroy()`를 호출하고 모든 리스너와 옵저버를 제거하므로, 사라지는 화면의 차트가 아무것도 남기지 않습니다. 프레임워크에서는 요소가 생기면 `mount`를 호출하고 요소가 사라지면 그 반환값을 호출하세요. React에서는 effect의 정리 함수, Svelte에서는 attachment, Vue에서는 `onBeforeUnmount`에서 호출합니다.
