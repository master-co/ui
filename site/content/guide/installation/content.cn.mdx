## 用 AI 编程智能体配置 \{#set-up-with-an-ai-agent\}

编程智能体可以代为完成配置。在应用根目录启动编程智能体，并粘贴下方的提示词。智能体会先检查项目，并在修改文件前询问如何加载样式表、导入范围、如何配置智能体，以及如何处理现有组件库。随后，它会安装锁定版本的包，导入样式表，再在浏览器中验证第一个组件，并运行 `master-ui check` 检查其标记。

## 配置 Master CSS \{#set-up-master-css\}

如果要使用源码样式表，请先配置 Master CSS 2.1 或更高版本，以及与所用框架对应的集成。请参阅 [Master CSS 安装指南](https://css.master.co/guide/installation)，按 Vite、Astro、Next.js、Svelte 等对应的步骤操作。

## 安装包 \{#install-the-package\}

```bash
npm install @master/ui --save-exact
```

可以使用任意包管理器，例如 `bun add @master/ui --exact` 或 `pnpm add @master/ui --save-exact`。Master UI 仍处于实验阶段，任何版本都可能引入与已发布版本不兼容的变更。请锁定版本，并在需要时主动升级。[稳定性](/guide/stability#experimental)列出了升级后要运行的命令。

## 导入样式表 \{#import-the-stylesheet\}

在应用的样式表中，先导入 Master CSS 预设，再导入 Master UI：

```css name=app.css
@import '@master/css';
@import '@master/ui';
```

预设声明了层叠层顺序 `theme, base, defaults, components, utilities`。Master UI 将规则放入 `components`，因此标记中的工具类仍然优先。

## 验证安装 \{#verify-the-installation\}

确认应用已加载 `app.css`，然后在实际渲染的页面中添加一个按钮。在 JSX 中，用 `className` 代替 `class`：

```html
<button type="button" class="btn btn-primary">Save changes</button>
```

使用项目现有的开发命令运行应用。按钮在浅色模式下应呈墨色，在深色模式下应呈浅色，通过键盘聚焦时应显示清晰可见的焦点环。按钮样式无需行为脚本，保存更改仍由应用的操作处理函数负责。

如果按钮看起来仍是浏览器的默认样式，请确认页面已加载 `app.css`，且编译产物中包含 `.btn`。如果导入的是源码，请确认 Master CSS 集成处理了这份样式表。然后[检查标记](#check-your-markup)。

## 按需导入 \{#import-only-what-you-use\}

每个组件也可以单独导入。先导入共享主题，再导入应用所需的组件：

```css name=app.css
@import '@master/css';
@import '@master/ui/theme.css';
@import '@master/ui/components/button.css';
@import '@master/ui/components/switch.css';
```

请导入标记中所有类名对应的样式表。例如，按钮中包含 `icon` 或 `spinner` 时，也需要导入对应组件的样式表。完整导入可以省去手动维护这份列表的工作。

## 每个样式表单独导入 \{#one-import-per-stylesheet\}

包中附带一个小型命令行工具。`init` 会生成 `ui/index.css` 和 `master-ui.json`，前者逐行导入主题和各个样式表，后者记录项目自行维护的内容：

```bash
npx master-ui init
```

```css name=app.css
@import '@master/css';
@import './ui/index.css';
```

可以用这个入口文件代替完整的 `@master/ui` 导入。如果想自行维护导入列表或[自行维护部分组件源码](/guide/registry)，可以选择这种方式。只有当标记不再使用某一行导入的类名时，才删除该行。

## 行为脚本 \{#behaviors\}

大多数组件无需脚本。组合框、命令面板和日历等少数交互模式没有对应的原生元素，包中为每种模式提供了参考脚本：

```js name=app.js
import { attach } from '@master/ui/behaviors'

const detach = attach()
```

等标记出现在 DOM 中后，在浏览器端代码中调用 `attach()`。它会为当时识别到的交互模式绑定行为，并返回清理函数。移除这些标记前，请调用 `detach()`。它不会监听之后插入的标记，也不会配置上下文菜单的触发目标。有关如何限定绑定范围和使用各个函数，请参阅[行为](/guide/behaviors)。在 React、Svelte 或 Vue 中，请使用[框架组件](/guide/frameworks)管理这些行为的生命周期。

## 在未使用 Master CSS 的项目中安装 \{#without-master-css\}

包中包含已编译为普通 CSS 的组件。只要打包工具支持导入 CSS，就可以使用已安装的锁定版本：

```css name=app.css
@import '@master/ui/base.css';
@import '@master/ui/standalone.css';
```

`base.css` 提供预设的重置样式，其中包括 `box-sizing: border-box` 和表单控件的字体设置。如果项目已提供等效的重置样式，可以省略这项导入。

对于静态页面，将已安装包中的编译产物复制到服务器对外提供的目录中。例如，如果 `public/` 的访问地址是 `/`：

```bash
mkdir -p public/styles
cp node_modules/@master/ui/dist/base.css public/styles/master-ui-base.css
cp node_modules/@master/ui/dist/standalone.css public/styles/master-ui.css
```

```html
<link rel="stylesheet" href="/styles/master-ui-base.css">
<link rel="stylesheet" href="/styles/master-ui.css">

<button type="button" class="btn btn-primary">Save changes</button>
```

复制的文件与已安装的包版本完全对应。主动升级版本后，请重新复制这些文件。采用这种方式，应用无需编译 CSS。

编译后的样式表声明的层和令牌与从源码构建时相同。它默认跟随读者的配色方案，也可以通过 `data-theme="light"` 或 `data-theme="dark"` 为整个页面或某个子树固定配色方案。样式表不包含 Master CSS 工具类，请自行编写布局所需的 CSS，并在复制[布局](/components#layouts)、[区块](/blocks)或[页面](/pages)时替换其中的工具类。

## 检查标记 \{#check-your-markup\}

每个样式表都有一份[契约](/guide/contracts)，规定了类名、各类适用的元素及所需的属性。`check` 会读取模板并报告违反契约的地方：

```bash
npx master-ui check
```

安装包后，从项目根目录运行该命令。它无需渲染即可检查 HTML 以及 JSX、Svelte、Vue 和 Astro 等模板。处理检查报告的问题后，在浏览器中核对显示效果和键盘交互。即使静态检查通过，也仍需验证无障碍性和浏览器支持情况。[与 AI 协作](/guide/ai#check-the-markup)介绍了如何处理诊断信息以及如何在 CI 中运行检查。

## 自定义主题 \{#customize-the-theme\}

参照[主题配置](/guide/theming#retune-tokens)修改品牌色、圆角半径或焦点颜色等共享值。[默认主题](/guide/theme)说明了这些值的用途和默认值。如果改动只涉及单个实例或组件，请先阅读[自定义](/guide/customization)，选择合适的修改层级。
