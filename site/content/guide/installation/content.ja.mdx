## AI エージェントでセットアップする \{#set-up-with-an-ai-agent\}

このセットアップはコーディングエージェントに任せることができます。アプリのルートディレクトリーで、下のプロンプトをエージェントに貼り付けてください。エージェントはプロジェクトを調べ、ファイルを変更する前に、スタイルシートの経路、インポートの範囲、エージェントのセットアップ、既存のコンポーネントライブラリの扱いについてあなたに確認します。その後、バージョンを固定したパッケージをインストールし、スタイルシートをインポートして、最初のコンポーネントをブラウザーと `master-ui check` で確認します。

## Master CSS をセットアップする \{#set-up-master-css\}

ソースのスタイルシートを使う場合は、まず Master CSS 2.1 以降と、使用するフレームワーク向けのインテグレーションをセットアップします。Vite、Astro、Next.js、Svelte などについては [Master CSS のインストールガイド](https://css.master.co/guide/installation)に従ってください。

## パッケージをインストールする \{#install-the-package\}

```bash
npm install @master/ui --save-exact
```

`bun add @master/ui --exact` や `pnpm add @master/ui --save-exact` など、どのパッケージマネージャーでも使えます。Master UI は実験段階で、どのリリースでも公開済みの内容が壊れる可能性があります。バージョンを固定し、意図してアップグレードしてください。アップグレード後に何を実行するかは[安定性](/guide/stability#experimental)に記載しています。

## スタイルシートをインポートする \{#import-the-stylesheet\}

アプリのスタイルシートで、Master CSS のプリセットの後に Master UI をインポートします。

```css name=app.css
@import '@master/css';
@import '@master/ui';
```

プリセットは `theme, base, defaults, components, utilities` というレイヤー順序を宣言します。Master UI はそのルールを `components` に追加するため、マークアップ内のユーティリティが引き続き優先されます。

## インストールを確認する \{#verify-the-installation\}

`app.css` がアプリで読み込まれていることを確認し、レンダリングされるページにボタンを追加します。JSX では `class` の代わりに `className` と書きます。

```html
<button type="button" class="btn btn-primary">Save changes</button>
```

既存の開発用コマンドでアプリを起動します。ボタンはライトモードではインク色の面、ダークモードでは淡い色の面になり、キーボードフォーカスリングが見えるはずです。見た目にビヘイビアスクリプトは不要ですが、変更の保存には引き続きアプリケーションのアクションハンドラーが必要です。

スタイルが適用されていないブラウザー標準のボタンに見える場合は、ページが `app.css` を読み込んでいること、そしてコンパイル結果に `.btn` が含まれていることを確認してください。ソースのインポートを使う場合は、Master CSS のインテグレーションがこのスタイルシートを処理していることを確認します。その後、[マークアップをチェック](#check-your-markup)します。

## 使うものだけをインポートする \{#import-only-what-you-use\}

各コンポーネントは個別にもエクスポートされています。まず共通のテーマをインポートし、次にアプリに必要なコンポーネントをインポートします。

```css name=app.css
@import '@master/css';
@import '@master/ui/theme.css';
@import '@master/ui/components/button.css';
@import '@master/ui/components/switch.css';
```

マークアップで使うすべてのクラスのスタイルシートを含めてください。たとえば、`icon` や `spinner` を含むボタンには、そのコンポーネントのスタイルシートも必要です。全体をインポートすれば、このリストを自分で管理する必要はありません。

## スタイルシートごとに 1 つのインポート \{#one-import-per-stylesheet\}

パッケージには小さなコマンドラインツールが付属しています。`init` は、テーマと各スタイルシートをそれぞれ 1 行でインポートする `ui/index.css` と、プロジェクトが所有するものを記録する `master-ui.json` を書き出します。

```bash
npx master-ui init
```

```css name=app.css
@import '@master/css';
@import './ui/index.css';
```

このエントリーファイルは、`@master/ui` 全体のインポートの代わりに使います。これは任意です。インポートのリストを自分で管理したい場合や、[一部のコンポーネントのソースを所有したい](/guide/registry)場合に選んでください。行を削除するのは、マークアップがそのクラスを使わなくなったときだけにしてください。

## ビヘイビア \{#behaviors\}

ほとんどのコンポーネントにスクリプトは不要です。いくつかのパターン（コンボボックス、コマンドパレット、カレンダー）にはネイティブ要素がなく、パッケージはそれぞれのリファレンススクリプトを同梱しています。

```js name=app.js
import { attach } from '@master/ui/behaviors'

const detach = attach()
```

マークアップが存在した後に、ブラウザー側のコードで `attach()` を呼び出します。その時点で認識したパターンをアタッチし、クリーンアップ関数を返します。そのマークアップを削除する前に `detach()` を呼び出してください。後から挿入されたものは監視せず、コンテキストメニューの対象も設定しません。範囲を限定したアタッチと個別の関数については[ビヘイビア](/guide/behaviors)を参照してください。React、Svelte、Vue では、[フレームワークコンポーネント](/guide/frameworks)を使ってそのライフタイムを管理します。

## Master CSS を使わない場合 \{#without-master-css\}

パッケージには、通常の CSS にコンパイル済みのコンポーネントが含まれています。CSS のインポートに対応したバンドラーであれば、インストールしてバージョンを固定したパッケージをそのまま使えます。

```css name=app.css
@import '@master/ui/base.css';
@import '@master/ui/standalone.css';
```

`base.css` は、`box-sizing: border-box` やフォームコントロールのフォントを含む、プリセットのリセットを提供します。プロジェクトにすでに同等のリセットがある場合は、このインポートを省略してください。

静的なページでは、インストール済みのパッケージからコンパイル済みのファイルを、サーバーが公開するディレクトリーにコピーします。たとえば `public/` が `/` で配信される場合は次のようにします。

```bash
mkdir -p public/styles
cp node_modules/@master/ui/dist/base.css public/styles/master-ui-base.css
cp node_modules/@master/ui/dist/standalone.css public/styles/master-ui.css
```

```html
<link rel="stylesheet" href="/styles/master-ui-base.css">
<link rel="stylesheet" href="/styles/master-ui.css">

<button type="button" class="btn btn-primary">Save changes</button>
```

コピーしたファイルは、インストールしたパッケージの正確なバージョンのものです。そのバージョンを意図的にアップグレードしたときに、もう一度コピーしてください。この経路では、アプリ内での CSS のコンパイルは不要です。

コンパイル済みのスタイルシートは、ソースからのビルドと同じレイヤーとトークンを宣言します。読み手のカラースキームに従い、`data-theme="light"` または `data-theme="dark"` でページやサブツリーのスキームを固定できます。Master CSS のユーティリティは含まれていません。レイアウトには独自の CSS を使い、[レイアウト](/components#layouts)、[ブロック](/blocks)、[ページ](/pages)をコピーするときはユーティリティクラスを置き換えてください。

## マークアップをチェックする \{#check-your-markup\}

各スタイルシートには[コントラクト](/guide/contracts)があります。そのクラス、各クラスを付ける要素、必要な属性です。`check` はテンプレートを読み取り、コントラクトに違反している箇所を報告します。

```bash
npx master-ui check
```

パッケージをインストールした状態で、プロジェクトのルートから実行します。HTML と、JSX、Svelte、Vue、Astro などのテンプレートを、レンダリングせずにチェックします。診断を解消したら、ブラウザーで見た目とキーボード操作を確認してください。静的チェックで問題がなくても、アクセシビリティやブラウザーサポートが保証されるわけではありません。診断と CI での使い方は [AI との協働](/guide/ai#check-the-markup)で説明しています。

## テーマをカスタマイズする \{#customize-the-theme\}

ブランドカラー、角丸、フォーカスカラーなどの共通の値を変更するには[テーマ設定](/guide/theming#retune-tokens)を参照してください。それらの役割と既定値は[既定のテーマ](/guide/theme)で説明しています。変更が 1 つのインスタンスや 1 つのコンポーネントだけに関わる場合は、[カスタマイズ](/guide/customization)から始めて適切なレイヤーを選んでください。
