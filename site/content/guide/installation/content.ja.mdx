## AI エージェントでセットアップする \{#set-up-with-an-ai-agent\}

セットアップをコーディングエージェントに任せることもできます。アプリのルートディレクトリで、下のプロンプトをエージェントに貼り付けます。エージェントはプロジェクトを調べ、ファイルを変更する前に、スタイルシートの読み込み方法、インポート範囲、エージェントの設定、既存のコンポーネントライブラリの扱いについてユーザーに質問します。続いてバージョンを固定してパッケージをインストールし、スタイルシートをインポートして、最初のコンポーネントをブラウザーと `master-ui check` で確認します。

## Master CSS をセットアップする \{#set-up-master-css\}

ソースを使う場合は、先に Master CSS 2.1 以降と、利用するフレームワーク向けの連携機能を設定します。Vite、Astro、Next.js、Svelte などでの手順は [Master CSS のインストールガイド](https://css.master.co/guide/installation)を参照してください。

## パッケージをインストールする \{#install-the-package\}

```bash
npm install @master/ui --save-exact
```

使い慣れたパッケージマネージャーを使えます。たとえば `bun add @master/ui --exact` や `pnpm add @master/ui --save-exact` を実行します。Master UI は実験段階で、どのリリースにも互換性を損なう変更が入る可能性があります。バージョンを固定して必要なときに更新し、更新後は[安定性ガイド](/guide/stability#experimental)に沿って確認します。

## スタイルシートをインポートする \{#import-the-stylesheet\}

アプリのスタイルシートで、Master CSS プリセットの後に Master UI をインポートします。

```css name=app.css
@import '@master/css';
@import '@master/ui';
```

プリセットはレイヤーの順序を `theme, base, defaults, components, utilities` と宣言します。Master UI のルールは `components` に入るため、マークアップに付けたユーティリティが優先されます。

## インストールを確認する \{#verify-the-installation\}

アプリで `app.css` が読み込まれていることを確認し、表示されるページにボタンを追加します。JSX では `class` の代わりに `className` を使います。

```html
<button type="button" class="btn btn-primary">Save changes</button>
```

普段の開発コマンドでアプリを起動します。ライトモードでは濃色、ダークモードでは淡色のボタンが表示され、キーボードでフォーカスを移すとリングが見えます。見た目はビヘイビアのスクリプトなしで再現できます。実際の保存処理はアプリのイベントハンドラーで実装します。

ブラウザー既定のボタンに見える場合は、ページが `app.css` を読み込み、コンパイル結果に `.btn` が含まれているか確認します。ソースをインポートしている場合は、Master CSS の連携機能がそのスタイルシートを処理しているかも確認します。その後、[マークアップを検査](#check-your-markup)します。

## 必要なスタイルだけをインポートする \{#import-only-what-you-use\}

コンポーネントのスタイルシートは個別にもインポートできます。共通のテーマを先に読み込み、続けてアプリに必要なコンポーネントを指定します。

```css name=app.css
@import '@master/css';
@import '@master/ui/theme.css';
@import '@master/ui/components/button.css';
@import '@master/ui/components/switch.css';
```

マークアップに含まれるクラスすべてに対応するスタイルシートを読み込みます。たとえばボタンの中に `icon` や `spinner` を置く場合は、それぞれのスタイルシートも必要です。一括インポートを使えば、一覧を個別に管理する手間を省けます。

## スタイルシートを 1 行ずつインポートする \{#one-import-per-stylesheet\}

パッケージには小さな CLI が付属します。`init` は、テーマと個別のスタイルシートを 1 行ずつインポートする `ui/index.css` と、プロジェクトで管理するソースを記録する `master-ui.json` を生成します。

```bash
npx master-ui init
```

```css name=app.css
@import '@master/css';
@import './ui/index.css';
```

このエントリーファイルは、`@master/ui` の一括インポートの代わりに使えます。インポート一覧を管理したい場合や、[一部のコンポーネントのソースをプロジェクトで管理する](/guide/registry)場合に選びます。マークアップで該当クラスを使わなくなったときだけ、その行を削除してください。

## ビヘイビア \{#behaviors\}

ほとんどのコンポーネントはスクリプトを必要としません。コンボボックス、コマンドパレット、カレンダーなど、対応するネイティブ要素がないパターンには、リファレンス実装のスクリプトが付属します。

```js name=app.js
import { attach } from '@master/ui/behaviors'

const detach = attach()
```

マークアップが DOM に入った後、ブラウザー側で `attach()` を呼び出します。その時点で認識したパターンにビヘイビアを取り付け、解除用の関数を返します。マークアップを取り除く前に `detach()` を呼び出します。後から挿入した要素の監視や、コンテキストメニューを開く対象の設定は行いません。適用範囲の指定と個別の関数は[ビヘイビア](/guide/behaviors)を参照してください。React、Svelte、Vue では、[フレームワークコンポーネント](/guide/frameworks)でライフサイクルを管理します。

## Master CSS を使わずに導入する \{#without-master-css\}

パッケージには通常の CSS にコンパイルしたコンポーネントが含まれます。CSS のインポートに対応するバンドラーでは、バージョンを固定してインストールしたパッケージから読み込めます。

```css name=app.css
@import '@master/ui/base.css';
@import '@master/ui/standalone.css';
```

`base.css` には、`box-sizing: border-box` やフォームコントロールのフォント指定を含む、プリセットのリセットが入っています。プロジェクトに同等のリセットがある場合は、インポートを省略できます。

静的なページでは、インストール済みのパッケージからコンパイル済みファイルを取り出し、サーバーが公開するディレクトリへコピーします。たとえば `public/` を `/` で配信する場合は、次のようにします。

```bash
mkdir -p public/styles
cp node_modules/@master/ui/dist/base.css public/styles/master-ui-base.css
cp node_modules/@master/ui/dist/standalone.css public/styles/master-ui.css
```

```html
<link rel="stylesheet" href="/styles/master-ui-base.css">
<link rel="stylesheet" href="/styles/master-ui.css">

<button type="button" class="btn btn-primary">Save changes</button>
```

コピーしたファイルはインストールしたバージョンに対応しています。パッケージを更新したときはコピーし直します。この方法ならアプリ側で CSS をコンパイルする必要はありません。

コンパイル済みスタイルシートは、ソースからビルドする場合と同じレイヤーとトークンを宣言します。閲覧者の配色設定に従いますが、`data-theme="light"` や `data-theme="dark"` を付けると、ページやその一部の配色を固定できます。Master CSS のユーティリティは含まれないので、レイアウトはアプリ側の CSS で指定します。[レイアウト](/components#layouts)、[ブロック](/blocks)、[ページ](/pages)の例をコピーするときは、ユーティリティクラスを置き換えてください。

## マークアップを検査する \{#check-your-markup\}

各スタイルシートには、クラス、対応する要素、必要な属性を定めた[コントラクト](/guide/contracts)があります。`check` はテンプレートを読み取り、コントラクトに反する箇所を報告します。

```bash
npx master-ui check
```

パッケージをインストールしたプロジェクトのルートで実行します。HTML や JSX、Svelte、Vue、Astro などのテンプレートを、レンダリングせずに検査します。検査で指摘された問題を修正したら、ブラウザーで表示とキーボード操作を確認してください。静的検査を通過した後も、アクセシビリティと対象ブラウザーでの動作を確認する必要があります。診断の読み方や CI での実行については、[AI との開発](/guide/ai#check-the-markup)を参照してください。

## テーマを調整する \{#customize-the-theme\}

ブランドカラー、角の半径、フォーカス色など、共有する値の変更方法は[テーマの変更](/guide/theming#retune-tokens)を参照してください。[既定のテーマ](/guide/theme)には、各トークンの役割と既定値が載っています。変更が一つのインスタンスまたは一つのコンポーネントだけに及ぶ場合は、まず[カスタマイズ](/guide/customization)を参照し、変更に適したレイヤーを選びます。
