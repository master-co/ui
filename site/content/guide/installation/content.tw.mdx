## 使用 AI 代理程式設定 \{#set-up-with-an-ai-agent\}

你可以讓程式開發代理程式代為設定。在應用程式的根目錄啟動代理程式，並貼上下方的提示詞。它會先檢查專案，在變更檔案前詢問你要採用哪種樣式表載入方式、採用完整匯入或逐份匯入、如何設定代理程式，以及如何處理既有的元件函式庫。接著，它會安裝鎖定版本的套件、匯入樣式表，並在瀏覽器中及使用 `master-ui check` 檢查第一個元件。

## 設定 Master CSS \{#set-up-master-css\}

若要使用原始樣式表，請先設定 Master CSS 2.1 或更新版本，並完成所用框架的整合。請依照 [Master CSS 安裝指南](https://css.master.co/guide/installation) 中對應 Vite、Astro、Next.js、Svelte 或其他框架的步驟操作。

## 安裝套件 \{#install-the-package\}

```bash
npm install @master/ui --save-exact
```

可以使用任何套件管理工具，例如執行 `bun add @master/ui --exact` 或 `pnpm add @master/ui --save-exact`。Master UI 仍處於實驗階段，任何版本都可能對已發布的功能做出破壞性變更，因此請鎖定版本，並在需要時主動升級。[穩定性](/guide/stability#experimental)說明了升級後應執行哪些指令。

## 匯入樣式表 \{#import-the-stylesheet\}

在應用程式的樣式表中，先匯入 Master CSS 預設集，再匯入 Master UI：

```css name=app.css
@import '@master/css';
@import '@master/ui';
```

預設集將層級順序宣告為 `theme, base, defaults, components, utilities`。Master UI 將規則放在 `components` 層，因此標記中的 utility 樣式仍然優先。

## 驗證安裝 \{#verify-the-installation\}

確認應用程式已載入 `app.css`，再將按鈕加到會實際算繪的頁面。在 JSX 中，請將 `className` 用於原本寫 `class` 的地方：

```html
<button type="button" class="btn btn-primary">Save changes</button>
```

使用專案既有的開發指令啟動應用程式。按鈕在淺色模式下應呈現墨色，在深色模式下應呈現淺色。使用鍵盤移到按鈕時，應能看到焦點外框。按鈕的外觀無須行為指令碼即可呈現，實際儲存變更仍需由應用程式的動作處理函式負責。

如果按鈕看起來像瀏覽器預設的按鈕，請確認頁面已載入 `app.css`，且編譯結果包含 `.btn`。如果匯入的是原始樣式，也請確認 Master CSS 的整合有處理這份樣式表。接著[檢查標記](#check-your-markup)。

## 只匯入用到的元件 \{#import-only-what-you-use\}

每個元件也有獨立匯出。先匯入共用主題，再匯入應用程式需要的元件：

```css name=app.css
@import '@master/css';
@import '@master/ui/theme.css';
@import '@master/ui/components/button.css';
@import '@master/ui/components/switch.css';
```

請匯入標記中所有類別所需的樣式表。例如，按鈕內若包含 `icon` 或 `spinner`，也要匯入對應元件的樣式表。完整匯入可省去自行維護這份清單的工作。

## 每份樣式表各用一行匯入 \{#one-import-per-stylesheet\}

套件隨附一個小型命令列工具。`init` 會寫入 `ui/index.css` 與 `master-ui.json`，前者逐行匯入主題及各份樣式表，後者則記錄由專案自行管理的項目：

```bash
npx master-ui init
```

```css name=app.css
@import '@master/css';
@import './ui/index.css';
```

可用這個入口檔案取代完整匯入 `@master/ui` 的寫法。若想自行維護匯入清單，或[自行管理選定元件的原始碼](/guide/registry)，可採用這個做法。只有在標記已不再使用某行所匯入的類別時，才刪除該行。

## 行為 \{#behaviors\}

大多數元件無須指令碼。少數互動模式（如組合方塊、命令面板和行事曆）沒有對應的原生元素，套件為這些模式各自提供了參考指令碼：

```js name=app.js
import { attach } from '@master/ui/behaviors'

const detach = attach()
```

等標記出現在 DOM 後，再從瀏覽器端的程式碼呼叫 `attach()`。它會為當下能辨識的互動模式掛載行為，並回傳清理函式。移除這些標記前，請先呼叫 `detach()`。它不會監看後續插入的標記，也不會設定情境選單的目標。[行為](/guide/behaviors)介紹了如何限制掛載範圍及使用個別函式。在 React、Svelte 或 Vue 中，請使用[框架元件](/guide/frameworks)管理這些互動模式的生命週期。

## 不使用 Master CSS \{#without-master-css\}

套件包含已編譯成標準 CSS 的元件樣式。支援匯入 CSS 的打包工具可直接使用已安裝且鎖定版本的套件：

```css name=app.css
@import '@master/ui/base.css';
@import '@master/ui/standalone.css';
```

`base.css` 提供預設集的重設樣式，包括 `box-sizing: border-box` 與表單控制項的字型設定。如果專案已提供等效的重設樣式，可以省略這項匯入。

如果是靜態頁面，請將編譯後的檔案從已安裝的套件複製到伺服器公開提供的目錄。例如，當伺服器在 `/` 提供 `public/` 的內容時：

```bash
mkdir -p public/styles
cp node_modules/@master/ui/dist/base.css public/styles/master-ui-base.css
cp node_modules/@master/ui/dist/standalone.css public/styles/master-ui.css
```

```html
<link rel="stylesheet" href="/styles/master-ui-base.css">
<link rel="stylesheet" href="/styles/master-ui.css">

<button type="button" class="btn btn-primary">Save changes</button>
```

複製的檔案來自你安裝的確切套件版本。日後主動升級套件時，請重新複製這些檔案。採用此方式，應用程式無須自行編譯 CSS。

編譯後的樣式表與從原始碼編譯的版本宣告相同的層級與 token。樣式表會依照使用者偏好的配色，並可透過 `data-theme="light"` 或 `data-theme="dark"` 為整個頁面或 DOM 子樹固定配色。這份樣式表不含 Master CSS utility，請自行撰寫版面配置的 CSS，並在複製[版面配置](/components#layouts)、[區塊](/blocks)或[頁面](/pages)時替換其中的 utility 類別。

## 檢查標記 \{#check-your-markup\}

每份樣式表都有一份[契約](/guide/contracts)，說明有哪些類別、各類別應套用在哪個元素上，以及需要哪些屬性。`check` 會讀取範本並回報違反契約的地方：

```bash
npx master-ui check
```

安裝套件後，請從專案根目錄執行指令。它會直接檢查 HTML 和 JSX、Svelte、Vue、Astro 等範本，無須先算繪這些範本。修正回報的問題後，請在瀏覽器中確認畫面呈現和鍵盤操作。通過靜態檢查並不能證明符合無障礙要求或受到瀏覽器支援。[與 AI 協作](/guide/ai#check-the-markup)說明如何處理檢查訊息，以及如何在 CI 中執行檢查。

## 自訂主題 \{#customize-the-theme\}

依照[主題設定](/guide/theming#retune-tokens)調整品牌色、圓角半徑或焦點色彩等共用值。[預設主題](/guide/theme)說明這些值的用途與預設值。如果變更只影響單一實例或單一元件，請先參考[自訂](/guide/customization)，選擇適合的層級。
