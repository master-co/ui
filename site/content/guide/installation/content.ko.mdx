## AI 에이전트로 설정하기 \{#set-up-with-an-ai-agent\}

코딩 에이전트가 이 설정을 대신 실행할 수 있습니다. 앱의 루트 디렉터리에서 아래 프롬프트를 에이전트에 붙여 넣으세요. 에이전트는 프로젝트를 살펴보고, 파일을 변경하기 전에 스타일시트 경로, 가져오기 범위, 에이전트 설정, 기존 컴포넌트 라이브러리의 처리 방법을 묻습니다. 그런 다음 고정된 버전의 패키지를 설치하고, 스타일시트를 가져오고, 첫 번째 컴포넌트를 브라우저와 `master-ui check`로 확인합니다.

## Master CSS 설정하기 \{#set-up-master-css\}

소스 스타일시트를 사용하려면 먼저 Master CSS 2.1 이상과 사용하는 프레임워크용 통합을 설정하세요. Vite, Astro, Next.js, Svelte 등은 [Master CSS 설치 가이드](https://css.master.co/guide/installation)를 따르세요.

## 패키지 설치하기 \{#install-the-package\}

```bash
npm install @master/ui --save-exact
```

`bun add @master/ui --exact`나 `pnpm add @master/ui --save-exact`처럼 어떤 패키지 매니저든 사용할 수 있습니다. Master UI는 실험 단계이며 어떤 릴리스든 이전에 게시한 것을 깨뜨릴 수 있으므로, 버전을 고정하고 의도적으로 업그레이드하세요. 업그레이드 후 무엇을 실행해야 하는지는 [안정성](/guide/stability#experimental)에서 설명합니다.

## 스타일시트 가져오기 \{#import-the-stylesheet\}

앱 스타일시트에서 Master CSS 프리셋 다음에 Master UI를 가져옵니다.

```css name=app.css
@import '@master/css';
@import '@master/ui';
```

프리셋은 `theme, base, defaults, components, utilities` 레이어 순서를 선언합니다. Master UI는 자신의 규칙을 `components`에 추가하므로, 마크업의 유틸리티가 여전히 우선합니다.

## 설치 확인하기 \{#verify-the-installation\}

앱이 `app.css`를 불러오는지 확인한 다음, 렌더링되는 페이지에 버튼을 추가합니다. JSX에서는 `class` 대신 `className`을 작성하세요.

```html
<button type="button" class="btn btn-primary">Save changes</button>
```

기존 개발 명령으로 앱을 실행합니다. 버튼은 라이트 모드에서 잉크색 면, 다크 모드에서 옅은 면을 가지며, 키보드 포커스 링이 보여야 합니다. 외형에는 동작 스크립트가 필요하지 않지만, 변경 사항을 저장하려면 여전히 애플리케이션의 액션 핸들러가 필요합니다.

스타일이 적용되지 않은 브라우저 기본 버튼처럼 보인다면, 페이지가 `app.css`를 불러오는지, 컴파일된 출력에 `.btn`이 포함되어 있는지 확인하세요. 소스 가져오기를 사용한다면 Master CSS 통합이 이 스타일시트를 처리하는지 확인하세요. 그런 다음 [마크업을 검사하세요](#check-your-markup).

## 사용하는 것만 가져오기 \{#import-only-what-you-use\}

각 컴포넌트는 개별적으로도 내보내집니다. 공유 테마를 먼저 가져온 다음, 앱에 필요한 컴포넌트를 가져옵니다.

```css name=app.css
@import '@master/css';
@import '@master/ui/theme.css';
@import '@master/ui/components/button.css';
@import '@master/ui/components/switch.css';
```

마크업에서 사용하는 모든 클래스의 스타일시트를 포함하세요. 예를 들어 `icon`이나 `spinner`를 포함한 버튼에는 해당 컴포넌트의 스타일시트도 필요합니다. 전체 가져오기를 사용하면 이 목록을 직접 관리하지 않아도 됩니다.

## 스타일시트마다 하나의 가져오기 \{#one-import-per-stylesheet\}

패키지에는 작은 명령줄 도구가 포함되어 있습니다. `init`은 테마와 각 스타일시트를 한 줄씩 가져오는 `ui/index.css`와, 프로젝트가 소유한 것을 기록하는 `master-ui.json`을 작성합니다.

```bash
npx master-ui init
```

```css name=app.css
@import '@master/css';
@import './ui/index.css';
```

전체 `@master/ui` 가져오기 대신 이 진입 파일을 사용합니다. 이는 선택 사항입니다. 가져오기 목록을 직접 관리하거나 [선택한 컴포넌트의 소스를 소유](/guide/registry)하고 싶을 때 선택하세요. 마크업에서 더 이상 해당 클래스를 사용하지 않을 때만 그 줄을 삭제하세요.

## 동작 \{#behaviors\}

대부분의 컴포넌트에는 스크립트가 필요하지 않습니다. 일부 패턴(콤보박스, 명령 팔레트, 캘린더)에는 네이티브 요소가 없으며, 패키지는 각각에 대한 참조 스크립트를 제공합니다.

```js name=app.js
import { attach } from '@master/ui/behaviors'

const detach = attach()
```

마크업이 존재한 후 브라우저 코드에서 `attach()`를 호출합니다. 이 함수는 그 시점에 인식한 패턴을 연결하고 정리 함수를 반환합니다. 해당 마크업을 제거하기 전에 `detach()`를 호출하세요. 이후에 삽입되는 요소를 관찰하거나 컨텍스트 메뉴 대상을 설정하지는 않습니다. 범위를 지정한 연결과 개별 함수는 [동작](/guide/behaviors)을 참고하세요. React, Svelte, Vue에서는 [프레임워크 컴포넌트](/guide/frameworks)를 사용해 생명 주기를 관리하세요.

## Master CSS 없이 사용하기 \{#without-master-css\}

패키지에는 일반 CSS로 컴파일된 컴포넌트가 포함되어 있습니다. CSS 가져오기를 지원하는 번들러는 설치되어 고정된 패키지를 사용할 수 있습니다.

```css name=app.css
@import '@master/ui/base.css';
@import '@master/ui/standalone.css';
```

`base.css`는 `box-sizing: border-box`와 폼 컨트롤 글꼴을 포함한 프리셋의 리셋을 제공합니다. 프로젝트에 이미 동등한 리셋이 있다면 이 가져오기를 생략하세요.

정적 페이지의 경우, 설치된 패키지에서 컴파일된 파일을 서버가 제공하는 디렉터리로 복사합니다. 예를 들어 `public/`이 `/`로 제공되는 경우는 다음과 같습니다.

```bash
mkdir -p public/styles
cp node_modules/@master/ui/dist/base.css public/styles/master-ui-base.css
cp node_modules/@master/ui/dist/standalone.css public/styles/master-ui.css
```

```html
<link rel="stylesheet" href="/styles/master-ui-base.css">
<link rel="stylesheet" href="/styles/master-ui.css">

<button type="button" class="btn btn-primary">Save changes</button>
```

복사한 파일은 설치한 정확한 패키지 버전에서 나온 것입니다. 의도적으로 해당 버전을 업그레이드할 때 다시 복사하세요. 이 경로에서는 앱에서 CSS를 컴파일할 필요가 없습니다.

컴파일된 스타일시트는 소스 빌드와 같은 레이어와 토큰을 선언합니다. 독자의 색 구성표를 따르며, `data-theme="light"` 또는 `data-theme="dark"`로 페이지나 하위 트리의 구성표를 고정할 수 있습니다. Master CSS 유틸리티는 포함되어 있지 않습니다. 레이아웃에는 자체 CSS를 사용하고, [레이아웃](/components#layouts), [블록](/blocks), [페이지](/pages)를 복사할 때는 유틸리티 클래스를 대체하세요.

## 마크업 검사하기 \{#check-your-markup\}

각 스타일시트에는 [계약](/guide/contracts)이 있습니다. 계약은 클래스, 각 클래스가 적용되는 요소, 필요한 속성을 정의합니다. `check`는 템플릿을 읽고 계약을 위반하는 부분을 보고합니다.

```bash
npx master-ui check
```

패키지가 설치된 상태에서 프로젝트 루트에서 실행하세요. HTML과 JSX, Svelte, Vue, Astro 같은 템플릿을 렌더링하지 않고 검사합니다. 진단 결과를 해결한 다음, 브라우저에서 보이는 결과와 키보드 상호작용을 확인하세요. 정적 검사를 통과했다고 해서 접근성이나 브라우저 지원이 보장되지는 않습니다. 진단과 CI에서의 사용은 [AI와 함께 작업하기](/guide/ai#check-the-markup)에서 다룹니다.

## 테마 사용자 지정하기 \{#customize-the-theme\}

브랜드 색상, 모서리 반경, 포커스 색상 같은 공유 값을 바꾸려면 [테마 설정](/guide/theming#retune-tokens)을 사용하세요. 각 값의 역할과 기본값은 [기본 테마](/guide/theme)에서 설명합니다. 변경이 하나의 인스턴스나 하나의 컴포넌트에만 영향을 준다면, 적절한 계층을 선택하기 위해 [사용자 지정](/guide/customization)부터 시작하세요.
