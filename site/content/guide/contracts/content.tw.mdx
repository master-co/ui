套件中的每份樣式表都附有契約：`button.css` 和 `button.json`。契約以程式可讀的格式記錄樣式表的承諾，包括它定義的類別、各類別的使用位置、呈現的狀態、公開的自訂屬性，以及最精簡的正確標記。

檢查器、自動產生的元件表格、可移植的元件頁面和[登錄庫](/guide/registry)都會讀取這些契約。將類別規則集中在同一處可減少重複，套件測試則會確認契約與樣式表一致。契約描述支援的標記，但仍須在瀏覽器中檢查互動、無障礙與視覺行為。

從 `npx master-ui contract button` 開始查閱按鈕的標記與公開屬性。你也可以將這份契約匯入為 `@master/ui/components/button.json`，或從 `@master/ui/contracts.json` 或 `https://ui.master.co/contracts.json` 取得所有契約。結構定義見 `https://ui.master.co/contract.schema.json`。

## 契約內容 \{#keys\}

| 鍵 | 內容 |
| --- | --- |
| `name`, `title`, `tier`, `category`, `description` | 與樣式表檔名相同的 slug、顯示給讀者的名稱、`component` 或 `layout`、所屬群組，以及一句簡介 |
| `use` | 適用時機 |
| `instead` | 其他情境下更合適的選項，每項以 `when` 說明，並在 `use` 填入另一份契約的名稱 |
| `composes` | 此標記引用其類別的其他契約，例如組合方塊會用到 `input` 和 `listbox`。也必須匯入這些契約對應的樣式表 |
| `script` | `none`、`optional` 或 `required` |
| `behavior` | 實作此模式行為的參考腳本 |
| `keyboard` | 各按鍵的原生功能，或接上行為後的功能 |
| `platform` | 用於增強體驗的各項平台功能，以及瀏覽器不支援時呈現的內容 |
| `classes` | 樣式表定義的所有類別，僅限這些類別 |
| `states` | 樣式表呈現的各個狀態，以及標示該狀態的屬性或虛擬類別 |
| `properties` | 公開的自訂屬性 |
| `example` | 最精簡的正確標記 |

`name`、`title`、`tier`、`category`、`description`、`use`、`script`、`classes` 和 `example` 為必填欄位。結構定義只允許使用表中列出的鍵與 `$schema`。

## 類別 \{#classes\}

每個類別都有 `name`、`kind` 和 `description`。類別種類決定它可以用在哪裡。

<GuideFigure name="contracts" title="根類別、修飾類別與部件類別">

**修飾類別與基底類別共用同一個元素，部件類別則用於根元素內部。** 根類別 `dialog` 和修飾類別 `dialog-drawer` 必須用在同一個對話框元素上。作為對話框子元素的標題使用部件類別 `dialog-title`。將修飾類別加到另一個元素上會違反這項規則。

</GuideFigure>

| 種類 | 使用位置 | 範例 |
| --- | --- | --- |
| `root` | 可獨立使用。一份樣式表可以有多個根類別 | `btn`, `btn-group`, `dialog` |
| `part` | 用在根元素內，根類別由 `of` 指定 | `dialog-title` 屬於 `dialog` |
| `modifier` | 與基底類別用在同一個元素上，基底類別由 `of` 指定 | `btn-primary` 屬於 `btn` |

部件的修飾類別會指定該部件。例如 `menu-item-danger` 的 `of` 值是 `menu-item`。如果某個類別可以搭配數個類別中的任一個，`of` 就會是清單。以下是按鈕 `classes` 中的三個項目：

```json name=button.json
{ "name": "btn", "kind": "root", "description": "The raised base button", "elements": ["button", "a", "summary", "label", "input"] },
{ "name": "btn-sm", "kind": "modifier", "of": "btn", "exclusive": "size", "description": "32px tall; the default is 38px" },
{ "name": "btn-square", "kind": "modifier", "of": "btn", "label": true, "description": "A square button for one icon; it needs an accessible name" }
```

## 檢查器強制執行的規則 \{#constraints\}

類別種類本身就提供兩條檢查規則：修飾類別必須搭配基底類別，部件類別必須有對應的根類別。類別上的四個選填鍵可讓 `master-ui check` 回報違反文件規則的情況。只有在樣式表或平台有要求時，契約才會加入這類限制，因為錯誤的限制會讓使用者的專案出現誤報。

| 鍵 | 含義 | 範例 |
| --- | --- | --- |
| `elements` | 類別只在指定的元素上生效。適用於任意元素時省略 | `dialog` 類別的此鍵值為 `["dialog"]` |
| `attributes` | 元素必須具備的屬性：`true` 表示接受任意值，字串表示只接受一個指定值，陣列表示接受其中任一值 | `switch`: `{ "type": "checkbox", "role": "switch" }` |
| `label` | 元素必須有無障礙名稱 | `btn-square`, `dialog-close` |
| `exclusive` | 群組鍵。具有相同鍵的兩個修飾類別不能用在同一個元素上 | `btn-sm` 和 `btn-lg` 都是 `"size"` |

第五個鍵用來放寬規則。`"anywhere": true` 標示可置於根元素外的部件，例如 `field-hint` 屬於 `field`，但也可置於對應的根元素外。

## 狀態與屬性 \{#states-and-properties\}

樣式表負責呈現狀態，標記則以原生屬性或 ARIA 屬性標示狀態。狀態一律不使用類別。每個項目都在 `on` 指定承載狀態標記的類別，並提供簡短的 `name`，以及依標記或 CSS 語法書寫的 `mark`。

```json name=button.json
{ "on": "btn", "name": "pressed", "mark": "aria-pressed=\"true\"", "description": "A quiet toggle that is on stays sunk into a well" }
```

以冒號開頭的標記，例如 `:user-invalid` 或 `:popover-open`，是由瀏覽器判定是否符合的虛擬類別，無須在標記中另行設定。

`properties` 列出屬於公開 API 的自訂屬性，也就是專案可以設定的屬性。每項都有 `name` 和 `description`。若宣告或讀取該屬性的類別並非第一個根類別，就在 `on` 指定該類別。若樣式表宣告了預設值，就提供 `default`。

```json name=button.json
{ "name": "--btn-height", "default": "2.375rem", "description": "Minimum block size" }
```

未列於此處的元件專用自訂屬性屬於實作細節。主題 token 是另一組跨元件共用的公開介面，其用途請見[預設主題](/guide/theme)。如需選擇主題 token 或元件屬性，請參閱[自訂](/guide/customization#property)，目前的版本政策則見[穩定性](/guide/stability)。

## 腳本與行為 \{#script\}

`script` 說明元件對 JavaScript 的依賴程度。

| 值 | 含義 |
| --- | --- |
| `none` | 所有狀態都能在沒有腳本的情況下運作 |
| `optional` | 腳本提供便利功能，例如用方向鍵操作選單。即使沒有腳本，頁面也能正常運作 |
| `required` | 這個模式沒有對應的原生元素，因此由腳本更新其屬性 |

`behavior` 指定參考腳本，該腳本以 `@master/ui/behaviors/<behavior>.js` 發布。組合方塊的契約列出 `"script": "required"` 和 `"behavior": "combobox"`：

```js
import { combobox } from '@master/ui/behaviors/combobox.js'

combobox(document.querySelector('.combobox'))
```

行為會更新樣式表讀取的屬性。分隔器等模式也會透過公開的自訂屬性傳遞從事件取得的值，再由樣式表決定如何呈現。`keyboard` 列出掛載行為後各按鍵的作用，或原生元素本身提供的按鍵操作。請參閱[行為](/guide/behaviors)。

## 範例 \{#example\}

`example` 是符合契約且包含實際文字的最精簡標記。套件測試會用檢查器檢查每個範例，預期不會產生任何診斷。以這份標記為起點，再為頁面加上標籤、唯一的 ID、應用程式動作及任何必要的行為。

```html
<button type="button" class="btn btn-primary">Save changes</button>
```

## 為自己的元件撰寫契約 \{#your-own\}

如果元件庫缺少某個設計，而該設計的各個部分共用材質、狀態、平台行為或幾何配置，專案就可以新增自己的元件。在 `@layer components` 中使用類別選擇器和 token 撰寫元件的樣式表，並將契約與樣式表一併放在 `ui/` 目錄中。契約採用與元件庫相同的結構描述。

```css name=ui/price-tag.css
@layer components {
  .price-tag {
    --price-tag-size: 1.125rem;
    display: inline-flex;
    align-items: baseline;
    gap: .375rem;
    color: var(--color-text-strong);
    font-size: var(--price-tag-size);
    font-variant-numeric: tabular-nums;

    &.price-tag-sale {
      color: var(--color-danger);
    }
  }

  .price-tag-was {
    color: var(--color-text-muted);
    font-size: .75em;
  }
}
```

```json name=ui/price-tag.json
{
  "$schema": "https://ui.master.co/contract.schema.json",
  "name": "price-tag",
  "title": "Price tag",
  "tier": "component",
  "category": "Commerce",
  "description": "The price of one product, with the price it replaces.",
  "use": "A price on a product card or in a cart row. Add price-tag-sale and the old price when the product is reduced.",
  "script": "none",
  "classes": [
    { "name": "price-tag", "kind": "root", "description": "The current price, in strong ink and tabular figures" },
    { "name": "price-tag-sale", "kind": "modifier", "of": "price-tag", "description": "A reduced price, in the danger hue" },
    { "name": "price-tag-was", "kind": "part", "of": "price-tag", "elements": ["s"], "description": "The price before the reduction, struck through in muted ink" }
  ],
  "properties": [
    { "name": "--price-tag-size", "default": "1.125rem", "description": "Font size of the current price" }
  ],
  "example": "<p class=\"price-tag price-tag-sale\">$24 <s class=\"price-tag-was\">$32</s></p>"
}
```

在應用程式的樣式表中，於 Master UI 之後匯入 `ui/price-tag.css`，讓範例套用樣式。CLI 無須透過這項 CSS 匯入，即可找到同一目錄下的契約：

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import './ui/price-tag.css';
```

接著就能用同一套工具處理專案的元件：

- `npx master-ui list` 會列出這個元件，`npx master-ui contract price-tag` 會印出它的契約。先讀取契約再撰寫標記的代理程式，也會用同樣的方式找到它。
- `npx master-ui check` 會依照契約檢查標記。在這個範例中，`npx master-ui check cart.html` 回報了三個錯誤：

```html name=cart.html
<p class="price-tag-sale">$24</p>
<p class="price-tag">$24 <span class="price-tag-was">$32</span></p>
<p class="price-tag price-tag-large">$24</p>
```

```
cart.html:1:1 error missing-base "price-tag-sale" modifies "price-tag": write class="price-tag price-tag-sale".
cart.html:2:26 error element "price-tag-was" goes on <s>, not <span>.
cart.html:3:1 warning unknown-class "price-tag-large" is not a class of price-tag. It has: price-tag, price-tag-sale, price-tag-was.

1 files checked: 2 errors, 1 warnings.
```

三項細節：

- **契約的讀取位置。** 工具會讀取專案 `ui/` 目錄中所有具備 `name` 欄位與 `classes` 陣列的 `.json` 檔案。`master-ui.json` 可在 `directory` 指定其他目錄，並在 `contracts` 陣列中指定其他檔案比對模式。
- **結構描述宣告。** `"$schema": "https://ui.master.co/contract.schema.json"` 讓編輯器在編寫時驗證檔案。
- **與元件庫同名的契約。** 專案契約若與元件庫的契約同名，就會取代原有契約。這樣一來，[由專案維護的元件](/guide/customization#own-a-component) 就會由專案中的契約副本描述。

## 診斷 \{#diagnostics\}

`master-ui check` 會為每筆結果輸出一行，列出檔案、行號、欄號、嚴重程度、診斷代碼和訊息。除 `unknown-class` 預設為警告外，其餘代碼都是錯誤。加上 `--strict` 後，該警告也會視為錯誤。

| 代碼 | 含義 | 修正方式 |
| --- | --- | --- |
| `unknown-class` | 類別名稱以根類別名稱加上連字號開頭，但未列在任何契約中 | 使用訊息列出的其中一個類別。如果是專案自訂的類別，請將它加入 `ui/` 中的契約，或改用不帶該元件前綴的名稱 |
| `missing-base` | 元素有修飾類別，但缺少被修飾的類別 | 在同一元素上加上基底類別，例如 `class="btn btn-primary"` |
| `outside-root` | 部件的祖先元素都沒有對應的根類別 | 將部件移到根元素內，或在容器上加上根類別 |
| `exclusive` | 同一元素有兩個屬於同一組的修飾類別，例如同時指定兩種尺寸 | 保留其中一個 |
| `element` | 類別用在契約未允許的元素上 | 改用訊息指定的元素，例如 `dialog` 應用在對話框元素上 |
| `attribute` | 元素缺少該類別要求的屬性，或屬性值不符 | 加上訊息指定的屬性，例如 `role="switch"` |
| `label` | 控制項沒有無障礙名稱 | 為控制項提供本身的文字、`aria-label`、`aria-labelledby`，或使用包住它或指向它的標籤 |

檢查器直接讀取原始碼，無須算繪頁面。它可以檢查運算式中的字面類別名稱，但無法解析動態計算的類別名稱、確認框架元件會在哪裡算繪子元素，或檢查其他檔案中的根元素。遇到無法確定的情況時，檢查器會略過。即使沒有診斷訊息，也無法據此確認焦點順序、對比度、瀏覽器支援情況，或選用的元件是否適合該用途。
