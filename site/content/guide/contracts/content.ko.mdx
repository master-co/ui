패키지의 각 스타일시트에는 계약이 함께 제공됩니다(`button.css` 및 `button.json`). 계약은 스타일시트가 지원하는 클래스와 각 클래스의 적용 위치, 스타일로 표현하는 상태, 공개하는 사용자 지정 속성, 올바른 최소 마크업을 프로그램이 읽을 수 있는 형식으로 명시합니다.

검사기, 자동 생성되는 컴포넌트 표, 이식 가능한 컴포넌트 페이지, [레지스트리](/guide/registry)는 이 계약을 읽습니다. 클래스 규칙을 한곳에서 관리하면 중복을 줄일 수 있으며, 패키지 테스트는 계약과 스타일시트가 일치하는지 확인합니다. 계약은 지원하는 마크업을 설명하지만, 상호작용과 접근성, 화면 표시 동작은 브라우저에서 직접 확인해야 합니다.

버튼의 마크업과 공개 속성을 확인하려면 `npx master-ui contract button`을 실행해 보세요. 계약을 `@master/ui/components/button.json`에서 가져오거나 `@master/ui/contracts.json` 또는 `https://ui.master.co/contracts.json`에서 모든 계약을 한꺼번에 가져올 수도 있습니다. 스키마는 `https://ui.master.co/contract.schema.json`입니다.

## 계약의 구성 \{#keys\}

| 키 | 내용 |
| --- | --- |
| `name`, `title`, `tier`, `category`, `description` | 스타일시트 파일명인 슬러그, 독자에게 표시되는 이름, `component` 또는 `layout`, 소속 그룹, 한 문장으로 된 소개 |
| `use` | 사용하기 적합한 상황 |
| `instead` | 다른 상황에 적합한 대안. 각 항목의 `when`에는 사용 조건을, `use`에는 다른 계약의 이름을 지정합니다. |
| `composes` | 마크업에서 사용하는 클래스가 속한 다른 계약. 예를 들어 콤보박스는 `input`과 `listbox`의 클래스를 사용합니다. 해당 스타일시트도 함께 가져와야 합니다. |
| `script` | `none`, `optional` 또는 `required` |
| `behavior` | 패턴의 동작을 구현하는 참조 스크립트 |
| `keyboard` | 네이티브 요소의 기본 키 동작 또는 동작을 연결한 뒤의 키 동작 |
| `platform` | 기능을 보강하는 데 사용하는 각 플랫폼 기능과 이를 지원하지 않는 브라우저에서 표시되는 내용 |
| `classes` | 스타일시트가 정의한 클래스 전체만 포함 |
| `states` | 스타일시트가 표현하는 각 상태와 이를 나타내는 속성 또는 가상 클래스 |
| `properties` | 공개 사용자 지정 속성 |
| `example` | 올바른 최소 마크업 |

`name`, `title`, `tier`, `category`, `description`, `use`, `script`, `classes`, `example`은 필수입니다. 스키마는 이 표에 나온 키와 `$schema`만 허용합니다.

## 클래스 \{#classes\}

각 클래스에는 `name`, `kind`, `description`이 있습니다. 클래스 유형에 따라 적용할 수 있는 위치가 정해집니다.

<GuideFigure name="contracts" title="루트, 수정자, 파트">

**수정자는 기본 클래스와 같은 요소에 적용하고, 파트는 루트 요소 안에 배치합니다.** 루트 `dialog`와 수정자 `dialog-drawer`는 같은 대화 상자 요소에 적용합니다. 자식 제목 요소에는 파트 `dialog-title`을 적용합니다. 수정자를 별도 요소에 적용하면 이 조건을 충족하지 못합니다.

</GuideFigure>

| 유형 | 적용 위치 | 예시 |
| --- | --- | --- |
| `root` | 단독으로 적용합니다. 한 스타일시트에 여러 개가 있을 수 있습니다. | `btn`, `btn-group`, `dialog` |
| `part` | `of`에 지정한 루트 요소 안에 배치합니다. | `dialog`의 `dialog-title` |
| `modifier` | `of`에 지정한 기본 클래스와 같은 요소에 적용합니다. | `btn`의 `btn-primary` |

파트에 적용하는 수정자는 해당 파트의 이름을 지정합니다. `menu-item-danger`의 `of` 값은 `menu-item`입니다. 클래스가 여러 후보 중 하나와 함께 쓰일 수 있으면 `of` 값은 목록이 됩니다. 다음은 버튼의 `classes`에 있는 항목 세 개입니다.

```json name=button.json
{ "name": "btn", "kind": "root", "description": "The raised base button", "elements": ["button", "a", "summary", "label", "input"] },
{ "name": "btn-sm", "kind": "modifier", "of": "btn", "exclusive": "size", "description": "32px tall; the default is 38px" },
{ "name": "btn-square", "kind": "modifier", "of": "btn", "label": true, "description": "A square button for one icon; it needs an accessible name" }
```

## 검사기가 적용하는 규칙 \{#constraints\}

검사기는 클래스 유형만으로 두 가지 규칙을 적용합니다. 수정자에는 기본 클래스가 필요하고, 파트에는 루트가 필요합니다. 클래스에 선택 키 네 가지를 사용하면 문서의 규칙을 어겼을 때 `master-ui check`에서 이를 진단할 수 있습니다. 잘못된 제약은 사용자 프로젝트에서 정상적인 마크업을 오류로 보고하므로, 스타일시트나 플랫폼에서 요구하는 경우에만 계약에 해당 키를 추가합니다.

| 키 | 의미 | 예시 |
| --- | --- | --- |
| `elements` | 클래스는 지정된 요소에서만 동작합니다. 어떤 요소에서든 동작하면 이 키를 생략합니다. | `dialog`의 허용 요소는 `["dialog"]` |
| `attributes` | 요소에 반드시 있어야 하는 속성. 값에 제한이 없으면 `true`, 특정 값 하나만 허용하면 문자열, 여러 값 중 하나를 허용하면 배열을 사용합니다. | `switch`: `{ "type": "checkbox", "role": "switch" }` |
| `label` | 요소에 접근 가능한 이름이 필요합니다. | `btn-square`, `dialog-close` |
| `exclusive` | 그룹을 나타내는 키입니다. 같은 키를 가진 수정자 두 개를 같은 요소에 적용할 수 없습니다. | `btn-sm`과 `btn-lg`의 그룹 키는 모두 `"size"`입니다. |

다섯 번째 키는 규칙을 완화합니다. `"anywhere": true`는 루트 밖에도 배치할 수 있는 파트를 표시합니다. 예를 들어 `field`의 파트인 `field-hint`를 해당 루트 밖에도 배치할 수 있습니다.

## 상태와 속성 \{#states-and-properties\}

스타일시트는 상태를 시각적으로 표현하고, 마크업에서는 네이티브 속성이나 ARIA 속성으로 상태를 나타냅니다. 상태를 나타내는 데 클래스는 사용하지 않습니다. 각 항목에는 상태 표시가 붙는 클래스의 이름을 `on`에 적고, 짧은 `name`과 마크업이나 CSS에 쓰이는 그대로의 `mark`를 담습니다.

```json name=button.json
{ "on": "btn", "name": "pressed", "mark": "aria-pressed=\"true\"", "description": "A quiet toggle that is on stays sunk into a well" }
```

`:user-invalid`이나 `:popover-open`처럼 콜론으로 시작하는 상태 표시는 브라우저가 적용하는 가상 클래스이므로 마크업에 따로 작성할 필요가 없습니다.

`properties`에는 프로젝트에서 설정할 수 있는 공개 API인 사용자 지정 속성이 나열됩니다. 각 속성에는 `name`과 `description`이 있습니다. 속성을 선언하거나 읽는 클래스가 첫 번째 루트가 아닌 경우 `on`에 해당 클래스를 명시하고, 스타일시트가 기본값을 선언하는 경우 `default`에 그 값을 명시합니다.

```json name=button.json
{ "name": "--btn-height", "default": "2.375rem", "description": "Minimum block size" }
```

이 목록에 없는 컴포넌트별 사용자 지정 속성은 내부 구현에 속합니다. 테마 토큰은 여러 컴포넌트에서 공유하는 별도의 공개 API입니다. 각 토큰의 역할은 [기본 테마](/guide/theme)를 참조하세요. 테마 토큰과 컴포넌트 속성 중 무엇을 사용할지는 [사용자 지정](/guide/customization#property)을, 현재 버전 정책은 [안정성](/guide/stability)을 참조하세요.

## 스크립트와 동작 \{#script\}

`script` 값은 컴포넌트가 JavaScript에 어느 정도 의존하는지 나타냅니다.

| 값 | 의미 |
| --- | --- |
| `none` | 모든 상태가 스크립트 없이 동작합니다. |
| `optional` | 스크립트는 메뉴의 방향키 조작과 같은 편의 기능을 추가하며, 페이지는 스크립트 없이도 동작합니다. |
| `required` | 패턴에 해당하는 네이티브 요소가 없어 스크립트가 속성을 갱신합니다. |

`behavior` 키는 `@master/ui/behaviors/<behavior>.js`로 공개되는 참조 스크립트를 지정합니다. 콤보박스 계약에는 `"script": "required"`와 `"behavior": "combobox"`가 명시되어 있습니다.

```js
import { combobox } from '@master/ui/behaviors/combobox.js'

combobox(document.querySelector('.combobox'))
```

동작은 스타일시트가 읽는 속성을 갱신합니다. 스플리터 같은 패턴은 이벤트에서 얻은 값도 공개 사용자 지정 속성을 통해 전달하며, 그 값을 화면에 어떻게 표현할지는 스타일시트가 결정합니다. `keyboard`에는 동작을 연결한 뒤 각 키가 하는 일이나 네이티브 요소가 기본으로 제공하는 키 동작이 나열됩니다. [동작](/guide/behaviors)을 참조하세요.

## 마크업 예시 \{#example\}

`example`은 실제 문구를 포함한 올바른 최소 마크업입니다. 패키지 테스트는 모든 예시에 검사기를 실행하고 진단 결과가 없는지 확인합니다. 이 예시를 마크업의 출발점으로 삼아 페이지에 맞는 레이블, 고유 ID, 애플리케이션 동작, 필요한 컴포넌트 동작을 추가하세요.

```html
<button type="button" class="btn btn-primary">Save changes</button>
```

## 프로젝트 컴포넌트의 계약 작성 \{#your-own\}

라이브러리에 없는 컴포넌트가 필요하고 그 구성 요소들이 재질, 상태, 플랫폼 동작 또는 형태를 공유한다면 프로젝트에 자체 컴포넌트를 추가합니다. `@layer components`에 클래스 선택자와 토큰을 사용해 스타일시트를 작성하고, `ui/` 디렉터리에 그 스타일시트와 나란히 계약 파일을 두세요. 계약은 라이브러리와 동일한 스키마를 따릅니다.

```css name=ui/price-tag.css
@layer components {
  .price-tag {
    --price-tag-size: 1.125rem;
    display: inline-flex;
    align-items: baseline;
    gap: .375rem;
    color: var(--color-text-strong);
    font-size: var(--price-tag-size);
    font-variant-numeric: tabular-nums;

    &.price-tag-sale {
      color: var(--color-danger);
    }
  }

  .price-tag-was {
    color: var(--color-text-muted);
    font-size: .75em;
  }
}
```

```json name=ui/price-tag.json
{
  "$schema": "https://ui.master.co/contract.schema.json",
  "name": "price-tag",
  "title": "Price tag",
  "tier": "component",
  "category": "Commerce",
  "description": "The price of one product, with the price it replaces.",
  "use": "A price on a product card or in a cart row. Add price-tag-sale and the old price when the product is reduced.",
  "script": "none",
  "classes": [
    { "name": "price-tag", "kind": "root", "description": "The current price, in strong ink and tabular figures" },
    { "name": "price-tag-sale", "kind": "modifier", "of": "price-tag", "description": "A reduced price, in the danger hue" },
    { "name": "price-tag-was", "kind": "part", "of": "price-tag", "elements": ["s"], "description": "The price before the reduction, struck through in muted ink" }
  ],
  "properties": [
    { "name": "--price-tag-size", "default": "1.125rem", "description": "Font size of the current price" }
  ],
  "example": "<p class=\"price-tag price-tag-sale\">$24 <s class=\"price-tag-was\">$32</s></p>"
}
```

예제에 스타일이 적용되도록 애플리케이션 스타일시트에서 Master UI 다음에 `ui/price-tag.css` 파일을 가져오세요. CLI는 이 CSS 가져오기와 별개로 같은 디렉터리의 계약을 찾습니다.

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import './ui/price-tag.css';
```

이제 같은 도구로 프로젝트의 컴포넌트를 다룰 수 있습니다.

- `npx master-ui list`를 실행하면 목록에 컴포넌트가 표시되고, `npx master-ui contract price-tag`를 실행하면 계약 내용이 출력됩니다. 마크업을 작성하기 전에 계약을 읽는 에이전트도 같은 방식으로 계약을 찾습니다.
- `npx master-ui check` 명령은 마크업이 계약을 따르는지 검사합니다. 이 예제에서 `npx master-ui check cart.html`을 실행하면 오류 세 건이 보고됩니다.

```html name=cart.html
<p class="price-tag-sale">$24</p>
<p class="price-tag">$24 <span class="price-tag-was">$32</span></p>
<p class="price-tag price-tag-large">$24</p>
```

```
cart.html:1:1 error missing-base "price-tag-sale" modifies "price-tag": write class="price-tag price-tag-sale".
cart.html:2:26 error element "price-tag-was" goes on <s>, not <span>.
cart.html:3:1 warning unknown-class "price-tag-large" is not a class of price-tag. It has: price-tag, price-tag-sale, price-tag-was.

1 files checked: 2 errors, 1 warnings.
```

세부 사항은 다음과 같습니다.

- **계약을 읽는 위치.** 프로젝트의 `ui/` 디렉터리에 있는 `.json` 파일 중 `name`과 `classes` 배열이 있는 파일을 모두 읽습니다. `master-ui.json`에서는 `directory`에 다른 디렉터리를 지정하고 `contracts` 배열에 패턴을 추가할 수 있습니다.
- **스키마 선언 줄.** `"$schema": "https://ui.master.co/contract.schema.json"`을 지정하면 편집기에서 파일을 작성하는 동안 스키마에 맞는지 검사할 수 있습니다.
- **라이브러리에 이미 있는 이름.** 프로젝트 계약의 이름이 라이브러리 계약의 이름과 같으면 프로젝트 계약이 기존 계약을 대체합니다. 이 방식으로 [프로젝트가 소유한 컴포넌트](/guide/customization#own-a-component)를 프로젝트에 복사해 둔 계약으로 정의합니다.

## 진단 \{#diagnostics\}

`master-ui check` 명령은 진단 항목마다 파일, 줄과 열, 심각도, 코드, 메시지를 한 줄에 출력합니다. `unknown-class` 코드는 기본적으로 경고이며 `--strict` 옵션을 전달하면 오류로 처리됩니다. 그 외 코드는 모두 오류입니다.

| 코드 | 의미 | 해결 방법 |
| --- | --- | --- |
| `unknown-class` | 클래스 이름이 루트 클래스 이름과 하이픈으로 시작하지만 어떤 계약에도 없습니다 | 메시지에 나열된 클래스 중 하나를 사용하세요. 프로젝트 자체 클래스라면 `ui/`의 계약에 추가하거나 컴포넌트의 이름 접두사로 시작하지 않는 이름을 사용하세요 |
| `missing-base` | 한 요소에 수정자 클래스가 있지만 해당 수정자가 적용되는 기본 클래스가 없습니다 | 같은 요소에 기본 클래스를 추가하세요: `class="btn btn-primary"` |
| `outside-root` | 파트가 적용된 요소의 조상 중 해당 루트 클래스가 지정된 요소가 없습니다 | 파트가 적용된 요소를 루트 안으로 옮기거나 컨테이너에 루트 클래스를 추가하세요 |
| `exclusive` | 크기 수정자 두 개처럼 같은 그룹의 수정자 두 개가 한 요소에 적용되어 있습니다 | 하나만 남기세요 |
| `element` | 계약에서 허용하지 않는 요소에 클래스가 지정되어 있습니다 | 메시지에 나온 요소를 사용하세요. `dialog` 클래스를 dialog 요소에 지정합니다 |
| `attribute` | 클래스에 필요한 속성이 요소에 없거나 해당 속성의 값이 다릅니다 | `role="switch"`처럼 메시지에 나온 속성을 추가하세요 |
| `label` | 컨트롤에 접근 가능한 이름이 없습니다 | 컨트롤 자체의 텍스트, `aria-label`, `aria-labelledby` 또는 컨트롤을 감싸거나 참조하는 레이블을 사용하세요 |

검사기는 페이지를 렌더링하지 않고 소스 코드를 읽습니다. 표현식에 리터럴로 적힌 클래스는 검사할 수 있지만, 계산으로 정해지는 클래스 이름을 알아내거나 프레임워크 컴포넌트가 자식 요소를 어디에 렌더링하는지 확인하거나 다른 파일의 루트를 검사할 수는 없습니다. 확실히 판단할 수 없는 경우에는 진단을 표시하지 않습니다. 진단이 없어도 포커스 순서, 대비, 브라우저 지원 여부, 선택한 컴포넌트가 작업에 적합한지는 확인되지 않습니다.
