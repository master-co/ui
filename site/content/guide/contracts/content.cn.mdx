包中的每份样式表都配有一份契约，例如 `button.css` 和 `button.json`。契约以机器可读的形式说明样式表支持哪些类、各个类可用在何处、样式表呈现哪些状态、公开哪些自定义属性，并提供最精简的正确标记。

检查器、自动生成的组件表格、可移植的组件页面和[注册表](/guide/registry)都读取这些契约。将类规则集中在一处可减少重复，包的测试会检查契约与样式表是否一致。契约描述支持的标记，交互、无障碍和视觉表现仍需在浏览器中验证。

先运行 `npx master-ui contract button`，查看按钮的标记和公开属性。也可以用 `@master/ui/components/button.json` 导入这份契约，或从 `@master/ui/contracts.json` 或 `https://ui.master.co/contracts.json` 获取全部契约。契约的结构定义见 `https://ui.master.co/contract.schema.json`。

## 契约包含哪些内容 \{#keys\}

| 键 | 内容 |
| --- | --- |
| `name`, `title`, `tier`, `category`, `description` | 标识符（即样式表的文件名）、面向读者的名称、`component` 或 `layout`、所属分组，以及一句简介 |
| `use` | 适用场景 |
| `instead` | 适用于其他场景的相关选项，每项包含一个 `when`，并在 `use` 中填写另一份契约的名称 |
| `composes` | 标记中用到的其他类所属的契约，例如组合框用到的 `input` 和 `listbox`。这些契约对应的样式表也必须导入 |
| `script` | `none`、`optional` 或 `required` |
| `behavior` | 驱动该模式的参考脚本 |
| `keyboard` | 各按键的作用，由浏览器原生提供或在接入行为脚本后生效 |
| `platform` | 用作增强的每项平台特性，以及浏览器不支持该特性时的显示效果 |
| `classes` | 仅列出样式表定义的全部类 |
| `states` | 样式表呈现的每种状态，以及标记该状态的属性或伪类 |
| `properties` | 公开的自定义属性 |
| `example` | 最精简的正确标记 |

`name`、`title`、`tier`、`category`、`description`、`use`、`script`、`classes` 和 `example` 都是必填项。结构定义仅允许使用表中列出的键和 `$schema`。

## 类 \{#classes\}

每个类都有 `name`、`kind` 和 `description`。类型决定类可以用在什么位置。

<GuideFigure name="contracts" title="根类、修饰类和部件类">

**修饰类与基础类用在同一元素上，部件类用在根元素内部。** 根类 `dialog` 和修饰类 `dialog-drawer` 应用在同一个 dialog 元素上。其子标题元素使用部件类 `dialog-title`。将修饰类加到另一个元素上会违反这条规则。

</GuideFigure>

| 类型 | 使用位置 | 示例 |
| --- | --- | --- |
| `root` | 可独立使用。一份样式表可以有多个根类 | `btn`, `btn-group`, `dialog` |
| `part` | 用在根元素内部，根类在 `of` 中指定 | `dialog` 的 `dialog-title` |
| `modifier` | 与基础类用在同一元素上，基础类在 `of` 中指定 | `btn` 的 `btn-primary` |

部件的修饰类以该部件为基础类。`menu-item-danger` 的 `of` 指向 `menu-item`。当一个类可与多个类中的任意一个搭配时，`of` 采用列表形式。以下三项来自按钮的 `classes`。

```json name=button.json
{ "name": "btn", "kind": "root", "description": "The raised base button", "elements": ["button", "a", "summary", "label", "input"] },
{ "name": "btn-sm", "kind": "modifier", "of": "btn", "exclusive": "size", "description": "32px tall; the default is 38px" },
{ "name": "btn-square", "kind": "modifier", "of": "btn", "label": true, "description": "A square button for one icon; it needs an accessible name" }
```

## 检查器强制执行的规则 \{#constraints\}

类的类型为检查器提供两条规则：修饰类必须搭配其基础类，部件类必须位于其根元素内。类上的四个可选键可将文档规则变为 `master-ui check` 能报告的违规项。只有样式表或平台要求时，才在契约中添加相应的键，因为错误的约束会在使用者的项目中引发误报。

| 键 | 含义 | 示例 |
| --- | --- | --- |
| `elements` | 该类仅在指定的元素上生效。适用于任意元素时省略此键 | 用在 `["dialog"]` 上的 `dialog` |
| `attributes` | 元素必须带有的属性。`true` 表示允许任意值，字符串表示只允许该字符串指定的值，数组表示允许其中任意一个值 | `switch`: `{ "type": "checkbox", "role": "switch" }` |
| `label` | 元素必须有无障碍名称 | `btn-square`, `dialog-close` |
| `exclusive` | 分组键。具有同一分组键的两个修饰类不能用在同一元素上 | `btn-sm` 和 `btn-lg` 都是 `"size"` |

第五个键可放宽一条规则。`"anywhere": true` 标记可放在根元素外的部件类。例如，`field-hint` 是 `field` 的部件类，也可以放在其根元素外。

## 状态与属性 \{#states-and-properties\}

样式表呈现状态，标记则通过原生属性或 ARIA 属性标明状态。状态没有专用类。每条记录在 `on` 中列出承载状态标记的类，并给出简短的 `name`，以及 `mark` 在标记或 CSS 中的原样写法。

```json name=button.json
{ "on": "btn", "name": "pressed", "mark": "aria-pressed=\"true\"", "description": "A quiet toggle that is on stays sunk into a well" }
```

以冒号开头的标记（如 `:user-invalid` 或 `:popover-open`）是由浏览器设置的伪类，无需手动添加。

`properties` 列出项目可以设置的自定义属性，这些属性属于公开 API。每个属性都有 `name` 和 `description`。如果声明或读取该属性的类不是第一个根类，则在 `on` 中列出该类。如果样式表声明了默认值，则给出 `default`。

```json name=button.json
{ "name": "--btn-height", "default": "2.375rem", "description": "Minimum block size" }
```

此列表之外的组件专用自定义属性属于实现细节。主题令牌是各组件共用的另一套公开接口，其用途见[默认主题](/guide/theme)。如何在主题令牌和组件属性之间选择，见[自定义](/guide/customization#property)。当前版本策略见[稳定性](/guide/stability)。

## 脚本与行为 \{#script\}

`script` 说明组件对 JavaScript 的依赖程度。

| 值 | 含义 |
| --- | --- |
| `none` | 所有状态都无需脚本即可生效 |
| `optional` | 脚本提供便利功能，例如在菜单中使用方向键。页面无需脚本也能正常使用 |
| `required` | 这种交互模式没有对应的原生元素，因此由脚本更新属性 |

`behavior` 指定参考脚本，脚本以 `@master/ui/behaviors/<behavior>.js` 的形式发布。组合框的契约给出 `"script": "required"` 和 `"behavior": "combobox"`：

```js
import { combobox } from '@master/ui/behaviors/combobox.js'

combobox(document.querySelector('.combobox'))
```

行为脚本更新样式表读取的属性。分隔条等交互模式还会通过公开的自定义属性传递从事件中取得的值，具体如何呈现由样式表决定。`keyboard` 列出挂载行为脚本后的按键功能，或原生元素已有的按键功能。参见[行为脚本](/guide/behaviors)。

## 示例 \{#example\}

`example` 提供包含实际文案的最简有效标记。包的测试会用检查器验证每个示例，要求不产生任何诊断。以它为标记模板，再补充页面所需的标签、唯一 ID、应用操作和必要的行为。

```html
<button type="button" class="btn btn-primary">Save changes</button>
```

## 为自己的组件编写契约 \{#your-own\}

如果库中没有满足需求的组件，而项目需要特定的材质、状态、平台行为或各部分共享的几何规则，就可以添加自己的组件。在 `@layer components` 中用类选择器和令牌编写样式表，并将契约与样式表一同放在 `ui/` 目录中。契约采用与库相同的模式。

```css name=ui/price-tag.css
@layer components {
  .price-tag {
    --price-tag-size: 1.125rem;
    display: inline-flex;
    align-items: baseline;
    gap: .375rem;
    color: var(--color-text-strong);
    font-size: var(--price-tag-size);
    font-variant-numeric: tabular-nums;

    &.price-tag-sale {
      color: var(--color-danger);
    }
  }

  .price-tag-was {
    color: var(--color-text-muted);
    font-size: .75em;
  }
}
```

```json name=ui/price-tag.json
{
  "$schema": "https://ui.master.co/contract.schema.json",
  "name": "price-tag",
  "title": "Price tag",
  "tier": "component",
  "category": "Commerce",
  "description": "The price of one product, with the price it replaces.",
  "use": "A price on a product card or in a cart row. Add price-tag-sale and the old price when the product is reduced.",
  "script": "none",
  "classes": [
    { "name": "price-tag", "kind": "root", "description": "The current price, in strong ink and tabular figures" },
    { "name": "price-tag-sale", "kind": "modifier", "of": "price-tag", "description": "A reduced price, in the danger hue" },
    { "name": "price-tag-was", "kind": "part", "of": "price-tag", "elements": ["s"], "description": "The price before the reduction, struck through in muted ink" }
  ],
  "properties": [
    { "name": "--price-tag-size", "default": "1.125rem", "description": "Font size of the current price" }
  ],
  "example": "<p class=\"price-tag price-tag-sale\">$24 <s class=\"price-tag-was\">$32</s></p>"
}
```

在应用样式表中，将 `ui/price-tag.css` 放在 Master UI 之后导入，以呈现示例。CLI 查找同目录下的契约，无需依赖这条 CSS 导入语句：

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import './ui/price-tag.css';
```

随后便可用同一套工具处理项目中的组件：

- `npx master-ui list` 将该组件列入清单，`npx master-ui contract price-tag` 输出其契约。先读契约再写标记的智能体也以同样的方式找到它。
- `npx master-ui check` 根据该契约检查标记。这里的 `npx master-ui check cart.html` 报告了三处错误：

```html name=cart.html
<p class="price-tag-sale">$24</p>
<p class="price-tag">$24 <span class="price-tag-was">$32</span></p>
<p class="price-tag price-tag-large">$24</p>
```

```
cart.html:1:1 error missing-base "price-tag-sale" modifies "price-tag": write class="price-tag price-tag-sale".
cart.html:2:26 error element "price-tag-was" goes on <s>, not <span>.
cart.html:3:1 warning unknown-class "price-tag-large" is not a class of price-tag. It has: price-tag, price-tag-sale, price-tag-was.

1 files checked: 2 errors, 1 warnings.
```

三个细节：

- **契约的读取位置。** 读取项目的 `ui/` 目录中所有同时包含 `name` 字段和 `classes` 数组的 `.json` 文件。`master-ui.json` 可在 `directory` 中指定其他目录，并在 `contracts` 数组中指定更多匹配模式。
- **模式声明。** `"$schema": "https://ui.master.co/contract.schema.json"` 让编辑器在编写文件时即可验证其内容。
- **与库中的契约同名。** 项目中的契约会替换库中的同名契约。这样，[由项目接管的组件](/guide/customization#own-a-component) 就由项目中的契约副本描述。

## 诊断 \{#diagnostics\}

`master-ui check` 为每条诊断输出一行，包含文件、行号、列号、严重级别、代码和消息。`unknown-class` 默认是警告，传入 `--strict` 后按错误处理。其余代码均为错误。

| 代码 | 含义 | 修复方法 |
| --- | --- | --- |
| `unknown-class` | 类名以根类名加连字符开头，但未在任何契约中声明 | 使用消息列出的任一类名。对于项目自有的类，可将其添加到 `ui/` 中的契约，或改用不带该组件前缀的类名 |
| `missing-base` | 元素使用了修饰类，却缺少该修饰类所修饰的类 | 在同一元素上添加基础类：`class="btn btn-primary"` |
| `outside-root` | 部件没有带对应根类的祖先元素 | 将部件移入根元素，或给容器添加根类 |
| `exclusive` | 同一元素使用了同组的两个修饰类，例如两个尺寸修饰类 | 只保留一个 |
| `element` | 类用在了其契约不允许的元素上 | 使用提示指定的元素，例如将 `dialog` 用在 dialog 元素上 |
| `attribute` | 元素缺少该类要求的属性，或该属性的值不符合要求 | 添加提示指定的属性，例如 `role="switch"` |
| `label` | 控件没有无障碍名称 | 为控件提供自身文本、`aria-label`、`aria-labelledby`，或使用包裹该控件或指向该控件的 label 元素 |

检查器直接读取源码，无需渲染页面。它能检查表达式中直接写出的类名，但无法解析动态计算的类名、确认框架组件在何处渲染子元素，或检查另一个文件中的根元素。遇到无法确定的情况，检查器会跳过。即使检查通过，仍需确认焦点顺序、对比度、浏览器支持以及所选组件是否适合当前任务。
