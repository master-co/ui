パッケージ内の各スタイルシートには、対応するコントラクトが同じ場所にあります。`button.css` と `button.json` がその例です。コントラクトには、スタイルシートが提供するクラスとその配置、表示する状態、公開するカスタムプロパティ、最小限の正しいマークアップを、プログラムで読み取れる形式で記述します。

チェッカー、自動生成されたコンポーネント表、別の環境でも使えるコンポーネントページ、[レジストリ](/guide/registry)は、コントラクトを参照します。クラスのルールを一か所にまとめて重複を減らし、パッケージのテストでコントラクトとスタイルシートの整合性を確認します。コントラクトが記述するのは、サポート対象のマークアップです。操作、アクセシビリティ、表示の挙動はブラウザーで確認してください。

まず `npx master-ui contract button` で、ボタンのマークアップと公開プロパティを確認します。`@master/ui/components/button.json` としてインポートすることも、`@master/ui/contracts.json` または `https://ui.master.co/contracts.json` から全件取得することもできます。スキーマは `https://ui.master.co/contract.schema.json` です。

## コントラクトの内容 \{#keys\}

| キー | 内容 |
| --- | --- |
| `name`, `title`, `tier`, `category`, `description` | スラッグ（スタイルシートのファイル名）、表示名、`component` または `layout`、所属グループ、概要を示す一文 |
| `use` | 使う場面 |
| `instead` | 別の場面に適した関連コンポーネント。各項目では、使う場面を `when` に、別のコントラクトの名前を `use` に記述 |
| `composes` | マークアップでクラスを使用する別のコントラクト。たとえばコンボボックスの場合は `input` と `listbox`。対応するスタイルシートもインポートが必要 |
| `script` | `none`、`optional`、または `required` |
| `behavior` | パターンを動かす参照実装スクリプト |
| `keyboard` | ネイティブのキーボード操作、またはビヘイビアを適用した後のキーボード操作 |
| `platform` | 機能強化に使う各プラットフォーム機能と、その機能に未対応のブラウザーでの表示 |
| `classes` | スタイルシートが定義するクラスのみをすべて列挙 |
| `states` | スタイルシートが表示する各状態と、それを示す属性または疑似クラス |
| `properties` | 公開カスタムプロパティ |
| `example` | 最小限の正しいマークアップ |

`name`、`title`、`tier`、`category`、`description`、`use`、`script`、`classes`、`example` は必須です。スキーマで使用できるキーは、この表にあるものと `$schema` に限られます。

## クラス \{#classes\}

各クラスには `name`、`kind`、`description` があります。クラスを付けられる場所は、その種別で決まります。

<GuideFigure name="contracts" title="ルート、修飾子、パーツ">

**修飾子は同じ要素に、パーツはその内側に配置します。** ルート `dialog` と修飾子 `dialog-drawer` は同じダイアログ要素に付けます。パーツ `dialog-title` は、その子要素である見出しに付けます。修飾子を別の要素に付けると、この関係を満たせません。

</GuideFigure>

| 種別 | 配置先 | 例 |
| --- | --- | --- |
| `root` | 単独で配置。1つのスタイルシートに複数定義可能 | `btn`, `btn-group`, `dialog` |
| `part` | `of` で指定するルートの内側 | `dialog` の `dialog-title` |
| `modifier` | `of` で指定する基底クラスと同じ要素 | `btn` の `btn-primary` |

パーツの修飾子は、対象のパーツを指定します。`menu-item-danger` では `of` に `menu-item` を指定します。複数の候補のいずれかと組み合わせられる場合、`of` はリストになります。以下はボタンの `classes` にある3つの項目です。

```json name=button.json
{ "name": "btn", "kind": "root", "description": "The raised base button", "elements": ["button", "a", "summary", "label", "input"] },
{ "name": "btn-sm", "kind": "modifier", "of": "btn", "exclusive": "size", "description": "32px tall; the default is 38px" },
{ "name": "btn-square", "kind": "modifier", "of": "btn", "label": true, "description": "A square button for one icon; it needs an accessible name" }
```

## チェッカーが検証するルール \{#constraints\}

クラスの種別から、修飾子には基底クラス、パーツにはルートが必要という2つのルールが決まります。クラスに指定できる4つの任意キーを使うと、ドキュメント上のルールに違反したときに `master-ui check` が報告します。誤った制約は利用側のプロジェクトで誤検出を招くため、スタイルシートやプラットフォームが求める場合に限って指定します。

| キー | 意味 | 例 |
| --- | --- | --- |
| `elements` | クラスが機能する要素をこの一覧に限定。どの要素でも使える場合は省略 | `["dialog"]` で指定した要素に付ける `dialog` |
| `attributes` | 要素に必須の属性。値を問わない場合は `true`、特定の値は文字列、候補のいずれかを許す場合は配列で指定 | `switch`: `{ "type": "checkbox", "role": "switch" }` |
| `label` | 要素にアクセシブルな名前が必要 | `btn-square`, `dialog-close` |
| `exclusive` | グループキー。同じキーを持つ修飾子は同じ要素に併用不可 | `btn-sm` と `btn-lg` はどちらも `"size"` |

5つ目のキーは制約を緩めます。`"anywhere": true` は、パーツをルートの外側にも配置できることを示します。たとえば、`field-hint` は `field` のパーツで、そのルートの外側にも配置できます。

## 状態とプロパティ \{#states-and-properties\}

状態の見た目はスタイルシートが決め、マークアップではネイティブ属性またはARIA属性で示します。状態専用のクラスは使いません。各項目には、状態を示す要素に付くクラスを `on` に、`name` に短い名前を、`mark` にマークアップまたはCSSでの表記をそのまま記述します。

```json name=button.json
{ "on": "btn", "name": "pressed", "mark": "aria-pressed=\"true\"", "description": "A quiet toggle that is on stays sunk into a well" }
```

`:user-invalid` や `:popover-open` のようにコロンで始まるものは、ブラウザーが適用する疑似クラスです。マークアップへの記述は不要です。

`properties` には、プロジェクトが設定できる公開APIとしてのカスタムプロパティを列挙します。各項目には `name` と `description` を記述します。そのプロパティを宣言または参照するクラスが最初のルートと異なる場合は `on` にそのクラスを記述し、スタイルシートに既定値の宣言があれば `default` に記述します。

```json name=button.json
{ "name": "--btn-height", "default": "2.375rem", "description": "Minimum block size" }
```

この一覧にないコンポーネント固有のカスタムプロパティは、内部実装の一部です。テーマトークンはコンポーネント間で共有する別の公開APIです。各トークンの役割は[既定のテーマ](/guide/theme)を参照してください。テーマトークンとコンポーネントプロパティの使い分けは[カスタマイズ](/guide/customization#property)、現在のバージョン方針は[安定性](/guide/stability)で確認できます。

## スクリプトとビヘイビア \{#script\}

`script` は、コンポーネントがJavaScriptにどの程度依存するかを示します。

| 値 | 意味 |
| --- | --- |
| `none` | すべての状態がスクリプトなしで機能 |
| `optional` | スクリプトはメニューの矢印キー操作などの補助機能を追加。ページはスクリプトなしでも動作 |
| `required` | パターンに対応するネイティブ要素がないため、スクリプトで属性を更新 |

`behavior` は、`@master/ui/behaviors/<behavior>.js` として公開されている参照実装スクリプトを指定します。コンボボックスのコントラクトには `"script": "required"` と `"behavior": "combobox"` が記述されています。

```js
import { combobox } from '@master/ui/behaviors/combobox.js'

combobox(document.querySelector('.combobox'))
```

ビヘイビアは、スタイルシートが参照する属性を更新します。スプリッターなどのパターンでは、イベントから得た値も公開カスタムプロパティを通じて渡し、スタイルシートが表示方法を決めます。`keyboard` には、ビヘイビアを適用した後のキー操作、またはネイティブ要素が備えるキー操作を列挙します。[ビヘイビア](/guide/behaviors)を参照してください。

## マークアップ例 \{#example\}

`example` は、実際の文言を含む最小限の正しいマークアップです。パッケージのテストでは、すべての例をチェッカーで検証し、診断が出ないことを確認します。このマークアップを土台に、ページに合わせてラベル、一意のID、アプリケーション固有の処理、必要なビヘイビアを追加してください。

```html
<button type="button" class="btn btn-primary">Save changes</button>
```

## 独自コンポーネントのコントラクトを書く \{#your-own\}

ライブラリーにないUIが必要で、その構成要素が質感、状態、プラットフォームのビヘイビア、形状のいずれかを共有する場合は、プロジェクトに独自コンポーネントを追加します。`@layer components` にクラスセレクターとトークンを使ってスタイルシートを書き、コントラクトはスタイルシートと同じ `ui/` ディレクトリーに記述します。コントラクトはライブラリーと同じスキーマに従います。

```css name=ui/price-tag.css
@layer components {
  .price-tag {
    --price-tag-size: 1.125rem;
    display: inline-flex;
    align-items: baseline;
    gap: .375rem;
    color: var(--color-text-strong);
    font-size: var(--price-tag-size);
    font-variant-numeric: tabular-nums;

    &.price-tag-sale {
      color: var(--color-danger);
    }
  }

  .price-tag-was {
    color: var(--color-text-muted);
    font-size: .75em;
  }
}
```

```json name=ui/price-tag.json
{
  "$schema": "https://ui.master.co/contract.schema.json",
  "name": "price-tag",
  "title": "Price tag",
  "tier": "component",
  "category": "Commerce",
  "description": "The price of one product, with the price it replaces.",
  "use": "A price on a product card or in a cart row. Add price-tag-sale and the old price when the product is reduced.",
  "script": "none",
  "classes": [
    { "name": "price-tag", "kind": "root", "description": "The current price, in strong ink and tabular figures" },
    { "name": "price-tag-sale", "kind": "modifier", "of": "price-tag", "description": "A reduced price, in the danger hue" },
    { "name": "price-tag-was", "kind": "part", "of": "price-tag", "elements": ["s"], "description": "The price before the reduction, struck through in muted ink" }
  ],
  "properties": [
    { "name": "--price-tag-size", "default": "1.125rem", "description": "Font size of the current price" }
  ],
  "example": "<p class=\"price-tag price-tag-sale\">$24 <s class=\"price-tag-was\">$32</s></p>"
}
```

例にスタイルが適用されるよう、アプリケーションのスタイルシートでMaster UIの後に `ui/price-tag.css` をインポートします。CLIは、このCSSのインポートとは独立して、スタイルシートと同じ場所にあるコントラクトを検出します。

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import './ui/price-tag.css';
```

これで、プロジェクト独自のコンポーネントも同じツールから扱えます。

- `npx master-ui list` で一覧に表示し、`npx master-ui contract price-tag` でコントラクトを出力できます。マークアップを書く前にコントラクトを読むエージェントも、同じ方法で見つけられます。
- `npx master-ui check` は、マークアップがそのコントラクトに従っているかを検証します。この例では、`npx master-ui check cart.html` が3件の誤りを報告します。

```html name=cart.html
<p class="price-tag-sale">$24</p>
<p class="price-tag">$24 <span class="price-tag-was">$32</span></p>
<p class="price-tag price-tag-large">$24</p>
```

```
cart.html:1:1 error missing-base "price-tag-sale" modifies "price-tag": write class="price-tag price-tag-sale".
cart.html:2:26 error element "price-tag-was" goes on <s>, not <span>.
cart.html:3:1 warning unknown-class "price-tag-large" is not a class of price-tag. It has: price-tag, price-tag-sale, price-tag-was.

1 files checked: 2 errors, 1 warnings.
```

コントラクトを記述する際の補足は3点あります。

- **コントラクトの読み込み元。** プロジェクトの `ui/` ディレクトリーにある `.json` ファイルのうち、`name` と `classes` 配列を持つものをすべて読み込みます。`master-ui.json` では、別のディレクトリーを `directory` に、追加のパターンを `contracts` 配列に指定できます。
- **スキーマの指定。** `"$schema": "https://ui.master.co/contract.schema.json"` を記述すると、編集中にエディターでファイルを検証できます。
- **ライブラリーと同じ名前。** プロジェクトのコントラクトにライブラリーのコントラクトと同じ名前を付けると、プロジェクト側の定義が優先されます。[ソースを自分で管理するコンポーネント](/guide/customization#own-a-component)は、この仕組みでコピー先のコントラクトを使って定義します。

## 診断 \{#diagnostics\}

`master-ui check` は、検出項目ごとにファイル、行、列、重大度、コード、メッセージを1行で出力します。`unknown-class` は `--strict` を指定しない限り警告で、それ以外のコードはすべてエラーです。

| コード | 意味 | 修正方法 |
| --- | --- | --- |
| `unknown-class` | クラス名がルートクラス名とハイフンで始まるが、どのコントラクトにも定義されていない | メッセージに示されたクラスのいずれかを使います。プロジェクト独自のクラスなら、`ui/` 内のコントラクトに追加するか、コンポーネントの命名範囲外の名前を付けます。 |
| `missing-base` | 修飾子が、修飾対象のクラスを持たない要素に付いている | 同じ要素に基底クラスも付けます。たとえば `class="btn btn-primary"` のように指定します。 |
| `outside-root` | パーツの祖先要素に対応するルートクラスがない | パーツをルートの内側に移動するか、コンテナーにルートクラスを追加します。 |
| `exclusive` | サイズ指定が二つあるなど、同じグループの修飾子が一つの要素に二つ付いている | どちらか一方だけを残します。 |
| `element` | コントラクトで許可されていない要素にクラスが付いている | メッセージが示す要素を使います。たとえば `dialog` はダイアログ要素に付けます。 |
| `attribute` | クラスが要求する属性がない、または属性値が異なる | `role="switch"` など、メッセージで示された属性を指定します。 |
| `label` | コントロールにアクセシブルな名前がない | コントロール自体のテキスト、`aria-label`、`aria-labelledby`、またはコントロールを囲むか参照するラベルで名前を付けます。 |

チェッカーはページをレンダリングせず、ソースを読み取ります。式の中にリテラルとして書かれたクラスは検査できますが、計算で決まるクラス名の解決、フレームワークのコンポーネントが子要素を描画する位置の特定、別ファイルにあるルートの検査はできません。確定できないケースは報告しません。フォーカス順、コントラスト、ブラウザーの対応状況、選んだコンポーネントが用途に合うかどうかは、診断がなくても別途確認が必要です。
