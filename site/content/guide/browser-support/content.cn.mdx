按应用实际使用的组件，确认目标浏览器支持哪些功能。Master UI 使用现代 CSS 实现基础外观，并借助原生元素实现交互行为。增强功能可改善定位、动效或控件体验。浏览器可能会自动采用回退方案，也可能需要应用提供处理程序。

先查看下方的基础要求，再查看所用组件对应的增强功能。CI 使用锁定版本的 Playwright 随附的 Chromium、Firefox 和 WebKit 运行框架测试场景，覆盖文档所述的调用命令、兴趣触发器（interest invokers）和锚点定位回退方案。表格列出功能要求。各浏览器发行版本的实际表现需逐一验证。请在支持的每种浏览器中[检查功能支持和实际效果](#checking-a-feature)。

## 基础要求 \{#baseline\}

在下列用途中，组件库直接使用这些功能，未提供回退方案。层叠层、嵌套和颜色函数广泛影响整个库。`subgrid` 或 `<dialog>` 等功能只影响使用它们的组件。

| 功能 | 用途 |
| --- | --- |
| 自定义属性 | 所有令牌及契约公开的所有属性 |
| 层叠层（`@layer`） | 所有组件和布局规则都位于 `components` 层，令牌位于 `theme` 层。工具类凭借层叠顺序覆盖组件样式，无需使用 `!important` |
| CSS 嵌套 | 规则采用嵌套写法，编译后的样式表也保留嵌套 |
| `light-dark()` | 随配色方案变化的主题颜色 |
| `oklch()` | 颜色令牌的值 |
| `color-mix()` | 淡色调、着色按钮、玻璃材质和墨色表面上的行内标签 |
| `:has()` | 父元素读取子元素状态的场景，包括[输入组](/components/input)、字段、[分段控件](/components/segmented)、[评分](/components/rating)、[步骤](/components/steps)以及[列表框](/components/listbox)的空状态 |
| 容器尺寸查询（`@container`） | [卡片](/components/card)、[对话框](/components/dialog)、[数据列表](/components/data-list)、[导航栏](/components/navbar)以及[表单](/components/form)、[Bento 布局](/components/bento)和[应用外壳](/pages/app-shell)布局 |
| `subgrid` | [日历](/components/calendar)、[图表](/components/chart)、[数据列表](/components/data-list) |
| 独立变换属性（`translate`、`scale`） | 控件抬升时的状态和浮层的入场效果 |
| `:focus-visible` | 控件的键盘焦点环 |
| `:dir()` | 在从右向左的文本中反转方向的部分，例如抽屉、面包屑分隔符和日历日期范围 |
| 逻辑属性和 `inset` | 随文本方向调整的间距和定位 |
| 动态视口单位（`dvh`） | [对话框](/components/dialog)和[命令面板](/components/command)的高度上限。`page` 和 `shell` 布局先声明一个 `vh` 值 |
| `popover` 属性 | [弹出层](/components/popover)、[菜单](/components/menu)、[工具提示](/components/tooltip)和[组合框](/components/combobox)的列表 |
| `<dialog>` | [对话框](/components/dialog)、[命令面板](/components/command)、[轻提示](/components/toast)、可关闭的[横幅](/components/banner) |

浏览器不支持的语法可能使声明、选择器或整条规则失效。缺少层叠层或嵌套支持会影响样式表中的大量规则。缺少颜色函数支持可能导致引用这些颜色的声明得不到可用值。增强功能的回退方案无法弥补基础功能的缺失。

## 增强功能 \{#enhancements\}

以下功能通过两种方式按浏览器支持情况启用。大多数功能放在 `@supports` 规则中，例如 `@supports (anchor-scope: --segmented-thumb)` 或 `@supports selector(::scroll-marker)`，并写在实现回退效果的规则之后。其余功能通过单条声明、一个 at 规则或一个属性启用，例如 `interpolate-size`、`@starting-style` 或 `closedby`。缺少相应支持的浏览器会忽略它们。

最后一列说明回退方案或集成时需要完成的工作。每份[契约](/guide/contracts)中的 `platform` 列表记录对应组件的具体行为。尤其是仅通过 `commandfor` 触发的对话框，在缺少调用命令支持的浏览器中，需要提供下文所述的处理程序才能打开。

<GuideFigure name="browser-support" title="基础定位与增强定位">

**增强功能在可用的基础方案之上改变呈现效果。** 浏览器原生支持弹出层时，两种情况下同一个表面都能打开和关闭。CSS 锚点定位将它放在触发控件旁边。缺少这项增强功能时，普通弹出层仍居中显示在视口内。两个视口示意图只展示位置的变化。两种方案都未为不支持弹出层的浏览器提供回退方案。

</GuideFigure>

### 浮层与定位 \{#overlays-and-placement\}

| 功能 | 使用该功能的组件 | 缺少该功能时 |
| --- | --- | --- |
| 调用命令：`command` 和 `commandfor` | [对话框](/components/dialog)、[命令面板](/components/command) | 在点击事件处理函数中调用 `showModal()` 和 `close()`，沿用同一份样式表 |
| `closedby="any"` | [对话框](/components/dialog)、[命令面板](/components/command) | 点击遮罩没有反应，按 Escape 或点击关闭按钮仍可关闭 |
| 兴趣触发：`popover="hint"` 配合 `interestfor` | [工具提示](/components/tooltip)、用作预览的[弹出层](/components/popover) | 工具提示或预览不会显示，控件保留无障碍名称，仍可作为链接或按钮使用 |
| CSS 锚点定位：`position-area`、`position-try-fallbacks` | [弹出层](/components/popover)、[菜单](/components/menu)、[工具提示](/components/tooltip)、带有 `popover` 属性的[列表框](/components/listbox) | 表面照常打开和关闭，并按浏览器对弹出层的默认定位居中显示在视口内 |
| `anchor-scope` 和 `anchor-size()` | [组合框](/components/combobox) | 列表留在文档流中，紧接在字段下方，使用自身宽度 |
| `anchor-scope` 配合 `anchor()`，让同一个指示标记在选项之间移动 | [分段控件](/components/segmented)、[标签页](/components/tabs)、[目录](/components/toc) | 每个选项成为当前选项时都会显示自己的标记，标记即时切换，无滑动动画 |
| `anchor-scope` 配合 `anchor()`，让分隔线从文字起始处开始 | [列表](/components/list) | 行下方的细线横跨整行 |
| `@position-try` | [上下文菜单](/components/menu) | 菜单从指针位置向下、朝行内末端展开，触及视口边缘时也不翻转 |
| `@starting-style` 和 `transition-behavior: allow-discrete` | [对话框](/components/dialog)、[弹出层](/components/popover)、[菜单](/components/menu)、[工具提示](/components/tooltip)、[轻提示](/components/toast)、[图表](/components/chart) | 浮层即时显示和隐藏，无淡入淡出效果。图表的柱条直接以完整高度显示 |

### 表单字段 \{#fields\}

| 功能 | 使用该功能的组件 | 缺少该功能时 |
| --- | --- | --- |
| `appearance: base-select` | [下拉选择框](/components/select) | 选择框保留凹槽样式和折线箭头，并打开平台原生的选项列表。`select-option` 不生效 |
| `field-sizing: content` | [输入框](/components/input)、[编辑器](/components/composer)和[步进器](/components/stepper)中使用 `input-auto` 的 textarea | textarea 保留最小高度和尺寸调整手柄，编辑器保持三行高度并可滚动，步进器保留 `--stepper-min` 的宽度 |
| `:user-invalid` | [输入框](/components/input) | 原生约束仍会验证字段。此自定义错误样式由 `aria-invalid="true"` 触发，原生约束不会触发该样式 |
| 原生字段的组成部分：`::-webkit-calendar-picker-indicator`、`::-webkit-inner-spin-button`、`::-webkit-search-cancel-button` | [输入框](/components/input) | 日期、时间、数字和搜索字段保留浏览器自带的控件图标 |
| 原生 `<meter>` 的组成部分 | [度量条](/components/meter) | 浏览器保留原生度量条，以自己的样式显示相同的数值和三种色调 |

### 滚动 \{#scrolling\}

| 功能 | 使用位置 | 不支持时 |
| --- | --- | --- |

| 滚动驱动动画：`view-timeline` 和 `timeline-scope` | [滑块](/components/slider)、[范围滑块](/components/range)、[对比](/components/compare) | 滑块和范围滑块的轨道仍呈现为简单的凹槽，拖动手柄仍指示相应的值；[对比行为](/guide/behaviors)将输入控件的值复制到 `--compare-position` |

| 功能 | 使用位置 | 不支持时 |
| --- | --- | --- |

## 检查功能支持情况 \{#checking-a-feature\}

使用功能的准确名称查找最新的兼容性信息。对于 CSS，还可以用样式表中的同一条件查询当前浏览器：

```js
CSS.supports('(anchor-scope: --mark)')
CSS.supports('(appearance: base-select)')
CSS.supports('selector(::scroll-marker)')
```

[`CSS.supports()`](https://drafts.csswg.org/css-conditional-3/#dom-css-supports)用于判断指定的 CSS 支持条件是否成立。返回肯定结果时，可据此选择 CSS 分支。渲染和交互仍需单独测试，`commandfor` 等 HTML 属性也需另行检查。

检查功能支持情况后，在目标浏览器中验证组件：

1. 通过应用提供的操作路径打开、关闭、选择或编辑。对于浮层，还要验证键盘操作和关闭后的焦点恢复。
2. 检查靠近视口边缘时的位置、窄幅布局和可滚动内容。
3. 检查准备随产品交付的回退方案。缺少动画可能可以接受，但必须有打开操作的处理程序，必要说明也必须在工具提示不可用时仍然可见。

将必要说明放在可见文本中。只有控件本身已有名称且用途明确时，省略工具提示才是可用的回退方案。

## 偏好设置与设备 \{#preferences-and-devices\}

支持范围还包括读者的设备和设置。组件有可调整之处时，其样式表也会响应相应的查询。

| 查询 | 变化 |
| --- | --- |
| `(hover: hover)` | 悬停状态定义在此条件内，仅在指针支持悬停时生效。触摸后，控件不会停留在悬停状态。 |
| `(pointer: coarse)` | 交互目标扩大到 44px。按钮的最小高度增至 `2.75rem`。复选框标签的点击区域围绕文字所在行扩大，周围元素保持原位。 |
| `(prefers-reduced-motion: reduce)` | 移除控件上浮、浮层缩放和滑动、指示器滑移等动效。保留淡入淡出，状态变化依然可见。 |
| `(forced-colors: active)` | 浏览器移除阴影并替换颜色，因此边缘和状态改用 `ButtonText`、`CanvasText` 和 `Highlight` 等系统颜色绘制轮廓和填充。 |
| `(prefers-contrast: more)` | 主题增强细线、分隔线和轮廓令牌，以及弱化和禁用状态的墨色。使用这些令牌的组件随之调整。 |
| `(prefers-reduced-transparency: reduce)` | [导航栏](/components/navbar)和[标签栏](/components/tabbar)的玻璃材质改为无模糊效果的实色表面。 |

主题配色中随方案变化的颜色使用 `light-dark()`，并遵循页面或子树的 `color-scheme`。参见[默认主题](/guide/theme#color-schemes)。

## 独立样式表 \{#standalone\}

`@master/ui/standalone.css` 由同一份源码编译为纯 CSS，适用于未使用 Master CSS 的项目。参见[安装](/guide/installation#without-master-css)，了解如何引入。

```css name=app.css
@import '@master/ui/standalone.css';
```

编译会展开混入，并将令牌写为自定义属性。编译保留 CSS 特性：文件声明相同的层，保留嵌套、`light-dark()` 和 `oklch()`，以及相同的 `@supports` 规则。浏览器要求和回退方案均以本页为准。`@master/ui/dist/themes/paper.css` 等编译后的主题也遵循这些规则。

编译后的文件还声明 `color-scheme: light dark`，并支持 `data-theme="light"` 和 `data-theme="dark"`。如果后续构建工具还会转换该文件，请测试应用实际提供的 CSS。
