請確認你的應用程式所使用的元件在瀏覽器中的支援情況。Master UI 以現代 CSS 建立基準外觀，並以原生元素提供行為。其他功能可改善定位、動態效果或控制項；它們的備援方式可能是自動的，也可能需要你的應用程式提供處理函式。

請先閱讀下方的基準，再閱讀與你的元件相關的強化功能列。CI 會在固定版本的 Playwright 相依套件所附帶的 Chromium、Firefox 與 WebKit 版本中執行各框架情境，包括 invoker commands、interest invokers 與錨點定位的文件化備援方式。這些表格描述的是功能需求，並不保證適用於每個已發布的瀏覽器版本。請在你支援的每個瀏覽器中[檢查功能與結果](#checking-a-feature)。

## 基準需求 \{#baseline\}

下列功能在所列位置使用時，元件庫不提供備援方式。串接層、巢狀與色彩函式會廣泛影響整個元件庫；`subgrid` 或 `<dialog>` 這類功能則只在元件使用它們的地方才有影響。

| 功能 | 使用位置 |
| --- | --- |
| 自訂屬性 | 每個 token，以及契約公開的每個屬性 |
| 串接層（`@layer`） | 每條元件與版面規則都位於 `components` 層，token 則位於 `theme`。這讓 utility 不需要 `!important` 就能勝過元件 |
| CSS 巢狀 | 規則以巢狀方式撰寫，編譯後的樣式表也保留巢狀 |
| `light-dark()` | 隨色彩配置改變的主題色彩 |
| `oklch()` | 色彩 token 的值 |
| `color-mix()` | 色調、帶色相的按鈕、玻璃材質、墨色表面上的行內 chip |
| `:has()` | 讀取子元素狀態的父元素：[輸入群組](/components/input)、欄位、[分段控制](/components/segmented)、[評分](/components/rating)、[步驟](/components/steps)、[listbox](/components/listbox) 的空狀態 |
| 容器尺寸查詢（`@container`） | [卡片](/components/card)、[對話框](/components/dialog)、[資料清單](/components/data-list)、[導覽列](/components/navbar)，以及 [form](/components/form)、[bento](/components/bento) 與 [shell](/pages/app-shell) 版面 |
| `subgrid` | [日曆](/components/calendar)、[圖表](/components/chart)、[資料清單](/components/data-list) |
| 個別的變形屬性（`translate`、`scale`） | 控制項的浮起狀態與覆蓋層的進場 |
| `:focus-visible` | 控制項上的鍵盤焦點環 |
| `:dir()` | 在由右至左的文字中會反轉的部件，例如抽屜、麵包屑分隔符號與日曆範圍 |
| 邏輯屬性與 `inset` | 依循文字方向的間距與定位 |
| 動態檢視區單位（`dvh`） | [對話框](/components/dialog)與[命令面板](/components/command)的高度上限。`page` 與 `shell` 版面會先寫入 `vh` 值 |
| `popover` 屬性 | [Popover](/components/popover)、[選單](/components/menu)、[工具提示](/components/tooltip)、[combobox](/components/combobox) 的清單 |
| `<dialog>` | [對話框](/components/dialog)、[命令面板](/components/command)、[toast](/components/toast)、可關閉的[橫幅](/components/banner) |

不支援的語法可能使一條宣告、一個選擇器或整條規則失效。失去串接層或巢狀支援會影響樣式表的大部分內容；失去某個色彩函式，則可能讓使用這些色彩的宣告沒有可用的值。強化功能的備援方式無法彌補缺少的基準功能。

## 強化功能 \{#enhancements\}

下列每項功能都以兩種方式之一加以控管。大多數位於 `@supports` 規則內，例如 `@supports (anchor-scope: --segmented-thumb)` 或 `@supports selector(::scroll-marker)`，並寫在繪製備援方式的規則之後。其餘則是不支援該功能的瀏覽器會忽略的單一宣告、at-rule 或屬性，例如 `interpolate-size`、`@starting-style` 或 `closedby`。

最後一欄說明備援方式或需要的整合工作。每份[契約](/guide/contracts)中的 `platform` 清單記錄了各元件特有的行為。特別注意，只有 `commandfor` 的對話框，在不支援 invoker commands 的瀏覽器中不會開啟，直到你提供下文所述的處理函式為止。

<GuideFigure name="browser-support" title="基準定位與強化定位">

**強化功能是在可運作的基準之上改變結果。** 在原生支援 popover 的情況下，同一個表面在兩種情況中都會開啟與關閉。CSS 錨點定位會將它放在觸發元素旁；沒有這項強化功能時，一般的 popover 仍會置中於檢視區。兩個示意檢視區只有定位不同。兩個分支都不會為不支援 popover 的瀏覽器提供備援方式。

</GuideFigure>

### 覆蓋層與定位 \{#overlays-and-placement\}

| 功能 | 使用的元件 | 不支援時 |
| --- | --- | --- |
| Invoker commands：`command` 與 `commandfor` | [對話框](/components/dialog)、[命令面板](/components/command) | 從點擊處理函式呼叫 `showModal()` 與 `close()`；樣式表相同 |
| `closedby="any"` | [對話框](/components/dialog)、[命令面板](/components/command) | 點擊遮罩不會有任何作用；Escape 與關閉按鈕仍可關閉它 |
| Interest invokers：搭配 `interestfor` 的 `popover="hint"` | [工具提示](/components/tooltip)、作為預覽使用的 [popover](/components/popover) | 工具提示或預覽不會出現；控制項保留其無障礙名稱，仍可作為連結或按鈕運作 |
| CSS 錨點定位：`position-area`、`position-try-fallbacks` | [Popover](/components/popover)、[選單](/components/menu)、[工具提示](/components/tooltip)、帶有 `popover` 屬性的 [listbox](/components/listbox) | 表面的開啟與關閉方式相同；它會置中顯示於檢視區，也就是瀏覽器放置任何 popover 的位置 |
| `anchor-scope` 與 `anchor-size()` | [Combobox](/components/combobox) | 清單位於文件流中，緊接在欄位下方，並使用自己的寬度 |
| `anchor-scope` 搭配 `anchor()`，用於一個會移動的指示器 | [分段控制](/components/segmented)、[分頁](/components/tabs)、[目錄](/components/toc) | 每個目前選項各自繪製指示標示，它會立即切換而不會滑動 |
| `anchor-scope` 搭配 `anchor()`，用於從文字處開始的分隔線 | [清單](/components/list) | 列下方的細線橫跨整列 |
| `@position-try` | [右鍵選單](/components/menu) | 它會在指標的下方與結尾方向開啟，到達檢視區邊緣時不會反轉 |
| `@starting-style` 與 `transition-behavior: allow-discrete` | [對話框](/components/dialog)、[popover](/components/popover)、[選單](/components/menu)、[工具提示](/components/tooltip)、[toast](/components/toast)、[圖表](/components/chart) | 覆蓋層會立即出現與離開，沒有淡入淡出；圖表的長條會直接以完整高度出現 |

### 欄位 \{#fields\}

| 功能 | 使用的元件 | 不支援時 |
| --- | --- | --- |
| `appearance: base-select` | [Select](/components/select) | select 保留其凹槽與箭頭，並開啟平台本身的選項清單；`select-option` 沒有作用 |
| `field-sizing: content` | [input](/components/input)、[composer](/components/composer)、[stepper](/components/stepper) 中的 `input-auto` textarea | textarea 保留其最小高度與調整大小的控制點；composer 維持三行並可捲動；stepper 維持 `--stepper-min` 的寬度 |
| `:user-invalid` | [Input](/components/input) | 原生限制仍會驗證欄位，但不會觸發這個自訂的錯誤外觀；`aria-invalid="true"` 仍會觸發 |
| 原生欄位的部件：`::-webkit-calendar-picker-indicator`、`::-webkit-inner-spin-button`、`::-webkit-search-cancel-button` | [Input](/components/input) | 瀏覽器在日期、時間、數字與搜尋欄位中保留自己的圖示 |
| 原生 `<meter>` 的部件 | [Meter](/components/meter) | 瀏覽器保留自己的量表，以自己的樣式呈現相同的值與相同的三種色調 |

### 展開收合 \{#disclosure\}

| 功能 | 使用的元件 | 不支援時 |
| --- | --- | --- |
| `interpolate-size`，搭配 `<details>` 上的 `::details-content` | [Accordion](/components/accordion)、[nav](/components/nav)、[expand](/components/expand)、[橫幅](/components/banner) | 面板或群組會立即開啟與關閉；關閉的橫幅會立即離開 |

### 捲動 \{#scrolling\}

| 功能 | 使用的元件 | 不支援時 |
| --- | --- | --- |
| 捲動驅動動畫：`animation-timeline: scroll()` | [捲動區域](/components/scroll-area)、[導覽列](/components/navbar)中的 `navbar-progress` | 區域的捲動方式相同，邊緣保持乾淨而沒有淡出效果；進度線不會繪製 |
| 捲動驅動動畫：`view-timeline` 與 `timeline-scope` | [Slider](/components/slider)、[range](/components/range)、[compare](/components/compare) | slider 或 range 的軌道維持一般凹槽，滑塊仍會顯示值；[compare 行為](/guide/behaviors)會將輸入的值複製到 `--compare-position` |
| 捲動驅動動畫：`animation-timeline: view()` | [Wheel](/components/wheel) | 選項以平面方式繪製，標示為 `aria-selected="true"` 的選項使用強調墨色 |
| `::scroll-button()` 與 `::scroll-marker` | [輪播](/components/carousel) | 沒有按鈕也沒有圓點：輪播是一列可滑動、捲動並吸附的內容 |
| 捲動狀態容器查詢：`container-type: scroll-state` | [導覽列](/components/navbar) | 導覽列的底板一律繪製，在頁面頂端也一樣 |
| `scroll-target-group` 與 `:target-current` | [目錄](/components/toc) | 在腳本或伺服器為連結設定 `aria-current` 之前，不會有任何連結被標示 |

### 版面 \{#layout\}

| 功能 | 使用的元件 | 不支援時 |
| --- | --- | --- |
| Grid lanes：`display: grid-lanes` | [Masonry](/components/masonry) | 由多欄方塊排列相同的圖塊；圖塊會沿每一欄往下填滿，而不是橫跨各通道 |
| `sibling-index()` | [Sticky stack](/components/sticky-stack) | 每個面板都黏在同一條線上，並完全覆蓋前一個面板，因此不會露出任何邊緣 |
| 容器查詢單位（`cqi`） | [Breakout](/components/breakout) | 寬版或滿版的子元素會留在閱讀欄內 |

| 功能 | 使用的元件 | 不支援時 |

## 檢查功能 \{#checking-a-feature\}

請使用確切的功能名稱查詢其目前的相容性資訊。對於 CSS，你也可以用樣式表所測試的相同條件，直接詢問眼前的瀏覽器：

```js
CSS.supports('(anchor-scope: --mark)')
CSS.supports('(appearance: base-select)')
CSS.supports('selector(::scroll-marker)')
```

[`CSS.supports()`](https://drafts.csswg.org/css-conditional-3/#dom-css-supports) 會評估 CSS 支援條件。正面的結果有助於選擇 CSS 分支，但它並不是渲染或互動測試。它也不會測試 `commandfor` 這類 HTML 屬性。

檢查功能之後，請在目標瀏覽器中驗證元件：

1. 透過你的應用程式提供的途徑開啟、關閉、選取或編輯它。對於覆蓋層，請包含鍵盤操作與焦點返回。
2. 檢查靠近檢視區邊緣時的定位、窄版版面，以及會捲動的內容。
3. 檢查你打算上線的備援方式。缺少動畫或許可以接受；缺少開啟用的處理函式，或將必要說明藏在無法顯示的工具提示中，則無法接受。

請將必要說明保留在可見的文字中。只有在底層控制項已具備名稱與用途時，省略工具提示才算是可用的備援方式。

## 偏好設定與裝置 \{#preferences-and-devices\}

支援不只關乎功能。凡是元件有需要改變之處，每份樣式表也會回應描述讀者裝置與設定的查詢。

| 查詢 | 改變的內容 |
| --- | --- |
| `(hover: hover)` | 懸停狀態寫在其中，因此只在指標可以懸停的地方套用。觸控不會讓控制項停留在懸停外觀 |
| `(pointer: coarse)` | 目標放大到 44px。按鈕的最小高度變為 `2.75rem`；核取方塊的標籤會在其所在行周圍擴大，而不移動旁邊的內容 |
| `(prefers-reduced-motion: reduce)` | 移除位移：控制項的浮起、覆蓋層的縮放與滑動、指示器的滑行。淡入淡出會保留，因此仍看得到變化 |
| `(forced-colors: active)` | 瀏覽器會移除陰影並替換色彩，因此邊緣與狀態會改以 `ButtonText`、`CanvasText` 與 `Highlight` 等系統色彩的外框與填色重新繪製 |
| `(prefers-contrast: more)` | 主題會加強其細線、分隔線與輪廓 token，以及弱化與停用狀態的墨色。讀取這些 token 的元件會跟著改變 |
| `(prefers-reduced-transparency: reduce)` | [導覽列](/components/navbar)與[分頁列](/components/tabbar)的玻璃材質會變成不透明表面，沒有模糊效果 |

在不同色彩配置間有差異的主題色彩會使用 `light-dark()`，並依循頁面或子樹的 `color-scheme`；請參閱[預設主題](/guide/theme#color-schemes)。

## 獨立樣式表 \{#standalone\}

`@master/ui/standalone.css` 是將相同原始碼編譯成一般 CSS 的版本，供未使用 Master CSS 的專案使用。[安裝](/guide/installation#without-master-css)說明如何連結它。

```css name=app.css
@import '@master/ui/standalone.css';
```

編譯會解析 mixin，並將 token 寫成自訂屬性。它不會降級 CSS：檔案宣告相同的串接層，保留巢狀、`light-dark()` 與 `oklch()`，並帶有相同的 `@supports` 規則。它的需求與備援方式就是本頁所列的內容。編譯後的主題（例如 `@master/ui/dist/themes/paper.css`）也是如此。

編譯後的檔案也宣告了 `color-scheme: light dark`，並支援 `data-theme="light"` 與 `data-theme="dark"`。若有其他建置工具在這一步之後轉換它，請測試你的應用程式實際提供的 CSS。
