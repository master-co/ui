確認應用程式使用的元件在瀏覽器中的支援情況。Master UI 使用現代 CSS 呈現基本外觀，並透過原生元素提供行為。進階功能可改善定位、動態效果或控制項。缺少這些功能時，有些備援會自動生效，有些則需要應用程式提供事件處理函式。

先確認下列基本需求，再查看所用元件對應的進階功能。CI 會在固定版本的 Playwright 相依套件隨附的 Chromium、Firefox 和 WebKit 中測試各框架的使用情境，涵蓋文件所述的觸發指令、興趣觸發器和錨點定位備援。表格列出各項功能的需求，但不保證每個已發布的瀏覽器版本都能正常運作。請在每個支援的瀏覽器版本中[檢查功能與實際結果](#checking-a-feature)。

## 基本需求 \{#baseline\}

下列使用情境中，函式庫不提供備援。層疊圖層、巢狀規則和色彩函式的影響遍及整個函式庫。`subgrid` 或 `<dialog>` 等功能則只影響使用它們的元件。

| 功能 | 使用位置 |
| --- | --- |
| 自訂屬性 | 所有 token，以及契約公開的所有屬性 |
| 層疊圖層（`@layer`） | 所有元件與版面配置規則都在 `components` 圖層，token 則在 `theme` 圖層。這讓 utility 無須使用 `!important` 就能覆寫元件樣式 |
| CSS 巢狀規則 | 規則採巢狀寫法，編譯後的樣式表也保留巢狀結構 |
| `light-dark()` | 隨配色模式變換的主題色彩 |
| `oklch()` | 色彩 token 的值 |
| `color-mix()` | 淡色、色調按鈕、玻璃效果，以及深色背景上的行內標籤 |
| `:has()` | 父元素讀取子元素的狀態，例如[輸入群組](/components/input)、欄位、[分段控制項](/components/segmented)、[評分](/components/rating)、[步驟](/components/steps)，以及[清單方塊](/components/listbox)的空白狀態 |
| 容器尺寸查詢（`@container`） | [卡片](/components/card)、[對話框](/components/dialog)、[資料清單](/components/data-list)、[導覽列](/components/navbar)，以及[表單](/components/form)、[便當盒](/components/bento)和[應用程式外框](/pages/app-shell)版面配置 |
| `subgrid` | [行事曆](/components/calendar)、[圖表](/components/chart)、[資料清單](/components/data-list) |
| 獨立變形屬性（`translate`、`scale`） | 控制項的上抬狀態與覆疊元件的進場效果 |
| `:focus-visible` | 控制項的鍵盤焦點外框 |
| `:dir()` | 在由右至左的文字中反轉方向的部分，例如抽屜面板、麵包屑導覽分隔符號和行事曆日期範圍 |
| 邏輯屬性與 `inset` | 隨文字方向調整的間距與定位 |
| 動態檢視區單位（`dvh`） | [對話框](/components/dialog)和[指令面板](/components/command)的高度上限。`page` 和 `shell` 版面配置會先宣告 `vh` 值 |
| `popover` 屬性 | [彈出框](/components/popover)、[選單](/components/menu)、[工具提示](/components/tooltip)、[組合方塊](/components/combobox)的清單 |
| `<dialog>` | [對話框](/components/dialog)、[指令面板](/components/command)、[浮動通知](/components/toast)、可關閉的[橫幅](/components/banner) |

瀏覽器不支援的語法可能使宣告、選擇器或整條規則失效。缺少層疊圖層或巢狀規則支援會影響樣式表的大部分內容。缺少色彩函式支援時，引用這些色彩的宣告可能取不到可用的值。進階功能的備援仍有賴瀏覽器滿足基本需求。

## 進階功能 \{#enhancements\}

下列功能各採用兩種方式之一處理相容性。大多數放在 `@supports` 規則中，例如 `@supports (anchor-scope: --segmented-thumb)` 或 `@supports selector(::scroll-marker)`，並寫在呈現備援樣式的規則之後。其餘則各自使用一項宣告、一條 at 規則或一個屬性，例如 `interpolate-size`、`@starting-style` 或 `closedby`，瀏覽器若不支援便會忽略。

最後一欄說明備援行為或需要自行整合的部分。各[契約](/guide/contracts)的 `platform` 清單記錄該元件的具體行為。尤其要注意，若對話框只靠 `commandfor` 開啟，在不支援觸發指令的瀏覽器中，必須加入下文所述的事件處理函式才能開啟。

<GuideFigure name="browser-support" title="基本支援與進階定位">

**進階功能會在基本功能正常運作的前提下改變呈現結果。** 只要瀏覽器原生支援彈出框，兩種情況下都能開啟與關閉同一個面板。支援 CSS 錨點定位時，彈出框會出現在觸發控制項旁。缺少錨點定位時，一般彈出框仍會置中於檢視區。兩張檢視區示意圖的差異僅在位置。兩種情況都需要瀏覽器支援彈出框。

### 覆疊元件與定位 \{#overlays-and-placement\}

| 功能 | 使用元件 | 缺少支援時 |
| --- | --- | --- |
| 觸發指令：`command` 和 `commandfor` | [對話框](/components/dialog)、[指令面板](/components/command) | 在點擊事件處理函式中呼叫 `showModal()` 和 `close()`，沿用原有樣式表 |
| `closedby="any"` | [對話框](/components/dialog)、[指令面板](/components/command) | 點擊遮罩不會關閉，仍可按 Escape 鍵或關閉按鈕 |
| 興趣觸發器：搭配 `interestfor` 使用 `popover="hint"` | [工具提示](/components/tooltip)、用於預覽的[彈出框](/components/popover) | 工具提示或預覽不會出現，控制項仍保有無障礙名稱，並可照常作為連結或按鈕使用 |
| CSS 錨點定位：`position-area`、`position-try-fallbacks` | [彈出框](/components/popover)、[選單](/components/menu)、[工具提示](/components/tooltip)、帶有 `popover` 屬性的[清單方塊](/components/listbox) | 面板照常開啟與關閉，瀏覽器會依彈出框的預設定位將其置中於檢視區 |
| `anchor-scope` 和 `anchor-size()` | [組合方塊](/components/combobox) | 清單依正常版面配置流程緊接在欄位下方，採用自身寬度 |
| 搭配 `anchor()` 使用 `anchor-scope`，讓同一個指示標記移動 | [分段控制項](/components/segmented)、[頁籤](/components/tabs)、[目錄](/components/toc) | 目前選取的項目各自顯示標記，切換時標記立即更新，沒有滑動效果 |
| 搭配 `anchor()` 使用 `anchor-scope`，讓分隔線從文字起點開始 | [清單](/components/list) | 項目下方的細線橫跨整列 |
| `@position-try` | [快顯選單](/components/menu) | 選單會在指標下方偏行尾的一側開啟，碰到檢視區邊緣時不會翻轉方向 |
| `@starting-style` 和 `transition-behavior: allow-discrete` | [對話框](/components/dialog)、[彈出框](/components/popover)、[選單](/components/menu)、[工具提示](/components/tooltip)、[浮動通知](/components/toast)、[圖表](/components/chart) | 覆疊元件會立即出現或消失，沒有淡入淡出效果。圖表的長條會直接以完整高度顯示 |

## 檢查功能支援 \{#checking-a-feature\}

使用確切的功能名稱查詢最新的相容性資訊。若是 CSS 功能，也可以用樣式表採用的同一個條件，在目前的瀏覽器中查詢：

```js
CSS.supports('(anchor-scope: --mark)')
CSS.supports('(appearance: base-select)')
CSS.supports('selector(::scroll-marker)')
```

[`CSS.supports()`](https://drafts.csswg.org/css-conditional-3/#dom-css-supports) 會判斷瀏覽器是否符合 CSS 支援條件。回傳肯定結果可用來選擇要套用的 CSS 規則，實際呈現與互動仍須另外測試。像 `commandfor` 這類 HTML 屬性也需要另外檢查。

檢查功能支援後，在目標瀏覽器中驗證元件：

1. 依照應用程式提供的操作流程，開啟、關閉、選取或編輯元件。測試覆疊元件時，也要確認鍵盤操作，以及關閉後焦點是否回到原處。
2. 檢查元件靠近檢視區邊緣、處於狹窄版面或內容可捲動時的定位。
3. 確認預計上線的備援行為。少了動畫或許可以接受，但開啟元件所需的事件處理函式不能缺少，必要指示也不能只放在可能無法顯示的工具提示中。

將必要指示放在看得見的文字中。只有當控制項本身已有名稱且用途清楚時，省略工具提示才是可用的備援。

## 偏好設定與裝置 \{#preferences-and-devices\}

除了瀏覽器功能支援，各樣式表也會在元件需要調整時，依據查詢條件配合使用者的裝置與設定。

| 查詢 | 變化 |
| --- | --- |
| `(hover: hover)` | 懸停樣式寫在這個查詢內，因此只會在指標能懸停時套用。觸碰後，控制項不會停留在懸停外觀 |
| `(pointer: coarse)` | 操作目標擴大至 44px。按鈕的最小高度增為 `2.75rem`，核取方塊標籤的可點擊範圍會從文字所在的那一行向外擴大，周圍元素的位置維持原樣 |
| `(prefers-reduced-motion: reduce)` | 停用控制項上抬、覆疊元件縮放與滑入滑出，以及指示標記滑動等效果。保留淡入淡出，讓使用者仍能看出變化 |
| `(forced-colors: active)` | 瀏覽器會移除陰影並替換色彩，因此邊緣與狀態會改以 `ButtonText`、`CanvasText` 和 `Highlight` 等系統色繪製外框與填色 |
| `(prefers-contrast: more)` | 主題會提高細線、分隔線與輪廓的對比度，也會提高次要文字與停用狀態文字的對比度。使用這些 token 的元件會跟著調整 |
| `(prefers-reduced-transparency: reduce)` | [導覽列](/components/navbar)和[頁籤列](/components/tabbar)會改用不透明的純色背景，並移除玻璃模糊效果 |

主題中隨配色模式變化的色彩會使用 `light-dark()`，並依頁面或子樹的 `color-scheme` 決定採用哪個色彩。請參閱[預設主題](/guide/theme#color-schemes)。

## 獨立樣式表 \{#standalone\}

`@master/ui/standalone.css` 由相同的原始碼編譯成純 CSS，供未使用 Master CSS 的專案使用。請參閱[安裝](/guide/installation#without-master-css)中的引入方式。

```css name=app.css
@import '@master/ui/standalone.css';
```

編譯時會展開 mixin，並將 token 寫成自訂屬性。編譯過程不會將現代 CSS 語法轉成舊版語法。編譯後的 CSS 仍宣告相同的層疊圖層，保留巢狀規則、`light-dark()` 和 `oklch()`，也沿用相同的 `@supports` 規則。本頁列出的需求與備援同樣適用於這個檔案，以及 `@master/ui/dist/themes/paper.css` 等編譯後的主題。

編譯後的檔案也會宣告 `color-scheme: light dark`，並支援 `data-theme="light"` 和 `data-theme="dark"`。如果後續還有其他建置工具轉換這份 CSS，請測試應用程式實際提供的版本。
