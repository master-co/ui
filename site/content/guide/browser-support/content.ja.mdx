アプリケーションで使うコンポーネントについて、ブラウザーサポートを確認してください。Master UI は、ベースラインの見た目にはモダンな CSS を、振る舞いにはネイティブ要素を使っています。追加の機能は配置、モーション、コントロールを改善します。そのフォールバックは自動で働く場合もあれば、アプリケーション側にハンドラーが必要な場合もあります。

まず以下のベースラインを確認し、次に使用するコンポーネントのエンハンスメントの行を読んでください。CI では、固定バージョンの Playwright 依存関係に同梱された Chromium、Firefox、WebKit でフレームワークのシナリオを実行しており、invoker commands、interest invokers、アンカー位置指定について記載したフォールバックもそこに含まれます。表は機能の要件を示すものであり、リリースされたすべてのブラウザーバージョンでの動作を保証するものではありません。サポートする各ブラウザーで[機能と結果を確認](#checking-a-feature)してください。

## ベースラインの要件 \{#baseline\}

以下の機能は、記載した箇所でライブラリ側のフォールバックなしに使われています。レイヤー、ネスト、色関数はライブラリ全体に影響します。`subgrid` や `<dialog>` のような機能は、それを使うコンポーネントでのみ問題になります。

| 機能 | 使われている箇所 |
| --- | --- |
| カスタムプロパティ | すべてのトークンと、コントラクトが公開するすべてのプロパティ |
| カスケードレイヤー（`@layer`） | すべてのコンポーネントとレイアウトのルールは `components` レイヤーに、トークンは `theme` にあります。これにより、ユーティリティが `!important` なしでコンポーネントより優先されます |
| CSS ネスト | ルールはネストして書かれており、コンパイル後のスタイルシートもネストを保持します |
| `light-dark()` | カラースキームに応じて変わるテーマカラー |
| `oklch()` | カラートークンの値 |
| `color-mix()` | ティント、トーン付きのボタン、ガラス、インクのサーフェス上のインラインチップ |
| `:has()` | 子の状態を読み取る親：[input group](/components/input)、フィールド、[segmented control](/components/segmented)、[rating](/components/rating)、[steps](/components/steps)、[listbox](/components/listbox) の空状態 |
| コンテナーサイズクエリー（`@container`） | [Card](/components/card)、[dialog](/components/dialog)、[data list](/components/data-list)、[navbar](/components/navbar)、および [form](/components/form)、[bento](/components/bento)、[shell](/pages/app-shell) の各レイアウト |
| `subgrid` | [Calendar](/components/calendar)、[chart](/components/chart)、[data list](/components/data-list) |
| 個別のトランスフォームプロパティ（`translate`、`scale`） | 持ち上がるコントロールの状態と、オーバーレイの登場 |
| `:focus-visible` | コントロールのキーボードフォーカスリング |
| `:dir()` | ドロワー、パンくずの区切り、カレンダーの範囲など、右から左へのテキストで向きが反転するパーツ |
| 論理プロパティと `inset` | テキストの方向に従う余白と配置 |
| 動的ビューポート単位（`dvh`） | [dialog](/components/dialog) と [command palette](/components/command) の高さの上限。`page` と `shell` のレイアウトは先に `vh` の値を書いています |
| `popover` 属性 | [Popover](/components/popover)、[menu](/components/menu)、[tooltip](/components/tooltip)、[combobox](/components/combobox) のリスト |
| `<dialog>` | [Dialog](/components/dialog)、[command palette](/components/command)、[toast](/components/toast)、閉じられる [banner](/components/banner) |

サポートされない構文は、宣言、セレクター、またはルール全体を無効にすることがあります。レイヤーやネストが使えないとスタイルシートの大部分に影響し、色関数が使えないと、その色を使う宣言に有効な値がなくなることがあります。エンハンスメントのフォールバックは、ベースラインの機能の欠如を補うものではありません。

## エンハンスメント \{#enhancements\}

以下の各機能は、2 つの方法のどちらかで条件付けされています。ほとんどは `@supports (anchor-scope: --segmented-thumb)` や `@supports selector(::scroll-marker)` のような `@supports` ルールの中にあり、フォールバックを描画するルールの後に書かれています。残りは、`interpolate-size`、`@starting-style`、`closedby` のように、その機能のないブラウザーが無視する単一の宣言、アットルール、または属性です。

最後の列は、フォールバック、または必要な統合作業を示しています。コンポーネント固有の振る舞いは、各[コントラクト](/guide/contracts)の `platform` リストに記録されています。特に、`commandfor` だけを持つダイアログは、以下で説明するハンドラーを用意するまで、invoker commands のないブラウザーでは開きません。

<GuideFigure name="browser-support" title="ベースラインとエンハンスメントによる配置">

**エンハンスメントは、機能するベースラインの上で結果を変えます。** ネイティブのポップオーバーに対応していれば、どちらの場合も同じサーフェスが開閉します。CSS アンカー位置指定はそれをトリガーの隣に配置し、このエンハンスメントがなければ、通常のポップオーバーはビューポートの中央に置かれたままです。2 つの模式的なビューポートで変わるのは配置だけです。どちらの分岐も、ポップオーバーに対応していないブラウザー向けのフォールバックは提供しません。

</GuideFigure>

### オーバーレイと配置 \{#overlays-and-placement\}

| 機能 | 使用するもの | ない場合 |
| --- | --- | --- |
| Invoker commands：`command` と `commandfor` | [Dialog](/components/dialog)、[command palette](/components/command) | クリックハンドラーから `showModal()` と `close()` を呼び出します。スタイルシートは同じです |
| `closedby="any"` | [Dialog](/components/dialog)、[command palette](/components/command) | スクリムをクリックしても何も起きません。Escape と閉じるボタンでは引き続き閉じられます |
| Interest invokers：`popover="hint"` と `interestfor` | [Tooltip](/components/tooltip)、プレビューとして使う [popover](/components/popover) | ツールチップやプレビューは表示されません。コントロールはアクセシブルな名前を保ち、リンクやボタンとして引き続き機能します |
| CSS アンカー位置指定：`position-area`、`position-try-fallbacks` | [Popover](/components/popover)、[menu](/components/menu)、[tooltip](/components/tooltip)、`popover` 属性を持つ [listbox](/components/listbox) | サーフェスは同じように開閉します。ブラウザーがあらゆるポップオーバーを置く位置、つまりビューポートの中央に表示されます |
| `anchor-scope` と `anchor-size()` | [Combobox](/components/combobox) | リストはフローの中でフィールドの直下に、自身の幅で配置されます |
| `anchor()` と組み合わせた `anchor-scope`（移動する 1 つのインジケーター用） | [Segmented control](/components/segmented)、[tabs](/components/tabs)、[table of contents](/components/toc) | 現在のオプションがそれぞれ自分のマークを描画し、マークは滑らかに移動せず即座に切り替わります |
| `anchor()` と組み合わせた `anchor-scope`（文字の位置から始まる罫線用） | [List](/components/list) | 行の下の細線が行全体に伸びます |
| `@position-try` | [Context menu](/components/menu) | ポインターの下方向・行末方向に開き、ビューポートの端で向きを変えません |
| `@starting-style` と `transition-behavior: allow-discrete` | [Dialog](/components/dialog)、[popover](/components/popover)、[menu](/components/menu)、[tooltip](/components/tooltip)、[toast](/components/toast)、[chart](/components/chart) | オーバーレイはフェードなしで即座に表示・消去されます。チャートのバーは最初から完全な高さで表示されます |

## 機能を確認する \{#checking-a-feature\}

最新の互換性情報は、正確な機能名で調べてください。CSS については、スタイルシートが判定するのと同じ条件を使い、手元のブラウザーに問い合わせることもできます。

```js
CSS.supports('(anchor-scope: --mark)')
CSS.supports('(appearance: base-select)')
CSS.supports('selector(::scroll-marker)')
```

[`CSS.supports()`](https://drafts.csswg.org/css-conditional-3/#dom-css-supports) は CSS のサポート条件を評価します。肯定的な結果は CSS の分岐を選ぶのに役立ちますが、レンダリングや操作のテストではありません。また、`commandfor` のような HTML 属性は判定しません。

機能を確認したら、対象ブラウザーでコンポーネントを検証します。

1. アプリケーションが提供する経路で、開く、閉じる、選択する、編集するといった操作を行います。オーバーレイでは、キーボード操作とフォーカスの戻りも確認します。
2. ビューポートの端付近での配置、幅の狭いレイアウト、スクロールするコンテンツを確認します。
3. 出荷するつもりのフォールバックを確認します。アニメーションがないことは許容できる場合もありますが、開くためのハンドラーがないことや、表示されないツールチップに重要な説明が隠れていることは許容できません。

重要な説明は、見えるテキストに置いてください。ツールチップが省かれても使えるフォールバックになるのは、元のコントロールがすでに名前と目的を備えている場合だけです。

## ユーザー設定とデバイス \{#preferences-and-devices\}

サポートは機能だけの問題ではありません。各スタイルシートは、コンポーネントに変えるべきものがある箇所で、読み手のデバイスと設定を表すクエリーにも対応しています。

| クエリー | 変わるもの |
| --- | --- |
| `(hover: hover)` | ホバー状態はこの中に書かれているため、ポインターがホバーできる環境でのみ適用されます。タッチ操作の後にコントロールがホバー状態に見えることはありません |
| `(pointer: coarse)` | ターゲットが 44px に大きくなります。ボタンの最小の高さは `2.75rem` になり、チェックボックスのラベルは周囲のものを動かさずに、行のまわりで大きくなります |
| `(prefers-reduced-motion: reduce)` | 移動が取り除かれます。コントロールの持ち上がり、オーバーレイの拡大縮小とスライド、インジケーターの滑らかな移動です。フェードは残るため、変化は引き続き見て取れます |
| `(forced-colors: active)` | ブラウザーが影を取り除き色を置き換えるため、端と状態は `ButtonText`、`CanvasText`、`Highlight` などのシステムカラーによるアウトラインと塗りで改めて描画されます |
| `(prefers-contrast: more)` | テーマが細線、区切り線、輪郭のトークンと、控えめなインクおよび無効状態のインクを強めます。それらのトークンを読むコンポーネントも追従します |
| `(prefers-reduced-transparency: reduce)` | [navbar](/components/navbar) と [tab bar](/components/tabbar) のガラスが、ぼかしのない不透明なサーフェスになります |

テーマカラーは、スキーム間で異なる箇所に `light-dark()` を使い、ページまたはサブツリーの `color-scheme` に従います。[既定のテーマ](/guide/theme#color-schemes)を参照してください。

## スタンドアロンのスタイルシート \{#standalone\}

`@master/ui/standalone.css` は、Master CSS を使わないプロジェクト向けに、同じソースをプレーンな CSS にコンパイルしたものです。リンク方法は[インストール](/guide/installation#without-master-css)で説明しています。

```css name=app.css
@import '@master/ui/standalone.css';
```

コンパイルではミックスインが解決され、トークンがカスタムプロパティとして書き出されます。CSS のダウンレベル変換は行いません。このファイルは同じレイヤーを宣言し、ネスト、`light-dark()`、`oklch()` を保持し、同じ `@supports` ルールを含みます。その要件とフォールバックは、このページに記載したものと同じです。`@master/ui/dist/themes/paper.css` のようなコンパイル済みテーマについても同様です。

コンパイル済みファイルは `color-scheme: light dark` も宣言し、`data-theme="light"` と `data-theme="dark"` に対応しています。この後に別のビルドツールが CSS を変換する場合は、アプリケーションが実際に配信する CSS をテストしてください。
