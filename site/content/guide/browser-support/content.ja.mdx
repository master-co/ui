アプリケーションで使うコンポーネントのブラウザー対応を確認します。Master UI は、基本の外観にモダン CSS を使い、動作にはネイティブ要素を使います。追加機能は配置や動き、コントロールを改善します。フォールバックは自動で適用される場合と、アプリケーション側でハンドラーが必要な場合があります。

まず以下の基本要件を確認し、次に使用するコンポーネントに該当する拡張機能の行を確認します。CI では、バージョンを固定した Playwright に同梱される Chromium、Firefox、WebKit で、フレームワークの利用シナリオをテストします。テストには、呼び出しコマンド、関心ベースの呼び出し、アンカー配置について、ドキュメントに記載されたフォールバックも含まれます。表は機能要件を示すもので、公開済みのすべてのブラウザーバージョンでの動作を保証するものではありません。サポート対象の各ブラウザーで[機能への対応と実際の動作を確認します](#checking-a-feature)。

## 基本要件 \{#baseline\}

以下に示す箇所では、ライブラリーによるフォールバックなしでこれらの機能を使います。レイヤー、ネスト、色関数はライブラリー全体に広く影響します。`subgrid`や`<dialog>`などは、それを使うコンポーネントで必要です。

| 機能 | 使用箇所 |
| --- | --- |
| カスタムプロパティ | すべてのトークンと、コントラクトで公開されるすべてのプロパティ |
| カスケードレイヤー（`@layer`） | コンポーネントとレイアウトのルールはすべて`components`レイヤーにあり、トークンは`theme`にあります。この構成により、`!important`を使わずにユーティリティをコンポーネントより優先できます。 |
| CSS ネスト | ルールは入れ子で記述され、コンパイル後のスタイルシートにもネストが残ります。 |
| `light-dark()` | 配色に応じて切り替わるテーマカラー |
| `oklch()` | カラートークンの値 |
| `color-mix()` | 淡い色付け、色付きボタン、ガラス調の質感、インク色のサーフェス上のインラインチップ |
| `:has()` | 子要素の状態を参照する親要素。該当するのは[入力グループ](/components/input)、フィールド、[セグメントコントロール](/components/segmented)、[評価](/components/rating)、[ステップ](/components/steps)、[リストボックス](/components/listbox)の空状態です。 |
| コンテナーのサイズクエリー（`@container`） | [カード](/components/card)、[ダイアログ](/components/dialog)、[データリスト](/components/data-list)、[ナビゲーションバー](/components/navbar)の各コンポーネントと、[フォーム](/components/form)、[ベントーレイアウト](/components/bento)、[アプリシェル](/pages/app-shell)の各レイアウト |
| `subgrid` | [カレンダー](/components/calendar)、[チャート](/components/chart)、[データリスト](/components/data-list) |
| 個別の変形プロパティ（`translate`、`scale`） | コントロールが浮き上がる状態と、オーバーレイの表示アニメーション |
| `:focus-visible` | キーボード操作時のコントロールのフォーカスリング |
| `:dir()` | 右から左に書く場合に向きが反転する部分（ドロワー、パンくずリストの区切り、カレンダーの範囲表示など） |
| 論理プロパティと`inset` | テキストの方向に応じた余白と配置 |
| 動的ビューポート単位（`dvh`） | [ダイアログ](/components/dialog)と[コマンドパレット](/components/command)の高さの上限。`page`と`shell`のレイアウトでは、先に`vh`の値を指定します。 |
| `popover`属性 | [ポップオーバー](/components/popover)、[メニュー](/components/menu)、[ツールチップ](/components/tooltip)、[コンボボックス](/components/combobox)のリスト |
| `<dialog>` | [ダイアログ](/components/dialog)、[コマンドパレット](/components/command)、[トースト](/components/toast)、閉じられる[バナー](/components/banner) |

未対応の構文があると、宣言やセレクター、ルール全体が無効になることがあります。レイヤーやネストが使えないとスタイルシートの広い範囲に影響し、色関数が使えないと、その色を参照する宣言に有効な値が渡らないことがあります。拡張機能のフォールバックでは、基本機能への未対応は補えません。

## 拡張機能 \{#enhancements\}

以下の機能は、対応状況に応じて 2 通りの方法で適用されます。大半は、フォールバックの表示を定義するルールの後に、`@supports (anchor-scope: --segmented-thumb)`や`@supports selector(::scroll-marker)`などの条件を使った`@supports`ルール内に記述されています。残りは`interpolate-size`、`@starting-style`、`closedby`などの単独の宣言、アットルール、属性で、未対応のブラウザーでは無視されます。

最後の列では、フォールバックや組み込み時に必要な対応を説明します。各[コントラクト](/guide/contracts)の`platform`一覧には、コンポーネントごとの動作が記載されています。特に、`commandfor`だけを指定したダイアログは、呼び出しコマンドに未対応のブラウザーでは開きません。その場合は、以下に示すハンドラーを用意します。

<GuideFigure name="browser-support" title="基本機能と拡張機能での配置">

**拡張機能は、基本機能が動作する状態で表示や動作を変えます。** ブラウザーがネイティブのポップオーバーに対応していれば、どちらの場合も同じサーフェスが開閉します。CSS アンカー配置が使える場合はトリガーの隣に配置され、使えない場合は通常のポップオーバーとしてビューポートの中央に表示されます。2 つの模式図で異なるのは配置だけです。どちらも、ポップオーバー自体に未対応のブラウザー向けのフォールバックは提供しません。

</GuideFigure>

## 機能への対応を確認する \{#checking-a-feature\}

機能の正確な名前で、最新の対応状況を調べます。CSS の場合は、スタイルシートと同じ条件を使って、使用中のブラウザーでも確認できます。

```js
CSS.supports('(anchor-scope: --mark)')
CSS.supports('(appearance: base-select)')
CSS.supports('selector(::scroll-marker)')
```

[`CSS.supports()`](https://drafts.csswg.org/css-conditional-3/#dom-css-supports)は CSS の対応条件を評価します。条件が成立すれば適用する CSS を選ぶ判断材料になりますが、描画や操作の動作までは確認できません。`commandfor`などの HTML 属性も確認の対象外です。

機能への対応を確認したら、対象ブラウザーでコンポーネントの動作を検証します。

1. アプリケーションが提供する操作手順に沿って、開く、閉じる、選択する、編集するなどの操作を試します。オーバーレイでは、キーボード操作と、閉じた後にフォーカスが戻ることも確認します。
2. ビューポートの端に近い位置での配置、幅の狭いレイアウト、コンテンツがスクロールする場合の動作を確認します。
3. 実際に提供するフォールバックを確認します。アニメーションの省略は許容できる場合がありますが、開くためのハンドラーがなかったり、必須の案内が表示できないツールチップにしかなかったりすると、操作に支障が出ます。

必須の案内は、常に見えるテキストに記載します。ツールチップの省略が実用的なフォールバックになるのは、元のコントロールだけで名前と用途が分かる場合に限ります。

## ユーザー設定とデバイス \{#preferences-and-devices\}

ブラウザー対応には、機能の有無に加えてデバイスやユーザー設定への対応も含まれます。各スタイルシートでは、コンポーネントに調整が必要な箇所で、それらの条件を表すクエリーに応じてスタイルを切り替えます。

| クエリー | 変化する箇所 |
| --- | --- |
| `(hover: hover)` | ホバー時のスタイルはこのクエリー内で定義され、ポインターでホバーできる場合にのみ適用されます。タッチ操作の後にコントロールがホバー状態の見た目のまま残ることはありません。 |
| `(pointer: coarse)` | 操作対象のサイズは 44px まで広がります。ボタンの最小の高さは`2.75rem`になり、チェックボックスのラベルは周囲の要素を動かさずにテキスト行の周りに広がります。 |
| `(prefers-reduced-motion: reduce)` | コントロールの浮き上がり、オーバーレイの拡大・縮小やスライド、インジケーターのスライドが省かれます。フェードは残るため、状態の変化は視覚的に分かります。 |
| `(forced-colors: active)` | ブラウザーが影を取り除き、色を置き換えるため、境界や状態は`ButtonText`、`CanvasText`、`Highlight`などのシステムカラーを使ったアウトラインや塗りで表します。 |
| `(prefers-contrast: more)` | テーマでは、細線、区切り線、輪郭のトークンと、控えめな表示や無効状態に使うインク色を強調します。これらのトークンを参照するコンポーネントにも変更が反映されます。 |
| `(prefers-reduced-transparency: reduce)` | [ナビゲーションバー](/components/navbar)と[タブバー](/components/tabbar)のガラス調のサーフェスは、ぼかしのない不透明なサーフェスに変わります。 |

テーマカラーは、配色ごとに色が異なる箇所で`light-dark()`を使い、ページまたはサブツリーの`color-scheme`に従います。[既定のテーマ](/guide/theme#color-schemes)を参照してください。

## スタンドアロンのスタイルシート \{#standalone\}

`@master/ui/standalone.css`は、Master CSS を使わないプロジェクト向けに、同じソースをプレーンな CSS にコンパイルしたものです。読み込み方は[インストール](/guide/installation#without-master-css)を参照してください。

```css name=app.css
@import '@master/ui/standalone.css';
```

コンパイルでは、ミックスインを展開し、トークンをカスタムプロパティとして出力します。古い CSS 構文への変換は行わず、同じレイヤーを宣言し、ネスト、`light-dark()`、`oklch()`、同じ`@supports`ルールを維持します。要件とフォールバックは、このページに記載されているとおりです。`@master/ui/dist/themes/paper.css`などのコンパイル済みテーマにも同じことが当てはまります。

コンパイル済みファイルは`color-scheme: light dark`も宣言し、`data-theme="light"`と`data-theme="dark"`に対応しています。この後に別のビルドツールで変換する場合は、アプリケーションが実際に配信する CSS をテストしてください。
