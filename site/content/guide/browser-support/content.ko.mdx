애플리케이션이 사용하는 컴포넌트의 브라우저 지원을 확인하세요. Master UI는 기본 외형을 위해 최신 CSS에, 동작을 위해 네이티브 요소에 의존합니다. 추가 기능은 배치, 모션, 컨트롤을 개선합니다. 그 폴백은 자동으로 이루어질 수도 있고, 애플리케이션에 핸들러가 필요할 수도 있습니다.

아래의 기본 요구 사항부터 확인한 다음, 사용하는 컴포넌트의 향상 기능 행을 읽으세요. CI는 고정된 Playwright 의존성에 포함된 Chromium, Firefox, WebKit 버전에서 프레임워크 시나리오를 실행하며, 여기에는 invoker 명령, interest invoker, 앵커 위치 지정에 대해 문서화된 폴백도 포함됩니다. 표는 기능 요구 사항을 설명할 뿐, 출시된 모든 브라우저 버전에 대한 보증이 아닙니다. 지원하는 각 브라우저에서 [기능과 결과를 확인하세요](#checking-a-feature).

## 기본 요구 사항 \{#baseline\}

이 기능들은 나열된 위치에서 라이브러리 폴백 없이 사용됩니다. 레이어, 중첩, 색상 함수는 라이브러리 전반에 영향을 줍니다. `subgrid`나 `<dialog>` 같은 기능은 해당 기능을 사용하는 컴포넌트에서만 문제가 됩니다.

| 기능 | 사용 위치 |
| --- | --- |
| 사용자 지정 속성 | 모든 토큰, 그리고 계약이 공개하는 모든 속성 |
| 캐스케이드 레이어(`@layer`) | 모든 컴포넌트와 레이아웃 규칙은 `components` 레이어에, 토큰은 `theme`에 있습니다. 유틸리티가 `!important` 없이 컴포넌트보다 우선하는 방법입니다 |
| CSS 중첩 | 규칙이 중첩된 형태로 작성되며, 컴파일된 스타일시트도 중첩을 유지합니다 |
| `light-dark()` | 색 구성표에 따라 바뀌는 테마 색상 |
| `oklch()` | 색상 토큰의 값 |
| `color-mix()` | 틴트, 톤 버튼, 글래스, 잉크 표면 위의 인라인 칩 |
| `:has()` | 자식의 상태를 읽는 부모: [입력 그룹](/components/input), 필드, [세그먼트 컨트롤](/components/segmented), [평점](/components/rating), [단계](/components/steps), [리스트박스](/components/listbox)의 빈 상태 |
| 컨테이너 크기 쿼리(`@container`) | [카드](/components/card), [대화 상자](/components/dialog), [데이터 목록](/components/data-list), [내비게이션 바](/components/navbar), 그리고 [폼](/components/form), [벤토](/components/bento), [셸](/pages/app-shell) 레이아웃 |
| `subgrid` | [캘린더](/components/calendar), [차트](/components/chart), [데이터 목록](/components/data-list) |
| 개별 변형 속성(`translate`, `scale`) | 들어 올려진 컨트롤 상태와 오버레이 진입 |
| `:focus-visible` | 컨트롤의 키보드 포커스 링 |
| `:dir()` | 서랍, 브레드크럼 구분자, 캘린더 범위처럼 오른쪽에서 왼쪽으로 쓰는 텍스트에서 방향이 바뀌는 부분 |
| 논리 속성과 `inset` | 텍스트 방향을 따르는 간격과 배치 |
| 동적 뷰포트 단위(`dvh`) | [대화 상자](/components/dialog)와 [명령 팔레트](/components/command)의 높이 제한. `page`와 `shell` 레이아웃은 먼저 `vh` 값을 작성합니다 |
| `popover` 속성 | [팝오버](/components/popover), [메뉴](/components/menu), [툴팁](/components/tooltip), [콤보박스](/components/combobox)의 목록 |
| `<dialog>` | [대화 상자](/components/dialog), [명령 팔레트](/components/command), [토스트](/components/toast), 닫을 수 있는 [배너](/components/banner) |

지원되지 않는 구문은 선언, 선택자, 또는 규칙 전체를 무효화할 수 있습니다. 레이어나 중첩을 잃으면 스타일시트의 상당 부분이 영향을 받고, 색상 함수를 잃으면 그 색상을 사용하는 선언에 쓸 수 있는 값이 남지 않을 수 있습니다. 향상 기능의 폴백은 빠진 기본 기능을 보완하지 않습니다.

## 향상 기능 \{#enhancements\}

아래의 각 기능은 두 가지 방식 중 하나로 조건이 걸려 있습니다. 대부분은 `@supports (anchor-scope: --segmented-thumb)`나 `@supports selector(::scroll-marker)` 같은 `@supports` 규칙 안에 있으며, 폴백을 그리는 규칙 뒤에 작성됩니다. 나머지는 `interpolate-size`, `@starting-style`, `closedby`처럼 기능이 없는 브라우저가 무시하는 단일 선언, at-rule, 속성입니다.

마지막 열은 폴백 또는 필요한 통합 작업을 설명합니다. 각 [계약](/guide/contracts)의 `platform` 목록에는 컴포넌트별 동작이 기록되어 있습니다. 특히 `commandfor`만 있는 대화 상자는 아래에 설명한 핸들러를 제공하기 전까지 invoker 명령이 없는 브라우저에서 열리지 않습니다.

<GuideFigure name="browser-support" title="기본 배치와 향상된 배치">

**향상 기능은 동작하는 기본 위에서 결과를 바꿉니다.** 네이티브 팝오버를 지원하면 두 경우 모두 같은 표면이 열리고 닫힙니다. CSS 앵커 위치 지정은 표면을 트리거 옆에 배치하고, 이 향상 기능이 없으면 일반 팝오버는 뷰포트 중앙에 남습니다. 두 개의 도식적인 뷰포트는 배치만 다릅니다. 어느 쪽도 팝오버를 지원하지 않는 브라우저를 위한 폴백을 제공하지 않습니다.

</GuideFigure>

## 기능 확인하기 \{#checking-a-feature\}

정확한 기능 이름으로 현재 호환성 정보를 찾으세요. CSS의 경우 스타일시트가 검사하는 것과 같은 조건으로 지금 사용 중인 브라우저에 직접 물어볼 수도 있습니다.

```js
CSS.supports('(anchor-scope: --mark)')
CSS.supports('(appearance: base-select)')
CSS.supports('selector(::scroll-marker)')
```

[`CSS.supports()`](https://drafts.csswg.org/css-conditional-3/#dom-css-supports)는 CSS 지원 조건을 평가합니다. 긍정적인 결과는 CSS 분기를 고르는 데 유용하지만 렌더링이나 상호작용 테스트는 아닙니다. 또한 `commandfor` 같은 HTML 속성은 검사하지 않습니다.

기능을 확인한 후 대상 브라우저에서 컴포넌트를 검증하세요.

1. 애플리케이션이 제공하는 경로로 컴포넌트를 열고, 닫고, 선택하거나 편집합니다. 오버레이의 경우 키보드 사용과 포커스 복귀도 포함하세요.
2. 뷰포트 가장자리 근처의 배치, 좁은 레이아웃, 스크롤되는 콘텐츠를 확인합니다.
3. 배포하려는 폴백을 확인합니다. 애니메이션이 빠지는 것은 허용될 수 있지만, 열기 핸들러가 빠지거나 필수 안내가 사용할 수 없는 툴팁 안에 숨겨지는 것은 허용되지 않습니다.

필수 안내는 보이는 텍스트로 두세요. 툴팁이 생략되어도 쓸 만한 폴백이 되는 것은 기반 컨트롤이 이미 이름과 목적을 갖추고 있을 때뿐입니다.

## 환경 설정과 기기 \{#preferences-and-devices\}

지원은 기능만의 문제가 아닙니다. 각 스타일시트는 컴포넌트에 바꿀 것이 있는 곳마다 독자의 기기와 설정을 설명하는 쿼리에도 응답합니다.

| 쿼리 | 바뀌는 것 |
| --- | --- |
| `(hover: hover)` | 호버 상태가 이 안에 작성되므로 포인터가 호버할 수 있는 곳에서만 적용됩니다. 터치한 뒤 컨트롤이 호버된 모양으로 남지 않습니다 |
| `(pointer: coarse)` | 대상이 44px로 커집니다. 버튼의 최소 높이는 `2.75rem`이 되고, 체크박스의 레이블은 주변 요소를 움직이지 않은 채 해당 줄 주위로 커집니다 |
| `(prefers-reduced-motion: reduce)` | 이동이 제거됩니다. 컨트롤의 들어 올림, 오버레이의 확대와 미끄러짐, 표시기의 활주가 사라집니다. 페이드는 남으므로 변화는 여전히 보입니다 |
| `(forced-colors: active)` | 브라우저가 그림자를 제거하고 색상을 대체하므로, 가장자리와 상태를 `ButtonText`, `CanvasText`, `Highlight` 같은 시스템 색상의 윤곽선과 채우기로 다시 그립니다 |
| `(prefers-contrast: more)` | 테마가 가는 선, 구분선, 윤곽 토큰과 흐린 잉크, 비활성 잉크를 강화합니다. 이 토큰을 읽는 컴포넌트가 이를 따릅니다 |
| `(prefers-reduced-transparency: reduce)` | [내비게이션 바](/components/navbar)와 [탭 바](/components/tabbar)의 글래스가 블러 없는 단색 표면이 됩니다 |

테마 색상은 구성표마다 다른 곳에서 `light-dark()`를 사용하며, 페이지나 하위 트리의 `color-scheme`을 따릅니다. [기본 테마](/guide/theme#color-schemes)를 참고하세요.

## 독립형 스타일시트 \{#standalone\}

`@master/ui/standalone.css`는 Master CSS를 사용하지 않는 프로젝트를 위해 같은 소스를 일반 CSS로 컴파일한 것입니다. 연결 방법은 [설치](/guide/installation#without-master-css)에 나와 있습니다.

```css name=app.css
@import '@master/ui/standalone.css';
```

컴파일은 믹스인을 해석하고 토큰을 사용자 지정 속성으로 작성합니다. CSS를 낮은 버전으로 변환하지는 않습니다. 이 파일은 같은 레이어를 선언하고, 중첩, `light-dark()`, `oklch()`를 유지하며, 같은 `@supports` 규칙을 담고 있습니다. 요구 사항과 폴백은 이 페이지에 있는 것과 같습니다. `@master/ui/dist/themes/paper.css` 같은 컴파일된 테마도 마찬가지입니다.

컴파일된 파일은 `color-scheme: light dark`도 선언하며 `data-theme="light"`와 `data-theme="dark"`를 지원합니다. 이 단계 이후에 다른 빌드 도구가 CSS를 변환한다면 애플리케이션이 실제로 제공하는 CSS를 테스트하세요.
