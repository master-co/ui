애플리케이션에서 사용하는 컴포넌트의 브라우저 지원 여부를 확인하세요. Master UI는 기본 모양을 구현하는 데 최신 CSS를 사용하고, 동작은 브라우저 기본 요소에 맡깁니다. 추가 기능은 배치, 애니메이션 또는 컨트롤을 개선합니다. 기능에 따라 폴백이 자동으로 적용되거나 애플리케이션에서 핸들러를 제공해야 할 수 있습니다.

아래의 기본 요구 사항을 먼저 확인한 뒤, 사용하는 컴포넌트에 해당하는 추가 기능 항목을 살펴보세요. CI는 버전을 고정한 Playwright 의존성에 포함된 Chromium, Firefox, WebKit 버전에서 프레임워크별 시나리오를 테스트합니다. 이 테스트에는 호출자 명령, 관심 호출자, 앵커 배치에 대해 문서화된 폴백도 포함됩니다. 표는 기능별 요구 사항을 설명하며, 출시된 모든 브라우저 버전에서의 동작을 보장하지는 않습니다. 지원 대상 브라우저마다 [기능 지원 여부와 실제 결과를 확인하세요](#checking-a-feature).

## 기본 요구 사항 \{#baseline\}

아래에 나열된 사용처에서 라이브러리는 이러한 기능에 대한 폴백을 제공하지 않습니다. 캐스케이드 레이어, 중첩, 색상 함수는 라이브러리 전반에 영향을 미칩니다. `subgrid` 또는 `<dialog>` 같은 기능은 해당 기능을 사용하는 컴포넌트에 영향을 미칩니다.

| 기능 | 사용처 |
| --- | --- |
| 사용자 지정 속성 | 모든 디자인 토큰과 계약에서 공개하는 모든 속성 |
| 캐스케이드 레이어 (`@layer`) | 모든 컴포넌트 및 레이아웃 규칙은 `components` 레이어에 있고, 디자인 토큰은 `theme`에 있습니다. 이 레이어 순서 덕분에 `!important` 없이도 유틸리티 규칙이 컴포넌트 규칙보다 우선합니다 |
| CSS 중첩 | 규칙을 중첩해서 작성하며, 컴파일된 스타일시트에서도 중첩 구조를 유지합니다 |
| `light-dark()` | 색 구성표에 따라 바뀌는 테마 색상 |
| `oklch()` | 색상 토큰의 값 |
| `color-mix()` | 옅은 색조, 색조 버튼, 유리 효과, 전경색을 배경으로 쓰는 표면의 인라인 칩 |
| `:has()` | 하위 요소의 상태를 참조하는 상위 요소: [입력 그룹](/components/input), 필드, [분할 컨트롤](/components/segmented), [평점](/components/rating), [단계](/components/steps), [리스트박스](/components/listbox)의 빈 상태 |
| 컨테이너 크기 쿼리 (`@container`) | [카드](/components/card), [대화상자](/components/dialog), [데이터 목록](/components/data-list), [내비게이션 바](/components/navbar) 및 [폼](/components/form), [벤토](/components/bento), [셸](/pages/app-shell) 레이아웃 |
| `subgrid` | [달력](/components/calendar), [차트](/components/chart), [데이터 목록](/components/data-list) |
| 개별 변환 속성 (`translate`, `scale`) | 컨트롤이 떠오르는 상태와 오버레이가 나타나는 전환 효과 |
| `:focus-visible` | 컨트롤의 키보드 포커스 윤곽선 |
| `:dir()` | 오른쪽에서 왼쪽으로 쓰는 텍스트에서 방향이 반전되는 요소로, 드로어, 이동 경로 구분자, 달력의 날짜 범위 등이 해당합니다 |
| 논리 속성과 `inset` | 텍스트 방향에 맞춰 조정되는 간격과 배치 |
| 동적 뷰포트 단위 (`dvh`) | [대화상자](/components/dialog)와 [명령 팔레트](/components/command)의 높이 제한에 사용합니다. `page` 및 `shell` 레이아웃에서는 `vh` 값을 먼저 선언합니다 |
| `popover` 속성 | [팝오버](/components/popover), [메뉴](/components/menu), [툴팁](/components/tooltip), [콤보박스](/components/combobox)의 목록 |
| `<dialog>` | [대화상자](/components/dialog), [명령 팔레트](/components/command), [토스트](/components/toast), 닫을 수 있는 [배너](/components/banner) |

브라우저가 지원하지 않는 구문은 선언이나 선택자, 규칙 전체를 무효화할 수 있습니다. 캐스케이드 레이어나 중첩이 지원되지 않으면 스타일시트의 상당 부분이 영향을 받습니다. 색상 함수가 지원되지 않으면 해당 색상을 사용하는 선언에 유효한 값이 남지 않을 수 있습니다. 추가 기능의 폴백은 기본 기능의 미지원을 보완하지 못합니다.

## 추가 기능 \{#enhancements\}

아래의 각 기능은 지원 여부에 따라 두 가지 방식 중 하나로 적용됩니다. 대부분의 기능은 `@supports (anchor-scope: --segmented-thumb)` 또는 `@supports selector(::scroll-marker)`와 같은 `@supports` 규칙 안에 있으며, 이 규칙은 폴백을 표시하는 규칙 뒤에 작성합니다. 나머지는 `interpolate-size`, `@starting-style`, `closedby`처럼 단일 선언, 앳 규칙 또는 속성으로 작성하며, 기능을 지원하지 않는 브라우저는 이를 무시합니다.

마지막 열에는 폴백이나 연동에 필요한 작업이 나와 있습니다. 각 [계약](/guide/contracts)의 `platform` 목록에는 해당 컴포넌트의 동작이 기록되어 있습니다. 특히 `commandfor`만 지정한 대화상자는 호출자 명령을 지원하지 않는 브라우저에서 아래에 설명된 핸들러를 추가해야 열립니다.

<GuideFigure name="browser-support" title="기본 배치와 앵커 배치">

**추가 기능은 기본 동작을 바탕으로 표시 결과를 바꿉니다.** 브라우저가 팝오버를 기본 지원하면 두 경우 모두 같은 표면이 열리고 닫힙니다. CSS 앵커 배치를 적용하면 표면이 트리거 옆에 나타납니다. 이 추가 기능이 없으면 일반 팝오버는 뷰포트 중앙에 표시됩니다. 두 뷰포트 예시에서 달라지는 것은 배치뿐입니다. 두 경우 모두 팝오버를 지원하지 않는 브라우저에 대한 폴백은 제공하지 않습니다.

</GuideFigure>

### 오버레이와 배치 \{#overlays-and-placement\}

| --- | --- | --- |
| 호출자 명령: `command` 및 `commandfor` | [대화상자](/components/dialog), [명령 팔레트](/components/command) | 클릭 핸들러에서 `showModal()`과 `close()`를 호출합니다. 스타일시트는 그대로 사용합니다 |

| 관심 호출자: `popover="hint"` 및 `interestfor`의 조합 | [툴팁](/components/tooltip), 미리 보기로 사용하는 [팝오버](/components/popover) | 툴팁이나 미리 보기가 표시되지 않습니다. 컨트롤은 접근 가능한 이름을 유지하며 링크 또는 버튼으로 계속 동작합니다 |
| CSS 앵커 배치: `position-area`, `position-try-fallbacks` | [팝오버](/components/popover), [메뉴](/components/menu), [툴팁](/components/tooltip), `popover` 속성이 있는 [리스트박스](/components/listbox) | 표면이 열리고 닫히는 동작은 같습니다. 브라우저가 일반 팝오버를 배치하는 위치인 뷰포트 중앙에 표시됩니다 |
| `anchor-scope` 및 `anchor-size()` | [콤보박스](/components/combobox) | 목록은 자체 너비를 유지하며 문서 흐름에서 필드 바로 아래에 배치됩니다 |
| 하나의 표시기를 이동시키는 데 쓰이는 `anchor-scope` 및 `anchor()`의 조합 | [분할 컨트롤](/components/segmented), [탭](/components/tabs), [목차](/components/toc) | 활성 항목마다 자체 표시가 나타납니다. 활성 항목이 바뀌면 표시도 즉시 바뀌며 부드럽게 이동하는 효과는 적용되지 않습니다 |
| 텍스트가 시작되는 위치부터 구분선을 그리는 데 쓰이는 `anchor-scope` 및 `anchor()`의 조합 | [목록](/components/list) | 행 아래의 가는 구분선이 행 전체 너비에 걸쳐 표시됩니다 |
| `@position-try` | [컨텍스트 메뉴](/components/menu) | 포인터를 기준으로 아래쪽과 인라인 끝 방향으로 열리며, 뷰포트 가장자리에서도 방향을 바꾸지 않습니다 |
| `@starting-style` 및 `transition-behavior: allow-discrete` | [대화상자](/components/dialog), [팝오버](/components/popover), [메뉴](/components/menu), [툴팁](/components/tooltip), [토스트](/components/toast), [차트](/components/chart) | 오버레이는 페이드 효과 없이 즉시 나타나거나 사라지고, 차트의 막대는 처음부터 최종 높이로 표시됩니다 |

### 입력 필드 \{#fields\}

| 기능 | 사용 컴포넌트 | 미지원 시 동작 |
| --- | --- | --- |
| `appearance: base-select` | [선택 상자](/components/select) | 선택 상자는 오목한 영역과 꺾쇠 아이콘을 유지하고 플랫폼 기본 옵션 목록을 엽니다. `select-option`은 효과가 없습니다 |

| 브라우저 기본 입력 필드의 구성 요소: `::-webkit-calendar-picker-indicator`, `::-webkit-inner-spin-button`, `::-webkit-search-cancel-button` | [입력](/components/input) | 날짜, 시간, 숫자 및 검색 필드에는 브라우저의 기본 표시가 유지됩니다 |
| 브라우저 기본 `<meter>`의 구성 요소 | [측정 막대](/components/meter) | 브라우저의 기본 측정 막대가 유지되며, 동일한 값과 3가지 색조를 브라우저 기본 스타일로 표시합니다 |

| 타입이 지정된 `attr()` | [진행 표시기](/components/progress)의 링 | 링이 `aria-valuenow` 값을 읽지 못하므로 `style` 속성에도 `--progress-ring-value` 값을 설정하세요 |
| `sibling-index()` | [스켈레톤](/components/skeleton) | 블록 안의 모든 스켈레톤에서 빛 띠 애니메이션이 동시에 시작됩니다 |
| `text-wrap: balance` 및 `text-wrap: pretty` | [제목](/components/heading) | 텍스트가 평소처럼 줄바꿈됩니다 |

## 기능 지원 확인 \{#checking-a-feature\}

정확한 기능 이름으로 최신 호환성 정보를 찾아보세요. CSS 기능은 스타일시트에서 검사하는 조건을 그대로 사용해 현재 브라우저의 지원 여부를 확인할 수도 있습니다.

```js
CSS.supports('(anchor-scope: --mark)')
CSS.supports('(appearance: base-select)')
CSS.supports('selector(::scroll-marker)')
```

[`CSS.supports()`](https://drafts.csswg.org/css-conditional-3/#dom-css-supports) 메서드는 CSS 지원 조건을 평가합니다. 결과가 참이면 적용할 CSS 분기를 선택하는 데 활용할 수 있습니다. 실제 렌더링과 상호작용은 별도로 테스트해야 합니다. `commandfor` 같은 HTML 속성도 검사 대상에서 제외됩니다.

기능 지원 여부를 확인한 뒤에는 대상 브라우저에서 컴포넌트가 제대로 동작하는지 확인하세요.

1. 애플리케이션에서 제공하는 방식으로 컴포넌트를 열고 닫거나 항목을 선택하고 편집해 보세요. 오버레이는 키보드로 조작할 수 있는지, 닫은 뒤 포커스가 돌아오는지도 확인하세요.
2. 뷰포트 가장자리 부근에서의 배치와 좁은 레이아웃, 스크롤되는 콘텐츠에서의 동작을 확인하세요.
3. 배포할 폴백을 확인하세요. 애니메이션 생략은 허용할 수 있지만, 열기 핸들러가 빠지거나 필수 안내가 표시할 수 없는 툴팁에만 들어 있어서는 안 됩니다.

필수 안내는 화면에 보이는 텍스트로 제공하세요. 컨트롤 자체에 이름이 있고 용도가 분명할 때만 툴팁을 생략해도 사용할 수 있습니다.

## 사용자 설정 및 기기 \{#preferences-and-devices\}

브라우저의 기능 지원 여부와 함께 사용자의 기기와 설정도 고려합니다. 각 스타일시트는 컴포넌트에서 조정할 부분이 있을 때 사용자의 기기와 설정에 해당하는 쿼리에 응답합니다.

| 쿼리 | 변경 사항 |
| --- | --- |
| `(hover: hover)` | 호버 상태를 이 쿼리 안에서 정의하므로 포인터로 호버할 수 있는 환경에서만 적용됩니다. 터치한 뒤에는 컨트롤에 호버 상태가 남지 않습니다 |
| `(pointer: coarse)` | 조작 대상이 44px로 커집니다. 버튼의 최소 높이는 `2.75rem`이 되고, 체크박스 라벨의 조작 영역은 텍스트 줄을 중심으로 넓어지며 주변 요소의 위치는 그대로 유지됩니다 |
| `(prefers-reduced-motion: reduce)` | 컨트롤이 떠오르는 효과, 오버레이의 크기 변화와 슬라이드, 표시기의 부드러운 이동을 없앱니다. 페이드 효과는 유지되어 상태 변화를 눈으로 확인할 수 있습니다 |
| `(forced-colors: active)` | 브라우저가 그림자를 제거하고 색상을 대체하므로 `ButtonText`, `CanvasText`, `Highlight` 같은 시스템 색상으로 윤곽선과 채우기를 적용해 경계와 상태를 다시 표시합니다 |
| `(prefers-contrast: more)` | 테마는 가는 선, 구분선, 외곽선에 쓰이는 디자인 토큰과 강조를 낮춘 전경색 및 비활성 전경색을 더 뚜렷하게 조정합니다. 이 토큰을 참조하는 컴포넌트에 변경 사항이 적용됩니다 |
| `(prefers-reduced-transparency: reduce)` | [내비게이션 바](/components/navbar)와 [탭 바](/components/tabbar)의 유리 효과가 흐림 없는 불투명 표면으로 바뀝니다 |

테마 색상은 색 구성표에 따라 값이 달라지는 곳에 `light-dark()` 함수를 사용하며 페이지나 하위 트리의 `color-scheme`을 따릅니다. [기본 테마](/guide/theme#color-schemes)를 참고하세요.

## 독립형 스타일시트 \{#standalone\}

`@master/ui/standalone.css`는 Master CSS를 사용하지 않는 프로젝트를 위해 같은 소스를 일반 CSS로 컴파일한 파일입니다. 연결 방법은 [설치](/guide/installation#without-master-css)를 참고하세요.

```css name=app.css
@import '@master/ui/standalone.css';
```

컴파일 과정에서 믹스인을 풀어 쓰고 디자인 토큰을 사용자 지정 속성으로 출력합니다. CSS 기능은 이전 문법으로 변환하지 않습니다. 파일은 같은 캐스케이드 레이어를 선언하고 중첩 구조와 `light-dark()`, `oklch()` 함수를 유지하며 동일한 `@supports` 규칙을 포함합니다. 지원 요건과 폴백은 이 페이지에 설명된 내용과 같습니다. `@master/ui/dist/themes/paper.css`처럼 컴파일된 테마에도 같은 내용이 적용됩니다.

컴파일된 파일은 `color-scheme: light dark`도 선언하며 `data-theme="light"`와 `data-theme="dark"` 설정을 지원합니다. 이후에 다른 빌드 도구가 CSS를 변환한다면 애플리케이션이 실제로 제공하는 CSS를 테스트하세요.
