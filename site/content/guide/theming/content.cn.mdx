主题为令牌赋值，并定义组件所读取的材质配方。你可以修改一个共享值、把它限定在页面的某一部分，或者在保留组件标记和行为的同时，替换整个界面的材质。

Moonstone 和 Obsidian 背后的材质选择请参阅[设计](/guide/design)。[默认主题](/guide/theme)记录了它们的令牌角色和值。若要判断某项修改应该放在主题中还是组件中，请先阅读[自定义](/guide/customization)。

## 调整令牌 \{#retune-tokens\}

在导入之后覆盖令牌。所有读取它的组件都会随之改变。

```css name=app.css
@import '@master/css';
@import '@master/ui';

@theme {
  --color-brand: oklch(58% .19 28);
  --color-brand-ink: oklch(99% .01 28);
  --radius-control: .5rem;
}
```

这会修改品牌表面和默认的控件圆角。小型和大型控件使用各自的圆角令牌。请对照新的底色检查 `--color-brand-ink`；品牌色文字使用单独的 `--color-brand-text` 令牌，不会自动采用新的色相。

### 将覆盖限定在一个区域 \{#scope\}

令牌是自定义属性，因此也会层叠。在某个元素上设置令牌，即可重新调整其后代元素，无需再次构建。下面的示例中，结账区域内的两个按钮继承了较小的圆角，而该区域之外的按钮保留默认值：

### 保持圆形圆角 \{#circular-corners\}

默认主题在浏览器支持时使用连续曲率圆角。若要在所有地方保持圆形圆角，请同时设置这两个圆角属性：

```css name=app.css
:root {
  --corner-shape: round;
  --corner-scale: 1;
}
```

在 `@theme` 中声明的令牌也可以作为工具类使用：`bg-surface-tray` 和 `shadow-lifted` 能让自定义元素获得与组件相同的材质。导入 Master UI 会把预设中共享的语义令牌设为默认主题；覆盖会同时重新调整读取这些令牌的组件和工具类。

## 主题决定什么 \{#what-a-theme-decides\}

构建主题时可以使用这份检查清单。[默认主题](/guide/theme)解释了令牌的角色及其默认值。

| 决定 | 令牌 |
| --- | --- |
| 每个表面的色调 | `--color-surface-base`、`-tray`、`-raised`、`-raised-low`、`-inset`、`-inset-hover`、`-floating`、`-chip`、`-inverse`、`-scrim` |
| 每种线条的明显程度 | `--color-line-hair`、`-contour`、`-divider`、`-strong`、`-mark` |
| 墨色 | `--color-text-strong`、`-body`、`-muted`、`-disabled`、`-inverse`、`--color-focus`、`--color-focus-halo` |
| 光线落在哪里 | `--color-highlight`、`--color-lip`、`--color-shade-1` 到 `-5` |
| 深度 | `--shadow-pressed`、`-flat`、`-raised`、`-raised-hover`、`-lifted`、`-floating`、`-overlay` |
| 墨色表面 | `--color-surface-inverse-high`、`-low`、`--color-ink-high`、`-low`、它们的 `-hover` 形式、`--color-ink-pressed`、`--color-ink-highlight`、`--color-ink-edge`、`--shadow-ink`、`-ink-hover`、`-ink-pressed`、`-ink-mark`、`-ink-well`、`-ink-top`、`--color-surface-tip`、`--shadow-tip` |
| 滑块 | `--color-thumb-high`、`-low`、`--color-thumb-on-high`、`-on-low`、`--shadow-thumb-on-ink` |
| 色相 | `--color-brand`、`-brand-ink`、`-brand-text`、`--color-info`、`-success`、`-warning`、`-danger`、`--color-tone-highlight`、`-tone-highlight-soft` |
| 图片与外部提供的颜色 | `--color-line-image`、`-image-strong`、`--color-line-on-color`、`--color-highlight-on-color`、`--color-on-image`、`-on-image-shade`、`--color-mark`、`-mark-underline`、`--color-sheen` |
| 形状 | `--radius-chip`、`-control-sm`、`-control`、`-control-lg`、`-surface`、`--corner-shape`、`--corner-scale` |
| 位移与时间 | `--lift`、`--duration-press`、`-quick`、`-base`、`--easing-glide` |
| 字体 | `--font-weight-control`，以及预设的 `--font-sans` 和 `--font-mono` |

软件包中的一项测试会拒绝组件样式表中的颜色字面量，使组件的颜色始终由主题控制。检查完整的令牌和配方时，请以已安装的 `@master/ui/theme.css` 为准。

## Paper：第二个主题 \{#paper\}

Paper 发布在 `@master/ui/themes/paper.css` 中。它把默认材质替换为扁平的表面、描线的边缘、更紧凑的圆形圆角、暖色调的中性色和绿色的品牌色。它的 `--lift: 0px` 移除了由该令牌驱动的悬停和按下位移；开关滑块移动之类的组件动画仍然正常运作。它没有修改任何组件样式表。

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import '@master/ui/themes/paper.css';
```

### 创建主题文件 \{#create-a-theme\}

如果想要一个扁平的起点，请从已安装的软件包中复制 Paper；如果想以默认材质为起点，请复制 `theme.css`：

```bash
mkdir -p themes
cp node_modules/@master/ui/themes/paper.css themes/app.css
```

在库之后导入你的文件，然后编辑其中的令牌和配方：

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import './themes/app.css';
```

使用现有的 Master CSS 集成重新构建。组件标记保持不变；在把主题应用到整个应用之前，请在两种配色方案中比较按钮、字段、墨色表面和浮层。

## 配方 \{#recipes\}

有些材质不止一个值：带有光线衰减的表面，在每种状态下都有对应表面的控件。主题把这些写成 mixin，组件按名称应用它们。主题文件可以重新定义某个 mixin；最后一个定义就是所有组件得到的版本。

| Mixin | 绘制什么 | Paper |
| --- | --- | --- |
| `--surface-sheet` | 凸起的表面 | 扁平，通过 `--color-surface-raised-low` |
| `--surface-ink` | 墨色面板：反色面板、已发送的消息 | 扁平，通过 `-inverse-high` 和 `-low` 令牌 |
| `--control-ink`、`-hover`、`-pressed` | 主要按钮在各状态下的表面和阴影 | 扁平，通过墨色令牌 |
| `--control-tone`、`-hover`、`-pressed` | 带色相的控件，根据控件自身的 `--tone` 混合而成 | 重新定义：单一的扁平色相 |
| `--surface-thumb` | 开关和滑动条的滑块 | 扁平，通过滑块令牌 |
| `--focus-ring` | 键盘焦点 | 未改变 |
| `--on-ink` | 墨色表面告知其内部行内标签的内容 | 未改变 |
| `--anchored`、`--pop` | 弹出层的位置，以及它如何进入和离开 | 未改变 |

优先使用令牌。Paper 只重新定义了带色调的控件，因为这个配方根据控件在自身上设置的色相来混合其表面，而根元素上的令牌无法读取该色相。

令牌是自定义属性，在运行时作用于任何元素。mixin 在 Master CSS 编译样式表时解析，因此重新定义的 mixin 会作用于整个构建。

## 不使用 Master CSS \{#without-master-css\}

该软件包还提供了每个主题与组件一起编译成的普通 CSS。CSS 打包工具可以从已安装的软件包中导入 Paper；用它代替默认的独立样式表：

```css name=app.css
@import '@master/ui/dist/themes/paper.css';

:root {
  --color-brand: oklch(58% .19 28);
}
```

对于不使用打包工具的页面，请把这个编译后的文件作为静态资源提供；重置样式和工具类方面的限制请参阅[安装](/guide/installation#without-master-css)。`dist/standalone.css` 包含 moonstone 和 obsidian。编译后的文件可以接受自定义属性的覆盖，但重新定义 mixin 需要用 Master CSS 编译主题。

## 主题的规则 \{#rules\}

- **主题从不选择组件。** 它设置令牌并定义 mixin。主题中像 `.btn { … }` 这样的规则属于组件覆盖；它应该放在哪里请参阅[自定义](/guide/customization)。
- **成对考虑。** 表面与其上的墨色、线条与其下方的表面，都要一起选择。请在两种配色方案中，检查每个表面上正文文字的对比度。
- **让边缘保持可辨。** 如果主题去掉了光影，边界就更多地依靠线条来表达。Paper 使用更明显的线条令牌，并针对每个角色和配色方案分别调校。
- **不绘制任何内容的阴影令牌应写为 `0 0 0 0 transparent`，而不是 `none`。** 组件以列表形式组合阴影，而 `none` 在列表中无效。
- **响应对更高对比度的请求。** 在 `prefers-contrast: more` 下，主题会加强其线条以及两种较淡的墨色；自行设置线条的主题也要编写这一块，就像 Paper 那样。修改配方时，请保留组件在强制颜色和减少动态效果模式下的行为。

请在浅色和深色模式下，通过键盘焦点、悬停、按下、禁用的控件和无效的字段来检查结果。在页面上打开菜单或对话框，对照实际的背景判断其边缘和文字。再在减少动态效果和强制颜色模式下重复检查：静止时看起来清晰的主题，仍然可能隐藏某个状态，或移除唯一可见的边界。
