主题为令牌赋值，并定义组件读取的材质配方。可以调整一个共享值，将调整限定在页面的某个区域，也可以在保留组件标记和行为的情况下替换整个界面的材质。

## 调整令牌 \{#retune-tokens\}

在导入语句之后覆盖令牌。所有读取该令牌的组件都会随之更新。

```css name=app.css
@import '@master/css';
@import '@master/ui';

@theme {
  --color-brand: oklch(58% .19 28);
  --color-brand-ink: oklch(99% .01 28);
  --radius-control: .5rem;
}
```

这会更改品牌色表面和控件的默认圆角半径。小号和大号控件各有自己的圆角半径令牌。请在新的表面颜色下检查 `--color-brand-ink` 的表现。品牌色文字使用独立的 `--color-brand-text` 令牌，需要单独调整才能采用新色相。

### 保留圆弧圆角 \{#circular-corners\}

浏览器支持时，默认主题使用连续曲率圆角。要让整个界面都使用圆弧圆角，请同时设置这两个圆角属性：

```css name=app.css
:root {
  --corner-shape: round;
  --corner-scale: 1;
}
```

`@theme` 中声明的令牌也可以通过工具类使用。`bg-surface-tray` 和 `shadow-lifted` 让自定义元素使用与组件相同的材质。导入 Master UI 后，预设的共享语义令牌采用默认主题的取值。覆盖令牌会同时调整读取它的组件和工具类。

## 主题决定哪些内容 \{#what-a-theme-decides\}

构建主题时可参照这份清单。令牌的用途和默认值见[默认主题](/guide/theme)。

| 设置项 | 令牌 |
| --- | --- |
| 各表面的色调 | `--color-surface-base`, `-tray`, `-raised`, `-raised-low`, `-inset`, `-inset-hover`, `-floating`, `-chip`, `-inverse`, `-scrim` |
| 各线条的清晰度 | `--color-line-hair`, `-contour`, `-divider`, `-strong`, `-mark` |
| 墨色 | `--color-text-strong`, `-body`, `-muted`, `-disabled`, `-inverse`, `--color-focus`, `--color-focus-halo` |
| 受光位置 | `--color-highlight`、`--color-lip`、`--color-shade-1` 至 `-5` |
| 层次 | `--shadow-pressed`, `-flat`, `-raised`, `-raised-hover`, `-lifted`, `-floating`, `-overlay` |
| 墨色表面 | `--color-surface-inverse-high`、`-low`、`--color-ink-high`、`-low` 及其 `-hover` 形式、`--color-ink-pressed`、`--color-ink-highlight`、`--color-ink-edge`、`--shadow-ink`、`-ink-hover`、`-ink-pressed`、`-ink-mark`、`-ink-well`、`-ink-top`、`--color-surface-tip`、`--shadow-tip` |
| 滑块 | `--color-thumb-high`, `-low`, `--color-thumb-on-high`, `-on-low`, `--shadow-thumb-on-ink` |
| 色相 | `--color-brand`, `-brand-ink`, `-brand-text`, `--color-info`, `-success`, `-warning`, `-danger`, `--color-tone-highlight`, `-tone-highlight-soft` |
| 图片与传入的颜色 | `--color-line-image`, `-image-strong`, `--color-line-on-color`, `--color-highlight-on-color`, `--color-on-image`, `-on-image-shade`, `--color-mark`, `-mark-underline`, `--color-sheen` |
| 形状 | `--radius-chip`, `-control-sm`, `-control`, `-control-lg`, `-surface`, `--corner-shape`, `--corner-scale` |
| 位移与时长 | `--lift`, `--duration-press`, `-quick`, `-base`, `--easing-glide` |
| 字体排印 | `--font-weight-control`，以及预设的 `--font-sans` 和 `--font-mono` |

如果组件样式表包含颜色字面值，包的测试就会失败，以确保组件颜色由主题控制。要查阅完整的令牌和配方，以已安装的 `@master/ui/theme.css` 为准。

## 另一个主题 Paper \{#paper\}

Paper 随 `@master/ui/themes/paper.css` 发布。它将默认材质换成平坦的表面、线条勾勒的边缘、半径更小的圆弧圆角和暖调中性色，并采用绿色作为品牌色。它的 `--lift: 0px` 取消由该令牌控制的悬停和按压位移，开关滑块移动等组件动画仍然有效。Paper 不改动任何组件样式表。

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import '@master/ui/themes/paper.css';
```

### 创建主题文件 \{#create-a-theme\}

要从平面材质入手，请从已安装的包中复制 Paper。要以默认材质为基础，请复制 `theme.css`：

```bash
mkdir -p themes
cp node_modules/@master/ui/themes/paper.css themes/app.css
```

先导入库，再导入自己的主题文件，然后编辑该文件中的令牌和材质配方：

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import './themes/app.css';
```

用现有的 Master CSS 集成重新构建。组件标记保持不变。在整个应用中启用主题前，先在浅色和深色模式下对照检查按钮、输入字段、墨色表面和浮层。

## 材质配方 \{#recipes\}

有些材质需要多个值共同定义，例如带有光照渐变的表面，或各个状态下表面不同的控件。主题用混入定义这些配方，组件按名称应用。主题文件可以重新定义混入，所有组件都使用最后一次定义。

| 混入 | 绘制内容 | Paper |
| --- | --- | --- |
| `--surface-sheet` | 凸起的表面 | 通过 `--color-surface-raised-low` 呈现平面效果 |
| `--surface-ink` | 墨色表面，例如反色面板或已发送的消息 | 通过 `-inverse-high` 和 `-low` 令牌呈现平面效果 |
| `--control-ink`, `-hover`, `-pressed` | 主按钮在各状态下的表面和阴影 | 通过墨色令牌呈现平面效果 |
| `--control-tone`, `-hover`, `-pressed` | 带色调的控件，以控件自身的 `--tone` 为基础混色 | 重新定义为单一纯色 |
| `--surface-thumb` | 开关和滑动条的滑块 | 通过滑块令牌呈现平面效果 |
| `--focus-ring` | 键盘焦点 | 保持不变 |
| `--on-ink` | 墨色表面传给其中行内标签的样式信息 | 保持不变 |
| `--anchored`, `--pop` | 弹出层的位置及其进出场效果 | 保持不变 |

优先使用主题令牌。Paper 只重新定义带色调控件的混入，因为配方用控件自身设置的色相混出表面颜色，而根元素上的令牌无法读取该色相。

主题令牌是 CSS 自定义属性，可在运行时用于任何元素。Master CSS 编译样式表时会解析混入，因此重新定义的混入对整个构建生效。

## 不使用 Master CSS \{#without-master-css\}

包中也提供各个主题与组件一起编译得到的纯 CSS。CSS 打包工具可以从已安装的包中导入 Paper，用它替换默认的独立样式表：

```css name=app.css
@import '@master/ui/dist/themes/paper.css';

:root {
  --color-brand: oklch(58% .19 28);
}
```

页面没有使用打包工具时，可将编译后的文件作为静态资源提供。样式重置和工具类的使用限制见[安装](/guide/installation#without-master-css)。`dist/standalone.css` 包含 Moonstone 和 Obsidian。编译后的文件支持覆盖自定义属性，重新定义混入则需要用 Master CSS 编译主题。

## 主题编写规则 \{#rules\}

- **主题中禁止使用组件选择器。** 主题负责设置令牌和定义混入。主题中形如 `.btn { … }` 的规则属于组件样式覆盖，应该写在哪里可参阅[自定义](/guide/customization)。
- **成对选取颜色。** 表面与其上的墨色要一起选定，线条与其下方的表面也一样。在浅色和深色模式下，检查正文在各个表面上的对比度。
- **让边界清晰可辨。** 如果主题去掉了光影，边界就更依赖线条来界定。Paper 使用更醒目的线条令牌，并按用途和配色模式分别调整。
- **用 `0 0 0 0 transparent` 表示不可见的阴影令牌，避免使用 `none`。** 组件通过列表组合多个阴影，`none` 在列表中是无效值。
- **响应更高对比度的偏好。** 在 `prefers-contrast: more` 下，主题会增强线条和两种低强调度墨色的对比度。如果主题自行设置了线条，也要像 Paper 一样编写这个规则块。修改材质配方时，保留组件在强制颜色和减少动态效果模式下的行为。

在浅色和深色模式下，检查键盘聚焦、悬停、按下、禁用控件和无效字段的效果。在页面上打开菜单或对话框，结合实际背景检查边缘和文字是否清晰。启用减少动态效果和强制颜色后再检查一遍。静止时看起来清晰的主题，仍可能让某个状态难以辨认，或使唯一可见的边界消失。
