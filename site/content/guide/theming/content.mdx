A theme gives values to the tokens and defines the material recipes that components read. You can change one shared value, limit it to part of a page, or replace the material across the interface while keeping the component markup and behavior.

For the design principles and token values of moonstone and obsidian, see [Default theme](/guide/theme). To decide whether a change belongs in a theme or in a component, start with [Customization](/guide/customization).

## Retune tokens \{#retune-tokens\}

Override a token after the import. Every component that reads it follows.

```css name=app.css
@import '@master/css';
@import '@master/ui';

@theme {
  --color-brand: oklch(58% .19 28);
  --color-brand-ink: oklch(99% .01 28);
  --radius-control: .5rem;
}
```

This changes brand surfaces and the default control radius. Small and large controls use their own radius tokens. Check `--color-brand-ink` against the new face; brand-colored text uses the separate `--color-brand-text` token and does not automatically take the new hue.

### Keep circular corners \{#circular-corners\}

The default theme uses continuous corners where supported. To keep circular corners everywhere, set both corner properties:

```css name=app.css
:root {
  --corner-shape: round;
  --corner-scale: 1;
}
```

Tokens declared in `@theme` are also available as utilities: `bg-surface-tray` and `shadow-lifted` give custom elements the same materials as components. Importing Master UI sets the preset's shared semantic tokens to the default theme; overrides retune both components and utilities that read them.

## What a theme decides \{#what-a-theme-decides\}

Use this checklist when building a theme. [Default theme](/guide/theme) explains the token roles and their default values.

| Decision | Tokens |
| --- | --- |
| The tone of each surface | `--color-surface-base`, `-tray`, `-raised`, `-raised-low`, `-inset`, `-inset-hover`, `-floating`, `-chip`, `-inverse`, `-scrim` |
| How firm each line is | `--color-line-hair`, `-contour`, `-divider`, `-strong`, `-mark` |
| The inks | `--color-text-strong`, `-body`, `-muted`, `-disabled`, `-inverse`, `--color-focus`, `--color-focus-halo` |
| Where the light falls | `--color-highlight`, `--color-lip`, `--color-shade-1` to `-5` |
| Depth | `--shadow-pressed`, `-flat`, `-raised`, `-raised-hover`, `-lifted`, `-floating`, `-overlay` |
| A face of ink | `--color-surface-inverse-high`, `-low`, `--color-ink-high`, `-low`, their `-hover` forms, `--color-ink-pressed`, `--color-ink-highlight`, `--color-ink-edge`, `--shadow-ink`, `-ink-hover`, `-ink-pressed`, `-ink-mark`, `-ink-well`, `-ink-top`, `--color-surface-tip`, `--shadow-tip` |
| A thumb | `--color-thumb-high`, `-low`, `--color-thumb-on-high`, `-on-low`, `--shadow-thumb-on-ink` |
| Hue | `--color-brand`, `-brand-ink`, `-brand-text`, `--color-info`, `-success`, `-warning`, `-danger`, `--color-tone-highlight`, `-tone-highlight-soft` |
| Pictures and supplied colors | `--color-line-image`, `-image-strong`, `--color-line-on-color`, `--color-highlight-on-color`, `--color-on-image`, `-on-image-shade`, `--color-mark`, `-mark-underline`, `--color-sheen` |
| Shape | `--radius-chip`, `-control-sm`, `-control`, `-control-lg`, `-surface`, `--corner-shape`, `--corner-scale` |
| Travel and time | `--lift`, `--duration-press`, `-quick`, `-base`, `--easing-glide` |
| Type | `--font-weight-control`, and the preset's `--font-sans` and `--font-mono` |

A package test rejects color literals in component stylesheets, keeping their colors under the theme's control. Use the installed `@master/ui/theme.css` as the source when checking the full set of tokens and recipes.

## Paper, a second theme \{#paper\}

Paper is published in `@master/ui/themes/paper.css`. It replaces the default material with flat faces, ruled edges, tighter circular corners, warm neutrals and a green brand. Its `--lift: 0px` removes the hover and press travel driven by that token; component animations such as a switch thumb moving still work. It changes no component stylesheet.

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import '@master/ui/themes/paper.css';
```

### Start a theme file \{#create-a-theme\}

Copy Paper from the installed package when you want a flat starting point, or copy `theme.css` to retain the default material as your starting point:

```bash
mkdir -p themes
cp node_modules/@master/ui/themes/paper.css themes/app.css
```

Import your file after the library, then edit its tokens and recipes:

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import './themes/app.css';
```

Rebuild with your existing Master CSS integration. The component markup stays the same; compare a button, a field, an ink surface and an overlay in both color schemes before applying the theme throughout the app.

## Recipes \{#recipes\}

A few materials are more than one value: a face with its fall of light, a control with a face for each state. The theme writes these as mixins, and a component applies them by name. A theme file may define a mixin again; the last definition is the one every component gets.

| Mixin | What it draws | Paper |
| --- | --- | --- |
| `--surface-sheet` | A raised face | Flat, through `--color-surface-raised-low` |
| `--surface-ink` | A sheet of ink: an inverse sheet, a sent message | Flat, through the `-inverse-high` and `-low` tokens |
| `--control-ink`, `-hover`, `-pressed` | The primary button's face and shadow in each state | Flat, through the ink tokens |
| `--control-tone`, `-hover`, `-pressed` | A hued control, mixed from the control's own `--tone` | Redefined: one flat hue |
| `--surface-thumb` | The thumb of a switch and a slider | Flat, through the thumb tokens |
| `--focus-ring` | Keyboard focus | Unchanged |
| `--on-ink` | What an ink surface tells the inline chips it holds | Unchanged |
| `--anchored`, `--pop` | Where a popover stands, and how it enters and leaves | Unchanged |

Reach for a token first. Paper redefines only the toned control, because that recipe mixes its face from a hue the control sets on itself, which a token at the root cannot read.

Tokens are custom properties and work at run time, on any element. Mixins are resolved when Master CSS compiles the stylesheet, so a redefined mixin applies to the whole build.

## Without Master CSS \{#without-master-css\}

The package also ships each theme compiled with the components into plain CSS. A CSS bundler can import Paper from the installed package; use this in place of the default standalone stylesheet:

```css name=app.css
@import '@master/ui/dist/themes/paper.css';

:root {
  --color-brand: oklch(58% .19 28);
}
```

For a page without a bundler, serve that compiled file from your static assets; see [Installation](/guide/installation#without-master-css) for the reset and utility limitations. `dist/standalone.css` contains moonstone and obsidian. A compiled file accepts custom-property overrides, but redefining a mixin requires compiling a theme with Master CSS.

## Rules for a theme \{#rules\}

- **A theme never selects a component.** It sets tokens and defines mixins. A rule such as `.btn { … }` in a theme is a component override; see [customization](/guide/customization) for where that belongs.
- **Keep the pairs.** A surface and the ink on it, a line and the surface under it, are chosen together. Check body text on every surface for contrast, in both color schemes.
- **Keep the edges findable.** If a theme removes light and shade, its lines carry more of the boundary. Paper uses firmer line tokens, tuned separately for each role and color scheme.
- **A shadow token that draws nothing is `0 0 0 0 transparent`, not `none`.** Components compose shadows in lists, and `none` is not valid inside one.
- **Answer a request for more contrast.** The theme firms its lines and its two quiet inks under `prefers-contrast: more`; a theme that sets its own lines writes that block too, as Paper does. Preserve the components' forced-color and reduced-motion behavior when changing recipes.

Check the result with keyboard focus, hover, press, disabled controls and invalid fields, in light and dark. Open a menu or dialog over the page to judge its edge and text against the actual backdrop. Repeat with reduced motion and forced colors: a theme that looks clear at rest can still hide a state or remove the only visible boundary.
