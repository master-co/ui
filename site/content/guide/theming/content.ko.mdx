테마는 토큰에 값을 지정하고 컴포넌트가 참조하는 표면 스타일 조합을 정의합니다. 컴포넌트의 마크업과 동작을 그대로 유지하면서 공유 값 하나를 바꾸거나, 변경 범위를 페이지 일부로 제한하거나, 인터페이스 전체의 표면 스타일을 교체할 수 있습니다.

Moonstone과 Obsidian의 표면 스타일을 어떻게 정했는지는 [디자인](/guide/design)을 참고하세요. [기본 테마](/guide/theme)에서는 각 토큰의 역할과 값을 설명합니다. 변경 사항을 테마와 컴포넌트 중 어디에 적용할지 판단하려면 [사용자 지정](/guide/customization)부터 살펴보세요.

## 토큰 값 조정 \{#retune-tokens\}

가져오기 구문 뒤에서 토큰 값을 재정의하세요. 해당 토큰을 참조하는 모든 컴포넌트에 새 값이 적용됩니다.

```css name=app.css
@import '@master/css';
@import '@master/ui';

@theme {
  --color-brand: oklch(58% .19 28);
  --color-brand-ink: oklch(99% .01 28);
  --radius-control: .5rem;
}
```

이렇게 하면 브랜드색 표면과 컨트롤의 기본 모서리 반경이 바뀝니다. 작은 컨트롤과 큰 컨트롤은 크기별 반경 토큰을 사용합니다. 새 표면 위에서 `--color-brand-ink` 색상이 어떻게 보이는지 확인하세요. 브랜드색 텍스트는 별도의 `--color-brand-text` 토큰을 사용하므로 새 색상이 자동으로 적용되지 않습니다.

### 특정 영역에만 적용하는 재정의 \{#scope\}

토큰은 사용자 지정 속성이므로 캐스케이드의 적용을 받습니다. 요소에 토큰 값을 지정하면 다시 빌드할 필요 없이 하위 요소의 스타일을 조정할 수 있습니다. 이 예에서 결제 영역의 두 버튼은 더 작은 반경을 상속하고, 영역 밖의 버튼은 기본값을 유지합니다.

### 원호형 모서리 유지 \{#circular-corners\}

기본 테마는 지원되는 환경에서 연속 곡선형 모서리를 사용합니다. 모든 환경에서 원호형 모서리를 유지하려면 모서리 속성 두 개를 모두 설정하세요.

```css name=app.css
:root {
  --corner-shape: round;
  --corner-scale: 1;
}
```

`@theme`에 선언된 토큰은 유틸리티로도 사용할 수 있습니다. `bg-surface-tray`와 `shadow-lifted`를 사용하면 사용자 지정 요소에 컴포넌트와 같은 표면 스타일을 적용할 수 있습니다. Master UI를 가져오면 프리셋의 공유 시맨틱 토큰에 기본 테마 값이 설정됩니다. 토큰을 재정의하면 이를 참조하는 컴포넌트와 유틸리티가 모두 바뀝니다.

## 두 번째 테마 Paper \{#paper\}

Paper는 `@master/ui/themes/paper.css`에 배포됩니다. 기본 표면 스타일을 평평한 표면, 선으로 구분한 테두리, 반경이 더 작은 원호형 모서리, 따뜻한 중성색, 녹색 브랜드색으로 바꿉니다. Paper는 `--lift: 0px`을 지정해 이 토큰으로 제어하는 호버 및 누름 시의 이동을 없앱니다. 스위치 손잡이의 이동 같은 컴포넌트 애니메이션은 계속 동작합니다. 컴포넌트 스타일시트는 그대로 유지됩니다.

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import '@master/ui/themes/paper.css';
```

### 테마 파일 만들기 \{#create-a-theme\}

평평한 표면 스타일에서 시작하려면 설치된 패키지에서 Paper를 복사하세요. 기본 표면 스타일에서 시작하려면 `theme.css` 파일을 복사하세요.

```bash
mkdir -p themes
cp node_modules/@master/ui/themes/paper.css themes/app.css
```

라이브러리 뒤에서 테마 파일을 가져온 다음, 파일의 토큰과 스타일 조합을 수정하세요.

```css name=app.css
@import '@master/css';
@import '@master/ui';
@import './themes/app.css';
```

기존 Master CSS 연동 방식으로 다시 빌드하세요. 컴포넌트 마크업은 그대로 유지됩니다. 앱 전체에 테마를 적용하기 전에 두 색상 모드에서 버튼, 입력 필드, 잉크색 표면, 오버레이를 비교하세요.

## 표면 스타일 조합 \{#recipes\}

빛이 닿는 효과를 더한 표면이나 상태별로 표면이 달라지는 컨트롤처럼, 여러 값이 필요한 스타일도 있습니다. 테마는 이런 조합을 믹스인으로 정의하고, 컴포넌트는 이름으로 믹스인을 적용합니다. 테마 파일에서 믹스인을 재정의하면 모든 컴포넌트에 마지막 정의가 적용됩니다.

| 믹스인 | 표현 대상 | Paper |
| --- | --- | --- |
| `--surface-sheet` | 한 층 위로 올라온 표면 | `--color-surface-raised-low` 토큰으로 평면 표현 |
| `--surface-ink` | 잉크색 표면: 반전된 표면, 보낸 메시지 | `-inverse-high`와 `-low` 토큰으로 평면 표현 |
| `--control-ink`, `-hover`, `-pressed` | 주요 버튼의 상태별 표면과 그림자 | 잉크 토큰을 통한 평면 표현 |
| `--control-tone`, `-hover`, `-pressed` | 컨트롤 자체의 `--tone`을 혼합해 색을 입힌 컨트롤 | 균일한 단색으로 재정의 |
| `--surface-thumb` | 스위치와 슬라이더의 손잡이 | 손잡이 토큰을 통한 평면 표현 |
| `--focus-ring` | 키보드 포커스 | 변경 없음 |
| `--on-ink` | 잉크 표면이 내부 인라인 칩에 전달하는 값 | 변경 없음 |
| `--anchored`, `--pop` | 팝오버의 위치와 표시·숨김 동작 | 변경 없음 |

먼저 디자인 토큰을 사용하세요. Paper는 색조가 적용된 컨트롤의 믹스인만 재정의합니다. 이 믹스인은 컨트롤이 자체적으로 설정한 색상을 섞어 표면색을 만들며, 루트에 정의된 토큰에서는 그 색상 값을 참조할 수 없습니다.

디자인 토큰은 사용자 지정 속성이므로 런타임에 모든 요소에서 사용할 수 있습니다. 믹스인은 Master CSS가 스타일시트를 컴파일할 때 처리되므로, 재정의한 믹스인은 빌드 전체에 적용됩니다.

## Master CSS 없이 테마 사용 \{#without-master-css\}

패키지에는 각 테마를 컴포넌트와 함께 일반 CSS로 컴파일한 파일도 포함되어 있습니다. CSS 번들러에서 설치된 패키지의 Paper를 가져와 기본 독립형 스타일시트를 대신할 수 있습니다:

```css name=app.css
@import '@master/ui/dist/themes/paper.css';

:root {
  --color-brand: oklch(58% .19 28);
}
```

번들러를 사용하지 않는 페이지에서는 컴파일된 파일을 정적 자산으로 제공하세요. 리셋과 유틸리티의 제약 사항은 [설치](/guide/installation#without-master-css)를 참고하세요. `dist/standalone.css`에는 moonstone과 obsidian이 포함되어 있습니다. 컴파일된 파일에서도 사용자 지정 속성을 재정의할 수 있지만, 믹스인을 재정의하려면 Master CSS로 테마를 컴파일해야 합니다.

## 테마 작성 규칙 \{#rules\}

- **테마에서는 컴포넌트를 직접 선택하지 않습니다.** 테마는 디자인 토큰 값을 설정하고 믹스인을 정의합니다. 테마에 넣은 `.btn { … }` 같은 규칙은 컴포넌트 스타일을 덮어씁니다. 이런 규칙을 어디에 작성해야 하는지는 [사용자 지정](/guide/customization)을 참고하세요.
- **서로 맞물리는 색상은 짝을 유지하세요.** 표면과 그 위에 쓰이는 잉크 색상, 경계선과 그 아래 깔린 표면 색상은 각각 함께 정합니다. 밝은 색상 구성과 어두운 색상 구성 모두에서 모든 표면의 본문 텍스트 대비를 확인하세요.
- **경계를 쉽게 알아볼 수 있게 하세요.** 테마에서 명암을 없애면 경계선이 경계를 구분하는 역할을 더 많이 맡습니다. Paper는 경계선이 더 뚜렷하게 보이는 디자인 토큰을 사용하며, 역할과 색상 구성에 따라 값을 따로 조정합니다.
- **그림자를 표시하지 않는 그림자 토큰에는 `none` 대신 `0 0 0 0 transparent` 값을 사용하세요.** 컴포넌트는 여러 그림자를 목록으로 조합하며, 목록 안에서는 `none`이 유효하지 않습니다.
- **대비를 높여 달라는 사용자 설정을 반영하세요.** 테마는 `prefers-contrast: more` 조건에서 경계선과 대비가 낮은 두 잉크 색상을 더 뚜렷하게 표시합니다. 경계선을 자체 정의하는 테마라면 Paper처럼 이 블록도 작성하세요. 스타일 정의를 변경할 때는 강제 색상과 동작 줄이기 설정에서 컴포넌트가 보이는 기존 동작을 유지하세요.
