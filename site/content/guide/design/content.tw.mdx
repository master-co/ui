Master UI 的設計語言透過協調一致的表面、幾何與狀態，讓包含關係、層級與互動清楚可見。本指南說明這些選擇。[Master Design](https://design.master.co/principles) 涵蓋一般的設計原則；[預設主題](/guide/theme)則記載可執行的 token 與材質配方。

## 權責歸屬 \{#ownership\}

| 專案 | 負責 | 不負責 |
| --- | --- | --- |
| Master Design | 一般的設計原則、基礎、模式與驗證方法 | 另一份執行階段樣式表或元件 API |
| Master UI | 其設計語言與指引、元件契約、主題、可重用的樣式、行為與實作範例 | 產品特有的內容、路由或應用程式資料 |
| Master CSS | 樣式語法、編譯、執行階段傳遞與一般的預設原語 | 產品的互動決策 |
| Master | 品牌與生態系網站、共用的官方網站外殼與發布基礎設施 | 平行存在的可重用元件庫 |

使用端專案以 Master UI 處理可重用的呈現，以 Master CSS 處理局部組合。網站外殼負責組合導覽、文件與網站特有的呈現。設計透過文件指引這些實作，而不是透過執行階段的相依性。

## 原生行為與明確的契約 \{#native-behavior-and-explicit-contracts\}

從原生元素及其實際的狀態屬性開始。Master UI 的 class 描述受支援的標記；其契約記載公開的部件與狀態。視覺 class 不會補上缺少的鍵盤行為。當模式需要時，請使用隨附的行為或完整的框架整合。

不要仿照類似的元件庫自行發明修飾 class。撰寫標記前先閱讀目前的元件契約，然後執行 UI 檢查器，並測試渲染後的互動。靜態檢查無法證明焦點、語音播報或視覺對比是否正確。

## Moonstone 與 Obsidian \{#moonstone-and-obsidian\}

預設材質在淺色外觀使用 **Moonstone**，在深色外觀使用 **Obsidian**。兩者共用中性的 zinc 色彩詞彙，以及一致的假想光源：位於上方略偏左。Moonstone 透過表面上節制的變化、細緻的輪廓與短而漸淡的陰影，呈現淡淡的珍珠質感。Obsidian 則透過填色層次、受控的高光與清晰可讀的邊緣來區分深色表面；單純反轉 Moonstone 的色彩會失去這種區分。

目的是讓包含關係與互動清楚易讀，而不讓裝飾性的色彩與內容互相競爭。中性的光線與深度用來辨識一般表面；語意色相傳達狀態，而刻意使用的品牌強調色則標示畫面中的重要時刻。這些是 Master UI 的預設，並不是對其他專案識別的要求。只有在相關的欄位、動作或圖層仍容易找到時，安靜的材質才算成功。

請在同一頁面上，以兩種外觀檢視一個凸起的按鈕、一個欄位與一個開啟的選單。選單必須與其後方的內容區隔開來，欄位在取得焦點前就必須能辨認出來，弱化文字在其實際所在的表面上也必須清楚可讀。請以渲染後的尺寸與相關的顯示密度檢查細緻的輪廓；裝飾性的邊緣並不能證明重要控制項的邊界符合對比要求。可執行的材質、[線條角色](/guide/theme#lines)與[文字角色](/guide/theme#text)由[預設主題](/guide/theme)負責。

## 在材質階梯上選擇角色 \{#choose-a-role-on-the-material-ladder\}

依表面的用途選擇表面，再讓主題決定其外觀。這個階梯表達的是彼此的關係，而不是規定每個巢狀容器都必須更亮或更高。

| 角色 | 設計目的 | 可觀察的檢視重點 |
| --- | --- | --- |
| 底層畫布 | 承載頁面，而不必包住每個區段 | 移除裝飾性容器後，閱讀順序仍然清楚 |
| Tray | 將容納相關 sheet 的容器凹入後方 | 容器有助於分組，但不與其所含的 sheet 競爭 |
| 凸起的 sheet | 呈現有邊界的一段內容或可操作的表面 | 其邊緣與周遭環境區隔，但不會看起來像覆蓋層 |
| 內凹的凹槽 | 讓可編輯欄位、軌道或集合區域讀起來是被包含的 | 使用者在懸停之前就能找到該區域；焦點與無效狀態仍可區分 |
| 浮動表面 | 將選單或 popover 與其覆蓋的內容區隔開來 | 其邊界在淺色與深色內容上都清楚可讀，且不會被裁切 |
| 反轉墨色 | 賦予主要動作或已選標記強烈的視覺重量 | 標籤與較小的標記保有對比；數個互相競爭的墨色區域不會遮蔽主要任務 |

強制回應對話框還需要其背景遮罩與平台的分層行為。陰影無法建立堆疊順序，也無法阻擋與背景的互動。同樣地，凸起的 sheet 不代表自動可以點擊：請以語意、標籤與受支援的狀態處理來傳達動作。目前的契約與數值請參考[表面的實作](/components/surface)、[表面角色](/guide/theme#surfaces)、[高度層次角色](/guide/theme#elevation)與[反轉墨色](/guide/theme#ink)。

## 同心幾何與連續曲率圓角 \{#concentric-geometry-and-continuous-corners\}

巢狀的邊緣應描述同一種關係。容器的圓角由內部控制項與兩者之間的間距推導而來；內縮的子元素則由外圍表面推導其圓角。這能讓間隙在轉彎處看起來保持均勻。若在有內縮的情況下讓兩條邊緣使用相同的半徑，即使每個半徑單獨看來都還可以，也會造成擠壓或膨脹的轉角。

Master UI 將這種關係應用於 tray 與 sheet、分段控制的軌道與其已選選項、輸入群組中的按鈕，以及卡片中的媒體。請一併協調內縮距離、圓角角色與元件尺寸。一組邊緣不相符時，不要只調整某個孤立後代元素的圓角，調到截圖碰巧看起來正確為止。滑塊與頭像等真正的圓形則保留其自身的幾何。

在瀏覽器支援時，連續曲率圓角會讓直線邊緣與轉彎之間的過渡更柔和。主題負責協調圓角形狀與視覺上的圓潤程度；圓形圓角的備援方式仍必須看起來是刻意設計的，並保有相同的內容邊界。連續曲率是一種材質選擇，並非無障礙或正確性的要求。

請在每個受支援的尺寸、兩種外觀以及圓角備援方式下，檢視已選分段與輸入群組按鈕周圍的間隙。內縮應在視覺上保持均勻；文字與焦點指示器不得被裁切。請參考[形狀的實作](/guide/theme#shape)、[分段控制](/components/segmented)、[輸入群組](/components/input)與[卡片](/components/card)。底層的幾何推理請參閱[幾何](https://design.master.co/craft/geometry)。

## 在穩定的控制項上提供狀態回饋 \{#state-feedback-on-a-stable-control\}

在預設材質中，靜止狀態看起來是凸起的；在支援懸停的指標裝置上，懸停會加強表面的邊緣並使其浮起；按下時則沉向內凹的表面。這個變化確認了輸入，而不改變控制項在版面中所佔的空間。區別不應只靠色彩變化來傳達，而在觸控裝置上，懸停也不得是發現某個動作的唯一途徑。

請將焦點、選取、按下、驗證與可用性視為各自獨立的資訊。焦點標示下一次鍵盤輸入的去處；已選的分段或勾選記號則標示持續存在的值。無效的欄位也可以同時取得焦點。忙碌中的動作需要明確的進度回饋，其應用程式整合也必須防止非預期的重複送出。單靠停用的視覺處理，並不能實作停用的行為。

請檢視指標按下與放開、取消、鍵盤觸發、已選且取得焦點、無效且取得焦點、停用與忙碌等狀態。使用者的值與標籤應保持穩定，版面不應跳動，焦點也不得消失在材質之下。在減少動態效果時，即使沒有浮起或縮放，狀態也必須清楚可讀。在強制色彩模式下，即使失去裝飾性的陰影，重要的邊界與選取狀態也必須保留。請參閱[按鈕契約](/components/button)、[選取控制項](/components/segmented)、[動態效果的實作](/guide/theme#motion)與[行為的權責](/guide/behaviors)。

## Paper 展示另一種材質 \{#paper-demonstrates-a-different-material\}

**Paper** 是在相同元件契約下的另一套主題。它以溫暖的中性色、扁平的表面、以線條勾勒的邊緣與較小的圓形圓角，取代預設的方向性光線。懸停與按下不再透過共用的浮起設定而升起或下沉；有意義的元件移動，例如開關滑塊改變位置，則仍然保留。選單與對話框保有節制的深度線索，因為單靠線條邊緣可能無法說明覆蓋關係。

Paper 證明了可重用的元件在於其結構、行為與協調一致的角色，而不是 Moonstone 特有的表面質感。移除漸層與高光之後，線條與填色差異就要承擔更多責任。將每個角色都壓平成相同的表面，只會移除層級，而不會形成一致的平面主題。

請在 Paper 與預設主題中比較同一個按鈕、欄位、已選控制項、反轉 sheet 與開啟的覆蓋層。標記、無障礙名稱、值的歸屬與鍵盤行為應保持不變。在 Paper 的兩種色彩配置中，邊界、焦點與同時存在的狀態都必須保持可見；減少動態效果與強制色彩模式仍然適用。請以 [Paper 的實作與預覽](/guide/theming#paper)和[主題配方](/guide/theming#recipes)為參考，本指南不另外提供第二份 token 表格。

## 自訂的界線 \{#customization-boundaries\}

當整體材質都要改變時，請變更語意角色；當某個元件需要受支援的變化時，請變更有文件記載的元件自訂屬性；當只有頁面的排列改變時，請使用局部組合。完整的主題會協調表面、其前景墨色、線條、深度、圓角與狀態處理。單獨改變背景，可能讓繪製於其上的所有關係失效。

主題提供 token 與共用的材質配方；它不應累積用來改寫個別元件結構的選擇器。Paper 大多使用 token，僅對帶色相的控制項使用配方覆寫，因為該控制項的表面取決於其自身的色相。token 可以在執行階段限定作用範圍；配方定義則在編譯期間解析，並會影響建置結果。當某個提議的例外只應套用於一個區域時，這個區別就很重要。

自訂時請保留已發布的部件與原生語意。不要為了讓截圖更安靜而移除焦點或選取狀態，不要以品牌色作為錯誤的唯一提示，也不要假設視覺上較小的控制項仍有足夠的點擊目標。改變圓角形狀時需要一併調整與其協調的縮放比例；改變動態效果時必須保留易於理解的狀態回饋。超出元件文件記載行為的標籤、資料、驗證與焦點流程，仍由應用程式負責。

採用覆寫之前，請以真實內容、鍵盤輸入與較長的標籤，實際操作具代表性的按鈕、欄位、巢狀控制項與覆蓋層。請檢查兩種色彩配置、提高對比、減少動態效果與強制色彩模式。請參考[自訂](/guide/customization)、[主題規則](/guide/theming#rules)、[契約](/guide/contracts)與[瀏覽器支援](/guide/browser-support)；它們目前的 API 與支援限制仍具權威性。

## 元件、版面、區塊與頁面 \{#components-layouts-and-blocks\}

元件之所以擁有共用的契約，是因為其各部件必須協調材質、狀態、平台行為或幾何。版面在一個區域內安排空間，但不擁有其材質；版面原語與[元件](/components#layouts)列在一起。[區塊](/blocks)為頁面中的具體一段組合元件與版面。[頁面](/pages)則在 `page` 或 `shell` 框架上組合整個畫面，定義其區域與捲動方式。

不要將網站文案或一次性的主視覺排列提升為通用元件。反之，可重用的對話框、按鈕或欄位，也不應在網站外殼中有第二份實作。請將轉接層限制在實際的網站組合與相容性需求範圍內。

| 設計考量 | Master UI 參考 | 在使用端驗證 |

## 一起審視變更 \{#review-a-change-together\}

從相關的基礎與使用指引開始。在 Master UI 中變更實作，然後驗證一個具代表性的使用端頁面。當預期行為改變時，請更新文件。讓原始碼、範例、契約與測試保持一致；請記錄瀏覽器與輔助科技的限制，而不是把一張截圖當成全面的無障礙聲明。
