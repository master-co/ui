Master UI 的設計語言透過相互協調的表面、幾何形狀與狀態，讓容納關係、層級和互動一目了然。本指南說明這些設計選擇。[Master Design](https://design.master.co/principles) 涵蓋通用原則，[預設主題](/guide/theme) 則記載可直接使用的 token 與材質配方。

## 權責分工 \{#ownership\}

| 專案 | 負責範圍 | 不負責的事項 |
| --- | --- | --- |
| Master Design | 通用設計原則、設計基礎、模式與驗證方法 | 另一套執行階段樣式表或元件 API |
| Master UI | 自身的設計語言與指南、元件契約、主題、可重用樣式、行為及實作範例 | 特定產品的內容、路由或應用程式資料 |
| Master CSS | 樣式語法、編譯、執行階段載入與通用預設的基礎構件 | 產品的互動設計決策 |
| Master | 品牌與生態系網站、第一方網站共用的外層框架與發布基礎設施 | 另一套並行的可重用元件庫 |

採用者以 Master UI 提供可重用的呈現方式，並用 Master CSS 組合局部樣式。網站外層框架整合導覽、文件與網站專屬的呈現方式。設計透過文件指引這些實作，無須加入執行階段依賴。

## 原生行為與明確契約 \{#native-behavior-and-explicit-contracts\}

從原生元素及其實際的狀態屬性著手。Master UI 的類別對應受支援的標記，元件契約則記載公開的組成部分與狀態。視覺類別本身無法補足缺少的鍵盤操作行為。模式需要這類行為時，請使用隨附的行為實作，或採用完整的框架整合。

請勿比照相似的元件庫自行杜撰修飾類別。撰寫標記前先閱讀目前的元件契約，再執行 UI 檢查工具，並測試實際呈現的互動。靜態檢查無法驗證焦點行為、輔助技術的宣告或視覺對比。

## Moonstone 與 Obsidian \{#moonstone-and-obsidian\}

預設材質在淺色外觀使用 **Moonstone**，在深色外觀使用 **Obsidian**。兩者共用中性的 zinc 色階，並假定光線一律來自略偏左的上方。Moonstone 透過表面細微的明暗變化、纖細的輪廓與短而漸淡的陰影，呈現淡雅的珍珠質感。Obsidian 則透過填色的明度級差、克制的高光與清楚的邊緣區分深色表面。單純反轉 Moonstone 的色彩會失去這種區隔。

目的是讓容納關係與互動清楚可辨，避免裝飾色搶走內容的注意力。中性的明暗與深度變化用來區分一般表面，語意色用來傳達狀態，則以審慎選用的品牌強調色突顯畫面中的關鍵時刻。這些是 Master UI 的預設做法，其他專案可依自身的品牌識別調整。材質即使低調，仍須讓使用者輕鬆找到相關欄位、操作或圖層。

在同一頁面檢查凸起按鈕、欄位與已開啟的選單，淺色與深色外觀都要檢查。選單必須與後方內容明確區隔，欄位在取得焦點前就應可辨識，弱化文字在實際承載它的表面上也必須清楚可讀。請以實際呈現尺寸與相關的顯示密度檢查細輪廓。裝飾性邊線本身不足以證明辨識控制項所需的邊界符合對比要求。可直接使用的材質、[線條角色](/guide/theme#lines)與[文字角色](/guide/theme#text)皆由[預設主題](/guide/theme)定義。

## 選擇材質層級中的角色 \{#choose-a-role-on-the-material-ladder\}

依表面的用途選擇角色，再由主題決定其外觀。材質層級用來表達表面之間的關係，巢狀容器無須逐層變亮或升高。

| 角色 | 設計目的 | 檢查重點 |
| --- | --- | --- |
| 底層畫布 | 承載整頁內容，無須逐一框住各區段 | 移除裝飾性容器後，閱讀順序依然清楚 |
| 托盤 | 在相關面板下方形成下沉的承載區 | 承載區能將面板分組，並讓視覺焦點留在面板上 |
| 凸起面板 | 呈現有明確邊界的內容或可操作的表面 | 邊緣能與緊鄰的內容區隔，且不會看起來像覆疊層 |
| 內凹區 | 讓可編輯欄位、軌道或項目集合所在區域有清楚的內凹邊界 | 指標移入前就能找到該區域，焦點與驗證未通過的狀態也能清楚區分 |
| 浮動表面 | 讓選單或彈出面板與其覆蓋的內容區隔 | 覆蓋淺色或深色內容時，邊界都清楚可辨，且不會被裁切 |
| 反相墨色 | 為主要操作或選取標記提供足夠的視覺分量 | 標籤與較小的標記維持足夠對比，多個墨色區域也不會彼此搶眼而掩蓋主要任務 |

模態對話框還需要背景遮罩與平台的圖層堆疊行為。陰影本身無法建立堆疊順序或阻擋背景互動。凸起面板也不會因此具備點擊行為。請透過語意、標籤與受支援的狀態樣式傳達可執行的操作。請參閱[表面實作](/components/surface)、[表面角色](/guide/theme#surfaces)、[高度角色](/guide/theme#elevation)與[反相墨色](/guide/theme#ink)，確認目前的契約與數值。

## 同心幾何與連續圓角 \{#concentric-geometry-and-continuous-corners\}

內外邊緣應呈現一致的幾何關係。外層容器的圓角取決於內部控制項的圓角及兩者的間距，內嵌子元素的圓角則由包住它的表面推導。這樣能讓間距在轉角處看起來仍然均勻。有內縮間距時，若內外邊緣採用相同半徑，即使兩個半徑單看都合適，轉角仍會顯得擠窄或鼓起。

Master UI 將這種關係用於托盤與面板、分段軌道與其中的選取項目、輸入群組內的按鈕，以及卡片內的媒體。請一併調整內縮間距、圓角角色與元件尺寸。內外圓角不匹配時，請勿只調整某個後代元素的圓角，讓單張截圖碰巧看起來正確。滑塊的拖曳鈕與頭像等正圓形元素保留自身的幾何形狀。

瀏覽器支援時，連續圓角能讓直邊與彎角之間的過渡更柔和。主題會協調圓角形狀與視覺上的圓潤程度。退回圓弧圓角時，外觀仍應協調，並維持相同的內容邊界。連續曲率屬於材質選擇，無障礙與實作正確性並不以此為前提。

在每種支援的尺寸下，檢查已選取的分段選項與輸入群組按鈕四周的間距，涵蓋兩種外觀及使用備援圓角的情況。內縮間距看起來應維持均勻，文字與焦點指標都不得被裁切。請參閱[形狀實作](/guide/theme#shape)、[分段控制項](/components/segmented)、[輸入群組](/components/input)與[卡片](/components/card)。背後的幾何原理請參閱[幾何](https://design.master.co/craft/geometry)。

## 維持控制項穩定的狀態回饋 \{#state-feedback-on-a-stable-control\}

在預設材質中，控制項平時看起來略為凸起。使用支援懸停的指標時，懸停會強化表面邊緣與抬升效果。按下時，控制項會下沉，表面看起來趨於內凹。這些變化用來確認輸入，且不影響控制項在版面配置中占用的空間。各狀態不應只靠顏色區分，觸控使用者也必須能在沒有懸停的情況下發現可執行的操作。

焦點、選取、按壓、驗證和可用性應各自傳達不同的資訊。焦點指出下一次鍵盤輸入會送往哪裡，選取的區段或核取標記則表示持續保留的值。驗證未通過的欄位仍可同時取得焦點。操作進行中時，必須明確提供進度回饋，應用程式整合時也必須防止意外重複提交。僅套用停用樣式，並不會實作停用行為。

檢查指標按下與放開、取消操作、鍵盤啟用、選取且聚焦、驗證未通過且聚焦，以及停用和處理中的狀態。使用者設定的值與控制項標籤應保持穩定，版面配置不應跳動，焦點指示也不能被材質效果遮蔽。在減少動態效果的設定下，即使沒有抬升或縮放，狀態也必須清楚可辨。在強制色彩模式下，即使裝飾性陰影消失，必要的邊界和選取狀態仍須清楚可見。請參閱[按鈕契約](/components/button)、[選取控制項](/components/segmented)、[動態效果實作](/guide/theme#motion)和[行為責任歸屬](/guide/behaviors)。

## Paper 示範另一種材質 \{#paper-demonstrates-a-different-material\}

**Paper** 是沿用相同元件契約的替代主題。它以暖調中性色、平坦表面、線條邊框和較小的圓弧轉角取代預設的定向光照。Paper 透過共用的抬升設定，讓控制項在懸停時不再抬升、按下時不再下沉，同時保留具有實際意義的元件動作，例如切換開關滑塊的位置變化。選單和對話框仍保留低調的深度提示，因為只靠線條邊框可能難以辨識重疊關係。

Paper 示範了元件如何憑藉結構、行為與彼此協調的角色，在換掉 Moonstone 特有的表面質感後仍可重用。移除漸層與高光後，視覺區別便更仰賴線條與填色的差異。如果所有角色都套用相同的平坦表面，視覺層級就會消失，難以形成一致的平面主題。

在 Paper 與預設主題中，比較同一個按鈕、同一個欄位、同一個已選取的控制項、同一個反相面板和同一個已開啟的浮層。標記、無障礙名稱、值的管理權責和鍵盤行為應保持一致。在 Paper 的兩種配色方案中，邊界、焦點和同時存在的狀態都必須清楚可見，並且仍須支援減少動態效果和強制色彩。請以 [Paper 實作與預覽](/guide/theming#paper)和[主題樣式配方](/guide/theming#recipes)為準，本指南無須另列一份 token 表。

## 自訂範圍 \{#customization-boundaries\}

要調整整體材質時，請修改語意角色。單一元件需要受支援的變化時，請修改文件中列出的元件自訂屬性。若只有單一頁面的排列要變動，請調整該頁的組合方式。完整的主題會協調各個表面、其上的前景色、線條、深度、轉角和各種狀態的呈現。只改背景，可能破壞背景與其上所有元素的視覺關係。

主題提供 token 和共用材質配方，應避免逐步加入改寫個別元件結構的選擇器。Paper 主要使用 token。Paper 也為表面顏色取決於控制項自身色相的帶色控制項提供配方覆寫。token 可在執行階段限定作用範圍，配方定義則在編譯期間解析，並影響建置結果。若某項例外只應套用在單一區域，就必須考量這項差異。

自訂時應保留已公開的元件部位和原生語意。請勿為了讓截圖看起來更簡潔而移除焦點或選取指示，也不要只用品牌色提示錯誤，或逕自認定外觀看起來較小的控制項仍有足夠的操作範圍。變更轉角形狀時，必須一併調整相應的尺寸級距。變更動態效果時，仍須保留清楚易懂的狀態回饋。超出元件文件所述行為的標籤、資料、驗證和焦點流程，仍由應用程式負責。

採用覆寫前，請以實際內容、鍵盤輸入和較長的標籤，測試具代表性的按鈕、欄位、巢狀控制項與浮層。檢查兩種配色方案，以及提高對比、減少動態效果和強制色彩的情況。請參閱[自訂](/guide/customization)、[主題規則](/guide/theming#rules)、[契約](/guide/contracts)和[瀏覽器支援](/guide/browser-support)，並以其中現行的 API 和支援限制為準。

## 元件、版面配置、區塊與頁面 \{#components-layouts-and-blocks\}

當各部位必須在材質、狀態、平台行為或幾何配置上相互協調時，元件就有必要提供共用契約。版面配置負責安排區域內的空間，材質則由其他層負責。基礎版面配置與[元件](/components#layouts)一同列出。[區塊](/blocks)結合元件與版面配置，形成頁面上的一段具體內容。[頁面](/pages)以 `page` 或 `shell` 為框架，組成完整畫面，並定義各區域和捲動方式。

避免把網站文案或只用一次的主視覺版面做成通用元件。可重複使用的對話框、按鈕或欄位，也應避免在網站外層框架中另做一套實作。轉接層僅用於網站實際的組合與相容性需求。

## 從設計準則到實作 \{#guideline-to-implementation\}

| 設計考量 | Master UI 參考文件 | 使用端驗證項目 |
| --- | --- | --- |
| 語意色彩、表面與深度 | [預設主題](/guide/theme)與[主題設定](/guide/theming) | 兩種主題中實際相鄰表面之間的對比 |
| 字體排印、間距、尺寸與覆寫 | [自訂](/guide/customization) | 長內容、資訊密度、文字縮放與操作目標範圍 |
| 標記、元件部位與狀態 | [契約](/guide/contracts) | 原生語意與同時存在的狀態 |

| 執行階段與備援要求 | [瀏覽器支援](/guide/browser-support) | 支援的瀏覽器、選用的增強功能與可用的備援方案 |

這些連結指出各項實作的權責歸屬，驗證範圍仍須依實際的組合方式確認。現有元件與範例請參閱 [Master UI 目錄](/components)。提案中的模式必須具備契約、行為實作和驗證證據，才能列為受支援的控制項。

## 共同審查變更 \{#review-a-change-together\}

先查閱相關的設計基礎與使用指南。在 Master UI 修改實作後，到具代表性的使用端頁面驗證。預期行為有變更時，請同步更新文件。保持原始程式碼、範例、契約和測試一致，並記錄瀏覽器與輔助技術的限制。無障礙聲明應以實際驗證的範圍為準，單張截圖不足以支持全面的聲明。
